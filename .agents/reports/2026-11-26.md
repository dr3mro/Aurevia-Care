## Lessons for workers

- Grep the whole test tree for direct construction before changing a constructor; a two-line fixture update outside a machine-enforced scope becomes a hard blocker, and no reflection seam or in-memory fallback in `src/main` is an acceptable substitute.
- Fill `Test evidence`, `Coverage` and `Review verdicts` before requesting post-code reviews: reviewers read the note when they run, and empty sections cause a `NO-GO` about stale notes rather than code.
- To prove delegation to a shared helper, mock the helper and assert calls with `toHaveBeenNthCalledWith`; byte-identical output comparison cannot detect a duplicate implementation. With `clearMocks: true`, `mockClear()` does not drain `mockReturnValueOnce`.
- Before a module B imports module A, grep for whole-file `jest.mock('…A')` factories; run the RED/GREEN Jest batch with `--no-coverage` because the global 100% threshold fails a partial batch.
- Check the ESLint `complexity` ceiling before adding a view conditional; move logic into small module-level helpers to stay under the limit and avoid uncoverable branches.
- Before designing a `SECURITY DEFINER` escape from FORCE RLS, probe the exact role/policy behavior on real PostgreSQL: an owner-only permissive policy works, but a function-level custom-GUC `SET` is rejected for a non-superuser migration role.
- Before attributing a red full suite to the environment, read the failing test names and tracebacks; run the authoritative generated-config checks individually and record final lines.
- Do not run `mvn verify`, `scripts/check.sh`, `scripts/check.sh` delegates or `scripts/coverage-check.sh` as a worker; target the touched suites and leave the full gate to the integrator.
- A clause can be `Partly built` when code and a fail-closed checker exist but the human drill and G5 sign-off do not: name exactly which portion is not built and who supplies it.
