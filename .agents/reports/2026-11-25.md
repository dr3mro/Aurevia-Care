## Lessons for workers

- Verify a named prerequisite against its current task mark, attempt count, release commits and promised files before accepting a brief's "already added" claim.
- A synthetic catalog generated into a contract is not a route allow-list: count real `@PostMapping` handlers before designing handler-to-command resolution.
- When adding a rule to a shared checker, run the checker against the shipped tree before writing fixtures so an additive rule cannot silently break every docs gate. Table helpers in `check-docs.py` count delimiters, not columns.
- Pin an unspecified policy value chosen by a design with exact-value tests and label it a local assumption; generate worked artifacts from the helper itself and pin them with a regression test.
- Guard the exact status-check string branch protection requires, derive expected values from the checker the workflow invokes, and prove sensitivity with synthetic mutations rather than asserting an already-correct file.
- Before re-editing a re-dispatched `FIX` story, run `git diff --name-only origin/main...HEAD`; if the fix already landed, verify and write a short pointer note instead of manufacturing a diff.
- Do not bind a synthetic in-process sink as a production sink to make a gate look green; that fails the requirement it claims to satisfy.
