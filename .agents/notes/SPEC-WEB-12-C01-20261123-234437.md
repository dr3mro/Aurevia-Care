## Lessons for workers

- Re-verify any specialist's "absence" claim with a direct `ls`/`grep` before writing it as evidence; a read-only survey wrongly reported no `dependabot.yml`, and the error only surfaced at the security review.
- A truthful evidence note must state when a verification command matches gap descriptions: scoping a grep to config paths (`.github/workflows/`, Dockerfiles) and separately citing gap documents avoids a false "empty result" claim.
- The four status values are prescribed per task family; older clause notes use `Proven by tests` / `Partly proven` and must not be copied for a WEB evidence note.
- For docs under `docs/spec/clauses/<domain>/`, count directory depth before writing links: four `../` reach the repository root, three reach `docs/`. `check-docs.py` resolves links but does not check heading sets or truth, so verify those by eye.
- `check-docs.py` prints nothing on success; record "exit 0, no output" in notes rather than inventing a final line.
