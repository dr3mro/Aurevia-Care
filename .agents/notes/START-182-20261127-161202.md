## Lessons for workers

- Probe runtime behavior before encoding a specialist's assumption: this JDK's `Instant.parse` accepts numeric offsets (`+03:00`, `-05:00`) and normalises to UTC, while offset-less local and DST-gap wall-clock strings fail. A plain `jshell`/single-file Java probe takes seconds and prevented a wrong 422 assertion.
- `InstructionFactInputs` builds error codes with `field.toUpperCase(Locale.ROOT)`, so camelCase fields produce `INVALID_CONTENTREF`, `INVALID_CLIENTID`, `INVALID_ACKNOWLEDGMENTDUEAT` — there is no inserted underscore.
- Validation runs before authorization on every MSG-05 command: a wrong-role test with a malformed field proves 422, not 403. Send otherwise-valid commands for role/tenant cases and seed membership in the requested organization for a genuine 404.
- "Two concurrent requests with one key → exactly one 200 and one 409" is not assertable where `putClientDigest` is an atomic `putIfAbsent` followed by a read-back: the loser may replay at 200. Prove both sides deterministically with a store subclass returning `false` for the reservation plus an ordinary winning call.
- When `worker-check.sh` stops in `python-coverage.sh` on an unrelated pre-existing tooling failure, record the exact command and final line once, run `frontend-check.sh`, SpotBugs and `db/check.sh` individually, and leave the protected files untouched; never re-diagnose the same artifact or edit `opencode.json` to make a test green.
