# SMSG-18 — Staff web: compact and tablet layouts for messenger and mail

## Summary

Add a self-contained, bilingual responsive layout wrapper for the staff messenger
and mail panes under the new `apps/staff-web/src/features/staffmsg/layout`
folder. Three panes at desktop width, two at tablet width, one pane with a Back
action on narrow screens, and a composer region that stays reachable above the
on-screen keyboard. Synthetic fixtures only.

## Implementation

New files only, under the exact task scope:

- `layout/panes.ts` — `layoutFor(width, hasDetail)` resolves the breakpoint from
  the existing `theme/breakpoints.ts` tokens and returns visible/drawer panes,
  grid tracks and control flags. All tracks use `minmax(0, …)` so a long value
  wraps instead of forcing horizontal scroll at 768 px (WCAG 1.4.10).
- `layout/labels.ts` — en/ar label dictionary with parity, pane accessible-name
  map and a lookup helper. No clinical content or identifier in any label.
- `layout/MessagePaneLayout.tsx` — controlled wrapper. `hasDetail` and `onBack`
  belong to the caller; the wrapper owns only presentation and focus movement.
  Three panes at 1280, two at 768 (auxiliary in the drawer), one at 320 with a
  Back action; the hidden panes stay in the DOM once each and are reachable
  through a labelled drawer (focus enters on open, returns to the toggle on
  close, Escape or scrim click). The drawer is a non-modal `complementary`
  region, not a false modal dialog. Its open state is derived from a key of the
  breakpoint and selection, so a resize or Back closes it without a state write
  in an effect and it cannot reopen when the old width returns.
- `layout/styles.ts` — tokenised styles. The root is a bounded scroll container
  (`max-block-size: 100dvh`, `overflow-block: auto`) with `overflow-x: clip` so
  a long value cannot force horizontal scroll; `scroll-padding-block-end` is on
  that same scroller and the sticky composer reserves
  `scroll-margin-block-end`, so a focused field stays clear of the keyboard.
- `layout/index.ts` — typed public exports.

No dependency, contract, configuration, tracker or workflow file changed. All
fixtures are synthetic strings such as `Synthetic folder navigation`.

## Findings

- **Title/acceptance contradiction.** The story title says "single-pane at
  768 px"; numbered acceptance criterion 1 and the design contract make 768 px
  the two-pane tablet breakpoint. The explicit acceptance criteria and
  `theme/breakpoints.ts` (`medium: 768`) were implemented, and boundary tests
  cover 767, 768, 1279 and 1280 px. A person should amend the title.
- **Requirement tag mismatch.** The story tags WEB-09 ("Resilient screens")
  but its acceptance criteria are WEB-07/UX-01 compact-layout work. The jsdom
  resize test covers the WEB-09 draft/selection/focus-preservation clause from
  `docs/design/responsive-layout.md` section 9. The other WEB-09 clauses
  (leave-with-unsaved-changes guard, stale-version compare/reload/copy, session
  expiry, correlation-ID error boundary) are **not claimed** by this slice.
- **Wiring follow-up is required.** Scope forbids editing
  `messenger/MessengerPanel.tsx` and `mail/MailScreen.tsx`. This change exports
  a tested wrapper; **no shipped screen became responsive** and no shipped
  entry point calls the wrapper yet. The wiring request is below.
- **Keyboard evidence limit.** The sticky composer and scroll reservations are
  jsdom attribute checks (design guide section 13), not a painted-layout or
  real-virtual-keyboard claim. A Playwright virtual-keyboard project is
  requested below.
- **Drawer semantics.** `docs/design/responsive-layout.md` section 4 describes
  an off-canvas *shell navigation* drawer with Escape and scrim close. This
  slice is a content-pane drawer, so it is a labelled non-modal
  `complementary` region rather than a modal dialog; it offers the close
  control, Escape and a labelled scrim button, each with focus return. The
  design's shell-navigation drawer itself remains a separate story.
- Plan review initially returned NO-GO with Required gaps on wiring, hidden
  pane reachability, boundary widths, WEB-09 evidence, Back focus behaviour and
  keyboard specificity. All were addressed before coding as recorded above.

## Lessons for workers

- When a story's `scope` names a folder that does not exist, check the sibling
  feature folders and the prerequisite task state first: an absent planned
  folder is not automatically a stale reference.
- A responsive wrapper with hidden panes must offer an accessible route to
  each hidden pane; "one pane visible" must never mean "action removed".
- In jsdom, inline `hidden` on a node with an inline `display` rule does not
  hide it; keep `display` off the drawer container.
- `role="dialog"` plus `onKeyDown` trips jsx-a11y non-interactive rules; a
  document-level Escape listener matches the existing Dialog component and
  keeps focus behaviour correct.
- V8 counts the false side of a non-Escape key check and of optional state
  transitions; assert the uninteresting side explicitly instead of deleting
  the guard.
