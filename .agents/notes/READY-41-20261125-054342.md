# READY-41 · Durable authorization decision ledger (OPS-02)

## Summary

Implement the durable production `DecisionSink` for `CommandAuthorization`: new append-only
tenant-isolated `authorization_decision` table (V65), `JdbcDecisionSink`, and a Spring
`@Configuration` bean. Sink failure must fail closed with reason `AUDIT_UNAVAILABLE`.

## Findings

Prerequisite READY-40 is complete. `origin/main` merge at start: "Already up to date."

Specialist design findings fused (reviewer evidence, no code yet):
- Database reviewer (GO): whitelist `reason_code` to the nine known codes because the
  ledger is append-only; allow `subject`/`correlation_id` to be nullable for absent
  identity/correlation; declare `Change: expand`; add a V65-specific probe that sets the
  tenant GUC in-session and seeds a row before asserting mutation rejection.
- Security reviewer (NO-GO on design): unauthenticated decisions have no tenant GUC, so a
  tenant-scoped insert cannot represent them; must decide explicitly. Correlation IDs and
  subjects must be bounded/control-character-stripped; reject UPDATE/DELETE/TRUNCATE for
  every role; join the guarded transaction, never `REQUIRES_NEW`.
- Backend reviewer (GO conditional): final class, assignment-only constructor, one
  exposure (`@Repository` **or** `@Bean`, not both), `public.app_org()` for tenant scope,
  no HTTP reachability in this story (AUTH-WIRE-01 owns the interceptor).
- Test engineer (GO): red test first on sink failure; mocked `NamedParameterJdbcTemplate`
  for deterministic failure/empty sides; real-PostgreSQL integration test autowiring the
  production bean; reset `jacoco.exec` before a coverage batch.

Contradictions resolved by the primary agent:
- Security reviewer marked the `DECISION_NOT_RECORDED` → `AUDIT_UNAVAILABLE` change as a
  Required drift, but the story explicitly requires reason `AUDIT_UNAVAILABLE`. The story
  wins; this is a deliberate contract change, the existing test is updated for that reason,
  and the change is recorded here.
- Backend reviewer preferred `REQUIRES_NEW`; security reviewer forbade it because the
  tenant GUC is transaction-local. The guarded transaction is authoritative: the sink joins
  the caller's transaction (as the `CommandAuthorization` Javadoc already states).
- "Decision is deny with reason `AUDIT_UNAVAILABLE`" is implemented as the fail-closed
  authorization outcome/error code. When the ledger itself fails, no row can be written by
  that ledger; inventing a fallback row would be fabricated evidence. Documented for the
  integrator and AUTH-WIRE-01 (any gate exception is a deny).
- The production sink bean has no caller until AUTH-WIRE-01. `check-wiring.py` only flags
  uncoupled `*Service` classes, so this staged slice passes; this story's entry point is the
  Spring `DecisionSink` bean exercised by the integration test, not an HTTP route.
  No route, controller or OpenAPI change is in this scope; a grep found no
  `DECISION_NOT_RECORDED` in `contracts/openapi.yaml`, so no client regeneration is needed.

Plan-reviewer Required gaps and their resolutions (all addressed before production code):
1. Transaction boundary — `JdbcDecisionSink` injects the shared `TransactionTemplate`
   (`AureviaApiApplication:31`) and wraps the insert in `executeWithoutResult`; it checks
   `TenantContext.current()` before opening the transaction and throws when absent. The
   integration test binds `TenantContext` before calling the autowired bean, and a unit test
   covers the no-context fail-closed path. It joins the existing guarded transaction
   (REQUIRED), never `REQUIRES_NEW`.
2. Columns and CHECKs — `resource_type` is the bounded, control-character-stripped command
   identifier token (length 1..128); `action`, `decision`, `reason_code` are bounded codes,
   `reason_code` is whitelisted to the nine known codes, `subject`/`correlation_id` are
   nullable and bounded to 255. A unit test covers catalog ids and long/control values;
   `organizationId=""` fails the UUID cast/RLS check and therefore fails closed with
   `AUDIT_UNAVAILABLE`, with a test.
3. `AUDIT_UNAVAILABLE` — the effective deny is `ApiException(500, "AUDIT_UNAVAILABLE")`;
   no row exists because the ledger itself failed. The red test asserts status, code and
   `assertThrows` (no allowed `Decision` escapes). It converts an otherwise-denied 403/422
   to 500 when audit fails; AUTH-WIRE-01 must use a working sink in its deny→403 tests.
4. TDD order — red `CommandAuthorizationTest` and `JdbcDecisionSinkTest` run before the
   production edits; the migration lands before the integration test goes green. Every new
   branch and its named test are listed under `## Coverage` at the end.
5. Append-only proof — the integration test seeds a row and attempts UPDATE, DELETE and
   TRUNCATE as the migration owner `aurevia_migrate` (trigger path), plus `aurevia_app`
   privilege checks, cross-tenant INSERT rejection, RLS flags and exact column set.
