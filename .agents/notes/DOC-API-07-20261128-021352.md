## Lessons for workers

- For a documentation-only story with a protected `scripts/` tree, an uncommitted `/tmp` detector plus positive controls is the only test-first option; record the conflict rather than silently dropping the failing-test clause.
- Mask string literals and text blocks in the detector, but never treat a prose apostrophe as a Java char literal; validate the detector with positive controls before trusting RED or GREEN.
- The notes path named by the worker prompt wins over the older task-file path; write only that one file. Fill Test evidence, Coverage and Findings before requesting post-code reviews, or reviewers return a NO-GO about stale notes.
- Ask senior-backend and senior-spring-security for per-package invariants before writing WHY comments; they catch claims that were true in an earlier slice but are stale in current code.
- Verify generated Javadoc with a compile and a marker scan: placeholder text and malformed `/**`/`*/` delimiters can pass a naive detector while breaking the build.
- `check-wiring.py` scans comments as well as code; recompute it after each documentation batch.
- `git add -N` is required before a `git diff -U0` audit of new files, and a frozen source snapshot under `/tmp` lets a full-suite before/after comparison survive an intervening worktree reset.
