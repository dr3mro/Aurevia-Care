## Findings

- The `Delivery gate` skips are a cascade of the red `frontend` job, not an independent
  workflow defect; `delivery.yml` chains all verification jobs behind `frontend`.
- Hand-off to the integrator: the local canonical gate does not exercise the Delivery
  workflow. Trigger and read a fresh `Delivery` run on the repair commit; the original
  run had `java-verify`, `docs`, `verify` and `release` skipped behind the red
  `frontend`, so a locally green staff-web check alone does not prove `main` is repaired.
- `scripts/check.sh` was deliberately not run: it delegates to `apps/api/check.sh`
  (full `mvn verify` plus every integration suite) and to Git-backed policy scripts,
  both forbidden for this worker by the owner directive and the worker gate rules.
  The applicable canonical gate for the single touched file,
  `bash apps/staff-web/check.sh`, was run and is green.
- The test waited only for the rendered error text and then synchronously asserted a
  passive-effect callback. Under CPU load the effect had not flushed when the DOM text
  was observed. The first test in the same file already awaits the same callback.

## Lessons for workers

- When a view test asserts a `useEffect` side effect, await the spy itself with
  `waitFor`; waiting for the rendered text does not guarantee the passive effect ran.
- A green full-suite run does not clear a flaky test: repeat the focused test enough
  times to reproduce the CI race before deciding it is transient.
