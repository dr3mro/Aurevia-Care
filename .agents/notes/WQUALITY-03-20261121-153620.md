# WQUALITY-03 — Swarm quality: validate scope and structured hand-offs on the pinned candidate

## Summary

`scripts/worker_gate.py` now validates the worker's hand-off against the pinned candidate commit in addition to its existing integration-failure triage. It checks that every changed file is inside the task's declared `scope` (or is the worker's own notes file), that no orchestrator-owned tracker changed, that the notes carry `## Test evidence`, `## Coverage` and — for a worker that stopped early — `## Why this is not finished`, that each required section is non-empty and free of `<placeholder>` text, and that HEAD did not change while the candidate was validated. Violations are returned as a structured `{"violations": [{"file": ..., "rule": ...}, ...]}` result and fail the gate. The new `scripts/tests/test_worker_gate.py` covers every rule, both sides of every new branch and the CLI entry point with synthetic diffs and notes.

## Findings

1. **Environment artifact (not a defect from this change).** In this worker worktree `git ls-files -v opencode.json` returns flag `S` (skip-worktree): the file is the CI profile copied by `agent-run.sh`, not the committed local profile. `check-pack.py` and three `test_check_pack` cases report `opencode.json is stale` for that reason. Verified from tool evidence: `git show HEAD:opencode.json` equals `gen.render(ROOT, ci=False)` byte-for-byte (38,387 bytes) while the worktree file equals `gen.render(ROOT, ci=True)`. This is the already-recorded OPS-CW-003-01 false positive; HEAD is correct and no file was changed for it.
2. **Follow-up wiring (outside scope).** No producer currently sets `NOTES_FILE` or `WORKER_FINISHED`: `swarm-worker.yml:46-58` exports `STORY_ID`/`STORY_BODY` only and `agent-run.sh:47` computes the notes path as a local variable. The gate validates when those variables are present (and derives the notes path from `STORY_ID` when `NOTES_FILE` is absent), but the "worker did not finish" rule is only activated when the trusted pipeline exports `WORKER_FINISHED=0`. The integrator's oversight issue for protected scripts should wire that signal; the tests drive it directly.
3. **Reviewer finding, deferred (LOW).** `section_body` stops at the first matching heading, so a duplicated `## Coverage` section with placeholder text would not be inspected. Kept out of this small change; a defensive follow-up should either reject duplicate required headings or validate all of them.
4. **Reviewer finding, deferred (LOW).** The placeholder regex `<[^\s<>]+>` catches the specified `<...>`/`<task-id>` forms but flags Markdown autolinks such as `<https://…>` and misses `<task id>`. Narrowing it to explicit template tokens is a follow-up; no real notes in this repository triggered either case.
5. **Reviewer findings tested or fixed here.** An empty HEAD SHA used to satisfy the pin check when Git failed for both samples; fixed with the `not candidate_sha or not head_sha` guard and two tests. `main()` used to call `changed_paths()` twice (TOCTOU); it now computes the snapshot once and passes it to `candidate_from_env`. A main-level candidate-change test asserts the printed JSON contains `file` and `rule`.

## Lessons for workers

- In a cloud worker, treat `opencode.json` policy results as CI-profile measurements: check `git ls-files -v opencode.json` for flag `S` and compare `git show HEAD:opencode.json` with the generator before reporting staleness (OPS-CW-003-01).
- A new gate function is not done at 100% unit coverage alone: drive it from the real CLI entry point (`main`) and assert the structured output, not just the return code.
- When a pinned-commit check reads Git twice, an unavailable Git must fail closed; an empty SHA is not a valid pin.
