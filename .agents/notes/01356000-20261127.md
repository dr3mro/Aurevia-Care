## Summary
Seven integrator/Agent-swarm runs since 21:00 EST aborted at
`swarm.py reconcile-tasks` because one open task held a prose `pr:` field; an
eighth failed on a transient GitHub API read. This change repairs the tracker
data, adds an offline `validate-tasks` preflight before publication, and gives
the paginated merged-PR read a bounded retry. Fail-closed reconciliation is
unchanged.

## Authorization boundaries and audit events
`validate-tasks` is offline, token-free and advisory; it cannot mark a check
passed. It mirrors reconcile's first-active-task-line rule and numeric `pr:`
field contract, skips `[x]`/`[!]` files, and reports a later open checkbox in
them. The retry keeps `child_environment(read_only=True)`, bounds attempts to
three, exposes gh stderr, and still raises ReconciliationError before any task
write. No new permission, no token in an agent step, per-run concurrency and
`cancel-in-progress: false` untouched.

## Migration and rollout considerations
The preflight is wired into `check.sh`, `quick-check.sh`, the publish job before
"Push only the exact validated commit SHAs", and the reconcile job as defence
in depth. It passes the current 1373-entry tracker.

## Findings
33 malformed `pr:` fields exist on already-done tasks; they are outside
reconcile's active-task scope, so the validator deliberately skips them rather
than blocking every merge on legacy metadata. AUTH-WIRE-02 needs an owner to
name the authoritative merge or close it; it is held as `[!]` with scope
reserved. The `gh api` failure trigger remains unknown because the old code
discarded stderr; the retry now prints it.

## Lessons for workers
`reconcile-tasks` persists by default; test it on a copy or a worktree, and
never leave an embedded `- [ ]` checkbox in a done task file.
