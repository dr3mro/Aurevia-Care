## Lessons for workers

- In an OpenCode cloud worker a red `check-pack.py` / `test_check_pack` result is
  usually the CI profile under `skip-worktree`. Compare `git show HEAD:opencode.json`
  with `gen_opencode.render(root, ci=False)` before regenerating, and never edit
  the protected file.
- On a fresh checkout, `scripts/python-coverage.sh` can error with
  `FileNotFoundError: apps/api/target/surefire-reports`. Creating that gitignored
  directory is a local workaround only; the real fix lives in protected test
  files and belongs in its own owner-approved task, not in a story PR.
- `python3 -I scripts/check-docs.py` enforces heading-level jumps, GFM table cell
  parity, relative-link resolution and specification requirement IDs; count
  unescaped pipes in every new table row and use only IDs defined in the spec.
- Do not repeat the "HL7 markers break the build" claim; check whether marker
  lines sit inside a comment before treating them as a compile failure.
- When a pack must "record no approval", a status legend plus placeholder cells
  ("owner to enter", "to be named") keeps it useful without inventing a market,
  region, contract or retention value.
