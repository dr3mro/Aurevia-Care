## Summary

Added a Playwright browser journey and a dev-only harness under the declared scope. Three synthetic staff views in two facilities of one synthetic tenant drive the **real** `MessengerPanel`, `MailPage`, `ReferenceInserter` and `PatientReferenceChip` under the production providers and their real typed API clients. Only `/api/v1/staff/**` is intercepted, by one append-only in-memory stub shared across three browser contexts. The journey covers explicit instant send with a clean attachment, cross-facility mail with Cc and 428 recipient confirmation, a reply back to the author, a patient reference allowed for the home-facility recipient and blocked for the other, a quarantined file that is refused then removed and replaced, and the same journey in English LTR and Arabic RTL. No production source, dependency, threshold or configuration changed.

## Lessons for workers

- A new e2e spec always flips the WEB-10 `currentSpecs` tripwire; check that pin before calling a staff-web browser-test story done, and ask for a task if the pin is outside scope.
- Adding a spec under `apps/staff-web/e2e` does not make `npm run typecheck` see it: run `npx tsc --noEmit -p tsconfig.lint.json` as well.
- The `Send` button label is shared by messenger and mail; scope locators to the labelled region and use `exact: true`.
- `ApiPage` and `MailScreen` both render a region named after the mail title; use `.first()` or a nested selector to avoid strict-mode violations.
- Real autosave is asynchronous: poll the stored draft's fields before clicking Send instead of trusting the first "Draft saved" notice.
- Playwright binary download is not enough in a cloud worker; system libraries (`libglib-2.0.so.0`) must be installed with `npx playwright install-deps chromium`.
