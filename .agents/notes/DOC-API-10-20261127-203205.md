## Lessons for workers

- For a documentation-only story with protected `scripts/` and tests, an uncommitted `/tmp` string-literal-aware scan is the only test-first option; record the scope conflict instead of silently dropping the "add a failing case" instruction.
- A bulk comment rewrite must preserve leading Javadoc indentation: normalise doubled spaces only on lines whose ID token was removed, never across the whole comment.
- Verify a literal-aware lexer against text blocks before applying it; a quote-only stripper can rewrite fixture SQL.
- Ask the domain specialist for per-package invariants before writing WHY comments: naive claims about facility scope, replay ordering, outbox persistence and approved-modality checks would all have been wrong.
- Check the notes-path convention of both `agent-run.sh` (`.agents/notes/`) and `worker_gate.py` (`docs/pr/notes/`) before finishing; keeping both copies is cheaper than a gate send-back.
- If `worker-check.sh` fails on a clean-base test artifact, record the exact failing command and final line, then run each later stage individually; never edit `scripts/` or `.opencode/` to force a green.
