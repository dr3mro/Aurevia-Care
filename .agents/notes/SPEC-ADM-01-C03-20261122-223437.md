## Findings

- **The gate and the task instruction conflict; the gate wins.** `tasks/00571000-SPEC-ADM-01-C03.md:9`
  mandates `@Disabled("GAP: ...")` for an unbuilt clause, but
  `scripts/check-constraints.py:56` rejects every newly added `@Disabled`. The repair
  directive forbids working around the gate, so the dead skipped test was deleted and
  the gap documented instead. The gate is not a defect to bypass.
- **No real implementation exists to enable.** Channel identity exists only as
  configuration keys (`critical.escalation.primary_channel`/`backup_channel`,
  `messaging.urgent_channel`/`downtime_channel` synthesized in the first attempt) and
  as V92 service-profile columns. There is no channel invocation adapter, so
  implementing the route would require fabricated "success" outcomes and out-of-scope
  changes to `ActionPolicy`, OpenAPI, a generated client and a migration. That would
  be theater, not proof, and is outside this test-only task.
- **First-attempt evidence retained for the integrator.** The earlier targeted run
  (`mvn -f apps/api/pom.xml -Dtest=PilotSiteOnboardingTestsConfiguredChannelTest test`)
  reported `Tests run: 4 ... Skipped: 4` and was green only because everything was
  disabled; that is why it was not kept as evidence of the clause.
- **Environment artifact (not re-diagnosed).** In a cloud worker
  `git ls-files -v opencode.json` shows `S` and `git show HEAD:opencode.json` is the
  valid generated profile, so `check-pack.py`/`test_check_pack` "stale" failures are
  the documented OPS-CW-003-01 false positive. No protected file was edited.
- **Optional (DevSecOps, forward-looking).** The future contract in the document uses
  422 for missing/unapproved channel configuration, while the existing
  `ConfigurationService.get()` returns 404 for an absent effective configuration.
  When the channel-test route is implemented, choose deliberately: 404 avoids
  revealing whether a key is configured-but-unapproved. No delivered control is
  affected by this note.

## Lessons for workers

- Do not add a `@Disabled("GAP: ...")` would-prove test in a swarm worker: the quality
  gate rejects newly added skipped tests. Survey and document the gap instead; a
  skipped test cannot prove anything and is the gate violation, not the fix.
- When a task instruction and a build-failing gate disagree, follow the gate and record
  the conflict; do not add a suppression, a qualified annotation, a tag exclusion or a
  waiver to satisfy the prose.
- A fully skipped test is dead code. Deleting it cannot lower real coverage and is the
  gate's own prescribed fix ("delete the dead code").
