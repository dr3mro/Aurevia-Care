## Lessons for workers

- Before patching a broken sibling test outside your scope, check `origin/main` first: main may have
  already fixed it (here `20bbffe6` fixed the same `ExportRecord`/`ExportProvenance` defect). On merge,
  keep main's version to avoid an out-of-scope diff and a needless conflict.
- A functionally identical fix on both sides of a merge is still a content conflict when the literal
  synthetic values differ; resolve by keeping the canonical (main) version.
- In a cloud worker, `git ls-files -v opencode.json` = `S` explains `test_check_pack` and
  `worker-check.sh` failures; verify with `git show HEAD:opencode.json` and do not re-diagnose it or
  regenerate/commit that file on a later pass.
- Do not run `scripts/check.sh` or `coverage-check.sh` in a swarm worker (full `mvn verify` timeout);
  run targeted `-Dtest=...` plus the individual policy scripts and leave the full gate to the integrator.
