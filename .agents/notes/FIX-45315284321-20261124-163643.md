## Root cause and reproduction

At `bca28f34` the merged PR hand-edited `.github/opencode.ci.json`, changing
`default_agent` and the matching agent key from `smartclinic-orchestrator` to
`orca`, while the agent files on that commit were still named `smartclinic-*`
and `scripts/gen-opencode.py` still generated `smartclinic-orchestrator`.
`scripts/check-pack.py` re-renders every declared output and compares it, so it
caught the drift. The local `opencode.json` at that commit was regenerated and
matched; only the CI profile was stale. All other policy scripts passed.

The seven `mandatory job ... is skipped` lines in the supplied log are
consequences of the one failed dependency, not seven defects. Feeding the
logged `needs` object back to the gate reproduced the log verbatim.

## Lessons for workers

- Reproduce a historical CI failure in a clean `git worktree` inside the repo
  before editing anything; a cloud worker's skip-worktree `opencode.json` is
  the CI profile and produces a false `check-pack` staleness report.
- In a Delivery gate log, the downstream `skipped` jobs are usually fallout
  from the first red dependency. Find the first actionable failing step before
  treating each gate line as a separate defect.
- Check whether a historical repair is already on `origin/main` before touching
  protected workflow or script files; here the stale file had been removed by a
  later refactor, so any edit would have been churn.
