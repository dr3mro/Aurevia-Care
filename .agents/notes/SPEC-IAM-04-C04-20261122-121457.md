# SPEC-IAM-04-C04 — Move chart visibility through a versioned association with the surviving record (IAM-04 clause 4)

## Summary

Proved IAM-04 clause 4 with a focused, synthetic-data, HTTP-level integration test
against real PostgreSQL, and documented the clause. The clause is already built in
production, so no test was disabled and no production code, contract or migration
was changed. One positive test proves chart visibility moves to the survivor through
version 1 of an `ACTIVE` `chart_association` while the original patient rows remain;
two negative tests prove a stale version and a chart already moved by another review
are refused without appending a second association.

## Lessons for workers

- The clause-test packages (`authz/clauses`, `tenancy/clauses`, now `patient/clauses`)
  are HTTP integration tests with a dedicated database, Flyway from `db/migrations`,
  synthetic staff seeds and `X-Synthetic-Subject`/`X-Active-Organization` headers; copy
  that pattern instead of writing a mocked unit test for a clause acceptance proof.
- To run one integration class without invoking the whole suite, use
  `mvn -B -f apps/api/pom.xml -Pno-security -Dtest=<Class> test` (the default profile does
  not set `excludedGroups=integration`; only the `fast` profile does).
- Check `git grep -nE '^(<<<<<<<|>>>>>>>) '` at the start: conflict markers can be
  committed inside Javadoc on `main`; if they are outside this task's scope, record them
  rather than editing production code.
