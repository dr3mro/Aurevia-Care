## Lessons for workers

- Before re-dispatching a clause test, check `git diff --name-status origin/main...HEAD` and `git status --short`: if the branch already carries the delivered files, verify and document instead of rewriting a green test or inventing a failing case.
- "For example" negative lists are illustrative; do not add a `@Disabled` test merely to tick an example. A case that is RED against correct code (cross-tenant with RLS as the boundary) or has no branch to assert (stale version in a create command) is not a gap for this clause and a skipped test fails the constraint gate.
- Reusing a production constant or a digest produced by the code under test in an expected-value assertion is vacuous: use a literal separator and an offline-precomputed fingerprint, as the existing class does.
- In a cloud worker, confirm the `opencode.json` "stale" signal once (`git ls-files -v opencode.json` → `S`, `git show HEAD:opencode.json`), then run remaining gate stages individually and never regenerate that protected file.
- Write one new note per run under `docs/pr/notes/<task-id>-<timestamp>.md`; never edit the shared `docs/pr/notes.md`.
