## Lessons for workers

- For chart negative paths, stub membership and roles on `ChartRepository` itself: `ChartService.authorize` reads that fold, and a missing stub silently converts the expected 404/200 into a 403. Give every role case the exact role key (`tenant_admin`, `privacy_auditor`, `reception`, `clinical_assistant`) — an empty role list is indistinguishable from a denied role.
- `ChartService.validate` runs before `authorize`, so a wrong-role record body must still be valid and must set `clinicalAuthor` to that caller's own subject; otherwise the test proves 403 `INVALID_CLINICAL_AUTHOR` instead of 403 `FORBIDDEN`. Likewise `IfMatch.parse` runs in the controller before authorization — verify negatives must carry a valid `If-Match`.
- A tenant-concealment test must make `find`/`chart` answer from `TenantContext.current().organizationId()` with a seeded row for the owner; an unconditional `Optional.empty()` proves nothing about isolation. Cross-tenant list is 200 with `{"entries":[]}`, never 404.
- Both verify failure branches log audit outcome `CONFLICT`: the stale-version 412 and the already-verified 409. An audit count of one fails a test that exercises both.
- `{}` as a command body binds to a record of null components and reaches `INVALID_PATIENT_ID`; unreadable JSON is a different path (400 `MALFORMED_REQUEST_BODY`).
- Confirm `scripts/worker-check.sh`/`scripts/check.sh` scope before running them in a worker: they execute all integration suites / full `mvn verify`. Targeted `-Dtest=...` plus standalone SpotBugs and the individual policy scripts are the correct scoped gate.
