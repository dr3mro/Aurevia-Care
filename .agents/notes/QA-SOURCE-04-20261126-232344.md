# QA-SOURCE-04 — Show and retry staff scheduling pagination failures

## Summary

Make the staff scheduling worklist retain already-loaded rows when a later page
fails and offer a working localized Retry that reuses the same cursor, appending
the recovered rows exactly once. This closes the WEB-09 error/retry gap for the
appointment worklist while keeping CLN-01 visit data intact. The change is
contained to `apps/staff-web/src/features/scheduling`.

## Affected requirements

- CLN-01 — visit data stays intact; loaded rows are not discarded on a later-page failure.
- WEB-09 — every screen defines an error/offline state with a recovery control and a component test, in English and Arabic.

## Lessons for workers

- Check the ESLint `complexity` ceiling before adding a view conditional. `SchedulingPage` was already at 12, so the inline `&&`/ternary had to move into small module-level helpers; that also removed an otherwise uncoverable `loaded.length > 0` branch inside the existing `else`.
- `result.reload()` from `useApi` is a generation bump; the page's own `reload` callback clears cursor, accumulated rows and next cursor. Retrying a later page must call the former, and the test must assert both same-cursor request and single occurrence of every row after recovery.
- Use a deferred for the retry request when asserting that retained rows stay visible in flight; a synchronous `getBy*` after an awaited API call sees the wrong state. Assert `getAttribute('disabled')` for button enablement instead of adding a type assertion.
- Re-run the canonical `bash apps/staff-web/check.sh` after any test-only edit; Vitest green alone does not cover typecheck, lint, build or the bundle budget. Root `npm ci` supplies Prettier when `apps/staff-web/node_modules` does not.
- Trust the pinned `package.json`/lockfile over stale `WORKSPACE.md` notes about TypeScript versions.
