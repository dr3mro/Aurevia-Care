## Lessons for workers

- Before adding a test for a "test-only" re-dispatch, run the targeted integration
  class first and read the Surefire `tests=` count. If it is already green and the
  clause doc has all four headings, report "duplicate dispatch, already proven" and
  write only the new note — never fabricate a gap or a `@Disabled` test.
- Never use `-Pno-security,fast -Dgroups=integration`: `fast` sets
  `excludedGroups=integration` and gives a false green. Use `-Pno-security
  -Dgroups=integration -Dtest=...` and confirm `tests="7" skipped="0"` in the report.
- A bare `spotbugs:check` is vacuously green; compile first with `-DskipTests compile
  spotbugs:check`. Do not run `scripts/check.sh` in a swarm worker — it invokes full
  `mvn verify` and times out the run.
- Guard order in the void path is 428/422 (precondition) → 422 (id/reason) → 403 →
  404 → 409 → 412; a missing-`If-Match` test must OMIT the header, or 428 becomes
  unreachable. Read unchanged state through the owner's HTTP GET under FORCE RLS, not
  a raw JDBC count that may hide rows.
- In a cloud worker, confirm the `opencode.json` pack failure once with
  `git ls-files -v` plus committed-vs-generated comparison, run the remaining gate
  stages individually, and leave the full gate to the integrator.
