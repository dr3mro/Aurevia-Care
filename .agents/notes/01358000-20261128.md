## Summary
The patient conversation inbox open action is now real. Pressing a row loads
that conversation's detail from the deployed endpoint, renders the existing
thread, records a versioned read with an idempotency key, and clears the unread
badge. The shared transport gained an optional header argument so the deployed
`If-Match`/`Idempotency-Key` contract can be honored without overriding the
authenticated identity or correlation id.

## Authorization boundaries and audit events
The organization id comes from verified host props, never from a server payload;
a spoofed record cannot cross a tenant boundary. Conditional headers cannot
override `Authorization` or `X-Correlation-Id`. 401 routes to the existing
session-expiry handler; other failures clear the thread and keep the inbox.

## Migration and rollout considerations
Reply sending and acknowledgment remain deliberately unwired placeholders;
`ConversationThread`'s `onSend` uses the existing no-op action and no POST is
issued from the composer. On compact windows the thread renders below the inbox
so the patient can return to the list; on large windows it uses the existing
detail pane.

## Findings
The read badge is cleared once a read succeeds rather than recomputed from the
read reply's sequence; the reply is validated and retained by the provider. A
stale-version read clears the thread but does not trigger a second inbox fetch.
