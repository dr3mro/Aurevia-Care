# WQUALITY-06 — Swarm failure classification (function, guide and tests)

## Summary

Adds `scripts/failure_classes.py` with a deterministic, offline `classify(log, task_text, changed_files)` that returns `{"class": ..., "catch_layer": ...}`: one of `task-policy`, `missing-tests`, `check-parity`, `implementation` or `infrastructure`, plus the single layer where the preventing regression belongs (`task template`, `worker-check`, `integrator-gate`, `unit test`, `contract test`). Plain keyword/pattern rules only; the module imports just `re` and performs no network, process or file I/O. Adds `docs/swarm/failure-classification.md` with the five classes, a synthetic example log for each, the class-to-layer table with rationale, the rule to apply after every five swarm pull requests, and an empty review-record table. Adds `scripts/tests/test_failure_classes.py` with a fixture log per class and 10 assertions. No dependency, no tracker and no file outside the task scope was changed.

The classifier complements `diagnose()` in `scripts/swarm.py` (read from `scripts/swarm.py:440-499`): `diagnose` explains what broke, `classify` names the layer that should have caught it. Rule priority is `task-policy` → `check-parity` → `infrastructure` → `missing-tests` → `implementation`, with `implementation` as the catch-all when nothing matches (there is deliberately no `unknown` class: every failed pull request needs a regression owner).

## Lessons for workers

- A `coverage`-less worker can still prove the AGENTS.md 100% rule with `sys.settrace`: derive executable lines from the AST (skip docstring `Expr` statements), record `(from, to)` arcs, and require both arcs at every `If` and `For` line. Report it as the closest supported measure; never claim the canonical gate ran.
- When the canonical coverage wrapper warns `coverage is not installed; the tests ran without the coverage check`, exit 0 is not a coverage result. Restore HEAD's `opencode.json` with a trap to get a green plain-unittest run, restore the worker profile byte-for-byte, and keep the two facts separate in the notes.
- `git grep` can report conflict markers that are already committed in HEAD; check `git show HEAD:<file>` and `git ls-files -u` before treating them as a merge you must resolve, and leave out-of-scope files alone.
- Keep classifier fixtures free of another class's keywords: `BUILD FAILURE` in the coverage and implementation fixtures is harmless only because `missing-tests` is ordered before `implementation`.
- `python3 -I` ignores `PYTHONPATH`; a stdlib-only harness written to `/tmp/opencode` and run as a file is the reliable way to measure a script's coverage in this worker.
