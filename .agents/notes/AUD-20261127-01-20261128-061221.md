# AUD-20261127-01 — Enforce X-Api-Version negotiation at the HTTP boundary with a machine-readable 422

## Summary

Wire the existing `ApiVersion.from` contract into `TenantContextInterceptor.preHandle` so an unsupported
`X-Api-Version` is refused with the existing machine-readable 422 before any handler or tenant binding runs.
Test-first: replace the enabled characterization with the desired HTTP assertions, then make one production call.

## Lessons for workers

- Fill `Test evidence`, `Coverage` and `Review verdicts` before requesting post-code reviews; an empty
  section produces a NO-GO about stale notes rather than about the code.
- When a version/validation call is placed before tenant binding, its error body carries `unassigned` as
  the correlation id while the response header carries the caller's id. Assert the header on that path;
  asserting the body id locks an `ApiErrorHandler` detail that is out of scope here.
- The tooling-suite profile failures (`test_check_pack` ×3 reading the skip-worktree worktree config),
  `test_process_env`'s descendant reaping and the full-suite-only `test_notes_files` archive failure are
  worker-image/order artifacts. Confirm once with the authoritative `gen-opencode.py --check` and
  `check-pack.py`, record the final lines, run the remaining gate stages individually, and do not edit a
  protected file to chase them.
- Run SpotBugs after a compile even for a one-line change: a discarded validation return can be reported as
  an ignored pure result. Here standalone `compile spotbugs:check` exited 0, so no exclusion was needed.
- A bare `mvn -Pno-security,fast ... -Dgroups=integration` never runs integration tests; `fast` sets
  `excludedGroups=integration` and wins. Always use `-Pno-security -Dgroups=integration` and confirm the
  Surefire count.
