## Lessons for workers

- For a test-only story an honest red-first cycle cannot happen: record the first-run green and, if useful, invert one expected value temporarily, capture the named failure, restore it and record the second green. Never leave the mutation in the tree.
- Pin a denial branch with the exact message (`missing action permission`), not only status and code; a 403 from the inactive-membership branch otherwise looks identical.
- `authorize` is re-derived inside every command: verify `times(3)` for membership and roles, and scope `never()` to config-data access so the audit and authorization reads are not accidentally forbidden.
- A mock-backed peer-tenant case proves control flow, not forced RLS. Say so in the class Javadoc and cite the real-PostgreSQL HTTP test instead of calling the mock isolation evidence.
- A cloud worker's Python suite can fail on five pre-existing sandbox/profile fixtures while the authoritative policy scripts pass. Rerun each failing module alone, compare with a pre-change baseline, and do not weaken a test to make it green.
- Fill `Test evidence`, `Coverage` and `Review verdicts` before requesting post-code reviews; reviewers read the note when they run and an empty section draws a NO-GO about stale notes rather than the code.
