## Findings

- Root cause (confidence high, tool evidence): `8f363e02` changed `worker_gate.main()` from
  `failing = failing_classes(REPORTS)` to
  `reports = Path(args[1]) ...; usable = reports.is_dir() and usable_reports(reports)`.
  `usable_reports()` calls `Path(reports_dir).glob(...)` without checking that the path
  exists. Two tests mock only `Path.is_dir -> True` and call `main(["1"])` without a second
  argument, so they enter `usable_reports()` against the non-existent legacy default
  directory and raise `FileNotFoundError`. The commit changed `scripts/worker_gate.py` but
  not these two test call sites, so the regression is pre-existing on `origin/main` and
  unrelated to BUILD-41.
- Order dependency (proved this pass): the two errors vanish whenever
  `apps/api/target/surefire-reports` happens to exist and holds parseable `TEST-*.xml`,
  which is why earlier Maven-then-Python local runs looked green while CI (fresh checkout,
  policy job before the Java job) stays red.
- Bounded fix plan (from the step-5 debugger report, treated as notes, for the owning
  maintainer): in `scripts/tests/test_worker_gate.py`
  (`test_integration_failure_still_fails_the_gate`, around lines 328-336) create a
  `tempfile.TemporaryDirectory()`, write one parseable `TEST-FooTest.xml`
  (`<testsuite failures="1" errors="0"></testsuite>`) into it, and call
  `worker_gate.main(["1", reports_dir])`; drop the `Path.is_dir` mock, keep the
  `failing_classes` mock returning `{"RxTransmissionFlowTest"}` and the `== 1` assertion.
  Do the same in `scripts/tests/test_worker_gate_coverage.py`
  (`test_maven_failure_with_failing_reports_still_fails`, around lines 552-555), reusing its
  existing `write_report` / `suite_xml` helpers (lines 56-65); extend `run_main` /
  `patch_common` (lines 504-521) so `reports=True` creates a real directory with one
  parseable `TEST-*.xml` and passes it as `argv[1]`, while `reports=False` keeps the
  `is_dir -> False` "no reports" branch covered. Prove with
  `rm -rf apps/api/target/surefire-reports && python3 -I -m unittest discover -s scripts/tests`
  → `Ran 1108 tests ... OK` (apart from the six skip-worktree `test_check_pack` failures in
  this runner), then `bash scripts/python-coverage.sh`, `bash scripts/check.sh` and
  `bash scripts/integrator-gate.sh`; `mvn -Pno-security verify` must stay green. No Java,

## Lessons for workers

- When a change alters the contract of a shared function (`worker_gate.main()` now needs an
  explicit fresh report directory), update *all* existing callers and unit tests in the same
  commit; mocking `Path.is_dir` is not a substitute for a real directory once the function
  globs it.
- A test that passes only because a previous command happened to create a build artifact
  (`apps/api/target/surefire-reports`) is not hermetic. Give such tests their own
  `TemporaryDirectory` with a parseable `TEST-*.xml`.
- Before re-running a fix, inspect `git log origin/main..HEAD`: earlier workers may already
  have applied it, and the correct job is independent verification plus a fresh notes file.
- Distinguish a pre-existing failure on `main` from a branch defect. A failure that
  reproduces on a clean `origin/main` belongs to its owning change, not to the story whose
  PR happens to be red.
- Respect protected paths: a swarm worker PR touching `scripts/`, `.opencode/`,
  `.github/`, `opencode.json` or a tracker is never auto-merged, and
  `worker_gate.validate_candidate` flags it as a scope violation. Put the finding in the
  notes hand-off instead of editing the file; `scope_ok()` also rejects protected paths in
  `task-requests`.
- In this cloud worker `opencode.json` is a skip-worktree CI profile: `git ls-files -v`
  shows `S`, `gen-opencode.py --check` judges the CI bytes and reports false staleness,
  while `git show HEAD:opencode.json` equals `gen.render(ROOT)`. Never regenerate or commit
  that file.
