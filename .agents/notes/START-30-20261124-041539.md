## Findings

- The scope path `docs/reference/modules/api-finance.md` was absent in this snapshot, so it was created as a planned new file, not treated as a stale reference.
- The plan reviewer found one Required gap — an explicit command table — because `FINANCE_APPROVE` has no HTTP route and would otherwise be omitted from the entry points section. Fixed by adding a nine-command table with role and route mapping.
- The brief said the controller has "8 routes"; the source has 9 (`create`, `list`, `issue`, `payment`, `credit`, `refund`, `void`, `get`, `reconciliation`). The guide records 9 and cites `FinanceController.java`.
- `python3 -I scripts/check-docs.py` exits 1 on the current tree for pre-existing unrelated documentation; the next worker should compare before/after rather than treat the raw exit code as a new failure.
- Two known weaknesses are documented under `## Things to know`: the published optional `Idempotency-Key` is not read by the controller (durability is keyed on the body `reference` plus SHA-256 fingerprint), and the generated command catalog's `issueInvoice` entry names `POST /api/v1/invoices` with `FINANCE_INVOICE_CREATE`, which does not match the live route or action.
- The devsecops and code reviewers found two Required inaccuracies, both fixed: the audit row originally claimed every outcome was audited, but only successes, authorization/approval denials and replay/void-after-posting conflicts append an outcome (other failures roll back silently); and the repository bullet originally said no durable implementation was selected at runtime, whereas the JDBC `FinanceRepository` is the sole production bean. A third Required finding from the code reviewer — the opening claim that every command takes a row lock and version precondition — had already been narrowed to commands changing an existing invoice before that review.
- The approver is a client-supplied subject validated for format plus distinctness, active membership and approval role, not a separately authenticated second party; this is now stated in `## Things to know` so readers do not assume stronger dual control than the code provides. Improving audit coverage or approver authentication is a code change outside this task's scope.

## Lessons for workers

- For any Markdown task in this snapshot, capture a `check-docs.py` baseline before editing. A raw exit 1 is not proof of your own failure; a before/after diff is.
- An "entry points" table needs the command vocabulary as well as HTTP routes: a command such as `FINANCE_APPROVE` exists only inside the service and is lost if you list routes alone.
- Derive test-count claims from the classes with `grep -c '@Test'`; estimates from a quick read are easy to get wrong.
