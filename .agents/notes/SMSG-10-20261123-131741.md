# SMSG-10 — API: notifications, mute, do-not-disturb, out-of-office reply and urgent flag

## Summary

Domain kernel in the `staffmsg.notify` package for per-person notification settings (mute, do-not-disturb window, out-of-office delegate), content-free notification drafts, an urgent "not for emergencies" notice, and per-sender-per-day auto-reply dedupe. No production route, migration, contract or send-path change is in scope; those are recorded as task requests below. All fixtures are synthetic; org/subject are derived only from `TenantContext`.

## Affected requirements

- MSG-06 (PROJECT_V1_SPEC.md:103) — content-free generic notifications, urgent contact instructions shown before sending, failed-notification/backlog surfacing. This slice provides content-free drafts and the fixed urgent notice; publish to the OpenAPI contract and the SMSG-16 web banner are follow-ups.
- ARC-07 (:128) — commit publication, audit, queue update and notification outbox together; durable message IDs. This slice publishes identifier-free drafts to the existing `DurableEventService` outbox; persistence of settings and the send-path call sites are follow-ups.

## Risk class

Cross-boundary (backend domain + configuration + outbox). Safety-relevant because notification text must never carry PHI and tenant scope must fail closed; covered by devsecops and simulated review.

## Review owner

Orchestrator / integrator (swarm worker). Simulated read-only reviewers only — no human or clinical evidence in this slice.

## Data changes

None in scope. No Flyway migration, no table, no backfill, no reserved migration version used. Settings/auto-reply receipts are held by a process-local adapter behind `NotificationSettingsPort`; a durable Jdbc store with RLS/FORCE RLS is requested below.

## Authorization boundaries and audit events

Tenant and subject come only from `TenantContext`; unbound context or blank organization fails closed with 401, blank actor with 422. Cross-tenant settings are concealed (lookup keyed by organization + subject). Notification drafts are published to the durable outbox through the existing `DurableEventService` (no new audit event type in this slice).

## Migration and rollout considerations

No migration. Production wiring adds only `@Bean`s (no new HTTP route), so `OpenApiRouteParityTest` and the shrinking `missing-routes.txt` baseline are unaffected. A test-only nested `@RestController` used with standalone MockMvc provides HTTP evidence without entering Spring component scan.

## Lessons for workers

- A circular do-not-disturb interval needs one `if (duration == 0)` with modular arithmetic; adding an `enabled` flag or `&&`/`||` only multiplies the branches the 100% gate must cover.
- An unused domain helper (for example `NotificationSettings.mutes`) is dead code until a caller uses it: make the in-memory adapter read it as the single source of truth instead of duplicating a mute set, or delete it.
- SpotBugs flags mutable `Set` record components even when a compact constructor copies them; pair the freeze with an overridden accessor returning `Set.copyOf(...)`.
- A test-only `@RestController` as a nested static class used with `standaloneSetup` gives HTTP evidence without entering the `@SpringBootTest` component scan that `OpenApiRouteParityTest` checks; confirm with a direct run of that integration test.
- Verify the full Spring context still starts after adding `@Bean`s: `mvn -Pno-security -Dgroups=integration -Dtest=OpenApiRouteParityTest test` (never add `-Pfast`, which excludes integration tests and gives a false green).
- When `check-pack` reports a stale `opencode.json` in a cloud worker, confirm OPS-CW-003-01 once and run the later gate stages individually; re-diagnosing it wastes a pass.
