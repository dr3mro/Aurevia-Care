## Lessons for workers

- A red/green `/tmp` scan is the only test-first option for a documentation-only story when `scripts/` is protected; record the scope conflict and label the scan as local evidence instead of silently dropping the "add a failing case" clause.
- Mask string literals before scanning comments, but never treat prose apostrophes as char literals; recompute RED against pristine `HEAD` files with the final detector.
- Ask senior-backend for per-package invariants before writing WHY comments: it caught eleven comments that were true when written but stale against the current code, including a false claim that a published attachment alone permits download.
- When adding Javadoc to interface implementations, `{@inheritDoc}` keeps the contract in one place and satisfies the tag checks; add a WHY sentence only where the implementation's behaviour is non-obvious.
- `git add -N` is required before a `git diff -U0` audit of new files; allow the single `package ...;` line of each new `package-info.java` in the comment-only check.
- Check the notes-path convention of both `agent-run.sh` (`.agents/notes/`) and `worker_gate.py` (`docs/pr/notes/`); keeping both copies is cheaper than a gate send-back.
