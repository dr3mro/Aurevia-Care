## Findings

Carried forward from `.agents/notes/AUTH-WIRE-01-20261125-002518.md` and re-verified above as still
true (reviewer evidence from that run, tool evidence for the current state):

- READY-41 has failed 45 times; there is no durable `DecisionSink` bean, no `V65` table with RLS and
  FORCE RLS, and no durable decision row to assert in an HTTP test.
- `CommandCatalog.synthetic()` has 24 synthetic G0 paths that mostly do not match delivered routes;
  adding real entries changes generated contract/client artifacts outside this task's scope and an
  existing "24 commands" assertion.
- A global POST interceptor would deny most delivered endpoints; a catalog-only interceptor would
  not run for most commands. Selecting the allow-list needs an owner/architecture decision.
- Deny statuses are not uniform (`422 UNKNOWN_COMMAND`, `500 DECISION_NOT_RECORDED`, `403 FORBIDDEN`)
  while the story says 403 on deny; a sink failure throws, so no decision row can exist for it.
- `StaffRepository.activeRoles(subject)` and `hasActiveMembership(subject)` have no organizationId;
  interceptor ordering and tenant scope need specification before use.

## Lessons for workers

- Verify a named prerequisite against the current task mark, attempts, release commits and promised
  files before accepting a brief's "already added" claim.
- A synthetic catalogue generated into a contract is not a route allow-list; match catalog paths to
  real `@PostMapping` routes before designing handler-to-command resolution.
- Do not add a required bean to a Spring context shared by hundreds of `@SpringBootTest` classes
  until the bean and the context count are both verified.
