# BUILD-71 — Patient app screens: match the approved design in English and Arabic

## Summary

Restyle the three patient feature screens to the approved phone design using a single token-backed,
bilingual presentation module inside the delivery scope. Appointments now show a status pill with a
shape-distinct glyph and word, large date/time, visit and facility-with-time-zone lines, and a
full-width Confirm action with the confirmation time. Reports show title, issuer, effective date,
Revision/Corrected pills, an amber correction note, Download PDF with the per-download check, a
result card, and a dashed withdrawal notice with no download. Conversations show the unit's service
hours and reply target before the composer, sender/time bubbles, a revision-bound acknowledgment,
a To line, an explicit Send (إرسال) and a standalone mirrored tab bar for design review. All copy is
English/Arabic; a screen without an explicit `locale` resolves it from the device direction, so the
mounted app renders Arabic on an Arabic device. No dependency, migration, API or credential change.

Shared module: `apps/patient-mobile/src/features/appointments/patientDesign.tsx`. It lives in the
appointments folder because a repository-wide `src/theme`/`src/components` module is outside this
story's scope; reports and conversations import it rather than duplicating tokens or copy.

## Affected requirements

- **PAT-01** — appointment list, facility time zone, status and Confirm with recorded time; details load through the existing `onOpenDetails` callback after sign-in.
- **PAT-02** — released report revision, issuer, effective date, correction context, authorized Download PDF with per-download check, and a withdrawn notice with no download control.
- **MSG-06** — unit service hours and reply target shown before the composer in the conversation thread.
- **UX-01** — English and Arabic RTL, token-only styling, logical properties, and a label/role on every control.

## Clinical and architecture review

No signed data, cross-organization sharing, patient association, prescribing or critical-result
behaviour is changed, so clinical/architecture sign-off is not required for this UI slice. A
shape-distinct glyph plus a word accompanies every status colour (token contract §3.3), and the

## Findings

1. **App-level wiring is out of scope.** `src/app/patientPages.tsx`, `providers.ts`, `messages.ts`,
   `tabs.ts` and `RootNavigator.tsx` are outside the three allowed folders. The screens derive
   locale from the device direction, so Arabic text and RTL render correctly on an Arabic device
   without those edits; however the MSG-06 service notice and the instruction projection are only
   rendered when a host supplies `Conversation.serviceNotice` / `Conversation.instruction`, which
   the current loaders do not. A follow-up story in the app layer should pass those fields and mount
   `ConversationThread` from the Messages tab. Recorded, not silently worked around.
2. **Tab bar.** The real Visits/Reports/Messages/Account bar is owned by `RootNavigator.tsx` and
   `app/tabs.ts` (out of scope). `ScreenFrame` provides an opt-in standalone bar so the approved
   phone-frame design can be rendered and tested without drawing two bars in the live app. The
   shell's Arabic account label is `الحساب` while the picture shows `حسابي`; changing it is out of
   scope.
3. **Instruction acknowledgment.** The MSG-05 screen in `features/acknowledgments` is outside scope
   and English-only. The in-scope conversation thread adds a bilingual, revision-bound
   acknowledgment for the conversation instruction, with the revision in its accessible label.
4. **Card radius.** The contract's `radius.md` (8 px) is used instead of the picture's ~14 px;
   `docs/design/approved/README.md` says the token contract wins where the picture and contract
   differ.
5. **Raw colour removed.** `ConversationInbox.tsx` previously hard-coded `#0a7d3c`; the unread badge
   now uses `SCREEN_TOKENS.color.successText`. A structural test fails if a raw hex or physical
   margin/padding/text-align appears in any of the three screen files.
6. **Existing test changes (intentional, not weakened).** `reports-screen.test.tsx`: two presses moved
   from `getByLabelText('download-report-1')` to `getByTestId('download-report-1')` because the
   control's accessible label is now the human word `Download PDF` rather than a machine token
   (the same control is still pressed and the same callback assertion remains); one correction
   assertion became a regex because the amber note box wraps the correction word. No test was
   deleted, skipped or made vacuous, and all other existing assertions are unchanged.
7. **Root gate environment artifact.** `bash scripts/check.sh` fails at `check-pack` on the stale
   skip-worktree `opencode.json` in this worker (evidence under Test evidence). It is unrelated to
   this change and was not modified here.
8. **Direction lifecycle.** RTL is a restart-time native flag (`app/direction.ts`); locale-specific
   copy works without restart through the screen's resolved locale, but true layout mirroring of the
   native navigator still needs the existing app-level restart behaviour. No new nested direction
   override was added beyond the screen frame's single `direction` style, matching the existing
   conversation/report convention.

## Lessons for workers

- In React Native Testing Library, `toHaveTextContent` is an exact match: a status pill whose glyph
  is a child text (`▦المواعيد`) needs a regex. A `ScreenFrame`'s `props.style` is an array, so assert
  direction with `expect.arrayContaining([expect.objectContaining({ direction: 'rtl' })])`.
- A `testID` is not a screen-reader label. Give every Pressable both `accessibilityRole="button"`
  and a human `accessibilityLabel`; `getByLabelText` will not find a bare `testID`.
- Arabic tab labels come from `appText(locale, …)`, so tests that assert a tab label must use the
  locale-aware Arabic string, and the standalone tab testID is `tab-button-appointments`, not
  `tab-button-visits`.
- With `verbatimModuleSyntax`, import `jest` from `@jest/globals` and all types with `import type`
  in every new test; `noUncheckedIndexedAccess` makes every optional value a coverage branch, so
  write the "absent" fixture before claiming 100%.
