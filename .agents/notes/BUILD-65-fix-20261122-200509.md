## Lessons for workers

- `scripts/check-constraints.py` scans **added** lines against the merge base: a
  suppression in a brand-new file fails the gate because the whole file is added.
  Before adding `@SuppressWarnings`, prove it is needed with
  `javac -Xlint:unchecked -Werror -proc:none`; if it is not, delete it.
- Deleting an added suppression is the correct "remove it and fix the cause" remedy;
  never replace it with an exclusion, `# pragma`, `.skip`, `@Disabled` or a lowered
  threshold — the constraint gate rejects those too.
- `check-verdicts.py` requires `## Review verdicts` with GO from code-reviewer,
  coverage-auditor and devsecops as soon as any non-documentation file is in the diff.
  Run the three reviewers on the final diff and copy their real last lines.
- A swarm worker must not run `coverage-check.sh` or full `mvn verify` (the script calls
  `mvn verify` for any `apps/api/` change and times out the run). Use targeted
  `-Dtest=...` plus the individual policy scripts; leave the full gate to the integrator.
- In a cloud worker, `git ls-files -v opencode.json` = `S` explains `test_check_pack`
  and `worker-check.sh` failures; verify with `git show HEAD:opencode.json` and never
  regenerate or commit that file on a later pass.
