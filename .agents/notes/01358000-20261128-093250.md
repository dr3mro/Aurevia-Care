## Summary

A bounded base-advance retry is an expected, handled outcome, not a broken publication step. `integrate-publish` now emits one explicit `publication_state` (`published`, `noop`, `deferred`, `failed`); `deferred` exits 0 while terminal failures still exit 1. `reconcile`, `resolve`, the bounded re-dispatch and the caller's wave loop re-gate on that state instead of treating every green publish as a merged batch. The allow-listed `integration_retry` JSON is unchanged and remains the sole retry authority.

The trusted publish job verifies the bundle tip and every PR head SHA before writing. Retry authorization stays with the existing allow-listed `integration_retry` JSON (`base_advanced`, 40-hex base, positive integer PR ids, attempt 0). No new audit event, tenant, role or patient scope; no patient data or credential in any output, test or note.

## Migration and rollout considerations

The CLI and workflow gates land in one commit so a green deferred publish can never satisfy the old `needs.publish.result == 'success'` gates. No force push, no protected-branch bypass, no change to permissions, concurrency or the attempt cap. A fully skipped publish emits no state and all consumers skip (fail closed); the existing hourly safety-net wave is the recovery path.

## Findings

- A pre-existing post-push failure (for example a `gh pr comment` after the push succeeded) still reports `failed`; it is unchanged here because making reporting best effort is a separate behavior change.
- A fully skipped publish now stops the wave loop where the old success gate continued it. This is the intended fail-closed tightening; the hourly safety-net wave remains the recovery path.
- No product defect meeting BUGS.md criteria was observed.

## Lessons for workers

Keep descriptive CI outputs strictly separate from authorization: a four-value state string can drive gating decisions but the allow-listed JSON must remain the only thing that can start a retry. Emit the state at the single trusted boundary and assert exactly one output line, otherwise a second emitter or a missing path silently changes downstream behavior. Locally, `-I` hides the user-site PyYAML needed by the workflow contract tests; run those without `-I` and record the environment limitation rather than changing the canonical command.
