# START-02 — Patient app: English and Arabic message parity test

## Summary

Added one new test-only file, `apps/patient-mobile/src/app/messageParity.test.ts`. It discovers both patient-app message bundles (`app/messages.ts` and `features/attachments/messages.ts`) through their exported key lists and lookup functions, materialises the English and Arabic maps, and enforces the localization contract from `docs/design/rtl-and-localization.md` section 8: identical key sets, no empty values, identical named `{placeholder}` sets, and Arabic letters in every Arabic value unless the exact value is an allow-listed code or number. Every failure message names the bundle and key. A synthetic broken bundle is checked too, proving all four rules actually fire. No message bundle was changed.

Acceptance mapping: both bundles have identical en/ar keys, non-empty values, matching placeholder names, and Arabic script in Arabic values except the documented code allow list. Proven by `English/Arabic message parity > passes every parity rule for each real message bundle`.
- **PAT-01** — patient-app surface labels (shell and attachment review). Acceptance mapping: both patient-facing bundles are enumerated and checked, with a length guard so a newly added bundle must be registered in the test.

## Findings

1. **Real gap, allow-listed, bundle unchanged:** `apps/patient-mobile/src/features/attachments/messages.ts`, key `checksum`, Arabic value is `SHA-256` — no Arabic letters. It is a shared algorithm code, not translatable text. Allow-listed by exact value in `ALLOWED_UNTRANSLATED_VALUES` with an explanatory comment. No bundle was edited.
2. **No other real gaps:** `app/messages.ts` (28 keys) and `features/attachments/messages.ts` (30 keys) have matching en/ar key sets, no empty values, and at least one Arabic letter in every other Arabic value. Neither bundle contains `{placeholder}` tokens today, so the placeholder rule passes for real bundles by equality of empty sets; the broken sample exercises the mismatch branch.
3. **API limitation (honest scope note):** both bundles keep `labels` module-private and expose only a key list plus `appText`/`attachmentText`. The checker therefore compares the maps materialised from the exported key list; for real bundles identical keys are also guaranteed structurally by `Record<Locale, Record<Key, string>>`. Extra keys that are not in the exported key list cannot be observed through the public API. The broken sample passes two independent maps, which proves the checker does detect a genuine en/ar key mismatch.
4. **Future bundles:** `REAL_BUNDLES` is an explicit list with a `toHaveLength(2)` guard, so adding a third bundle fails this test until it is registered here. There is no runtime bundle registry to enumerate automatically.
5. Only two `messages.ts` bundles exist under `apps/patient-mobile/src`; no other bilingual dictionary was found (`grep -rn "ar:" --include=messages.ts` matched only these two files).
6. `scripts/check.sh` cannot pass in this cloud worker because the skip-worktree CI `opencode.json` profile fails `check-pack`; this is pre-existing and unrelated to the two new files. Trusted integrator/Delivery runs should judge the committed HEAD profile.
7. Specialist review findings (reviewer evidence, `aurevia-senior-mobile`): **F1** key parity is structurally guaranteed by `Record<Locale, Record<Key,string>>` and the broken sample proves the runtime check fires, so the real-bundle key loop is defensive rather than load-bearing — mitigated by the documented limitation in item 3 (exporting raw maps is out of scope). **F2** the original `[\u0600-\u06FF]` regex also matched Arabic-Indic digits and punctuation; adopted the fix, now `[\u0621-\u064A\u066E-\u066F\u0671-\u06D3\u06D5\u06FA-\u06FC\u06FF]` (letters only). **F3** doc comment attributed empty-value and Arabic-letter rules to localization §8; corrected to §8/§9.9 plus "two safety rules defined here". Reviewer also flagged `match[1] ?? ''` as an unreachable `??` branch in a test helper; removed by switching to `value.match(...) ?? []`, whose `[]` side is exercised by real bundles with no placeholders.

## Lessons for workers

- Both patient bundles keep `labels` unexported: build the comparison from the exported `appMessageKeys`/`attachmentKeys` plus `appText`/`attachmentText` rather than importing the map.
- `bash apps/patient-mobile/check.sh` installs from a cold `node_modules` in ~25s and is fast enough to run directly; it is the single canonical gate (typecheck + lint + Jest 100%).
- Test files are excluded from Jest coverage, so a test-only story cannot change global coverage; still map every checker branch to an assertion as AGENTS.md requires.
- Use `noUncheckedIndexedAccess`-safe indexing (`value === undefined` guards and `match[1] ?? ''`); the module compiles with `strict`, `noUnusedLocals` and `noUnusedParameters`.
