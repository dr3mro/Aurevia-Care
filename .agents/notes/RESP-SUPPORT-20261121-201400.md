# RESP-SUPPORT — Staff web: phones and tablets count as supported widths

## Summary

Lowered the staff-web browser-support floor from 768 px to 320 px and extended
the supported client matrix to mobile engines, per decision 0004. `isSupportedBrowser`
now recognises iOS Safari and the WebKit browsers on iOS (Chrome, Firefox and Edge)
by the **iOS version** rather than their stale `CriOS`/`FxiOS`/`EdgiOS` tokens,
and keeps Chrome, Firefox and Edge on Android under their existing engine baselines.
Internet Explorer and unknown engines still fail closed. Doc comments and the
synthetic test matrix were updated; no production logic branch was added or removed.

Scope honoured: only `apps/staff-web/src/features/system/browserSupport.ts` and
`apps/staff-web/tests/features/system/browserSupport.test.ts` were changed.

## Affected requirements

- WEB-07 — supported clients / unsupported-browser plain message; browser matrix.
- UX-01 — WCAG 2.2 AA reflow at 320 CSS px (decision 0004 constrains the 320 px floor).

Decision: `docs/decisions/0004-responsive-staff-web.md`. NOTE: WEB-07 in
`PROJECT_V1_SPEC.md` still states 1280/768 px and must be amended by a person;
the swarm may not edit the specification (decision 0004, "Consequences and evidence").

## Findings

1. **Pre-existing committed contract drift (blocks `apps/staff-web/check.sh`, out of
   scope).** At HEAD, `git show HEAD:contracts/openapi.yaml | grep -c 'order-entry/drafts'`
   → `3`, while `git show HEAD:apps/staff-web/src/api/generated/openapi.d.ts | grep -c
   'order-entry/drafts'` → `0`. A generated diff to `/tmp/opencode/generated-openapi.d.ts`
   shows 376 diff lines of missing order-entry paths. Therefore `npm run gen:api:check`
   (step 1 of the module check) fails on this branch regardless of this story. Only the
   two in-scope files are modified (`git status --short`). A regeneration task is
   requested below; it was NOT performed because `src/api/generated` is outside scope.
2. **Root check artefact in workers.** `bash scripts/check.sh` stops at
   `check-pack: opencode.json is stale: run scripts/gen-opencode.py`. MEMORY.md
   (dispatch-3 finding) records that a worker's worktree `opencode.json` is the CI
   profile copied under `skip-worktree`, so `check-pack.py` judges that profile, not
   `HEAD`. Not caused by this story; `opencode.json`, `.opencode/` and `scripts/`
   are forbidden worker edits, so no change was made.
3. **iPad "Request Desktop Website" UA (non-blocking, not in the required matrix).**
   A desktop-mode iPad reports a Macintosh UA with a stale `Version/` and no
   `CPU … OS` token, so it falls to the desktop Safari rule and can be rejected.
   The senior-react reviewer raised this (Low). No reliable token distinguishes it
   from a genuinely old Mac Safari, and accepting stale Mac Safari would weaken
   WEB-07's old-version rule, so no production rule was added; the required iPad
   UA (`iPad; CPU OS 17_0`) is supported and tested at all six widths.
4. **Specialist review provenance.** `aurevia-senior-react` (session
   `ses_e003f0a33ffea9rcGST1gJnHz0`) had read-only tools and could not run git or

## Lessons for workers

- In a worker, a red `apps/staff-web/check.sh` at `gen:api:check` may be pre-existing
  contract drift, not your change: verify with `git show HEAD:contracts/openapi.yaml`
  versus `git show HEAD:apps/staff-web/src/api/generated/openapi.d.ts`, then run the
  module's remaining steps individually instead of regenerating out-of-scope files.
- All iOS browsers use WebKit and may advertise stale `CriOS`/`FxiOS`/`EdgiOS`
  versions; match `CPU (iPhone )?OS <major>_` before the generic engine rules so
  they are judged by the OS version. Android engines reuse the `Chrome`, `Firefox`
  and `EdgA` rules.
- Root `check.sh`'s `check-pack` step reads the CI-profile `opencode.json` in workers;
  cite MEMORY.md instead of regenerating a forbidden file.
