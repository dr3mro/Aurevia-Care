The feature: `AccessionsPage` renders a state-filtered, cursor-paginated accession
worklist plus a requisition-accession form that shows the issuer-scoped accession
id after creation. `AccessionDetailPage` (`/lab/accessions/:id`) shows the current
accession and immutable event history and offers only commands the LAB-01 state
machine allows for the current state. Reject requires a reason; a successful
recollect links the new specimen. All data is synthetic and every request is
tenant-scoped.

## Lessons for workers

- Self-registering feature routes break the two exact-route-list assertions in
  `src/app/routes.test.tsx` and `tests/app/AppShell.test.tsx`. The durable fix is
  FIX-ROUTES-01 (derive expectations from `collectFeatureRoutes`), not per-feature
  array edits that conflict across parallel workers.
- A new `features/<name>/routes.ts` needs a `routes.test.tsx` that renders each
  lazy page component, otherwise the lazy import functions are the only uncovered
  lines and the 100% per-file gate fails.
- To prove 100% coverage of an owned feature while an unrelated test is red, run
  `npx vitest run --coverage --coverage.include='src/features/<name>/**/*.{ts,tsx}' --exclude 'e2e/**' src/features/<name>`.
- In page tests that mock `send`, use `mockResolvedValue(view)` for the initial
  GET view, not a `mockResolvedValueOnce` that an extra mount call can consume.
