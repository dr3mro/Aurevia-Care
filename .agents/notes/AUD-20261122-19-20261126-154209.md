# AUD-20261122-19 — Consolidate patient credential storage behind one sign-out-safe store

Tested revision: fa0e8048bc506101d9170a24d7156965f43d78a3

## Summary

Consolidate the two patient credential stores behind one canonical OS-backed
session store so sign-out or device revocation from either entry point removes
the token and every in-memory clinical payload, even when native deletion
fails. Closes the PAT-02 credential gap recorded by the 2026-11-22 daily audit.

### senior-mobile (reviewer proposal, VERDICT: GO)

- Proposed a single canonical store with a small `platformSecureStore` wrapper
  that adds `{ requireAuthentication: false }` inside its `setItemAsync`, so the
  canonical store always calls the adapter's 2-arg shape. This preserves
  `tokenStore.test.ts:50` (native 3-arg) and `report-core.test.ts:98`
  (injected 2-arg) simultaneously, with no options branch to cover.
- Confirmed the native call shape does not regress on iOS or Android: the
  platform module still receives `(key, value, options)` on save and `(key)` on
  get/delete; `requireAuthentication: false` is the library default on both
  platforms and the reports save path only makes that default explicit.
- Warned that `try/finally` must not become sequential await or `catch`: the
  cache clear must survive a failed delete, and the native error must still
  propagate at the API boundary. `RootNavigator.tsx:362-367` in fact swallows
  that error with `.catch(() => undefined)` (QA correction); its fail-closed
  behavior comes from the `finally` clear, not from propagation.
  `idleSession.ts:10` uses the same bound function.
- **Conflict resolved:** the specialist's preferred canonical location was
  `features/reports/credentials.ts` with `api/tokenStore.ts` as a shim, but it
  flagged the features→api layer inversion. The brief and the layer direction
  both require the opposite, so the adopted shape is its documented Option C:
  canonical factory in `api/tokenStore.ts`, thin adapter in `credentials.ts`.
- Additional read-only regression file found:
  `src/spec/patient-access/protect-local-credentials-os-backed-storage.test.ts`
  asserts both call shapes, the blank guard on both stores, deletion through
  both entry points and cache clearing when the native delete rejects.
  It is kept green and is not edited.

### senior-typescript (reviewer proposal, VERDICT: GO)

  (`verbatimModuleSyntax` requires the `type` form). Existing type-only
  imports from `./credentials` keep working.
- Keep `setItemAsync(key, value)` at exactly 2 args in the interface. Expo's

- `platformSecureStore` wrapper adds `STORE_OPTIONS` inside its own
  `setItemAsync`; the canonical store always uses the 2-arg seam.
  `new SecureCredentialStore()` keeps `= SecureStore` (raw 2-arg native calls),

- Lint/strictness: explicit return types, `async` only where `await` exists,
  type-only import/export, no optional properties in new types so
  `exactOptionalPropertyTypes` is inert, no floating promises.

guidance, not a rule change; the story's "one canonical store" outcome is met.

## Lessons for workers

- Before making module A a runtime dependency of module B, grep for whole-file
  `jest.mock('…A')` factories. A mock with only the old exports turns any new
  import from B into `TypeError: … is not a function` in an out-of-scope suite.
  Keep the canonical implementation in a module no test replaces wholesale and
  let the mocked API module bind it.
- Run the RED/GREEN batch with `--no-coverage`: this module's Jest config
  enforces a global 100% threshold, so a two-file batch fails on unexecuted
  files even when the two files under test are perfect.
- Include out-of-scope mock suites (`RootNavigator*.test.tsx`,
  `providersApi.test.ts`, spec tests) in the targeted GREEN batch before the
  full gate. The full `check.sh` would have caught the mock break, but the
  targeted run localized it in seconds.
- Put native-only options inside the platform adapter, never in the canonical
  store: that keeps the injected 2-arg seam stable and removes an options
  branch from the coverage surface.
- Cite file:line precisely in the notes coverage table; a reviewer will check
  that the named test actually lives in the named file.
- Record what a caller actually does before paraphrasing a specialist's risk
  note: `RootNavigator` swallows the native delete error, so fail-closed comes
  from the `finally` clear, not from error propagation.
