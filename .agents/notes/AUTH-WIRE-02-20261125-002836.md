## Findings

1. The task's own brief says "Await these open prerequisites before implementation:
   AUTH-WIRE-01". That prerequisite is still open and its production gate is absent.
2. Strict two-way parity cannot pass on this checkout: 248 POST handlers vs 24
   catalog entries, and 5 catalog entries have no live route by documented design.
   A "short allow-list" cannot represent that gap; doing so would either add ~224
   unexplained entries or weaken the guard into meaninglessness.
3. Adding those catalog entries here would duplicate and conflict with
   AUTH-WIRE-01 and the per-family routing stories, all outside this task's scope.
4. This session's durable directive (`.opencode/config/MEMORY.md` lines 63-67 and
   the agent instructions) forbids Git and Git-backed operations. The worker brief
   asks for a local commit and `git merge --no-edit origin/main`; I did not run
   either. A trusted integrator must publish any change from this run.

## Lessons for workers

- Before designing a parity gate, count both sets with a tool. The catalog and the
  live handler set differ by an order of magnitude here; a naive set-equality test
  is guaranteed red and will consume the whole time budget.
- `OpenApiRouteCoverage` is the repository's model for build-failing route parity:
  pure comparator in `src/test`, Spring mapping for discovery, frozen baseline for
  known debt, and a unit test that proves the failure message names each gap.
- Maven's offline cache here lacks `surefire-junit-platform:3.6.1`; run targeted
  tests without `-o` in this worker image. A MOCK-web `SpringBootTest` discovery
  test works without PostgreSQL (2/2 green above).
- The catalog's five virtual paths are documented defects, not allow-list debt;
  suppressing them would hide test-enforced drift.
