## Plan

A self-contained, exported responsive messaging layout wrapper under the new `layout` folder: bilingual labels (`layoutText.ts`), a pure breakpoint/pane model (`layoutModel.ts`), a generic wrapper with a compact back action and sticky composer (`MessagingLayout.tsx`), an export surface (`index.ts`) and colocated tests. Existing `useBreakpoint`/breakpoint tokens are reused, not duplicated. MessengerPanel and MailScreen remain untouched because they are outside scope; a task request for their later adoption is included below.

`aurevia-plan-reviewer` first returned NO-GO with five Required gaps; all are resolved in the revised plan before any code was written:

1. Tablet pane count: `paneVisibility` now shows the auxiliary pane only at expanded, giving 3/2/1 visible panes; tests count visible `data-pane` regions, not grid tracks. Consumers compose folders and message list into the `list` pane node so no action is lost at medium.
2. 768 px reflow: every pane region carries `minInlineSize: 0` and `overflowWrap: 'anywhere'`; tests assert those and that all medium tracks are `minmax(0, 1fr)` with no fixed-px track. Painted scroll is a Playwright concern outside this scope and is labelled as such in the notes.
3. Keyboard model: the root is the named scroll container (logical `overflow-block: auto` / `overflow-inline: clip`, `maxBlockSize: 100dvh`, `scrollPaddingBlockEnd: calc(16rem + space.2)`, `display: block` to escape `.page`'s grid); the composer is its last sticky child (`position: sticky`, `inset-block-end: 0`). Tests assert the inline styles.
4. API fit: an optional `notices` slot sits between the title and panes for the emergency banner / synthetic notice / connection status; dialogs stay with the parent component.
5. Rotation (WEB-09 §9): no per-breakpoint early returns or breakpoint-derived keys; panes toggle with the `hidden` attribute so stateful children stay mounted. A test flips matchMedia compact -> medium -> compact and asserts stage and typed value survive.

Plan-review outcome: two NO-GO rounds (pane count/keyboard/notices/API-fit, then the matchMedia change-event mechanics), each fixed before coding; final `aurevia-plan-reviewer: GO`. The rotation test uses one stable stub `MediaQueryList` per query with captured `change` callbacks, because `useBreakpoint` only re-queries when the query string changes. Scroll root uses logical `overflow-block: auto` / `overflow-inline: clip` and a documented 16rem + space.2 composer reserve.

## Lessons for workers

- A breakpoint-flip test must mutate and dispatch `change` on one stable `MediaQueryList` object per query: `useBreakpoint` caches its snapshot until a change event, so re-stubbing `matchMedia` alone leaves the mounted component on the old breakpoint. Wrap the mutation in `act()` or React does not flush the store update before the assertion.
- React serializes numeric zero in inline styles as `0`, not `0px` (`inset-block-end: 0`), while `min-inline-size: 0` keeps its property name; assert the style attribute rather than a camel-cased getter for logical properties in jsdom.
- An explicit `role="region"` on a `<section>` with `aria-label` is redundant and fails the strict jsx-a11y config; the implicit region role already satisfies `getByRole('region', …)`.
- Split grid tracks with a regex, not `split(' ')`, because `minmax(0, 1fr)` contains a space.
