## Summary

One new test-only class at `apps/api/src/test/java/com/aurevia/events/EventsNegativePathsTest.java` (package `com.aurevia.events`) documents and locks the fail-closed failure signals of the `events` package. ## Lessons for workers

- Grep the whole test tree, including other packages such as `web/clauses`, before calling a negative path uncovered: the events package alone showed all five categories covered, and four proposed tests were duplicates.
- For a test-only story an honest red-first cycle cannot happen against unchanged production code: record the first green, invert one expected value temporarily, capture the named failure, restore from a `/tmp` copy and record the second green with the restored SHA. Never leave the mutation in the tree.
- Pin a role-denial branch with an active member of a non-permitted role, not an inactive or missing subject; otherwise the 403 comes from the membership branch and proves the wrong rule.
- A cross-tenant caller must hold an active permitted role in the peer organization to reach the 404 concealment path, because `authorize` runs before `requireEvent`.
- Fill `Test evidence`, `Coverage` and `Review verdicts` before requesting post-code reviews; reviewers read the note when they run, and an empty section draws a NO-GO about stale notes rather than the code.
