## Findings

Reviewer evidence (not tool evidence) from the pre-code plan review:

- Required: the dependency has failed; stop and request READY-41 completion. Any implementation
  now either references a missing bean (breaking ~215 Spring contexts) or substitutes a sink the
  OPS-02 contract does not accept.
- Required: the catalog/route contradiction must be resolved before an interceptor exists.
  There are far more than two dozen real `@PostMapping` handlers, controller bodies carry no
  `command` field, and the synthetic catalog does not map to them. Denying unmapped POSTs breaks
  most endpoints; allowing them leaves the gate inert.
- Required: acceptance 4 ("assert a decision row") needs the durable ledger and an HTTP test
  through production Spring wiring, not standalone MockMvc plus `InMemoryDecisionSink`.
- Required: `StaffRepository.activeRoles(subject)` and `hasActiveMembership(subject)` have no
  organizationId; interceptor ordering, transaction wrapping and a cross-tenant negative test
  must be specified before using them.
- Required: deny statuses are not uniform (`422 UNKNOWN_COMMAND`, `500 DECISION_NOT_RECORDED`,
  `403 FORBIDDEN`) while the story says 403 on deny; each code needs an explicit mapping and test.
- Required: a sink failure throws inside `record()`, so no decision row can exist for that case;
  acceptance 4 cannot hold for every scenario without a fallback recording path.
- Required: enumerate every new branch and its named test before claiming 100% coverage.
- Required: do not substitute `AuditRepository` for the append-only `authorization_decision` ledger.
- Optional: a partial slice must be labelled "Why this is not finished" with the task left open.

- READY-41 is the hard dependency and has failed 26 times. There is no production `DecisionSink`
  bean, no `V65` table with RLS/FORCE RLS, and no durable row to assert in a test.
- The synthetic command catalog is not a route map for the delivered API. Realignment touches
  generated contract artifacts outside this scope and an existing "24 commands" assertion.
- A global POST interceptor would deny the majority of delivered endpoints once activated;
  a catalog-path-only interceptor would not run for most commands. This needs an owner decision
  on the allow-list that AUTH-WIRE-02 is meant to enforce.
- The sink-failure scenario is self-contradictory as written: `CommandAuthorization.record()`
  throws on sink failure, so that request has a denial but no recorded decision row.

## Lessons for workers

- Check the actual state of a named prerequisite (`tasks/<id>.md` mark, `attempts`, release commits,
  and the promised files/beans) before accepting a brief's "already added" claim; a `[-]` task with
  a failed release history is not a delivered dependency.
- Do not add a required bean to a Spring context that 215 existing `@SpringBootTest` classes load;
  check the bean's existence and the context count first.
- A synthetic catalogue generated into a contract is not a route allow-list. Verify that catalog
  paths match real `@PostMapping` routes before designing handler-to-command resolution.
- The `subagent` tool's agent IDs are unprefixed; the `aurevia-` form is only a notes convention.
