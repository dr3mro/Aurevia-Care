# TRACK-02 — Patient app: "Where is it?" tracker for prescriptions, lab tests and imaging

## Summary

Added a self-contained patient-facing tracker feature under `apps/patient-mobile/src/features/tracker`. It renders one plain-word step line per tracked item (prescription, lab test, imaging) from the facts the server released to the patient. Hidden workflow facts never appear. Labels and layout are bilingual (English/Arabic) and direction-aware, and an in-memory `TrackerCache` discards every tracked item on sign-out. Test-first: red tests were written before any production file, then implemented to green.

## Affected requirements

- **PAT-02** — released reports/results presented to the patient; no persistent clinical cache; confirm intent (here: plain-word released-step presentation only, no download added).
- **XCH-03** — recipient/version/release facts projected as an ordered, patient-visible step line; unreleased facts stay hidden.
- Supporting: **UX-01** — English/Arabic parity and right-to-left layout.

## Findings

- **Necessary one-line scope exception (transparently recorded):** adding any new folder under `apps/patient-mobile/src/features` makes `src/features/domain-layout.test.ts` fail because it hard-codes the approved feature-directory list. This gate cannot be green without registering the folder. I added exactly one line (`'tracker', // TRACK-02 …`) to that governance test. This follows the merged precedent of BUILD-53 / PR #308, which added `'notifications'` to the same list in the same PR despite a similarly narrow `features/notifications` scope. I did not change any other out-of-scope file, and no tracking file (`TODO.md`, `MEMORY.md`, `WORKSPACE.md`, `BUGS.md`, `PROJECT.md`) was touched. First `check.sh` run failed only on this test (1 failed / 567 passed); after the one-line registration it was 568/568 green.
- **Defects found:** none in the new feature. Environment noise only: npm printed deprecation warnings for transitive dev dependencies, and the root `scripts/check.sh` pack check hit the `opencode.json` skip-worktree false positive described above (OPS-CW-003-01); no threshold, dependency, config or protected file was changed.
- **Decisions:** step labels are keyed by `itemKind.step` in a flat bilingual table (reuses the existing `Locale` type from `app/messages` and the server's canonical step wire keys from TRACK-01 rather than inventing a new vocabulary). The step separator is a separate text node so each step's accessible label is the plain word alone.

## Lessons for workers

- A new patient-mobile feature folder must be registered in `apps/patient-mobile/src/features/domain-layout.test.ts`'s `DOMAIN_FOLDERS`; otherwise `bash apps/patient-mobile/check.sh` fails on the layout invariant even when all feature tests and coverage are green (precedent: BUILD-53 / PR #308).
- `toHaveTextContent` in `@testing-library/react-native` is an exact match: when a step is preceded by a `›` separator, keep the separator in its own `Text` so the plain-word label assertion stays exact.
- `render(...).rerender(...)` returns `void`, not a fresh view object; assert against the original `view` after calling `await view.rerender(...)`.
- A defaulted prop (`locale = resolveScreenLocale()`) is a coverage branch — add a render test with the prop omitted or the module's branch coverage stays below 100%.
