## Lessons for workers

- Before adding a negative-path test, list what the neighbouring `it/clinical` suites already assert; the value here is the combined controller→real-service boundary, exact machine codes and audit outcomes, not a new validator.
- A mock-backed "other tenant" test proves control flow, not RLS. Say so in the class Javadoc and cite the real-PostgreSQL concealment test instead of calling the mock isolation evidence.
- For a test-only story, a red→green cycle cannot happen honestly. Invert one expected value in the new test, run the targeted suite to observe the named failure, restore it, and rerun green; record both commands.
- In a cloud worker, `.opencode/opencode.json` is a skip-worktree CI profile. `check-pack.py` and `gen-opencode.py --check` compare the committed blob and pass, while a unittest that reads the worktree file directly fails; report both, never regenerate protected files from a worker.
- `python3 -I -m unittest discover -s scripts/tests` can fail on unrelated sandbox fixtures (daily archives, process reaping). Rerun the failing module alone, record the exact final line, and do not weaken a test to make it green.
