## Summary

Fix pass on the committed BUILD-31 work. The prior commit already added
`JdbcTherapyStore`, made `TherapyService` an injected Spring bean, moved the
synthetic `InMemoryTherapyStore` to `src/test` and added the reserved V85
migration. Critical review of the persisted aggregate found one real defect in
the JDBC adapter that the prior unit tests did not detect: **goals were written
to `therapy_goal` with `goal.description().hashCode()` as the row ordinal**.

`therapy_goal.ordinal` is the clinical plan order (`GOAL_COLUMNS` reads with
`ORDER BY g.ordinal`, and V77 keys the table on `(organization_id, episode_id,
ordinal)` with `CHECK (ordinal > 0)`). A hash is neither ordered nor positive
nor unique: the RED test observed ordinals `[-1441088475, 1228489237,
-1441088475]`. Consequences before the fix:

- goal clinical order was lost on a save/reload round trip;
- two goals with the same description collided, and `ON CONFLICT DO NOTHING`
  silently dropped the second goal from durable storage;
- a description with a negative hash violated `CHECK (ordinal > 0)` and would
  fail a legitimate clinical command with a 500.

Fixed test-first: the goal loop now allocates sequential positive ordinals
(`int goalOrdinal = 0; … addValue("ordinal", ++goalOrdinal)`), the same rule
already used for evaluation problems. Added a deterministic unit test and an
end-to-end PostgreSQL integration test. No dependency, migration, threshold,
exclusion or file outside the declared scope was changed.

## Lessons for workers

- When a domain list is persisted with an `ordinal` column that is read back
  with `ORDER BY`, allocate sequential positive ordinals; never use a content
  hash (it destroys order, collides on duplicates and can breach a `> 0` CHECK).
- A mocked-JDBC unit test that counts UPDATE calls can miss the *values* bound
  to a statement. Capture `SqlParameterSource` with an `ArgumentCaptor` and
  assert the concrete parameters (here the ordinals), not just that SQL text
  containing the table was issued.
- Cover the durability half with a real-PostgreSQL round trip: a unit test
  cannot prove that `ON CONFLICT DO NOTHING` silently dropped a colliding row,
  but reading three goals back through the controller/service path can.
- Treat `scripts/check.sh` / `apps/api/check.sh` as forbidden in worker mode
  (they reach `mvn verify` and every integration suite). Run targeted
  `-Dtest=… test`, `jacoco:report`, `db/check.sh`, SpotBugs and the policy
  scripts individually, and record the exact commands.
- In a cloud worker, `check-pack.py`/`gen-opencode.py`/`test_check_pack.py`
  staleness of `opencode.json` is the known skip-worktree CI-profile artifact
  (`git ls-files -v` shows `S`), not a defect in the diff.
