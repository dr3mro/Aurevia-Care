# RESP-BUTTON — Staff web: responsive `Button` component

## Summary

Made the shared `Button` opt into the existing responsive contract without new CSS:
it now carries the stylesheet's `.touch` class (24 px fine / 44 px coarse target on
both axes), uses logical inline properties for padding, text alignment and label
wrapping, keeps a logical scroll margin so a focused primary action is not hidden by
the on-screen keyboard, and exposes the resolved breakpoint as `data-breakpoint`.
The inline `minHeight: '32px'` was removed because it outranked the `.touch` 44 px
coarse rule in the block axis. Added a parameterized jsdom suite that drives the
real breakpoint hooks with a synthetic `matchMedia` at compact, medium and expanded
and asserts structure, labels, roles, keyboard order, wrapped long English and
Arabic labels, touch membership and the right-to-left case at every width.
No exported name, prop, text, click handler or API call changed. Synthetic fixtures
only — no patient data, credentials or network calls.

## Affected requirements

- WEB-07: supported responsive layout from 320 px upward with compact (0–767),
  medium (768–1279) and expanded (1280+) breakpoints (ADR-0004 supersedes the old
  768 px floor in the specification text; owner amendment still pending).
- UX-01: WCAG 2.2 AA presentation — 44 × 44 CSS px coarse-pointer targets, logical
  properties that mirror under RTL, long English/Arabic label wrapping, reflow
  without horizontal page scroll, text scalable to 200% and a reachable primary
  action.

## Findings

- **Wrapper `check.sh` blocked by pre-existing generated-client drift (tool
  evidence, out of scope).** `git status` shows only the two in-scope files changed.
  Generating to `/tmp/opencode/generated-check.d.ts` and diffing against
  `src/api/generated/openapi.d.ts` shows `contracts/openapi.yaml` now carries
  `/api/v1/printing/handouts` and `/api/v1/printing/handouts/download` (operation
  `printHandout` / `downloadHandout`) that the checked-in client lacks. This is the
  same class of drift recorded in `RESP-BREAKPOINTS`/`RESP-STYLESHEET` notes, with
  different paths; it predates this story and neither contract nor generated file
  was touched.
- **Inline `minHeight` conflict resolved.** The old `minHeight: '32px'` outranked
  `.touch`'s `min-block-size: 44px` under `@media (pointer: coarse)`, giving a
  44 × 32 px button. Deleting it leaves both floors to `.touch`; the fine-pointer
  floor drops from 32 px to the documented 24 px general floor.
- **`useBreakpoint` cost.** Every `Button` instance now subscribes to two
  `matchMedia` listeners. Acceptable for this slice; a shell-level breakpoint
  context (one subscription shared by all buttons) is the better long-term design
  and belongs to a separate story.
- **Safe-area insets** are correctly owned by `.page`/`.app-shell`/`.sheet` in
  `responsive.css`; a leaf button at a viewport edge is not expected to add its own
  safe-area padding. The button uses only logical properties so it composes with
  those containers.
- **Keyboard reachability** is only partially addressable in a leaf button:
  `scrollMarginBlockEnd` keeps a focused button clear of a sticky footer, but the
  sticky footer and `scroll-padding-block-end` belong to the form/shell boundary
  (design §8) and cannot be proven in jsdom (design §13).
- ADR-0004 is still `Proposed` and `PROJECT_V1_SPEC.md` WEB-07 still states the
  old 1280/768 floors; code follows the decision as the story instructed and the
  owner amendment remains pending (inherited finding).

## Lessons for workers

- jsdom 25 *does* serialize logical properties (`padding-block`, `padding-inline`,
  `min-block-size`, `min-inline-size`, `scroll-margin-block-end`, `text-align: start`)
  into the style attribute, so assert those directly; still avoid painted-pixel claims.
- Mock `matchMedia` per query string with `vi.stubGlobal` and restore with
  `vi.unstubAllGlobals()`; read query strings from `BREAKPOINT_MEDIA_QUERIES` instead
  of hard-coding them. Wrap `change` dispatches in `act()` or React logs a warning.
- Never add an inline size that competes with `.touch`: inline `minHeight` or
  `minInlineSize` beats the stylesheet's coarse 44 px rule and silently breaks the
  touch target. Assert `style.minHeight`/`style.minBlockSize`/`style.minInlineSize`
  are empty to prevent a regression.
- `responsive.css` has no shared interactive-control class. Wrapping
  (`min-inline-size: 0; overflow-wrap: anywhere`) is granted only to children of
  layout containers; a standalone button needs logical inline styles. A reviewable
  `.control` class in a separate stylesheet story would remove that duplication.
  Do not edit the stylesheet from a component story (the story forbids it).
- A JS breakpoint hook in a leaf control costs two `matchMedia` subscriptions per
  instance; prefer a shell-level breakpoint context when wiring more controls.
