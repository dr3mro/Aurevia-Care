## Lessons for workers

- A mocked repository returning `Optional.empty()` proves only the service's concealment *decision*, not PostgreSQL forced RLS. Say so in the notes and point to the real-PostgreSQL test; never claim the mock proves isolation.
- For a test-only story there is no production red→green. Prove sensitivity instead: invert one expected literal, run the targeted suite, record the named failure with expected/actual, restore the file, verify byte equality with the backup and rerun green. That is the equivalent of a red observation and takes seconds.
- When a positive control is added to a tenant-concealment test, scope the "no history read/no write" assertions to the peer request (the owner's successful read legitimately calls `history`); use a call count or `clearInvocations` so the assertion still fails on a genuine peer leak.
- Fill `Test evidence`, `Coverage` and `Review verdicts` before requesting post-code reviews: reviewers read the note when they run, and an empty section produces a stale-notes NO-GO about the note rather than the code.
