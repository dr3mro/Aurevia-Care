# START-51 — Negative-path and tenant-isolation tests for `documents`

## Summary

Add one new test class, `apps/api/src/test/java/com/aurevia/documents/DocumentsNegativePathsTest.java`, recording **assertion-strengthening
evidence** for the existing `documents` API: machine-readable error codes at the real controller boundary, exact audit outcomes for
denials and foreign-tenant reads, branch-specific compare-and-set failures, and `verify`-level proof that content-based retries do
not write twice. This story adds evidence only: no production code, route, contract, migration, dependency, threshold or existing
test changes. The pre-code reviews established that the production branches are already covered elsewhere; this class raises the
strength of the assertions rather than duplicating branch coverage.

## Affected requirements

CLN-07 (link originals, retain bytes, void with reason, versioned PDFs), ARC-02 (tenant context from authentication, policy in
application services, fail closed when context or membership is absent).

## Risk class

Cross-boundary verification of two HTTP entry points (`DocumentController`, `DocumentArtifactController`) and their domain
services. Safety-critical evidence for tenant isolation and wrong-role denial; no production boundary is changed.

## Review owner

Orchestrator / integrator. Read-only reviewers: plan-reviewer, test-engineer, senior-backend (pre-code); code-reviewer,
coverage-auditor, devsecops and qa-reviewer (post-code).

## Data changes

None. No Flyway migration, RLS change, backfill, table or contract edit. All fixtures are synthetic UUIDs and payload metadata;
no patient identifiers or credentials.

## Authorization boundaries and audit events

No new boundary. Tests assert the existing behaviour: `DocumentService.authorize` denies absent membership and missing role with a
`DENIED` audit and 403; a foreign-tenant identifier resolves empty and yields 404 with a `NOT_FOUND` audit and never a `SUCCESS`
audit; `DocumentArtifactController.actor()` fails closed for a patient role (403) and a null context (401); `PdfBindingService.validateRevision`
records a 403 `WRONG_TENANT` `ACCESS_DENIED` fact carrying only the synthetic revision identifier and no payload, checksum or foreign
organization.

## Migration and rollout considerations

None — test-only change on the existing branch.

### Corrected plan (all Required gaps addressed)

1. Through `DocumentController.link`/`render`, assert **status + code** for one representative of each distinct `DocumentInputs`
   guard: INVALID_ID, INVALID_SUBJECT_TYPE, INVALID_MEDIA_TYPE, INVALID_FILE_NAME, INVALID_CONTENT, CONTENT_TOO_LARGE,
   INVALID_LINES, INVALID_TITLE. These codes are not asserted by `DocumentInputsTest` (status only) or the HTTP clause tests.
   No rotation/locale/reason cases (named-neighbour duplicates).
2. Wrong role through public entry points only: `render` with inactive membership and `voidAssociation` with a role lacking the
   permission — assert 403 FORBIDDEN plus the `DENIED` audit. Patient-role 403 and null-context 401 through public
   `requestRender`/`bind`/`release` commands instead of the already-covered complete/download.
3. Foreign-tenant: mocked repository empty for `association`/`rendered`/`renderedContent` → 404 NOT_FOUND with a `NOT_FOUND`
   audit and **no SUCCESS audit**; WRONG_TENANT via public `requestRender` with fact detail `WRONG_TENANT`, `resourceId` = synthetic
   revision id, no checksum/payload/foreign org.
4. Genuine CAS gaps: `voidAssociation` with an active association at the expected version and `repository.voidAssociation(...)=0`
   → 412 STALE_VERSION, verified by `verify(repository).voidAssociation(...)`; `link`/`render` `DuplicateKeyException` → 409
   CONFLICT with no event/audit.
5. Content-based replay only, with `verify` call counts: repeat `requestRender` returns the same jobId with exactly one
   `putPdfJob`; repeat `bind` with the existing binding returns the original with no second `putPdfBinding`; repeat `release` with
   a prior decision returns the original with no `insertReleaseIfAbsent`. Every `release` case explicitly calls
   `roles(CLINICIAN, "clinician")` and `useTenant(ORG_A, CLINICIAN)` first, because `DocumentActions` grants RELEASE only to
   clinician/privacy_auditor and the fixture default `document_reviewer` would return 403. Do not assert an `Idempotency-Key`
   header or 428 for documents; the OpenAPI header is optional correlation-only.
6. Gates: targeted Maven test, SpotBugs after compile, `python3 -I -m unittest discover -s scripts/tests`,
   `python3 -I scripts/check-wiring.py`. No full `mvn verify`.

The corrected plan was sent back to plan-reviewer, test-engineer and senior-backend for a final bounded re-check before coding.
