# ISS-1452 — Make XCH-04 reconciliation resolutions durable and remove them from the open queue

Tested revision: 9868e93d391988cf068f4ed770d7d8142f9951c1

## Summary

BUILD-08 AC2 was marked done but never delivered: `ReconciliationService.resolve` keeps the immutable
Resolution in a process-local `ConcurrentHashMap`, V22 blocks a status UPDATE and grants only SELECT/INSERT
on `xch04_reconciliation`, and `ResultRepository.listReconciliation` keeps returning resolved entries for
`?status=open`. This hand-off delivers the missing durable storage, queue exclusion and acceptance evidence
without changing the REST contract.

## Lessons for workers

- A new table whose name starts with an ID prefix (`xch04_`, `rx02_`, …) is a new `requirement-id-name`
  finding in `scripts/check-wiring.py`; the protected baseline may only shrink, so choose a business name
  in the migration itself. Three independent reviewers caught this before any code was written.
- An anti-join alone is not queue closure: the immutable ledger's status never changes, so `?status=resolved`
  stays empty and the mapped status still reads `open`. Fold presence of the fact into both the filter and
  the projected `status`, and qualify every shared column in the join (`id`, `created_at` are ambiguous).
- `app.current_org` is set by `TenantGuardTransactionManager` only after a transaction opens. A read outside
  `transactions.execute(...)` returns 404 under forced RLS even for the owning tenant; the integration test
  found this after the unit tier was fully green.
- The empty side of `INSERT ... ON CONFLICT DO NOTHING RETURNING` and the mapped row need a mocked
  `NamedParameterJdbcTemplate` with a driven `RowMapper`; returning a prebuilt list leaves the mapper uncovered.
- POST/GET/409/404 can already pass before a durability fix. The honest red is the queue exclusion plus the
  missing durable row; record which assertions are regression guards rather than red evidence.
- A read endpoint is a security boundary too: `GET /{id}/resolution` had no membership/role check. Reuse the
  existing read action policy and write a read audit; report a denial *after* the transaction callback,
  because throwing inside it rolls the DENIED audit back.
- Do not run `mvn verify`, `scripts/check.sh` or `scripts/coverage-check.sh` as a worker; target the touched
  suites, reset `jacoco.exec` before the batch, and merge the integration report before reading counters.
