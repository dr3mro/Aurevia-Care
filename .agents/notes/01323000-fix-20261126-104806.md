## Findings

1. OPS-CW-003-01 was closed in memory as a known false positive without a code fix; that is why it recurred. It is now fixed and its history moved to `.opencode/config/ARCHIVE.md`; `MEMORY.md` keeps only the still-open OPS-CW-003-02. `BUGS.md` had no stale row to delete (its reconciliation had already removed it), and that fact is recorded there as evidence.
2. `git ls-files` exit 128 is treated as "no repository" only when `.git` is absent; a fatal failure inside a real repository fails closed. `check-pack.py` still labels a trusted-read failure as "stale"; a distinct message is an optional future refinement, not a bypass.
3. `--validated-checks false` is exercised only by unit tests because the publish job already refuses to call publish when the trusted validator failed. That preserves the existing publication guard and is intentional.
4. The `validate` job re-runs `worker-check.sh` with `origin/main` as its base because `.agent/base-sha` is untracked and absent from the bundle. This divergence is documented, not changed here.
5. Follow-up contract work remains: the Swarm gate still requires `evidence:` on a `[-]` task while the merge integrator writes it at `[x]`, and an open PR does not make a task non-dispatchable under `force`. PR #1749 needed a manual tracker patch. A task request is below.

## Lessons for workers

- A "known false positive" in memory is not a fix. If the same gate error recurs, trace the comparison source before accepting the diagnosis.
- Fake `subprocess.run` `side_effect` functions must `raise` exceptions; returning an exception instance silently marks the branch uncovered.
- Generated configs have two outputs; a fake `git show` must answer for both.
- Trust the job that checks out the default branch and runs trusted scripts, not a value produced inside the agent step.
