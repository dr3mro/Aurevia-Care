## Lessons for workers

- A skipped test is a gate suppression, not evidence. If a clause cannot be exercised because the behaviour is missing, do not hide a complete test behind `@Disabled` when `check-constraints.py` rejects it: either implement the behaviour in scope or record the gap as documentation and file the implementation task. Confirm the exception exists in code, not just in the brief.
- Before writing a gap test, check whether the task scope permits the production change that would make it active. If it does not (as here), a deleted placeholder plus a precise gap write-up is a cleaner hand-off than a red-gated PR.
- A tenant-scoping proof must share every local identifier across the two organizations; otherwise a global or subject-only lookup passes and proves nothing.
- In a cloud worker, `git ls-files -v opencode.json` showing `S` explains `check-pack.py`/`test_check_pack` failures; verify once with `git show HEAD:opencode.json` and never regenerate or commit that file.
