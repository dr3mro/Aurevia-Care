## Summary

`IdempotencyLedger` previously existed only as a process-local implementation with no
production caller. This change adds a durable, tenant-scoped replay ledger and wires it
into the real HTTP chain: a servlet capture filter buffers a keyed POST, an MVC
interceptor evaluates the key against the durable row after tenant identity is bound,
and the capture filter freezes the first 2xx response. Replays write the stored status
and body without invoking the handler. The header remains optional.

## Affected requirements

- ARC-03: versioned write commands, idempotency keys scoped to tenant, caller and
  command with a server-computed digest; same key and payload replay the original
  outcome; different payloads with the same key conflict.
- ARC-04: explicit POST commands and machine-readable errors for a reused key.

## Data changes

New table `public.idempotency_record` in `db/migrations/V66__idempotency_ledger.sql`:
`organization_id uuid`, `subject text`, `key text`, `request_hash text`,
`status_code integer` (200..299), `response_body jsonb`, `created_at timestamptz`,
`expires_at timestamptz`, primary key `(organization_id, subject, key)`, index
`(organization_id, expires_at)`. ENABLE and FORCE RLS, a `tenant_isolation` policy
using `public.app_org()`, `GRANT SELECT, INSERT, DELETE TO aurevia_app` and
`REVOKE UPDATE, TRUNCATE`. No token, credential, header, correlation id or raw request
body is stored; a row holds only the SHA-256 digest and the first successful response
with a 30-minute expiry. Lock/volume: additive DDL on a new relation; rows are bounded
by one expiry window. Recovery/forward-fix: a later contract migration can drop the
table with `Requires-expand: V66`; no secret rotation is needed.

## Fix round after review

The post-code reviewers raised issues that were fixed in code, not suppressed:

- **Path-variable/query collisions:** the digest now includes `getRequestURI()` and
  `getQueryString()` in addition to the body; a new HTTP test proves two concrete paths
  sharing one handler pattern with the same key and body conflict.
- **Pre-auth and multipart buffering:** the capture filter now runs at `@Order(0)` (after
  the security chain), only on `/api/v1/**`, only for JSON content types, and only up to
  1 MiB declared body size. Multipart, non-JSON, oversized and non-API requests pass
  through untouched; new direct tests cover each guard.
- **Ledger failure after commit:** a failed store write is caught, emits one fixed
  non-PHI warning, and preserves the already-committed response; a mock-throwing test
  asserts the 201 body is still delivered.
- **Missing body attribute:** the interceptor now skips idempotency when the capture
  filter did not supply a body string, instead of hashing the literal `null`.
- **Retention:** `evaluate` purges expired rows for the active tenant on every keyed
  read, including keys that are never retried; the HTTP integration test asserts an
  expired, never-retrieved row is gone, and the migration comments now state that the
  table is PHI-bearing and that a scheduled sweep for silent tenants is separate work.
- Comments and Javadoc were updated in the same change as each behavior.

## Lessons for workers

- An MVC interceptor, not a servlet filter, is the correct decision point for
  idempotency: `TenantContext` is bound by an interceptor inside the dispatcher and
  only an MVC interceptor can throw into `@RestControllerAdvice`.
- Re-capturing scope values is not enough for a JDBC write: the tenant-guarded
  transaction manager reads the thread-local `TenantContext`, which is cleared before
  an outer servlet filter resumes. Rebind the captured context around the write and
  clear it afterwards.
- MockMvc standalone setups do not load Spring-registered filters. Add both filter
  classes explicitly to prove the HTTP behaviour, and use a separate full-context
  integration test to prove production registration.
- Spring can CGLIB-proxy a `@Repository` bean; a `final` class fails startup. For
  SpotBugs EI_EXPOSE_REP2 on framework collaborators, a nested holder whose class name
  ends in `Store` is covered by the central exclusion without a new annotation.
