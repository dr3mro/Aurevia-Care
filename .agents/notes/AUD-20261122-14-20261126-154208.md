## Lessons for workers

- An output-parity assertion cannot detect a duplicated implementation when the copies are byte-identical. To prove delegation, mock the shared helper and assert it was called with each bundle's template; keep the output comparison as a separate regression guard.
- With Vitest `clearMocks: true`, `mockClear()` does not drain a `mockReturnValueOnce` queue. Use a persistent implementation plus `try/finally` restoration (or `mockReset()`), and assert with `toHaveBeenNthCalledWith` rather than indexing `mock.calls[0]` under `noUncheckedIndexedAccess`.
- Run a repo-wide grep before scoping a dedup story: this one found a sixth regex copy in `features/results/resultsMessages.ts:213`. Do not widen the declared scope to fix it; file a task request in the notes so the integrator can queue it.
- Keep generated coverage output out of the change: `apps/staff-web/check.sh` writes to the ignored `coverage/` directory, while only the four scoped sources plus one new test and the notes file are staged.
