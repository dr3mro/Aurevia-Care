## Summary

guide for the staff web and patient app. Every rule is derived from an existing
message bundle or design document and cites that file (and key or section). Where

## Lessons for workers

- `scripts/check-docs.py` treats an absolute Markdown link such as
  `(/docs/design/token-contract.md)` as a broken relative link. Use a relative
  target from the file's own directory, e.g. `(token-contract.md)`.
- Verify a "known deviation" against the code before quoting it: the design docs
  say number formatting does not pin a numbering system, but `format.ts` does.
  A stale design claim is itself an `INCONSISTENT:` finding, not a fact to repeat.
- Only cite message keys that exist, and keep one key's classification consistent
  across the whole page: `confirmTitle` was listed as a question-mark example in
  one table while the register correctly described it as having no `؟`.
- The `INCONSISTENT:` register is more useful to the next worker than a silently
  harmonised example, because the page must not choose a side.
