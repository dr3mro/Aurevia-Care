## Findings

- No production caller of `CommandAuthorization` exists in this snapshot (`docs/decisions/0003` records this explicitly). This change supplies the durable sink bean and proves it on real PostgreSQL; it does not add an HTTP route, because the owning story `AUTH-WIRE-01` (open, `depends: READY-41`) owns the interceptor, HTTP tests and route-level deny semantics. OPS-02 production enablement is complete only after that story.
- On a failed insert the deny with `AUDIT_UNAVAILABLE` is carried by `DecisionAuditUnavailable`; a *persisted* deny row cannot be guaranteed when the ledger itself is unavailable (a second insert in the same aborted transaction would fail too). `CommandAuthorization` therefore still answers 500/DECISION_NOT_RECORDED and denies the command. If a durable deny-on-audit-failure row is required, that needs a separate task with a different outage strategy; I did not change the public error contract.
- Decisions with a blank or malformed organization (for example unauthenticated 401 paths) cannot enter a `uuid NOT NULL` tenant-owned row and are converted to the same `AUDIT_UNAVAILABLE` deny. They are therefore not row-stored, but the command fails closed. AUTH-WIRE-01 should decide whether those need a separate tenant-less ledger.
- Tamper detection here is append-only grants plus `reject_immutable_mutation()` triggers, not V3's hash chain; the migration header states this. I did not expand scope to add a chained decision ledger.
- Worker-environment false positives (tool evidence, not product defects): stale CI `opencode.json` under skip-worktree makes `check-pack`, `quick-check.sh` and `worker-check.sh` fail; two `test_hermetic_env` signal tests fail because the sandbox has no `ps`/`kill`. Documented in AGENTS.md; no protected file was edited.
- Optional reviewer suggestions deliberately deferred, not defects in this slice: pass the JDBC root cause into `DecisionAuditUnavailable` for operator diagnostics (reviewer evidence from code-reviewer and devsecops); have AUTH-WIRE-01 consume `decision()` so `AUDIT_UNAVAILABLE` reaches a runtime consumer rather than only tests; consider asserting the `jdbc.update` row count in a later hardening story. Adding any of these would change the approved, reviewed contract and require its own tests, so none was folded into this story.
- No OWASP dependency scan was run here: no dependency changed, and the worker image lacks the NVD data; the integrator's full Delivery gate covers it. No patient data or credential is present in any changed file, test or note.

## Lessons for workers

- Before writing `JdbcDecisionSink`, ask the plan reviewer about the story's "on exception the decision is deny" wording: an already-failing sink cannot persist a fallback row in the same transaction, so the deny must be carried by an exception and the request must fail closed through the unchanged `CommandAuthorization` contract.
- Seed `role_assignment` only after binding `app.actor` to a seeded member of the active tenant; `set_granted_by_from_actor()` rejects an actor that is not an authenticated tenant user.
- In shared integration databases, assert on the test's own correlation IDs instead of the total row count, and sort expected `information_schema.columns` names exactly as PostgreSQL does (`decided_at` before `decision`).
