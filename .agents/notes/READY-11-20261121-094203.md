# READY-11 — Staff web OIDC login with a session cookie and CSRF protection (WEB-03)

## Summary

This run is a re-dispatch of a story whose implementation was already merged to `main` as PR #285 (commit `fefe3f2`, `READY-11: staff web OIDC login with session cookie and CSRF (WEB-03)`). That commit is an ancestor of this branch's HEAD (`3ed9068`), and the four production files and four test files for the story are byte-identical between `fefe3f2` and HEAD, so there was no missing code to implement. I therefore verified the whole slice end to end rather than duplicating it: I re-ran the failing test set, the full required worker gate and the JaCoCo coverage report; all are green. The only repair this run made was worktree-local: regenerating the generated `opencode.json` so `worker-check.sh` can pass in this CI-profile worker (see Findings). No production code, token, secret or patient data was added, and the `synthetic-auth` profile is untouched.

Implemented behaviour (from the merged code, re-verified here): a second `SecurityFilterChain` ordered before the stateless bearer chain matches only requests without `Authorization: Bearer`, uses `oauth2Login`, an HTTP-only secure `SameSite=Lax` session cookie configured under `server.servlet.session.cookie.*`, CSRF with a readable `XSRF-TOKEN` cookie, a 12-hour absolute session guard driven by the injected `Clock`, and `POST /logout` that invalidates the server session and clears both cookies. `TenantContextInterceptor` accepts the browser `OAuth2AuthenticationToken` through the existing `ClaimsTenantResolver`, so tenant scope is unchanged and the bearer path keeps its no-CSRF semantics.

## Authorization boundaries and audit events

Every non-bearer request on the browser chain requires an authenticated OIDC session; CSRF is enforced with a per-session token readable only via the non-HTTP-only `XSRF-TOKEN` cookie (an anti-CSRF value, not an auth token — nothing is stored in browser storage). The browser principal's `sub`/`orgs` attributes are resolved through the existing `ClaimsTenantResolver`, so a session cannot widen its organization set and the active tenant still comes only from `X-Active-Organization` intersected with verified claims. The bearer chain is unchanged; CSRF is ignored only for `Authorization: Bearer` requests. No new audit event was added; 401/403 denial semantics are unchanged.

## Migration and rollout considerations

`@ConditionalOnWebApplication(SERVLET)` keeps the non-web startup test green and prevents the browser chain from existing without an HTTP surface; `@Profile("!synthetic-auth")` leaves the synthetic profile untouched. In production all three `AUREVIA_OIDC_*` values must be supplied or startup fails closed; issuer and client secret are never written to the repository. The IdP must publish `/authorize`, `/token` and `/userinfo` beneath the issuer and return `sub` and `orgs` in user-info — an assumption to confirm with the real IdP before enablement. The host must terminate TLS so the session and XSRF cookies carry `Secure`.

## Findings

1. **Re-dispatch on already-merged work.** The story was returned with `attempts: 2` and TODO still `[-]`, but PR #285 (`fefe3f2`) already merged the implementation and the files in this branch are identical to it. No code was duplicated. The integrator should mark TODO `[x]` with `pr: #285`; I did not edit TODO.md (swarm worker rule).
2. **`worker-check.sh` failed before any check due to a known CI-profile artifact; repaired worktree-locally.** `gen-opencode.py --check` initially exited 1 because the worktree `opencode.json` was the CI profile (`git ls-files -v` → `S`, skip-worktree) while HEAD holds the local profile — the documented OPS-CW-003-01 measurement artifact, not a change by this story. Running `python3 -I scripts/gen-opencode.py` restored the committed local profile, `--check` now exits 0, the file is skip-worktree so `git status` stays clean and nothing was committed, and `bash scripts/worker-check.sh` now exits 0 end to end. No protected file was edited in the commit.
3. **WEB-03 limit deliberately out of scope:** listing and revoking a user's *other* sessions needs a server-side session registry and must be a separate follow-up task approved by a person. Authentication-endpoint lockout/rate-limiting is likewise not part of this slice. Neither is claimed as covered here.
4. Audience is still not fail-closed (`AUREVIA_OIDC_AUDIENCE` defaults empty) — a pre-existing production-enablement risk from the AUD-20261120-03 notes, not widened here.
5. **Health probes are not exempt outside `synthetic-auth` (pre-existing, not introduced here).** Both chains use `anyRequest().authenticated()`, so `GET /health/live` and `/health/ready` need a credential and the browser chain would redirect to OIDC login. WEB-05 requires these routes unauthenticated; fix in a WEB-05/health-lifecycle story with its own tests, not inside READY-11.
6. OWASP Dependency-Check was not run locally (no `NVD_API_KEY`; the feed would time out). The new starter is managed by the Spring Boot parent with no version tag; the integrator's cached-NVD run owns this evidence.

## Lessons for workers

- Regenerate the generated `opencode.json` with `python3 -I scripts/gen-opencode.py` before `worker-check.sh` in a CI-profile worker; because the file is skip-worktree this restores HEAD's local profile without creating a commit, and it is the only way the pack gate can pass locally (do not edit `scripts/` or the file by hand).
- On a re-dispatched story, first check `git merge-base --is-ancestor <merged-pr> HEAD` and diff the story files; verify and document rather than reimplementing already-merged code.
- In this Boot 4.1.2 / Spring Security 7 slice, `AntPathRequestMatcher` no longer exists — use `PathPatternRequestMatcher.pathPattern(HttpMethod.POST, "/logout")` and `ClientRegistration.getProviderDetails().getAuthorizationUri()`.
- With `CookieCsrfTokenRepository`, set `CsrfTokenRequestAttributeHandler.setCsrfRequestAttributeName(null)` or the `XSRF-TOKEN` cookie is never written on a GET and the SPA has no token to send.
- Boot validates `spring.security.oauth2.client.registration.*.client-id` at startup even with empty defaults; keep custom env-backed properties and build the registration yourself when a profile must stay untouched.
- `MockHttpSession` has no `setCreationTime`; override `getCreationTime()` in an anonymous subclass for deterministic session-age tests.
