## Test evidence

today. `com.aurevia.chart.record.ChartService.record(...)` performs
an optional `ChartRepository.lookupCatalog(...)` mapping and constructs the
entry with `command.originalText()` / `command.originalCode()` retained verbatim
and the mapping result in separate `mappedCode`/`mappedText`/`catalogVersion`
fields; `ChartEntry` documents the retention invariant; `ChartService.verified(...)`

and an unpaired code/system. `db/migrations/V13__longitudinal_chart.sql` defines
the retained and mapped columns with RLS/FORCE RLS. No missing behaviour was
found, so no test is `@Disabled`.

## Lessons for workers

- For clause-evidence tasks, first check whether the clause is already built;
  when it is, write green regression evidence and say explicitly that there is
  no production red phase, instead of inventing a failing test.
- Give each chart clause integration suite its own database name, and seed a
  distinct approved catalog code per test (`LOC-77`/`LOC-88`/`LOC-99`) so approvals
  cannot collide when test order changes.
- `-Pno-security` plus a targeted `-Dtest=ClassName` proves an integration suite
  quickly; reserve SpotBugs for its standalone command from the backend skill.
- `check-pack: opencode.json is stale` in a cloud worker is the CI profile under
  `skip-worktree`. Confirm with `git ls-files -v` and `git show HEAD:opencode.json`,
  never regenerate or commit that file, and run the remaining gate stages
  individually.
- Assert the original values differ from the mapped catalog label; otherwise a
  test that only checks the mapped text could pass even if the original had been
  overwritten.
