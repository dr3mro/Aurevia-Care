## Summary

Added the OPS-04 recovery drill procedure and an empty evidence template under
the new `docs/operations/recovery/` business-named directory. The runbook states
the restore order (database, objects, identity-provider dependencies), the
read-only reconciliation gate before writes reopen (hashes, source versions,
in-flight deliveries, audit coverage, plus reapplication of revocations and
withdrawals), the roles that may approve reopening, and the checks applied at the
RTO mark. The evidence template has one row per runbook step (planned time,
actual time, result, evidence link, approver) plus measured RPO/RTO fields. No
results were invented; all fields are blank or `—`.

## Lessons for workers

- For a Markdown-only story, `python3 -I scripts/check-docs.py` is the
  story-mandated gate; write relative links only to files that already exist,
  and remember worker notes under `.agent/` are skipped by that checker.
- `check-pack.py` judges the skip-worktree CI `opencode.json`; a staleness result
  there is not caused by documentation-only changes and must not be "fixed" by
  regenerating a protected file from a swarm worker.
- When creating a business-named docs folder that another task plans to rename
  into, keep cross-directory references as plain text rather than relative
  links so the docs checker stays green whichever rename lands first.
