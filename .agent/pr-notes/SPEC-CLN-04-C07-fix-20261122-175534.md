## Lessons for workers

- A `check-verdicts.py` rejection on a Java-changing branch is fixed by adding real reviewer verdicts to the notes, not by broadening scope or by weakening the gate. If all changed files were docs-only, the script would pass without verdicts.
- In a cloud worker, the worktree `opencode.json` is the CI-profile mask. Restoring `git show HEAD:opencode.json` (and the CI profile) into the worktree makes `gen-opencode.py --check` and `worker-check.sh` pass without committing a protected file.
- When a debugger reports a previously blocking compile break was fixed on main, verify the focused test directly instead of repeating the stale diagnosis.
- Keep wording tight in coverage notes: a null/absent language tag is "missing", not "blank", unless a whitespace case is actually asserted.
