# SPEC-MSG-02-C05 — Track awaiting staff, awaiting patient, resolved and closed states

## Summary

Spec MSG-02 clause 5 (API test). Adds ONE clause-focused API/service test that proves a
conversation work item tracks `awaiting_staff`, `awaiting_patient`, `resolved` and `closed`,
that a reply reopens a resolved work item to `awaiting_staff`, and that forbidden refusals
(closed thread, stale version, wrong unit, missing reason) are rejected. Also adds the
clause-proof document. Test-only change: no production code, migration, contract or existing
test was modified. All fixtures are synthetic.

## Lessons for workers

- Copying a fixture from an older test does not make its annotations safe to copy: a
  `@SuppressWarnings("unchecked")` that is grandfathered in the source file is a *new* gate failure
  in a new file. Mockito's generic `invocation.getArgument(0)` infers the type without a cast.
- For clause-proof tests, a stubbed `find()` can return the state you assert even when the write is
  wrong. Verify the exact `updateState`/`appendEvent` wire arguments as well as the returned state.
- A chained command sequence needs consecutive `loadForUpdate` and `find` returns with matching
  versions; one `stubView` only keeps the last stub active.
