## Lessons for workers

- A tracker requirement ID attached to a docs story can be stale: verify the ID against the package's actual Javadoc, migration headers and service code before attributing a requirement in a module guide.
- For a Markdown-only change under a globally red docs gate, save the checker output before the edit and diff it after; that proves the new page adds no errors without touching unrelated broken files.
- `scripts/check-docs.py` checks table pipe counts and heading levels, so mirror the existing `api-api.md` structure and avoid literal pipes in cells; notes under `.agent/` are skipped by that checker.
- `bash scripts/docs.sh` is a cheap second gate for a module guide: it proves the page renders and writes only to the gitignored `build/` tree.
