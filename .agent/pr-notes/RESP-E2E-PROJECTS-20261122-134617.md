# RESP-E2E-PROJECTS — staff-web Playwright device matrix

## Summary

Extended the staff-web Playwright harness to a device-class matrix. Nine new
Chromium viewport projects cover phone portrait/landscape, tablet
portrait/landscape, laptop and desktop; the original `chromium` project is kept
first and unchanged. WebKit and Firefox variants are added only for the
390×844, 820×1180 and 1280×720 sizes, and only when those engine binaries are
present in the environment, so a Chromium-only worker keeps a green list while
a full browser-matrix CI job exercises all three engines. No runtime code,
dependency, route or spec file was changed.

## Findings

1. **Pre-existing red module gate (out of scope).** `bash apps/staff-web/check.sh`
   fails on 18 assertions in `tests/responsive/features-*` component tests.
   These files are unchanged by this task, do not import the Playwright config,
   and the failing set varies between runs. The integrator/Delivery should run
   the full gate and, if still red, route those defects to the owning responsive
   stories rather than to this harness change. No attempt was made to weaken or
   rewrite them.
2. **Known worker false positive.** `scripts/check.sh` stops at `check-pack.py`
   because `opencode.json` is the CI profile under `skip-worktree` in this image
   (`git ls-files -v` → `S`); HEAD's committed profile is correct. Remaining
   policy stages were run individually and are green.
3. **Synthetic review finding, disposition.** The bounded senior-react review
   flagged `isMobile: true` on the phone projects as likely to break
   `smoke.spec.ts:91` `page.setViewportSize(...)` ("not supported for isMobile
   contexts"). Verified against the installed Playwright 1.65.1 source: the
   client `setViewportSize` sends `Page.setViewportSize` with the `isMobile`
   flag and has no such guard, and the app's `index.html` has
   `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`.
   The claim reflects older Playwright behavior, so `isMobile` was retained to
   satisfy the "(touch, mobile)" acceptance text. A real-browser rerun in CI is
   still the authoritative proof.
4. **Accepted matrix consequence.** With `testDir: '.'`, all six spec files —
   including the five journey specs that create their own contexts — now run
   on every project. That is inherent to adding projects to the shared config.
   If a future CI job wants journeys only on desktop engines, scope them at
   invocation time (`--project=chromium`) rather than by editing `smoke.spec.ts`.
5. **Environment limit.** Browser binaries downloaded but cannot launch here
   (`libglib-2.0.so.0` missing). No config change can fix this; CI images with
   `playwright install --with-deps` are the intended runtime.

## Lessons for workers

- The Playwright config lives in `e2e/`; running `npx playwright test --list`
  from the module root silently picks up Vitest `.test.ts` files and fails.
  Always run it from `apps/staff-web/e2e` or pass
  `--config e2e/playwright.config.ts`.
- `tsconfig.json` excludes `e2e/`, so `npm run typecheck` never checks the
  config. Run a focused `tsc` with `--exactOptionalPropertyTypes` on the file;
  this is where a pre-existing `webServer: … ? undefined : {…}` issue was found.
- Check installed-browser detection with `--list` both before and after
  `playwright install`: enumerating tests needs no browser launch and covers
  both branches even in a worker image without native libraries.
- Assertions in `tests/responsive/**` can be red on the branch for reasons
  unrelated to an e2e-config change; confirm the failing paths and their
  variability before attributing a red `check.sh` to your own diff.
