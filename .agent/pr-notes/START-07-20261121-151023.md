## Lessons for workers

- When a threat model must cite only real controls, extract every backticked path from the draft and assert it exists before calling the task done; shorthand package names (for example `exchange/critical`) pass prose review but fail that check.
- A client-side CSRF header is not a control unless a server-side session chain validates it; describe the server chain, not the header, as the control.
- For docs-only stories, state explicitly that coverage and frontend `check.sh` gates are not applicable rather than leaving the reviewer to infer it.
- Never write a path convention you have not machine-checked: expand test citations to full paths and assert every backticked path exists, or a reviewer will find same-name files in different packages.
- Distinguish fixture logic from a control in a threat model; a synthetic client with a "production must use ..." comment is not a defensive boundary.
- Attribute behaviour to the file that implements it: a 401 mapping lives in the transport, a no-op context is not a session manager, and an interface method is not implemented by its caller.
