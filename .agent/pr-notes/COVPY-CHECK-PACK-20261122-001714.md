## Lessons for workers

- In a cloud worker, `git ls-files -v opencode.json` showing `S` means the worktree
  config is the CI profile under skip-worktree; `check()` / `gen-opencode.py --check` then
  report "stale" and several existing `test_check_pack.py` tests fail. Verify with
  `git show HEAD:opencode.json` (HEAD matches the generator) before treating it as drift.
- To cover `main()` success paths under that artifact, mock `pack.check` with
  `mock.patch.object(pack, "check", return_value=[])`; do not regenerate or edit
  `opencode.json` from a test-only task.
- `pip` may be absent: `curl -fsS https://bootstrap.pypa.io/get-pip.py -o /tmp/opencode/get-pip.py`
  then `python3 /tmp/opencode/get-pip.py --user --break-system-packages` and
  `python3 -m pip install --user --break-system-packages coverage` bootstraps the
  coverage tool (coverage.py 7.17.4).
