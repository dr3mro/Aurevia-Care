## Lessons for workers

- Seed both `patient_link` (conversation `patientLinkActive`) and `patient_account` + `account_chart_link` (the `current_chart_links()` fold used by `JdbcMessagingStore` and `JdbcInstructionFactStore`); seeding only `patient_link` fails `connect` with `NO_VERIFIED_CHART`.
- `InstructionContract.Kind` deserializes by enum name (`COLLECTION`), while `InstructionContract.State` serializes by enum name (`SENT`, `WITHDRAWN`) and `ConversationContract.State`/`ConnectionState` use lowercase wire values (`awaiting_staff`, `resolved`, `active`). Check the actual record annotation before writing JSON or asserting state.
- `Fact.type()` is not serialized by Jackson; assert the receipt by its `scope` (`RECEIPT`) and `actor` in the facts timeline.
- One connection needs one eligible relationship: `patient_unit_connection` is unique on (org, patient, unit, context_reference), so seed a pool of relationships with distinct references when several tests connect the same chart.
- The `InstructionStore.InMemory` seed keys are scoped by `TenantContext.current()`; bind and clear the context around every seed call, and feed it the connection id returned by the HTTP `connect` call.
