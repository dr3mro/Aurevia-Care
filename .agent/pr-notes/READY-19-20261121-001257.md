# READY-19 — Staff web router and application shell with role-based navigation

## Summary

Replaced the demo-only `AppShell` with the real application shell from
`docs/design/screens-and-navigation.md` section 1 and added a dependency-free
client router. A single `RouterProvider` owns the pathname from
`window.location.pathname`, follows `popstate`, and exposes `useRoute()`;
`matchRoute` is a pure exact/`:param` matcher; `Link` renders a real anchor and
intercepts only plain left clicks. `AppShell` now renders a skip link, a header
(product name, organization switcher, language and theme toggles, user menu with
Sign out), a role-scoped rail built from the existing `navigationFor(role)`
(READY-10), a `role="status"` banner, and `<main id="main" tabIndex={-1}>` with
the lazily loaded matched route. Focus moves to `main` on each path change.
Only `/`, `/design-preview` (DEV only) and a catch-all not-found page are
registered; the old demo content was **moved**, not deleted, to `DesignPreview`.
No dependency was added and no file outside the declared scope was changed.

## Findings

- **Earlier attempt**: TODO.md showed `attempts: 1` and the branch was already
  claimed by `swarm-2`, but no notes file existed and the working tree was
  clean at `b4ec3eb`. This run started from that clean base; no earlier work was
  overwritten.
- **READY-10 compatibility**: `src/app/navigation.test.tsx` (inside this scope)
  renders `<AppShell role=... />` directly, without a `RouterProvider`, and
  queries the rail as `role="group"` named "Sections". The rewritten shell keeps
  the optional `role` prop, the `role="group"` rail and a `useRoute()` fallback
  to `window.location.pathname`, so that existing test still passes unchanged.
- **`ImportMeta.env` typing**: `src/env.d.ts` is outside scope and
  `import type {} from 'vite/client'` fails typecheck (`vite/client.d.ts` is not
  a module). `routes.tsx` therefore declares a minimal local `ImportMeta.env`
  augmentation; no global file or config was edited.
- **Design-doc vs story gap**: `docs/design/screens-and-navigation.md` section 1
  also lists a facility selector and a user-menu sessions link. The story's
  explicit header list omits both; they are **not** implemented here and remain
  for the screen that owns the facility/session surfaces (READY-11). The banner
  area is an empty polite live region, as the design specifies for normally
  quiet banners.
- **`onSignOut` in `App.tsx`**: the prop is part of the shell contract but the
  application entry does not supply a handler until READY-11 owns the session;
  clicking it today is inert. Tests cover both defined and undefined handlers.
- **Focus policy**: focus moves to `main` on the initial mount as well as on
  later navigation (one effect keyed on `path`, with no extra branch). This is a
  deliberate choice documented for the next worker.
- **Mock partner/human evidence**: none. RTL correctness was asserted through
  the document `dir`, Arabic rail labels and the absence of physical inset
  properties; jsdom cannot prove painted layout. A real-browser RTL pass remains
  a later verification item.

## Lessons for workers

- In this module, `src/app/*.test.tsx` files are production-adjacent tests that
  render `AppShell` without providers. Before rewriting a shared component,
  grep every test that renders it (`grep -rn "<AppShell" apps/staff-web/src`)
  and keep its contract or adapt it deliberately in the same change.
- `import.meta.env` is not typed by the module's `tsconfig` and
  `import type {} from 'vite/client'` is not valid here; a minimal local
  `declare global { interface ImportMeta { ... } }` is the scoped alternative.
- To cover an `import.meta.env.DEV` branch at 100%, move the conditional into a
  pure factory (`createRoutes(boolean)`) and test both arguments. Do not try to
  stub the constant or rely on module re-imports.
- `React.lazy` always suspends on first render: use `findBy*`/`waitFor` for
  route content, and keep the exact `<p role="status">Loading</p>` fallback
  because `src/app/screenLoading.test.tsx` asserts it.
- jsdom schedules a native navigation for any anchor click whose default is not
  prevented. In router click tests, add a document-level `click` listener that
  calls `preventDefault()` after React's handler to keep the log clean.
- Wrap a bare call to the exported `navigate()` in `act()` so the provider's
  state update is flushed before asserting.
