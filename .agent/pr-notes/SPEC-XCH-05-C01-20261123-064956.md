## Findings

- Doc line citations for `contracts/openapi/missing-routes.txt` are stale: the doc says lines 29-30 and
  170-177, but the ten critical-results routes are actually at lines 25-26 and 149-156. The content of
  the claim is correct; only the line numbers drifted. Not changed here because the re-dispatch brief
  requires verification without rewriting, and the doc's "Proven by tests / Gap: None" conclusion is
  unaffected. Optional debt for a future doc-only task.
- The happy path's `verifiedBySubject()`/`verifiedAt()` assertions (:175-176) are fed by the hardcoded
  `result()` fixture (:117, :129-134) rather than the arguments the service passes to
  `repository.verify`, so the doc phrase "verification binds the verifier and instant" is slightly
  overstated for this class alone. Clause 1 requires verification itself (proven), not who/when binding;
  that binding is carried by `CriticalResultRepository.verify` and the HTTP test. Optional.
- Latent, pre-existing branch at `CriticalResultService:163`
  (`ownerSubject()==null || dueAt()==null`): the suite covers both-null and neither-null, not the
  isolated owner-present/due-null operand. This is existing production code, not this task's diff, so it
  is outside this story's coverage gate; Optional debt for the owning task.
- The two gate failures above (worker-check `check-pack`, Python tooling tests) are documented
  worker-image false positives (OPS-CW-003-01 skip-worktree CI profile; mocked git/gh fixtures), not
  defects of this change. No PHI, secret or credential was found in the test, doc or notes.

## Lessons for workers

- On a re-dispatch, confirm both target files are present, complete and `git diff --exit-code HEAD`
  clean before touching anything; verify and record rather than rewrite, because an overwrite destroys
  the prior worker's accepted evidence.
- `worker-check.sh` aborts at `check-pack` on the skip-worktree CI profile in a cloud worker. Confirm
  `git ls-files -v opencode.json` = `S` once, then run the remaining stages (docs, frontend, SpotBugs,
  targeted tests) individually instead of re-diagnosing the same artifact or editing the protected file.
