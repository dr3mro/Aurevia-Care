# BUILD-74 — Staff web: documents in the chart (upload, preview, link, void)

## Summary

Stopped at the story's step-5 contract gate before writing any code. The document API this
screen must call is absent from `contracts/openapi.yaml` (and from the generated staff-web
client): 0 occurrences of `document`, `artifact`, `quarantine`, `scan` or `checksum`, and none
of the 19 published `/api/v1/...` paths concerns documents. Step 5 says to stop rather than
invent the API. A backend `DocumentController` exists with real routes, but those routes are
deliberately unpublished in the contract, and the upload/scan/quarantine commands that drive
the story's preview gate are domain-only with **no HTTP route at all**. No files under
`apps/staff-web/src/features/documents` were created; no other file was changed.

This follows the accepted precedent of BUILD-75 (`6cc19f27`, PR #319), which stopped at the
same step-5 gate for the same class of missing task API and was recorded as `[x]` with a
notes-only commit.

## Affected requirements

| ID | Requirement | Acceptance in story | Status |
|---|---|---|---|
| CLN-07 | Documents retained with checksum, void reason and history; never show a file before it is scanned clean | Upload with type/size/checksum checks and a visible scan state; preview only when scanned clean; link to chart/order/result; rotation display-only; void with reason that keeps history | Blocked — no HTTP contract for upload/scan/scan-state |
| ARC-06 | Upload validation, private quarantine, mediated downloads, object-version checks | Type/size/checksum validation and scan state from the server; downloads via API only, never a URL or patient data in the page address | Blocked — quarantine and mediated-download commands have no HTTP route |
| WEB-09 | Resilient screens (loading/empty/error/offline/forbidden/conflict/session-expired) | Seven states, keyboard/RTL/tenant tests, conflict keeps typed work | Not started — depends on the API above |

Acceptance tests the story requires (quarantined file cannot be opened, rotation does not
change the stored file, void asks for a reason and keeps history, English and Arabic) cannot
be written against a normal entry point until the contract and the upload/scan HTTP surface
exist. Screen-only message parity and RTL rendering could be authored locally, but the data
contract is a hard prerequisite for the screen itself (BUILD-75 precedent).

## Risk class

Cross-boundary blocker plus safety-critical (docs/WORKFLOW.md): the story depends on an API
contract and an upload/scan/quarantine HTTP surface outside this worker's scope
(`apps/staff-web/src/features/documents` only). A document shown before a clean scan or a void
that loses history is a clinical-safety and patient-privacy risk (CLN-07/ARC-06); the contract,
scan gate and void semantics must be owned server-side, not invented in the UI.

## Findings

- **Hard blocker (decisive):** the document operations required by steps 1–3 of the story are
  not in `contracts/openapi.yaml`. There is no document path, schema or generated-client type.
  Step 5 says to stop rather than invent the API; this note is that stop.
- **The backend surface is only partly usable and partly unwired.** `DocumentController` has
  link/history/content/void/render routes, but they are unpublished in the contract, so a
  typed staff-web client cannot import them. The upload, scan and mediated-download commands
  that drive the preview gate live only in `QuarantineService` with no controller route, so
  "never show before scanned clean" cannot be implemented from the browser at all.
- **Story dependency gap:** `BUILD-76` will register the documents routes, but nothing in the
  scheduled work publishes the document contract or adds the upload/scan HTTP surface ahead of
  BUILD-74. The owner should add that API story before re-dispatching this one.
- No defect was observed in existing code; the baseline staff-web check is green.

## Lessons for workers

- For any screen story with step 5 ("if the API is missing from `contracts/openapi.yaml`,
  stop"), run the contract/generated-client grep **before** scaffolding the feature folder. A
  domain model or a Java `@RestController` is not an HTTP contract — check the OpenAPI paths
  and the generated client (`apps/staff-web/src/api/generated/openapi.d.ts`).
- `grep -ic "document" contracts/openapi.yaml` is a fast, decisive gate. Do not build a typed
  `api.ts` wrapper or a mock endpoint to fill the gap; that is inventing the API and will fail
  `gen:api:check` and the wiring checks. BUILD-75 already established this as an accepted stop.
- A route that exists in a controller but is absent from the contract is still "missing" for
  these frontend stories; distinguish the two and record both in the notes.

## Why this is not finished

The story's step-5 gate fired: **the API needed is missing from `contracts/openapi.yaml`**.

Missing contract operations, mapped to the story's acceptance points:

1. **Upload with type, size and checksum checks and a visible scan state** — no upload or scan
   path in the contract and no HTTP route anywhere (`grep` for upload|scan|quarantine routes in
   `apps/api/src/main/java` → none). `QuarantineService.upload/scan` exist in process only.
2. **Preview that never shows a file before it is scanned clean** — no scan-state or
   mediated-download endpoint in the contract; `QuarantineService.download/view` are unwired.
   The gate cannot be enforced from the browser without a server-reported verdict.
3. **Link to a chart, order or result** — `POST /api/v1/documents/associations` exists in
   `DocumentController` but is absent from `contracts/openapi.yaml` and the generated client.
4. **Rotation as display-only metadata** — no rotation field or command in the contract or the
   generated client; no HTTP operation to record or read display-only rotation.
5. **Void with a reason that keeps history** — `POST .../associations/{id}/void` and
   `GET .../associations/{id}` (history) exist in `DocumentController` but are not in the
   contract or generated client, so the screen cannot use them through a typed client.
6. **Downloads through the API, no URL or patient data in the page address** — `GET
   .../associations/{id}/content` exists in the controller but is unpublished in the contract.

What was tried: confirmed absence in all three OpenAPI files and in the generated client
(keyword counts above); listed all 19 contract paths; read `DocumentController.java` and
`QuarantineService.java`/`DocumentService.java` public commands; searched the API for any
upload/scan/quarantine HTTP route (none); confirmed no `apps/staff-web/src/features/documents`
folder and no existing staff-web document API wrapper. Ran the baseline `check.sh` and
typecheck to confirm the tree is green. No code was written, so there is no failing test to
attach.

Most likely cause: the document HTTP surface was built as an internal slice (BUILD-06,
BUILD-27) and its controller was never published in `contracts/openapi.yaml`; the
upload/scan/quarantine commands remain domain-only because the "API versioning story" that
`contracts/documents/document-artifacts.md` says owns the public REST surface was never
scheduled ahead of BUILD-74.

Exact next step for the owner / next worker: add an API story (outside this worker's scope)
that (a) publishes the document upload, scan/scan-state, link, preview, rotation, void and
mediated-download operations and schemas in `contracts/openapi.yaml` and regenerates

download commands through a controller with tenant/role authorization and an append-only Jdbc
store with RLS migration, each with HTTP-level integration tests, then re-dispatch BUILD-74.
Do not proceed with a frontend-only implementation against an invented contract.
