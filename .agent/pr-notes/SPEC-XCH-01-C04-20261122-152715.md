# SPEC-XCH-01-C04 — XCH-01 clause 4 API proof

## Summary

Added active (non-disabled) proof that the receiving organization sees only its bounded XCH-01
exchange work item and can bind a locally verified patient without general chart access. The clause
was already implemented; this change adds a nine-test service/HTTP proof class and the clause

workflow was changed. The senior developer brief was accurate; no correction was needed.

## Lessons for workers

- Do not leave a read-only reviewer reading a file while a temporary red-probe mutation is active, or
  briefly tell it that the mutation is deliberate and will be restored; otherwise it reports the
  probe as a real defect.
- In `OrderService`, `AuditAppender.append(context, purpose, action, ...)`: `purpose` is `EXCHANGE`
  and `action` is `WORK_ITEM_LIST` / `WORK_ITEM_VERIFY`. A verification that puts the action in the
  purpose slot fails with a positional argument mismatch.
- In a cloud worker, `opencode.json is stale` from `worker-check.sh` is the documented skip-worktree
  false positive. Confirm `git ls-files -v opencode.json` shows `S`, compare `git show HEAD:opencode.json`
  with `gen.render(ROOT)`, record the exact failing command and final line, run the remaining gate
  stages individually, and never regenerate or edit the protected file.
