## Lessons for workers

- On a re-dispatch, verify before writing: prove prior delivery with
  `git log -- <path>`, `git merge-base --is-ancestor <sha> HEAD`, an empty
  `git diff origin/main -- <path>` and blob-hash equality against the merged
  commit. Do not rewrite complete files to "do something".
- In the XCH-01 order flow, seed an approved grant in `@BeforeAll` before any
  release test; `OrderService.create` checks the grant before the patient, so a
  cross-tenant patient with a bad grant returns 403 and makes a 404 assertion
  silently wrong. Pair every negative with a control 201 and a zero-row assertion.
- The destination work-item projection is deliberately bounded: do not assert
  `encounterRef`, `orderCode`, `sourceActor` or `responsibleClinician` on it —
  those live only on the order response/row. `sourceActor` is `clinician-a`
  (caller) while `responsibleClinician` is `dr-a` (command).
- A swarm worker must not run `worker-check.sh`, `scripts/check.sh` or full
  `mvn verify`: they execute every integration suite and time out the run. Run
  the targeted `-Dtest=...`, the individual policy scripts, SpotBugs on compiled
  classes and `db/check.sh`, and leave the full gate to the integrator.
- Confirm the "opencode.json is stale" failure once with
  `git ls-files -v opencode.json` (`S`) and `git show HEAD:opencode.json`; never
  regenerate or commit that file, and do not re-diagnose it on a later pass.
- Re-check stale findings from earlier notes before copying them forward: a
  previously flagged conflict-marker issue was already resolved in this pass.
