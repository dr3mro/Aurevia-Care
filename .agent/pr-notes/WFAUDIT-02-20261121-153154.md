# WFAUDIT-02 — choose the last good slot image by immutable generation

## Summary

Adds four pure helpers plus a small command wiring in `scripts/swarm.py` so a
swarm wave can name the immutable slot-image generation it will start from,
fall back to the last good generation when the newest publish is incomplete,
and wait rather than pull a stale or half-written `:latest`. No workflow file
was changed; the matching workflow patch is the separate WFAUDIT-03 task.

Scope respected: only `scripts/swarm.py` and the new
`scripts/tests/test_slot_generations.py`. Synthetic fixtures only; no
dependency, no credential, no patient data.

Entry point to test trace:
`main()` `images-ready` (`scripts/swarm.py`) → `parse_generations()` →
`images_ready_command(slots, generations)` → `wave_generation()` →
`pick_generation()` / `last_good()` → `_generation_complete()`; tag built by
`generation_tag()`. The CLI emits `generation` and `generation_source` next to
the existing `ready` / `reason` / `dispatch` outputs. Tests drive the pure
functions directly and the command through `CommandWiringTests` with `gh`,
`image_runs`, `slot_manifests_exist` and `emit` patched.

## Affected requirements

- OPS-06 — CI policy/tooling; defensive, reproducible delivery. This change
  removes the "stale or half-written worker image" failure mode described in
  the story by making the generation choice deterministic and evidenced.

Acceptance mapping (story step 3):

| Acceptance scenario | Tests |
|---|---|
| A complete newest generation wins | `PickGenerationTests.test_complete_newest_generation_wins`, `WaveGenerationTests.test_complete_newest_wins`, `CommandWiringTests.test_reports_newest_generation_when_complete` |
| Incomplete newest falls back to previous complete | `LastGoodTests.test_returns_previous_complete_generation`, `WaveGenerationTests.test_incomplete_newest_falls_back_to_last_good`, `CommandWiringTests.test_reports_fallback_when_newest_incomplete` |
| No complete generation returns none and the wave waits | `WaveGenerationTests.test_no_complete_generation_returns_none`, `CommandWiringTests.test_no_complete_generation_makes_the_wave_wait` |
| Tag format stable and unique per run | `GenerationTagTests` (5 tests) |

## Migration and rollout considerations

None in this change. WFAUDIT-03 (separate task, proposed workflow patch) must

first, one entry per slot, shaped as
`{"tag": "g<run>-<sha12>", "run_number": N, "sha": "...",
  "slots": [{"slot": 1, "exists": true, "digest": "sha256:..."}, ...]}`.

## Findings

- The full `scripts/tests` suite has 3 pre-existing failures in
  `test_check_pack.py` (`GeneratorTests.test_check_mode_detects_drift`,
  `PackTests.test_committed_opencode_json_is_generated`,
  `PackTests.test_repository_pack_is_valid`) with
  `opencode.json is stale: run scripts/gen-opencode.py`. This module does not
  import `swarm` (verified), so the change cannot cause them. Root cause is the
  documented cloud-worker artifact (MEMORY.md OPS-CW-003-01, BUGS.md
  OPS-CW-003-01): `git ls-files -v opencode.json` reports `S` (skip-worktree)
  and the worktree holds the CI profile (`shell`/`gh *` resources) while the
  generator renders the committed local profile (`subagent`/`*`). `opencode.json`
  is a protected file and was not touched. `scripts/check.sh` fails for the
  same reason at its first gate. The integrator's environment (committed local
  profile in place) is expected to pass.
- Design note for WFAUDIT-03: `images_ready_command` deliberately treats
  `generations=None` as "unmanaged" (today's behaviour) and only enforces the
  "wave waits" rule when a generations list is actually supplied. The workflow
  patch must pass the list or the new safety rule stays dormant. No workflow
  file was edited here.
- Completeness is defined over the records supplied by the caller: a non-empty
  `slots` list where each entry has `exists` truthy and a non-empty `digest`.
  The caller is responsible for including one entry per expected slot.

## Lessons for workers

- In a cloud worker, the worktree `opencode.json` is the CI profile under
  `skip-worktree`; `check-pack.py` and `scripts/check.sh` fail on it even when
  the committed local profile is correct. Confirm with `git ls-files -v` and
  record it as pre-existing instead of "fixing" a protected file.
- With stdlib `trace`, `ast.FunctionDef` `def` lines are not counted (the
  module was imported before tracing); exclude them when asserting 100% line
  coverage of new functions.
- Keep a pure-function seam for workflow-facing decisions: the workflow patch
  can pass generation records through a JSON CLI argument without any network
  or GitHub calls in the unit tests.
