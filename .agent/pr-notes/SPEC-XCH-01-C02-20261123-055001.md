# SPEC-XCH-01-C02 — XCH-01 clause 2 API test

## Summary

Proves XCH-01 clause 2 — "The sending organization authorizes the specific payload, recipient, purpose and duration." — with one permitting and five refusing unit tests over the real `OrderService.create`/`checkGrant` decision, plus a clause-status document. The clause was already implemented; this change adds a focused, named proof and records its status. No production code, existing test, contract, migration or tracker was edited.

## Lessons for workers

- To isolate the per-release maximum-duration branch of `checkGrant`, give the grant `expiresAt = null` (or a far-future expiry); with a 1-hour expiry, a 61-minute request trips the "disclosure outlives the grant" window operand first and proves the wrong branch.
- `AuditAppender.append` is `(context, scope, action, resource, scope, id, outcome)`: the `checkGrant` DENIED event passes `action` twice, while the `create` SUCCESS event passes `EXCHANGE` first. Assert each shape exactly.
- `OrderRepository.appendSnapshot` argument order is `(id, orderId, version, content, fingerprint)`; the snapshot content to capture is the fourth argument.
- A new file under a brand-new directory appears in `git status --porcelain` as the directory (trailing `/`), so `worker_gate.py` reports a `scope` violation until the files are committed; commit before trusting that verdict.
- Confirm the `opencode.json` CI-profile `skip-worktree` artifact once, record the failing command and final line, run the remaining gate stages individually, and never regenerate the protected file.
