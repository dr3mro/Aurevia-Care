## Lessons for workers

- For a proof-only spec-clause story whose implementation already exists, write active `it(...)`
  tests and Status "Proven by tests"; do not skip them, and do not add production code just to
  create a red run.
- Make each negative a single-field differential from the valid fixture and assert the exact
  error code plus the absence of a resolved document reference. A positive `resolves.toEqual` on
  the valid fixture alone is tautological if the parser is an identity function.
- Local fixtures under `src/spec/patient-access/` must be redefined in the new test: importing
  from another `.test.ts` re-registers its `describe` blocks. Use `import type` for type-only
  imports under `verbatimModuleSyntax`, and the recorder pattern avoids needing `jest` from
  `@jest/globals`.
- Run `python3 -I scripts/check-docs.py` only after `npm ci` has finished; running it concurrently
  can scan a partially replaced `node_modules` and produce a transient `FileNotFoundError`.
