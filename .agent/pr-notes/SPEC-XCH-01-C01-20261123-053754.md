## Findings

- **Contract gap (pre-existing, out of scope):** `POST /api/v1/orders` is implemented in
  `OrderController.java:43-47` but absent from `contracts/openapi.yaml` (only `GET /api/v1/orders`
  at line 401). It is already tracked in `contracts/openapi/missing-routes.txt:251`. No contract
  edit or client regeneration was made, per task scope.
- **Source-actor persistence nuance:** `OrderRepository.insertOrder` does not write `source_actor`;
  the V19 trigger `set_exchange_source_actor_from_actor` fills it from `app.actor`. A service-level
  assertion on the in-memory `OrderView` alone cannot prove the database round trip, so the evidence
  doc cites the unmodified `OrderExchangeIntegrationTest` HTTP assertion as the end-to-end proof.
  The next worker touching this clause must keep both halves.
- **Worker-gate false positive:** `scripts/worker-check.sh` and the Python tooling suite stop on the
  CI-profile-under-skip-worktree `opencode.json is stale` check (OPS-CW-003-01). Confirmed once with
  `git ls-files -v`, file hashes and a non-mutating generator render comparison; remaining stages
  were run individually. No protected file was edited.
- **Pre-existing tool note (not changed):** `scripts/check-wiring.py` exits 0 but notes that
  `apps/api/src/main/java/com/aurevia/smartclinic/messaging/evidence/G3EvidenceService.java` is
  fixed in source and could be removed from `scripts/wiring-baseline.json`. That is protected-file
  debt for a separate task, not part of this scope.
- **Pre-existing committed conflict markers (not introduced here):** `git grep -nE '^(<<<<<<<|>>>>>>>) '`
  finds six marker lines inside Javadoc comments in `apps/api/src/main/java/com/aurevia/smartclinic/exchange/hl7/`
  (for example `Hl7ParseException.java:6,10`). `git show HEAD:<path>` contains the same lines and
  `git diff --name-only` is empty, so they are already committed on the base branch and compile only
  because they sit inside comments. A separate owner should clean them up; this task did not edit
  any production file.

## Lessons for workers

- For a clause-proof task, survey the existing HTTP-level integration test, the persistence trigger
  and the OpenAPI entry BEFORE writing the service-level test; the plan reviewer requires the
  evidence doc to separate "nine fields proven at the service entry point" from "end-to-end proof
  carried by the unmodified HTTP test", or the plan is NO-GO.
- In a cloud worker, when `worker-check.sh` stops at `opencode.json is stale`, confirm once with
  `git ls-files -v` (`S`), a hash comparison with `.github/opencode.ci.json` and
  `git show HEAD:opencode.json` against the generator render, then run the remaining gate stages
  individually. Do not regenerate or commit that protected file, and do not re-diagnose it later.
- Stub the valid grant before emptying `patientIdentity` in a 404 negative test: `checkGrant` runs
  first, so without it the assertion sees `403 DISCLOSURE_NOT_AUTHORIZED` instead of `404 NOT_FOUND`.
