## Decisions and risk notes

- Concealment: the production `load()` paths return 404 NOT_FOUND and the error body contains only `code`, generic `message` and a correlation id. Tests compare the full body after normalising the correlation id, so an existence leak through different codes/messages fails the test.
- The production code returns 403 for a same-tenant wrong-facility id and for a removed participant, and does not write an audit fact for a 404 load. Tests assert the behaviour that exists, and both residual gaps (403-vs-404 enumeration and unaudited concealment) are escalated under `## Findings` with task requests rather than editing production code (out of scope). An owner decision is required to accept or close them before the story's "audited without leaking existence" clause can be claimed fully met.
- The SSE factory seam is package-private; the security package reaches it through reflection in the fixture with a documented reason, avoiding a change to production visibility.

## Lessons for workers

- A test-only story still needs a fault-detection phase: temporarily break one control per class, run the exact targeted test, capture the failing assertion, then restore the file byte-for-byte and rerun the suite.
- Mockito stubs must not mix a raw value with a matcher (`eq(ORG_B), anyString()`), and a mail concealment injection must also satisfy `visibleTo`, or the red run proves nothing.
- Check helper visibility before planning reuse: `InMemoryMailStore` is package-private, `InMemoryStaffAttachmentStore` is public. The public `MailStore` interface plus a Mockito mock is the cross-package route.
- In a cloud worker, `check-pack` failure and `test_check_pack` failures are the CI `opencode.json` under `skip-worktree`; confirm with `git ls-files -v`, do not regenerate or commit it, and run the other gate stages individually.
- Mock a captured `SseEmitter` via the package-private `EmitterFactory` seam with a reflective proxy for deterministic `never().send()` assertions; keep `TenantContext.clear()` in `tearDown` for both servlet and direct-service tests.
