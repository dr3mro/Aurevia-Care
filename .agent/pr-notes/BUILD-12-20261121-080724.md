- Runtime role `smartclinic_app` gets read + append (and controlled UPDATE on episode,
  evaluation, scale approval and draft notes); DELETE/TRUNCATE are revoked and append-only
  triggers reject immutable mutation for every role, including the migration owner.

  stay in `TherapyService`; the migration adds no application bypass.
- Audit: `therapy_audit_event` records organization, actor subject, action, resource and outcome
  per PT-01 command; append-only with a per-tenant identity sequence.

## Lessons for workers

- On a resume story, read the existing domain and tests before implementing: here the entire
  PT-01 behaviour and its 44 negative/positive tests already existed, so the real deliverable
  was the reserved migration. Reuse, verify and record that — do not rewrite.
- In a cloud worker, treat `check-pack.py`/`gen-opencode.py`/`test_check_pack.py` staleness of
  `opencode.json` as the known skip-worktree CI-profile artifact, not a defect in your diff;
  confirm with `git status --short` and `git ls-files -v opencode.json`.
- `scripts/check.sh` → `apps/api/check.sh` → full `mvn verify`; do not run it from a worker even
  though a generic checklist names it. Use targeted `-Dtest=... test`, `jacoco:report`,
  `db/check.sh` and the policy scripts instead.
- A reserved `V<n>__build_XX.sql` name is allowed: `check-names.py` only inspects folders and
  Java packages, not migration filenames.
