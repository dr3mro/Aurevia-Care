## Authorization boundaries and audit events

Every fact and returned item carries an `organizationId`; both queries filter on the active tenant and copy that id onto the item, so identical local ids in two tenants never cross. `OperationalQueueItem.assign` / `resolve` require a non-empty `actor` and `reason`, reject a resolved item (409 `INVALID_TRANSITION`) and an action at or before creation (422 `INVALID_ACTION_TIME`), and append an immutable `QueueAction`.

This domain model deliberately does **not** enforce the ADM-02 operator allowlist (`tenant_admin`, `privacy_auditor`, `operator`), active-at-next-action revocation, or an `audit_id` referencing an existing OPS-02 audit event: there is no operator registry, audit appender or command boundary in the scoped paths. Those must be enforced by the future command/controller boundary before live enablement. No audit event was added or changed and no clinical payload is logged or returned by these types.

## Findings

1. **End-to-end "done" gap is a scope decision, resolved by hand-off (no code fix possible in scope).** AGENTS.md's "done means working end to end" would require a Flyway migration with RLS/FORCE RLS, a `Jdbc*` store behind a `*Store` interface, a controller receiving its service by injection, an HTTP-level integration test and an OpenAPI entry plus a regenerated client. BUILD-17 reserves no migration version and its `scope` names only `clinical`/`config` main/test directories, so none of those can be added here. The scoped projection is complete and 100% covered but not reachable from HTTP and not durable across a restart. This pass does not silently claim otherwise: it re-requests the follow-up story below (V91) and leaves the wiring gap explicit.
2. **No durable operator actions or audit references.** Items are re-derived and `assign`/`resolve` return immutable values; nothing persists the assignment, reason or actor. ADM-02's per-action `audit_id` and operator allowlist are intentionally absent because no audit/operator boundary is in scope. The follow-up must add them before live enablement.
3. **Partial ADM-02 action/state set.** The authoritative catalog also defines `escalated`, `escalate` and `retry`. The task asks specifically for assign/resolve/reason on these two queues, so `escalate`/`retry` and the other five queues are deferred, not silently claimed. The catalog itself marks `retry` scope as a declared assumption needing site alignment.
4. **Declared assumption needing a site ruling:** suppression is encounter-wide. Any signature-bearing revision (`SIGNED` or `ADDENDUM`) removes the encounter even if a newer `AMENDMENT_DRAFT` is unsigned. This follows the explicit "signed encounter leaves the queue" acceptance criterion but is narrower than a per-note reading of the catalog. It is documented in `UnsignedEncounterQueue`'s Javadoc and pinned by `anAmendmentDraftWithASignedOriginalLeavesTheQueue` and `aSignatureBearingAddendumAlsoRemovesTheEncounter`.

## Lessons for workers

- Survey the domain before adding a type: `NoteState.editable()` and `signatureBearing()` already encode CLN-05 signature semantics, so the unsigned-encounter queue is a short projection rather than a duplicated state machine.
- With a narrow scope and no migration, a pure immutable projection with static queries is preferable to an in-memory holder in `src/main`: it avoids new `InMemory*`/`Service`/`Store` wiring findings, cannot leak across tenants and is deterministic to test.
- Targeted `clean ... test jacoco:report` + reading `jacoco.csv` proves 0 missed counters per touched class without the forbidden full `verify`; JaCoCo counters are `missed/covered` (`0/22` is 100%).
- In a cloud worker, check `git ls-files -v opencode.json` first: flag `S` means `check-pack` failures are a CI-profile measurement artifact, not a defect.
- `check-wiring.py` prints stale-baseline notes on a clean tree; those are not new findings and must not be "fixed" by editing the protected baseline.
- When the catalog wording and an explicit acceptance criterion can be read differently (encounter-wide vs per-note signing), implement the acceptance criterion, declare the interpretation in Javadoc and notes and add a synthetic test that pins it.
- Root `.gitignore` ignores any directory named `coverage/`; a Java package `config.coverage` would be untracked. The domain package is `config.rosters` instead — check `git check-ignore -v <new file>` before staging a new package.
- Distinguish an out-of-scope "done" gap and pre-existing main-level red gates from an in-scope defect: verify the scoped slice to 100%, then hand the gaps off with a `task-requests` entry instead of silently editing files the task forbids.
