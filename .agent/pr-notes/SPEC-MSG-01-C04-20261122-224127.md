## Lessons for workers

- A copied `@SuppressWarnings("unchecked")` from an existing test is still an *added* suppression in
  a new file: `scripts/check-constraints.py --base origin/main --require-base` fails the integrator
  gate. Use wildcard target typing (`TransactionCallback<?> cb = invocation.getArgument(0)`) instead.
- `-Pno-security` makes SpotBugs vacuously green (`Spotbugs plugin skipped`); add
  `-Dspotbugs.skip=false` to get a real verdict, and compile first so the check is not vacuous.
- On the positive `ConversationService.reply` path, stub `repository.patientLinkActive(subject, patientId)`
  as well as `loadForUpdate`/`nextSequence`/`find`; otherwise the fixture fails with a 404 that is not
  a production defect.
- In a cloud worker, confirm the `opencode.json` CI profile once (`git ls-files -v` → `S`,
  `git show HEAD:opencode.json`) and then run remaining gate stages individually; do not regenerate
  the protected file or repeat the diagnosis on a later pass.
- A test-only clause story can honestly claim "Proven by tests" only when both the denial and the
  permitted path are exercised through the command entry point; include positive tests so the proof
  is not vacuous with respect to the rule being enforced.
