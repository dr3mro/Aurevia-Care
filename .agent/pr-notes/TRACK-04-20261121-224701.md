# TRACK-04 — API integration tests: prescribe→pharmacy and order→released result

## Summary

Re-verification pass (attempt 2) of the whole-loop, two-tenant API integration tests under the
single allowed scope `apps/api/src/test/java/com/aurevia/journey/loop`. The scoped
test suite was authored and merged in the earlier attempt (PR #587, commit `d7ebb5ef`), so this
run changed no production or test source: it re-ran every applicable gate at the current HEAD
(`d345f387`, equal to `origin/main`) and confirmed the deliverables still hold after the many
later merges. The four test classes are:

- `PrescriptionJourneyLoopTest` — RX-02 / XCH-03: prescribe (create + attest), route (transmit +
  confirm delivery), pharmacy accept, dispense; plus a same-local-ID / peer-context isolation test.
- `LaboratoryJourneyLoopTest` — LAB-01 / LAB-02 / XCH-03: authorized exchange order, collect
  (accession + matched specimen), result (preliminary), verify (second verifier → final), release
  (immediate patient visibility), corrected report + corrected release.
- `ImagingJourneyLoopTest` — RAD-01 / XCH-03: worklist receive, schedule + study link, signed
  report, addendum + referrer acknowledgment.
- `LoopSupport` — shared synthetic DB seeding, tenant-aware HTTP client and journey projector
  helpers (disjoint time bands, cross-item mix, 404 cross-tenant probes).

After each step the facts observed in real HTTP responses are normalized to `JourneyEvent`
records and projected with the real read model `JourneyTimeline.view(...)`, asserting the exact
complete/pending pattern and the next expected step. Two tenants (ORG_A, ORG_B) run side by side
with identical local IDs; facts are mixed before projection and each tenant's HTTP reads are
checked against the peer (cross-tenant 404; non-member peer context 403). All data is synthetic.

## Authorization boundaries and audit events

Every request carries only synthetic headers (`X-Synthetic-Subject`, `X-Active-Organization`)
plus command `If-Match`/`Idempotency-Key`. Roles are seeded per tenant (clinician, clinician/
prescriber, pharmacy_staff, lab_collector, lab_verifier, radiology_staff, radiology_interpreter,
reception, tenant_admin); lab verification uses a different subject from result entry so
`SELF_VERIFICATION` is not triggered. Asserted boundaries: cross-tenant reads of the peer's
prescription, order, lab result, release and imaging worklist/report return 404; a subject without
membership in the peer tenant gets 403; identical local IDs resolve to each tenant's own row.
No audit event was added or changed by this story; existing audit events emitted by the exercised
endpoints are not asserted beyond their HTTP effects.

## Lessons for workers

- When a task is re-dispatched after its commit is already merged, verify the scoped tests at the
  *current* HEAD before assuming the work is missing; later merges are the usual reason a
  previously green suite must be re-proven.
- A red repository-wide `quick-check.sh` is not always this task's fault: attribute failures by
  the changed-path/scope and the failing test names before fixing anything out of scope. Here the
  three OpenApi rule failures name SMSG instant-messaging routes, not journey/loop code.
- Reconfirm the `opencode.json` CI-profile `skip-worktree` artifact with `git ls-files -v` and
  `cmp` against both `.github/opencode.ci.json` and `git show HEAD:opencode.json`; run local gates
  with the HEAD bytes restored and put the CI bytes back byte-for-byte. Never regenerate or
  commit that file.
