## Lessons for workers

- Before a path rename, run the repo-wide grep first and classify each hit by
  ownership (in scope vs protected). Here the only out-of-scope owner was
  `scripts/check-names.py`, which is safe to leave because a stale allowlist
  entry cannot fail the check — but it must be reported for owner cleanup.
- `check.sh` scripts in this repo use `cd "$(dirname "$0")"` and relative paths,
  so moving their folder needs no edit to the script body. The `s_g5_` hits were
  in docstrings, Markdown links and temp-path names, not in the shell gates.
- In a cloud worker, a red `check-pack.py` / `gen-opencode.py --check` is usually
  the skip-worktree CI profile, not a stale generator. Check `git ls-files -v
  opencode.json` and compare with `git show HEAD:opencode.json` before changing
  anything; never "fix" it by editing the generated file.
- A path-string replacement helper scoped to `infra/` and `docs/operations/`
  automatically catches cross-folder links (for example
  `docs/operations/s_g5_07/evidence-contract.md` pointing at `../s_g5_05/`),
  which a per-folder edit would miss.
