# RESP-E2E-PROJECTS — staff web Playwright device matrix

## Summary

Turned the single-Chromium Playwright harness into a device matrix. Added nine
Chromium device projects (phone, tablet, laptop and desktop viewports from the
story acceptance list) and six opt-in WebKit/Firefox variants behind
`E2E_CROSS_BROWSER=1`. The existing `chromium` project, global settings and
`webServer` are byte-for-byte unchanged. Only `apps/staff-web/e2e/playwright.config.ts`
was edited. Evidence below is **tool evidence** from commands I executed unless
labelled reviewer or simulated user; there was no human or clinical participant.

## Coverage

`e2e/playwright.config.ts` is outside every coverage instrument: `tsconfig.json`
includes only `src`, `tests` and `vite.config.ts`, and Vitest uses
`--exclude 'e2e/**'`. A numeric coverage percentage for this file is therefore
an unavailable metric; per CODING_STYLE.md it is documented here with the
closest compensating executable evidence (the two `--list` runs plus the
assertion-bearing config evaluation). The canonical gate reports 100% on all
213 instrumented staff-web source files.

## Findings

1. **Brief command is wrong.** Bare `cd apps/staff-web && npx playwright test
   --list` collects Vitest specs from `tests/` and prints `TypeError: Cannot read
   properties of undefined (reading 'config')`, `Total: 0 tests in 0 files`. The
   `e2e` npm script uses `--config e2e/playwright.config.ts`; all evidence here
   uses that explicit form. The story's step 3 wording needs correcting.
2. **Project-name contract change for downstream tasks.** The brief mandates
   `<device-class>-<WxH>` names, so `npm run e2e -- --project=phone-portrait`
   (referenced in task 00338 / TODO) now selects nothing. Use e.g.
   `phone-portrait-360x740`. RESP-README must document this.
3. **Flag documentation/CI wiring.** `E2E_CROSS_BROWSER` is referenced only in
   this config; no workflow installs WebKit/Firefox or sets the flag (confirmed
   by context-optimizer). Document the flag in RESP-README (out of scope) and
   wire it into an e2e CI job after browser installation as a separate task.
4. **Design doc drift.** `docs/design/responsive-layout.md` §13 lists
   320x720, 360x780, 720x320, 768x1024, 1024x768 and 1280x800; the story sizes
   used here (360x740, 390x844, 844x390, 820x1180, 1180x820, 1280x720,
   1920x1080) differ. The story is authoritative; downstream specs must use the
   project names above rather than the §13 names.
5. **Pre-existing strict-tsc incompatibility.** Running strict tsc with
   `--exactOptionalPropertyTypes` over the config fails on the frozen
   `webServer: process.env['E2E_BASE_URL'] ? undefined : {...}` line: `Type
   'undefined' is not assignable to type 'TestConfigWebServer |
   TestConfigWebServer[]'`. Reproduced identically with `git show
   HEAD:apps/staff-web/e2e/playwright.config.ts`, so it predates this change and
   was not fixed (the brief freezes `webServer` byte-for-byte).
6. **Pre-existing smoke spec limitation at phone width.** See Test evidence:
   the language-toggle test fails at 360x740 because the control is in the
   compact drawer. `smoke.spec.ts` is out of scope; a task request is included.
7. **Pre-existing committed conflict markers** in
   `apps/api/src/main/java/com/aurevia/smartclinic/exchange/hl7/Hl7*.java` exist
   in HEAD (`<<<<<<< HEAD` / `>>>>>>> origin/swarm/BUILD-37-469`). `git merge
   --no-edit origin/main` reported `Already up to date`; these are unrelated to
   this change and were not touched.
8. Earlier issue-monitor findings were noise (no prior notes, PR or failing
   pipeline for this task). Implementation started from the current config.
9. **No committed test guards the config.** A future edit could silently break
   the matrix because no gate instruments `e2e/`. The config-eval assertions
   used here live outside the repo; a task request is included.
10. Chromium and its OS libraries were installed in the worker image only
    (environment setup), never committed.

## Lessons for workers

- In `apps/staff-web`, Playwright commands must include `--config
  e2e/playwright.config.ts`; the bare command collects Vitest specs and fails.
- `--list` proves only names and counts. Evaluate the config with
  `node --experimental-strip-types` and `node:assert/strict` to prove viewport,
  screen, touch, mobile and browser engine; run one process per env state.
- `devices['Desktop Chrome']` carries `screen: 1920x1080`; override `screen`
  whenever overriding `viewport`, and do not spread a Chromium descriptor into
  a WebKit/Firefox project (it brings `defaultBrowserType: 'chromium'` and, for
  phone descriptors, `isMobile: true`).
- `isMobile` is Chromium-only; use `hasTouch` for coarse pointers on Firefox and
  WebKit. Gate on `process.env['FLAG'] === '1'`, not truthiness.
- `exactOptionalPropertyTypes` rejects the idiomatic Playwright
  `webServer: cond ? undefined : {...}`; the e2e config is outside tsconfig, so
  run strict tsc over the file with that one flag omitted and record the
  pre-existing error separately.
- Install browsers and OS libraries as worker-environment setup, delete
  `test-results/` and `playwright-report/` before committing, and keep notes to
  the single file named in the prompt.
