## Lessons for workers

- A "Repair main" story quoting only the `if: always()` artifact-upload tail has
  not identified the failure. Reproduce the job's real run steps locally
  (`apps/api/check.sh` = tests + JaCoCo + OWASP + SpotBugs, then `db/check.sh`) and
  capture the first failing step and its final line before classifying.
- For a Java integration failure, use `mvn -Pno-security -Dgroups=integration
  -Dtest=<Class> test` with `SMARTCLINIC_PG_ADMIN=postgres`. Never add `fast`:
  `-Pno-security,fast -Dgroups=integration` excludes integration tests and gives a
  false green.
- When a service validates drafted values against an approved config fold, an
  HTTP proof test must seed the config fold (entry + approval, tenant-scoped) in
  its own scratch DB. `UseSiteSApprovedUrgentDowntimeChannelsTest.seedPolicy` is the
  canonical pattern; the seeded codes must match the test's own request literals.
- A test-only fixture fix has no new production coverage obligation; do not claim
  a targeted `jacoco:report` proves the bundle. Record that the authoritative
  BUNDLE 1.00 JaCoCo gate belongs to the integrator's `-Pno-security verify`.
