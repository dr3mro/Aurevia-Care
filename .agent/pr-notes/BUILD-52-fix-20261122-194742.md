# BUILD-52 — Staff web: register the new feature routes and navigation (fix pass 2)

## Summary

BUILD-52 registers the BUILD-45..51 feature routes in the staff-web shell and adds
their role-scoped rail entries. The production change is contained in
`apps/staff-web/src/app` (commit `cebabcbd` plus the fix edits in this pass):

- `AppShell.tsx` lazily loads a fixed `ForbiddenPage` and swaps it in when the
  matched route is denied by the active role.
- `navigation.ts` adds the `exports` / `imports` label keys, the two Operations
  navigation rows, and the `routeAccessRoles` / `canAccessRoute` helpers that
  mirror `navigationFor`, so a link hidden from a role cannot be opened by URL.

  direct-link behaviour.

## Lessons for workers

- Re-run the full canonical gate after merging `main` before assuming a prior
  worker's red result still applies; the earlier "checks: failed" was a
  stale-base artifact, not a code defect.
- Keep the shell's role table in sync with each feature's authoritative role
  constant. A rail row that grants fewer roles than the page/API authorize makes
  the new shell guard deny legitimate users on a direct link.
- A branch is not covered just because it was evaluated: the named test must
  fail if the clause were removed. Short-circuit operands such as
  `|| roles.includes(ALL_STAFF_ROLE)` are easy to leave untested.
- Distinguish in-scope regressions from pre-existing out-of-scope gaps when a
  reviewer flags a security issue. File a `task-request` for the latter rather
  than inventing roles or editing feature files outside the declared scope.
- For the staff web, the definition of done is `bash apps/staff-web/check.sh`
  (typecheck, lint, build, gzip budget and per-file 100% coverage), not Vitest
  alone; `tsc --noEmit` prints nothing on success, so paste the
  `npm run typecheck` final line separately.
