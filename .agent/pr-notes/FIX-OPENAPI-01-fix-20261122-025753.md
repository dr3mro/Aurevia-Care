# FIX-OPENAPI-01 — fix pass: re-merge `origin/main` to remove stale instant routes from the contract

## Summary

The integrator/debugger reported that PR #632's branch was red on its SHA with
three contract-rule failures caused by a **stale merge**, not by a defect in this
story's gate. The branch's `contracts/openapi.yaml` still documented 8 lines of
`/api/v1/staff/instant/...` routes that `origin/main` deliberately removed in
`bec14c4c`; the contract-rules and pagination-rules tests correctly rejected those

origin/main` into the branch and resolve the single conflict in

superset of the branch's, with data lines still sorted and unique, so no route is
lost). The merge removes the instant paths from the contract and generated client;
main's baseline correctly re-records the 9 instant routes as contract debt.

## Findings

1. **Root cause confirmed: stale merge.** Pre-merge HEAD contained 8
   `/api/v1/staff/instant` lines in the contract; `origin/main` (tip
   `f6c45d25`, containing `bec14c4c`) contains 0. The three reported failures
   (`OpenApiContractRulesTest.committedStaffApiContractSatisfiesEveryRule`,
   `OpenApiPaginationRulesTest.committedContractPassesEveryPaginationRule` and
   `.theOnlyExemptionIsTheBareArrayCatalogFamilyList`) disappeared after the
   merge. The 16-line baseline refresh from the earlier worker is already in
   main and was not repeated.
2. **Conflict resolution verified, not blind.** `origin/main`'s
   `missing-routes.txt` (351 lines) is a strict superset of the branch's
   (342 lines): all 9 added lines are instant routes (`GET` conversations /
   unread / `{}/messages`, `POST` direct / groups / participants / read /
   `{}/messages`, `DELETE` participants). `comm -23` of the sorted unique sets
   was empty and the data lines passed `sort -u`; no documented route was
   dropped from the baseline.
3. **`check.sh` cannot complete in this cloud worker.**
   `git ls-files -v opencode.json` → `S` (skip-worktree); worktree sha256
   `50005c9c…` differs from committed HEAD `0dc2ac8e…`, so `check-pack.py`
   judges the CI profile rather than HEAD. This predates the change, is out of
   scope (worker rules forbid editing `opencode.json`, `.opencode/`, `scripts/`)
   and is recorded as OPS-CW-003-01. All policy checks after `check-pack.py`
   were run individually and passed.
4. **Committed conflict markers exist in `origin/main` itself** in
   `apps/api/src/main/java/com/aurevia/exchange/hl7/`
   (`Hl7ParseException.java`, `Hl7Parser.java`, `Hl7Segment.java`). They are
   inside Javadoc text (prefixed `*`), so compilation and the parity test are
   unaffected, and they survive the merge unchanged. They are pre-existing and
   outside this task's scope; no attempt was made to "fix" them here.
5. **The branch now equals `origin/main` in content** apart from an earlier
   worker's notes file; the fix is entirely the re-merge. Trusted jobs must
   push the merged SHA so CI can verdict it — this worker did not push, tag or
   call `gh`.
6. **The debugger's fourth proof command** (`mvn -Pno-security,fast test`, the
   full unit tier) was intentionally not run: the worker rule forbids
   commands that run every test, and only the four affected contract test
   classes were executed. The integrator/Delivery run the full gate.

## Lessons for workers

- When the integrator reports contract-rule failures after parallel merges,
  first check `git rev-list --left-right --count HEAD...origin/main`: a stale
  branch whose contract still carries routes removed on main is a common cause,
  and a re-merge — not a new test or allow-list edit — is the whole fix.
- Before `git checkout --theirs` on a baseline conflict, prove the incoming file
  is a strict superset (`comm -23` on sorted unique data lines) and that its
  data lines are sorted and unique; this keeps both sides' intent and avoids
  silently dropping a baseline route.
- `git grep -nE '^(<<<<<<<|>>>>>>>) '` can report markers already committed in
  `main` inside Javadoc comments; do not "resolve" out-of-scope files during a
  merge just to silence that grep — verify against `origin/main` first.
- A red `check-pack: opencode.json is stale` in a cloud worker is the
  skip-worktree CI profile, not a change defect; confirm with
  `git ls-files -v opencode.json` and compare worktree vs `git show HEAD:`.
