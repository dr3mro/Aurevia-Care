owner decision in `MEMORY.md` (line 33) and the current `AGENTS.md`

## Findings

1. **Decision compliance (root cause of this pass).** The branch's aliased class
   (`Component as RenderErrorBoundaryBase`) passed the literal grep scan but
   violated `MEMORY.md` line 33 and the now-stricter AGENTS.md function-component
   rule. The offending class is gone: the `react-error-boundary` dependency owns
   the unavoidable catcher and our module declares no class. Three compliance
   tests now guard the decision, including aliased-base regressions the generic
   scan cannot see.
2. **React dev replay discards hook state.** An initial `useRef`-based ID was
   generated twice because React replays the erroring tree and remounts function
   components. The code now keeps a single module-level failure record (valid
   because there is one global boundary and one active failure), cleared on Retry
   and in the test `afterEach`. This keeps one ID and one log line per failure.
   The rationale is documented at the module state and in the compliance tests.

   exits 2 at the root `tsc --noEmit -p tsconfig.json` step on

## Lessons for workers

- A React 18 error boundary must be a class somewhere. Under a
  function-components-only policy, put that class in a reviewed, exactly-pinned
  dependency and wrap it in a function component; do not alias
  `React.Component` to slip past the literal forbidden-pattern grep.
- React replays an erroring render tree and discards in-progress hook state, so a
  `useRef` inside a boundary wrapper is not stable across the replay. Use one
  module-level record for a single global boundary and clear it on Retry.
- `scripts/frontend-check.sh` also type-checks patient-mobile files from the
  repo root. A patient-mobile test using bare `jest` fails the whole gate even
  for a staff-web-only change; confirm the failing path is in your scope before
  treating it as your own regression, and record it under Findings.
- Re-run the exact command that failed in the integrator (`bash
  scripts/frontend-check.sh`) and the affected app's check (`bash
  apps/staff-web/check.sh`), not just a single test file, before declaring ready.
