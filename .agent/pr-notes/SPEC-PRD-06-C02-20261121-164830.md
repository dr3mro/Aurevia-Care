## Lessons for workers

- A negative/exclusion clause is best evidenced by naming the enforcing classes and tests for each forbidden item and writing "found none" explicitly for the rest; do not infer compliance from a single grep.
- Use fully qualified relative links from nested `docs/spec/clauses/<locale>/` files: four `../` segments reach the repository root. Verify with `python3 -I scripts/check-docs.py` plus a link-existence audit before finishing.
- Watch for benign keyword collisions (`controlled` = guarded batch/transmission, `discharge` = PT episode, `WalkInPatient` = scheduling fixture) when claiming that a feature is absent.
- A requirement ID mentioned in a new Markdown file must be defined in `PROJECT_V1_SPEC.md` or `check-docs.py` fails the build; gate IDs such as `G5` and task IDs such as `S-G5-04` are not matched by that rule.
