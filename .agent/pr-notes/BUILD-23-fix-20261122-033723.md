## Lessons for workers

- Before re-fixing a red PR, query the Checks API for the exact head SHA. A still-`in_progress` heavy job is not a failure; do not invent a fix or claim a pass/fail before a conclusion is published.
- When a contract is edited on `main` after a story packaged a copy, the drift test is the real gate — re-run it and the route-parity gate against the merge result before declaring readiness. A byte-for-byte `cp` plus `cmp`/sha256 is the whole fix.
- A new public route must be declared where the parity test can see it (`contracts/openapi.yaml` or `contracts/openapi/missing-routes.txt`). Clean-`main` parity is not evidence that your branch will pass: the route only exists after your change.
- JaCoCo evidence from an accumulated `jacoco.exec` can overstate a targeted run. Reset `apps/api/target/jacoco.exec`, run the complete in-scope batch (include `BrowserSessionHttpTest` for the browser-session/logout lines), then generate and parse the report.
- In a cloud worker `opencode.json` is the CI profile under `skip-worktree`; confirm with `git ls-files -v` and hashes, restore HEAD bytes only under a trap for local gates, then restore the CI bytes and re-verify the hash. Never commit that file.
- Respect the worker time limit: `apps/api/check.sh`, `scripts/check.sh` and `scripts/coverage-check.sh` end in full `mvn verify`; use `scripts/quick-check.sh` plus standalone SpotBugs and JaCoCo instead and let the integrator run the heavy gate.
