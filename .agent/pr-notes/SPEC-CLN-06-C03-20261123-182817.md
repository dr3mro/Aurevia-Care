## Implementation map (read-only survey)

The clause is already implemented; there is no build gap. The real path is:

- `FollowUpController` (`POST /api/v1/follow-ups/suggest`, `/{id}/override`, `/{id}/confirm`, `/{id}/tasks`, `GET /{id}/tasks`, `/tasks/{taskId}/complete`) → injected `FollowUpCommandService` → `FollowUpService`.
- `FollowUpService.confirm` is the only command that calls `booking.book(...)`; its guards are: version precondition (parsed by `IfMatch.parse` in the controller), authenticated context (401), active membership + `APPOINTMENT_BOOK` role (403), already-confirmed (409), version match (412). ## Lessons for workers

- When proving a version precondition at HTTP level, assert the parser's code (`INVALID_IF_MATCH` from `IfMatch.parse`), not the deeper service code (`INVALID_VERSION`): the controller parses before the service, so the HTTP body can only show the parser's decision.
- `worker-check.sh` stops early at `check-pack.py` under the OPS-CW-003-01 skip-worktree profile. Confirm once with `git ls-files -v opencode.json` = `S`, then run its later stages (docs/wiring/policy scripts, targeted `-Dtest=...`, SpotBugs) individually; never regenerate the protected `opencode.json`.
