# SPEC-XCH-02-C03 — XCH-02 clause 3 (API test)

## Summary

Adds a synthetic, database-free clause proof that a transmission delivery receipt
cannot close or advance a clinical task (`SMARTCLINIC_V1_SPEC.md:64`, XCH-02
clause 3: "A transmission acknowledgment cannot close a clinical task."). The
rule is already implemented in `ExchangeTaskService`, `ExchangeStateMachine`,
`ExchangeActionPolicy` and the V20 database guard, so this change is test and
documentation only: **no production code, existing test, contract or migration
was changed**, and no `@Disabled` case was needed. Eight tests enter through the
real `ExchangeTaskService.execute` entry point and assert both the rule being
met and five distinct classes of refusal.

## Lessons for workers

- For a clause-proof story on an already-implemented rule, a green first run is expected; spend the effort on making negatives discriminating: stub membership TRUE for a wrong-role case, and add explicit `never()` write assertions so a stale-version test cannot be satisfied by the CAS-false 412.
- On a denial, the audit action is the dimension's `policyAction()` (`EXCHANGE_REVIEW` for RESOLVE/ACKNOWLEDGE), not the command's `auditAction()`; if a single test has a positive control, `clearInvocations` before the denial verifications and verify the control's writes first.
- A mocked empty `loadForUpdate` cannot prove tenant isolation. Keep the test name only if the Javadoc and clause doc explicitly scope it to the service 404 path and cite the real RLS/HTTP integration tests.
