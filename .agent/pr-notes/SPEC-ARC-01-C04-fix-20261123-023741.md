## Lessons for workers

- For clause-proof stories, grep for the rule's implementation before assuming the clause is missing; the issuer-uniqueness rule lives in `lab/accession/LabAccessionService.accession` and `V26__laboratory_accession.sql`, while no partner-identifier surface exists at all.
- Reuse the neighbouring HTTP fixture's DB setup but use a dedicated database name and disjoint synthetic MRN/accession prefixes per test method; under a shared `UNIQUE` key a repeated pair across methods returns 409 and fails the wrong assertion.
- Creating a patient requires the `reception` role even when the clause under test is about laboratory accession: seed a registrar in every tenant whose patient fixture is created.
- In this worker image, `check-pack.py` and `test_check_pack` "opencode.json is stale" failures are the documented CI-profile artifact: confirm with `git ls-files -v opencode.json` and `git show HEAD:opencode.json`, record it, and never edit or regenerate the protected file.
- `scripts/check-constraints.py --require-base` rejects every added `@Disabled`/`skip`, even when a story step asks for a GAP test. Record the gap in the clause note and a follow-up task and keep the suite free of skipped tests; a verbatim reason does not exempt the line from the gate.
- Do not run `scripts/worker-check.sh` in a swarm worker: it runs every integration suite and times out the run. Run the targeted `-Dtest=...` suite plus the individual policy scripts and SpotBugs, and leave the full gate to the integrator.
- When a fix-pass prompt names a `-fix-<timestamp>.md` notes file, create that exact file even if an earlier notes file already exists from the first worker; the integrator reads the prompted path for verdicts and may report "did not finish cleanly" when only the earlier name is present.
