# SPEC-MSG-06-C01 — MSG-06 clause 1: enabled unit publishes service hours, response targets, topics and urgent instructions

## Summary

Adds a synthetic, test-only acceptance proof for `PROJECT_V1_SPEC.md:103` ("Each
enabled unit must publish service hours, response targets, appropriate topics and
urgent contact instructions.") plus the mandated clause record. The clause is already
implemented in `messaging/service` and persisted by V92, so no `@Disabled`, no failing
test and no production edit is left behind. One positive test publishes, approves and
serves a profile and asserts all four field groups; four refusals prove the wrong role,
a stale version, another tenant's unit and missing mandatory publish fields.

## Lessons for workers

- For a test-only clause proof of already-built behaviour, a RED run is not available;
  prove reachability through the normal domain entry point and cite the existing HTTP
  integration suite instead of manufacturing a failure.
- In a cloud worker, confirm the `opencode.json is stale` failure once (`git ls-files -v`
  shows `S`, worktree equals the CI profile, committed HEAD equals `gen.render`), then
  run the remaining gate stages individually; never regenerate or commit that file.
- Stop a gate command that crosses the five-minute worker budget and run the single
  clause-relevant integration class; leave the full integration suite to the integrator.
- Reuse `InMemoryServiceProfileStore` and `Clock.fixed` from the neighbouring
  `messaging.service` tests for synthetic, deterministic clause proofs; assert the exact
  `id`/`version` so a pre-seeded profile cannot satisfy the field assertions.
