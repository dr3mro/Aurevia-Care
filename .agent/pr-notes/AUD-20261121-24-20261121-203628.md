FIX-OPENAPI-01 and FIX-OPENAPI-02 already track this; this story's scope excludes `contracts/`, so it was not changed. This is a documentation/contract gap, not a runtime defect.
4. **Pre-existing tooling failure.** Five `test_check_pack` failures are the CI-profile `opencode.json` skip-worktree artifact, not a regression (details under Test evidence).
5. `DocumentService.link()/render()` (the separate chart-document CLN-07 path at `/api/v1/documents`) was deliberately left unchanged; both specialists agree it is a different controller/store flow and that its immutable render versioning is already covered by `DocumentDownloadHttpIntegrationTest`.

## Lessons for workers

- Before acting on an "unreachable service" audit finding, `git log --oneline -- <path>` and check TODO.md for an earlier `[x]` audit task with the same wording: a later daily-audit task can duplicate a fix that already merged.
- Confirm the wire format of enum states before asserting on HTTP JSON: `ArtifactState` serializes as `FAILED`/`CLEAN`, so use `equalsIgnoreCase` (as the existing integration test does) rather than lowercase literals.
- A download precondition test must advance `If-Match` to the post-transition version (scan bumps 1→2); otherwise `IfMatch.parse`/`requireVersion` yields 428/412 and masks the 409 you meant to prove.
- The worker prompt and `scripts/check.sh` conflict: `check.sh` runs `apps/api/check.sh` = `mvn verify` (all integration suites + full JaCoCo/OWASP). In swarm-worker mode run the targeted test plus JaCoCo report and the lightweight policy scripts instead, and leave the full gate to the integrator.
- Running the Python tooling suite may print a line about writing `scripts/wiring-baseline.json`; confirm with `git status` that no tracked file actually changed before staging.
