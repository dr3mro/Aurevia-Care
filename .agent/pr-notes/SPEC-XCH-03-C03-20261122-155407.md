- The story says "same fixtures, style and database setup as the neighbouring tests",
  but the neighbouring `ExchangeResponseServiceTest` is mock-based and the clause-test
  precedent (`scheduling/clauses/TransferHandoffRequiresActiveAssigneeTest`) is
  database-free. Following the clause precedent, this test is deliberately
  database-free; the real-PostgreSQL proof (retained purpose/legal hold at
  `ExchangeResponseExchangeTest:312-318`, no copy on rejected change at line 400,

## Lessons for workers

- A mocked read-back is circular unless the stub derives from the actual write. To
  prove a record's defensive copy, return the *live mutable* list from the repository
  stub: `List.copyOf` in the stub makes the unmodifiable assertion vacuous.
- Assert the exact arguments of `repository.update(...)`, not the object returned by a
  mocked `find(...)`; the latter is fixed by the stub and proves nothing about state.
- Rejecting a linked change sets state `REJECTED` while keeping revision one current;
  it does not set state `ACCEPTED`. Reading the service before asserting saved a cycle.
- For a role-denial test, re-stub membership to `true` alongside the denied role, or
  the first authorization guard short-circuits and the role check is never exercised.
- `insertRetained` has no timestamp argument; inject a fixed instant in the `doAnswer`
  when reconstructing a `RetainedCopy` for read-back.
- When `git grep` finds conflict markers, check `git show HEAD:<path>` first: markers
  inside Javadoc comments can be committed and still compile. Report them instead of
  editing out-of-scope production files.
- Do not re-diagnose the `opencode.json` CI-profile artifact: confirm with
  `git ls-files -v`, compare with `.github/opencode.ci.json` and `git show HEAD:`, then
  run the remaining gate stages individually.
