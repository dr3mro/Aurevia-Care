# READY-02 — Security headers on every API response (WEB-02)

## Summary

Added one servlet filter that sets the WEB-02 browser-defence headers on every HTTP response, and enabled the framework forward-header strategy so the HSTS decision follows the client's scheme behind a TLS-terminating load balancer. Synthetic fixtures only; no Spring Security code was changed to satisfy this story.

## Affected requirements

- WEB-02 (SMARTCLINIC_V1_SPEC.md section 8.1): Content-Security-Policy without `unsafe-inline`/`unsafe-eval`, `frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, restrictive `Permissions-Policy`, `X-Robots-Tag`, `Cache-Control: no-store` on `/api/`, HSTS only on secure requests.
- Supporting: OPS-02 (defensive response controls), WEB-13 (`noindex` via `X-Robots-Tag`).

Acceptance mapping:
| Criterion | Implementation | Test |
|---|---|---|
| CSP, nosniff, referrer, permissions, robots on every response | `SecurityHeadersFilter.doFilterInternal` | `everyResponseCarriesTheBaselineDefensiveHeaders` |
| `Cache-Control: no-store` for `/api/` | `/api/` prefix guard | `apiResponsesAreNotStored` |
| No `Cache-Control: no-store` on `/health/live` | same guard, false side | `healthResponsesHaveNoNoStoreDirective` |
| HSTS only when `request.isSecure()` | `isSecure()` guard | `hstsIsAdvertisedOnlyOnSecureRequests` (plain + `.secure(true)`) |
| `isSecure()` correct behind edge | `server.forward-headers-strategy: framework` | reviewed; see Findings F1 |
| Ordered first, one component | `@Component`, `@Order(Ordered.HIGHEST_PRECEDENCE)` | reviewed; see Findings F1 |

## Migration and rollout considerations

`server.forward-headers-strategy: framework` makes Spring Boot trust `X-Forwarded-Proto` from the edge. The edge must strip/overwrite inbound forwarded headers and block direct ingress, otherwise a caller can spoof `isSecure()` and force HSTS on a plaintext hop (reviewer out-of-scope note). No schema change; safe progressive rollout and revert.

## Findings

1. **F1 (medium, simulated reviewer) — full real-chain ordering is not proven by the prescribed standalone test.** `@Component` + `@Order(HIGHEST_PRECEDENCE)` ties with Spring Boot's `ForwardedHeaderFilter`, and `standaloneSetup(...).addFilters(...)` bypasses both `FilterChainProxy` and that wrapper. If the effective order is wrong, `isSecure()` could be read before the forwarded wrapper, dropping HSTS behind the edge, and a security denial committed before this filter might lack headers. No change was made: the story explicitly prescribes the standalone test and the `@Component`/`@Order` approach. Next worker/owner: add a full-context assertion with `X-Forwarded-Proto: https` and a 401/403, and consider an explicit `FilterRegistrationBean` order if it fails.
2. **F2 (low, simulated reviewer) — Spring Security's default header writer may add `Cache-Control` to every response in the deployed app.** `SecurityConfiguration` has no `.headers(...)` customization, so `no-cache, no-store, max-age=0, must-revalidate` may overwrite the exact `no-store` and add the header to `/health/live`. The policy is not weakened, but the deployed behaviour can differ from the standalone assertion. Fixing it requires the `SecurityConfiguration` owner (outside this task's scope); no change was made.
3. **Defect: none in the change.** The only local failures were environment artifacts (PyYAML absent, CI-profile `opencode.json`) and the OWASP hang described above; all were handled without touching files outside scope.

## Lessons for workers

- In a cloud worker, worktree `opencode.json` is the CI profile under `skip-worktree`; `check-pack.py`/`gen-opencode.py --check`/unittest pack failures there are a known measurement artifact. Verify with `git show HEAD:opencode.json` and restore the CI bytes exactly — never regenerate or commit that file from a worker.
- `apps/api/check.sh` without a profile can hang in OWASP with no `NVD_API_KEY`; use `-Pno-security` for the local JaCoCo proof and leave OWASP/SpotBugs to the integrator.
- When a story prescribes a standalone MockMvc test, do not silently convert it to a full-context test; record real-chain gaps as findings for the owner instead.
