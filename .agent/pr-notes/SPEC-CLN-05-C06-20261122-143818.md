# SPEC-CLN-05-C06 — Signing differs from patient release and PDF rendering

## Summary

Dedicated API evidence for CLN-05 clause 6. Added one integration test class that proves, through
the real HTTP entry points and a fresh database migrated from `db/migrations`, that signing a
clinical note records a signature but does not release the note to a patient and does not render a
PDF. Added the clause note under `docs/spec/clauses/chart/`. No production code, existing test,
migration or contract was changed. All fixtures are synthetic.

## Lessons for workers

- For a test-only evidence story, prove falsifiability by inverting one assertion, running the
  targeted suite to see a real failure, then restoring from a byte-for-byte backup and re-running
  green; do not leave the inverted assertion in the commit.
- The patient-release separation can be asserted cheaply through
  `GET /api/v1/patients/{id}/released-revisions` as a clinician (200, `[]`) plus a tenant-scoped
  row count on `patient_release`/`rendered_document` after binding `app.current_org`; the migration
  owner is subject to FORCE RLS, so always `SET app.current_org` before counting.
- `worker-check.sh`/`check-pack.py` fail in this worker on the skip-worktree CI profile. Confirm with
  `git ls-files -v opencode.json` → `S` and `git show HEAD:opencode.json`, then run the later stages
  individually instead of regenerating protected config. Never re-diagnose it on a later pass.
- `mvn ... -Pno-security -Dtest=ClassName test` runs an `@Tag("integration")` test by default; only
  the `fast` profile sets `excludedGroups=integration`. Use `-Pno-security` (not `-Pno-security,fast`)
  for a targeted DB suite.
