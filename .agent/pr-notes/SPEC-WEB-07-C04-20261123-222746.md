# SPEC-WEB-07-C04 — WEB-07 clause 4 (Staff web test): Unsupported browsers see a plain message and no data

## Findings

- The clause is entirely built on `main`; the only deliverable was clause-specific evidence. No
  production gap, no failing test and no `it.skip` was needed. `Proven by tests` is the correct
  status because the new test plus the three cited active existing tests cover the rule end to end.
- The supported-client case deliberately drives the real `isSupportedBrowser` guard and asserts
  that the plain notice is not the chosen entry tree; it does not stage a self-rendered "app
  marker", which would make the refusal tautological. The production proof that a supported client
  mounts `<App />` remains the existing `tests/main.test.tsx` assertion, credited in the clause doc.
- **Optional, out of scope (not changed):** `apps/staff-web/src/features/system/messages.ts:31`
  still says the portal needs a browser "at least 768 pixels wide", while the enforced reflow floor
  is `MIN_SUPPORTED_WIDTH = 320` (`browserSupport.ts:38`, decision 0004). This is a stale message,
  cosmetic/UX only; fixing it would change production text and an existing string assertion, so it
  is recorded here for a separate task rather than edited in this evidence-only change. Flagged
  independently by the devsecops reviewer.
- The `apps/staff-web/check.sh` coverage run prints jsdom "Not implemented: navigation" stack
  traces on stderr; they come from pre-existing tests that click the Go-home button (for example
  `tests/features/system/systemPages.test.tsx`), not from the new test, which never clicks it. All
  2980 tests passed and the gate exited 0.

## Lessons for workers

- A `.ts` React spec that uses `createElement` must put `children` in a typed props *variable*
  (not a literal prop): `tsc` strict overloads require `children` in props, while the strict
  `react/no-children-prop` ESLint rule rejects a literal `children` prop. A typed variable satisfies
  both — see `tests/spec/localization/support-english-arabic-rtl-direction-local-name.test.ts`.
- For a supported-client "negative refusal" in a spec test, drive the real guard and assert the
  forbidden surface is absent; do not stage a synthetic app marker and assert its presence, because
  a marker the test renders itself makes that assertion incapable of detecting a regression. Credit
  the real entry-point test for the "app mounts" half of the trace.
- Survey `git log` and the named domain packages first: when the clause is already implemented and
  tested, the honest deliverable is clause-specific evidence only, with no production change and a
  `Proven by tests` status backed by the existing active tests.
