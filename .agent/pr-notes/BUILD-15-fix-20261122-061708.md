## Lessons for workers

- When two workers appear to own the same story, survey `main` and all prior notes before reimplementing: check whether the feature and its acceptance tests already landed, then contribute only the missing slice (here: the HTTP entry-point test) and drop duplicate tests at conflict resolution.
- On merge conflict, "keep both sides' intent" can mean taking the base file wholesale when the base already contains equivalent coverage; preserve the other side's unique file instead. State explicitly which intent each kept file carries so the coverage claim stays honest.
- Do not write a "Why this is not finished" section unless work is genuinely blocked: its text is posted to the issue and can re-dispatch an already-complete story.
- In cloud workers `opencode.json` is skip-worktree (CI profile). Before treating a `check-pack.py` / `gen-opencode --check` / `quick-check.sh` "stale" failure as yours, confirm `git ls-files -v opencode.json` shows `S` and compare `git show HEAD:opencode.json` with `gen_opencode.render(ci=False)`.
- For records implementing an interface with a discriminator method, `type()` is not a JSON property — assert on record components (`genericKey`, `scope`, `actor`, `revision`) in MockMvc tests.
- Do not run `scripts/check.sh`, `scripts/coverage-check.sh` or `mvn verify` as a swarm worker: they invoke the full DB integration and static-analysis gate, which belongs to the integrator/Delivery and can time out the worker.
