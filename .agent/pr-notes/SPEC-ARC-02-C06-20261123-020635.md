## Lessons for workers

- Wrap raw-SQL assertions in `as(org, subject, () -> transactions.execute(...))`; an unguarded `JdbcTemplate` query under FORCE RLS silently returns a false zero, making a "no row was written" assertion vacuous.
- In a shared-database test class, locate the created work item by its unique marker/fingerprint rather than by list index — JUnit does not guarantee method order.
- Use a UUID `X-Correlation-Id` distinct from the clinical-question marker; otherwise the marker can land in the audit `correlation_id` column and defeat the "no clinical payload in audit" assertion.
- Confirm `opencode.json` drift with `git ls-files -v` plus an in-memory `gen.render(ROOT)` comparison against `git show HEAD:opencode.json` before treating a pack failure as a defect; do not regenerate or commit that file.
- `worker-check.sh` runs the full integration group; when it stops at the known pack false positive, run the remaining stages individually instead of re-diagnosing the artifact, and leave full `mvn verify`/JaCoCo to the integrator.
