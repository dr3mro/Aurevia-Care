## Lessons for workers

- An OpenCode cloud worker sees the CI `opencode.json` under `skip-worktree`; a red
  `check-pack.py` / `gen-opencode.py --check` there is usually a profile artifact.
  Confirm with `git ls-files -v`, then compare `git show HEAD:opencode.json` with
  `gen_opencode.render(ROOT, ci=False)` before regenerating anything, and never edit
  that protected file.
- `python3 -I scripts/check-docs.py` enforces heading-level jumps, GFM table cell
  parity, relative-link resolution and specification requirement IDs; count the
  unescaped pipes in every new table row and use only IDs defined in the spec.
- When a pack must "record no approval", a status legend plus placeholder cells
  ("owner to enter", "to be named") keeps the document useful without inventing a
  market, region, contract or retention value.
- Check conflict markers with `git grep ... origin/main -- <path>` before treating
  them as something a merge just introduced; committed markers outside `scope` are
  not this worker's to fix.
