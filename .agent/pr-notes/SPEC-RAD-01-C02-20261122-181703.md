## Lessons for workers

- For a clause-verification story, read the production path first: if the rule
  already exists, write active tests rather than a `@Disabled` GAP test; reserve
  `@Disabled` for genuinely absent or partial behavior.
- When the brief mandates a `.clauses` package, do not declare the production
  package from that directory. If the only service-accepting controller
  constructor is package-private, build the controller with the public
  constructor and obtain its service for fixture setup with
  `ReflectionTestUtils.getField`, documenting the field-name dependency.
- Seed negatives from a valid accessioned order and re-stub roles deliberately:
  all `requireText` guards run before the role gate, and `load` runs before the
  version guard, so a blank field or wrong tenant otherwise returns the wrong
  code. Assert unchanged order and event state, not only status/code.
- In a cloud worker, confirm the `opencode.json` artifact once with
  `git ls-files -v`, then temporarily restore the committed bytes for the
  tooling run and put the CI bytes back; never regenerate or commit that file.
- Do not run `scripts/check.sh` or the full `worker-check.sh` integration leg in
  a swarm worker: run targeted `-Dtest=...` plus the individual policy scripts
  and leave the full gate and 100% JaCoCo to the integrator.
