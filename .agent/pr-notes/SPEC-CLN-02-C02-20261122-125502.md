# SPEC-CLN-02-C02 — CLN-02 clause 2 API test evidence

## Summary

Test-only story for CLN-02 clause 2. Surveyed the scheduling domain and confirmed
the clause is fully implemented today, then added a focused active API test class
that proves the worklist read rule with one positive and two negative cases, plus
the clause evidence document. No production code, existing test, contract,
migration or tracker was changed.

Source survey (step 1 of the task) found the implementation in
`apps/api/src/main/java/com/aurevia/scheduling/checkin/`:
`ClinicController` (`GET /api/v1/clinic/worklist`), `CheckInService.worklist(...)`,

`WorklistItem` (assignment and timestamp projection), `V12__checkin_worklist.sql`
(the forced-RLS `worklist_entry` table) and `V93__membership_facility_scope.sql`
(facility-scope guard). Neighbouring proof lives in
`it/schedulingcheckin/CheckInWorklistIntegrationTest` (ordering, configured priority,
assignment) and `authz/clauses/FacilityScopeFurtherNarrowAccessTest` (facility scope).
No contract under `contracts/` describes the worklist route; it is served directly by
`ClinicController`.

## Lessons for workers

- When seeding worklist fixtures directly, remember `worklist_entry.appointment_id`
  is a UUID FK to `appointment.id`: insert `CAST(:appointmentId AS uuid)`, not a
  subselect on a non-existent `appointment.appointment_id` column.
- `scripts/check-pack.py` can transiently report a stale `opencode.json` in a cloud
  worker because the CI profile sits under `skip-worktree`; confirm with
  `git ls-files -v opencode.json` (`S`) and a byte comparison to HEAD before treating
  it as a defect, and re-run once before recording a failure.
- The global instruction forbids running the full `mvn verify`/all integration
  tests in a worker; `scripts/check.sh` and `worker-check.sh` both invoke them, so
  run the targeted `-Dtest=Class` integration test plus individual fast policy
  stages instead, and leave the full gate to the integrator.
