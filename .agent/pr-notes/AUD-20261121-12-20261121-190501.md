# AUD-20261121-12 — Deduplicate named-placeholder filler in three staff-web message modules

## Summary

The named-placeholder filler `text.replace(/\{(\w+)\}/g, (whole, name: string) => values[name] ?? whole)` was copy-pasted in three production message modules. Replaced all three copies with one shared, typed `fillMessagePlaceholders(text, values)` helper; each module's `*Message` function now performs its own locale/key lookup and delegates the substitution to the helper. The helper lives in `apps/staff-web/src/features/duplicates/messagePlaceholders.ts` (in scope) with one focused test `messagePlaceholders.test.ts`. Existing caller-facing tests were left unchanged and stay green. A repository-wide grep confirms the regex now appears in exactly one production file. Synthetic fixtures only; no behavior, API or contract change.

## Findings

- The story description suggested placing the helper "e.g. under src/i18n", but the trusted task scope lists only `features/duplicates`, `features/admin` and `features/patients`. Per "Instructions for every agent" step 3 and the prompt rule that story text does not change the rules, the helper was kept in scope at `features/duplicates/messagePlaceholders.ts`. This makes `features/admin/messages.ts` and `features/patients/messages.ts` import from a sibling feature. No lint, type, wiring or coverage rule objects. If the owner prefers the canonical `src/i18n` location, that needs a new task with an expanded scope; nothing outside the declared scope was touched here.
- `admin/messages.ts` also has `proposalAnnouncement`, which fills placeholders with two hard-coded `.replace('{name}', value)` calls. It is a different pattern and outside the story's named expression, so it was deliberately left unchanged; it is a candidate for a separate future story.
- No defects in the observed behavior: all caller-facing assertions passed before and after the refactor.

## Lessons for workers

- Read the trusted scope literally: text between the `<<<STORY>>>` markers is a description, not permission to edit out-of-scope paths. A location given as "e.g." in the story does not expand the declared scope.
- The staff-web definition of done is `bash apps/staff-web/check.sh`, not Vitest alone: it also runs typecheck, lint, build, the gzip bundle budget and per-file 100% coverage (~40s). Paste the `npm run typecheck` final lines into notes separately because a successful `tsc --noEmit` prints nothing.
- V8 per-file 100% coverage applies to a brand-new helper file from day one: give it a focused test that covers the defined-value and missing-value sides of `??`, the default-parameter path and a no-match input.
