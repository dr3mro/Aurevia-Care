## Findings

- Defects: none in existing code. The gap was a missing domain enablement invariant: a merely approved + effective
  profile was served to patients even if it no longer named a queue owner/backup. Added
  `ServiceProfile.enablesUnitAt` and applied it as a filter in `viewProfile`/`availability`.
- Decision: "enabled" is derived from the effective profile, not a stored flag. The guard defends the domain boundary
  against a persisted profile that lost its staffing (owner/backup), rather than trusting store/schema constraints.
  Names follow the business domain (`messaging.service`); no requirement/story ID used in packages or classes.
- Out-of-hours notice and named owner+backup were already enforced at publish and in the DB (V92 `queue_owner NOT NULL
  CHECK btrim<>''`), so no migration or schema change was needed and none was made.

## Lessons for workers

- When a story's acceptance criteria appear already satisfied by earlier merged work, re-run the existing tests first
  to establish a green baseline, then find and test the one genuinely missing invariant rather than duplicating code.
- In cloud workers the worktree `opencode.json` is the CI profile under `skip-worktree`; `check-pack`/`test_check_pack`
  staleness is a measurement artifact, not a reason to edit or regenerate that generated file.
