# BUILD-56 — Staff web: route chunk budget, self-hosted fonts and no third-party scripts

## Summary

WEB-08 build-platform work, entirely inside `apps/staff-web/scripts`, `apps/staff-web/vite.config.ts` and `apps/staff-web/public`.

- `vite.config.ts` now sets `build.rollupOptions.output.manualChunks = assignChunk`, hashed `chunkFileNames`/`assetFileNames`, an `immutable-hashed-assets` middleware for `/assets/` (dev and preview), and a `self-hosted-fonts` plugin that injects the local font stylesheet into emitted HTML.
- `scripts/web-platform-config.ts` holds the pure, unit-tested policy: `assignChunk`, `immutableCacheHeader`, `FONT_STYLESHEET_HREF`, `injectFontStylesheet`.
- `scripts/check-external-resources.mjs` fails on external script/link/`url()`/`@import` references and on known third-party font/tracker hosts. It is invoked from `scripts/check-bundle-size.mjs`'s `main()`, which `check.sh` already runs after the build — so the new gate is CI-wired without editing the out-of-scope `check.sh`.
- `public/fonts/fonts.css` declares self-hosted `@font-face` faces with an explicit Arabic `unicode-range` and `font-display: swap`; `public/fonts/smartclinic-ui-subset.woff` is a deterministic synthetic subset with Arabic cmap segments (verified, see Test evidence). The built document links `/fonts/fonts.css`; no CDN is contacted.

Existing route-level code splitting was already in place (`src/app/routes.tsx` and each `src/features/*/routes.ts` use `lazy`); the config change keeps it intact and adding a shared `react-vendor` chunk makes per-feature route chunks explicit and small.

## Findings

1. Vite 8.3.8 prints a non-fatal deprecation warning: `import "./scripts/web-platform-config" without a file extension (vite.config.ts:11:8)`. Adding `.ts` is rejected by `tsc` (TS5097) unless `allowImportingTsExtensions` is enabled, and `tsconfig.json` is outside scope. `VITE_CONFIG_NATIVE_IGNORE_WARNING` was not set because `check.sh` is outside scope. All gates pass; no action needed today, but a future Vite major with the native config loader will require this to be resolved.
2. The committed WOFF is a deterministic synthetic fixture (simple box outlines) with real Arabic cmap ranges, generated with Python stdlib zlib — not a licensed production typeface. Replace the asset with the approved, subsetted Arabic face before clinical use; the `@font-face` structure and fallback do not need to change.
3. `font-family` is not applied to any `src` component (out of scope). The stylesheet is injected into the emitted document and the face is available; a follow-up should wire `"SmartClinic UI"` into `src/theme/tokens.ts` and keep the documented system fallback.
4. `check.sh` was not edited (out of scope). The external-resource gate runs inside the already-wired `node scripts/check-bundle-size.mjs` step, so CI coverage is unchanged.
5. No third-party script, font or tracker URL was found in the real `dist` output; React's `https://react.dev/errors/...` strings are intentionally ignored because they are messages, not fetched resources.
6. Root `scripts/check.sh` fails at `check-pack` solely because this cloud worker's `opencode.json` is the CI profile under `skip-worktree` (see Test evidence item 6). A worker must not regenerate or edit that protected file; the module's canonical `apps/staff-web/check.sh` gate is green.

## Lessons for workers

- Do not import `vite.config.ts` directly from a Vitest test: its `import.meta.url` is not a `file:` URL there (`TypeError: The URL must be of scheme file`). Put pure config policy in a separate module and test that.
- When `check.sh` is out of scope but a new build gate must run in CI, import the new checker into the existing `check-bundle-size.mjs` `main()` instead of editing the shell script.
- A valid WOFF with Arabic cmap coverage can be generated with Python `struct`+`zlib` alone — no font tools or new dependency needed.
- Third-party-resource checks must match resource references (`src=`, `href=`, `url()`, `@import`) plus a host allowlist, not every `http` substring; framework bundles contain harmless absolute URLs in strings.
