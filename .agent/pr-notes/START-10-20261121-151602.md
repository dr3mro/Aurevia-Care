## Findings

- Recorded 10 interface inconsistencies with exact files/keys: Facility (المرفق vs المنشأة), Chart (الملف السريري vs الملف الطبي), Checksum (المجموع الاختباري vs SHA-256), State/Status (حالة), Cancel/Deactivate/Void (إلغاء), Register/Sign in/Check-in/Enrollment/Recorded (تسجيل), Issuer (الجهة المُصدرة vs جهة إصدار رقم الملف), History/Record/Provenance (السجل), Sign out (لقد سجّلت الخروج vs تم تسجيل الخروج), Display/Display name (الاسم المعروض). None was fixed, per the story.
- Two initially drafted Arabic strings were not verbatim in any bundle (`الموظفون`, `الموعد`); replaced with the exact bundle strings `الموظفين` and `المواعيد`. No code name was fabricated; the nonexistent `chart_record` table was removed from the Verification row in favour of the existing `VerificationState`/`ChartEntry` classes.
- Field-level code names were checked against the source records: `Patient.mrnIssuer` (not `issuer`), `Patient.dob` (not `dateOfBirth`), `Patient.dobUnknownReason`, and `AuditEvent.actorId` (not `actor`). Table names were checked with `grep 'CREATE TABLE' db/migrations/*.sql`.
- `check-docs.py` treats `UX-01` as outside its defined-ID set (the spec writes it as a bold lead without the ` · ` separator) but does not flag it because no `UX` prefix is defined; `PRD-01` is a defined table row. Neither mention fails the gate.

## Lessons for workers

- Verify every Arabic term in a bilingual document by machine against the actual bundles (`rglob('messages.ts')` plus `components/stateViewMessages.ts`) before calling it done. Plausible-looking forms like `الموظفون` and `الموعد` are not necessarily the strings the interface uses — only `الموظفين` and `المواعيد` appear in these files.
- When citing a DB table as a code name, confirm it with `grep 'CREATE TABLE' db/migrations/*.sql`; an intuitive name such as `chart_record` does not exist (the chart tables are `chart_association` and `clinical_note_revision`).
