# SPEC-IAM-03-C01 — IAM-03 clause 1 API acceptance test

## Summary

Added a focused real-PostgreSQL acceptance test for IAM-03 clause 1, "Record
PatientRecord and issuer-scoped MRN per organization", plus the clause evidence
document. No production code, existing test, contract or migration was changed.
The clause is already implemented in the delivered `patient` slice; the test
proves the rule end to end through the HTTP entry point and reads the durable
row back under forced row-level security, with negative refusals for issuer
reuse, cross-tenant concealment and a role without patient permission.

Files (only these two, both inside the task scope):

- `apps/api/src/test/java/com/aurevia/patient/clauses/RecordPatientrecordIssuerScopedMrnOrganizationTest.java`
- `docs/spec/clauses/patient/record-patientrecord-issuer-scoped-mrn-organization.md`

## Lessons for workers

- Before declaring an IAM clause "not built", survey the domain package, V7-style
  migrations, the `web` controller and the generated OpenAPI file: the `patient`
  clause was fully implemented while only a focused acceptance test was missing.
- Use a dedicated PostgreSQL database name per clause test (for example
  `orevia_iam03_clause1_it`) so parallel workers do not drop each other's
  fixtures, and keep `@Tag("integration")` so the fast tier excludes it.
- When a 3-argument JUnit status assertion needs a body in the message, concatenate
  it: `assertEquals(HttpStatus.CREATED, response.getStatusCode(), "why: " + response.getBody())`;
  a fourth String argument resolves to a double/float overload and fails compilation.
- In a cloud worker, a red pack check is the CI profile under `skip-worktree`:
  confirm with `git ls-files -v opencode.json` and `git show HEAD:opencode.json`,
  record it, and never regenerate or commit that file.
- Run the new `@Tag("integration")` class directly (with `-Dgroups=integration
  -Dtest=ClassName`) before touching any gate; it is fast and catches real SQL,
  RLS and HTTP-wiring errors that unit mocks cannot.
