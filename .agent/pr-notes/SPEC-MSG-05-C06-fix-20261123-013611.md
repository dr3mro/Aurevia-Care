## Lessons for workers

- On a "did not finish cleanly" fix attempt, first verify the committed work is
  actually broken before rewriting it: re-run the focused test and the individual
  gate stages. Green work usually means the prior session simply ended early.
- To prove an `opencode.json is stale` report without touching the protected
  file: confirm the `S` skip-worktree flag and no worktree diff, then regenerate
  in a throwaway directory containing copies of `scripts`, `.opencode` and
  `.github` and `diff` both outputs against `git show HEAD:<path>`. An `S` flag
  plus byte matches confirms OPS-CW-003-01; do not re-diagnose it on a later pass.
- `python3 -I -m unittest` cannot import the `scripts` package by dotted name;
  use `discover -s scripts/tests` (optionally `-p 'test_java_conventions.py'`).
- When a reviewer raises an Optional evidence-precision issue in a clause
  document, fix it and re-run `check-docs.py` plus a bounded reviewer follow-up:
  the evidence trace is the deliverable of a clause-evidence story.
- Keep clause-gap text in the document and notes as prose: an added `@Disabled`
  fails `scripts/check-constraints.py`, so a green PR cannot carry a skipped GAP
  test even when the story wording suggests one.
