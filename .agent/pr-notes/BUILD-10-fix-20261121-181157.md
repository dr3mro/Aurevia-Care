# BUILD-10 fix — Prescription channel evidence and a printable local prescription (RX-02)

## Summary

Fix pass on the committed BUILD-10 change (`a847ccca`). The production behaviour was
already correct and fully unit-covered; the acceptance gap was **evidence**: the new
`GET /api/v1/prescriptions/{id}/printable` route was guarded only by
`RxPrintableControllerTest`, a plain Mockito test that calls
`controller.printable(ID)` directly. It cannot detect a missing, misspelled or
unmapped route. This pass adds an HTTP-level test through the real controller mapping
and strengthens three existing assertions. No production behaviour was changed; the
temporary red-phase edit to `RxController` was restored byte-identically.

## Findings

- **Fixed — no HTTP proof of the new route.** The original `RxPrintableControllerTest`
  was a Java-level mock delegation test; the red phase (404 on three cases) proves it
  could not detect a broken mapping. `RxPrintableHttpTest` now proves reachability,
  serialization and error translation through the real `@GetMapping`.
- **Out of scope — HTTP security contract omits the new route.**
  `apps/api/src/test/java/com/aurevia/smartclinic/it/prescription/RxHttpSecurityTest.java:169-194`
  claims to cover "every RxController route" but its `endpoints()` list does not include
  `GET /api/v1/prescriptions/{id}/printable`. It lives under `it/prescription`, outside
  this task's `prescription` test scope, so it was not edited. A task-request is filed.
- **Out of scope — no OpenAPI entry** for the printable route (the whole prescription
  command family is currently unpublished, per the original note). `contracts/` is
  outside this scope; a task-request is filed.
- **Decision needed — READ-role printing.** `RxService.printable` authorizes with
  `RxActions.READ` (as `get` does), so a READ-only role can mint a print-ready document
  carrying the original prescriber's attestation, while `attest`/`transmit` require the
  prescriber. No story criterion requires prescriber-only printing and `get` already
  exposes the same trail, so no behavior change was made; flagged for a clinical/security
  owner decision.
- **Unrelated red gate — `check-docs.py`:** `docs/reference/partner-api-guide.md:200:
  table row has 4 cells, expected 3`. Already committed by another worker and outside
  this scope; not touched. It also causes one of the four Python unittest failures.
- The other three Python unittest failures are `test_check_pack` cases caused by the
  worktree `opencode.json` being the CI profile under `skip-worktree` (documented in
  MEMORY.md, dispatch-3 run 3). They are environmental and unrelated to this change.

## Lessons for workers

- A direct Mockito call to a controller method is **not** an HTTP test. Use the repo's
  `MockMvcBuilders.standaloneSetup(...)` + `ApiErrorHandler` + `TenantContextInterceptor`
  convention, and prove the test guards the mapping by deliberately breaking the
  `@GetMapping` and observing 404 before restoring it.
- In a fix pass with no explicit findings, read the original note's "Why this is not
  finished" and route to the senior/QA reviewers; AGENTS.md "Done means working end to
  end" item 4 is a hard gate that coverage alone cannot satisfy.
- Repository-wide gates can be red from parallel workers' committed files. Record the
  exact command and failing line, confirm the file is outside your scope, and do not
  "fix" it inside your own PR.
