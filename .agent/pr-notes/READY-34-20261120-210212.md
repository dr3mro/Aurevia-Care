# READY-34 — Patient app four-tab navigation

## Summary

Replaced the READY-33 placeholder navigator with the four-tab patient shell from
`docs/design/screens-and-navigation.md` section 3: **Appointments, Reports,
Messages, Account**, in that order. Appointments and Reports mount their existing
presentational screens directly. Messages and Account are small local push/pop
stacks (no stack-navigator dependency exists and none was added) that expose the
conversation list, attachment review and instruction acknowledgment screens, and
the enrollment, recovery, support and lockout screens. All screen props come from
synthetic `placeholder...` providers; no authentication, network client or push
notification code was added. The single native-direction boundary
`applyDirection(locale)` calls `I18nManager.forceRTL` and is unit tested for both
locales.

- **PAT-01** — Appointments tab renders `AppointmentListScreen` with a generic notice.

- **UX-01** — English/Arabic tab labels and accessibility labels from `app/messages.ts`;
  one tested `applyDirection(locale)` helper; accessible control roles/labels; tab order
  mirrors with native RTL.

## Findings

1. **Shared Jest mock gap (test-only, worked around).** `jest.setup.ts` replaces
   `react-native-safe-area-context` with `jest.requireActual(.../jest/mock)`, which
   exposes only a `default` export. `@react-navigation/bottom-tabs` reads the named
   `SafeAreaInsetsContext` and crashed with `Cannot read properties of undefined
   (reading 'Consumer')`. The fix is local to `RootNavigator.test.tsx`: a file-scoped
   `jest.mock` that spreads the real module and supplies the named contexts and a
   headless safe-area provider. No shared file was edited (out of scope). A maintainer
   may want to fix the shared setup mock in a separate, owner-approved change.
2. **Async rendering.** In this React Native/Jest version `render()` returns a promise
   and navigation state updates settle across ticks. New tests `await render(...)` and
   use `waitFor` after presses. This is a harness detail, not app behavior.
3. **No stack navigator package.** Only `@react-navigation/native` and
   `@react-navigation/bottom-tabs` are installed. The two nested stacks are therefore
   small local state machines. A real `native-stack` with gesture back should be a
   separate, dependency-authorized story.
4. **`forceRTL` needs a restart.** Per `docs/design/rtl-and-localization.md`, native
   direction is a startup flag; the helper is unit tested but real layout mirroring on
   iOS/Android is unverified here and needs a device pass.
5. **No defects found in existing feature screens** while wiring their props.

## Lessons for workers

- In this Jest setup, bottom-tabs needs named `react-native-safe-area-context`
  exports; the repository mock returns only `default`. Add a scoped test-file mock
  instead of editing the shared `jest.setup.ts` from a story branch.
- `getByTestId` plus `tabBarButtonTestID` is more reliable than querying tab roles:
  under jest-expo (iOS) bottom-tab items use `role="button"`, not `role="tab"`.
- Every inline arrow passed as a screen prop counts as a function for coverage. Use one
  shared `placeholderAction` and press every control in tests so no callback is left
  uncovered.
- `render()` and navigation updates are async here; `await render()` and `waitFor`
  after `fireEvent.press` avoid flaky "element not found" failures.
