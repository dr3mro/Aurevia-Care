# READY-29 — Messages: /messages unit inbox and conversation view

## Summary

Implemented the staff-web messages feature under `apps/staff-web/src/features/messages`.
Added a tenant-scoped conversation API client, an Inbox/Work-queue page with per-row
unread counts and a text-plus-colour SLA marker, a `/messages/:id` conversation page
with server-ordered messages, an in-memory-only reply box, a single `read` on open,
and assign/transfer/resolve/close with explicit confirmation and reasons. Bilingual
labels, synthetic fixtures, feature route registration and full unit coverage are
included. No dependency, migration or API contract change was made.

  resolve and close with reasons, the four work-item states, one `read` on open,
  and unread counts updated from that read.
- MSG-03 — this slice shows the conversation surface but adds no file-attachment

## Authorization boundaries and audit events

- Tenant comes only from `useActiveOrganization()`, sent as
  `X-Active-Organization` by `buildRequestDescriptor`; no request body carries an
  organization or actor field.
- Every write carries the loaded conversation's `If-Match` version and a fresh
  `Idempotency-Key` per user action. A 409/412 renders the shared conflict state
  and keeps the typed reply or dialog values.
- The in-memory read-receipt store is keyed by `organizationId + conversationId`,
  so two tenants with the same conversation id cannot see each other's receipts.
  It is process memory only, never browser storage, and the durable watermark
  remains server-side.
- Authorization, state transitions and audit (`CONVERSATION_READ`, `CONVERSATION_ASSIGN`,
  etc.) stay server-side in `ConversationService`; this UI does not approve any
  clinical or care-team action itself.
- Routes are already grouped under Messages in `app/navigation.ts` for `unit_staff`;
  a direct visit still fails closed through the 403 state view.

## Migration and rollout considerations

Both routes are code-split (`MessagesPage` 1537 B, `ConversationPage` 2137 B gzip)
and stay under the 250 KB WEB-08 budget. No feature flag is introduced. The shared
SLA target is a bounded 24-hour presentation default until MSG-06 publishes a
unit-specific response target; it never drives escalation.

## Findings

**Simulated senior React review (subagent, static only — no tool results claimed)**
raised six findings. Disposition:

1. **Blocking — shared `Dialog` trapped Tab on its close button**, which is the only
   focusable element in that placeholder, so confirmation fields would be unreachable
   by keyboard; a new `onClose` arrow also re-ran the focus effect on every keystroke.
   **Resolved in this change:** the confirmation is now an in-page labelled group with
   native focusable `FormField`s, initial focus on the safe Cancel button, and no
   shared-dialog focus trap. `ConversationPage.test.tsx > starts confirmation on the
   safe Cancel choice with focusable fields` asserts the behaviour reachable in jsdom.
   Tab/Shift+Tab traversal itself needs a real-browser pass.
2. **High — row link accessible name lacked patient id and time.**
   **Resolved:** `MessagesScreen.tsx` appends a visually hidden
   `RowIdentity` (patient id + UTC received time) inside the link;
   `MessagesPage.test.tsx > shows each conversation…` asserts the accessible name.
3. **Medium — read receipts could mask a later server unread count.**
   Documented follow-up: the receipt is an ephemeral post-read overlay and the API
   has no staff unread sequence in the work-queue projection. A durable server-side
   staff watermark (or a receipt invalidated by a newer inbox response) is needed
   before the badge can be trusted for arriving messages.
4. **Medium — the synthetic notice said no real endpoint was used**, although the
   page calls the real conversation API. **Resolved:** en/ar wording now says test
   fixtures are synthetic while the screen reads live unit data.
5. **Low — SLA from `createdAt` can flag a reopened old thread.** Documented
   heuristic pending MSG-06; prefer the latest `reopened`/inbound event time in a
   later API contract change.
6. **Low — fixed-noun unread count instead of ICU plurals.** Localization follow-up
   for the owner (Arabic plural categories); not changed here because both bundles
   use one named-placeholder key and the parity test passes.

- **Shared route-registry tests updated outside the declared scope (necessary).**
  `apps/staff-web/src/app/routes.test.tsx` and
  `apps/staff-web/tests/app/AppShell.test.tsx` assert the exact ordered route pattern
  list, so adding `/messages` and `/messages/:id` requires two-line edits in each.
  READY-21/22/23 set the precedent of updating this registry when adding routes.
  No production file outside the scope was changed.
- **Conversation endpoints are absent from `contracts/openapi.yaml`**, so the
  generated client has no path keys for them. `api.ts` reuses
  `buildRequestDescriptor` with an existing contract path and overrides `.url`,
  the same pattern as `admin/api.ts`. Adding the paths to the contract and
  regenerating `src/api/generated/openapi.d.ts` needs a contracts/owner story.
- **Patient-scoped `/inbox` versus staff roles (owner/API hand-off).**
  `ConversationActions.java` grants `INBOX_READ` only to the `patient` role;
  `STAFF_ACTIONS` contains `WORK_QUEUE_READ` but not `INBOX_READ`. The story names
  both endpoints for one staff page, so this slice reads them together and uses
  the inbox entry's `unreadCount` as the per-conversation overlay. Against the
  current server a real staff caller therefore receives 403 from `/inbox`, which
  the shared error/forbidden state renders. A staff-scoped inbox endpoint (or a
  deliberate policy change adding `INBOX_READ` to staff roles) plus a server-side
  unread count on work-queue entries is needed for the two-tab page to be fully
  live. This cannot be fixed inside the `features/messages` scope; no client-side
  role guess was added.
- **SLA default is a presentation heuristic.** The API view has no due time or
  response target; `domain.ts` uses 24 hours for `awaiting_staff` threads and
  shows the word "SLA breached" plus a token colour. Unit-specific MSG-06 policy,
  escalation and overdue routing remain server-side work.
- **The shared `ConflictState` and `ErrorState` still use noop Compare/Reload/Copy
  and Retry actions** (`src/components/StateViews.tsx`) because `ApiPage`/`StateView`
  accept no callbacks. Typed work is preserved; wiring real recovery actions needs
  a staff-web owner change to those shared components (same hand-off as READY-23).
- **Free-text message language is unavailable in the API projection**, so message
  bodies are tagged with the active UI locale rather than a stored language tag.
  Recording a real language tag with each message is an API change.
- **Repository `scripts/check.sh` is red in this worker only** because the worktree
  `opencode.json` is the CI profile under `skip-worktree` (hash evidence under Test
  evidence). The scoped frontend gate `bash apps/staff-web/check.sh` is green.
- Evidence provenance: the commands above came from executed tools; specialist
  findings (when present) are simulated static review, explicitly labelled. No
  clinician, simulated user or human participant evidence was used.

## Lessons for workers

- `useApi` tenant keys already clear stale data on render, so no extra `key` prop is
  needed to prevent a previous tenant's rows from being painted; still assert it.
- Use `vi.mock('../../api/transport', …)` and queue one response for the GET and
  one for the follow-up `read` POST, or a StrictMode double effect consumes the
  wrong mock and fails with a shape error.
- All `?:`, `??`, optional spreads and callback closures count as V8 branches;
  cover the fallback explicitly (null topic, optional id, both tab callbacks).
- A guard against an impossible state (for example `confirm === undefined` inside
  a handler only rendered when confirm exists) is dead code and fails 100% coverage;
  pass the narrowed value as a parameter instead.
- Two shared tests assert the exact ordered feature-route list; update both when
  registering a new feature route, or the module gate fails before coverage runs.
