## Lessons for workers

- When a stopped task's findings point at a red gate, first prove the branch is
  merged with the base that contains the fix (`git merge-base --is-ancestor
  <fix-sha> HEAD`) and run the regression test that reproduces the failure
  before editing any scoped file. Here the defect was on main, and re-editing
  the shell could not turn the gate green — only landing `4bc9e562` could.
- `scripts/quick-check.sh` and `scripts/python-coverage.sh` are not HEAD truth
  inside a worker: `agent-run.sh` installs the CI `opencode.json` under
  skip-worktree. Confirm with `git ls-files -v` and the HEAD blob, and restore
  the worktree file after measuring. Record the command and final line; do not
  edit `opencode.json`, `scripts/` or a workflow to "fix" the artifact.
- `apps/staff-web/check.sh` is the canonical staff-web gate (typecheck, lint,
  build, bundle and 100% coverage). `scripts/coverage-check.sh <base>` and
  `scripts/frontend-typecheck-check.sh <base>` are the fast, scope-sensitive
  worker gates; with no `apps/api/` file in the diff they skip the forbidden
  full Java verify.
- From earlier passes: `Link` in `src/app/router.tsx` accepts no `className`,
  `aria-label` or event handlers, so the icon rail uses a real `<a>` with click
  guards; `useBreakpoint` falls back to `expanded` without `matchMedia`, so stub
  each media query deterministically and restore globals in `afterEach`.
- A conflict marker on `origin/main` is base-branch debt, not a conflict in your
  merge. Cleaning it inside an unrelated scoped story breaks scope and forces
  the wrong coverage gate; hand it back through Findings and a task-request.
