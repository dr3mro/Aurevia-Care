# SPEC-IAM-04-C02 — IAM-04 clause 2 API test

## Summary

Added one real-PostgreSQL HTTP integration test that proves IAM-04 clause 2 —
"Show both identities, conflicting demographics, dependencies, and a dry run" —
through `GET /api/v1/duplicate-reviews/{survivorId}/{duplicateId}`, plus three
negative tests (wrong role, peer tenant, invalid pair). Added the clause evidence
document. No production code, contract, migration or existing test was changed.
The clause was already implemented, so no `@Disabled` gap test was needed.

Entry-point-to-test trace: `GET /api/v1/duplicate-reviews/{survivorId}/{duplicateId}`
→ `ConsolidationController.review` → `ConsolidationService.review` (authorize, load
both patients, fold conflicts/dependencies/dryRun, audit) → `ReviewDetail` JSON →
four assertions in `ShowIdentitiesConflictingDemographicsDependenciesDryRunTest`.

Affected requirements: IAM-04 (clause 2 only).

Requirement/acceptance mapping:
- Clause sentence → `reviewShowsBothIdentitiesConflictsDependenciesAndDryRun`
  (both identities, `conflicts` fields, `dependencies`/`ORDER`/`order-9`, `dryRun`
  with `blockers=1`, unchanged `chartVisibilityId`).
- "must refuse" → `reviewRefusesCallerWithoutReviewPermission` (403),
  `reviewRefusesPeerTenant` (403 then 404), `reviewRefusesInvalidPairAndMalformedIdentifier` (422).

## Lessons for workers

- Give every synthetic patient in one integration test class a distinct MRN prefix:
  the API rejects a reused MRN+issuer with 409, which looks like a product defect
  but is a fixture collision. Reusing the neighbouring tests' `prefix-1`/`prefix-2`
  pattern avoids it.
- Assert 422 with `getStatusCode().value() == 422`; the Spring 7 `HttpStatus` enum
  constant for 422 is not the older name.
- `worker-check.sh` on a cloud worker stops at `check-pack` with the
  OPS-CW-003-01 profile false positive; verify `git ls-files -v opencode.json`
  (`S`) and run docs/Python/SpotBugs/targeted-test/db checks individually rather
  than regenerating the protected file.
