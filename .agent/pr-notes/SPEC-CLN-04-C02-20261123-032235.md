## Lessons for workers

- Never add a `@Disabled("GAP: …")` (or any `@Disabled`) to a new test in this repo:
  `python3 -I scripts/check-constraints.py --base origin/main --require-base` rejects every added
  Java `@Disabled`. Old disabled tests are grandfathered and are not proof that a new one passes.
  If the surface a would-be test targets does not exist, document the gap and file a follow-up task;
  do not leave a skipped test standing in for it.
- For an evidence-only API task with no endpoint, keep an active domain-level test so the "Partly
  proven" claim stays honest, and say explicitly which production classes were executed versus only
  surveyed.
- Delete the whole dependency cone of a removed test: helpers, constants, imports, and a fixture
  (Spring context, DB seed/migrate/drop) that no active test uses. Keeping a fixture that nothing
  asserts against is dead overhead and makes the evidence note overstate what was actually proven.
- Re-run a reviewer after a fix that landed while it was reading: the first code-reviewer pass saw
  the pre-repair notes and returned NO-GO on findings already fixed. Re-run on the final state before
  copying a GO verdict. Read the Surefire XML for authoritative `tests/errors/skipped/failures`, not
  the exit code.
