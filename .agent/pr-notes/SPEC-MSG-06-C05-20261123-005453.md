- `assignee() == null` true → `WI_OVERDUE_NULL`; false → `WI_OPEN_BLANK` and the two

- `state == AWAITING_STAFF && lastStaffResponseAt == null && !now.isBefore(createdAt + target)`:

  second operand true → `WI_OVERDUE_NULL`/`WI_OPEN_BLANK`, false → `WI_RESPONDED`;

## Findings

- The supervisor-snapshot route is listed in `contracts/openapi/missing-routes.txt:16`
  as a baselined OpenAPI contract-parity gap. This task is read-side proof only and
  explicitly may not edit the contract; the finding is left for the owning contract
  task. Optional task request: publish `GET /api/v1/care-units/{}/supervisor-snapshot`
  into `contracts/openapi.yaml` with the required tag and regenerate the client.
- A patient acting on a protected route needs an active `membership` row in addition to
  the `patient_account`/connection fixtures; without it the denial is `no active
  membership` (403) rather than the missing-action reason the negative test intends to
  prove. The patient fixture now seeds all three.
- The injected Spring `Clock` is `Clock.systemUTC()` shared by many beans; a fixed-clock
  test override would be brittle, so deadline fixtures use far-past/far-future anchors
  (2020 / 2099) that the real clock cannot flip.

## Lessons for workers

- When a negative test must prove a *reason* for a denial, assert the `ErrorBody.message`
  too: `authorize` returns the same 403 `FORBIDDEN` for "no active membership" and for
  "missing X permission", and those need different fixtures.
- A `patient` subject seeded only as `patient_account` + connection is not an active
  member; `hasActiveMembership` reads `membership`, so seed a membership and role too
  before asserting a missing-action denial.
- `pgjdbc` cannot bind `java.time.Instant` directly; seed work facts with the injected
  `ServiceProfileStore.addWorkItem` inside a `TenantContext`, not raw SQL.
