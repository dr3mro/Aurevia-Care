# READY-28 — Lab: /lab/accessions list and accession actions

## Summary

Added a self-registering `features/lab` staff-web feature on the existing
laboratory accession API. `AccessionsPage` renders a state-filtered,
cursor-paginated accession worklist and a requisition accession form that shows
the issuer-scoped accession id after creation. `AccessionDetailPage`
(`/lab/accessions/:id`) shows the current accession and immutable event history
and offers only the commands the LAB-01 state machine allows for the current
state; rejection requires a reason and a successful recollect links the new
specimen. All data is synthetic and every request is tenant-scoped.

## Affected requirements

- **LAB-01** — accession identity, state machine, rejection reason and linked
  recollection are implemented in the UI against the existing API.
- **LAB-02** — assigned to this story. This slice exposes accession state and
  history only; numeric/qualified/text/coded observation entry, report revisions
  and verification remain the separate lab-result slice. No observation or
  result-release behavior was added or claimed here.

## Risk class

Routine-to-cross-boundary: a new staff-web feature consuming the existing
`/api/v1/lab/accessions` contract with no API, database or contract change. It
is safety-sensitive in that action buttons are gated by the LAB-01 state
machine, so client gating mirrors the server guard and a bounded Senior React
review was requested.

## Review owner

Senior React and Vite (bounded advisory review dispatched), Senior TypeScript
(strict type and generated-client ownership). Evidence source: tool commands and
the module gate; no human or simulated-clinical acceptance was claimed.

## Data changes

None. No Flyway migration, backfill, lock or volume impact; no rollback or
forward-fix. No reserved migration version was used. No dependency was added.

## Authorization boundaries and audit events

Every request is built with `buildRequestDescriptor` and carries
`X-Active-Organization` from `ActiveOrganizationProvider`. State-changing
commands carry `If-Match` on the version read from the record; accession
creation carries a fresh `Idempotency-Key`. URLs carry only the opaque accession
id — no patient name, identifier, free text or rejection reason appears in a
URL, page title, log or browser storage. The server owns the audit events; no
audit event was added or changed.

## Migration and rollout considerations

None. Routes self-register through `features/lab/routes.ts`; `app/routes.tsx`
and `app/navigation.ts` were not edited (the navigation model already contains
the `/lab/accessions` item for the `lab` role).

## Findings

- **Form-field reconciliation.** The story text lists the accession form fields
  as "requisition id, specimen type, site", but the authoritative
  `AccessionCommands.AccessionRequest` requires `accessionNo`,
  `accessionIssuer`, `patientId` and `sourceOrderRef`, and `LabInputs` accepts
  specimen type/site only on the `CollectRequest`. The create form therefore
  collects the issuer-scoped requisition identity and the verified patient id,
  and specimen type/site are entered on the detail screen's Collect form. The
  issuer-scoped id (`accessionNo` + `accessionIssuer`) is shown after creation.
  Evidence: `apps/api/.../lab/accession/LabAccessionController.java`,
  `AccessionCommands.java`, `LabInputs.java`.
- **Two out-of-scope test expectations updated.** `src/app/routes.test.tsx` and
  `tests/app/AppShell.test.tsx` assert exact route lists and failed once the lab
  routes self-registered. Only their expected arrays were extended with
  `/lab/accessions` and `/lab/accessions/:id`; no behavior changed. This follows
  the precedent of READY-21/22/23, which updated `AppShell.test.tsx` when adding
  routes. Required for `bash apps/staff-web/check.sh` to be green.
- **`scripts/check.sh` artifact.** Red only at the `check-pack` stale
  `opencode.json` step, caused by the CI profile being copied over the committed
  file under `skip-worktree` in the worker (`git ls-files -v opencode.json` =
  `S`, worktree differs from `HEAD`). Unrelated to this change; documented as
  OPS-CW-003-01. No protected file was edited.
- **Bounded Senior React review finding, fixed.** `linked` and `commandError`
  survived in-app navigation because `AppShell` reuses the page component when
  only `:id` changes; following the recollection link could show a
  self-referential "Linked recollection" banner. Added a reset effect on
  `[id, organizationId]` in `AccessionDetailPage.tsx` and the regression test
  `AccessionDetailPage.test.tsx > clears the recollect banner when navigating to
  the linked specimen`. Gate re-run green afterwards (601 tests, 100% coverage).
- **Bounded Senior React review finding, deferred.** Client validators check
  non-empty reason / accession number / patient id but do not mirror every
  `LabInputs` bound (2–200 char reason, 3–64 char accession, UUID patient id), so
  a near miss returns a generic error state instead of an inline field error.
  Deferred deliberately: CODING_STYLE.md forbids duplicating domain rules across
  layers, and the API remains the enforcing boundary with a typed error and
  correlation id. Acceptance paths and failure states are covered; no clinical
  harm (no record is written on a 422).
- No new defect was found in the existing accession API; no BUGS.md entry was
  warranted.

## Lessons for workers

- When adding a self-registering feature route, update the two exact-route-list
  assertions in `src/app/routes.test.tsx` and `tests/app/AppShell.test.tsx` in
  the same change (including the `/design-preview` variant), or `check.sh` fails.
- A new `features/<name>/routes.ts` needs a small `routes.test.tsx` that renders
  each lazy page component; otherwise the lazy import functions are the only
  uncovered lines and the 100% per-file gate fails (READY-51 made the same
  observation).
- In page tests that mock `send`, set `mockResolvedValue(view)` for the initial
  GET view rather than relying on a `mockResolvedValueOnce` before render; a
  once-value can be consumed by an unexpected extra call during mounting.
