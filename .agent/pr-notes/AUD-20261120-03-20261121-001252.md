# AUD-20261120-03 — Production authentication, part 2: validate OIDC bearer tokens and bind the tenant context

## Summary

Outside `synthetic-auth`, `/api/v1/**` now requires a validated OIDC JWT bearer token and binds the active tenant from verified token claims. The `synthetic-auth` profile is unchanged: the interceptor remains the only gate for the synthetic header login that every existing test relies on. Added the two managed Spring Security dependencies, a stateless OIDC resource-server chain plus a permissive synthetic chain, the issuer/audience configuration keys, an issuer fail-closed startup check, and the JWT branch in `TenantContextInterceptor`. All changes are inside the declared scope; synthetic fixtures only. No real issuer, audience, client id or secret was written to the repository.

## Authorization boundaries and audit events

The OIDC chain requires authentication for every request; `TenantContextInterceptor` derives the tenant only from verified `sub` and `orgs` claims plus the explicit `X-Active-Organization` header. A token cannot widen its organization set. The synthetic header path is strictly profile-gated. No new audit event was added; tenant binding and denial semantics are unchanged.

## Migration and rollout considerations

`@ConditionalOnWebApplication(SERVLET)` keeps the non-web application-start test working and avoids creating a security chain where there is no HTTP surface. Outside `synthetic-auth`, an empty issuer fails startup closed, so deployment must supply `SMARTCLINIC_OIDC_ISSUER_URI` (and preferably `SMARTCLINIC_OIDC_AUDIENCE`). CSRF is skipped only for bearer requests; the staff-web cookie chain remains a later story (READY-11), so this change must not be used to justify disabling CSRF for browser sessions. Rollout is a normal image promotion; no data migration or rollback SQL is needed.

## Findings

1. **Standalone MockMvc does not populate `SecurityContextHolder` from `jwt()`.** The post-processor stores the context under spring-security-test's `...$TestSecurityContextRepository.REPO` request attribute; it is loaded by Spring Security's `SecurityContextHolderFilter`, which standalone setup does not include. `TenantContextInterceptorJwtTest` bridges that attribute with a test-only filter so the four required cases exercise the real interceptor logic. The `SecurityFilterChainHttpTest` uses the actual `SecurityFilterChain` from a `WebApplicationContextRunner` for negative HTTP evidence. This was flagged independently by both specialist plans.
2. **`@WebMvcTest` / `AutoConfigureMockMvc` are unavailable in this Boot 4.1.2 slice artifact set.** Replaced with `WebApplicationContextRunner` plus standalone MockMvc; no new dependency was added.
3. **SpotBugs CT_CONSTRUCTOR_THROW** on the original `Objects.requireNonNullElse(issuerUri, "")` guard. Spring's `@Value` with an empty default cannot inject null, so the guard was dead code; it was deleted (not suppressed) and the null test removed. SpotBugs now reports 0 findings.
4. **`bash scripts/worker-check.sh` exits 1 before API checks** with `check-pack: opencode.json is stale: run scripts/gen-opencode.py`. This is the documented CI-profile artifact (BUGS OPS-CW-003-01): the worktree `opencode.json` is flagged `S` (skip-worktree) and equals `.github/opencode.ci.json`, while `git show HEAD:opencode.json` equals the generator's local profile (verified by importing `scripts/gen-opencode.py` and comparing `render(ROOT, ci=False)`). No protected file was edited.
5. **`bash scripts/frontend-check.sh` fails on patient-mobile TypeScript errors** (`apps/patient-mobile/src/api/transport.ts(240,50)`, `apps/patient-mobile/src/features/attachments/attachments.test.tsx(231,3)` and others). These files are outside this task's scope and unchanged by it (`git status` shows only `apps/api/pom.xml`, the three `web` Java files and `application.yml`).
6. **OWASP Dependency-Check could not complete locally**: `timeout 540 mvn -B -f apps/api/pom.xml -DskipTests -Dspotbugs.skip=true verify` exited 124 after `NVD API has 430,019 records in this update` because no `NVD_API_KEY` is available in this worker. The integrator runs OWASP with cached NVD data. No dependency was suppressed; the two new dependencies are managed by the Spring Boot parent.
7. **Audience is not fail-closed.** `SMARTCLINIC_OIDC_AUDIENCE` defaults to empty; the story only mandates an issuer check. An empty audience means issuer-only validation, which would accept a token from another audience at the same issuer. This is a production-enablement risk to track (not fixed here, to stay inside scope).
8. **`@ConditionalOnWebApplication(SERVLET)` on `SecurityConfiguration`** keeps `SmartClinicApiApplicationTest.startsTheApplicationEntryPoint` (which starts a non-web context with no issuer) green without weakening the fail-closed check.

## Lessons for workers

- With Spring Security's MockMvc test post-processors in a `standaloneSetup`, you must bridge spring-security-test's `SecurityContextRepository.REPO` request attribute into `SecurityContextHolder` yourself, or build the real filter chain; `jwt()` alone silently produces 401 for every case.
- In Spring Boot 4.1.2 slice tests, `@WebMvcTest` and `@AutoConfigureMockMvc` are not on the starter-test classpath; `WebApplicationContextRunner` plus `MockMvcBuilders.standaloneSetup(...).addFilters(chain.getFilters())` gives real-chain HTTP evidence without them.
- Run SpotBugs *with* tests (`mvn -Dowasp.skip=true verify`) when validating a Java change; `-DskipTests` makes JaCoCo fail first and hides the SpotBugs verdict.
- An unreachable null guard flagged by SpotBugs should be deleted, not annotated, because the coverage rule also forbids untestable branches.
