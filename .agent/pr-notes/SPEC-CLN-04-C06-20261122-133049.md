## Findings

1. **No HTTP/OpenAPI entry for template approval.** The CLN-04 approval workflow is a domain
   service only: no `web` controller and no `contracts/openapi.yaml` path reference
   `TemplateService`, dictionaries or templates. The clause rule is built and proven at the
   domain entry point, so this is outside the clause's scope, not a reason to disable the test.
   Exposing it over HTTP would be a separate production story (new controller + contract +
   integration test). Files that would change: an `api`/`web` controller, `contracts/openapi.yaml`
   and generated staff types.
2. **Pre-existing conflict markers in committed HEAD** (outside this task's scope, not introduced
   here): `apps/api/src/main/java/com/aurevia/exchange/hl7/Hl7ParseException.java`,
   `Hl7Parser.java` and `Hl7Segment.java` contain `<<<<<<< HEAD` / `>>>>>>> origin/swarm/BUILD-37-469`
   lines inside Javadoc comments with identical text on both sides. They are committed in HEAD,
   do not break compilation (verified by the successful compile/SpotBugs run) and were left
   untouched.
3. **Known worker-environment false positive (OPS-CW-003-01).** `check-pack.py` and six
   `test_check_pack.*` tests fail here with `opencode.json is stale`. Evidence:
   `git ls-files -v opencode.json` → `S` (skip-worktree); the worktree file is the CI profile copied
   by `agent-run.sh`, while `git show HEAD:opencode.json` is the correct generated local profile and
   differs from both the CI profile and the worktree file. No protected file was edited; the
   integrator owns the full gate.

## Lessons for workers

- Clause proof tasks with a `chart/clauses` scope can be fully unit-style: reuse
  `InMemoryTemplateStore` + `TemplateActor.of(...)` from `TemplateNoteAcceptanceTest`; no PostgreSQL
  fixture is needed to prove a domain-service governance rule.
- Read the known worker-environment false positives before treating `check-pack.py` or
  `test_check_pack.*` red as a defect: check `git ls-files -v opencode.json` first (`S` means the
  CI profile masks the worktree file) and do not regenerate or edit protected config.
- `check-names.py` accepts the business-domain package `com.aurevia.chart.clauses`;
  `clauses` is a spec-evidence folder used across domains, not a task or gate ID.
