# SPEC-MSG-04-C03 — MSG-04 clause 3 (API test): five named instruction examples are typed kinds

## Summary

Added a green, test-only proof that MSG-04 clause 3's five named examples — collection, imaging
preparation, therapy home instructions, visit follow-up and pharmacy pickup — are real typed
instruction kinds. The clause is already built: `InstructionContract.Kind` declares all five with
stable wire keys and `wire()` / `from(String)`, and `InstructionService.send` carries the kind into
a published `SENT` revision that `listForPatient` returns. No production gap exists, so both tests
are active (no `@Disabled`) and the clause status is `Proven by tests`. Added a clause evidence doc.

Two new files only:
- `apps/api/src/test/java/com/aurevia/messaging/clauses/ExamplesIncludeCollectionImagingPreparationTherapyHomeTest.java`
- `docs/spec/clauses/messaging/examples-include-collection-imaging-preparation-therapy-home.md`

Entry-point-to-test trace: the fast unit test calls `InstructionContract.Kind.from/wire` and
`InstructionService.send` → `InstructionStore.InMemory.save` → `InstructionService.listForPatient`
directly and asserts on the returned `Revision.kind()`, `Revision.state()` and the five visible
revisions. There is no HTTP entry point added: this change adds no route, and an HTTP-level test
would require out-of-scope production edits. The plan reviewer confirmed a DB-less unit proof is
sufficient for a vocabulary clause (the reachability gaps are tracked separately).

## Findings

1. Brief correction (decision, not a defect): the worker brief's example fixture used
   `new InstructionService(store, new InstructionActions(), Clock.fixed(...))`. That constructor is
   package-private (`InstructionService.java:61`), so a test in `…messaging.clauses` cannot call it.
   Caught by the plan reviewer and the test engineer; the test uses the public 2-arg
   `InstructionService(store, new InstructionActions())` constructor instead. No assertion depends
   on time, so the injected clock is unnecessary. No production visibility was widened.
2. Stronger closed-vocabulary proof adopted from the test engineer: literal wire-key assertions
   (`"collection"`, `"imaging_preparation"`, `"therapy_home"`, `"visit_follow_up"`,
   `"pharmacy_pickup"`) plus a free-text-path pin (`templateId() == null`) and a distinct-thread
   count. Round-tripping alone would not detect a wire-key rename.
3. Adjacent context, not a gap in this clause (from the proof survey): MSG-04 instruction routes
   are absent from `contracts/openapi.yaml` and there is no `JdbcInstructionStore` or migration for
   instruction revisions. These are outside this task's scope and tracked elsewhere.
4. No genuine red run was possible: the clause is already built and production edits are forbidden
   by scope. Referencing each named `Kind` constant by name makes removal a compile error, and the
   negative test pins the closed vocabulary; this is recorded honestly rather than claimed as a
   red-then-green cycle.
5. Environment artifacts (not change defects): skip-worktree `opencode.json` makes `worker-check.sh`
   and six `test_check_pack` tooling tests fail; recorded once with evidence above. No protected
   file was edited.
6. Code-review Optional adopted (truthfulness): reworded the doc and two assertion messages so they
   say the revisions appear in the instruction list over an active patient-unit connection via the
   **staff** `listForPatient` branch. The test binds `clinician-a`, so patient-chart binding (IAM-05)
   is not exercised and is not claimed.
7. Code-review Optional noted, not changed: `messaging.clauses` does not mirror the production
   `messaging.instructions` package. This is a deliberate clause-proof grouping fixed by the task
   scope; it makes the Clock-injecting constructor unreachable, but no assertion depends on time, so
   the public 2-arg constructor is deterministic and no flakiness is introduced.

## Lessons for workers

- Before copying a neighbouring test fixture into a sibling package, check constructor visibility:
  the 3-arg `InstructionService(store, actions, Clock)` is package-private in
  `messaging.instructions` and unreachable from `messaging.clauses`.
- For a closed-vocabulary clause proof, assert the literal wire keys, not only `Kind.from(k.wire())`
  round-trips — a rename can preserve round-tripping. Naming each enum constant also makes deletion
  a compile error, the strongest removal signal available in a test-only change.
- Never combine `-Dtest=SomeClass` with `verify`: the JaCoCo BUNDLE 100% rule fails a partial run.
- The skip-worktree `opencode.json` CI profile is a known cloud-worker artifact. Confirm once with
  `git ls-files -v` / `git show HEAD:…`, record the failing command and final line, run the other
  gate stages individually, and never regenerate or commit that file.
- Keep a clause proof inside the clause: no template, approval, context, clinical-authorization or
  other-clause assertions, even when the surrounding service makes them easy to add.
