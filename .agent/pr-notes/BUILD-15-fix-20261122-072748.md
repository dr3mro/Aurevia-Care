## Lessons for workers

- When a story is re-dispatched many times, stop after one clean verification pass and go find the *automation* evidence: read the PR's title, labels and the gate/tracker trigger conditions. Here the answer was a `needs-fix` label blocking `plan_integration` plus a `fix-pr-gate.yml` title/label precondition — neither visible from local checks alone.
- Confirm the recurring bounce is a real gate/hand-off failure before spending another pass on no-op re-verification; a green local run is not proof CI is green, and recommitting the same notes cannot change a label.
- When two workers implement the same story, survey `main` and all prior notes before reimplementing: keep the feature/acceptance that already landed, contribute only the missing slice (here the HTTP entry-point test), and on conflict adopt the base file when it already carries equivalent coverage.
- In cloud workers `opencode.json` is skip-worktree (`S`) with the CI profile; compare `git show HEAD:opencode.json` with `gen.render(root)` before treating `check-pack.py` "stale" failures as yours.
- Do not run `scripts/check.sh`, `scripts/coverage-check.sh` (full `mvn verify`) or `scripts/docs.sh` as a worker; the full PostgreSQL/static-analysis/documentation gate is reserved for the integrator/Delivery.
