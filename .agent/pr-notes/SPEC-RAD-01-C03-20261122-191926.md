# SPEC-RAD-01-C03 — RAD-01 clause 3 API test: signed interpretation with five narrative sections

## Summary

Proves spec RAD-01 clause 3 ("Produce a signed interpretation with technique,
comparison, findings, impression and follow-up.") by a green HTTP test through the
real `POST /api/v1/radiology/reports` entry point, plus refusal negatives. The

no production code, contract, migration or existing test was changed. The clause

## Lessons for workers

- For a clause story, first decide whether the clause is proven at the HTTP boundary or the domain kernel. `ReportService.publish` carries technique/comparison/findings/impression/follow-up but does not validate their presence; `ImagingService.sign` does. A blank-narrative POST returning 422 would be a false expectation over HTTP — do not write that test.
- `worker_gate.py` invoked by hand without `STORY_BODY`/`STORY_ID`/`NOTES_FILE` reports bogus scope and notes-heading violations; run worker stages with the swarm environment or supply those variables before trusting its verdict.
- In a cloud worker, `git ls-files -v opencode.json` → `S` explains both `check-pack.py` and `test_check_pack` failures; confirm once and run the remaining gate stages individually rather than editing the protected file.
