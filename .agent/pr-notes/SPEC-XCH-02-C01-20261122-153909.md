internal states for workflow (requested → accepted → processing → completed,
with rejected/cancelled branches), transmission (pending → sent → delivered or
failed), and clinical review (unreviewed → acknowledged → action pending →
resolved)."

## Lessons for workers

- Cloning a clause test from another domain is a style choice, not a fixture
  choice: take the domain fixtures (organization, membership, role, fixed clock)
  from the existing HTTP integration suite of the same domain, and take only the
  RestClient/header/timeout helper from the generic clause template.
- The V20 `UNIQUE (organization_id, order_ref)` key means every test in a shared
  database needs its own order reference; a copied single reference fails every
  case after the first at create (409 `CONFLICT`).
- `assertNotNull(node.asText())` cannot fail on a JSON null node: Jackson returns
  the literal `"null"`. Assert the exact DB-derived value instead (here the
  `user_identity` id of the acting clinician).
- Describe a forbidden transition by the command and role the test actually
  uses; "clinician-only complete" is wrong here because workflow commands are
  allowed for both clinician and lab_collector.
- In a cloud worker, confirm the `opencode.json` "stale" verdict once
  (`git ls-files -v`, compare with `.github/opencode.ci.json` and
  `git show HEAD:opencode.json`), record the final line, then run the remaining
  gate stages individually instead of re-diagnosing it.
