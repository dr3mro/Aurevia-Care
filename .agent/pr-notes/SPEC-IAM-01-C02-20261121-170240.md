## Step 1 survey — where the clause is implemented today

Found (production, under `apps/api/src/main/java/com/aurevia/`):
- `web/TenantContextInterceptor.java` — derives the request tenant from
  `X-Active-Organization`; missing/invalid selection fails closed (422).
- `web/ClaimsTenantResolver.java` — for JWT auth, accepts an organization only when
  it is in the token's `orgs` claim (403 otherwise).
- `tenant/TenantContext.java` — request-scoped context whose `organizationId` is the
  active organization (never inferred from a resource or first membership).

- `tenancy/FacilityController.java`, `FacilityService.java`, `FacilityRepository.java`
  — thin controller + domain service + RLS-bounded JDBC repository; membership is
  re-checked in the active organization on every protected request.
- `authz/ActionPolicy.java` — action/role permission policy used by FacilityService.

Migrations: `db/migrations/V1__tenant_schema.sql` (organization table, composite
`(organization_id, id)` tenant-owned keys), `V2__rls_roles_policies.sql` (forced RLS
keyed on `app.current_org()`), `V4__staff_lifecycle.sql` (`has_active_membership`

## Lessons for workers

- In a cloud worker, `opencode.json` is the CI profile under skip-worktree, so
  `check-pack.py` / `test_check_pack` fail even with a clean change; verify with
  `git ls-files -v opencode.json` before treating it as your defect.
- `scripts/quick-check.sh` can stop at shellcheck on pre-existing info-level notes in
  protected scripts; confirm against `git show HEAD:<file>` before changing anything.
- Real-PostgreSQL clause tests should use a unique database name
  (`aurevia_tenant_org_it`) to avoid clashing with parallel workers; mirror
  `FacilityIsolationTest` fixtures and Flyway setup.
