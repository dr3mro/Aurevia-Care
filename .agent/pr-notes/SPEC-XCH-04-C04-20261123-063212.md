## Clause and acceptance mapping

Requirement XCH-04 clause 4: "Corrections preserve prior versions, notify prior recipients where appropriate, and reopen review even after acknowledgment."

| Clause part | Test method | Assertion |
|---|---|---|
| preserve prior version | `correctionPreservesPriorRevisionNotifiesPriorRecipientAndReopensAcknowledgedReview` | v1 review still `acknowledged`, two immutable revision rows, v1 `previousId` link |
| notify prior recipient | same | one notification to `verifier-a` with `supersededVersion` 1 |
| reopen review after acknowledgment | same | v2 review `unreviewed`, one `XCH04_REVIEW_REOPENED` audit keyed to v1 |
| refuse wrong role | `correctionBySubjectWithoutImportRoleIsForbidden` | HTTP 403, no revision/notification appended |
| refuse peer tenant / RLS concealment | `correctionFromPeerTenantCannotModifyHomeTenantData` | 403 without membership, 404 on cross-tenant read, 202 reconciliation, home counts unchanged |
| refuse stale correction | `correctionWithNonTipSupersedesVersionIsQueuedNotImported` | 202 `conflict`, no revision/notification |
| refuse missing input | `correctedResultWithoutSupersedesVersionIsRefused` | 422 for `SUPERSEDES_REQUIRED` and `SUPERSEDES_NOT_ALLOWED`, counts unchanged |

## Findings

  assert a v1 size of 1.
- No defect was found in the implemented clause; all five tests passed against existing production.

## Lessons for workers

- When a clause already has a broad integration test, a dedicated `exchange.clauses` test still adds
  value only if it adds distinct negatives (here: wrong role, peer tenant with RLS concealment,
  non-tip and missing-input refusals) and side-effect assertions, not a copy of the happy path.
- For a correction test, establish a matched order + imported v1 baseline before asserting a
  supersedes refusal: `findOrder`/`match` and reconciliation run before the `SUPERSEDES_*` checks, so
  a mismatched fixture yields 202 instead of the intended 422.
- A standalone `-Dtest=...` integration class must create `smartclinic_migrate`/`smartclinic_app`
  itself; no other script guarantees those roles exist.
