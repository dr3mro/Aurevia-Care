## Findings

- **Prior blocker resolved (tool evidence).** The generated-client drift that
  stopped the earlier attempt is fixed on `origin/main`; `gen:api:check` now
  passes and the full module gate is green.
- **Reviewer finding rejected after investigation.** The senior-react review
  suggested resetting `dir`/`lang` per test because the RTL case mutates the
  document. `apps/staff-web/tests/setup.ts` already removes both attributes in
  a global `afterEach`, so no pollution existed. I added two assertions at the
  start of the first parameterized test to guard that invariant; they pass.
- **Comment over-claim corrected.** `Button.tsx` now states that
  `scrollMarginBlockEnd` is best-effort scroll clearance and that the sticky
  form footer owns keyboard reachability (design §8) — no behavior change.
- **Missing shared control class.** `responsive.css` has no generic
  interactive-control utility; Button (and Dialog/StateViews) duplicate logical
  padding/wrap/alignment/scroll-margin inline. Recorded under Lessons; the
  stylesheet was not edited (story step 3 forbids it).
- **Safe-area insets** are owned by `.page`/`.app-shell`/`.sheet` in
  `responsive.css`; a leaf button composes with them via logical properties.
- **Keyboard reachability** is only partly addressable in a leaf button;
  `scrollMarginBlockEnd` plus the sticky footer/scroll-padding boundary is the
  full pattern and cannot be proven in jsdom (design §13).
- **Inline `minHeight` conflict (inherited).** The prior attempt removed the old
  `minHeight: '32px'` that outranked `.touch`'s coarse 44 px block floor; the
  fine-pointer floor consequently uses the documented 24 px general floor.
- **ADR-0004 / WEB-07 text (inherited).** ADR-0004 is still `Proposed` and
  `PROJECT_V1_SPEC.md` WEB-07 still states the old 1280/768 floors; code
  follows the decision as the story instructed and the owner amendment remains
  pending.
- **Out-of-scope repo state (observed).** `git grep` shows pre-existing conflict
  markers committed in unrelated `apps/api/.../exchange/hl7/Hl7*.java` files.
  They are not part of this story's diff and the staff-web gate is unaffected;
  they should be handled by their owning workers.

## Lessons for workers

- Check `apps/staff-web/tests/setup.ts` before adding per-test `dir`/`lang`
  cleanup — a global `afterEach` already removes `dir`, `lang` and the theme
  dataset. A reviewer recommendation to add a per-file reset was unnecessary.
- jsdom 25 serializes logical properties (`padding-block`, `padding-inline`,
  `scroll-margin-block-end`, `text-align: start`) into the style attribute, so
  assert those directly; still avoid painted-pixel claims (design §13).
- Never add inline `minHeight`/`minInlineSize` that competes with `.touch`:
  inline sizes outrank the stylesheet's coarse 44 px rule. Assert those style
  properties are empty to prevent regression.
- Mock `matchMedia` per query string with `vi.stubGlobal` and restore with
  `vi.unstubAllGlobals()`; read query strings from `BREAKPOINT_MEDIA_QUERIES`
  instead of hard-coding them. Wrap `change` dispatches in `act()`.
- `responsive.css` lacks a shared `.control`/`.action` utility for logical
  padding + `overflow-wrap: anywhere` + `text-align: start` +
  `scroll-margin-block-end`; Button/Dialog/StateViews duplicate it. A follow-up
  stylesheet story should add one; do not edit the stylesheet from a component
  story.
- In a worker story, run the module `bash apps/staff-web/check.sh` as the
  canonical gate. Do not run the repo-wide `scripts/check.sh`, which invokes
  the full Java/DB gates (10+ minutes) that this task forbids.
