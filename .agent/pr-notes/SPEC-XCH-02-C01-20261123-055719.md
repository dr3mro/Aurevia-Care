# SPEC-XCH-02-C01 — XCH-02 clause 1 API proof

## Summary

Adds an HTTP-level integration test that proves XCH-02 clause 1 through the real
REST entry point: one exchange task holds three independent state channels
(workflow, transmission, clinical review), each with its legal chain and
rejected/cancelled/failed branches, and a delivery receipt never closes a
clinical task. Adds the matching spec-clause evidence document. No production
code, migration, contract or existing test changed.

## Affected requirements

XCH-02 (clause 1). Clause: "Use separate internal states for workflow (requested → accepted → processing → completed, with rejected/cancelled branches), transmission (pending → sent → delivered or failed), and clinical review (unreviewed → acknowledged → action pending → resolved)."

## Risk class

Routine (test-only addition; existing behavior exercised, not changed). Safety
invariants (tenant isolation, role separation, human acknowledgment) are asserted
with negative cases but not implemented here.

## Lessons for workers

- For a per-clause proof against code that is already built, a test is green on its first run. Do a bounded, reverted-only assertion flip in your own test file to show the assertion is live, restore it with `cmp` verification, and record the red line; do not claim a red run you did not observe and never mutate production code in a shared worktree.
- Give every mutating test its own seeded task UUID and orderRef, and give the class its own database name. Reusing the broad `smartclinic_xch02_it` database makes `@BeforeAll DROP DATABASE ... WITH (FORCE)` interfere with sibling workers.
- `worker-check.sh` and `python-coverage.sh` stop on the skip-worktree `opencode.json` profile in a cloud worker (and `coverage` is not installed there). Confirm once with `git ls-files -v opencode.json` → `S` plus `git show HEAD:opencode.json`, then run the remaining stages individually; never regenerate or commit that protected file.
