## Lessons for workers

- For a test-only clause-proof story, copy the domain's existing HTTP harness (here `scheduling/followup/it/FollowUpHttpIntegrationTest`) for facility/config/appointment seeding and the sibling clause test for per-class fresh DB and RLS-bound row counting; give each test its own patient so counts stay order-independent on a shared class DB.
- To make a cross-tenant HTTP negative deterministic, remove the contested resource key from the peer tenant (ORG_B has no `MAIN` facility) so the LIVE 404 comes from `FollowUpConfiguration.facilityZone` under forced RLS — no `@Disabled`, no failing test on a green PR.
- V5 config approval needs `app.current_org` AND `app.actor` set to a user_identity of that org: the `config_entry`/`config_approval` triggers derive `created_by`/`approved_by` from `app.actor`. V8 appointments have the same actor requirement plus FKs to patient, facility, clinician resource and visit type.
- `-Pno-security` sets `spotbugs.skip=true`; run compile and `spotbugs:check` without that profile (with `-DskipTests compile` first) or the scan is vacuously green.
- In a cloud worker, a red `worker-check.sh` at `check-pack` is the CI-profile `skip-worktree` artifact; confirm once with `git ls-files -v opencode.json`, record it, and run the remaining stages individually rather than editing a protected file.
