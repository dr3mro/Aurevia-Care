## Lessons for workers

- `tests/messageParity.test.ts` glob-discovers every `src/**/messages.ts` and requires a statically imported registry entry in that out-of-scope file; a feature-local bilingual bundle should be named `labels.ts` (as `pharmacyinbox` does) unless the story owns the registry.
- In this cloud worker, a red `check-pack` is the CI `opencode.json` under `skip-worktree`; confirm with `git ls-files -v opencode.json`, compare worktree to `.github/opencode.ci.json` and to `git show HEAD:opencode.json`, and never regenerate or commit it (documented in the delivery skill and the reconciled notes).
- `gen:api:check` can be red at HEAD because a parallel story edited `contracts/openapi.yaml` without regenerating `apps/staff-web/src/api/generated/openapi.d.ts`; diagnose with `git log --oneline -- <contract> <generated>` before assuming your change caused it.
- A per-file 100% coverage gate is satisfied without a dedicated component test for a `Record`-lookup branch, but a distinct worded message per blocker still deserves its own parity test (`labels.test.ts`) so a missing translation fails the build.
