# ISS-746 — Wire recovery action callbacks through staff-web shared state views

## Summary

The shared state views now forward recovery actions instead of rendering inert no-ops. `StateViews.tsx` exports one `StateViewActions` interface (five optional `(() => void) | undefined` callbacks) and `StateView.forTransportError(error, actions?)` passes them into `SessionExpiredState`, `ConflictState` and `ErrorState`. `SessionContext.tsx` gains an optional `onSignIn` with a safe noop default. `ApiPage.tsx` gains an optional `actions` prop and, in its error branch, sources Reload from `useApi`'s `result.reload` and Sign in from `useSession()`; `onSessionExpired` stays only in the existing once-per-error dedup effect, so clicking Sign in never re-notifies expiry. All ~30 existing one-argument `forTransportError` callers and the out-of-scope `{ onSessionExpired }`-only providers remain valid.

Status: the scoped change and every stage that exercises it are green. The canonical `bash apps/staff-web/check.sh` cannot reach exit 0 on this base because of two pre-existing failures on `main` outside this task's scope (see Findings and "Why this is not finished"). No out-of-scope file was edited to hide them.

Story/brief: the brief was accurate. One deliberate implementation deviation is recorded in Findings (a `?? {}` helper replaces the suggested `= {}` default parameter to satisfy the complexity-12 lint rule; behavior is identical).

## Affected requirements

No requirement IDs in the story. This is the shared staff-web state-view plumbing that supports WEB-09 (required screen states), UX-01 (keyboard reachability and accessible announcements) and WEB-07 (logical, wrappable layout). Evidence lines below are co-located tests, not new clinical acceptance.

Requirements covered by the acceptance matrix:
- Conflict view: Compare / Reload / Copy each invoke the matching supplied callback and no other.
- Session-expired view: Sign in invokes the supplied callback; expiry notification count stays 1 after the click.
- Server and timeout views: Retry invokes the supplied callback.
- ApiPage: Reload re-runs the loader via `result.reload` when no action is supplied; Sign in uses the session owner; explicit actions win over both fallbacks.
- No-callback paths: every control stays keyboard reachable and clicking it does not throw.

## Findings

1. **Pre-existing gate blocker — generated client drift.** `bash apps/staff-web/check.sh` stops at `npm run gen:api:check` with `✨ openapi-typescript 7.13.0` / `✘  Generated types are not up-to-date!`. `contracts/openapi.yaml` on base `main` contains `/api/v1/staff/instant/events` and `/api/v1/staff/instant/events/stream` (plus `RealtimeEventType`/`RealtimeEvent`) that the committed `apps/staff-web/src/api/generated/openapi.d.ts` lacks; regenerating to a temporary file produces a 160-line diff. Both files are byte-identical to `origin/main` and outside this task's scope. This is already tracked by the existing instant-messaging OpenAPI repair task in `TODO.md` (its step 4 is "Regenerate staff web types with `npm --prefix apps/staff-web run gen:api`"), so no task request is added here.

2. **Pre-existing gate blocker — whole-repo coverage.** `npm run test:coverage` passes all 2618 tests but exits 1 on 48 per-file sub-100% entries in unrelated files (e.g. `src/components/invariant.ts`, `src/features/chart/*`, `src/features/scheduling/*`, `src/theme/useBreakpoint.ts`). None of the three touched source files is in that list; each is 100%. These files and their tests are unchanged by this story.

3. **No production owner for the new actions yet (Optional, not a regression).** No production `SessionContext.Provider` is mounted under `apps/staff-web/src`, and no production `<ApiPage actions={…}>` caller exists. `useSession()` therefore returns `defaultSessionContext`, so Sign in is a noop on real screens until a shell provider supplies `onSignIn`; Compare/Copy/Retry likewise stay noop until callers pass them. Reload is live everywhere because it falls back to `result.reload`. Mounting the shell provider and supplying caller actions needs a separate story outside this scope; the plan reviewer and both code reviewers raised this as Optional only.

4. **Brief deviation (behavior-identical).** The brief suggested `StateView.forTransportError(error, actions = {})`. A default parameter adds 1 to ESLint's `complexity`, taking the 11-case switch from 12 to 13 against the repo's `complexity: ['error', 12]`. The implementation uses `actions?: StateViewActions` plus the two-line `actionsOrEmpty(actions)` helper (`actions ?? {}`) instead: still a second optional argument with an empty-object fallback, and the helper's own `??` is covered by both no-actions and supplied-actions tests.

5. **Lint-driven test layout.** Splitting the new ApiPage tests into a second `describe('ApiPage recovery actions')` was required by `max-lines-per-function: 150` on the original describe callback; no rule was loosened. The parameter in `forTransportError` omits `| undefined` because `@typescript-eslint/no-duplicate-type-constituents` rejects it on optional parameters, while interface properties keep `| undefined` for `exactOptionalPropertyTypes`.

6. **Reviewer tooling limitation.** The subagents could not run shell commands; their verdicts are static-review evidence. Typecheck, lint, build, bundle, Vitest (red and green), coverage and formatting were executed and recorded by the primary agent.

## Lessons for workers

- In `apps/staff-web`, a `= {}` default parameter on the already-large `forTransportError` switch breaks `complexity: 12`; a tiny `?? {}` helper keeps the same behavior and the lint gate green.
- `max-lines-per-function: 150` counts the `describe(...)` callback. Splitting new tests into a second `describe` is a real fix; an eslint-disable is not.
- Under `exactOptionalPropertyTypes`, optional interface properties need `fn?: (() => void) | undefined`, but an optional *parameter* must be `actions?: StateViewActions` — adding `| undefined` there trips `no-duplicate-type-constituents`.
- When `check.sh` fails before reaching your code, prove the blocker is pre-existing (untouched files, generated diff), run each remaining stage individually, and record it. Do not edit `contracts/`, generated clients, thresholds or protected scripts to make a worker gate green.
- A `vi.fn()` passed through a callback chain proves wiring; a `.not.toThrow()` click only proves the noop path does not crash. Keep both kinds of assertion.
