## Findings

1. **No directory/roster/escalation paths in the staff API contract.**
   `contracts/openapi.yaml` (781 lines, read in full) defines exactly 19 paths:
   facilities (2), configuration (4), catalogs (4), audit-events (1), staff (4),
   appointments (1), lab/accessions (1), finance/invoices (1), orders (1).
   There is no referral-partner directory, coverage-roster, critical-escalation,
   roster-gap or unit service-profile resource. The generated client
   `apps/staff-web/src/api/generated/openapi.d.ts` has the same 19 paths.

2. **The generic catalog/config APIs cannot honestly satisfy the acceptance
   criteria.** `/api/v1/catalogs/{family}` stores an opaque `value` string
   (`maxLength: 4000`) and `/api/v1/configuration` likewise; neither validates
   owner, deadline or backup contact, so "a rule without a backup is refused"
   would only be a client-side convention, not a durable API invariant.
   `referral_partner` appears only as a *validator example* in
   `apps/staff-web/src/features/admin/api.test.ts:559` and a Javadoc example in
   `apps/api/src/main/java/com/aurevia/smartclinic/catalog/CatalogEntry.java:6`,
   not as a contracted resource with destination/contact-channel/order-type
   fields. Treating it as one would mean inventing the contract.

3. **The backend has implementations, but they are not contracted for staff
   web.** `apps/api/src/main/java/com/aurevia/smartclinic/messaging/service/ServiceProfileController.java`
   exposes `/api/v1/care-units/{unitId}/service-profile`, `/availability`,
   `/service-profile/versions`, `/supervisor-snapshot`, `/service-profiles`
   and `/service-profiles/{profileId}/approve` (MSG-06: service hours, queue
   owner, backup coverage, escalation/urgent/downtime channels, named approval).
   `CareUnitController` exposes `/api/v1/care-units`.
   `apps/api/src/main/java/com/aurevia/smartclinic/exchange/critical/CriticalResultController.java`
   has an operational report of overdue alerts, roster gaps and failed
   notifications, and `CriticalResultService` reads escalation channels from
   configuration. None of these paths appear in `contracts/openapi.yaml` or in
   `contracts/openapi/generated/openapi.yaml` (which has only
   `/api/v1/critical/{id}/acknowledge` and
   `/api/v1/therapy/referrals/{id}/accept` for these domains). The staff-web
   generated client therefore cannot call them.

4. **No navigation route exists for this feature.** `apps/staff-web/src/app/navigation.ts`
   and `docs/design/screens-and-navigation.md` have no referral-partner or
   coverage-roster route; adding one is also outside this task's scope.

Next worker must know: the blocker is a missing/unsynchronized API contract, not
a coding or coverage problem. Do not build the screens on top of opaque
configuration values or client-invented schemas; that would create a feature with
no real entry point and would fail the "done means working end to end" bar in
AGENTS.md.

## Lessons for workers

- When a story says "read the X API in `contracts/openapi.yaml`" and also has a
  "do not invent it, stop" clause, verify the paths in the contract *and* in the
  generated client before designing any screen. Backend controllers that are not
  in the contract are not callable from staff web.
- `bash apps/staff-web/check.sh` green only proves the existing tree is healthy;
  it does not prove a story's API prerequisite exists. Check the contract first.
- Keep stop-early notes precise: enumerate the missing paths, the closest wrong
  alternatives, the exact files/lines inspected and the concrete next step, so
  the next worker or person does not rediscover the gap.
