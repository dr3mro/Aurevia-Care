## Findings

1. CLN-04 clause 4 is implemented at the domain/persistence layer
   (`TemplateService`, `BaselineTemplates.fieldsFor(PERINATAL)`,
   `TemplateKind.PERINATAL`, `V80__template_store.sql`, `V87__baseline_templates.sql`)
   but has no HTTP controller, no `/api/v1/clinical/templates/**` route and no OpenAPI
   operation. Hence "Partly proven" and a disabled GAP test. The chart clause test
   package intentionally hosts this test because the story assigns that scope.
2. Pre-existing committed conflict markers inside Javadoc on `main` in
   `apps/api/src/main/java/com/aurevia/smartclinic/exchange/hl7/Hl7ParseException.java`,
   `Hl7Parser.java` and `Hl7Segment.java` (from `origin/swarm/BUILD-37-469`). They do
   not break compilation and are outside this task's scope; left untouched. Owner/
   integrator should clean them.
3. `InMemoryTemplateStore` currently lives under `apps/api/src/main/.../clinical/templates`,
   contrary to the "InMemory* fakes live in src/test" rule. Existing condition, out of
   scope; this test uses it only as the test double, matching `TemplateNoteAcceptanceTest`.
4. OPS-CW-003-01 (see Test evidence) makes `check.sh`, `check-pack.py`,
   `python-coverage.sh` and 6 unit tests red in this worker. Committed profile is correct;
   integrator owns the full gate.
5. `check-wiring.py` prints informational "fixed; delete it from scripts/wiring-baseline.json"
   notes for pre-existing entries and exits 0.
6. A bounded senior-backend review (subagent, simulated) confirmed the "Partly proven"
   classification and found two gaps, both fixed in this follow-up: the `missing:birthHistory`
   negative was added (both histories are now proven required), and the clause document
   no longer calls the `src/main` `InMemoryTemplateStore` an "in-test" double. The
   "FrozenMeanings" claim was narrowed to field meanings recorded at save time;
   historical-version resilience is clause 7 and is not claimed here.

## Lessons for workers

- For a CLN-04 clause test, survey `com.aurevia.smartclinic.clinical.templates` first,
  not only `chart/record`: versioned template notes live there and `chart/clauses` is the
  assigned home for the clause-evidence tests.
- Confirm whether an HTTP controller exists before writing an HTTP-level clause test.
  When the rule exists only at the domain layer, write enabled domain-level tests plus
  one `@Disabled("GAP: ...")` HTTP test and set the clause doc to "Partly proven"; this
  keeps the PR green and gives the next worker an executable target.
- In cloud workers, an `opencode.json is stale` failure is the CI profile under
  skip-worktree (`git ls-files -v` shows `S`). Confirm once, record it, run the other
  gate stages individually, and never regenerate that protected file.
