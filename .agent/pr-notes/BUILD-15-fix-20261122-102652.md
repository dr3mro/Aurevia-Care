## Lessons for workers

- When a story is re-dispatched many times and local checks are green, the blocker is usually in the hand-off tooling, not the code — but trace the *actual* red CI job before blaming a label. Here the red job was `script-tests`, caused by a one-line workflow token regression (`499fea23`), not by a stale label; fourteen-plus fix passes repeated identical green verification and misdiagnosed it.
- Verify a claimed root cause against the current tree before acting: the workflow fix (`4bc9e562`) was already merged to `main`, so the correct action was verification and hand-off, not another edit. Running the single previously-failing guard test is the cheapest decisive evidence.
- Never edit `.github/workflows/*`, `scripts/*`, trackers or `.opencode/*` as a worker. Put the diagnosis and the exact trusted next step in the notes; a protected-path PR is not merged automatically and blocks the story.
- Do not run `scripts/check.sh`, `scripts/coverage-check.sh` (full `mvn verify`), `apps/api/check.sh` or `scripts/docs.sh` as a worker; the full PostgreSQL/static-analysis/documentation gate is reserved for the integrator/Delivery.
