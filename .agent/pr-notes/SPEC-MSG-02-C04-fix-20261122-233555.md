## Lessons for workers

- For a fix pass whose code is already correct, the deliverable that unblocks the
  gate is the correctly named notes file (`.agent/pr-notes/<task-id>-fix-<stamp>.md`)
  with the complete hand-off sections and genuine reviewer verdicts; write it
  before running `quality-gate.sh`, because `check-verdicts.py` reads it.
- Under `-Pno-security`, SpotBugs is skipped. Add `-Dspotbugs.skip=false` and
  compile first, then confirm `BugInstance size is 0` in the output.
- For a test-only clause proof, run the targeted `test` phase, not `verify`:
  JaCoCo's build-failing gate sees only the selected test at `verify`. State
  explicitly in the notes that no production line changed.
- Before treating `check-pack.py` or `test_check_pack` staleness as a defect in a
  cloud worker, run `git ls-files -v opencode.json`; `S` plus a HEAD file that
  matches the generator means the worktree is the CI profile under
  skip-worktree. Confirm once, record the command and final line, and do not
  regenerate or re-diagnose it.
- To prove a "within the unit" rule, stub the out-of-unit target as an active
  member with a role from another unit; otherwise the test only proves the
  inactive-target branch and passes for the wrong reason.
