## Findings

- **Resolved in this pass — Senior React/Vite reviewer findings (2).** A bounded
  read-only review confirmed all five story acceptance points and reported:
  (1) the medium icon-rail `<a>` bypassed the router `Link` click guards, so a
  Ctrl/Cmd/Shift/Alt or middle click forced same-tab in-app navigation; and
  (2) `onPointerLeave`/`onPointerCancel` called `releaseLongPress`, which hid a
  tooltip that had been opened by keyboard focus even while focus remained,
  contrary to the cited WCAG 1.4.13 rule. Both were reproduced with failing tests
  first (6 click cases + 1 tooltip case) and then fixed in `AppShell.tsx` (click
  guards; new `onCancelPress` prop wired to pointer leave/cancel). `Link` could
  not be reused because it exposes no `aria-label`/`className` and `router.tsx`
  is outside this story's scope; the guard is therefore duplicated locally with
  a comment explaining why. The reviewer's third point was informational: the
  `main.style.overflowX === ''` assertion only proves there is no inline
  override, not that the page cannot scroll horizontally; the real mechanism is
  the `page`/`app-shell` classes and `min-inline-size: 0`, which jsdom cannot lay
  out. No change made — keep the `classList.contains('page')` assertion and read
  `overflowX` only as "no inline override". Evidence source: reviewer source
  report (advisory) plus my executed red/green commands (tool).
- **Resolved in this pass — out-of-scope changes.** Fix pass 1 committed three
  Java files under `apps/api/src/main/java/com/aurevia/exchange/hl7/`
  to clear conflict markers left by `BUILD-37`'s merge. Those files are outside
  the RESP-SHELL scope and made the worker coverage gate start the forbidden full
  Java verify. They are restored to their exact `origin/main` content; the PR
  diff no longer touches them. **No production behavior changed.**

## Lessons for workers

- Check `git diff origin/main --name-only` before finishing, not just after the
  first implementation: a previous fix pass's out-of-scope edits can survive in
  the branch and make `scripts/coverage-check.sh` start the full Java verify.
  Restoring those files to the base branch keeps both scope and runtime correct.
- A conflict marker on `origin/main` is base-branch debt, not a conflict in your
  merge. Cleaning it inside an unrelated scoped story breaks scope and forces the
  wrong coverage gate; hand it back through Findings and a task-request instead.
- `apps/staff-web/check.sh` is the canonical staff-web gate (typecheck, lint,
  build, bundle and 100% coverage). `scripts/coverage-check.sh <base>` and
  `scripts/frontend-typecheck-check.sh <base>` are the fast worker gates and are
  scope-sensitive to the changed paths.
- From earlier passes: `Link` in `src/app/router.tsx` accepts no `className`,
  `aria-label` or event handlers. For an icon-only link render a real `<a>` with
  an `aria-label` and an `onClick` that calls `preventDefault()` then
  `navigate(route)` to avoid a document reload. `useBreakpoint` falls back to
  `expanded` without `matchMedia`, so stub each media query deterministically and
  restore globals in `afterEach`.
