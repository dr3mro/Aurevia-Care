# RESP-APP-CONFIG — Patient app: enable tablets and rotation in the Expo configuration

## Summary

Configuration-only change to `apps/patient-mobile/app.json`: the patient Expo app now
supports tablets and both orientations and no longer forces full-screen on iPad.
`ios.supportsTablet` is set to `true`, top-level `orientation` is set to `default`, and
`ios.requireFullScreen: false` is added so Split View and Slide Over keep working. Every
other key is preserved; no plugin, dependency or source file was added. This applies the
device/orientation and iPad-multitasking decisions in
`docs/decisions/0005-patient-app-tablets.md`.

## Affected requirements

- **PAT-01** (appointments self-access) / **PAT-02** (released reports): the patient app
  can now run on iPad and Android tablets and after rotation, so the appointment list and
  released reports are reachable on those form factors. Configuration prerequisite only —
  no API, authorization or cache behaviour changed.
- **UX-01** (native screen readers, English/Arabic RTL, 200% text): tablet/landscape and
  multitasking support is the prerequisite for the responsive/accessibility contract in
  decision 0005; this change locks no orientation and forces no full-screen.

  manifest but does not assert the tablet/orientation keys. Adding such assertions is out of

## Lessons for workers

- For a patient-mobile config-only story, the manifest acceptance test is
  `src/app/appConfig.test.ts` — run it targeted (`npx jest --ci --runTestsByPath …`)
  before the full module gate to separate your change from unrelated noise.
- `bash apps/patient-mobile/check.sh` currently has an unrelated red
  (`domain-layout.test.ts` / `tracker` folder from TRACK-02). Confirm whether a failing
  test even reads your changed file before treating the gate as blocked by your work.
- A JSON/manifest change adds no coverage branches; state that explicitly in `## Coverage`
  instead of inventing a test or weakening the 100% gate.
