# BUILD-37 — HL7 v2 order and result messages (ORM and ORU)

## Summary

Added a dependency-free HL7 v2 parser, writer, mapper and acknowledgment entry point in
`com.aurevia.exchange.hl7`. It handles ORM^O01 orders and ORU^R01 results, escape
rules (including hex escapes and CR/LF segment-injection defence), repeating fields, declared
non-standard delimiters, segment order, and positive/negative ACKs. Messages map to the existing
`OrderRequest` and `ImportResultRequest` commands; malformed, partial or duplicate messages yield
a negative ACK with a stable reason and never produce a command. All fixtures are synthetic.

Scope was strictly the two `exchange/hl7` paths; no dependency, controller, migration, contract
file or tracker was changed.

## Affected requirements

- XCH-01 — order payload mapping, sender authorization facts supplied by caller, ACK.
- XCH-04 — result mapping, identifier-bearing command, corrected-result revision, negative ACK.
- LAB-02 — observation status mapping (final/corrected/critical) and repeating values.

## Risk class

Cross-boundary (partner interface). No patient data, credentials or real identifiers are used;
no clinical sign-off is claimed.

## Review owner

Senior Integrations (contract, duplicates, corrections, unsupported variants) and Senior Java
and Spring Boot (SOLID, SpotBugs, Javadoc).

## Data changes

None. No Flyway migration, table, backfill or lock impact. The duplicate ledger is an in-memory
`Set` in `Hl7Exchange` and is explicitly documented as process-local; durable replay protection
is a follow-up (see Findings).

## Authorization boundaries and audit events

No new audit events. XCH-01 authorization facts (`purpose`, `authorizationId`, `durationMinutes`,
`workQueue`) come from the caller's `Hl7SenderContext`, not from the wire; the mapper rejects a
missing or non-positive value before creating an order command. No tenant, role or patient-link
decision is made in this bounded slice.

## Migration and rollout considerations

None in this change. A follow-up must add a tenant-owned forced-RLS store before any production
enablement.

## Clinical and architecture review

Not required for merging this bounded parser slice: it performs no clinical decision, signs no
data and exposes no patient-facing surface. Result disposition mapping is a documented synthetic
profile (OBX-11 `F`→FINAL, `C`→CORRECTED, `A`→CRITICAL) and must be confirmed against a real
partner implementation plan before enablement.

## Findings

1. An early writer revision placed facilities in MSH-3/MSH-5, so the mapper read `EXCHANGE`
   instead of the sender/receiver. Caught by `Hl7MapperTest`; fixed by writing facilities in
   MSH-4/MSH-6 and application names in MSH-3/MSH-5.
2. An early mapper revision formatted the parsed instant back to HL7 form instead of ISO-8601;
   caught by `Hl7MapperTest`; fixed with `Instant.toString()`.
3. `Hl7Parser` had a `mshLine == null` guard that could never be true after the `isBlank()`
   guard. Deleted rather than left as uncoverable code (AGENTS.md Coverage rule 3).
4. The story scope forbids a controller, migration, OpenAPI client and HTTP integration test, so
   the "done means working end to end" checklist cannot be satisfied here. `Hl7Exchange` is a
   pure Java entry point with full unit coverage but no production caller and a process-local
   dedup ledger; production wiring and durable replay protection need a follow-up task.
   Evidence source: executed commands and file reads (tool), not a reviewer or human.

## Lessons for workers

- In a cloud worker `opencode.json` is the CI profile under `skip-worktree`; `check-pack.py`
  failure there is a measurement artifact. Verify against the committed HEAD profile in a
  temporary root instead of editing the protected file.
- JaCoCo counts every `case`, `catch` and side of an `||`. After a guard such as `isBlank()`, a
  later "is null/empty" guard is dead code — delete it rather than trying to test it.
- When writing HL7 MSH, MSH-2 encoding characters are structure (write raw) while MSH-4/MSH-6
  are facilities; swapping them into MSH-3/MSH-5 produces a mapper mismatch that only an
  end-to-end writer→parser→mapper test reveals.
- A parser that decodes before splitting repetitions turns an escaped `\R\` into a false
  repetition; split on the raw separator first, then decode each leaf.
