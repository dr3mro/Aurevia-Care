## Summary

Replaced the process-local `@Repository` `InMemoryMessagingGovernanceStore` with
a PostgreSQL adapter behind the unchanged `MessagingGovernanceStore` interface.
`V62__messaging_governance.sql` adds eleven tenant-owned tables (audit event,
retention policy, resource, retention duty, legal hold, record-access policy,
connection, provenance link, export, copy request, revocation effect), each with
`organization_id`, `created_at`, forced RLS, a `public.app_org()` policy and
explicit grants. Append-only ledgers also carry reject-mutation triggers.
`JdbcMessagingGovernanceStore` implements all 26 interface methods through the
tenant-guarded `TransactionTemplate` with parameterised SQL, reusing the
authoritative V4 membership/role folds. The in-memory adapter lost `@Repository`
and moved to `src/test` with the same package, so both existing unit test files
compile unchanged and Spring sees exactly one store bean.

## Data changes

`V62__messaging_governance.sql` is additive (`-- Change: expand`) and uses only
the reserved version V62. Eleven empty tables; no backfill, no edit to any
existing migration. Lock/volume impact is negligible. Row-level isolation and
grant details are in the migration header. Migration order is last under both
`sort -V` and Flyway numeric order, so `organization`, `public.app_org()` and
`public.reject_immutable_mutation()` all exist first. The tagged test creates and
drops its own `orevia_governance_it` database.

## Authorization boundaries and audit events

Every adapter method runs inside the shared tenant-guarded `TransactionTemplate`,
which binds `app.current_org` and `app.actor` transaction-locally before SQL.
Reads name the active organization explicitly and rely on forced RLS; writes
carry the method's `organizationId` so `WITH CHECK` fails closed on mismatch
(proved for retention policies, connections and audit facts). No authorization
decision changed: `MessagingGovernanceService` still re-checks membership and
roles on every request through the authoritative fold. No audit event type was
added or changed.

## Migration and rollout considerations

Runtime-written current-state tables (retention policy, duty, legal hold,
record-access policy, connection) use `ON CONFLICT DO UPDATE` and therefore hold
the UPDATE grant. Exports are append-only (`DO NOTHING`, INSERT-only grant) so a
duplicate id cannot rewrite an OPS-07 record. The resource reference is
SELECT-only: V62 seeds no rows, so an authorized setup path must populate it
before hold and retention commands can act (Finding 3). Forward/rollback: a
later contract removing a table must point at an earlier `Change: expand` per
`docs/decisions/0002`.

## Findings

1. **`bash scripts/worker-check.sh` and the full tooling test suite are red on a
   known false positive, not a defect of this change** (tool): `check-pack`
   reports a stale `opencode.json`. Verified `git ls-files -v opencode.json` →
   `S` (skip-worktree) and `git diff HEAD -- opencode.json` empty: the committed
   profile is unchanged and the worktree holds the CI profile. This is
   OPS-CW-003-01, already documented in `MEMORY.md` and the READY-37 notes. The
   protected file was not edited; all later gates were run individually and are
   green.
2. **`scripts/wiring-baseline.json` has two now-stale entries** (tool +
   simulated reviewer): `inmemory-in-main` for `InMemoryMessagingGovernanceStore`
   and `store-without-durable` for `MessagingGovernanceStore`. `check-wiring.py`
   exits 0 and only prints notes; the baseline file is protected `scripts/` and
   outside this story's scope, so it was not edited. The integrator/owner should
   delete those two lines (baseline may only shrink).
3. **`messaging_resource` has no production writer** (tool): V62 grants SELECT
   only, following the V61 precedent, and the interface has no
   `putResource` method. `placeHold`, `retentionDecision` and `applyRetention`
   cannot work end-to-end until an authorized setup path seeds resources. The
   integration test seeds them through the owner connection. Out of scope here;
   flagged for the owning product story.
4. **No HTTP-level integration test or OpenAPI contract entry for governance**
   was found (tool). The controller exists at `/api/v1/messaging-governance`
   with a mocked unit test, but this persistence story proves only the store
   boundary end-to-end. Recorded as a pre-existing gap, not claimed as done.
5. **Exports are append-only** (simulated reviewer finding F1, tool-verified):
   `putExport` uses `DO NOTHING` rather than the in-memory `Map.put` overwrite,
   and the table has no UPDATE grant plus a reject-mutation trigger. No
   production path re-uses an export id, so no observable semantic change;
   this is deliberate OPS-07 hardening.
6. **Guard triggers for legal-hold release and connection revocation**
   (simulated reviewer F3) were not added: they would introduce new SQL
   functions with negative test obligations outside this story's bounded scope.
   Flagged as a follow-up hardening story.
7. **Two defects found and fixed before the first test run** (tool): the
   `legalHold` SQL bound `:holdId` while the statement used `:id`, and
   `addConnection` would pass null into `OffsetDateTime.ofInstant` for an active
   connection. Both are now covered by the round-trip tests.
8. **Initial test-order coupling** (tool): the immutability test's un-deletable
   seed rows made two whole-table list assertions order-dependent on the first
   run (`expected 2 but was 3`, `expected [copyA] but was [seed, copyA]`). Fixed
   with `contains`/`containsAll` and index-based ordering assertions; no
   threshold, exclusion or skip was added.

## Lessons for workers

- `worker-check.sh` fails at `check-pack` in cloud workers because the CI
  `opencode.json` sits under `skip-worktree`. Confirm with `git ls-files -v` and
  an empty `git diff HEAD -- opencode.json`, then run the later stages
  individually (frontend, SpotBugs, targeted integration, `db/check.sh`,
  policy scripts). Do not edit the protected file.
- Prove per-class 100% coverage with the targeted tagged test plus
  `mvn -Pno-security jacoco:report` and read `jacoco.xml`; do not run the
  ten-minute full verify as a worker.
- When replacing a seeded in-memory fake, move it to `src/test` with the **same**
  package so existing tests compile unchanged, and remove `@Repository` in the
  same commit as the new bean to avoid `NoUniqueBeanDefinitionException`.
- Integration tests sharing one database must use order-independent assertions
  (`contains`, `indexOf`) because append-only seed rows cannot be deleted.
- `check-wiring.py` baseline shrinkage is an integrator/owner task; a worker
  must not edit `scripts/wiring-baseline.json`.
