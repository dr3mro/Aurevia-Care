## Lessons for workers

- The `organization` table is RLS-protected too: set `app.current_org` before
  seeding every tenant row, even when connecting as the owner, because FORCE RLS
  applies to the owner.
- Trust the specification's name list, not a brief's count; enumerate the clause
  names and map each one before choosing a status.
- In this cloud worker, when `check-pack.py` reports a stale `opencode.json`,
  verify `git ls-files -v` and the HEAD render once, then run the remaining gate
  stages individually instead of editing the protected generated file.
- When a task file still asks for `@Disabled("GAP: ...")` but AGENTS.md and
  `check-constraints.py` forbid it, keep the proof green with an enabled
  characterization assertion, get the plan reviewer to ratify the waiver and
  record it in the doc and notes; a new disabled line fails the gate.
