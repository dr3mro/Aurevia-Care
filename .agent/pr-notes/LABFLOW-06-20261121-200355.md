# LABFLOW-06 — Staff web: collection desk (find order, verify patient and accession, record collection, print labels)

## Summary

Built a self-contained collection desk in `apps/staff-web/src/features/labcollection`
following `docs/design/screen-recipe.md` and the `features/scheduling` conventions.
A collector can find an order by accession or patient, complete a two-name plus
accession identity check, record specimen details, print a required-field label
sheet, or reject a specimen with a bounded reason. All data is synthetic and no
dependency was added. No file outside the declared scope was edited.

Files added (all under `apps/staff-web/src/features/labcollection`):
`domain.ts`, `api.ts`, `messages.ts`, `fixtures.ts`, `FindOrderPanel.tsx`,
`IdentityVerification.tsx`, `CollectionForm.tsx`, `RejectionForm.tsx`,
`LabelSheet.tsx`, `CollectionDeskScreen.tsx`, `CollectionDeskPage.tsx`, `routes.ts`,
plus six `*.test.ts(x)` files.

## Affected requirements

| Requirement | Mapping | Evidence |
|---|---|---|
| LAB-01 | Find an accession; issuer-scoped accession + patient match at collection; record specimen type, site, collector, time and quality; print label data (accession, patient name/identifier, specimen type, collection time); rejection retains a bounded reason and `other` detail | `domain.ts` (`checkMatch`, `findOrders`, `validateRejection`, `labelRows`), `api.ts` (`listAccessions`, `collectSpecimen`, `readLabel`, `rejectSpecimen`), `LabelSheet.tsx`; mirrors the LABFLOW-01/02 backend endpoints |
| WEB-09 | Loading, empty, error (with correlation id), timeout/offline, forbidden, stale-version conflict and session-expired states; conflict keeps typed work; unsaved drafts cleared on order/tenant change | `CollectionDeskPage.tsx` via shared `StateViews`; `CollectionDeskPage.test.tsx` state test block; `CollectionDeskScreen.test.tsx` reset test |
| UX-01 (supporting) | English and Arabic, RTL, both name forms, isolated identifiers, logical properties | `messages.ts`, every component test's Arabic case, `components.test.tsx` RTL checks |

The two-name check is the explicit display of both the Latin and local-script
patient name (`IdentityVerification.tsx`) plus the issuer-scoped accession and
patient identifier; the collector must confirm both names and the accession and
the entered identifiers must match before any command control is enabled.

output plus a simulated senior React review; **no real clinician, patient or
human participant** was involved and no clinical sign-off is claimed.

`readLabel` and `rejectSpecimen` send `X-Active-Organization` from
`useActiveOrganization()`; collection/rejection carry `If-Match`/idempotency

bedside match and OPS-02 audit rows remain owned by the LABFLOW-01/02 API.
No patient data is placed in a URL, page title or browser storage.

   - **F1 tenant isolation (fixed):** `CollectionDeskPage` held accumulated pages without an owner, so the frame after an organization switch could paint the old tenant's rows under the new tenant id. Pages now carry `organizationId`; `loaded`/`selected`/error are derived during render and empty unless the owner matches. New deferred-response test `does not paint the previous tenant rows while the new tenant is still loading` observes the pending frame.
   - **F2 false success announcement (fixed):** the screen announced "Collection recorded"/"Specimen rejected" immediately after a `void` callback even when the command failed. The page now owns `statusMessage` and sets it only after an awaited success, clearing it on failure/selection/tenant change. Conflict tests assert the success text is absent.
   - **F3 missing POST headers (fixed):** the cross-cutting contract requires both `Idempotency-Key` and `If-Match` on protected POSTs. `collectSpecimen` now sends both; `rejectSpecimen` now sends both. API and page tests assert both headers. Note: the idempotency key is minted per API call; the shared transport never retries writes (GET only), so there is no retry path that reuses an old key.
   - **F4 two-name check limited by the API projection (open, out of scope):** the authoritative `LabAccession` schema has no patient-name fields, so `toCollectionOrder` can only show the opaque patient id as the Latin form and has no local-script name in live use. The component and screen tests inject both name forms, so 100% coverage does not prove the two-name display through the real HTTP entry point. Documented rather than claimed; a contract/backend task is requested below.
   - **F5 accessibility (fixed):** the `other` detail error is now attached to its field through `FormField.error` (`aria-invalid`/`aria-describedby`), and the `role="alert"` summary is gated by a `touched` flag so a pristine form announces nothing. Only one live region fires per error case.
   - **F6 keyboard test (improved):** the test now focuses the input and the native submit button and asserts an observable submitted-query status. jsdom does not synthesise a button's Enter activation, so the click is explicitly the DOM stand-in; this limit is recorded rather than hidden.

## Lessons for workers

- When a new staff-web feature adds `messages.ts`, the shared `tests/messageParity.test.ts` registry must be updated in the same change; it is outside every feature's declared scope, so plan a paired task or an owner edit.
- `gen:api:check` can be red at HEAD when a contract path is published without regenerating `src/api/generated/openapi.d.ts`; confirm drift by regenerating to a temp file and check `git status` before attributing it to your change.
- In a collection/verification screen, a guard reachable only in tests (e.g. `if (selected === undefined) return` under a button that is only rendered when selected exists) is dead production code: use the render invariant plus a non-null assertion instead of leaving an uncovered branch.
- Orders surfaced through a search panel do not render patient text on first load; use the screen heading (`collectionDesk`) as the async readiness signal in page tests, not a patient value.
