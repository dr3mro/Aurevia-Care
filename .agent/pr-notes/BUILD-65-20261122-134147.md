# BUILD-65 — Cross-cutting scenarios and the first implementation slice, end to end

## Summary

Added a new test-only package `apps/api/src/test/java/com/aurevia/smartclinic/acceptance/scenarios`
with one shared synthetic fixture helper and six acceptance test classes (12 tests). No production
source, contract, migration, script or tracker file was changed. All data is synthetic (two clinic
organizations, one partner laboratory, fabricated subjects/patients).

- `ScenarioSupport.java` — synthetic org/subject constants and tenant-context helpers.
- `FirstImplementationSliceAcceptanceTest.java` — one end-to-end test: staff membership (invite),
  site-verified patient registration, booked-appointment identity check-in, one signed/fingerprinted
  laboratory order to the partner lab, specimen collection, result verification, correction,
  clinician acknowledgment, approved patient release, and cross-clinic concealment.
- `MissedCoverageScenarioAcceptanceTest.java` — deadline escalation to a staffed on-call backup,
  attempt receipt/owner/deadline facts, primary/backup channel gates, delivery vs. acknowledgment.
- `RetractedDocumentScenarioAcceptanceTest.java` — withdrawn revision stops portal access while the
  issued-disclosure audit history remains; correction notifies only the original recipient list.
- `PatientContactsTwoUnitsScenarioAcceptanceTest.java` — two verified unit connections, separate
  threads, PDF shared with one unit only, verified instruction from the other unit, cross-unit denial.
- `FailedExchangeAfterCommitScenarioAcceptanceTest.java` — committed state survives a fresh service
  instance (simulated process loss); replay yields one effect; payload conflict; one clinical task
  per correction revision.
- `PatientLinkageDisputeScenarioAcceptanceTest.java` — privacy-officer review of other associations,
  step-up link suspension, new-download recheck, independent association and audit survive; support
  channel resolution.

## Findings

- Pre-existing defect — FIXED in coverage-check repair attempt 1: `apps/api/src/test/java/com/aurevia/smartclinic/tenant/retention/OffboardingCommandTest.java`
  called `new ExportRecord(...)` with 6 arguments; the record in
  `apps/api/src/main/java/com/aurevia/smartclinic/messaging/governance/MessagingAuditContract.java:295`
  requires 7 (`ExportProvenance provenance`). This broke `mvn test-compile` module-wide. All four call
  sites now pass a synthetic `PROVENANCE` constant; the targeted test and the full coverage check both
  pass (see Coverage above). No production code changed.
- Pre-existing committed conflict markers (outside scope, NOT fixed): Javadoc text in
  `apps/api/src/main/java/com/aurevia/smartclinic/exchange/hl7/Hl7ParseException.java`,
  `Hl7Parser.java`, `Hl7Segment.java` contains `<<<<<<<`/`=======`/`>>>>>>>` inside comments.
  They do not break compilation but `git grep -nE '^(<<<<<<<|>>>>>>>) '` reports them.
- Multi-chart patient enrollment: `PatientAccessService.enroll` creates a NEW account per invitation,
  so a second enrollment does not add a link. My linkage test seeds one account with two verified
  links via `InMemoryPatientAccessStore.putAccount` (a legitimate fixture), then exercises the real
  service commands. A next worker needing multi-link scenarios should do the same.
- `CareUnitDirectoryService.connect` and `ReleasedReportService` require a bound `TenantContext` even
  with in-memory fakes; bind before driving them.

## Lessons for workers

- When a sibling test at HEAD breaks `mvn test-compile`, do not conclude your change is broken:
  validate with `javac -sourcepath apps/api/src/test/java` plus the JUnit console launcher, and record
  the pre-existing failure. If you temporarily patch the sibling for a Maven run, restore it
  byte-for-byte and prove `git diff` on it is empty before committing.
- In-memory fakes (`InMemoryMessagingStore`, `InMemoryAttachmentStore`, `InMemoryInstructionFactStore`)
  live under `src/test`, so manual `javac` needs `-sourcepath apps/api/src/test/java`.
- `check-pack`/`worker-check.sh` staleness in a cloud worker is the skip-worktree CI profile, not HEAD
  truth; confirm with `git ls-files -v opencode.json`.

## Why this is not finished

The six test classes and all 12 tests are green, but a few acceptance sub-points from section 11
could not be proven inside this API test-only scope and are recorded here as gaps rather than faked:

1. "Approved release visible to the patient through **both patient mobile platforms**": the API test
   proves the patient portal endpoint serves the released revision. Walking the two native platforms
   requires `apps/patient-mobile` UI tests (`bash apps/patient-mobile/check.sh`), outside this task's
   scope. Next step: add a mobile acceptance slice that opens the same synthetic released report on
   iOS and Android.
2. "Outbound correction tasks ... **expose failed deliveries**" (retracted document): the test proves
   correction notifies the original recipient list, but not a failed-delivery attempt surfaced through
   an outbox/review queue. Needs a delivery-attempt fixture and an assertion on the failed-attempt view.
3. "**In-flight reads** and new downloads recheck link status" (linkage dispute): the new-download
   recheck is proven; a read already in progress at the moment of suspension would need a concurrency
   harness and is not asserted.
4. "No result is silently reassigned to an **unstaffed queue**" (missed coverage): the test proves the
   staffed on-call recipient and the primary/backup channel gates. No production configuration path
   for an unstaffed queue was available to assert against, so that negative case is not covered.
5. Physical survival "after process loss" is simulated by replaying against a fresh service instance
   over the same repository; actual restart durability is owned by the database integration suite
   (integrator), which I did not run.
6. The required full worker gate and 100% JaCoCo gate could not be completed here because of the
   pre-existing HEAD defects and false positives listed above (out of scope). The integrator must run
   them after those are resolved.
