## Summary

Adds an API-level clause proof for XCH-01 clause 5 ("Sharing an order grants no general chart access.") and the matching clause document. The test drives the real `OrderService` through `OrderController` and the request interceptor with synthetic headers, proving that the receiver sees only the bounded `WorkItemView` projection, that a wrong role and an invisible sender order are refused, and that the opaque sender patient reference cannot be used as a chart key. No production code, existing test, contract, migration, dependency or tracker was changed.

XCH-01 (whole requirement read at `SMARTCLINIC_V1_SPEC.md:63`, section 4 at `:59`). Clause 5 only: "Sharing an order grants no general chart access."

## Lessons for workers

- For an isolated clause-proof test with no production change, assert the exact JSON key set (for example `aMapWithSize(15)` on a `WorkItemView`) as well as the released content values. A field-count guard alone catches a new chart column but not a silent substitution of an existing value.
- With standalone MockMvc around a real service, mock `TransactionTemplate` so its callback runs inline; the interceptor's `TenantContext` then stays bound for the service call. Clearing `TenantContext` in `@AfterEach` prevents cross-test leakage.
- Record fields with null components serialize as JSON null in this project (no `NON_NULL` inclusion rule), so a Hamcrest `nullValue()` assertion is the precise way to prove `localPatientId` is unset.
- When a repository mock stands in for PostgreSQL RLS, say so in the test and the clause doc, and cite the existing DB-backed integration test for the real enforcement. Wiring `ChartController` with a mocked `ChartService` would only exercise the stub, not the tenant-scoped chart query.
- The six `test_check_pack` failures are environmental in this worker image. Confirm `git ls-files -v opencode.json` once, record the command and final line, run the other gate stages individually, and never regenerate or commit `opencode.json`.
