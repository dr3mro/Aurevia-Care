## Findings

- **Export HTTP adapter is defective at HEAD.** `TenantExportService.start/download/expire` do not open a `TenantGuardTransactionManager` transaction. In the first red run every export HTTP command that reached the service returned 500 (missing-subject/missing-organization requests were still refused 401/422 by the interceptor): `audit_event` insert violated forced RLS (`new row violates row-level security policy for table "audit_event"`) at `TenantExportService.authorize:189`, preceded by an empty membership/role fold. `PlatformAcceptanceTest.java:470-473` already flags the HTTP download caveat; the new clause note records it as Gap 1. Out of scope here (no production code allowed).
- **Export timestamp parse defect.** `JdbcExportStore.mapJob` uses `ResultSet.getString("expires_at")`, which PostgreSQL returns as `2026-11-24 02:06:52.799497+00`; `ExportJob.expired()` calls `Instant.parse` and throws `DateTimeParseException` for a `COMPLETE` job loaded from the database. The positive test therefore proves isolation at the store/object boundary. Recorded as Gap 2.
- **Stale gate document.** `docs/gates/g0-isolation-surfaces.md:43` still says "Tenant export | No" and describes a disabled `/api/v1/tenant-exports` test. HEAD has `ExportController`, `TenantExportService`, `JdbcExportStore`, `ExportPermissionGuard` and `V89__tenant_export.sql`. The stale document was read but not edited (out of scope) and its obsolete route was not copied.
- **OpenAPI parity absent.** `contracts/openapi.yaml` has no `/api/v1/tenant/exports` operations; they are baselined in `contracts/openapi/missing-routes.txt:116,333,334`. No parity is claimed in the note. Gap 3.
- **Pre-existing conflict markers in HEAD (not from this change).** `git grep -nE '^(<<<<<<<|>>>>>>>) '` finds markers committed in `apps/api/src/main/java/com/aurevia/smartclinic/exchange/hl7/{Hl7ParseException,Hl7Parser,Hl7Segment}.java` at HEAD (inside Javadoc comments). `git merge --no-edit origin/main` was `Already up to date`; the working tree is clean. Left untouched because it is outside this task's scope; the integrator should route it.
- **Plan review.** The first `smartclinic-plan-reviewer` verdict was NO-GO with Required items (export seeding mechanism, mandatory worker-check, no OpenAPI parity claim, merge reconciliation). All were addressed: seeding uses `ObjectStorePort` + `TenantGuardTransactionManager`; worker-check was run and the OPS-CW-003-01 artifact verified; parity is not claimed; `git merge --no-edit origin/main` was run at start and after coding. Status is `Partly proven` per the attachment sub-gap.

## Lessons for workers

- Before writing an HTTP test for an existing route, run it once against HEAD: a `200`-only assumption hid two latent export defects (missing guarded transaction and non-ISO `expires_at`). Reading the controller is not enough — check that the service opens a guarded transaction before its repository/audit calls.
- `docs/gates/*.md` can lag production by several stories. Verify route and class existence at HEAD before trusting a "Not built" claim, and never copy a disabled test's obsolete route.
- In a cloud worker, a `test_check_pack` failure accompanied by `git ls-files -v opencode.json` = `S` and a worktree file equal to `.github/opencode.ci.json` is OPS-CW-003-01: record it once, run the remaining gate stages individually, and never regenerate the file.
- Use a dedicated disposable database name in parallel-worker runs; reuse of the neighbour's `smartclinic_isolation_surfaces_it` would let another worker drop the fixtures mid-test.
- A `@Disabled` GAP is story-mandated but rejected by `scripts/check-constraints.py`. When the surface exists but is defective, prove what can be proven at the durable boundary, record the defect under `## Gap` and use `task-requests` instead of skipping.
