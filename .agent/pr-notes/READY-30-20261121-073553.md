# READY-30 — Finance: `/finance` invoices with issue, payment, refund and void

## Summary

Added the self-registering finance feature under `apps/staff-web/src/features/finance`. It provides integer-minor-unit money helpers, an API client for every finance endpoint named in the story, a status-filtered cursor-paged invoice list, an invoice detail screen with itemized lines, balance and linked payment/refund/credit ledger, and issue/payment/refund/credit/void commands. Refund, credit and void require a reason and an independent approver id; void is additionally withheld once the invoice has a ledger trail, matching the server's `VOID_AFTER_POSTING` guard. The payment form keeps one `Idempotency-Key` across failed retries of the same payment. Instants use `formatInstant(..., 'UTC', locale)`; row links carry the invoice id in their accessible name; failed validation moves focus to one live summary. Routes `/finance` and `/finance/:id` self-register via `features/finance/routes.ts`. All data is synthetic; no dependency, migration, OpenAPI file or file outside the feature folder was changed.

## Affected requirements

- **FIN-01** — integer minor units with one currency per invoice; draft/issued/partially_paid/paid/void states; linked immutable payment, refund and credit entries with reason and approval; stable payment reference/idempotency; balance shown from the API; finance-only fields with no clinical narrative.
- **PRD-04** — self-pay invoices, payments, refunds and receipts; no claims adjudication, payer integration, card data or accounting ledger.
- Route registration follows READY-51 (`features/<name>/routes.ts` exporting `routes: AppRoute[]`); `app/routes.tsx` and `app/navigation.ts` were not touched.

## Authorization boundaries and audit events

The active organization comes only from `useActiveOrganization()` (`X-Active-Organization` via the shared request builder); every API descriptor carries it. Invoice ids are opaque and encoded with `encodeURIComponent` before being placed in a command path or a `/finance/:id` link; no patient name, reason, approver id, reference or money value goes into a URL, page title, log or browser storage. Authorization, replay deduplication, approval invariants and audit remain server-side (`FinanceService`/`FinanceActions`); this slice adds no audit event and does not duplicate those checks. The UI's action table mirrors the server lifecycle so it never offers a command the API would reject on state grounds.

## Migration and rollout considerations

None for this code-only slice. The generated OpenAPI client publishes only `GET /api/v1/finance/invoices`; as the scheduling feature already does, sub-path descriptors reuse the shared builder and substitute only the URL, so no contract file needed editing inside this scope. `createInvoice` and `getReconciliation` are implemented and unit-tested because the story lists those endpoints, but no screen for them is part of this story.

## Lessons for workers

- When a story requires adding a self-registering feature route, check `src/app/routes.test.tsx` and `tests/app/AppShell.test.tsx` first: both hard-code the full registry, so a new feature route is a scheduled test update for the owner of those files, not an optional cleanup.
- Form field labels must be unique across every form that can be on screen at once; duplicate labels appear only when an invoice reaches a state that renders multiple command forms.
- `Intl.NumberFormat`'s `maximumFractionDigits` is typed optional even for currency style; a non-null assertion with a rationale comment is needed under strict TypeScript, and mocked `crypto.randomUUID()` values must be UUID-shaped because its return type is a template literal type.
- The shared `Link` in `src/app/router.tsx` forwards only `to`/`children`/`target`/`ariaCurrent`; a hyphenated `aria-label` prop typechecks but is silently dropped. Put distinguishing identity in the link text instead.
- A void is not a pure lifecycle question: a fully refunded invoice returns to `issued` but keeps its ledger, and the server then rejects void. Gate destructive UI on both state and ledger contents.
