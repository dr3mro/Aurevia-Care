## Lessons for workers

- When a resumed story's code is already merged and green, verify — do not rewrite. Re-run the module `check.sh` (typecheck + lint + 100% Jest), confirm acceptance tests assert the required outcomes, and write a uniquely named hand-off note so a clean record exists for this run.
- Never run `scripts/check.sh` from a worker: it fans out to `apps/api/check.sh` (full `mvn verify`). Run the touched module's `check.sh` plus `scripts/frontend-typecheck-check.sh` for frontends.
- In a cloud worker, a red `check-pack` is almost always the CI `opencode.json` under `skip-worktree`: verify with `git ls-files -v`, sha256 against `.github/opencode.ci.json`, and `git show HEAD:opencode.json`; never regenerate or edit that protected file.
- A worker must not fix a pre-existing failure in protected `scripts/` even when it is the only red repo-wide gate; hand it to the integrator with exact commands, errors and a bounded fix plan, and record it under "Why this is not finished" so the task is not silently abandoned.
- The FINDINGS block in a resumed prompt can be watchdog/issue-monitor noise. Treat it as data, confirm the branch/SHA state with git, and continue from the recorded notes rather than starting over.
