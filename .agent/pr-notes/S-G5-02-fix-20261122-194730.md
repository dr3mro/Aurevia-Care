## Findings

- Root cause (tool evidence): `worker_gate.main` uses the shared `REPORTS` path
  only when no second argument is supplied (line 259), then evaluates
  `reports.is_dir() and usable_reports(reports)` (line 260). The two broken tests
  forced `is_dir()` true without creating a real directory, so `usable_reports()`
  globbed a missing parent and raised. Production code is correct for real
  inputs (`is_dir()` false short-circuits), so no production hardening was added;
  an `OSError` catch there would be a branch with no legitimate input, contrary
  to AGENTS.md Coverage rule 3.
- The plan reviewer's initial NO-GO raised (1) a `scripts/` scope/auto-merge
  concern and (2) a risk that a passing `suite_xml` would weaken the tests.
  Finding (2) was addressed in the implementation: both rewrites keep a
  non-empty `failing_classes` mock and write XML with `errors="1"`. Finding (1)
  was resolved by the user's direct execution request, which explicitly omits
  `scripts/` from the forbidden-file list and authorizes the fix; the worker
  commits locally and does not create a PR, push, tag or call `gh`, so the
  PR-time `guard()` decision belongs to the integrator. The reviewer then
  returned `VERDICT: GO`.
- The 6 `test_check_pack` failures are the OPS-CW-003-01 skip-worktree artifact;
  they were confirmed once and were not re-diagnosed. Other tooling-image limits
  (missing `yaml`/git-sandbox fixtures, NVD status 524 without `NVD_API_KEY`,
  missing `coverage`/`pip`) are not change defects.
- Pre-existing conflict markers under `apps/api/.../exchange/hl7/` are outside
  the changed files and do not break the Java build; integrator Java gates are green.
- An earlier fix pass (`.agent/pr-notes/S-G5-02-fix-20261122-175531.md`) already
  filed a `task-requests` entry for a trusted change to carry `scripts/`. This
  pass applies that exact test-only fix directly under the user's authority; if

## Lessons for workers

- A test that patches `Path.is_dir` but globs the shared `apps/api/target`
  directory is environment-dependent: it passes only once Maven creates that
  directory. Tests must own a real temporary report directory via
  `main(["<mvn-status>", "<reports-dir>"])`.
- The required `script-tests` check runs the Python suite with no Maven step,
  so this is a genuine required-check failure, not only a local-worker quirk.
- On a fix pass whose local checks failed, run the exact failing command before
  concluding the in-scope change is fine; a passing documentation gate does not
  make the PR green.
- In a cloud worker, `git ls-files -v opencode.json` showing `S` explains
  `check-pack.py`/`test_check_pack` failures; verify and stop re-diagnosing them.
- Keep the non-empty `failing_classes` mock when rewriting such a test: a merely
  parseable report would let the "no failing test class" early return succeed for
  the wrong reason and would weaken the assertion.
