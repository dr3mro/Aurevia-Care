## Summary

Added a self-contained lab/imaging requisition-print feature under `apps/staff-web/src/features/print/orders`. `PrintOrderButton` is the exported entry point. It refuses drafts with a worded reason, opens a preview that renders the requisition sheet(s) as accessible HTML, lets the clinician choose one combined sheet or one sheet per order, and hands the chosen sheets, audit reason and language to the owning screen through `onPrint`. The sheet shows the tests or study, clinical question, priority, preparation instructions, where to go and a barcode-free human-readable order number (`ORD-<id>`) isolated as an LTR run. English and Arabic are supported; the interface locale drives controls and the chosen handout language drives the sheet.

No dependencies were added and no file outside the story scope was changed. No real patient data, identifiers or credentials are used; all fixtures are synthetic.

## Affected requirements

- LAB-01: requisition/accession identity shown as a human-readable order number; preparation text on the sheet.
- RAD-01: imaging study, clinical question, urgency and where-to-go on the sheet; drafts refused.
- WEB-09: loading/refusal semantics, worded reasons, keyboard Escape and focus restoration, bilingual resilient preview.

## Authorization boundaries and audit events

The component performs no authorization decision of its own: it receives already-scoped orders and delegates the print to `onPrint`, which the owning screen uses to record the existing PRINT-02 audit (who/what/version/why/when, never content). Reason choices reuse the shared print vocabulary (`give-to-patient`, `referral`, `patient-request`) so the audit reason stays consistent with `features/print/components`. The tenant scope of the orders remains the caller's responsibility; this component does not infer or widen it.

## Findings

- The shared `PrintPreviewDialog` only accepts a PDF `documentUrl`, so it cannot display structured, assertion-visible requisition text. This feature renders the sheet as React HTML in its own preview and injects the shared A4 `printStylesheet`; each sheet carries `data-print-handout="true"` and controls carry `data-print-controls`, so browser printing keeps the sheet and hides the chrome.
- The bilingual dictionary is named `labels.ts`, following the established `apps/staff-web/src/features/radworklist/labels.ts` precedent. A file named `messages.ts` would be auto-discovered by `tests/messageParity.test.ts` and require registering a new bundle in that out-of-scope test. The local `labels.test.ts` enforces the same key-parity, non-empty and Arabic-letter rules, so no compliance check was weakened.
- Pre-existing, out-of-scope gates block the wrapper scripts: generated OpenAPI client drift (`gen:api:check`) and duplicate migration version V91 (`scripts/check.sh`). See Test evidence for exact commands and counts.
- Simulated senior-React review (advisory subagent) returned no acceptance-blocking defect and five findings, all resolved in scope: (1) MEDIUM — the sheet inherited `document.dir` from the UI locale, so an Arabic handout in an English interface was laid out LTR; fixed with `dir`/`lang` on the sheet and direction assertions in both locales. (2) MEDIUM — `aria-modal` without a focus trap; the existing keydown handler now wraps Tab/Shift+Tab among the dialog's own controls, with a dedicated test covering wrap-forward, wrap-backward, middle and outside-focus cases. (3) LOW — reason error not associated with its control; the alert now has a `useId`-based id referenced by the reason fieldset's `aria-describedby` and focus moves to the first reason radio. (4) LOW — fixed DOM ids collided across instances; the language select and error id use `useId`, and the injected print stylesheet uses a data attribute instead of the shared id. (5) LOW — handout language seeded once from the locale; reopening now reseeds from the current interface locale, with a test. All fixes kept 100% coverage (54 targeted tests, 1321 full-suite tests).

## Lessons for workers

- Count index metadata as `S` before believing a stale `opencode.json`: the worktree copy is the CI profile under `skip-worktree`; compare with `.github/opencode.ci.json` and `git show HEAD:opencode.json`, restore bytes byte-for-byte after any temporary swap.
- A new `messages.ts` anywhere under `src` breaks the global message-bundle registry test; a feature-owned `labels.ts` with its own parity test is the in-repo pattern when the registry file is outside scope.
- Per-file 100% Vitest coverage is achievable with small pure helpers (`domain.ts`) and explicit tests for both sides of `&&` and ternaries; keep effect branches deterministic (focus a known opener, dispatch Escape and a non-Escape key).
- A handout rendered as HTML is its own document: set `dir`/`lang` from the chosen handout language, not the surrounding UI locale. An `aria-modal` dialog must trap Tab, not just Escape and initial focus.
