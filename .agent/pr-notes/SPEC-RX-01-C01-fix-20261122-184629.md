## Lessons for workers

- On a "did not finish cleanly" fix attempt with no failing check, verify the committed work is actually broken before rewriting: re-run the focused `-Dtest=...` integration test, read the Surefire header (`skipped="0"`), then run each gate stage individually. Green work usually means the earlier run ended before emitting its completion signal.
- Check `scripts/check-constraints.py` against a new test file before designing a GAP placeholder: a new `@Disabled("GAP: …")` is rejected even though older stories used one. An enabled characterization test that asserts the missing field is absent, plus an honest `Partly proven` doc and a `task-requests` block, proves the gap and keeps every gate green.
- Never add `fast` to a targeted `-Dgroups=integration` Maven run: `excludedGroups=integration` in the `fast` profile wins and gives a vacuous green. Always read the Surefire XML and require `tests=N, skipped=0`.
- In a cloud worker, `check-pack.py`, `worker-check.sh` and the Python tooling suite can stop at the stale CI-profile `opencode.json` (`git ls-files -v` -> `S`). Confirm once, run the remaining stages individually, and never regenerate or commit that protected file.
- A bare `spotbugs:check` is vacuously green without compiled classes: always run `compile spotbugs:check` together, and record the plugin version and finding count.
