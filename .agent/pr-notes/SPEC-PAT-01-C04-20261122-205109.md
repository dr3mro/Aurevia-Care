## Lessons for workers

- A clause-proof task over an already-built domain needs no TDD red run: the proof passes
  against existing production code, and the red-run discipline applies only when production
  behavior changes. Still verify the new suite is actually discovered (targeted Jest run),
  because the full coverage-mode summary prints only aggregate counts.
- Before writing a clause note, check `python3 -I scripts/check-docs.py`'s prefix rule: an ID
  such as PAT-01 that is not a defined prefix is not flagged, but links must resolve; safer to
  cite paths in backticks (as the sibling clause notes do) than to add relative Markdown links.
- In a cloud worker, `check-docs.py` skips `.agent/` notes, but the PR template's Test evidence,
  Coverage and Review verdicts sections are still required; populate them from captured command
  output, not memory.
