# RESP-DATATABLE — Staff web: responsive `DataTable` component

## Summary

Made the shared staff-web `DataTable` responsive at every supported width without
changing its behaviour, text, API or exported names. The real `<table>`, its
`<caption>` and every `<th scope="col">` are rendered identically at all three
breakpoints, so no clinical column is added, removed or dropped. On compact
phones the table is wrapped in the existing `.table-region` class with
`role="region"`, `aria-label={caption}` and `tabIndex={0}`, giving a labelled,
keyboard-scrollable region that keeps the page free of horizontal scroll. Medium
tablets and expanded desktops keep the bare table. Header and value cells carry
logical inline wrapping (`minInlineSize: 0`, `overflowWrap: anywhere`,
`whiteSpace: normal`) so long English and Arabic strings wrap instead of clipping
or overlapping, including at 200% zoom. The component uses the existing
`useBreakpoint()` hook and the stylesheet's `.table-region` class; no CSS,
dependency or file outside the declared scope was changed.

## Affected requirements

- **WEB-07** — responsive staff web from 320 px; the DataTable is fully usable on
  phones via a labelled scroll region while retaining every table column and
  native table semantics.
- **UX-01** — WCAG 2.2 AA: labelled region with `role="region"`/`tabindex="0"`,
  native caption and column headers, logical properties only, no hidden
  clinical column, keyboard-reachable scroll region, text wrapping for long
  English and Arabic values, no fixed block size that would clip at 200% zoom.

sections 2, 5, 11–13; `docs/design/accessibility-patterns.md` sections 2 and 4;

## Findings

- **Pre-existing generated-client drift blocks `check.sh` at stage 1.**
  `contracts/openapi.yaml` contains printing handout routes that the checked-in
  `apps/staff-web/src/api/generated/openapi.d.ts` lacks. Regenerating the client
  or editing the contract is outside `RESP-DATATABLE` scope, so it was not done.
  All later check stages pass directly. The owning PRINT/RESP-MANIFEST work
  should regenerate `openapi.d.ts` so the canonical gate is green again.
- **Deferred reviewer observation (non-blocking):** at the medium breakpoint the
  table is returned bare rather than inside an overflow-aware region. This
  matches the story's "tablets and desktop keep the table" and the design
  contract's "region only when content overflows" (no overflow in the current
  two-column datasets; wrapping prevents page scroll). A future wide
  multi-column worklist routed through this component at 768–1279 px should add
  an overflow-aware region in its own story. Source: Senior React review of
  `DataTable.tsx:73-81` and `responsive.css:78-82`.
- Root `scripts/check.sh` is red for the known CI-profile `skip-worktree`
  artifact above; the committed HEAD `opencode.json` is the correct local profile
  and the pack gate is green on it. No worker action is appropriate.
- No production defect was found by the simulated Senior React reviewer.

## Lessons for workers

- When `bash apps/staff-web/check.sh` stops at `gen:api:check` on a parallel-worker
  contract update, do not regenerate or hand-edit the generated client inside a
  narrowly scoped story. Run typecheck, lint, build, bundle size and coverage
  directly and record the drift as an out-of-scope finding.
- A jsdom `matchMedia` stub must return one stable state object per query
  (so the hook's initializer and effect share listeners) and media-change fires
  must be wrapped in `act()` or React will not flush the re-render before the
  assertion.
- Symmetric CSS shorthands (`padding: 4px`, `border: 1px solid …`) are
  direction-neutral: do not assert that computed `paddingLeft` is empty when
  checking logical properties. Assert on the style attribute's declarations
  (`(?:margin|padding|border)-(?:left|right)`, `text-align: left|right`) instead.
- `responsive.css` has no `.clinical-value` class even though
  `docs/design/responsive-layout.md` section 12 shows one with
  `min-inline-size: 0; overflow-wrap: anywhere; white-space: normal`. Per the
  story rule against editing the stylesheet, I used those three logical inline
  styles on `th`/`td` instead. A follow-up story could add the class to
  `responsive.css` and its coverage test.
- The shell owns safe-area insets and coarse-pointer/field-font rules; a table
  primitive needs neither inputs nor controls, so those requirements are met by
  the existing `.page`/`.app-shell`, `.touch` and `.field` CSS rather than by
  local code.
- Write notes only to this file; it is the hand-off and pull-request description
  and is committed with the change.
