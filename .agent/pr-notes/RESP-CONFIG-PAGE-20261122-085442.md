# RESP-CONFIG-PAGE — Staff web: responsive `ConfigPage` (features-admin)

## Summary

Made `apps/staff-web/src/features/admin/ConfigPage.tsx` responsive at every
supported width using only the shared classes in `apps/staff-web/src/theme/responsive.css`
and the `useBreakpoint()` / `usePointerCoarse()` hooks. No new stylesheet, dependency,
behaviour, text, API call or exported name was added. Added a new jsdom test file that
mocks `matchMedia` at 320/360/390/768/820/1024/1280 px (compact/medium/expanded,
coarse and fine pointers) and at RTL, asserting structure, labels, roles, keyboard
order and the right-to-left case.

Changes in `ConfigPage.tsx`:
- Root gains `className="page"` plus `data-breakpoint` / `data-coarse-pointer`; the
  inline `display: grid` was removed so the shared `page` class owns the grid, the
  1200 px reading cap and the logical safe-area padding.
- Every section (lookup, catalog family, catalog definition, approval dialog) uses
  `className="stack"`; the single-field form wrappers use `stack`, and the three-field
  catalog definition wrapper uses `grid-2` (one column on phones, two from 768 px).
- Long catalog cell values use logical inline styles (`min-inline-size: 0`,
  `overflow-wrap: anywhere`) because `responsive.css` has no dedicated
  clinical-value/cell class.

All data in tests is synthetic (`Synthetic booking rule`, `facility.MAIN.booking`,
Arabic phrases); no patient data, real identifier or credential appears anywhere.

## Lessons for workers

- `.page` already owns the `minmax(0,1fr)` grid, the 1200 px reading cap and the
  logical safe-area padding; replace an inline `display: grid` with that class instead
  of duplicating layout rules, and expose `data-breakpoint` / `data-coarse-pointer`
  so jsdom can assert the band.
- A `<section aria-label>` (the `ApiPage` page wrapper) and the `AdminTableRegion` div
  can share an accessible name and both expose `role="region"`. Select the scrollable
  table region by `tabindex="0"` rather than `getByRole(..., { name })` alone.
- When mocking `send` for a lookup-then-catalog flow, give the history call a
  `mockResolvedValueOnce` (object) and the catalog list a `mockResolvedValue` (array);
  a default that returns a history object makes `entries.map` throw in `CatalogFamily`.
- Re-run `bash apps/staff-web/check.sh` at the start of a re-attempt on a fast-moving
  `main`: generated-client drift and sibling test counts change between runs.
