# SPEC-MSG-06-C06 — MSG-06 clause 6 (API test + enforcement), repair pass 1

## Summary

The previous pass documented an unbuilt clause with a class-level `GAP` `@Disabled`
test. `scripts/check-constraints.py` rejected that suppression. This repair removes
the suppression and fixes the cause: MSG-06 clause 6 is now implemented and the
HTTP proof runs enabled. `ServiceProfileService.publish` requires both the urgent
and downtime channel to be a member of the tenant's effective, named-approved
site policy before a draft is stored; a blank, absent or unapproved code is
refused with a structured `422 UNAPPROVED_CHANNEL` through the service's audited
denial path, with no durable row. The policy is read from the versioned
`config_entry`/`config_approval` fold through
`JdbcServiceProfileStore.approvedChannels`. The clause document now records
`Status: Proven by tests`. No migration, contract, dependency or workflow changed.

## Data changes

None. No Flyway migration, backfill, lock or volume impact. The rule reuses the

Existing tenants without a channel policy now fail closed on publish until a

## Authorization boundaries and audit events

`publish` keeps its existing context, active-membership, role, unit-existence and
stale-version checks before the new gate. The policy read is bound to the active
tenant twice: the tenant-guarded transaction sets the `app.current_org`/`app.actor`
GUCs and the SQL also names `organization_id` explicitly, so a stale context
yields an empty set and a denial. No new audit event type is introduced: the
existing `deny()` helper records `PROFILE_PUBLISH`/`DENIED` for the target unit;
a refused publish writes no `SUCCESS` audit and no `service_profile` row. Denial
messages use fixed field-name constants only. All fixtures are synthetic.

## Migration and rollout considerations

No migration. Two effective config entries per tenant (urgent and downtime
policy keys) are required before publish succeeds; both are seeded in each HTTP
fixture. Production deployment remains separately authorized.

## Lessons for workers

- When the gate flags a `GAP` `@Disabled` test, the durable fix is to implement the
  missing behavior and enable the test, not to argue for an exemption in notes.
  A skipped test can never be green evidence.
- Read config folds through the tenant-guarded transaction template; a plain
  `jdbc.query` sees no transaction-local `app.current_org` and would deny every
  publish under forced RLS.
- A full `{@link #method(...)}` self-link fails the Java conventions test because
  the prefix before `#` is empty. Use a fully qualified target or plain `{@code}`.
- Before changing publish semantics, enumerate every test that reaches the entry
  point and seed its policy fixture; otherwise legitimate new denials look like
  regressions.
