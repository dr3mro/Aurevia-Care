That test proves the next ARC-03 sentence ("Different payloads using the same key yield conflict"), which is task C07, and duplicates `IdempotencyLedgerTest.reusedKeyWithDifferentPayloadConflicts`. Per the story's "one positive + at least one negative" and the test-engineer Required finding, the new file has exactly two tests; the adjacent clause remains covered by the existing test.
- **Brief/story step 3 conflicts with the quality gate.** `@Disabled("GAP: ...")` is rejected by `scripts/check-constraints.py:56` for Java and forbidden by AGENTS.md. The clause is implemented at the contract layer, so a live green test plus a `Partly proven` status document is the honest proof; no disabled test was added.
- **No live maintainer was available** in this worker to confirm scope/entry point. The decision was made from tool evidence (grep: zero production callers of `IdempotencyLedger`; Javadoc calls it a non-durable stand-in) and recorded here rather than guessed.
- **GAP owner already exists.** Open task `READY-42` (depends on `READY-41`) owns the durable ledger and HTTP wiring; no duplicate task was filed for that work. Its scope includes `apps/api/src/test/java/com/aurevia/web`, the parent of the new test path — the orchestrator should check no concurrent READY-42 worker touches `web/clauses/`.
- **Semantics to reconcile.** READY-42's brief specifies 422 `IDEMPOTENCY_KEY_REUSED` and replay of a stored HTTP status/body, while this contract returns `Decision.CONFLICT` and an opaque outcome reference that the caller re-authorizes, concealing lapsed authorization with 404 `NOT_FOUND`.
