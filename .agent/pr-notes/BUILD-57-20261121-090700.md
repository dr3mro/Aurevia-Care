# BUILD-57 — Load test profile and report for the pilot size

## Summary

Added a dependency-free (Python standard library) synthetic OPS-03 pilot load
generator under `infra/loadtest`. It encodes the exact pilot profile, plans a
seeded 70/30 read/command workload over synthetic chart identifiers, issues it
on a fixed-rate schedule using a pool sized by the declared active-staff count,
and reports read and command p95 separately. It exits 0 on pass, 1 when read
p95 > 500 ms, command p95 > 900 ms or any request fails, and 2 for a
configuration error. The default target is loopback and only a `synthetic`
environment is accepted, so the tool never points at a real environment by
default. Ships with 60 tests, a build-failing 100% line-coverage gate, a
machine-readable profile artifact and a module README.

Files added (all inside scope `infra/loadtest`):
`load_generator.py`, `pilot-profile.json`, `README.md`, `check.sh`,
`tests/test_load_generator.py`, `tests/test_coverage_gate.py`,
`tests/run_coverage.py`, `tests/coverage_gate.py`.

## Affected requirements

- OPS-03 — pilot profile literals (20 orgs / 100,000 charts / 200 active staff /
  50 rps / 30 min) and p95 targets (reads <= 500 ms, commands <= 900 ms).
  Acceptance mapping: profile constants + `pilot-profile.json` (step 1–2),
  `plan_requests`/`run_load` with `workers=concurrent_staff` (step 2),
  `summarize`/`format_report` separate p95 + threshold exit codes (step 3),
  loopback/`synthetic`-only validation + `MainTest` against an ephemeral local
  fake server (step 4).

None. No migration, backfill, table or lock. Synthetic identifiers only

## Authorization boundaries and audit events

No tenant, role or patient-link scope: the tool runs against a synthetic target
only. Defensive gates: default loopback target; `--environment synthetic`
required (any other value exits 2); non-loopback host requires explicit
`--allow-remote`; malformed port exits 2. Reports record `environment` and a
redacted `scheme://host:port` target (no userinfo) as an audit trail. No audit
events are emitted to the application.

## Migration and rollout considerations

None. This is a standalone rehearsal tool. It is explicitly *not* final pilot
evidence: OPS-03 requires server-side measurement excluding document
transfer/rendering and external calls, collected in an approved environment by
an authorized run and evaluated by `infra/s_g5_05/capacity_evidence.py`.
Reports carry `kind: synthetic_rehearsal` / `final_evidence: false` and print a
`SYNTHETIC REHEARSAL - not final pilot evidence` banner. Pilot acceptance is a
human gate.

- DevSecOps (simulated, read-only): no material high/medium findings. Low F1
  (report not self-labelled), F2 (target not recorded), F3 (https sent as
  plaintext) were adopted: reports now carry `kind`/`final_evidence`/
  `environment`/redacted `target` and a rehearsal banner; `http_sender` uses
  `HTTPSConnection` for `https`. F4 (safety only in `main`) and F5 (string
  loopback match) were considered and not adopted: all entry points go through
  `validate_target`, and `localhost` string matching plus the explicit
  `--allow-remote` opt-in is the repository's existing convention.
- Senior Python (simulated, read-only): three medium findings adopted —
  `concurrent_staff` was inert (now sizes a `ThreadPoolExecutor` and is asserted
  by `test_concurrent_staff_drives_the_worker_pool`); https was plaintext
  (fixed); a malformed port escaped as exit 1 (now exit 2). Low finding 4
  (negative/non-finite timing) adopted with `test_main_exits_two_for_invalid_timing_values`.
  Low finding 5 (missing branch map / untested percentile clamps) adopted: map
  above plus two clamp tests. Low finding 6 partially adopted: the previously
  inert command delay now drives a command-breach integration test; the
  unreachable `None` arm in `run_coverage.py` test tooling was left as-is
  because test tooling is outside the measured production surface.
- Defect found during implementation: the first concurrent version measured
  latency at collection time, charging requests for the whole submit loop
  (~900–1000 ms). Fixed by timing inside the worker (`_timed_request`), which
  restored ~11 ms p95 in the smoke run. No unrelated code was changed.
- `scripts/check.sh` and three `test_check_pack` tests fail only on the stale
  CI-profile `opencode.json` (protected file, outside scope). Recorded, not
  fixed here.

## Lessons for workers

- When adding concurrency to a fixed-rate load loop, time each request inside
  the worker; measuring at future-collection time charges queueing behind the
  submit loop to every request and produces false threshold breaches.
- The stdlib `trace --count --missing` gate only proves line coverage. To honour
  the 100%-branch rule, write a named test for each side of every condition and
  record the map in the notes, because the tool cannot report branch coverage.
- If an acceptance parameter (e.g. "200 active staff") looks like metadata,
  wire it to real behaviour or explicitly flag it in Findings; a reviewer will
  treat inert values as a gap.
- Config validation must cover URL parsing details (port, scheme, environment)
  inside the same `try` that returns the documented config-error exit code,
  otherwise malformed inputs produce an uncaught traceback and the wrong exit
  code.
- `scripts/check.sh`/`test_check_pack` can fail on the worktree's stale
  CI-profile `opencode.json`; verify this is a protected-file artifact before
  attributing it to your change, and report it without editing those files.
