## Lessons for workers

- When a slice adds controller routes, publish them in `contracts/openapi.yaml` in the same
  change and regenerate the client; `OpenApiRouteParityTest`, `OpenApiContractRulesTest` and
  `OpenApiPaginationRulesTest` all fail otherwise, and adding the routes to
  `missing-routes.txt` would hide rather than fix the gap (the baseline must only shrink).
- A GET that really returns a JSON array must use a named array schema whose name does not end
  in `Page` (e.g. `PendingStaffAttachments`); an inline `type: array` or a `*Page` name makes the
  pagination rules treat it as a paginated list and fail the exact-set assertions.
- Every new operation needs `operationId`, `summary`, `tags`, and 401/403 responses; every POST
  needs the `IdempotencyKeyOptional` header component, not a hand-written copy. Route-parity green
  is not enough: read the service for the real 409/422 statuses and the controller for the real
  response media type before declaring a contract entry truthful. A command's verdict vocabulary
  may differ from the stored state vocabulary (`clean`/`failed` versus
  `pending`/`clean`/`quarantined` here).
- In cloud workers, a `check-pack: opencode.json is stale` result usually means the CI profile is
  active under skip-worktree. Compare `git show HEAD:opencode.json` with the worktree file before
  treating it as a real failure; never edit that protected file to make the gate pass.
