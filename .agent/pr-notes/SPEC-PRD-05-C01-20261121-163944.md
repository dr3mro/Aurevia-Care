## Findings

- **Status rationale.** PRD-05 is partly built, not fully built: onboarding
  import and English/Arabic operation have real application code and tests, but
  export, monitoring/observability and recoverability are represented only by
  fail-closed artifact evaluators, handoff documents and runbooks. The next
  worker must not read the passing `infra/` gates as operational evidence — each
  evaluator's own documentation says it judges a synthetic artifact.
- **No runtime export found.** A search of `apps/api/src/main/java` found no
  tenant export service/controller/store; the `export`-named Java files are
  dictionary/localization and messaging-governance code. This is recorded in the
  clause note rather than treated as a defect here.
- **No observability implementation found.** No Micrometer/Prometheus/actuator
  metrics, dashboard, alerting or structured request-log pipeline was found in
  the application sources; only the `HealthController` probes and evaluator
  documents exist.
- **Pre-existing documentation drift (out of scope, not fixed).**
  `docs/operations/onboarding/README.md` states "68 synthetic unit tests pass"
  while `bash infra/onboarding/check.sh` reports `Ran 70 tests`;
  `docs/operations/tenant-lifecycle/README.md` states "92 synthetic unit tests
  pass" while its check reports `Ran 94 tests`. Count drift only; both gates are
  green. Left unchanged because the story scope is a single new file under
  `docs/spec/clauses/product/` and the shared docs are maintainer-owned. A
  maintainer may reconcile those two counts in a separate change.

## Decisions

- Used status **Partly built** rather than *Built and verified* or *Not built*:
  real code and synthetic tests exist for two of the five sub-clauses, while the
  other three and the market-policy boundary have no runtime or human evidence
  in the repository.
- Quoted the clause sentence word for word, including the final period, in
  `## Clause`.
- Linked only verified-existing paths (checked with a filesystem existence loop
  before writing) and only requirement IDs defined in the specification, so
  `scripts/check-docs.py` stays green.
- Counted the gap as at least seven separate tasks (two engineering slices plus
  five human/cloud/signed slices), with named suppliers drawn from specification
  section 10 and the G5 gate.

## Lessons for workers

- A passing `infra/*/check.sh` proves an evaluator accepts a synthetic artifact,
  not that the underlying operation happened. Read the evaluator's "What it
  does not prove" section before assigning a clause status.
- When writing a clause note under a new `docs/spec/clauses/...` directory,
  compute relative links from that directory (four `../` to the repo root from
  `docs/spec/clauses/product/`) and verify each target with `[ -e ]` before
  running `python3 -I scripts/check-docs.py`.
- Keep evidence-source attribution explicit: tool output, file reads, simulated
  review and human evidence are not interchangeable, and only the first two were
  available in this task.
