# SPEC-ARC-03-C01 — ARC-03 clause 1 API acceptance proof

## Summary

Added one real-PostgreSQL HTTP integration test class and one clause-status
document proving ARC-03 clause 1: versioned `/api/v1` routes, stable
tenant-scoped cursor pagination, correlation-id round trip and machine-readable
errors. No production code, contract, migration, existing test or tracker was
changed. Status is `Partly proven` because `X-Api-Version: v2` is not enforced
over HTTP today (`ApiVersion.from` has no production caller).

The brief and story step 3 asked for the unsupported-version gap test to be
marked `@Disabled("GAP: ...")`. That instruction conflicts with AGENTS.md
coverage rules and `scripts/check-constraints.py:56`, which reject any added
`@Disabled`/`@Ignore` line and fail `scripts/quality-gate.sh`. Following the
rule that the brief is guidance and AGENTS.md governs, the complete desired test
was written, observed RED, then converted to an ENABLED gap-characterization
test with a documented flip-forward. This is recorded below and in the clause
doc; no skipped test, threshold, exclusion or suppression was added.

## Findings

- Confirmed gap, not fixed here: `api/contract/ApiVersion.java:41` `from` has no
  production caller; no filter/interceptor reads `X-Api-Version`, so `v2` is
  silently accepted and `UNSUPPORTED_API_VERSION` is unreachable over HTTP.
  Versioning is prefix-only. A `task-requests` entry below asks for the
  cross-boundary fix; that task must flip the characterization assertion from
  200 to 422/`UNSUPPORTED_API_VERSION`.
- `ApiVersion.java:6-10` documents the interceptor rejecting unsupported
  versions, which is intent rather than current wiring. Left unchanged: it is
  production documentation outside this scope; the clause doc records the
  discrepancy.
- The two Optional reviewer suggestions were applied: removed the unused
  `ORG_A_SUBJECTS` fixture, and mirrored the no-leak assertions on the
  cross-tenant 403. The targeted test was re-run green after both edits.
- The coverage auditor's Required hand-off finding (missing notes file) is
  resolved by this file. No code or test change was needed for it.
- Environment-only false positive recorded once under Test evidence; no
  protected file was edited and the artifact was not re-diagnosed.

## Lessons for workers

- Read `scripts/check-constraints.py` before following a story instruction to
  add `@Disabled`: on any new untracked Java file the added line is scanned and
  fails `quality-gate.sh`. An enabled gap-characterization test with a RED
  observation and a documented flip-forward keeps the PR green and honest.
- `HttpStatus.UNPROCESSABLE_ENTITY` is renamed `UNPROCESSABLE_CONTENT` in the
  current Spring version; assert numeric `422` in HTTP tests to avoid coupling
  to the enum name.
- `it.staff.StaffListIntegrationTest`'s helpers are private; a test in
  `web.clauses` must re-declare its own fixtures and request helper instead of
  importing them, and editing that test is out of scope.
