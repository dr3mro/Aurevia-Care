# PHARM-08 — Browser journey and operations guide for the pharmacy workflow

## Summary

Added one Playwright browser journey across two users (prescriber, pharmacy) and
the plain-language operations guide it documents. The prescriber leg mounts the
exported status timeline, clarification reply and substitution review through a
dev-only harness because those components are not routed in the staff portal
yet; the pharmacy leg drives the real `/pharmacy` and `/pharmacy/:id` routes.
Both legs share one deterministic in-browser stand-in for
`/api/v1/pharmacy/**` and `/api/v1/prescriptions/**`, so a fact written by one
user is what the other reads. The journey prescribes and routes, asks a question
and answers it, proposes and approves a substitute, accepts, and records
dispensing, asserting the status wording on each side at every step. No
production source, dependency, contract or tracker was changed and nothing was
pushed or tagged.

## Clinical and architecture review

No signed data, cross-organization sharing or patient association was added. The
journey exercises the existing clinical screens and asserts the existing
presentation rules: attestation before approval, no prescription change before
approval, a question with content before it is sent, and dispensing evidence
kept separate from acceptance. The substitution approval and prescribing
entitlement are enforced by the API/database stories; this test only checks the
status wording and command sequence. Simulated only through synthetic UI renders
in a real browser; no clinician, Arabic-speaking user, pharmacist or patient
participated and no clinical sign-off is claimed. The guide states that live
enablement needs market, policy, partner and G5 approvals.

## Lessons for workers

- The module tsconfig includes only `src`, `tests` and `vite.config.ts`, so the
  e2e `.ts`/`.tsx` files are **not** covered by `npm run typecheck`. Run the
  targeted strict `tsc` command above, and remember the harness `.tsx` needs
  `--jsx react-jsx` and `DOM.Iterable` in `--lib`.
- `eslint .` does lint `e2e/**`: `await a === b ? x() : y()` is rejected as an
  unused expression. Use an explicit `if/else` in route handlers.
- Playwright locators need care on these screens: the detail heading appears as
  both `h2` and `h3` (use `level: 2`), and the portal has a global
  `role="status"` "Notifications" region (assert the command text directly).
- When sharing one mock across two browser contexts, derive the resource id from
  the first path segment after the prefix; the action suffix (`/accept`,
  `/clarification`) otherwise looks part of the id and produces false 404s.
- The Playwright config starts Vite itself; on a bare runner install both the
  Chromium binary and `playwright install-deps chromium`, or the browser exits
  with missing shared libraries.
