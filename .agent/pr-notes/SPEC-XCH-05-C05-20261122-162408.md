## Summary

Proves XCH-05 clause 5 with one new HTTP-level integration test class and one
clause-evidence document. The clause is already implemented in production, so
this change adds tests and documentation only: no production code, existing
test, contract or migration is touched. Three tests cover the full report rule
and its two refusal paths, with synthetic fixtures in a dedicated PostgreSQL
database.

## Affected requirements

XCH-05 (clause 5: "Report overdue items, roster gaps and failed notification
attempts.").

## Risk class

Routine (read-only report proof, test + doc only). Name folders and Java
packages after the business domain (`exchange.clauses`).

## Review owner

orevia-senior-backend (test-only change); read-only reviews by
orevia-plan-reviewer, orevia-code-reviewer,
orevia-coverage-auditor and orevia-devsecops.

## Data changes

None. V23__critical_results.sql already defines `critical_result` and
`critical_result_event` with RLS, FORCE RLS, append-only triggers, a report
index and grants. The test uses a dedicated scratch database
`orevia_xch05_report_it`, dropped in `@AfterAll`.

## Authorization boundaries and audit events

No new rule. The test proves that `CriticalResultService.authorize` refuses a
caller without `CRITICAL_READ` (reception -> 403) and that forced RLS confines
the report to the active organization (a peer admin sees three empty arrays
while a seeded victim fact exists). Role and organization come only from
`X-Synthetic-Subject` and `X-Active-Organization` headers; neither is read from
a request body. No audit event is added or changed.

## Migration and rollout considerations

None. No migration reserved version was used.

## Findings

- `GET /api/v1/critical-results/report` is listed in `contracts/openapi/missing-routes.txt:29`. Publishing the route in `contracts/openapi.yaml` and regenerating the client is out of scope for this test-only task; it needs a separate contract task.
- Environment only: the worktree `opencode.json` is the CI profile installed under `skip-worktree` (OPS-CW-003-01). It makes `check-pack`, `scripts/worker-check.sh` and six `test_check_pack` cases fail locally. HEAD's committed local profile is correct; the integrator owns the full gate.
- `CriticalResultFlowTest` already proves this clause end to end (`reportSurfacesOverdueAlertsAndRosterGaps`, `overdueAndSystemDownUseApprovedBackupChannel`, `authorizationAndTenantIsolationHoldOnEveryCommand`). This per-clause suite follows the per-clause evidence convention and adds exact result-id binding on every reported row.
- Pre-existing state observation (not changed here): HEAD already contains Git conflict markers in `apps/api/src/main/java/com/aurevia/exchange/hl7/Hl7Parser.java` (and two sibling `Hl7*` files). Confirmed with `git show HEAD:... | grep -nE '^(<<<<<<<|>>>>>>>) '`. `git status` shows them clean, so they were committed by another worker, not by this change.

## Lessons for workers

- Helpers in `it.exchangeresult.CriticalResultFlowTest` are private/package-private: a test in `exchange.clauses` cannot call them. Copy the self-contained setup/HTTP-helper pattern of `scheduling/clauses/StaffSeeOrganizationFacilityWorklistOrderedScheduledTest` instead.
- Record the failed escalation BEFORE revoking the backup clinician's membership. Once the backup is inactive, escalation short-circuits into a roster-gap fact and never appends the failed-notification event.
- A peer-tenant "empty" assertion is vacuous unless the victim tenant is seeded with a reportable fact first; seed a sentinel and assert the victim's own report is non-empty.
- OPS-CW-003-01: confirm the `skip-worktree` CI profile once (`git ls-files -v opencode.json` -> `S`, compare with `git show HEAD:opencode.json`), record the failing command and its final line, then run the remaining gate stages individually. Never regenerate or edit the protected file from a worker.
