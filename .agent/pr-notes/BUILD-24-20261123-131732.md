# BUILD-24 — Swagger UI at /swagger-ui for the contract

## Summary

Published an in-repository Swagger UI at `/swagger-ui/` that renders the already-served
`/api/v1/openapi.yaml` contract with no CDN. The generated page and initializer are served
by a Spring resource handler (not a `@RestController`), so the OpenAPI route-parity gate is
unaffected. The feature is enabled by the `synthetic-auth` or `development` profile, or by
`orevia.docs.enabled=true`; the default is off. Both production security chains permit
the docs subtree only while enabled, and the browser CSP is relaxed to same-origin sources
only on the docs path while every other response keeps the baseline policy.

Requirement IDs: specification section 7 (generated OpenAPI client types / V1 REST with
OpenAPI), WEB-02 (CSP, spec line 150). No requirement ID was added to a package or class name.

## Affected requirements

- Section 7 — V1 REST with OpenAPI and generated client types; the UI consumes the existing public contract route.
- WEB-02 — CSP contains no `unsafe-inline`/`unsafe-eval`, keeps `frame-ancestors 'none'`, and is scoped to the docs path.

## Risk class

Cross-boundary (build dependency, Spring MVC resource handling, two security chains and the
global headers filter). No patient data, migration or clinical workflow is involved.

## Data changes

None. No Flyway migration, backfill, table, RLS policy, store or lock change. Rollback is

## Authorization boundaries and audit events

- `/swagger-ui`, `/swagger-ui/` and `/swagger-ui/**` are static, tenant-free documentation.
- When disabled there is no permit rule in either chain and no resource mapping: an
  authenticated caller gets 404 and an anonymous caller is denied (redirect/401).
- Fail-closed OIDC startup checks (issuer, audience, client id/secret) remain unconditional.
- `TenantContextInterceptor` stays mapped to `/api/v1/**` only; the docs subtree is not
  tenant-scoped or rate-limited, and the local contract fetch keeps its existing public
  but rate-limited behavior.
- No audit event, role, permission or tenant policy changed.

## Migration and rollout considerations

No migration. New operator switch `orevia.docs.enabled` defaults to false; it is read
through `Environment` and needs no `application.yml` edit. The pinned webjar is
`org.webjars:swagger-ui:5.36.0`; the same version is hard-coded in the resolver root and
guarded by `SwaggerUiHttpTest.pinnedWebjarVersionIsResolvable`. `application.yml` is out of
scope, so operator documentation of the switch is requested via `task-requests` below.

- **Protected build file (needs a person).** `apps/api/pom.xml` is in `PROTECTED` and the
  task text says a person adds the webjar. It was absent, so this worker added the single
  pinned `org.webjars:swagger-ui:5.36.0` dependency following the accepted BUILD-40 precedent
  (task `[x]`, PR #615, same "needs a person: pom.xml" wording), where the worker added the
  pinned dependency and flagged it. The integrator should treat this PR as `needs-human` /
  `SWARM_ALLOW_PROTECTED` for that file and have a person confirm the pinned version. No other
  build file was changed.
- **"Development" profile.** No literal Spring `development` profile exists in the repository.
  The condition checks an explicitly activated profile named `development`, which the
  `development` test activates via `ApplicationContextRunner.withInitializer`. If operators
  intend "every non-production deployment", that is a semantics decision for the owner; this
  implementation does not guess at it and keeps the default off.
- **Defensive hardening added during review.** The resolver rejects any relative path
  containing `..` before constructing the webjar `ClassPathResource`, and the generated page
  uses absolute same-origin `/swagger-ui/...` asset URLs so the exact `/swagger-ui` path also
  renders its assets. Both have named assertions and are included in the 100% branch evidence.
- **Stock webjar initializer.** It points at `https://petstore.swagger.io/v2/swagger.json`.
  The resolver always serves the generated initializer instead, so no CDN or remote origin is
  used by the page. The webjar bundles contain URL string literals (SVG namespaces, schema
  IDs) that are data, not resource loads; the no-CDN assertions cover the served HTML and
  initializer.
- **CSP scoping is path-only.** A disabled `/swagger-ui/` request can still carry the scoped
  CSP header even though it 404s; relaxing a response header on a non-existent static path
  grants no resource access and keeps the filter constructor unchanged for existing tests.
- **Known worker-image artifacts.** `opencode.json` CI profile under `skip-worktree`
  (OPS-CW-003-01), missing `@typescript-eslint/parser` in patient-mobile lint, no OWASP NVD
  key/cache, and the 5-minute integration-test cap. None is a defect of this change.

## Lessons for workers

- `WebApplicationContextRunner` builders are immutable: `withPropertyValues` and
  `withInitializer` return a NEW runner. Assign the result or the profiles/properties never
  reach the context and every "enabled" test silently 404s or redirects.
- `withPropertyValues("spring.profiles.active=x")` does not reliably activate Spring
  profiles in a bare context runner; use `withInitializer(ctx -> ctx.getEnvironment()
  .setActiveProfiles(...))` and assert the active profiles when debugging.
- PathPattern `/**` does not match a bare `/swagger-ui/` request; register the exact paths
  alongside the wildcard handler pattern.
- A custom `ResourceResolver` receives the full request path here, not the path within the
  handler mapping; strip the docs prefix before dispatching to in-memory or webjar resources.
- Do not subclass `ByteArrayResource` to add a filename: SpotBugs reports both
  `EQ_DOESNT_OVERRIDE_EQUALS` and `EQ_OVERRIDING_EQUALS_NOT_SYMMETRIC`. Implement
  `AbstractResource` directly (Spring 7 requires `getDescription()`).
- Adding a `@Bean` parameter to a security filter-chain method breaks every existing
  `WebApplicationContextRunner` that loads that config; add the bean to all such runners in
  the same change and rerun the whole package, not just the new test class.
