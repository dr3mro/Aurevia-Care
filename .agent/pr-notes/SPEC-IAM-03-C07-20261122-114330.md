# SPEC-IAM-03-C07 — IAM-03 clause 7 API test evidence

## Summary

Added one API test class and one clause evidence document proving that shared phone,
names and dates of birth cannot link patient records or patient accounts. No
production code, existing test, OpenAPI contract or migration was changed. The rule
is already implemented in the patient domain; this story adds proof only.

Files added (only files in scope):

- `apps/api/src/test/java/com/aurevia/patient/clauses/SharedPhoneNamesDatesAloneCannotLinkTest.java`
- `docs/spec/clauses/patient/shared-phone-names-dates-alone-cannot-link.md`

## Affected requirements

IAM-03 (whole requirement): "Record PatientRecord and issuer-scoped MRN per organization.
Normalize search while preserving original spelling. Registration collects names,
date of birth or a coded unknown reason, contacts, language, identifiers with issuer
and verification state, and applicable consent records. Warn on likely duplicates.
Confirm two identifiers at high-risk transitions when available, including collection
and chart consolidation. Document the approved alternate process when identifiers are
unavailable. Shared phone or names and dates alone cannot link records or patient
accounts."

Clause 7 is the last sentence. The neighbouring high-risk controls it relies on are
IAM-04 (two-identifier consolidation) and IAM-05 (invitation-only account linking).

## Lessons for workers

- For proof-only clause stories, check whether the rule is already implemented
  before reaching for `@Disabled`: a green test with real service logic and a
  deliberate negative is stronger proof than a disabled placeholder.
- Mockito strict stubs are avoided here by plain `mock()` plus a passthrough
  `TransactionTemplate`, the same fixture style as `IdentityProofingUnitTest` and
  `ConsolidationServiceTest`; it keeps boundary assertions readable and stable.
- The worktree `opencode.json` under `skip-worktree` makes `check-pack.py` and
  `test_check_pack.*` fail with a clear stale-config message. Verify the `S` flag
  once, record it, and run the remaining gate stages individually instead of
  editing the protected generated file.
- `scripts/check.sh` and `scripts/worker-check.sh` run the full integration tier;
  for a scoped test-only change run the target test plus individual policy checks
  and leave the full gate to the integrator.
