## Summary

Adds `diagnose(log_text)` to `scripts/swarm.py`: a secret-safe, structured summary of a failed CI log (tool, failing step, exit code, up to five failing test/file names, first error line, problem class) and a `diagnosis()` formatter that puts the summary before the masked, clipped raw tail. `fail()`, `report_pr_stuck()` and `report_worker_handoff()` now post that block in PR comments and issues instead of a bare log tail. New `scripts/tests/test_swarm_diagnostics.py` covers every tool, every class, masking, empty/huge logs, deduplication and the five-name cap. Synthetic fixtures only; no dependency added; no file outside the task scope changed.

## Lessons for workers

- Synthetic log fixtures must not contain another tool's name in an assertion message: `AssertionError: ... 'Vitest'` made the tool detector report Vitest for a Python-unittest log. Keep assertion text tool-neutral.
- A single-line ternary where both outcomes reach the same next line is not a separate measured coverage branch; still test both directions, but do not expect two arcs.
- `frame` objects cannot hold custom attributes; a stdlib trace harness must keep per-frame state in a dict keyed by `id(frame)`.
- In cloud workers, check `git ls-files -v opencode.json` before treating `test_check_pack` failures as your own; the `S` flag means the CI profile is in the worktree and the failures are pre-existing.
