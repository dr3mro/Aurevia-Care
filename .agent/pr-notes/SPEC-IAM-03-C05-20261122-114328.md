# SPEC-IAM-03-C05 — confirm two identifiers at high-risk transitions (API clause test)

## Summary

Added an HTTP-level clause-proof test for IAM-03 clause 5 and its clause evidence note.
The chart-consolidation half of the clause is built: the test proves that a second
reviewer's two issuer-scoped identifiers must match both records, and that a request
with neither two identifiers nor a documented process is refused. The collection
half is not built: registration binds a single MRN/issuer and performs no
two-identifier confirmation. Its complete test is present but `@Disabled` with a
`GAP:` reason so the pull request stays green. No production code, migration,
contract or existing test was changed.

## Findings

1. **Clause is partly built.** The chart-consolidation transition enforces two issuer-scoped identifiers (or one coded alternate process) and audits the basis. Patient registration does not: `PatientController.RegisterRequest` has only one MRN/issuer plus a free-text `identifiers` JSON, and `PatientService.register` never confirms two identifiers. The disabled test `collectionConfirmsTwoIdentifiersWhenAvailable` documents the intended contract; enabling it requires a separate implementation task. Status in the clause note is `Partly proven`.
2. **OpenAPI gap.** The consolidation route is not in `contracts/openapi.yaml`; it is baselined in `contracts/openapi/missing-routes.txt`. The clause note records this so it is not mistaken for a proven public contract.
3. **Pre-existing conflict markers.** `git grep -nE '^(<<<<<<<|>>>>>>>) '` finds committed markers in the Javadoc of `Hl7ParseException.java`, `Hl7Parser.java` and `Hl7Segment.java` under `apps/api/src/main/java/com/aurevia/smartclinic/exchange/hl7/`. They predate this branch, are inside comments, and are outside the task scope; not changed here. A maintainer should resolve them before the developer-reference build is trusted.
4. **Worker-profile false positive.** `scripts/check.sh` and six `test_check_pack` cases fail on `opencode.json is stale` because this worker has the CI profile under skip-worktree. HEAD's committed profile is correct; no regeneration was attempted (protected file, and regeneration would not fix the worktree profile). See Test evidence item 5.

## Lessons for workers

- For clause-proof stories, first grep for the rule's implementation before assuming the clause is missing: the two-identifier rule lives in `patient/consolidation/ConsolidationService.confirmationFailure`, not in the patient package named in the task text. Reuse the neighbouring HTTP test's DB setup and a dedicated database name so parallel workers do not collide.
- Use a unique synthetic MRN prefix per test method; `count(...)`/`scalar(...)` SQL assertions through the migrate role are a reliable way to prove a refusal left no row behind.
- In this worker image, treat `check-pack.py` and `test_check_pack` "opencode.json is stale" failures as the documented CI-profile artifact: confirm with `git ls-files -v opencode.json` and `git show HEAD:opencode.json`, record it, and do not edit or regenerate the protected file.
- A `@Disabled("GAP: ...")` test must still be complete and assert outcomes, so the next worker can enable it after the implementation task; state explicitly in the notes that it is not counted as a pass.
