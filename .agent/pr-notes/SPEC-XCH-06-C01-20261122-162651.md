correlation id. The role-negative test asserts two `DENIED` audit rows. Cross-tenant tests assert
that ORG_B sees no ORG_A release row, event or notification (forced RLS).

## Lessons for workers

- When the clause is already built, an active HTTP test that asserts the exact stored
  references is the proof; a `@Disabled` GAP would be wrong. A bounded temporary expectation
  change (red probe, then restore via trap) demonstrates the assertion is live without
  touching production code.
- The `synthetic-auth` correlation id reaches `release_notification.correlation_id` and
  `audit_event.correlation_id` verbatim, but `CorrelationIdFilter`'s response header/MDC use a
  random UUID unless the header is itself a UUID — assert against the DB, not the response header.
- A peer-tenant clinician posting the same patient and revision is a valid 201 in its own tenant
  (the unique index includes organization); use a member of the wrong active organization for
  the 403 denial and a peer member for the 404/no-leak read.
- Use a far-future fixed `effectiveFrom` with kind `TIMED` so the effective instant is asserted
  rather than defaulted from the injected clock, and pass `If-Match: "1"` (quoted) on correct
  so the state guard does not mask the same-revision immutability guard.
- Spring 7's `HttpStatus` constant for HTTP 422 is `UNPROCESSABLE_CONTENT`;
  `UNPROCESSABLE_ENTITY` compiles but is a different enum constant and fails the assertion.
