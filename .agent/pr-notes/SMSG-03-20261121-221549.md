# SMSG-03 — API: instant conversations inside a facility

## Summary

Implemented the domain layer for instant staff-to-staff conversations inside one
facility (MSG-02, ARC-07): find-or-create direct conversations, create groups,
add/remove participants with preserved membership history, idempotent message
send, monotonic per-reader read cursors and per-person unread counts. All files
are inside the declared scope (`apps/api/.../staffmsg/instant` main and test).
No dependency, migration, controller, contract, tracker, workflow, agent or
script file was changed. No push, tag or `gh` call was made.

This is a **bounded, 100%-covered domain slice**, not an end-to-end HTTP feature:
the scope forbids the read-cursor migration, controller, OpenAPI entry and JDBC
store that AGENTS.md "Done means working end to end" requires. See Findings and
the `task-requests` block. The in-memory fake lives only in `src/test`.

## Affected requirements

- **MSG-02** — open/find a direct conversation, create a group, manage
  participants, send, unread counts on the (future) work queue; history stays
  visible to members present at the time a message was sent.
- **ARC-07** — message shape reused from `StaffMessagingContract` (sender identity
  and role, immutable body, server timestamp, per-conversation sequence),
  durable client message id deduplication, tenant/facility authorization,
  per-reader read cursors. Staff messaging is borrowed scope from the still
  human-unapproved SMSG-01 amendment (`docs/decisions/staff-messaging`); no
  claim of approved-spec conformance beyond the code paths tested here.

| Task acceptance | Test |
|---|---|
| Retried send makes one message | `retriedSendMakesOneMessageAndDoesNotAdvanceTheSequence` — same client key returns the original id/sequence/body, ledger stays at one row, next key takes sequence 2 |
| Removed member cannot read later messages | `removedMemberCannotReadLaterMessagesButKeepsEarlierHistory` — half-open `[joinedAt, leftAt)` window at the message's `sentAt`; earlier message visible, later one hidden; send and mark-read refused after removal |
| Unread counts are per person | `unreadCountsArePerPersonAndExcludeOwnMessagesAndFormerMembers`, `readCursorIsMonotonicAndClampedToPublishedSequence` — separate cursors, own messages excluded, lower cursor cannot resurrect unread, clamp to last published sequence |
| Wrong facility or tenant refused | `openDirectRefusesSelfAndForeignFacilityAndTenant`, `accessIsRefusedAcrossTenantsFacilitiesAndForNonMembers`, `conversationFromAnotherFacilityCannotBeReachedByFacilityAMember` — 403/404 with no cross-facility or cross-org data |

## Authorization boundaries and audit events

Every public `InstantConversationManager` operation re-resolves the acting
subject through `StaffGate.activeStaff(organizationId, subject)` on each call;
an absent active membership is a 403 before any state read. Conversation
access additionally requires the actor's authorized facility to equal the
conversation facility (403) and a membership row (403/404). Management
operations (add/remove participant) require an active OWNER. A departed member
keeps read access only to messages sent inside their membership window.
No audit event type was added or changed: MSG-07 audit remains SMSG-09.

## Migration and rollout considerations

No migration in scope. Read cursors are held by the test-only fake and are
therefore **not durable across a restart** — the one AGENTS.md end-to-end
property this slice cannot satisfy without a scope deviation. A follow-up must
add a forced-RLS read-cursor table (next free version is V94) and a Jdbc store;
see `task-requests`.

## Findings

1. **Scope-blocked end-to-end wiring (high, not a code defect).** The task scope
   names only the two `staffmsg/instant` directories. A durable read-cursor
   table, a `Jdbc*` store behind the port, a thin controller, an HTTP
   integration test and an OpenAPI entry all live outside it. The ports are
   deliberately named `...State` / `...Gate` and the domain class `...Manager`
   so `scripts/check-wiring.py` reports no new finding; that naming is **not**
   evidence of durability. `check-wiring` was green with only stale baseline
   notes.
2. **Read state is non-durable in this slice.** `saveReadSequence` is
   implemented only by the test fake. Conversations, membership history and the
   message ledger are owned by V91 and are durable; per-reader cursors are not.
   A restart resets unread counts until follow-up work adds a table.
3. **Rejoin is intentionally unsupported.** Re-adding a departed member returns
   the existing row unchanged because V91's `staff_participant` primary key is
   `(org, conversation, subject)`; clearing `leftAt` would destroy the earlier
   membership window and leak history. A durable rejoin needs a new membership
   window design and a migration.
4. **Direct pair uniqueness is enforced only by the fake.** V91 has no unique
   constraint on an unordered participant pair, so two concurrent
   `openDirect` calls could create two DIRECT rows in a durable store; the
   follow-up needs a pair-key constraint.
5. **Pre-existing environment artifacts (not caused by this change).**
   `worker-check.sh` and five `test_check_pack` cases fail on the CI profile
   copied over `opencode.json` under `skip-worktree`; the committed HEAD profile
   is correct. Unrelated committed conflict markers remain inside Javadoc in
   `exchange/hl7/Hl7ParseException.java`, `Hl7Parser.java` and `Hl7Segment.java`
   from BUILD-37; they were left untouched as out of scope.

## Lessons for workers

- Reuse the SMSG-02 `StaffMessagingContract` value types instead of creating a
  parallel conversation/message model; the membership window predicate
  `isActiveAt` already encodes the half-open history rule.
- Filter reads by `participant.isActiveAt(message.sentAt())`, never by "is a
  member now": the first preserves pre-leave history, the second either hides
  all history or leaks post-leave messages. Pin the clock with a mutable test
  clock so the `at == leftAt` boundary is deterministic.
- Deduplicate sends **before** allocating a sequence; allocating first creates
  a gap even when the retry returns the original message.
- `check-wiring.py` recognizes only `InMemory*` in `src/main`, `*Store`
  interfaces without a `Jdbc*` implementer and `Controller` that constructs a
  service. Renaming to avoid a finding is legal but must be disclosed — it is
  not proof of durability.
- In this worker image `opencode.json` has Git flag `S` (skip-worktree): check
  `git ls-files -v` before treating `check-pack.py` or `test_check_pack`
  failures as a defect of your change.
- Fully qualified `{@link ...}` targets are required by `test_java_conventions`;
  the new Javadoc here uses only fully qualified links and the conventions test
  suite reported no new failures.
