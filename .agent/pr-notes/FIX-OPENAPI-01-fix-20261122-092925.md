## Lessons for workers

- When a fix pass finds the scoped files equal to `origin/main` and the targeted tests
  green, the correct action is to record completion evidence — not to re-apply the fix or
  add another notes-only re-verification commit. An extra identical pass adds no evidence
  and is the loop's pattern here.
- `git rev-list --left-right --count HEAD...origin/main` plus an empty
  `git diff origin/main -- <scoped files>` is the fastest proof that a stale-merge fix is
  fully present before spending time on tests.
- A red `check-pack: opencode.json is stale` in a cloud worker is the skip-worktree CI
  profile, not a change defect. Confirm with `git ls-files -v opencode.json` and
  `git show HEAD:opencode.json`; a temporary, trap-restored swap to HEAD bytes proves both
  pack checks green without editing the committed file.
- The module `check.sh` scripts install pinned dependencies with `npm ci` when
  `node_modules` is absent; unset `CHECK_SCRIPT`, `BRANCH_PREFIX` and `BASE_BRANCH` when
  running them directly, and capture `npm run typecheck` separately for the mandatory
  frontend definition of done.
- Do not run `scripts/worker-check.sh` or full `mvn verify` as a worker; run only the
  touched test classes and leave the full gate to the integrator.
