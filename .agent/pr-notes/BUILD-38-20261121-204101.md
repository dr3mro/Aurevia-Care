# BUILD-38 — Partner contract fixtures: duplicates, corrections, reordering and outages

## Summary

Extended the synthetic partner conformance domain with an authorized replay-with-reason
scenario and FHIR/HL7 wire adapters that carry every fixture event across a partner
encoding and back. A new `PartnerReportProcessor` entry point applies events directly or
through either wire adapter, records authorized replays, and exposes an immutable
`FinalReport` snapshot. Tests prove that all 13 existing fixtures plus the new replay
fixture reach the same final report state through FHIR and HL7, that a duplicate or an
older revision never overwrites the final report, that an unmatched report waits in the
reconciliation queue, and that an authorized replay keeps the immutable event id.

All changes are inside the declared scope (the two `exchange/conformance` paths). No
dependency, migration, contract, tracker, workflow, script or out-of-scope file was changed.
All data is synthetic.

## Affected requirements

ARC-05 (delivery: dedup in sender/type namespace, hold out-of-order, bounded retry,
dead-letter, preserve replay event identity with authorization and reason, synthetic
contract fixtures including duplicates/corrections/partial outages); XCH-04 (identifier
matching, reconciliation queue, prior revisions preserved); G2 (gate evidence).

## Risk class

Cross-boundary (partner wire interface) but fully synthetic and in-memory: no database,
no real partner, no patient data, no credential, no clinical sign-off claimed.

## Authorization boundaries and audit events

A replay is only accepted with a `ReplayRequest` carrying a non-blank reason and a
non-blank authorizing actor, and only when its `eventId` equals the event being replayed
(`ReplayRequest.matches` / `PartnerReportProcessor.authorizeReplay`). This is synthetic
conformance evidence, not a production authorization decision. No audit event added or
changed.

## Migration and rollout considerations

None. This is a deterministic, in-memory conformance harness; no production enablement.

## Lessons for workers

- A public fixture factory can be added to `ConformanceFixtures` without breaking the
  existing `assertEquals(13, all().size())` test as long as it is not inserted into
  `ALL`; call it directly from the new test and cover it there.
- Round-trip wire adapters preserve `PartnerEvent` identity only if every field is
  explicit in the encoding. FHIR extensions and an HL7 custom `ZEV` segment carrying
  eventId/sender/kind/aggregate/revision/identifier/unit/payload make the FHIR and HL7
  paths reach byte-equal `FinalReport` snapshots for every fixture.
- Encode a null optional field as an empty string and decode empty→null with
  `"".equals(value)`; a `value == null || value.isEmpty()` guard leaves an uncovered
  branch because the encoder never emits a missing field.
- For a replay fixture that dead-letters then recovers, the delivery gate must fail
  every attempt of the first apply (`calls > maxAttempts`) so the first disposition is
  `DEAD_LETTER`; `calls > 2` with `maxAttempts = 3` applies on the first try.
