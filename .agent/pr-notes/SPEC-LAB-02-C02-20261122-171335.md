## Lessons for workers

- When a clause-evidence brief mandates a plain JUnit test but the plan reviewer requires HTTP proof, keep the in-scope domain test, set Status "Partly proven", state both the HTTP and contract gaps in the doc `## Gap`, and file `task-requests`; do not silently claim "Proven by tests".
- `git grep -nE '^(<<<<<<<|>>>>>>>) '` can report markers committed in unrelated files; confirm with `git show HEAD:<path>` before treating them as conflicts from your own merge, and record them as a finding instead of editing out of scope.
- In a cloud worker, `git ls-files -v opencode.json` showing `S` explains check-pack and `test_check_pack` failures (OPS-CW-003-01); verify once, record the final line, and never regenerate or commit that protected file.
- The Surefire XML line (`tests="7" ... skipped="0"`) is the proof a new test class actually ran; a bare BUILD SUCCESS is not enough when a test could have been filtered out.
- Check `contracts/openapi/missing-routes.txt` when a story says "routes already exist": a controller route there is not yet a documented API contract.
