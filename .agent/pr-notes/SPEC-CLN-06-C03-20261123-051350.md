## Lessons for workers

- The booking reason lands in `public.appointment.override_reason` (from `BookingRequest`), while
  `follow_up_suggestion.override_reason` holds the override's own reason. Assert the former when
  proving what confirmation booked; the two values differ in this flow.
- With one clinician resource booked at a fixed 09:00 slot, two successful confirms in a
  shared class-level DB must use distinct dates or the GiST slot exclusion turns the second 200
  into a conflict. Keep every booked date after the largest `encounterAt`, otherwise
  `applicablePriorFollowUp` reclassifies later suggestions.
- Jackson `NullNode.asText()` returns the string `"null"`: assert `isNull()` on `bookingId`, not
  `assertNotNull(asText())`, or a missing booking id passes the test.
- Private fixture helpers in another package cannot be imported; copy/adapt them into the
  mandated package and keep the unique DB name and matching `@SpringBootTest` datasource URL.
- Confirming the CI-profile `opencode.json` once (`git ls-files -v` = `S`, compare with
  `.github/opencode.ci.json`) avoids re-diagnosing the same six `test_check_pack` failures.
