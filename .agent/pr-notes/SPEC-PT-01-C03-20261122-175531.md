## Lessons for workers

- For clause-evidence tasks on a partly built requirement, prefer GREEN service-level proof of the built portion plus an honest `## Gap`, not a new `@Disabled` test: `scripts/check-constraints.py:56` rejects added `@Disabled` in Java and fails the quality gate.
- `mvn -Pno-security,fast -Dgroups=integration` is a false green (fast profile excludes integration); use `-Pno-security -Dgroups=integration -Dtest=ClassName` and confirm the Surefire XML count. Compile before `spotbugs:check` or the check is vacuous.
- A fresh dedicated DB name per worker avoids parallel collisions; `aurevia_pt_clause3_it` is used here. Reuse the fixture helpers by copying them into a self-contained class — the neighbouring test's helpers are private.
