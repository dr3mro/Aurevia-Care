# SMSG-22 — Docs: staff messaging guide, rules for what not to send, and UAT scenario

## Summary

Added the staff messaging operations handoff for MSG-07: a guide covering
instant messages versus mail, in-facility and between-facility use, attachments,
patient references, the "not for emergencies" rule, retention and auditing; and
a synthetic numbered UAT scenario with explicit negative steps. Documentation
only — no production code, contract, migration, CI or tracker file was changed.

## Affected requirements

- MSG-07 (primary): every clause is mapped to a section in `README.md` and
  exercised by the numbered steps in `uat.md`.
- Context only (no new requirement): MSG-01 (verified connections, new recipient
  requires a separate conversation), MSG-03 (attachment types, scan/quarantine),
  MSG-04 (typed instructions, corrections), MSG-05 (revision-bound acknowledgment
  is receipt only), MSG-06 (service profile, hours, urgent/downtime channels),
  OPS-02 (append-only audit with actor, purpose, scope, correlation, outcome),
  OPS-07 (retention, legal hold, export), IAM-01/IAM-02 (fresh membership/role
  check), IAM-05 (disputed access).

| Severity | Reviewer finding | Resolution in this change |
|---|---|---|
| HIGH | The clinician-authorization gate for issuing a clinical instruction (MSG-04) was omitted; UAT step 3 had `unit_staff` send a "typed instruction" | README "Instant messages versus mail" and "Inside a facility" now distinguish operational coordination from clinical instructions and require the configured clinician authorization and professional scope; UAT step 3 is now an operational message, step 4 is an authorized clinician instruction and NEGATIVE step 5 refuses an `unit_staff` clinical instruction |

## Findings

- F1 (environmental, pre-existing, not a defect in this change): `check-pack.py`
  and `gen-opencode.py --check` report `opencode.json` stale. In this cloud
  worker `git ls-files -v opencode.json` is `S` (skip-worktree): the worktree
  file is the CI profile injected by `agent-run.sh`, with SHA
  `50005c9c…`, while `git show HEAD:opencode.json` is `0dc2ac8e…`. The three
  `test_check_pack` failures are the same artifact. This is documented in
  MEMORY.md (OPS-CW-003-01) and cannot be fixed from this docs-only scope;
  `opencode.json` is a protected file I must not edit.
- F2 (pre-existing, unrelated): `test_swarm.TwoTierTests.test_integrate_batch_retries_when_main_advanced`
  fails (`gate.call_count` 1, expected ≥2). It does not read the changed files.
- F3 (decision): the service profile's concrete urgent/downtime channel values,
  role-name mapping, retention windows and record-access policy version are
  site decisions; the guide records them as open items rather than inventing
  values.
- F4 (decision): I did not use reserved migration version — no schema change is
  needed for documentation.
- F5 (specialist finding, resolved): the physician reviewer raised one HIGH
  (missing clinician-authorization gate for clinical instructions), one MEDIUM
  (no inbound-emergency escalation rule) and one LOW (two "what not to send"
  rules not exercised by a UAT negative). All three were fixed inside the two
  docs before commit; see "Clinical and architecture review" above.

## Lessons for workers

- For a docs-only story, the applicable step-6 gate is `python3 -I
  scripts/check-docs.py` (plus `check-secrets.py`); do not run `scripts/check.sh`
  because it launches the forbidden full `mvn -q -B verify` through
  `apps/api/check.sh`.
- In a cloud worker, `git ls-files -v opencode.json` showing `S` means the
  worktree file is the skip-worktree CI profile: `check-pack.py` and
  `gen-opencode.py --check` "stale" results there are measurement artifacts,
  not HEAD truth. Check `git show HEAD:opencode.json` before treating them as
  defects (MEMORY.md OPS-CW-003-01).
- Reuse the implemented domain vocabulary (`MessagingAuditContract`,
  `MessagingGovernanceActions`, `ServiceProfileContract`) when documenting
  MSG-07 so the guide names the real audit facts and roles instead of inventing
  parallel terms.
