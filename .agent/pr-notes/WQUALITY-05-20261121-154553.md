# WQUALITY-05 — validate the runtime OpenCode profile separately from the generated config

## Summary

**Story complete.** Added `--check-runtime` to `scripts/gen-opencode.py` and a
20-case suite in `scripts/tests/test_opencode_profile.py`. The new mode validates
the CI runtime profile (`.github/opencode.ci.json`) on its own, independently of
the generated local config (`opencode.json`), which `check-pack.py` already
covers for drift. Requirement: **OPS-06** (CI policy and secret scanning).
Synthetic fixtures only; no dependency added; existing `--check` behaviour
unchanged. `scripts/gen-opencode.py` is at **100% line and branch coverage**.
The only red check in this worker is a pre-existing, out-of-scope `test_swarm`
failure that also fails on pristine `origin/main` (see below).

Scope cleanup: an earlier segment accidentally committed vendored `coverage`
metadata under `.coverage-tools/` (outside the declared scope and effectively a
dependency) even though its note said the bootstrap directory was removed. This
segment removed those 8 tracked files; no other file outside the two scope paths
is changed by this work.

## Findings

- **Interpretation of the protected-path rule.** It checks file-edit tool
  permissions (`write`/`edit`/`patch`), not shell command permissions. The
  orchestrator has `shell: "*" allow` in the CI profile and owns `TODO.md` per
  AGENTS.md, so a literal "no agent can write" cannot apply to it; shell is
  governed separately by the bash permission list and the generator's explicit
  `SHELL_DENY`/`CI_SHELL_DENY`. Including shell here would make the repository
  profile fail its own gate. (Raised by the senior-Python reviewer; accepted.)
- **Reviewer detection** uses the exact catch-all deny dict, matching the
  convention already used by `scripts/check-pack.py`. A hand-edited reviewer
  expressed differently would be misclassified; the profile is generator-owned.
- **Narrow write patterns** such as `.github/ISSUE_TEMPLATE/*` may not match the
  representative protected files; the canonical `.github/*`, `TODO.md`,
  `.opencode/*` and `*` patterns are caught.
- **Model rule** fires only when a profile declares a `model` key; the generator
  emits none because the worker model is supplied from `slots.json` via the
  environment. It prevents an unapproved pinned model from being added later.
- **Malformed non-dict entries** in a hand-edited profile would raise rather than
  report a violation; the profile is machine-generated and `--check` detects
  drift from it.
- **No CI caller was added** for `--check-runtime`: the story scope is only the
  two files, so wiring it into a workflow is left to an integrator/owner.
- **Out-of-scope artifact removed.** An earlier segment committed
  `.coverage-tools/{a1_coverage.pth,coverage-7.17.4.dist-info/*}` (8 tracked
  files) despite its note saying the bootstrap directory was removed before
  commit; the actual `coverage/` package was gitignored, so the metadata was
  useless cruft and a de-facto dependency outside the declared scope. Removed
  in this segment; no dependency, lock file, tracker, `opencode.json`, workflow
  or `.opencode/` file is changed by the final diff.
- **Pre-existing red gate.** `scripts/check.sh` and the full tooling suite have
  one failure, `test_swarm.TwoTierTests.test_integrate_batch_retries_when_main_advanced`
  (`gate.call_count` 1, expected >= 2). Verified byte-identical `scripts/swarm.py`
  and `scripts/tests/test_swarm.py` against `origin/main` and reproduced the same
  failure on a detached pristine `origin/main` worktree. It is unrelated to
  this story and outside its scope; see `## Why this is not finished`.
- Static analysis for this Python-only change: `scripts/check-secrets.py`,
  `check-names.py`, `check-pack.py`, `check-docs.py`, `check-wiring.py` and the
  changed-script coverage gate all passed.

## Lessons for workers

- In a cloud worker, `opencode.json` is the CI profile under `skip-worktree`:
  `gen-opencode.py --check` and `check-pack.py` judge that worktree file, not the
  committed local profile. Use `git show HEAD:opencode.json` to restore it for
  local gates, then copy `.github/opencode.ci.json` back; never commit it.
- `python-coverage.sh` needs the `coverage` package. Without pip, download the
  pure-Python `py3-none-any` wheel from PyPI, extract it into an in-workspace
  temp dir and set `PYTHONPATH` (network works from the workspace, not from an
  external `cd`).
- In temporary-profile tests, re-save the mutated dict before calling the
  checker; tests that delete or corrupt the file must call the checker directly
  instead of a helper that rewrites it.
- A `subprocess` invocation is not traced by `coverage`, so an `if __name__ ==
  "__main__"` guard stays uncovered. Execute the real script in-process with
  `runpy.run_path(path, run_name="__main__")` and assert `SystemExit.code` to
  cover that arc and the CLI entry point at once.
- Do not `git add -A` a coverage bootstrap: `.gitignore` hides the package
  directory but keeps distribution metadata, producing a committed half-package
  outside scope. Keep the bootstrap under `/tmp` and set `PYTHONPATH`.

## Why this is not finished

The WQUALITY-05 change itself is complete: `--check-runtime` and its 20 tests are
green, `scripts/gen-opencode.py` is at 100% line/branch coverage, and the
changed-script coverage gate passes. The only reason the repository-wide
`scripts/check.sh` (step 6) does not exit 0 is a pre-existing failure outside
this story's scope:

- Command: `bash scripts/check.sh` (and `python3 -I -m unittest discover -s scripts/tests -q`).
- Error: `FAIL: test_integrate_batch_retries_when_main_advanced (test_swarm.TwoTierTests)`,
  `AssertionError: 1 not greater than or equal to 2`, `Ran 472 tests`,
  `FAILED (failures=1)`.
- Most likely cause: the `SWARM_ALLOW_PROTECTED` / protected-file merge changes
  on `origin/main` altered `integrate_batch` so the re-gate after a failed push
  runs once instead of twice; the test assertion was not updated with it.
- What was tried: ran the test in isolation (fails deterministically); verified
  `scripts/swarm.py` and `scripts/tests/test_swarm.py` are byte-identical to
  `origin/main` (`git rev-parse` `b0377856…`); created a detached worktree of
  pristine `origin/main` and reproduced the identical failure there. This rules
  out the WQUALITY-05 diff as the cause.
- Exact next step for the owner/integrator: open a separate repair task scoped to
  `scripts/swarm.py` / `scripts/tests/test_swarm.py` to reconcile the re-gate
  count with the protected-file merge change; do not fold it into this story.
