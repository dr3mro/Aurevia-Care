# WQUALITY-05 — validate the runtime OpenCode profile separately from the generated config

## Summary

Added `--check-runtime` to `scripts/gen-opencode.py` and a 17-case suite in
`scripts/tests/test_opencode_profile.py`. The new mode validates the CI runtime
profile (`.github/opencode.ci.json`) on its own, independently of the generated
local config (`opencode.json`), which `check-pack.py` already covers for drift.
Requirement: **OPS-06** (CI policy and secret scanning). Synthetic fixtures only;
no dependency added; existing `--check` behaviour unchanged.

## Test evidence

Commands run from the repository root (Python 3.11). Coverage package 7.17.4
(pure-Python wheel) was bootstrapped into a temporary in-workspace directory
because the system Python has no pip; `PYTHONPATH` was set only for the coverage
run and the directory was removed before commit.

- `python3 -I -m unittest discover -s scripts/tests -p 'test_opencode_profile.py' -v`
  → `Ran 17 tests ... OK` (exit 0).
- `python3 -I scripts/gen-opencode.py --check-runtime` → exit 0, no output.
- `python3 -I -m unittest discover -s scripts/tests -q` → exit 0 (full tooling suite).
- `bash scripts/python-coverage.sh` → `python coverage: every changed script line is covered` (exit 0).
- `bash scripts/check.sh` → CHECKSH_RESULT (see note below on the worker artifact).

Worker artifact: in this cloud worker `opencode.json` is the CI profile copied
under `skip-worktree`, so `gen-opencode.py --check` and `check-pack.py` judge the
CI profile and report it stale (`opencode.json is out of date`). This is the
known OPS-CW-003-01 measurement artifact, not a change defect. For the local
gates the committed local profile (`git show HEAD:opencode.json`) was restored
temporarily and the CI profile copied back afterwards; the file was never
committed and `git status` shows it unmodified.

## Findings

- **Interpretation of the protected-path rule.** It checks file-edit tool
  permissions (`write`/`edit`/`patch`), not shell command permissions. The
  orchestrator has `shell: "*" allow` in the CI profile and owns `TODO.md` per
  AGENTS.md, so a literal "no agent can write" cannot apply to it; shell is
  governed separately by the bash permission list and the generator's explicit
  `SHELL_DENY`/`CI_SHELL_DENY`. Including shell here would make the repository
  profile fail its own gate. (Raised by the senior-Python reviewer; accepted.)
- **Reviewer detection** uses the exact catch-all deny dict, matching the
  convention already used by `scripts/check-pack.py`. A hand-edited reviewer
  expressed differently would be misclassified; the profile is generator-owned.
- **Narrow write patterns** such as `.github/ISSUE_TEMPLATE/*` may not match the
  representative protected files; the canonical `.github/*`, `TODO.md`,
  `.opencode/*` and `*` patterns are caught.
- **Model rule** fires only when a profile declares a `model` key; the generator
  emits none because the worker model is supplied from `slots.json` via the
  environment. It prevents an unapproved pinned model from being added later.
- **Malformed non-dict entries** in a hand-edited profile would raise rather than
  report a violation; the profile is machine-generated and `--check` detects
  drift from it.
- **No CI caller was added** for `--check-runtime`: the story scope is only the
  two files, so wiring it into a workflow is left to an integrator/owner.
- No dependency, lock file, tracker, `opencode.json`, workflow or `.opencode/`
  file was changed. Static analysis for this Python-only change: the repository
  `scripts/check-secrets.py`, `check-names.py`, `check-pack.py` and the full
  tooling suite ran green under `scripts/check.sh`.

## Lessons for workers

- In a cloud worker, `opencode.json` is the CI profile under `skip-worktree`:
  `gen-opencode.py --check` and `check-pack.py` judge that worktree file, not the
  committed local profile. Use `git show HEAD:opencode.json` to restore it for
  local gates, then copy `.github/opencode.ci.json` back; never commit it.
- `python-coverage.sh` needs the `coverage` package. Without pip, download the
  pure-Python `py3-none-any` wheel from PyPI, extract it into an in-workspace
  temp dir and set `PYTHONPATH` (network works from the workspace, not from an
  external `cd`).
- In temporary-profile tests, re-save the mutated dict before calling the
  checker; tests that delete or corrupt the file must call the checker directly
  instead of a helper that rewrites it.
