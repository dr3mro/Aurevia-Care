# AUD-20261121-11 — Extract one facility-code validator instead of five duplicated regex declarations

## Summary

The facility/code regex `[A-Z0-9_-]{2,32}` was declared five separate times (scheduling follow-up, scheduling inputs, check-in workflow inputs, tenancy facility service including its compound cursor regex, and clinical-note inputs). A single typed primitive `com.aurevia.smartclinic.api.contract.FacilityCode` now owns the expression. It follows the existing `CatalogCode` / `CanonicalUuid` convention: a record with a static `facilityCode(String)` factory, a shared deterministic `INVALID_MESSAGE`, a shared `PATTERN` regex fragment for compound tokens, and a compact constructor that rejects null / malformed codes. All five callers delegate to it and translate the single rejection into their own field-specific `422` error, so the identifier rule can be tightened in exactly one place. No behavior, status or error code changed; only the error detail text is unified.

## Lessons for workers

- When the same regex is declared in several trust-boundary validators, expose one shared regex-fragment constant beside the typed primitive so composite parsers (cursors, tokens) do not re-declare it; keep each caller's field-specific error code in its own exception translation rather than moving status codes into the primitive (`CatalogCode` / `CanonicalUuid` convention).
- In a cloud worker, a `check-pack` "stale opencode.json" result is usually the CI profile under `skip-worktree`, not HEAD truth: compare with `.github/opencode.ci.json` and `git show HEAD:opencode.json` before regenerating anything, and never edit `opencode.json` from a story worker.
- `scripts/check.sh` delegates to the module `check.sh` files, so it runs full `mvn verify` with every integration test. For a bounded story, run `scripts/quick-check.sh`'s policy checks individually plus targeted `-Dtest=...` tests and a targeted `jacoco:report`, and leave the full gate to the integrator.
