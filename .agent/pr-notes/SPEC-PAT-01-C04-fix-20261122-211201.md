## Lessons for workers

- On a "did not finish cleanly" fix attempt, first verify the committed work is actually broken
  before rewriting it: re-run the focused test and the module `check.sh`, then check the
  individual policy scripts. Green work usually means the prior session ended early or its
  notes were captured mid-write.
- For a test-only clause-proof task over an already-built domain, no TDD red run is possible:
  the proof passes against existing production code. Still verify the new suite is actually
  discovered with a targeted Jest run, because the full coverage-mode summary prints only
  aggregate counts.
- Write the fix-pass hand-off at the exact notes path in the prompt, including the `-fix-`
  segment; the first worker's timestamped path is not the path the integrator reads for this pass.
- Check `python3 -I scripts/check-docs.py` (prefix/link validation) and
  `python3 scripts/check-constraints.py --base origin/main` (no suppression/exclusion/skip)
