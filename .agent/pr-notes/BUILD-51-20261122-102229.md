## Requirements and acceptance mapping

- **OPS-07** (SMARTCLINIC_V1_SPEC.md line 140): tenant export with manifest, schema
  version, checksums, authorized documents, provenance and audit history. This
  slice renders the export request, the expiring download list with manifest
  checksum, record count and retention instant, and an explicit expired state
  that withholds the download action.
- **OPS-08** (SMARTCLINIC_V1_SPEC.md line 141): versioned onboarding manifest,
  deterministic mapping, dry-run counts / unsupported fields / duplicate risk /
  missing attachments / errors, provenance preservation and authorized sign-off.
  This slice builds a synthetic versioned manifest, renders the whole dry-run
  report and provides a named sign-off step bound to the reviewed manifest.
- **Acceptance 1 — expired export shown as expired**: `ExportPage.test.tsx`
  "shows an expired export as expired and withholds its download action"
  (clock injected after `expires_at`); pure rule in `exportState`.
- **Acceptance 2 — dry-run report lists unsupported fields**:
  `ImportPage.test.tsx` "lists unsupported fields and the other findings in the
  dry-run report" asserts `legacy_ssn` and `free_text_notes` in the dedicated list.
- **Acceptance 3 — forbidden state**: `ExportPage.test.tsx` / `ImportPage.test.tsx`
  "conceals the screen from a role without import/export permission" plus the
  API-403 tests that assert the shared `ForbiddenState`.
- **Only permitted roles**: export is `tenant_admin` only (matches API
  `ExportPermissionGuard`); import review and sign-off are `tenant_admin` and
  `privacy_auditor` (matches `ControlledImportService.AUTHORIZED_ROLES`). The role
  comes from `useRole()`/props, never from a form or the URL.

## Contract finding

The story says BUILD-41/BUILD-43 added these APIs to `contracts/openapi.yaml`.
At this checkout the routes exist only as Spring controllers
(`/api/v1/tenant/exports*`, `/api/v1/tenant/imports/*`); they are absent from
`contracts/openapi.yaml` and the generated `openapi.d.ts`. Scope forbids editing
either, so the feature follows the established `features/admin/api.ts` pattern:
`buildRequestDescriptor` supplies tenant/correlation/idempotency metadata from a
declared contract path and the `url` is bound to the live route, with locally
declared response types mirroring the Java records. See Findings and
`task-requests`.

## Findings

- No product defect found in the new screens. `contracts/openapi.yaml` and the
  generated client do not declare the OPS-07/OPS-08 routes despite the story
  text; the local descriptor override keeps the change inside scope but leaves
  a real contract gap (task-request 1).
- The OPS-07 API has no "list export jobs" route, so the download list is
  session-local and is lost on navigation/reload. The screen never claims
  durability (task-request 2).
- `tests/messageParity.test.ts` globs `../src/**/messages.ts` against a fixed
  registry outside this scope. The feature labels are therefore named
  `labels.ts`, following the existing `features/print/settings/labels.ts`
  precedent, with an in-scope `labels.test.ts` parity check. The global registry
  stays green and no file outside scope was edited.
- Pre-existing, unrelated: conflict markers are already committed in `HEAD` in
  `apps/api/src/main/java/com/aurevia/smartclinic/exchange/hl7/{Hl7ParseException,Hl7Parser,Hl7Segment}.java`
  (verified with `git show HEAD:…`). They are outside this scope and were left
  untouched (task-request 3).
- `downloadManifest` runs through the shared `send`, which parses JSON; the API
  returns the manifest as `application/json` bytes, so the pairing is valid.
- Simulated review only; no clinical or human acceptance evidence.

## Lessons for workers

- Before adding a `messages.ts` under staff-web features, check
  `tests/messageParity.test.ts`: any new `messages.ts` must also be registered in
  an out-of-scope fixed list. A feature-local `labels.ts` plus its own parity test
  satisfies UX-01 without touching that registry.
- `tsc --noEmit` with `noUnusedLocals` rejects an imported type that is only used
  indirectly; remove such imports before claiming green. Vitest alone does not
  catch it — run the module `check.sh`.
- `submitSignOff` in the Java API is a POST with no body for start/expire-style
  commands; staff-web commands still need an `Idempotency-Key`, so key the header
  off the HTTP method rather than the presence of a body.
- In a cloud worker, `git grep` conflict markers may come from pre-existing
  commits in `HEAD`; confirm with `git show HEAD:<path>` before attributing them
  to your own merge.
