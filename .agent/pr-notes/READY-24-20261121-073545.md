# READY-24 — Admin pages: /admin/config and /admin/audit on the real API

## Summary

Wired the two remaining administration screens to the real API. `ConfigPage.tsx`
looks a configuration key up, renders its immutable version and approval history
through the reused `ConfigEditor`, defines a version, approves a pending version
only after an explicit confirmation, and lists/defines catalog-family entries.
`AuditPage.tsx` submits bounded filters, pages the audit trail with an accumulating
"Load more", renders a distinct no-events state, and shows each instant in the
facility zone with the UTC instant on hover or focus. Both routes self-register in
`features/admin/routes.ts`. All data in every test is synthetic; no dependency,
migration, credential or patient data was added.

## Affected requirements

- **ADM-01** — tenant configuration and catalogs with immutable versions, named
  approval, effective dates and version history; define and approve commands carry
  a fresh idempotency key and a server-derived author/approver (no body tenant).
- **OPS-02** — append-only audit review with actor, purpose, scope, correlation,
  action, resource, outcome and instant; no client-side tamper claim is fabricated
  from API rows; outcomes are shown with word + shape-distinct glyph.
- WEB-09 (resilient screens) and UX-01 (bilingual, RTL, facility zone) are
  supporting requirements for the seven states, the Arabic bundle and time display.

## Risk class

Cross-boundary (staff web ↔ real configuration/catalog/audit API). Approval is an
irreversible administration command, so it is confirmed and assigned a fresh
idempotency key; the API remains the authorization authority. No signed clinical
data, patient association, prescribing or critical-result surface is changed.
Negative, forbidden, conflict and failure paths are covered with synthetic data.

## Authorization boundaries and audit events

- Tenant comes only from `useActiveOrganization()` and is sent as
  `X-Active-Organization` by `buildRequestDescriptor`; no request body or URL
  carries an organization. Path segments are `encodeURIComponent`-encoded.
- All four POST commands send a fresh `crypto.randomUUID()` `Idempotency-Key`.
  The approve request body contains only the optional note; approver identity is
  derived server-side.
- Audit is restricted in `app/navigation.ts` to `privacy_auditor` and
  `tenant_admin`; config to `tenant_admin`. A direct visit still fails closed via
  `StateView.forTransportError` mapping 403 → `ForbiddenState`.
- Audit filters stay in component state; nothing is written to local/session
  storage, the URL, a page title or a log. No audit event is added or changed by
  this client slice; server-side `AUDIT_READ`/`CONFIG_ADMIN` auditing remains the
  API's responsibility.

## Findings

- Two out-of-scope shared registry test files were extended mechanically:
  `src/app/routes.test.tsx` and `tests/app/AppShell.test.tsx` each assert the
  exact `createRoutes(false/true)` pattern array. Adding any feature route
  changes that array, so without these two-line insertions `check.sh` fails
  even though production code is correct. This follows the merged precedent of
  READY-21/22/23. No production file outside `apps/staff-web/src/features/admin`
  was changed. If the orchestrator prefers a strict scope, it should move these
  assertions to a tolerance check in a separate owner change.
- The audit chain badge is deliberately disabled for real API rows
  (`showChain={false}`): `AuditEvent` from the API has no `hash`/`previousHash`,
  so reusing the synthetic verifier would show a fabricated "chain not
  verified"/tamper claim. Server-side tamper detection remains authoritative.
- The facility time zone is the synthetic `America/New_York` fixture
  (`syntheticTimeZone`) because this slice has no facility-selection or tenant
  time-zone API to read; the label states the zone explicitly. Wiring a selected
  facility's zone is a follow-up when that context is available.
- `ConfigEditor` now clears the draft only when `onPropose` returns `true` (or a
  promise resolving to `true`); an existing `vi.fn()` returning `void` still
  clears, so the existing synthetic tests were not weakened. On a 409/412 the
  ConfigPage command returns `false` and the typed draft is kept, satisfying the
  conflict-state rule.
- `AuditEventList` makes each timestamp a `tabIndex={0}` focusable `<time>` so
  the UTC instant is available to keyboard users; this adds one tab stop per
  row. A UI owner may prefer a single per-row details control.
- `ConfigEditor` still requires a civil effective date when defining a version
  and sends it as `...T00:00:00Z`. The API's null "effective on approval" option
  is displayed as "not applicable" but is not offered as a define choice.
- The shared `ConflictState`, `ErrorState` Retry and `SessionExpiredState`
  Sign-in actions remain noops (READY-23 finding); `ApiPage`/`StateView` accept
  no callbacks. Out of scope and unchanged here.
- `bash scripts/check.sh` is red only at `check-pack.py` because of the
  skip-worktree CI-profile artifact described under Test evidence; this is an
  environment measurement, not a product defect, and the committed profile was
  not modified.
- Evidence provenance: all commands and results came from executed tools; the
  senior-react findings came from a read-only advisory subagent. No CI run,
  clinical reviewer, simulated user or human participant evidence was claimed.

## Lessons for workers

- `getByLabelText` also matches a `<section aria-label>`, so give a section and
  its input distinct accessible names; two fields with the same "Effective from"
  label also collide — add a distinct key for the second form.
- Clearing a cursor in a `useEffect` after applying filters issues two requests
  (one for the new filter with the old cursor, one after the reset). Reset the
  accumulated rows and the cursor in the same handler that applies the filters.
- With `exactOptionalPropertyTypes`, pass fresh-query filter objects built with
  conditional spreads; a literal `undefined` property does not typecheck.
- `PageSink` must receive a stable `onPage` callback, otherwise mapping data
  inside `append` re-appends a page when the locale changes. Accumulate raw API
  rows with `useCallback(..., [])` and map them at render time.
- An `ApiPage` `isEmpty` predicate receives the resolved body; a mocked call
  that was not primed returns `undefined`, so prime one response per reload the
  component triggers (a keyed remount counts as a reload).
- Read-only specialist review is useful before writing pages: it caught the
  civil-date/instant mismatch, the filter-reset double request and the necessity
  of updating the two shared exact route-array assertions.
