# SPEC-XCH-07-C02 — XCH-07 clause 2 (API test): display source unit, reference range, time and interpretation

## Summary

Test-only clause proof for XCH-07 clause 2. The clause is already implemented;
this change adds a real HTTP-level integration test that proves a patient trend
shows each observation's source unit, reference range, effective time and source
interpretation, that ineligible (non-final / `<`-qualified) results stay visible
as exclusions without being plotted, and that the clinical read is role-scoped
and tenant-isolated. A clause document records the evidence and Status
"Proven by tests". No production code, existing test, contract or migration was
changed. Evidence source: **tool** (Maven/Surefire, SpotBugs, policy scripts)
and **reviewer** (four read-only specialists); no simulated-user or human
participant was used, so no clinical acceptance is claimed.

## Lessons for workers

- For a test-only "(API test)" clause proof, the plan reviewer requires a real
  HTTP-level integration test mirroring `TrendingTest` (own DB, synthetic-auth,
  Flyway, RLS) — a fast domain-unit test alone is not sufficient. Give the class
  its own database name so parallel workers do not collide.
- `-Pno-security,fast -Dgroups=integration` is a vacuous-zero-test trap: the
  `fast` profile's `excludedGroups=integration` wins. Use `-Pno-security -Dgroups=integration -Dtest=ClassName`
  and open the Surefire report to confirm the test count; `-q` hides the console
  summary.
- Confirm the `opencode.json` skip-worktree false positive once with
  `git ls-files -v` and the failing command/final line, record it, run the
  remaining gate stages individually, and never edit or regenerate that file
  or re-diagnose it on a later pass.
- When the coverage reviewer flags an unasserted field on an excluded/displayed
  object, add the explicit equality assertion and re-run the targeted suite;
  "it is covered elsewhere" does not close a Required finding.
