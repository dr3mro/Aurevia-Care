## Lessons for workers

- For a clause-proof task where production code already exists, write the full enabled
  test (no `@Disabled`) and record that the first run is green because the behaviour is
  already implemented; prove detection power with specific status/value assertions and
  negative cases rather than with a red run.
- Use Jackson (`tools.jackson.databind.ObjectMapper`, already a test dependency) to build
  and parse request/response JSON when fields are JSON strings stored as jsonb — the
  hand-rolled `field()` helper in the neighbouring `PatientRegistrationTest` cannot read
  a JSON string that itself contains quotes.
- Any helper declaring `throws Exception` forces `throws Exception` on every calling
  `@Test` method; add it up front to avoid a compile-only failure.
- Confirm the `opencode.json` "stale" result once with `git ls-files -v` and
  `git show HEAD:opencode.json`, record it, and do not regenerate or edit the protected
  file; run the remaining gates individually.
- Run a newly added `@Tag("integration")` class directly with
  `mvn -Pno-security -Dtest=ClassName test` before any broader gate; it proves the
  Flyway/RLS setup in seconds.
