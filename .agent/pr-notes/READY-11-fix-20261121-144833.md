2. **LOW, pre-existing, not introduced:** `SecurityConfiguration.isBearerRequest` uses case-sensitive `startsWith("Bearer ")`. RFC 7235 auth-schemes are case-insensitive, so a client sending `bearer …` falls into the browser chain. The bounded Spring Security reviewer was asked to judge it and explicitly **did not** call it a blocker for READY-11: none of the six acceptance criteria or their tests exercise a lowercase scheme, and `Bearer` is conventional. It is now load-bearing for chain *selection* (not just CSRF bypass), so the reviewer recommends tracking it as a hardening item in a separate security-reviewed story — which is also why it was deliberately not silently changed here (it is shared with AUD-20261120-03 and widening the CSRF exemption needs tests touching both matchers).
3. **Pre-existing, out of scope (WEB-05):** both non-synthetic chains use `anyRequest().authenticated()`, so `GET /health/live` and `/health/ready` require a credential outside `synthetic-auth`. WEB-05 needs them unauthenticated; that belongs to a health-lifecycle story, not READY-11.
4. **Local `opencode.json` is a `skip-worktree` CI profile (re-confirmed this pass).** `git ls-files -v opencode.json` = `S`; regenerating locally with `scripts/gen-opencode.py` makes `gen-opencode.py --check` and `check-pack.py` green.
