## Lessons for workers

- Never put a bracketed placeholder token in the Test evidence or Coverage sections of a worker notes file: `worker_gate.validate_candidate` applies its placeholder regex to those two sections and fails the candidate. Describe placeholders in prose instead.
- Do not write review verdict lines before the reviewer has actually answered. The docs-only short-circuit in `check-verdicts.py` will not catch a fabricated GO line.
- Never cite TODO.md line numbers in a durable document. `TODO.md` is a regenerated view; name the task and quote its exact sentence instead, so a merge cannot turn a correct citation into a wrong one.
- A GitHub verification runbook that ticks a box, writes verified or fills a result cell defeats its own purpose. Keep the header, boxes, table and Approval in the nothing-verified state until a person runs it on GitHub. A scratch red proof is a deterministic local check, not GitHub evidence.
- `scripts/check-docs.py` applies its structural rules to `docs/operations/` as well as most of the tree; run it after every edit in that directory, and demonstrate the red case first with a malformed scratch copy.
