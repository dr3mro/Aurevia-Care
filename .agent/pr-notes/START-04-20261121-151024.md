## Findings

- **Declarations mistaken for telemetry are the main trap.** The 13 signals in
  `docs/operations/s_g5_06/operational-runbooks.md` and `infra/s_g5_06/recovery_evidence.py`
  are fail-closed evidence checks, not live alerting; the existing document says
  so explicitly. The runbooks keep that distinction.
- **No secret manager, rotation script or key-use audit exists.** Secrets are
  env vars / CI secrets (`application.yml`, `pom.xml`, workflows). `scripts/check-secrets.py`
  only proves no literal is in the tree. A historical `NVD_API_KEY` exposure is
  recorded in `BUGS.md` (`DS-G0-01-01`) with a durable owner decision not to
  rotate or rewrite history; the runbook states this is an incident-specific
  decision, not a general exemption.
- **No image vulnerability scanner, SBOM/signing implementation or CodeQL
  config** was found; OWASP, SpotBugs and the secret regex are the real checks.
- **No deploy/rollback or 5%/25%/100% rollout automation.** `infra/DEPLOYMENT.md`
  is a design handoff; `delivery.yml` publishes images and records digests but
  does not deploy. `WEB-11` and `WEB-13` rows are open.
- **Legal-holds endpoint nuance (corrected during review).** `POST /api/v1/messaging-governance/legal-holds`
  is a real controller, but `docs/operations/s_g5_08/README.md` states its
  policy tuple is a versioned-in-code stand-in, not a live policy-pack binding;
  the runbook describes it precisely and does not call it an approved hold system.
- **Docs-only commits do not trigger Delivery CI** (workflow `push`/`pull_request`
  paths ignore `docs/**` and `**/*.md`), so there is no SHA-linked CI run for this
  commit; the integrator's full gate on the merged state is the broader check.

## Lessons for workers

- Before writing operational docs, read the code and config for the actual
  environment-variable names, endpoints and gates. Plausible tools such as a
  pager, secret manager, image scanner, progressive rollout and rollback CLI
  exist only as spec rows or synthetic evaluators here — mark `NOT YET IN PLACE:`
  instead of inventing a command or contact.
- `python3 -I scripts/check-docs.py` validates every relative Markdown link and
  every mentioned ID whose prefix is defined in the specification; keep links
  relative and cite only defined prefixes (OPS, WEB, IAM, XCH, CLN, etc.). The
  notes directory is skipped, but the tracked docs are not.
- `scripts/check.sh` is not a fast check: it calls `apps/api/check.sh` →
  `mvn -q -B verify` and the DB/module gates. For a docs-only story run the
  applicable `check-docs.py` (plus cheap policy checks) and leave the full gate
  to the integrator.
- Distinguish "real endpoint whose policy is a stand-in" from "synthetic
  fixture": the governance controller is real code, the approved policy pack is
  not. Precision matters in incident documentation.
