## Findings

1. **Story vs quality gate on the single `@Disabled` test (owner decision needed).** The story
   (step 3) and the brief both explicitly require the complete would-be HTTP proof to be marked
   `@Disabled("GAP: …")`; the same package has a merged precedent
   (`CaptureChiefConcernHistoryExamAssessmentDiagnosesTest.java:303-313`, PR #863). However,
   `scripts/check-constraints.py` was added one hour AFTER that precedent (12:42 vs 13:41 on
   2026-11-22) and flags every newly added Java `@Disabled`, so `quality-gate.sh` rejects this
   change. The exact failing command and final line are in Test evidence item 5. The worker must
   not edit that protected script or add an exemption, so the resolution is an owner decision:
   either accept the story-mandated single GAP test for evidence-only clause tasks, or re-scope
   this task to put the would-be HTTP test verbatim in the doc's `## Gap` instead.
2. **Brief correction:** template persistence tables already exist with RLS in V80/V87, so the
   `## Gap` correctly says no new migration is required for the follow-up. The brief's conditional
   "migration with ENABLE/FORCE RLS if template tables are absent" does not apply.
3. **Fixture correction:** a patient insert in ORG_B failed until `reception-b` was seeded and the
   actor derived per organization — the V7 `set_patient_created_by_from_actor` trigger requires an
   authenticated user of the active tenant. This was a test-fixture fix only.
4. **`@SpringBootTest` retained deliberately** (story step 1 / brief "same database setup as the
   neighbouring tests") even though the active tests use an in-memory domain store. It requires
   PostgreSQL, which is available here; the test engineer preferred a plain JUnit class, but the
   authoritative story chooses the sibling fixture pattern.
5. **Environment artifacts** (opencode.json CI profile under `skip-worktree`, six `test_check_pack`
   failures) are reproduced once with evidence and not re-diagnosed; no protected file was edited.

## Lessons for workers

- For evidence-only clause tasks, check `scripts/check-constraints.py` before coding: any newly
  added `@Disabled("GAP: …")` in a `.java` file fails the constraint gate even though the story may
  mandate it (a merged sibling test predates the gate). Get an owner decision or use a doc-only gap
  route rather than discovering this after the work is done.
- When seeding patient fixtures across two tenants, seed a reception user in BOTH organizations and
  derive `app.actor` per organization; otherwise the patient-registration trigger aborts `@BeforeAll`.
- A cross-tenant 404 negative is only meaningful with an in-tenant precondition (assert v1 exists in
  ORG_A first), and a missing-field/dictionary negative must assert the exact violation string —
  `assertFalse(report.valid())` alone passes for unrelated reasons.
- Confirm a cloud-worker `opencode.json` "stale" report once with `git ls-files -v` and a comparison
  to `.github/opencode.ci.json`, then run the remaining gate stages individually; never regenerate
  the protected file from a worker.
