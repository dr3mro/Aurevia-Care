## Summary

Added a synthetic Playwright browser journey for clinician order entry under the
story scope `apps/staff-web/e2e/orderentry`. A dev-only harness mounts the three
real `src/features/orderentry` parts (`OrderEntryPanel`, `DeliveryChoice`,
`OrdersTab`) through the real `ThemeProvider`/`I18nProvider`; a deterministic
stub stands in for `/api/v1/orders/**`. The journey searches and places a lab
order sent electronically, places an imaging order with a required clinical
question, makes the partner stub refuse the send and switches that order to
print, checks status wording and that exactly one order exists after the switch,
then cancels one order and amends another. The same journey is asserted in
English and Arabic (RTL). No production source, dependency, migration or
tracker file was changed.

## Affected requirements

- LAB-01 — lab order entry, delivery choice and tracking (catalog search, electronic send, status wording).
- RAD-01 — imaging order with a mandatory clinical question; failed send falls back to print.
- WEB-09 — resilient bilingual screens; worded failed-send recovery, reason-backed cancel/amend, RTL wording.

## Findings

- The module `tsconfig.json` includes only `src`, `tests` and `vite.config.ts`, so `npm run typecheck` does not check `e2e/**`; I added an explicit `tsc` invocation (above) to prove the new e2e files type-check.
- Playwright was not installed in this worker. Environment-only setup (not committed): `npm ci --no-audit --no-fund`, `npx playwright install chromium`, `npx playwright install-deps chromium`. After that, the pre-existing print journey passed, confirming the harness pattern works here.
- The harness's `onOpenPrintPreview` callback places one print-mode order and shows the synthetic `placed → printed` timeline; that is the injected print-fallback seam the delivery part expects, not a direct import of the print feature.
- `git status` showed only the new in-scope directory plus Playwright's generated `apps/staff-web/test-results/`; the generated directory was removed before committing.
- No defect was found in the existing order-entry components.
- I did not run `scripts/check.sh`: it invokes `apps/api/check.sh` (`mvn -q -B verify`) and every database integration test, which this worker prompt forbids ("Never run the full mvn verify or any command that runs every integration test"). The scoped staff-web gate, the e2e journey, `scripts/check-docs.py`, `scripts/frontend-check.sh` and an explicit e2e typecheck were run instead; the integrator/Delivery runs the full gate.

## Lessons for workers

- Install the browser before assuming an e2e story is blocked: `npx playwright install chromium` plus `npx playwright install-deps chromium`; a missing `libglib-2.0.so.0` is an OS-dependency issue, not a test failure.
- A Vite-served harness under `e2e/<domain>/` needs an HTML file whose module script is a relative `./<name>.tsx`; Playwright can then navigate to `/e2e/<domain>/<name>.html` exactly as the print and radiology journeys do.
- Drive the partner failure from the stub's mutable state (`api.failNextSend = true`) rather than from component props, so the journey proves the real failure path reached the browser boundary.
- After a `git merge --no-edit origin/main`, check `git grep -nE '^(<<<<<<<|>>>>>>>) '` only for files you touched: committed conflict markers can exist in unrelated files and are not merge conflicts to resolve.
