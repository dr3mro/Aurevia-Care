## Lessons for workers

- When a clause spans plain and versioned search, make the tagged alternative a distinct entry whose name does not match the query but whose ingredient does; otherwise it becomes an extra hit and the "one item" assertion fails for the right implementation.
- `scripts/check-constraints.py` rejects an added Java `@Disabled`, so confirm the behaviour exists by reading the production fold before writing an evidence-only test; a genuine GAP test needs an explicit decision rather than a silent skip.
- In a cloud worker, confirm the `opencode.json` skip-worktree false positive once (`git ls-files -v opencode.json` → `S` plus `git show HEAD:opencode.json`), record the failing command and final line, then run the remaining gate stages individually; never regenerate or commit that protected file.
- A mocked repository does not prove tenant RLS. Cite the real-PostgreSQL integration test for durability/tenant scope and describe its fixtures precisely instead of claiming cross-tenant negative proof it does not contain.
- `mvn -Pno-security,fast -Dgroups=integration` does not run integration tests because the `fast` profile excludes them; never trust a green result from that combination.
