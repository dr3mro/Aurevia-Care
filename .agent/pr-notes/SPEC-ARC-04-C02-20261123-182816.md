## Findings

- **Implemented, not a GAP.** Context optimizer and test engineer confirmed the
  clause is satisfied by `ExchangeResponseInputs.uuid` plus the V21 tenant-scoped
  local-patient trigger and `SqlFailureTranslator`; XCH-01's `verifyPatient` is a
  different requirement and is not called by XCH-03 accept. No `@Disabled` test
  was written (story step 3 does not apply), and no production code was added.
- **Pre-existing drift (documented, not fixed).** The spec sample route
  `POST /api/v1/orders/{id}/accept` is not served; the live route is
  `POST /api/v1/xch03/orders/{id}/accept` (`ExchangeResponseController.java:33,88-92`).
  The live accept operation in `contracts/openapi.yaml` uses `RetryKey` and omits
  `If-Match` plus 412/428 responses, and the controller does not consume
  `Idempotency-Key`. Parts are already owned by `READY-42` (durable idempotency
  ledger); the spec-sample-path mismatch needs an owner decision. No new task
  request is raised because the work does not depend on them.
- **Reviewer optional findings resolved.** DevSecOps noted that the seed helper's

## Lessons for workers

- For a clause that is already implemented, prove it with active HTTP tests and
  record that no red run exists; do not add a `@Disabled("GAP…")` test or invent
  a failing baseline.
- Pin negative tests to their real reason: send a fully valid body for the 403
  role case, give the peer a genuine role in its own tenant for the 404 case,
  advance the version with a real command before the 412 case, and assert the
  distinguishing message (`referenced record not found` vs `order not found`).
- Use a distinct database name per test class; a neighbouring XCH-03 suite drops
  `smartclinic_xch03_it` in its own `@BeforeAll`.
- Assert JSON null with `isNull()` — a `NullNode.asText()` returns the string
  `"null"` and would pass a wrong-reason assertion.
