## Summary

Unifies the two untracked `[0-9a-f]{64}` SHA-256 hex validators (ARC-05 delivery payload digest and OPS-08 onboarding import checksum/signature) behind one typed primitive in `api/contract`, mirroring the established `CanonicalUuid` pattern. Adds a new `Sha256Hex` record with a single `sha256Hex(String)` entry point that accepts exactly 64 hex digits in either case, normalizes to canonical lowercase, and throws `IllegalArgumentException(INVALID_MESSAGE)` otherwise. `DeliveryInputs.digest` translates that rejection into its existing `422 INVALID_DIGEST`; `OnboardingImportService.isSha256` translates it to a boolean. Each caller keeps its own error vocabulary while the boundary rule lives in one place. Both local regex declarations are deleted.

This is the scoped half of the story: the `documents`/`messaging/attachments` copy was already extracted into `UploadValidation` by AUD-20261121-08 (PR #478), which is outside this task's `scope`. See `## Findings` and the `task-requests` block.

## Affected requirements

- ARC-03 — canonical typed value primitive and machine-readable 422 at API trust boundaries (pattern from `CanonicalUuid`).
- ARC-05 — `DeliveryInputs.digest` validates `payloadDigest` before any durable event/store call.
- OPS-08 — `OnboardingImportService.isSha256` validates attachment checksums and historical-signature checksums in a synthetic, provenance-preserving dry run.

## Risk class

Routine (contained local refactor). No schema, migration, wire format, controller signature or clinical decision logic changes. One intentional behavior widening: `OnboardingImportService` now accepts uppercase hex checksums (previously lowercase-only), matching `DeliveryInputs` and `CanonicalUuid`; hex is case-insensitive, so this cannot reject a previously valid value.

### Senior-backend review outcome (3 findings, all addressed)

- **Finding 1 (Medium, normalization discarded at import boundary).** Reviewer noted `isSha256` uses the primitive as a boolean and throws away the canonical value, so the original uppercase checksum text flows into `ImportedRecord` and `ControlledImportService.canonicalRecord`/`batchDigest`, making manifests identical except for checksum case produce different signed digests. Resolution: this is required OPS-08 semantics, not a defect — the spec says "Preserve import provenance and historical signature evidence without creating a new attestation", so original signed text must be kept verbatim. Documented that choice in the `Sha256Hex` class Javadoc and in an inline comment at `isSha256`, and strengthened `uppercaseHexChecksumsAreAcceptedByTheSharedDigestRule` to assert the original uppercase checksum is preserved in `ImportedRecord.historicalSignature().checksum()`. No behavior change to canonical hashing (same input still yields the same digest).
- **Finding 2 (Low, stale `DeliveryInputs.digest` Javadoc).** Already fixed before the review: now reads "normalizing uppercase hex to lowercase", returns canonical lowercase, and `@throws ... not 64 hexadecimal characters`.
- **Finding 3 (Low, `Sha256Hex` overstates global ownership).** Fixed: class Javadoc now says "shared by the migrated event and import validators", names ARC-05/OPS-08, explains that other checksum boundaries keep their own rule until separately migrated, and explains why the two callers use the canonical form differently.

## Lessons for workers

- Re-check the live tree before trusting a story's line numbers: AUD-08 had already moved two of the four regex copies, so the "four callers" phrasing was stale. A single `grep -rn` at the start resolves this without widening scope.
- `CanonicalUuid` in `api/contract` is the canonical template for a trust-boundary text primitive: a record, an `INVALID_MESSAGE` constant, a static `sha256Hex(...)`-style factory, and a compact constructor that throws `IllegalArgumentException` for callers to translate. Reuse it instead of inventing a new shape.
- Do not run `scripts/check.sh` as a swarm worker: it calls `apps/api/check.sh` → `mvn verify` (full integration + JaCoCo + OWASP), which times out the run. Run targeted `mvn -Pno-security test -Dtest=...` plus the individual fast policy scripts, then leave the full gate to the integrator.
- A full `unittest discover -s scripts/tests` can be red in a cloud worker purely from the skip-worktree `opencode.json` CI profile; isolate the actually relevant test module (`-p test_java_conventions.py`) before treating it as your regression.
