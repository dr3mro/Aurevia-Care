## Findings

- Root cause of the recurring red (high confidence, tool evidence reproduced this pass):
  `8f363e02` changed `worker_gate.main()` from `failing = failing_classes(REPORTS)` to
  `reports = Path(args[1]) if ... else Path(REPORTS); usable = reports.is_dir() and usable_reports(reports)`
  (`worker_gate.py:259-260`). `usable_reports()` globs `reports_dir` (line 63) and `Path.glob` on
  this Python 3.11 runner raises `FileNotFoundError` for a missing directory. Two tests mock only
  `Path.is_dir -> True` and call `main(["1"])` with no second argument, so `reports` is the
  non-existent legacy default and the glob raises. The regression is pre-existing on
  `origin/main`, not introduced by BUILD-41.
- Bounded fix for the owning maintainer (exact, verified against current HEAD; **do not apply in
  this worker** — `scripts/` is protected):
  - `scripts/tests/test_worker_gate.py::MainTest::test_integration_failure_still_fails_the_gate`
    (lines 328-336): create `tempfile.TemporaryDirectory()`, write one parseable
    `TEST-FooTest.xml` (`<testsuite name="FooTest" tests="1" failures="1" errors="0" skipped="0"></testsuite>`)
    into it, drop the `Path.is_dir -> True` mock, keep the `failing_classes` mock returning
    `{"RxTransmissionFlowTest"}` and the `main(["1", reports_dir]) == 1` assertion.
  - `scripts/tests/test_worker_gate_coverage.py::MainTest::test_maven_failure_with_failing_reports_still_fails`
    (~line 552-555): do the same, reusing that file's existing `write_report` / `suite_xml`
    helpers (lines 56-65); extend its `run_main` / `patch_common` (lines 504-521) so `reports=True`
    builds a real directory with one parseable `TEST-*.xml` and passes it as `argv[1]`, while
    `reports=False` keeps the `is_dir -> False` "no reports" branch covered.
  - Prove with `rm -rf apps/api/target/surefire-reports && python3 -I -m unittest discover -s scripts/tests`
    → 0 errors (only the six skip-worktree `test_check_pack` failures expected in this runner),
    then `bash scripts/python-coverage.sh`, `bash scripts/check.sh`, `bash scripts/integrator-gate.sh`;
    `mvn -Pno-security verify` must stay green. No Java, migration or baseline file is touched.
- Alternative production-side fix (maintainer's call): make `usable_reports()` treat a missing
  directory as `False` (catch `OSError` around the glob) and add a test for that branch. The

## Lessons for workers

- When a change alters a shared function's contract (`worker_gate.main()` now needs an explicit
  fresh report directory), update every existing caller and unit test in the same commit; mocking
  `Path.is_dir` is not a substitute for a real directory once the function globs it.
- A test that passes only because a prior command happened to create a build artifact
  (`apps/api/target/surefire-reports`) is not hermetic. Give it a `TemporaryDirectory` with a
  parseable `TEST-*.xml`.
- Before re-running a fix, inspect `git log origin/main..HEAD`; earlier workers may already have
  applied it, and the correct job may be independent verification plus a fresh notes file.
- Distinguish a pre-existing failure on `main` from a branch defect; a failure that reproduces on
  clean `origin/main` belongs to its owning change, not to the story whose PR happens to be red.
- Respect protected paths: a worker PR touching `scripts/`, `.opencode/`, `.github/`,
  `opencode.json` or a tracker is never auto-merged, `worker_gate.validate_candidate` flags it as a
  scope violation, and `scope_ok()` rejects protected paths in `task-requests`. Put the finding in
  the notes hand-off.
- In this cloud worker `opencode.json` is a skip-worktree CI profile. Never regenerate or commit
  it; verify HEAD truth with `git show HEAD:opencode.json`.
- Do not trust a prior pass's "Maven Central 429" note as permanent: this pass the same targeted
  Maven command succeeded. Re-run the exact command before declaring coverage unreproducible.
