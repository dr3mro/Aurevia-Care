# AUD-20261121-08 — Deduplicate the ArtifactInputs / AttachmentInputs upload validators

## Summary

`ArtifactInputs` (documents/X-03) and `AttachmentInputs` (messaging attachments/MSG-03) each carried their own copy of the 10 MiB size bound and the UUID, key, path-free file-name, hex-magic, SHA-256-checksum, size, detail, object-key, id and `INVALID_<FIELD>`-code rules. Any tightening of a bound or traversal guard had to be made twice and could drift into a file-validation hole. I extracted one pure, typed primitive `com.aurevia.smartclinic.documents.UploadValidation` that owns these rules and left only the module-specific parsers (`MediaType`/`FileType`, `Language`, `positiveVersion`, `verifiedObjectKey`, `pdfObjectKey`) in their owning classes. Both validators now delegate to the shared primitive; public method signatures, error codes and messages are unchanged, so no caller or contract changed. A dedicated `UploadValidationTest` (10 tests) pins the shared rules, including path traversal and Arabic/RTL names.

Evidence source: executed file reads, `grep`, Maven/Surefire and JaCoCo XML (tool), plus one bounded simulated `smartclinic-senior-backend` design review. No human, clinical or simulated-user evidence and no patient data.

## Affected requirements

- **ARC-06** — document-artifact quarantine, upload validation and mediated download (`ArtifactInputs`, `UploadValidation`).

## Findings

1. **Third divergent file-name validator (recorded, not changed).** `apps/api/src/main/java/com/aurevia/smartclinic/documents/DocumentInputs.java:31` declares `[^\x00-\x1F/\\]{1,180}` — a 180-character bound and no `contains("..")` guard — while the now-shared primitive uses `{1,200}` plus explicit parent-traversal rejection. It belongs to CLN-07/ARC-03, not to the ARC-06/MSG-03 pair named by this story; migrating it would change accepted input and its tests, so it was left untouched. A bounded follow-up is requested below.
2. **Pre-existing dead HTTP entry point (recorded, not changed).** `QuarantineService` (the X-03 quarantine service whose `upload`/`scan` commands are validated by `ArtifactInputs`) has no production caller — a repository grep for `QuarantineService` finds only its own file; `DocumentController` exposes associations/rendered paths but no upload/scan route. The validators are exercised through `DocumentArtifactTest` and the controller via `DocumentContentControllerTest`. This is a pre-existing reachability gap, not introduced here, and outside this story's scope.
3. **Placement decision.** `UploadValidation` lives in `com.aurevia.smartclinic.documents`, so `messaging.attachments` imports it. This is acceptable because the primitive imports only `java.util.*` and `com.aurevia.smartclinic.api.ApiException` — it is type-agnostic and references neither domain contract — and `printing.HandoutService` already imports `ArtifactInputs`, so the dependency direction is not new. A neutral home (`api/contract`) would be cleaner but is owned by another worker (AUD-20261121-10/13) and outside this story's scope.
4. **Environment-only gate noise:** `check-pack.py` / 5 `test_check_pack` failures from the worktree CI `opencode.json` under `skip-worktree` (OPS-CW-003-01), reproduced at HEAD. No `opencode.json`, `scripts/` or tracker file was edited.

## Lessons for workers

- Before extracting a shared primitive, check whether the two contracts' enum parsers have different failure semantics (`ScanVerdict.from` returns `null` in documents but throws in attachments). Have the shared primitive return a validated **wire string** and let each caller map it to its own enum; do not reuse divergent parsers.
- Copy validation regexes verbatim when moving them: `KEY` `{1,63}`, `FILE_NAME` `[^/\\\x00-\x1F]{1,200}` **plus** the separate `contains("..")` guard (a path such as `../x` fails the regex, but `notes..pdf` only fails the traversal guard), and keep `toLowerCase(Locale.ROOT)`/`toUpperCase(Locale.ROOT)` for SpotBugs.
- In this cloud worker, a red `check-pack.py` / `test_check_pack` means the CI `opencode.json` is active under `skip-worktree`; verify with `git show HEAD:opencode.json` and do not regenerate or commit it.
- A full Java unit suite plus `jacoco:report` and a small XML parse gives fast per-class 100% proof without the forbidden ten-minute `mvn verify`; Surefire report totals are a compact entry-point-to-test trace.
- When the story names a specific pair of near-duplicate classes, record other divergent copies found in the same directory as findings/task-requests instead of silently widening the refactor.
