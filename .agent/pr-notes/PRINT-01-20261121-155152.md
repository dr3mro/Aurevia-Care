# PRINT-01 — API: render a prescription, lab order, imaging order, chart summary or report as a patient handout PDF

## Summary

Added a bounded `com.aurevia.printing` package with one service (`HandoutService`) that renders five handout kinds as immutable, versioned A4 PDFs. The service validates tenant, language and revision selectors, applies kind-specific print policy, reuses an unchanged source's original rendering, and renders a new version when the bound source revision or checksum changes. It reuses `documents.PdfRenderer`, `DocumentModel.PdfSpec`, `ArtifactInputs`, `DocumentContract.Actor`, `NoteChecksum` and the domain state vocabularies from `prescription`, `lab`, `radiology` and `clinical.notes`. No dependency was added and no file outside the two scoped directories was changed.

Cross-boundary (reuses the documents renderer and four domain vocabularies) but bounded to a new package. Print endpoints, role permissions, audit trail and durable storage are deliberately PRINT-02/PRINT-03 scope; no HTTP surface was added here.

## Data changes

None. No migration, no table, no backfill. `LocalHandoutArchive` is an in-process, tenant-keyed registry that gives the service stable versions within a process; durable handout persistence is a later printing story. No patient data, credential or real identifier appears in code or fixtures (`org-alpha`, `PAT-SYN-1`, `Synthetic Patient`, fixed 2026-11-21T10:15:00Z).

## Authorization boundaries and audit events

Tenant: `HandoutSource.organizationId` must equal the freshly derived `Actor.organizationId`, otherwise 403 `WRONG_TENANT` before any render. Missing actor → 403 `FORBIDDEN`. State/channel refusals are 409 `SOURCE_NOT_PLACED`, `SOURCE_NOT_SIGNED`, `PRINT_CHANNEL_NOT_APPROVED`; invalid language/selector → 422 from `ArtifactInputs`. No role widening is accepted from the request; endpoint permissions and print audit belong to PRINT-02. No new audit event type was added in this slice.

## Migration and rollout considerations

None. New Spring `@Configuration` exposes `HandoutService` as a bean for later endpoint injection; no existing bean or route is modified. `scripts/check-wiring.py` reports no new finding.

## Clinical and architecture review

Simulated static review only: prescribed-channel gate, signed-content gate and tenant isolation are enforced with negative tests. A real clinical sign-off for patient-facing Arabic copy and the patient-release policy is a G5 gate and is not claimed here. The font in the shared renderer is the existing synthetic TrueType placeholder (S-G1-07 explicitly deferred production glyph shaping and font licensing to an approved rendering library); this story does not change it.

## Findings

- The worker `worker-check.sh` / `check.sh` gates are blocked in this environment by the skip-worktree CI `opencode.json` profile (`check-pack: opencode.json is stale`) and the same 3 `test_check_pack` failures. Verified with `git ls-files -v opencode.json` → `S`; not caused by this change and not repaired here (protected file).
- `LocalHandoutArchive` is process-local by design and is deliberately not named `InMemory*`/`*Store`; durable, audited handout version storage is PRINT-02/PRINT-03. The service is exposed as a Spring bean for later controller injection, so check-wiring sees no unreferenced service.
- No HTTP endpoint, OpenAPI entry or migration was added because the story scope and TODO assign them to later printing stories. This story is complete as the bounded rendering slice, not as a deployable print feature.
- No defects found in the reused documents renderer; its deterministic bytes made reprint identity assertions possible without mocking.

## Lessons for workers

- Reuse `documents.PdfRenderer`/`PdfSpec` rather than writing a second PDF writer: it already owns A4, font embedding, direction, page numbers and determinism, so the new tests only need to assert the header/provenance and version behaviour.
- `check-wiring.py` flags any `*Service` that no other main class mentions and any `*Store` interface without a `Jdbc*` implementation. A plain domain service exposed via a small `@Configuration` bean satisfies both without adding endpoints outside scope.
- A "changed source" can keep the same revision number and change only its checksum; cover that `&&` branch explicitly or JaCoCo reports 5/6 on the archive.
- Do not try to regenerate `opencode.json` from a cloud worker: `git ls-files -v` shows `S`, and the resulting `check-pack` failures are a measurement artifact of the CI profile, not a change defect.
