# AUD-20261121-02 — Rename Xch03 requirement-ID classes to business-domain names

## Summary

Renamed the six `Xch03*` production classes in `exchange/response` to `ExchangeResponse*` using `git mv` (history preserved), renamed the five in-scope test files and their inner test classes to match, updated the `api/authorization` callers and the catalog identifier constant to a business-domain name, and added a naming-guard test proving the new names are wired. ## Findings

1. **Catalog wire identifier deliberately kept stable.** `CommandCatalog.EXCHANGE_RESPONSE_POLICY` was renamed from `EXCHANGE_POLICY`, but its value remains `"Xch03ActionPolicy"`. This string is emitted as `x-smartclinic-policy` into the generated OpenAPI (`contracts/openapi/generated/openapi.yaml`, `manifest.json`) and is pinned by `CommandClientGeneratorTest.committedArtifactsMatchAFreshGeneration` and `contracts/openapi/check.py`. Those artifacts are outside this story's scope, and the story directs contract/rollback compatibility for published identifiers. A Javadoc note in `CommandCatalog` records it as deliberate debt. Changing the value is available as the follow-up request below.
2. **Two out-of-scope Markdown link edits were unavoidable.** Renaming `Xch03Controller.java`/`Xch03Service.java` breaks relative links that `scripts/check-docs.py` validates in `docs/reference/partner-api-guide.md` and `docs/spec/clauses/product/closed-loop-orders-diagnostic-results-specialty-referrals.md`. Only the path strings were updated (`Xch03*` → `ExchangeResponse*`); no prose or requirement IDs changed. Without these two mechanical edits the worker gate and integrator `check.sh` would fail. No other active story touches these two files.
3. **`check-pack.py` / 5 tooling tests fail on a known environment artifact.** The worktree `opencode.json` is the CI profile copied under `skip-worktree` (`git ls-files -v opencode.json` → `S`), so `gen-opencode.py --check` compares the CI profile against the committed local profile and reports staleness. `git show HEAD:opencode.json` differs from the worktree file; this predates and is unrelated to this diff (MEMORY.md, dispatch-3 finding). The Java/docs diff touches no `opencode.json`, `.opencode/` or `scripts/` file.
4. **Deliberate debt retained per the story.** Public route `/api/v1/xch03/orders`, DB tables `xch03_*`, `V21__xch03_order_response.sql`, and the `scripts/wiring-baseline.json` `requirement-id-name` entries for the old paths are unchanged. `check-wiring.py` now reports those six entries as "fixed" (informational notes, exit 0), exactly as expected; removing them is maintainer-owned.

## Lessons for workers

- Before renaming any Java class, grep the whole repository for both the class name and the *file path*. `scripts/check-docs.py` fails on broken relative Markdown links, and `CommandClientGeneratorTest.committedArtifactsMatchAFreshGeneration` pins generated OpenAPI artifacts to catalog string constants — a "pure" rename can break both gates.
- `mvn -Pno-security,fast -Dgroups=integration` does **not** run integration tests: the `fast` profile's `excludedGroups=integration` wins. Use `mvn -Pno-security -Dgroups=integration` (as `worker-check.sh` does) and confirm the Surefire report shows the expected test count before trusting the result.
- In a cloud worker the `opencode.json` skip-worktree CI profile makes `check-pack.py` and five `test_check_pack` tests report staleness. Treat that as the documented environment artifact, not as a change-induced failure, and record it with the `git ls-files -v opencode.json` evidence.
