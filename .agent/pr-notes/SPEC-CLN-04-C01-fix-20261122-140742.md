## Lessons for workers

- A "did not finish cleanly" flag with no failing command is usually the
  `check-pack.py` CI-profile `skip-worktree` false positive: confirm once with
  `git ls-files -v opencode.json` and a clean `git diff HEAD -- opencode.json`,
  run the remaining stages individually, and never regenerate that protected
  file from a worker.
- On a fix pass, write the notes file named in the prompt even when the source
  change was already committed in an earlier pass; a correctly named hand-off
  is part of "finished cleanly".
- A base-branch `testCompile` error blocks every targeted Maven test. When the
  broken file is out of scope, prove your own test with a temporary, byte-exact
  removal of only that file, restore it, and verify `git status --short` and a
  `git diff --quiet origin/main --` check on that path before finishing.
- Take the version number from the define command result; the JDBC sequence and
  the in-memory fake number the first version differently, and the clause does
  not prescribe a starting number. Give each integration test its own random
  organization so per-tenant version histories do not leak between tests.
