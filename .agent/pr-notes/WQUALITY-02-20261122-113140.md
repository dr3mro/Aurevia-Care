## Findings

- The eight full-suite failures are worker-image limits, confirmed once: `git ls-files -v opencode.json` → `S` (skip-worktree CI profile), and the committed local profile is `git show HEAD:opencode.json`; the `worker_gate` errors are `FileNotFoundError: apps/api/target/surefire-reports` (no Maven build here). No protected file edited, no re-diagnosis.
- `HEAD` already contains unresolved conflict markers in three unrelated HL7 Java files (`exchange/hl7/Hl7ParseException.java`, `Hl7Parser.java`, `Hl7Segment.java`, from `origin/swarm/BUILD-37-469`). My `git merge --no-edit origin/main` was a no-op; these are pre-existing and outside this task's scope, so I did not touch them. The integrator should resolve them.
- Interpretation of "once per head SHA and then needs-human": the `DRAFT_FIX` path calls existing `fail(simple=True)`, which adds `needs-fix`/`fix-N` and dispatches a fix worker. `plan_integration` then skips that draft (blocked by `needs-fix`) until the fix worker pushes a new head; `pr_flow`'s needs-fix branch clears the label and marks the PR ready once Delivery passes, while `fail`'s existing fix → debugger → `needs-human` escalation handles persistent failure. The escalation is deliberately delegated to existing machinery to keep this change small; a follow-up could make the per-SHA cap explicit in `draft_recovery` if the integrator wants stricter behavior.

## Lessons for workers

- When a story's scope lists only a new test file (not `test_swarm.py`), do not change `pr_flow`'s draft block: `test_swarm.py::PrFlowTests::test_a_draft_nobody_took_goes_to_a_fix_worker_and_starts_a_wave` asserts a passed-checks draft is sent to a fix, so a `draft_recovery` rewrite there breaks an out-of-scope test. Wire recovery into `plan_integration` instead (its prior draft test uses fixtures with no head, which classify as `leave` and keep passing).
- This worker has no `coverage` module and no `pip`; prove script coverage with `trace.Trace(count=1)` hit counts plus an explicit branch→test list, as WQUALITY-01 recorded.
- `check-pack.py`'s "opencode.json is stale" and `worker_gate`'s missing surefire-reports are documented worker false positives — confirm once with `git ls-files -v opencode.json`, run the remaining checks individually, and never edit the protected file to make them pass.
