## Findings

- Root cause (confidence high, tool evidence): commit `8f363e02` (FIX-WORKER-REPORTS,
  PR #680, already on `origin/main`) changed `worker_gate.main()` from
  `failing = failing_classes(REPORTS)` to reading `reports = Path(args[1])` and calling
  `usable_reports(reports)`, which globs a path without checking it exists. Two tests

  empty, so the regression is pre-existing on main and unrelated to BUILD-41.
- Order dependency (proved this pass): the two errors vanish whenever
  `apps/api/target/surefire-reports` exists with parseable `TEST-*.xml`, which is why
  local Maven-then-Python runs look green while CI's policy job (before the Java job
  creates reports) stays red. With reports present the full Python suite fails only on
  the six skip-worktree `test_check_pack` cases.
- Bounded fix plan (from the earlier step-5 debugger report, treated as notes, for the
  owning maintainer): in `scripts/tests/test_worker_gate.py`
  (`test_integration_failure_still_fails_the_gate`, ~line 336) create a

## Lessons for workers

- JaCoCo coverage of a JDBC store depends on the integration test: a unit-only pattern
  leaves `JdbcExportStore` under-covered; including `TenantExport*Test`
  (`TenantExportIntegrationTest`, real PostgreSQL) brings it to 100%. Always run the full
  pattern `-Dtest='Export*Test,ExportPermissionGuardTest,JdbcExportStoreTest,TenantExport*Test'`
  when claiming 100%.
- When a change alters the contract of a shared function (`worker_gate.main()` now needs
  an explicit fresh report directory), update *all* callers and unit tests in the same
  commit; mocking `Path.is_dir` is not a substitute for a real directory once the function
  globs it.
- A test that passes only because a previous command created a build artifact
  (`apps/api/target/surefire-reports`) is not hermetic. Give it its own
  `TemporaryDirectory` with a parseable `TEST-*.xml`.
- Before re-running a fix, inspect `git log origin/main..HEAD`: earlier workers may already
  have applied it, and the correct job is independent verification plus a fresh notes
  file. Do not redo what earlier findings record as tried.
- Distinguish a pre-existing failure on `main` from a branch defect. A failure that
  reproduces with `scripts/` identical to `origin/main` belongs to its owning change, not
  to the story whose PR happens to be red.
- Respect protected paths: a swarm PR touching `scripts/`, `.opencode/`, `.github/`,
  `opencode.json` or a tracker is never auto-merged, and `worker_gate.validate_candidate`
  flags it as a scope violation. Put the finding in the notes hand-off instead.
- In this cloud worker `opencode.json` is a skip-worktree CI profile: `git ls-files -v`
  shows `S`, `gen-opencode.py --check` judges the CI bytes and reports false staleness,
  while `git show HEAD:opencode.json` is the committed local profile. Never regenerate or
  commit that file.
