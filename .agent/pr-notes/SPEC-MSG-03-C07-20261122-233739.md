## Findings

- The brief and task step 3 suggest writing a complete `@Disabled("GAP: ...")` test for the
  missing byte-for-byte behaviour. That is wrong for this worker run:
  `scripts/check-constraints.py:56` flags any newly added `@Disabled` in a Java file and
  `scripts/quality-gate.sh` runs it with `--require-base`, so a new GAP-disabled test would
  fail the task twice and be sent back. The four existing GAP-disabled tests in `main` are
  grandfathered (the check only scans added lines). I documented the complete test design
  under `## Gap` in the clause doc instead and added no disabled test.
- The brief was also imprecise about "checksum equals SHA-256 of bytes": this class supplies
  a checksum derived from the synthetic bytes using the controller's SHA-256/HexFormat
  pattern and proves its preservation; it does not drive the multipart controller. `## Evidence`
  marks `AttachmentController` as REFERENCED only and cites the existing
  `AttachmentControllerHttpTest.uploadsThroughMultipartScansAndDownloads` as the HTTP proof.
- Environment artifact (OPS-CW-003-01): `check-pack.py` and six `test_check_pack` tests fail
  only because the CI `opencode.json` is under skip-worktree. Already recorded in MEMORY.md;
  no protected file was edited.
- PostgreSQL `timestamptz` rounds Java nanoseconds to microseconds. Exact `Instant`
  equality on `createdAt` failed; the test now uses a one-microsecond tolerance helper,
  which still proves the binding was not rewritten.
- Pre-existing, out of scope: committed HEAD contains conflict markers in three
  `apps/api/src/main/java/com/aurevia/exchange/hl7/` files
  (`Hl7ParseException.java:6,10`, `Hl7Parser.java:14,18`, `Hl7Segment.java:10,14`). They are
  in `origin/main`, not in my working tree, and are unrelated to `messaging/attachments`;
  I left them untouched. No conflict markers are in any file I changed.
- Byte-for-byte original storage exists only in the parallel staff slice
  (`JdbcStaffAttachmentStore`, `FileSystemObjectStore.getVerified`), not on the patient
  path this story covers; `messaging/attachments` injects no object-store port. Recorded in
  `## Gap` as two future tasks.

## Lessons for workers

- `mvn -Pno-security,fast -Dgroups=integration` does NOT run integration tests (`fast` wins
  over `-Dgroups`); always confirm the Surefire XML count. A bare `spotbugs:check` is
  vacuously green; compile first.
- Under forced RLS, a "count is unchanged" assertion is vacuous unless the count binds the
  owning tenant AND asserts a non-zero baseline. Bind `app.current_org` on both sides.
- A JDBC round-trip of `Instant` through `timestamptz` is rounded to microseconds; compare
  with a small tolerance instead of exact equality when proving a timestamp was preserved.
- Returned DTOs are produced by `withState` and can hide a failed persistence write; reload
  from the store and assert the durable binding columns.
- Never add a new `@Disabled` to satisfy a GAP: `scripts/check-constraints.py` rejects it.
  Record the complete test design in the clause doc's `## Gap` and keep the PR green.
