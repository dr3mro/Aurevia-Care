# SPEC-MSG-04-C04 — MSG-04 clause 4 API test

## Summary

Prove with one enabled Java test class and one evidence doc that MSG-04 clause 4
("Use unit-approved templates or approved free text within the sender's professional
scope.") is enforced: only a template approved for the sender's unit and tenant, or
clinician-scoped free text, may be sent; out-of-scope roles, units, tenants and
contexts are refused. Test and documentation only; no production code, existing
test, contract or migration is changed.

MSG-04 (clause 4). Related tracked debt, not changed here: READY-40 (durable store),
FIX-OPENAPI-01/02/03/04 (contract route parity).

authorization boundary), so the negatives were reviewed by devsecops and the
matrix by the test engineer.

## Review owner

The tests exercise the implemented boundaries through `InstructionController`:

## Findings

- The senior developer brief said to use `Clock.fixed` through a three-argument
  `InstructionService` constructor. That constructor is package-private to
  `com.aurevia.messaging.instructions`, so the mandated `messaging.clauses`
  test cannot call it. The public two-argument constructor is used instead and time
  assertions were limited to `approvedBy` and a non-null `approvedAt`. No third
  fixture file was added, keeping the two-file scope.
- The brief suggested `.agent/pr-notes/SPEC-MSG-04-C04.md`; the prompt's dated path
  wins and is used here.
- `worker-check.sh` and the Python tooling suite cannot pass in this cloud worker
  because of the skip-worktree `opencode.json` profile; evidence above. This is
  environmental, not a change defect.
- No `task-requests`: READY-40 and the FIX-OPENAPI series already track the missing
  durable store and contract routes.
- Pre-existing on HEAD (origin/main, outside this task's scope): three HL7 source
  files still contain unresolved conflict markers inside Javadoc comments, for
  example `apps/api/src/main/java/com/aurevia/exchange/hl7/Hl7ParseException.java:6`.
  They are comment text, so compilation succeeds. Not touched here; flag to the
  integrator or a dedicated cleanup task.

## Lessons for workers

- Check constructor visibility before designing a fixture in a neighbouring test
  package; a package-private fixed-clock constructor is not callable from
  `messaging.clauses`, and adding a fixture helper outside the declared scope is
  worse than using the public constructor and avoiding exact-time assertions.
- In MSG-04, `authorRole()` is a role key (`clinician`), while `authorSubject()` is
  the authenticated subject (`clinician-a`). Assert the one you mean.
- In this cloud worker, `git ls-files -v opencode.json` showing `S` explains every
  `opencode.json is stale` failure in `check-pack.py`, `worker-check.sh`,
  `unittest discover` and `python-coverage.sh`. Verify the HEAD copy, never
  regenerate or commit that file, and run the remaining gate stages individually.
- `scripts/worker_gate.py` reads `git status --porcelain`; untracked new paths appear
  as directories and fail its scope check. Stage the scoped files and write the
  notes before running that gate.
