# SPEC-XCH-01-C03 — XCH-01 clause 3 proof (snapshot, stamp, disclose)

## Summary

Added active clause-level proof that releasing an order snapshots the exact released
content, stamps four fresh identifiers and version 1, and records one bounded
disclosure carrying the same fingerprint; negative tests prove that a wrong role, a
missing membership, an over-max-duration grant and an expired grant refuse the release
without writing the order, snapshot, disclosure or work item. Added the clause evidence
document. This is proof only: no production code, existing test, contract or migration
changed. Clause sentence: "Snapshot the released content, stamp identifiers and
versions, and record disclosure."

## Authorization boundaries and audit events

The tests exercise `OrderService.create`, `deny` and `checkGrant`: membership and the
`clinician` exchange role are re-derived inside the transaction, the grant is checked
against order code, recipient, purpose, validity window and duration, and denials write
exactly one `AuditAppender` row with outcome `DENIED` (action/purpose `ORDER_DISCLOSURE`,
resource `ORDER`, scope `EXCHANGE`, resource id `GRANT`) before returning 403. The happy
path writes one audit `SUCCESS` row scoped to the stamped order id. Audit rows contain
only opaque ids and action keys, never chart text, patient identifiers or credentials.
No new audit event was introduced.

   as a scope note under `## Evidence` in the clause doc and here; deliberately not a red
   unit test, as directed by the brief. Needs a separate database-level story.

## Lessons for workers

- In a cloud worker, a `worker-check.sh` stop at "opencode.json is stale" is usually the
  CI profile under `skip-worktree`: confirm with `git ls-files -v opencode.json` and
  `git show HEAD:opencode.json`, then run the remaining stages individually. Do not run a
  bare `python3 -I scripts/gen-opencode.py` to investigate — it rewrites the worktree
  file; restore it from `HEAD:.github/opencode.ci.json` if you do.
- For an exact-content proof, pin an independently written canonical content literal and
  a hardcoded fingerprint computed once with a one-off script. It fails red on any drift
  and cannot give a false green; verify the digest before trusting it.
- Distinguish "no domain writes" from "no writes": denials intentionally append one
  `DENIED` audit row, so assert `never()` on the four domain writes and exactly one
  `DENIED` audit append.
