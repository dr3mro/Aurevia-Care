## Findings

- The native patient app declares no iOS deployment target and no Android minimum SDK level. `apps/patient-mobile/app.json` carries orientation, tablet, full-screen and bundle settings only. `browserSupport.ts` is a staff-web web-engine guard; it has no authority over the installed app. Status in the clause doc is therefore `Not built`.
- `docs/decisions/0005-patient-app-tablets.md` is `proposed` and concerns tablets and landscape, not an OS floor. Its context is stale about the current Expo orientation and tablet settings (the config now has `orientation: default` and `supportsTablet: true`). Recorded as a finding, not as proof.
- `docs/operations/production-readiness/evidence.md:27` marks WEB-07 "proven by test" citing only staff-web tests. That row does not prove the native-app clause; a task-request is raised rather than editing that out-of-scope file.
- Story conflict: step 3 asks for a deliberately skipped gap test. `AGENTS.md` Coverage rule 2 forbids an added skipped test and `scripts/check-constraints.py` rejects it. The gap is an active green tripwire instead, and the conflict is recorded in the clause doc `## Gap`. No suppression, exclusion, skipped test or lowered threshold was added.
- The brief's proposed positive test name described a behavior that does not exist. It was replaced with a name describing the comparison actually performed, and the change is recorded in the clause doc `## Evidence`.
- No task in `tasks/` builds native OS support, so a task-request is included below.
- The test engineer's first design review was NO-GO because it proposed refusing baseline-2 (the real guard accepts it) and a tripwire aimed at `browserSupport.ts`. The refined design — baseline-2 accepted, baseline-3 refused, tripwire reading the Expo config — was implemented and the gates re-run green.
- The code reviewer's first pass was NO-GO with one Required finding: `expectTypeOf` pins on a locally declared `CurrentExpoPlatformShape` could not detect a new key in `app.json`, so the "fails typecheck" claim was false. The local interface and its two type pins were removed; the config check is now accurately described as a runtime assertion, while the surviving `keyof typeof browserSupport` pin types a real imported module and does flip typecheck. All gates were re-run after the fix.

## Lessons for workers

- Pin a gap tripwire at the artifact that would change when the capability lands, not at an adjacent module that merely comments on it. Checking `browserSupport.ts` alone would stay green after the native policy was added to `app.json`.
- Check the guard's real predicate before writing a "stale version" assertion: this repository's window of two behind baseline accepts three majors, so baseline-2 is supported and baseline-3 is the first refusal.
- When a story's requested mechanism (a skipped test) is banned by the rules, implement the repository's active-tripwire precedent and record the conflict in the clause doc and notes rather than silently dropping either rule.
- A type-level tripwire only flips if it pins a real imported type. An `expectTypeOf` over a locally declared model of a JSON file is documentation, not a detector; either import the config with `resolveJsonModule` or state plainly that the detector is the runtime key check.
