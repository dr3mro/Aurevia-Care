## Lessons for workers

- Before writing any frontend slice, prove the route can be discovered: check whether `import.meta.glob` is one level deep and whether a parent `features/<domain>/routes.ts` exists. A perfectly tested screen under a nested folder is still a dead screen.
- Check that a data contract and generated client method exist before planning `api.ts`. If the OpenAPI path is absent, an HTTP client in a web-only scope is necessarily fabricated; stop and request the contract task.
- Cross-check the story's fields against the server record type. A UI field with no backing column/record field ("allowed file types and size" vs a settings record without a size) cannot be persisted and is not done.
- Compare the brief's proposed task requests with `TODO.md` before filing them; a sibling story (here SMSG-19) may already own one, and a duplicate request creates duplicate work.
- Verify whether `check-verdicts.py` is invoked with `--base`: a docs-only notes change is exempt, so an unfinished task must report "not run" honestly instead of inventing reviewer GO lines.
