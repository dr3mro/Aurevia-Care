## Summary

Test-only story for CLN-07 clause 3 ("Image rotation is presentation metadata.").
Direct file reads (tool evidence) confirm the clause is fully implemented in the
`documents` domain: rotation is a separate, bounded presentation column on the
retained association, the SHA-256 is derived by PostgreSQL from the exact stored
bytes, and rendering writes rotation only into the immutable render's `/Rotate`
entry. This change adds one HTTP-level integration test class on real PostgreSQL
that proves the rule end to end plus three refusal paths, and the clause evidence
document. No production code, existing test, contract, migration or dependency is
changed. No human, clinical or real-patient evidence is claimed; all fixtures are
synthetic and all reviews were simulated/static.

## Discovery (tool evidence: direct file reads and grep)

The clause is implemented today by:

- `com.aurevia.documents.DocumentInputs` — `rotation(Integer)` accepts
  only 0/90/180/270, maps `null` to 0 and raises `422 INVALID_ROTATION` otherwise.
- `com.aurevia.documents.DocumentService` — `link` forwards the
  validated quarter turn; `associationContent` re-verifies the database-owned
  digest of the exact retained bytes before serving them; `render` stamps rotation
  onto the immutable render. Its class Javadoc states rotation never touches the
  original.
- `com.aurevia.documents.DocumentRepository` — `insert` writes
  `rotation_degrees` and never writes a caller-supplied digest; the association
  row mapper reads the column back.
- `com.aurevia.documents.PdfRenderer` — writes `/Rotate <degrees>` to
  the page object; the whole body is hashed into the render's PDF identifier.
- `com.aurevia.documents.DocumentPolicy` — reception may link and read;
  only a clinician may render or void.
- `db/migrations/V17__document_associations.sql` — the separate
  `rotation_degrees smallint NOT NULL DEFAULT 0 CHECK (rotation_degrees IN
  (0,90,180,270))` column is at line 49 (inside the association table at lines
  37-60); the insert trigger at line 133 sets
  `sha256 = encode(sha256(content), 'hex')`, and line 200 pins rotation on update.
  Forced RLS bounds every read to the active tenant.
- `com.aurevia.documents.DocumentController` — live routes
  `POST /api/v1/documents/associations`,
  `GET /api/v1/documents/associations/{id}[/content]`,
  `POST /api/v1/documents/rendered` and
  `GET /api/v1/documents/rendered/{id}[/content]`.

The document routes are listed in `contracts/openapi/missing-routes.txt` (lines
33-39) rather than `contracts/openapi.yaml`. That is a pre-existing, separately
tracked contract-publication debt, not a gap in this clause; no contract file is
in this task's scope.

## Lessons for workers

- For a clause-verification story, read the production path first: if the
  behaviour exists, write the green acceptance test rather than a `@Disabled`
  GAP test; reserve `@Disabled` for genuinely absent or partial behaviour.
- Mirror the seeded-synthetic / RestClient / flat-`field()` pattern of the
  neighbouring `*HttpIntegrationTest` classes and give the test its own
  database plus a unique MRN per chart, so parallel and repeated runs cannot
  collide.
- Assert error codes by numeric status (`assertEquals(422, ...value())`) rather
  than a Spring `HttpStatus` constant: this codebase's Spring version names the
  422 constant `UNPROCESSABLE_CONTENT`, not `UNPROCESSABLE_ENTITY`.
- In this worker image, confirm the skip-worktree `opencode.json` artifact once
  with `git ls-files -v`, temporarily restore `git show HEAD:opencode.json`
  bytes to run `check-pack.py`/`quick-check.sh`/`unittest`, then put the CI bytes
  back. Never commit or regenerate `opencode.json`.
