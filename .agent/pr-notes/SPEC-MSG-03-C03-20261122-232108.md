## Advisor brief assessment

The brief correctly identifies the `messaging.attachments` slice (not
`staffmsg.attachments`, whose store lacks a `unitId`) and the real-Postgres
clause-test pattern. One correction was verified with the reviewers: through the
real `POST /api/v1/patient/files/upload` entry point the service's explicit
`WRONG_UNIT` / organization-mismatch branches are structurally unreachable,
because the controller passes `grant.patientId()` as the actor's patient id and
RLS already confines `store.grant(...)` to the active tenant. The HTTP test
therefore proves the clause through the grant-derived response and persisted-row
bindings and through role / inactive / missing / cross-tenant / client-rebind
refusals; the defensive `WRONG_UNIT` branches remain proven by the unchanged
service-level `AttachmentAcceptanceTest`. The plan reviewer first returned NO-GO
on three concrete gaps (name the no-`fast` Maven command, set `app.current_org`
on every assertion query, use a foreign-only connection id); all were fixed and
the reviewer then returned `VERDICT: GO`.

## Lessons for workers

- When a clause's defensive branch is structurally unreachable through the real
  HTTP entry point, prove the observable binding and say so in the clause doc;
  do not invent an HTTP negative that cannot pass or claim a branch not taken.
- A genuine red for a test-only story can be made by first asserting the unsafe
  behavior (here, the client-spoofed unit) and then correcting the expectation;
  the failing final line becomes direct evidence the server enforces the rule.
- For a real-Postgres clause test, every assertion query must bind
  `app.current_org` transaction-locally and roll back; an unscoped SELECT under
  forced RLS returns zero rows and makes a "no row written" assertion vacuous.
- Use a connection id seeded only in the peer tenant for the cross-tenant
  negative; two tenants sharing all local ids leave no foreign-only identifier
  to request.
- Keep the `fast` profile out of the targeted Maven command: it sets
  `excludedGroups=integration` and would silently run zero tests.
