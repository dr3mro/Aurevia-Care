## Lessons for workers

- Before treating `check-pack.py` or `gen-opencode.py --check` staleness as your own regression, run `git ls-files -v opencode.json` once: flag `S` means the worktree holds the CI profile under skip-worktree and `git show HEAD:opencode.json` is the truth. Confirm once, record the command and final line, and do not re-diagnose it on a later pass (OPS-CW-003-01).
- For a documentation-only change, `python3 -I scripts/check-docs.py` (plus `check-secrets.py`) is the applicable gate; a green docs gate does not make `worker-check.sh` green while the CI profile is active in the worker, so a draft PR can still be correct and complete.
- Conflict markers inside a Javadoc block on `origin/main` are committed content, not an unresolved merge. Confirm with `git ls-files -u` and `git show origin/main:<file>` before treating them as work to fix.
- When a fix pass finds the scoped deliverable already correct, say so plainly and record the out-of-scope red gate under "Why this is not finished" instead of editing a protected file or inventing a change.
