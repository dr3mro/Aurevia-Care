## Summary

This is fix attempt 3 for story SPEC-IAM-06-C02. The original delivery added one
independent, active, real-PostgreSQL HTTP acceptance test plus a status document
proving IAM-06 clause 2; no production code, existing test, migration, contract or
client was changed. The integrator rejected that pull request for a single reason:
the worker's notes file contained the literal SpotBugs XML element name inside the
`## Test evidence` section, which `scripts/worker_gate.py` matches as a placeholder
token. This fix pass adds a corrected hand-off note with that text rewritten as
prose; it changes no test, no production code and no document. The positive test
proves a qualified clinician opens a reasoned, time-limited grant in their own
organization that is alerted, opens a privacy-auditor review and is independently
reviewed. Five negative tests prove the rule refuses wrong roles, a foreign tenant,
an unapproved site, invalid input and stacked grants (and that expired grants are
unusable).

## Lessons for workers

- Never write a literal angle-bracketed token (XML element names, template names)
  in the `Test evidence` or `Coverage` notes sections: `worker_gate.py` matches any
  such token as a placeholder and fails the pull request. Say "zero bug instances"
  in prose instead.
- For a clause proof that asserts audit rows on a shared database, give every
  test its own correlation id; otherwise audit-count assertions can be satisfied
  by another test's rows and pass vacuously.
- If the test name or status doc claims "reviewed", assert the review is actually
  closed with an outcome and an independent reviewer — an open V88 row proves
  only that the alert was raised.
- To prove cross-tenant invisibility rather than a missing-membership denial,
  seed the same subject as an active member of both tenants, and add an owner-org
  anchor that shows the grant is visible where it belongs.
- In a cloud worker, confirm the `opencode.json` staleness false positive with a
  detached worktree under the ignored `build/` directory (`git ls-files -v` shows
  `S` in the worker, `H` at HEAD); never regenerate or commit that file.
- `scripts/worker-check.sh` runs all 118 integration classes (632 tests) and
  `scripts/check.sh` runs full `mvn verify`; run their applicable constituents
  individually in a worker and leave the aggregate to the integrator.
