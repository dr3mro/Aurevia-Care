## Brief assessment

The advisor brief is accurate about the built rule and the two new files. Two corrections applied from direct code evidence:

1. The chart list route `GET /api/v1/chart/records/patients/{patientId}/entries` does **not** return 404 for a foreign patient. `ChartService.listForPatient` has no patient-existence check and `CHART_READ` permits `clinician`, so RLS conceals the sender's `chart_entry` rows and the response is `200` with zero entries (confirmed in `it/chart/record/ChartRecordIntegrationTest.tenantIsolationConcealsCrossTenantRowsAndForcesChecks`). The test asserts `200` plus an empty chart, with a seeded sender chart entry so the assertion is not vacuous, and `404` on the single-entry route.
2. `GET /api/v1/patients/{senderPatientId}` as `clinician-b/ORG_B` is **403 FORBIDDEN** ("missing patient permission"): `PatientService.get` authorizes before lookup and `ActionPolicy` does not grant `PATIENT_READ` to clinicians. The **404** for a concealed foreign patient is asserted with `reception-b/ORG_B`, which does have `PATIENT_READ`. The brief collapsed these two cases.
3. There is no `GET /api/v1/exchange/work-items/{id}` route. "404 on the work item" is exercised through the guarded `POST /api/v1/exchange/work-items/{id}/verify-patient` with `clinician-c/ORG_C`, which returns 404 from `OrderService.verifyPatient`'s work-item lookup.
4. The work-item inbox is not asserted to have total size 1 (all three tests create orders against one shared seeded DB). The test asserts exactly one work item whose `orderRef` equals this test's order id.

## Lessons for workers

- Never trust an advisor's expected HTTP statuses for a different surface: verify against the deciding policy. A chart list is `200` with concealed rows under RLS, not 404; a clinician lacks `PATIENT_READ` (403) while a receptionist with that permission gets 404 for a concealed foreign patient.
- An empty-result assertion is vacuous without a seeded row the owner can see. Seed a synthetic sentinel in the sender tenant first, and re-assert concealment after a successful work-item bind so a regression that widens access on verification cannot pass.
- `git add -N` new files before sending a diff to read-only reviewers; untracked files are invisible to `git diff`.
- When `opencode.json` is under skip-worktree, confirm once (`git ls-files -v`, `git show HEAD:opencode.json`), record the failing command and final line, run the remaining gate stages individually, and do not regenerate or edit protected files.
