## Lessons for workers

- Before reporting "local checks: failed" on a cloud worker, reproduce each command. A red
  `check-pack.py`/`gen-opencode.py --check` is usually the CI-profile `skip-worktree` artifact —
  confirm with `git ls-files -v opencode.json` and `git show HEAD:opencode.json`, restore the HEAD
  bytes into the worktree to run the gate, and never regenerate or commit that file.
- `python-coverage.sh` (part of `check.sh`/`worker-check.sh`) runs `usable_reports()` in
  `scripts/worker_gate.py`, which globs `apps/api/target/surefire-reports`. In a fresh tree that
  gitignored directory is absent and two worker_gate tests raise `FileNotFoundError`. Creating the
  empty directory locally makes the suite pass; a durable fix to the test/tooling must come from the
  maintainer because `scripts/` is protected.
- Do not rewrite a gate evidence note a prior pass already verified. Re-verify cited test methods
  and spec-row wording with `grep`, record fresh tool evidence, and avoid churn.
- `scripts/check.sh` runs the full `apps/api/check.sh` verify/integration suite and is forbidden for
  workers; for a docs-only change use `python3 -I scripts/check-docs.py`, the other policy checks,
  `bash scripts/coverage-check.sh` and `bash scripts/python-coverage.sh` instead.
- Keep "engineering evidence proven" strictly separate from "human acceptance open"; a
  `GATE-PACK-*` or `S-G5-*` task prepares evidence and never records approval.
