## Lessons for workers

- For a "describe the interface" docs story, read the `messages.ts` bundles and
  the screen components, not only the approved design pictures. The pictures
  can show copy the code does not render (for example patient appointment
  status pills).
- Before calling a screen "existing", check for a registered `routes.ts`, not
  just a component file. A component with no route is not reachable. Even for a
  routed path, read the routed `*Page.tsx`: a presentational `*Screen.tsx` can
  render labels the real page never shows (chart status, document list).
- A dialog's confirm button can reuse the parent button's label key: the note
  sign confirmation says "Sign draft", not "Sign". Quote what the code renders
  at that call site, not the obvious short form.
- In a cloud worker, a red `check-pack` on `opencode.json` is a CI-profile
  measurement artifact when `git ls-files -v` shows `S`. Verify against
  `git show HEAD:opencode.json` and leave the protected generated file alone.
