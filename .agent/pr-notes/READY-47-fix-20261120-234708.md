## Affected requirements

| ID | How this change (the existing READY-47 implementation) serves it |
|---|---|
| PAT-01 | `createTransport` sends a bearer credential read immediately before each request over HTTPS with `Accept-Language` and an opaque correlation id; `tokenStore` keeps the credential in OS-backed storage so revocation takes effect on the next action. |
| ARC-03 | Versioned `/api/v1` paths are supplied by the caller; every call carries a fresh `X-Correlation-Id`; 409 and 412 map to `conflict`; the server's machine-readable `code` and well-formed field errors are preserved; a missing or blank credential fails closed before any request is sent. |

The credential is read immediately before each request and is never stored in
application state, `AsyncStorage` or a clinical cache. A missing or blank
credential produces a typed `unauthenticated` error without a fetch. No
server-side audit event is added or changed; the client sends the correlation id
the server uses for its audit record.

## Lessons for workers

- When a fix pass arrives with an empty story body, verify every in-scope gate
  first and record the exact commands and results; do not invent a code change
  to make the pass look productive.
- In `apps/patient-mobile`, run `bash apps/patient-mobile/check.sh` as the final
  gate; it re-runs `npm ci`, so `npx jest src/api --coverage --collectCoverageFrom='src/api/*.ts'`
  is the fast inner loop for the api surface.
- A green module gate does not imply a green full-repository gate: the integrator
  additionally runs `scripts/check.sh` and `scripts/docs.sh`. For a frontend-only
  scope, an `apps/api` integration failure in that gate is out of scope — say so
  with evidence instead of editing backend code.
- `opencode.json` under `skip-worktree` in a cloud worker is the CI profile, not
  HEAD truth. Use `git show HEAD:opencode.json` and `git ls-files -v` before
  reporting a pack-check staleness; re-reporting OPS-CW-003-01 wastes a pass.
- Put patient-mobile tests under `src/**` (Jest `testMatch` ignores a new
  `tests/` directory) and import `jest` from `@jest/globals` before `jest.fn`.
