## Lessons for workers

- Sweep the whole note, including the Related-evidence list, for a corrected phrase; the same stale label recurs in the narrative and in a bullet. Use a literal zero-hit grep (`grep -n 'current HEAD' …`) as the verification gate.
- When wording a reword that a substring grep will check, avoid near-miss phrases: "then-current HEAD" still contains `current HEAD`. Prefer "at HEAD `<sha>`" or "as of `<sha>`".
- Prefer historical provenance ("tested head `<sha>`", "as of `origin/main` `<sha>`") over "current HEAD `<sha>`": a historical statement stays true when the branch is rebased or main advances.
- Write the hand-off notes file before launching the final reviewers; otherwise they report the absent file as a Required finding and a re-review is needed just to confirm the race.
- `check-verdicts.py` short-circuits when every changed path is documentation; still list only reviewers actually run, and keep the `## Review verdicts` section present with real final lines.
- Do not run `scripts/check.sh` in a swarm worker: it calls full `mvn verify`. Run the bounded `-Dtest=...` suite plus the individual policy scripts and leave the full gate to the integrator.
