## Lessons for workers

- For a scoped test-only clause story, `mvn -q -B -f apps/api/pom.xml -Pno-security
  -Dtest=ClassName test` is the correct verification. `scripts/worker-check.sh` and
  `scripts/check.sh` both end up running every integration test / full `mvn verify`;
  the task explicitly forbids those for workers and assigns them to the integrator.
- Give each clause integration test its own database name (here
  `orevia_cln02_intake_it`) so parallel workers cannot collide, and scope row-count
  assertions by a unique reason string because the seeded ledger is append-only across
  test methods in one class.
- Check `git show origin/main:<file>` before treating committed conflict markers as your
  own merge damage; base-branch markers are not yours to resolve inside a narrow scope.
- `git ls-files -v opencode.json` returning `S` explains `test_check_pack --check` failures;
  compare with `git show HEAD:opencode.json` before regenerating anything.
- When the clause under test is already built, a positive test plus a wrong-role and a
  cross-tenant refusal gives a compact, fully green proof without writing production code.
