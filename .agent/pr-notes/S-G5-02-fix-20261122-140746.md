## Lessons for workers

- On a fix pass with only a truncated "did not finish cleanly" note, first prove
  the existing change with the module's applicable gates and verify its claimed
  evidence paths. If everything is green and accurate, finalize with a fresh
  hand-off note rather than inventing a change.
- A decision pack that is already thorough usually needs the explicit
  acceptance triplet (owner role / evidence location / status), not more prose.
- Verify "in memory / not built / does not survive a restart" claims against the
  current tree before writing them into a launch record; both such claims here
  were already closed on main.
- In a cloud worker, a red `check-pack.py` with `git ls-files -v opencode.json`
  showing `S` means the CI profile is installed under skip-worktree; confirm
  with `cmp` against `.github/opencode.ci.json` and never regenerate or commit
  that file.
- For a Markdown-only story, `python3 -I scripts/check-docs.py` plus a direct
  re-read is the applicable gate; `scripts/check.sh` starts the full Maven
  verify and must be left to the integrator.
