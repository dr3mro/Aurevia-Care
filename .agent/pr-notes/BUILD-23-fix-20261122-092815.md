## Lessons for workers

- When a green fix PR is repeatedly returned, do not re-apply the fix or write another verification-only note. Read `scripts/swarm.py` `publish`/`fail`/`plan_integration`/`pr_flow`: a `needs-fix`/`needs-human`/`needs-debug` label excludes the PR from integration regardless of green checks, so "the integrator will retest" is false until the label is cleared by a trusted job.
- When there is genuinely no in-scope change left, say so plainly with the decisive source evidence and the exact owner/maintainer next step instead of churning another no-op commit; a notes file must add a concrete new fact (this pass adds fresh full-gate evidence and the confirmed 403 on live PR verification).
- Check check-runs on the exact **PR head SHA**, not the local HEAD — the PR head can trail local tracker/merge commits.
- Treat a scope violation in an inherited fix as a real hand-off finding: a strict worker-gate rerun can reject a PR whose CI is green.
- Reset `apps/api/target/jacoco.exec` before the coverage batch and include `BrowserSessionHttpTest`; accumulated exec data can overstate a targeted run.
- The frontend definition of done is mandatory even on a data-only backend pass: run both `check.sh` scripts, paste the `tsc --noEmit` final lines, treat any `error TS…` as a hard stop.
- Inside a cloud worker, worktree `opencode.json` is the CI profile under `skip-worktree`; report which profile was measured rather than treating it as HEAD truth, and attribute `test_check_pack.py` failures to it rather than to the change.
