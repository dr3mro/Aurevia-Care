## Lessons for workers

- Before reusing an old evidence note, resolve every cited commit hash with `git rev-parse --verify <sha>^{commit}`. A worker-branch HEAD can survive in prose after its object has been garbage-collected; citing it makes an otherwise correct claim unverifiable.
- Distinguish a requirement ID from the story ID that implemented it. A commit subject can start with the requirement ID while TODO.md assigns the PR to a different story name; check both before writing "Merged stories".
- Re-run the bounded evidence suite at the *current* HEAD before updating the provenance line, and read the Surefire XML: `mvn -q` suppresses the "Tests run" summary, so exit 0 alone is not a test count.
- Keep the "evidence, not acceptance" framing intact on a fix pass. It is tempting to tidy caveats into a verdict; the note must still leave Product Owner, clinical and privacy acceptance to humans.
- A fix pass is still a fix pass: confirm the prompt's exact notes-file path wins over the generic `-fix-` convention, and write it as inline code in the note so the docs link checker does not try to resolve it.
- Write the hand-off notes file **before** launching the final reviewers. Reviewers that read the tree before the notes file exists report an absent hand-off as a Required finding and return NO-GO even when the file is created moments later; a re-review is then needed just to confirm the race, not a real defect.
- When reusing an old evidence note, sweep the whole file for the corrected label, not just the line that was flagged: the same stale "RAD-01 (PR #302)" appeared in both the matrix row and the Related-evidence list.
