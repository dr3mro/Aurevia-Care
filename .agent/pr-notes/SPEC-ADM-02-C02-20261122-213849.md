## Lessons for workers

- For a test-only clause story, write the active tests against the real kernel and
  keep the missing HTTP boundary only in complete `@Disabled("GAP: …")` tests;
  never claim HTTP behaviour that has no route, service or audit row.
- `scripts/check-constraints.py` matches the literal token `@Disabled` even in a
  Javadoc `{@code ...}` mention; describe it as "disabled" in prose to keep the
  finding list to the real annotations.
- The `opencode.json` skip-worktree false positive is environmental: confirm once
  with `git ls-files -v`, then run the remaining policy stages individually and
  never regenerate that file.
- Check the domain Javadoc before claiming a feature: `QueueAction`'s own comment
  names the missing command boundary, which is the strongest survey evidence.
- Use the repo's real synthetic headers (`X-Synthetic-Subject`,
  `X-Active-Organization`) in intended HTTP tests so a later task can enable them
  without rewriting fixtures.
