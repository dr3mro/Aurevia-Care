# READY-11 (fix pass) — Staff web OIDC login with a session cookie and CSRF protection (WEB-03)

## Summary

The READY-11 implementation was originally merged as PR #285 (commit `fefe3f2`, "READY-11: staff web OIDC login with session cookie and CSRF (WEB-03)"). It was subsequently **deleted from the tree by a bad integration merge**, commit `be171ca` "Integrate swarm PRs (reconciled)". That commit deleted five implementation/test files and reverted the supporting changes in `pom.xml`, `application.yml`, `SecurityConfiguration.java` and `TenantContextInterceptor.java`. Later PRs re-merged most of the other files that `be171ca` dropped, but READY-11 was never re-merged, which is why the story kept being re-dispatched with TODO still `[-]`.

The two previous fix passes (notes `READY-11-20261121-094203.md` and `READY-11-fix-20261121-114248.md`) reported success, but they verified a branch lineage that still contained the code; the deletion only reached this branch's HEAD through the later merge `e93bf0c` of `origin/main`. They therefore missed the regression.

This fix pass **restores the exact merged implementation** from `fefe3f2`: all nine affected files are byte-identical (SHA-256 verified) to that commit. No new production behaviour was invented, no credential, token or patient data was added, and the `synthetic-auth` profile is untouched. The previously out-of-scope blocker from the last pass — the stale central route-registry tests in `apps/staff-web` — was fixed on `main` by PR #333 (FIX-ROUTES-01) and is confirmed green here.

Restored behaviour: a second `SecurityFilterChain` ordered before the stateless bearer chain matches only requests without `Authorization: Bearer`, uses `oauth2Login`, an HTTP-only secure `SameSite=Lax` session cookie, CSRF with a readable `XSRF-TOKEN` cookie, a 12-hour absolute session guard driven by the injected `Clock`, and `POST /logout` that invalidates the server session and clears both cookies. `TenantContextInterceptor` accepts the browser `OAuth2AuthenticationToken` through the existing `ClaimsTenantResolver`; the bearer path keeps its no-CSRF semantics.

## Authorization boundaries and audit events

Every non-bearer request on the browser chain requires an authenticated OIDC session. CSRF is enforced with a per-session token readable only through the non-HTTP-only `XSRF-TOKEN` cookie (an anti-CSRF value, not an authentication token — nothing is written to browser storage). The browser principal's `sub`/`orgs` attributes are resolved through the existing `ClaimsTenantResolver`, so a session cannot widen its organization set and the active tenant still comes only from `X-Active-Organization` intersected with verified claims. The bearer chain is unchanged; CSRF is ignored only for `Authorization: Bearer` requests. No audit event was added and 401/403 denial semantics are unchanged.

## Migration and rollout considerations

`@ConditionalOnWebApplication(SERVLET)` keeps the non-web startup test green and prevents the browser chain from existing without an HTTP surface; `@Profile("!synthetic-auth")` leaves the synthetic profile untouched. In production all three `OREVIA_OIDC_*` values must be supplied or startup fails closed. Issuer and client secret are never written to the repository. The IdP must publish `/authorize`, `/token` and `/userinfo` beneath the issuer and return `sub` and `orgs` in user-info — confirm with the real IdP before enablement. The host must terminate TLS so the session and XSRF cookies carry `Secure`.

## Findings

1. **Root cause of the repeated re-dispatch: the merged implementation was deleted by a bad integration merge.** `be171ca` "Integrate swarm PRs (reconciled)" deleted `StaffWebLoginConfiguration.java`, `AbsoluteSessionTimeoutFilter.java`, `BrowserSessionHttpTest.java` and the two unit test files, and reverted the `pom.xml`, `application.yml`, `SecurityConfiguration.java` and `TenantContextInterceptor.java` changes. `git log fefe3f2..be171ca` shows `be171ca` is the only commit that touched these files, and no commit after it touched them, so restoring from `fefe3f2` is exact. This pass restores all nine files. Integrator: after merging this PR, TODO entry READY-11 should be marked `[x]` with `pr: #285` and this fix reference.
2. **The two prior fix passes reported green on a stale lineage.** They verified before the `origin/main` merge (`e93bf0c`) that carried the deletion into this branch. Lesson: on a re-dispatched story, always confirm the production files actually exist in the current worktree (or `git diff origin/main...HEAD --name-only` plus a file-existence check) before trusting earlier notes.
3. **The previously out-of-scope staff-web blocker is resolved on `main`.** PR #333 (FIX-ROUTES-01) changed `apps/staff-web/src/app/routes.test.tsx` and `tests/app/AppShell.test.tsx` to derive expected patterns from `collectFeatureRoutes`/`featurePatterns()` instead of a hard-coded list. `bash apps/staff-web/check.sh` now exits 0 with 100% coverage, so the whole frontend gate is green for this story.
4. **WEB-03 limit deliberately out of scope:** listing and revoking a user's *other* sessions needs a server-side session registry and must be a separate follow-up approved by a person. Authentication-endpoint lockout/rate-limiting is likewise not part of this slice. Neither is claimed as covered here.
5. Audience is still not fail-closed (`OREVIA_OIDC_AUDIENCE` defaults empty) — a pre-existing production-enablement risk from the AUD-20261120-03 notes, not widened here.
6. **Health probes are not exempt outside `synthetic-auth` (pre-existing, not introduced here).** Both chains use `anyRequest().authenticated()`, so `GET /health/live` and `/health/ready` need a credential and the browser chain would redirect to OIDC login. WEB-05 requires these routes unauthenticated; fix in a WEB-05/health-lifecycle story with its own tests.
7. OWASP Dependency-Check, SpotBugs and the real-PostgreSQL integration suites were not run locally (the worker gate forbids the full `mvn verify`; no `NVD_API_KEY` is available locally and the feed would time out). The Spring Boot parent manages the restored starter with no version tag. The integrator/Delivery cached-NVD full gate owns this evidence.
8. **Bounded Senior Spring Security / OIDC review returned NO blocking finding** (simulated reviewer; read-only file/tool reads, test/coverage green claims not independently reproduced by the reviewer). It confirmed every WEB-03 acceptance point in the restored code: `@Order(1)` browser chain with `securityMatcher(!isBearerRequest)` ahead of the `@Order(2)` bearer chain; secure HTTP-only SameSite=Lax cookie; `CookieCsrfTokenRepository.withHttpOnlyFalse()` plus a null request-attribute handler so `XSRF-TOKEN` is actually written; 12h `Clock`-driven guard; `POST /logout`; env-only fail-closed settings; bearer requests keep no-CSRF semantics. It also confirmed the production `Clock` bean (`ClockConfiguration`) resolves the injected dependency and that staff-web `transport.ts` reads `XSRF-TOKEN` and sends `X-XSRF-TOKEN` with `credentials:'include'`. All nine files present; no READY-11 file missing.
9. **LOW (pre-existing, not introduced — hand-off):** `SecurityConfiguration.isBearerRequest` uses case-sensitive `startsWith("Bearer ")`. RFC 7235 auth-schemes are case-insensitive, so a client sending `bearer …` would fall into the browser chain (CSRF / OIDC redirect) instead of the stateless chain. This helper is shared with the AUD-20261120-03 CSRF matcher, so it was not created by this restoration. Suggested follow-up: `regionMatches(true, …)` plus a test touching both matchers — not changed here to keep the restoration byte-identical.
10. **LOW (verify at deploy, not introduced):** `CookieCsrfTokenRepository.withHttpOnlyFalse()` does not itself set the `Secure` flag on `XSRF-TOKEN`. It is a non-auth anti-CSRF value (session cookie is Secure + HSTS) and acceptance does not require it, but confirm the deployed `XSRF-TOKEN` is Secure.
11. **MEDIUM (functional readiness, not a code defect):** `BrowserSessionHttpTest` seeds an `OAuth2AuthenticationToken` directly; the authorization-code redirect/callback, the manually built (no-discovery) `/authorize`, `/token`, `/userinfo` endpoints and the `sub`/`orgs` claim assumptions are unverified against a real IdP. Validate in UAT before live enablement. Also confirm topology: SameSite=Lax requires the SPA and API to be same-site for `credentials:'include'` fetch to carry the session cookie.

## Lessons for workers

- On a re-dispatched/already-reported-done story, first verify the production files still exist in the current worktree AND that `git merge-base --is-ancestor <merged-pr> HEAD` holds; earlier notes can be green on a lineage that a later `origin/main` merge overwrote. A file-existence check (`ls`) plus `git log --diff-filter=D -- <path>` catches an accidental deletion that a diff-only check misses.
- When a broad "reconciled" integration commit deletes many files, check whether each story's files were re-merged; a later PR may restore most paths while silently dropping one. Restore the dropped files from the canonical merged commit only after confirming no other commit changed them in between.
- Deriving expected route patterns from `import.meta.glob`/`collectFeatureRoutes` (PR #333) keeps the central staff-web route tests stable as features self-register; do not reintroduce a hard-coded pattern list.
- Regenerate `opencode.json` with `python3 -I scripts/gen-opencode.py` before any gate in a CI-profile worker; it is `skip-worktree`, so this restores HEAD's local profile without committing (do not edit `scripts/` or the file by hand).
- In this Boot 4.1.2 / Spring Security 7 slice, `AntPathRequestMatcher` no longer exists — use `PathPatternRequestMatcher.pathPattern(HttpMethod.POST, "/logout")` and `ClientRegistration.getProviderDetails().getAuthorizationUri()`.
- With `CookieCsrfTokenRepository`, set `CsrfTokenRequestAttributeHandler.setCsrfRequestAttributeName(null)` or `XSRF-TOKEN` is never written on a GET and the SPA has no token to send.
- `MockHttpSession` has no `setCreationTime`; override `getCreationTime()` in an anonymous subclass for deterministic session-age tests.
