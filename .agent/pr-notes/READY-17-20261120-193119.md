## Decisions and deviations

- **Cursor format**: canonical `Instant.toString()` of `created_at` plus the immutable row `id`, mirroring the approved READY-16 order list. A non-canonical or unparseable instant is rejected with `INVALID_CURSOR`. Ordering is `(created_at DESC, id DESC)` so paging is stable when two rows share a creation instant (exercised by the integration fixture).
- **Invalid `state` error code**: the story specifies HTTP 422 but not the machine code; chose `INVALID_STATE` (resource-specific, consistent with the sibling `INVALID_STATUS`).
- **List rows carry no history**: `AccessionPage` items are `AccessionView` as required, constructed with an empty event list on list reads. The single-record read `get` keeps ownership of the immutable event stream, so neither its response shape nor behavior changed and a page stays bounded.
- **Authorization**: reused `LabActionPolicy.ACCESSION_READ` and the existing `lab_collector`/`lab_verifier` roles exactly as the single-record read; no new role or action key.
- **RLS**: repository relies on forced row-level security for tenant isolation (no manual organization predicate), with parameterised SQL only and real V26 column names.
- **Scope deviation (documented, as in READY-16)**: the story's explicit steps require an `it/` integration test (step 6) and contract regeneration (step 7). Those files are outside the literal `scope` prefixes: `apps/api/src/test/java/com/aurevia/smartclinic/it/lab/AccessionListIntegrationTest.java` and `apps/staff-web/src/api/generated/openapi.d.ts`. The generated d.ts was produced with the pinned generator (never hand-edited) because the full gate enforces `gen:api:check`; `contracts/openapi/generated/openapi.yaml` (catalog-generated X-04 artifacts) is unchanged by a GET route, so `contracts/openapi/check.py` stays green. No tracker, workflow, POM, migration or dependency file was touched.
