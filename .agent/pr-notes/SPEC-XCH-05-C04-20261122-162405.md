## Lessons for workers

- In `CriticalResultService.acknowledge` the delivered-attempt guard runs before the read-back guard; register a clause test with `readBackRequired=true` when asserting `NO_DELIVERED_ATTEMPT`, otherwise the ordering is unobservable because the read-back guard short-circuits. To prove "delivery alone is not acknowledgment", assert `READ_BACK_REQUIRED` after a delivered attempt and before read-back.
- A released critical result is an unchanged `Result` (no state/version change) — assert on the release response with `/state` and `/version`, and on a GET with `/result/state` and `/result/version`; mixing those pointers fails compilation or the assertion.
- Do not run `scripts/worker-check.sh` in a swarm worker: it runs `-Dgroups=integration` across every suite. Run the targeted `-Dtest=...` suite plus individual policy scripts and leave the full gate to the integrator.
- In this cloud worker, treat `check.sh`/`python-coverage.sh`/`test_check_pack` `opencode.json is stale` results as the skip-worktree CI profile, not HEAD truth; confirm once with `git ls-files -v` and `git show HEAD:opencode.json` and move on instead of editing the protected file.
