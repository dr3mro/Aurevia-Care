# BUILD-50 — Staff web: templates, field dictionaries and release policies (admin)

## Summary

Added a self-contained `apps/staff-web/src/features/policies` feature with three
review areas (clinical templates, field dictionaries, patient release policies).
Each area shows the append-only version history with approval state, named
approver and effective date. One shared governed editor refuses a change when a
named proposer is missing; release policies additionally support immediate,
timed and hold (with reason and review date) modes. Because the contract exposes
only an opaque bounded `value`, configuration changes carry a versioned envelope
(`sc-policy/v1 ` + JSON) so the mode, reason, expiry and proposer survive the API
round trip; a plain or malformed value falls back to the mode derived from the
configuration key so a hold never fails open as an immediate release. English
and Arabic bundles, RTL direction, isolated mixed-script values and the shared
loading/empty/error state views are covered. Synthetic fixtures only; no
dependency added; no file outside the task scope changed.

Requirements mapping:
- **ADM-01** — tenant-scoped review of versions, explicit approval, effective
  dates, named approval and append-only history; admin-only area buttons.
- **CLN-04** — versioned template families and field dictionaries that keep the
  historical meaning beside each version; dictionary values carry a field code.
- **XCH-06** — release mode is immediate/timed/hold; a hold needs a reason and a
  review date; current patient access is derived from the approved version on a
  fixed anchor civil date.

## Clinical and architecture review

- No clinical decision is automated. Domain functions are deterministic and
  clock-free; "today" is the fixed `policyAnchorCivilDate` fixture.
- A plain or malformed configuration value under a hold/timed key falls back to
  the key-derived hold/timed mode, so it can never be evaluated as an immediate
  patient release.
- The proposer name is a governance gate captured in the value envelope and
  shown in history; the final approval is recorded by the server from the
  authenticated actor, as stated in the editor.
- Release access is presentation only; authoritative patient-release
  authorization remains the server's XCH-06 workflow.
- Accessibility: real `<table>` with `<caption>`/`scope`, a labelled focusable
  scroll region, `role="status"` outcomes, one error summary plus bound inline
  errors, native buttons with `aria-pressed`, no colon punctuation adjacent to
  isolated mixed-script values, and safe Cancel focus in the approval dialog.

## Findings

Two bounded senior React review passes (simulated review; files tool-inspected
by the reviewer, commands re-run by this worker) raised 17 findings. Resolutions:

1. **HIGH — selected release mode was discarded**. **Fixed** with the envelope;
   mode is decoded from stored configuration values. Covered by
   `domain.test.ts` and `api.test.ts`.
2. **HIGH — hold reason and expiry were never sent or rendered**. **Fixed**:
   both round-trip in the envelope and render in history and the current-access
   panel.
3. **MEDIUM — named approver was validation theater**. **Fixed**: the name
   round-trips as "Proposed by"; the editor states the signed-in actor is the
   recorded approver on approval.
4. **MEDIUM — error-summary link id did not match the input id**. **Fixed**:
   both use `policy-effectiveFrom`.
5. **MEDIUM — `PolicyPage` has no registered route**. **Deferred, out of
   scope**: `routes.test.tsx` asserts the exact route set and BUILD-52 owns
   `app/routes.tsx` and `app/navigation.ts`. The component is exported and
   tested; registration is that story's explicit purpose.
6. **MEDIUM — translated label concatenated with a version digit and a literal
   colon beside a `<bdi>`**. **Fixed** with a `approveVersion` placeholder
   message and colon-free flex rows.
7. **LOW — hard-coded date placeholders**. **Fixed** with `datePlaceholder`.
8. **LOW — dead `approvedNotice` message**. **Fixed**: removed.
9. **Contract gap (pre-existing)**: `contracts/openapi.yaml` has no dedicated
   template or release-policy endpoints. The feature uses `/configuration` and
   `/catalogs`, the only contract surfaces with version history and approval.
10. **Dictionary approval is intentionally absent**: the catalog list endpoint
    exposes only effective approved entries, so an approve action there was
    unreachable and was deleted rather than left as dead code.
11. **HIGH — fail-open fallback**: a plain or malformed value under
    `release.hold` was evaluated as immediate after the envelope change.
    **Fixed**: `releaseModeForKey` is restored as the decode fallback for
    configuration values, so hold/timed keys stay held/scheduled.
12. **MEDIUM — encoded value visible in the admin catalog table**:
    **Mitigated within scope** — dictionary definitions no longer use the
    envelope, so catalog views stay readable. Configuration values still use
    it; a cross-feature follow-up should decode them in
    `features/admin/ConfigEditor.tsx` before display (outside this scope).
13. **MEDIUM — scheduled line missing when no policy is in force**: **Fixed**
    by passing `organizationId` explicitly and filtering on it.
14. **MEDIUM — literal `{date}` and doubled colon**: **Fixed** with a
    standalone `nextScheduledLabel` and `<time>` element.
15. **MEDIUM — bidi-unsafe colons before isolated values**: **Fixed** by
    rendering label and value as separate flex children; unused
    `currentReason`/`currentReviewDate` keys removed.
16. **LOW — approver label contradicted the actor note**: **Fixed** by renaming
    the field and refusal text to "Proposed by" semantics.
17. **LOW — envelope can exceed the 4000-char value limit**: **Fixed** with
    `validatePolicyChange` length check and a `valueTooLong` message.

## Lessons for workers

- The staff-web `tsconfig` uses `exactOptionalPropertyTypes`. Passing
  `error={maybeUndefined}` to `FormField` fails typecheck; spread
  `{...(value === undefined ? {} : { error: value })}` instead. The same applies
  to test fixtures (`approver: undefined`, `expiry: undefined`).
- A guard that can never be true fails 100% branch coverage. Move the command
  into a child component that receives the narrowed value as a required prop.
- `routes.test.tsx` asserts the exact registered route list; a feature that
  adds a pattern in its own `routes.ts` breaks that test.
- `ApiPage.isEmpty` uses the shared `EmptyState` ("Nothing to show"), not a
  feature-specific sentence. Assert the shared state heading in page tests.
- Multiple identical labels are common in version tables; use `getAllByText`
  or role-scoped queries in tests.
- A v8 coverage branch with counts like `[0, 13]` is still below 100%: the
  never-taken side must be exercised. Include a fixture that omits each
  optional field as well as one that sets it.
- An array `.sort((a, b) => ...)` comparator is only covered with at least two
  eligible items.
- When a label and an isolated `<bdi>` value render in one element, exact
  `getByText('Label')` fails because the text node includes the colon and
  spaces; assert with a regex or `getAllByText`.
- In a cloud worker, `opencode.json` is the CI profile under skip-worktree;
  `scripts/check.sh` can report it stale even when HEAD truth is green. Verify
  in a detached worktree rather than editing the protected file.
