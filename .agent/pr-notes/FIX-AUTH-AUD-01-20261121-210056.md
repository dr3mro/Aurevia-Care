# FIX-AUTH-AUD-01 — Validate the token audience in the OIDC chain

## Summary

The non-synthetic resource-server chain now fails startup with `SMARTCLINIC_OIDC_AUDIENCE must be set` when the audience is blank, and wraps its JWT decoder with a validator that requires `aud` to contain the configured audience alongside the default JWT validators and an explicit issuer validator. The issuer check is unchanged and still fails startup first with `SMARTCLINIC_OIDC_ISSUER_URI must be set`. The synthetic-auth profile is untouched. `SMARTCLINIC_OIDC_AUDIENCE` is documented as required in `apps/api/src/main/resources/application.yml`, the in-scope file that already lists the production environment variables.

Entry point → test trace: `GET /probe` → `SecurityFilterChain` (`oidcSecurityFilterChain`, order 2, non-synthetic) → `BearerTokenAuthenticationFilter` → decoder returned by `SecurityConfiguration.withClaimValidation` → 200 / 401 assertion in `AudienceValidationHttpTest`; startup guard asserted in `SecurityConfigurationTest` and `AudienceValidationHttpTest.blankAudienceFailsStartup`.

## Findings

1. **Specialist F1 (accepted and fixed).** `BrowserSessionHttpTest.bearerRequestSkipsCsrfAndReachesController` used a stub JWT with `iss` but no `aud`; the positive bearer test would have flipped to 401. Added `.audience(List.of("synthetic-api"))` to the stub and the `audiences` property to that runner; the test remains green.
2. **Specialist F2 (accepted and fixed).** Adding a required `JwtDecoder` bean parameter means Spring resolves it before the fail-closed guards. Added `DecoderStub` to the blank-issuer runner, passed the decoder and the new constructor argument in the two direct-call tests, and set the `audiences` property in every non-synthetic runner (`SecurityConfigurationTest`, `SecurityFilterChainHttpTest`, `HealthChainHttpTest`, `BrowserSessionHttpTest`).
3. **Specialist F3 (accepted).** The locally signed test token now carries `typ: JWT` explicitly so the default `JwtTypeValidator` cannot reject it for a missing header.
4. **Specialist F5 (not applicable).** The reviewer believed `JwtAudienceValidator` takes a `Collection<String>` in this version. Verified from `spring-security-oauth2-jose-7.1.2.jar` with `javap`: the public constructor is `JwtAudienceValidator(java.lang.String)`; `aud` is a collection on the token side and the validator checks `contains`. Compilation and the green tests confirm it.
5. **Specialist F4 (noted).** Spring Boot auto-configuration may also apply an audience validator when this property is set. The explicit wrapper is kept as the authoritative control: it is the only validator the locally signed-key test exercises, and it guarantees issuer + timestamp + audience validation regardless of auto-configuration behavior. Double validation is harmless (same predicate, same value); no issuer or timestamp check was removed.
6. **Exception semantics discovered during red→green.** Throwing plain `JwtException` from a decoder is converted by `JwtAuthenticationProvider` (7.1.2) into `AuthenticationServiceException`, which `BearerTokenAuthenticationFilter` does not turn into 401. The wrapper throws `BadJwtException`, which the provider converts into `InvalidBearerTokenException` → HTTP 401. This is why the rejection assertions are HTTP-level, not just unit-level.
7. **Out of scope, pre-existing.** `apps/api/README.md:25` still describes `SMARTCLINIC_OIDC_AUDIENCE` as "Recommended (fail-closed audience enforcement is a separate story)". The grep-confirmed environment table lives outside this task's scope, so the required documentation was added to `apps/api/src/main/resources/application.yml` and a follow-up task is requested below.
8. **Out of scope, pre-existing.** Two committed migrations share version V91, and the CI-profile `opencode.json` is checked out under skip-worktree. Both break repository gates in this worker but are unrelated to this change.

## Lessons for workers

- In Spring Security 7.1.2, a validation failure thrown from a `JwtDecoder` must be a `BadJwtException` for `BearerTokenAuthenticationFilter` to answer 401; a plain `JwtException` escapes as `AuthenticationServiceException`.
- `JwtAuthenticationProvider` resolves every `@Bean` method parameter before the method body, so a fail-closed guard that must produce a specific message cannot rely on a missing collaborator bean — supply a stub decoder in those context runners.
- Verify library APIs from the resolved jar with `javap` before accepting a reviewer's version-specific claim; the reviewer here had no shell access and was wrong about `JwtAudienceValidator`'s constructor.
- In cloud workers, a worktree `opencode.json` marked `S` (skip-worktree) is the CI profile; `check-pack` failures there are measurement artifacts. Compare `git show HEAD:opencode.json` with `gen_opencode.render(ROOT)` before treating them as drift, and never regenerate committed config from inside a worker.
