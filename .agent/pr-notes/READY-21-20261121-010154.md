## Findings

1. **Scope deviation (disclosed):** `apps/staff-web/tests/app/AppShell.test.tsx` is outside the declared scope. Its `route registry` test hardcoded `['/', '*']` and necessarily failed once the two required routes were registered. I made the minimal expectation-only change (add `/schedule`, `/schedule/book` to both expected arrays). No assertion weakened, no test skipped; required by AGENTS.md coverage rule 7 ("if an existing test must change because behavior changed on purpose, say so"). The integrator/owner should confirm.
2. **API contract gap:** `AppointmentController` implements `POST /api/v1/appointments`, `/check-in` and `/cancel`, but `contracts/openapi.yaml` / generated `openapi.d.ts` declare only `GET /api/v1/appointments`. `api.ts` therefore builds command descriptors locally, reusing `buildRequestDescriptor` for the tenant/correlation/version/idempotency headers. `gen:api:check` is green (no drift). Publishing the command paths belongs to a separate contract story.
3. **Live assignment is a local draft:** no appointment-assign endpoint exists (the worklist assign API targets a different aggregate). The screen keeps the local assignment behavior from the synthetic version; it is lost on reload and is not claimed as durable.
4. **Projection limits:** the API appointment has no patient name or facility time zone. The mapper shows the opaque `patientId` as the name and labels instants UTC; the "name + opaque id" and facility-zone display in the screen recipe needs a follow-up API/directory change.
5. **State gap:** API `held`/`expired` map to domain `booked`/`cancelled` (no domain equivalents). Clinical confirmation of this mapping is a G1 follow-up.
6. **`send()` cannot abort:** `useApi` ignores late aborted responses but `transport.send` has no `AbortSignal` parameter; in-flight fetches are not cancelled on tenant switch. Out of scope.
7. **Booking idempotency is client-only:** an `Idempotency-Key` is sent, but `AppointmentController.book` does not declare/consume it; server replay protection is a separate story. Double-submit is mitigated by the form clearing the slot after submit.
8. **Flake hardened:** one rare timing failure in the page assign test under coverage load was fixed with an `act()` flush before interaction; five subsequent full/coverage runs were green.

## Lessons for workers

- `buildRequestDescriptor` only accepts contract `ApiPath`s; for command routes not yet in the generated contract, build a local descriptor helper that reuses it for headers and substitutes only the URL — never cast to `ApiPath` or edit the contract from a screen story.
- Registering a new route breaks `tests/app/AppShell.test.tsx`'s hardcoded route list; update that expectation in the same change or reserve the file in scope.
- With per-file 100% function coverage, every inline JSX arrow callback must be exercised by a test; delete unreachable guards rather than writing tests that only touch a line.
- `importOriginal<typeof import('...')>` is rejected by lint (`consistent-type-imports`); use `import type * as Module from '...'` and `importOriginal<typeof Module>()`.
- When the real API needs clinical context the synthetic form never collected (patient id, facility, visit type), collect it in the form rather than fabricating values — a made-up patient id is a clinical-safety hazard.
