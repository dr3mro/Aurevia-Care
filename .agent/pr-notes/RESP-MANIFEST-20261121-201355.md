## Findings

1. **Manifest is not yet linked from the document (P1, outside scope).** `apps/staff-web/index.html` has no `<link rel="manifest" href="/manifest.webmanifest">`, so browsers will not discover the asset at runtime. `index.html` is outside this task's two-file scope and no task covers the link; a task-request is filed below. The manifest file itself and its acceptance tests are complete.
2. **Pre-existing generated-client drift blocks the mandatory module gate (P1, outside scope).** `bash apps/staff-web/check.sh` exits at `gen:api:check` with `✘ Generated types are not up-to-date!`. Verified by regenerating to a temp file and diffing: `src/api/generated/openapi.d.ts` lacks `/api/v1/order-entry/drafts`, `/api/v1/order-entry/drafts/{id}`, `/api/v1/order-entry/drafts/{id}/place` and `/api/v1/order-entry/orders/{id}` that the current `contracts/openapi.yaml` describes. `git status` showed only my two new files, so this drift exists at HEAD and is not caused by this change. Scope forbids editing the generated file here; task-request filed.
3. **`scripts/check.sh` fails on the documented CI-profile artifact (environment, not a change defect).** `git ls-files -v opencode.json` → `S` (skip-worktree); the worktree file `cmp`-equals `.github/opencode.ci.json`, so the pack check reads the CI runtime profile rather than the committed local profile. MEMORY.md and the daily-note lessons record this false positive; no agent, workflow or config file was touched.
4. **No icon assets exist** (`apps/staff-web/public/` contains only `robots.txt`), so `icons` is intentionally omitted; no icon path points at a missing file. Browser install prompts may generate a placeholder icon; adding real icon assets needs its own story.
5. Minor: `index.html` title is `Orevia Staff Portal` while the manifest name follows `project.json` (`Aurevia Care`). The arabic-style-guide records the brand-name policy as undecided, so this story kept the project identity and did not touch the HTML title.

## Lessons for workers

- Vitest 5 no longer accepts `--reporter=basic`; use the default reporter for targeted runs.
- In this cloud worker, treat a `check-pack`/`gen-opencode.py --check` staleness as the CI-profile `skip-worktree` artifact (`git ls-files -v opencode.json` shows `S`; worktree equals `.github/opencode.ci.json`). Do not regenerate or commit `opencode.json`.
- Before blaming your own change for a failing first gate step, regenerate the artifact to a temp path and diff; here the generated OpenAPI client was stale at HEAD, unrelated to two new static files. Run the remaining `check.sh` steps individually so real regressions are still caught.
- A static JSON asset under `public/` is outside Vitest's `src/**` coverage scope; write file-level tests anyway, but do not expect it to change the coverage denominator.
