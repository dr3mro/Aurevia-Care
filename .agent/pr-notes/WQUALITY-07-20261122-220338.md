## Lessons for workers

- `scripts/check-docs.py` applies its structural rules to `docs/operations/` as well as most of the tree; only `docs/swarm/`, `.agent/` and `docs/archive/` are exempt. Run it after every edit, and demonstrate the red case first by calling `markdown_errors` on a scratch malformed string (unbalanced fence, heading jump, ragged table, token pattern).
- When a runbook cites pending work, quote the exact tracker line that says it is pending. A nearby audit task about a related prerequisite is not the source of the pending phrase.
- A verification checklist that ticks a box, writes "verified" or fills a result cell defeats its own purpose. Keep the header, boxes, table and Approval in the "nothing verified" state until a person runs it on GitHub.
