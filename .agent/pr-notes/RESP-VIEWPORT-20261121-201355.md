- **Decision:** theme colours use `color.surface.default` from the normative token contract — light `#ffffff`, dark `#111827` (`docs/design/token-contract.md` section 3.1). Each has its own `media="(prefers-color-scheme: …)"` attribute so the browser paints matching chrome.
- `color-scheme` and `noindex, nofollow` were kept exactly as the story required. Note for a later owner: token-contract section 7 prefers `color-scheme` set to the active mode rather than `light dark`; changing that belongs to theme integration, not this story.
- `viewport-fit=cover` is the document-level safe-area enabler that lets CSS `env(safe-area-inset-*)` inset content. No CSS inset was added: the story's steps enumerate only the viewport and theme-colour metadata and the declared scope has no stylesheet.
- **Evidence provenance:** test, coverage and gate results are executed tool commands; the senior-react review is simulated; no simulated user, human participant or clinician was involved.
- **Simulated senior-react review** (bounded, two scoped files only): no blocking findings. Two low-impact hardening suggestions were adopted — exact viewport string equality (a token matcher accepted `initial-scale=1.5`) and an explicit `color-scheme` regression guard, because the story requires keeping that meta.

## Lessons for workers

- When the module `check.sh` is red at a gate outside the declared scope, prove the drift with a temp generation plus `diff` and run every remaining gate step directly. Never "fix" out-of-scope generated files to turn the script green.
- Root `scripts/check.sh` runs the full `mvn -q -B verify` through `apps/api/check.sh`; swarm workers must use the module gate instead.
- A theme-color meta per scheme needs its own `media` attribute; one meta with a comma-separated media list is a different design and fails this test.
- `viewport-fit=cover` is what makes safe-area insets available — assert it explicitly, because zoom (no `user-scalable=no` / `maximum-scale`) and safe-area are independent accessibility requirements.
