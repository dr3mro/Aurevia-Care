# SPEC-CLN-04-C03 — OB/GYN captures LMP and structured obstetric history (CLN-04 clause 3)

## Summary

Added a focused clause-evidence API/domain test and the required spec-clause document. The clause **is implemented** in `com.aurevia.smartclinic.clinical.templates`: the OB/GYN baseline captures `lmp` (required `DATE`) and `obstetricHistory` (required `CODE` bound to the approved `obstetric_history` site dictionary); `TemplateService` validates ISO date format, dictionary membership and requiredness, and freezes the field meanings and dictionary entries on save. No production code, contract, migration or existing test was changed. Tests are active (not `@Disabled`) because the clause is built.

## Affected requirements

CLN-04 (clause 3 — OB/GYN LMP and structured obstetric history from the approved site dictionary).

Acceptance mapping:
- Rule met → `obgynNoteCapturesLmpAndDictionaryBackedObstetricHistory` (valid LMP + in-dictionary code validate, save and freeze meanings).
- Forbidden code → `obstetricCodeOutsideTheApprovedSiteDictionaryIsRefused`.
- Missing input → `obgynNoteWithoutLmpIsRefused`.
- Invalid format → `obgynNoteWithMalformedLmpIsRefused`.
- Unapproved dictionary → `obgynTemplateCannotBeApprovedBeforeItsDictionaryIsApproved`.
- Wrong role → `nonClinicianCannotSaveAnObgynNote`.

- When a spec clause is implemented in a domain service with no REST controller, write the clause-evidence test against that service's public entry point (as the neighbouring CLN-04 tests do) instead of inventing an HTTP route; state the entry-point-to-test trace explicitly.
- A test-only change needs no new JaCoCo branch mapping: confirm 100% on the exercised production classes from the unit suite and state that no production file changed; the integrator owns the full gate.
- Do not re-diagnose `opencode.json` "stale" in a worker: `git ls-files -v opencode.json` → `S` means the CI profile is installed under skip-worktree (OPS-CW-003-01). Record the failing command and final line and run the remaining gate stages individually.
- Check the exact bytes around any `git grep` conflict-marker hit before treating it as a merge defect; committed markers inside Javadoc comments are harmless to compilation and may be out of scope.
