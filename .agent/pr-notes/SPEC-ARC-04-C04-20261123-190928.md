## Lessons for workers

- Check where the assertions a clause story names actually live before writing anything: a `web`
  scope can be stale when the behavior and the clause-doc convention belong to `exchange`. With no
  maintainer channel in a swarm run, stop and file `task-requests` instead of guessing a new home.
- A story template can mandate a mechanism the quality gate forbids. `@Disabled("GAP: …")` fails the
  added-line constraint check even though four grandfathered examples exist; the compliant handoff
  is active green tests for what exists plus `## Status: Partly proven` and a full test design in
  `## Gap` (see the exchange retention clause doc). Never lower a threshold or add an exclusion.
- `python3 -I -m unittest … | tail -N` reports the exit code of `tail`, not of the test run. Always
  read the `Ran … / OK|FAILED` summary (or use `set -o pipefail`) before recording a green result.
- Confirm a documented cloud-worker false positive once (here `git ls-files -v opencode.json` → `S`
  plus comparison with `.github/opencode.ci.json`), record the command and final line, and do not
  re-diagnose or edit the protected file on a later pass.
