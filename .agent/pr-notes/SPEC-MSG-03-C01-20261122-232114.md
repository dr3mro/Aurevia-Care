# SPEC-MSG-03-C01 — Allow both sides to attach PDFs and JPEG/PNG images

## Summary

Added a focused, clause-only API proof that a verified patient and an authorized unit
staff member can each attach all three supported file types (PDF, JPEG, PNG), with
negative cases showing unsupported or mismatched files, roles without upload permission,
wrong bindings and unknown grants are refused. Added the matching clause evidence doc.
The clause was already fully implemented; this change is proof only.

## Lessons for workers

- For a clause-proof test that claims "both sides", assert the server-derived unit,
  patient, organization and uploader binding on every returned attachment; assertions on
  file type and state alone do not prove the bind-to-uploader rule.
- The staff HTTP upload fixture uses a PDF payload; exhaustive PDF/JPEG/PNG proof for the
  staff side lives in the domain tests (`StaffAttachmentDomainTypesTest`,
  `StaffAttachmentServiceTest`). Cite each piece of evidence for what it actually proves.
- In a cloud worker, `git ls-files -v opencode.json` returning `S` explains
  `check-pack.py`/`test_check_pack` failures. Confirm with `git show HEAD:opencode.json`,
  record the failing command and final line once, run the remaining gate stages
  individually, and never regenerate or commit that generated file.
- Run SpotBugs only after compiling (`-DskipTests compile spotbugs:check`); a bare
  `spotbugs:check` is vacuously green. Do not run `scripts/check.sh` or full `mvn verify`
  in a swarm worker.
