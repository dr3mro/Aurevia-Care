# START-12 · Docs: service level objectives and alert thresholds

## Summary

Added `docs/operations/slo.md`. It contains one table of seven objectives
(availability, API read latency, API command latency, recovery point and time,
critical-result acknowledgment time, partner delivery age, queue age). Each row
gives the exact specification target, how it is measured, the metric or log that
exists today, the alert threshold and who is called. Items not produced by code
are marked `NOT MEASURED YET:` with a suggested task title. No metric name was
invented; no number was invented where the specification has none. No other file
was changed; `docs/reference/index.md` was not touched (START-18 owns it).

ADM-01, ADM-02, ARC-05, MSG-05, MSG-06, PAT-01.

## Findings

- The specification fixes numbers only for availability (99.9% monthly), p95 read
  (≤ 500 ms), p95 command (≤ 900 ms) and recovery (RPO ≤ 15 min, RTO ≤ 4 h). It
  gives **no** numeric target for critical-result acknowledgment time, partner
  delivery age or queue age; those are site-configured due times
  (XCH-05, ADM-01/ADM-02). The page says so instead of inventing numbers.
  Source: `PROJECT_V1_SPEC.md` lines 21, 136-138 and
  `docs/operations/s_g5_11/queue-catalog.md` lines 100-104.
- The `observability` package contains only `RequestLogFormatter` (fixed JSON
  fields `correlationId`, `method`, `route`, `status`, `latencyMs`) and
  `CorrelationIdFilter` (`X-Correlation-Id`, MDC key `correlationId`, route label
  `UNMATCHED`). There is no Micrometer/Prometheus registry, p95 aggregation,
  external uptime probe, queue-age gauge, delivery-age gauge or backup collector.
  All seven rows therefore carry a `NOT MEASURED YET` marker for the runtime
  producer; the page does not claim live monitoring.
- The five-minute figure in the pilot metrics is approved-release visibility to
  the patient, not partner delivery age; the page records that distinction so a
  reader cannot misapply it.
- Owner roles are taken from `docs/operations/s_g5_06/operational-runbooks.md`
  and `docs/operations/production-readiness/launch-checklist.md`; no person or
  contact detail is stored.
- Existing repository state observed but not changed: `TODO.md` contains a
  duplicated task section with a conflict block. Out of scope for this worker;
  left for the integrator.

## Lessons for workers

- Read the exact numeric targets from the specification and the evaluators
  (`infra/s_g5_05/capacity_evidence.py`, `infra/s_g5_06/recovery_evidence.py`)
  before writing an SLO page; some OPS-05 signals have no numeric target and must
  be described as site-configured rather than assigned an invented number.
- Quote field/constant names from the code you actually read. For this repository
  the only request-level telemetry in `src/main` is the request-log JSON line and
  the two health routes; everything else is a domain record, an audit event or an
  offline evidence evaluator.
- When a docs-only task points at `python3 -I scripts/check-docs.py`, do not also
  run `scripts/check.sh` — it fans out to the full Java verify and PostgreSQL
  integration suites and breaks the worker time cap.
- `docs/reference/index.md` is owned by START-18: add the page but never edit the
  index in a parallel docs task.
