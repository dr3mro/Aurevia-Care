## Findings

- Source survey result: the clause IS built. Implementation found in
  `patient/consolidation/ConsolidationService.correct`, `ConsolidationController`
  (`POST /{reviewId}/correct`), `DuplicatePolicy.CORRECT` (tenant_admin only),
  `Consolidation`, `DuplicateReview`, `DuplicateRepository` append operations, with
  audit via `appendAudit`; neighbours in `patient/identity/`. Public route in
  `contracts/openapi.yaml`, tables in `db/migrations`. Nothing missing; Status in
  the clause doc is "Proven by tests" and Gap is "None".
- Independent QA review (simulated reviewer, files tool-inspected by the reviewer)
  found two proof-quality defects, both fixed in this branch:
  1. The doc claimed the correct route was declared in `contracts/openapi.yaml`.
     Verified by tool: it is not; `POST /api/v1/duplicate-reviews/{}/correct` is in
     `contracts/openapi/missing-routes.txt:202`, the baseline of undocumented routes.
     The Evidence section was corrected and `## Gap` now records this one-task
     contract gap (Status stays "Proven by tests" for behavior).
  2. `correctionViaApiDeniesNonAdminRolesAndAuditsTheRefusal` did not stub
     `activeRoles("auditor-a")`, so both denials were evaluated as the default
     `reception` role and a regression granting `CORRECT` to `privacy_auditor`
     would not be caught. The test now explicitly assigns `privacy_auditor` to that
     subject; the doc's role-denial claim is now true.
- The only failures observed were the two self-inflicted test mistakes above and
  the known environment false positive; none indicates a production defect.
- `scripts/check.sh` cannot complete in this worker because of `check-pack.py`
  measuring the skip-worktree CI profile (OPS-CW-003-01), documented in AGENTS.md.
  This is not a defect in the change and the integrator owns the full gate.
- Pre-existing defect outside this task's scope: `git grep -nE '^(<<<<<<<|>>>>>>>) '`
  on HEAD (after `git merge --no-edit origin/main`, which reported "Already up to
  date") finds committed conflict markers inside Javadoc comments in
  `apps/api/src/main/java/com/aurevia/smartclinic/exchange/hl7/Hl7ParseException.java`
  (lines 6/10), `Hl7Parser.java` (14/18) and `Hl7Segment.java` (10/14). Both sides
  of each marker have identical text; they are inert inside `/** ... */`, so Java
  compilation and all tests pass, but they are real committed merge residue from

  edit these production files. Evidence: tool output from `git grep` and `sed -n

## Lessons for workers

- `TenantContextInterceptor.afterCompletion` clears `TenantContext`; after a
  MockMvc request `TenantContext.current()` is null. Capture the context with an
  `ArgumentCaptor<TenantContext>` on `appendAudit` instead of reading it afterwards.
- A missing `If-Match` header is rejected by Spring as 400 before `IfMatch.parse`;
  send an empty header to exercise the 428 `PRECONDITION_REQUIRED` path.
- Mockito requires every argument be a matcher once one argument uses a matcher;
  use `eq()` for literal values in `verify`.
- For a proof-only clause task, run the targeted test plus the fast unit suite and
  the individual gates; `scripts/check.sh` stops early on the documented
  skip-worktree `opencode.json` false positive in a cloud worker.
