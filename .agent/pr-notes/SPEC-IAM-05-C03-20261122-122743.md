# SPEC-IAM-05-C03 — IAM-05 clause 3 (API test)

## Summary

Added one focused API-level proof for IAM-05 clause 3, "Unlinking immediately
ends future account access for the affected chart", and its clause evidence
document. No production code, existing test, contract or migration was changed.

Source survey (step 1 of the task) found the clause implemented in:
`apps/api/src/main/java/com/aurevia/patient/identity/IdentityProofingController.java`
(routes `POST /links/unlink`, `GET /accounts/{subject}/access`, `GET /accounts/{subject}/links`
under `/api/v1/patient-identity`), `IdentityProofingService.java` (appends an
`unlinked` event and retires unspent invitations), `IdentityProofingRepository.java`

(the append-only event projection) and `db/migrations/V10__patient_identity_proofing.sql`
(forced RLS, append-only triggers and the current-link fold). An existing broader
proof is `IdentityProofingIsolationTest.unlinkEndsFutureAccessButKeepsSiblingLinks`.

## Findings

1. **Repeat unlink is accepted.** A second unlink of an already-unlinked chart
   returns HTTP 200 and appends a second `unlinked` event rather than 404.
   `IdentityProofingService.unlink` tests `repository.currentLink(...).isEmpty()`,
   but `currentLink` returns the latest event of any type, so a terminal
   `unlinked` event still counts as a current link. Access remains `false`, so
   this is not an IAM-05 clause-3 violation and no production change was made.
   Reproduced by the first run of
   `unlinkOfAChartWithNoCurrentLinkIsRefusedAndAccessStaysEnded` (now corrected to
   a never-linked chart). Paths:
   `apps/api/src/main/java/com/aurevia/patient/identity/IdentityProofingService.java`,
   `.../IdentityProofingRepository.java`.
2. **OpenAPI contract gap (separate task).** The `/api/v1/patient-identity/*`
   routes, including `/links/unlink` and `/accounts/{subject}/access`, are not in
   `contracts/openapi.yaml`; they are baselined in
   `contracts/openapi/missing-routes.txt` (lines 67-68 and 251-255). The clause
   doc states this accurately. Out of scope here (contract is protected).
3. **Pre-existing committed conflict markers (not caused by this work).**
   `git grep -nE '^(<<<<<<<|>>>>>>>) '` finds markers committed in `HEAD` and
   `origin/main` in `apps/api/src/main/java/com/aurevia/exchange/hl7/Hl7ParseException.java`,
   `Hl7Parser.java` and `Hl7Segment.java` (they sit inside Javadoc so the build
   still compiles). `git merge --no-edit origin/main` reported
   `Already up to date.`; these were not introduced or resolved here because they
   are production files outside this task's scope.
4. **Known worker false positive.** `bash scripts/quick-check.sh` stops at
   `check-pack: opencode.json is stale`. Confirmed OPS-CW-003-01:
   `git ls-files -v opencode.json` -> `S opencode.json` (skip-worktree CI profile)
   and `git diff HEAD -- opencode.json` is empty. The integrator owns that gate.

## Lessons for workers

- For append-only event folds, "no current link" means the pair was never
  linked: `currentLink` returns the latest terminal event too. Before writing a
  404/forbidden-state negative, check whether a terminal event still satisfies
  the service's emptiness test.
- Verify documentation claims against the repository before writing them. The
  patient-identity routes are baselined as missing from the OpenAPI contract, not
  documented in it.
- Inside a worker, a `check-pack` staleness report is the CI profile measured
  under `skip-worktree`; confirm with `git ls-files -v` and `git diff HEAD` before
  treating it as a defect, then run the remaining gates individually.
