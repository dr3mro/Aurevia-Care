# BUILD-63 — Gate G3 acceptance tests: patient access, messaging and operations

## Summary

Added a synthetic, database-free acceptance suite under
`apps/api/src/test/java/com/aurevia/acceptance/patient` that proves the ten G3
scenarios named in the story through the real domain services. Six test classes, 18 tests.
No production code, dependency, scope or migration was changed; no tracker was edited.

## Affected requirements

PAT-01, PAT-02, PAT-03, MSG-01, MSG-02, MSG-03, MSG-04, MSG-05, MSG-06, MSG-07, G3.
Supporting: IAM-05, XCH-06, ARC-02, ARC-06, ARC-07, OPS-02, OPS-05, PRD-03.

## Risk class

Cross-boundary / safety-critical evidence only (docs/WORKFLOW.md): the tests assert patient
authorization, wrong-unit denial, connection revocation, withdrawn releases and clinical-text
leakage. They add no runtime behavior and no PHI/credential-bearing fixture. Evidence source:
executed tool commands (local, synthetic fixtures); no simulated-user, clinician or human
participant evidence is claimed.

## Review owner

Senior Java and Spring Boot / Test Engineer / QA Reviewer (simulated specialist routing via the
loaded skills). Independent human clinical acceptance remains a G5 gate.

## Data changes

None. No Flyway migration, no schema change, no reserved version consumed. All identifiers,
subjects, content references and payload metadata are synthetic (for example `syn-patient`,
`patient-1`, `document-1`, `a`*64 checksums).

## Authorization boundaries and audit events

Asserted that: tenant context is required and the verified chart link is re-read on every
protected report access; a foreign patient revision is concealed with 404 and a DENIED audit
fact; a withdrawn release yields 410 plus a WITHDRAWN audit fact; a wrong-unit connection is
denied with 403; revocation immediately blocks a patient reply and no message is inserted;
an upload reaches only its granted unit inbox; an acknowledgment is bound to one exact
instruction revision; a notification retry appends a new generic dispatch fact. No new audit
events were added — the existing audit sinks were asserted.

## Migration and rollout considerations

None: test-only change. No rollout or rollback impact.

## Findings

1. No product defect was found. All ten scenarios are provable against the current domain
   services with synthetic fixtures.
2. These are domain-service acceptance tests with in-memory or mocked infrastructure ports,
   not HTTP-plus-PostgreSQL tests. The corresponding controller/HTTP tests already exist on
   main (`messaging/reports/ReleasedReportControllerHttpTest`,
   `it/exchangerelease/PatientReleasedRevisionsControllerHttpTest`,
   `messaging/appointments/PatientAppointmentControllerHttpTest`,
   `it/messaging/ConversationHttpSecurityTest`,
   `messaging/attachments/AttachmentControllerHttpTest`,
   `messaging/acknowledgment/InstructionFactControllerTest`,
   `messaging/evidence/GateEvidenceControllerHttpTest`). The integrator runs the database and
   full HTTP/integration tier.
3. Pre-existing red gate, out of this task's scope: the worktree `opencode.json` carries flag
   `S` (skip-worktree) and holds the CI profile, so `gen-opencode.py --check`,
   `check-pack.py` and three `test_check_pack` cases fail locally. Verified
   `git show HEAD:opencode.json` **equals** the generator render while the worktree copy does
   not (BUGS OPS-CW-003-01, already closed as a false positive). No config was edited.
4. Pre-existing red gate, out of scope: `bash scripts/frontend-check.sh` fails on
   `src/app/routes.test.tsx` and `tests/app/AppShell.test.tsx`, which hard-code 20 routes
   against 27 registered (TODO `FIX-ROUTES-01`). The patient-mobile part of the same script
   is green.
5. `bash scripts/check.sh` and `mvn verify` were intentionally not run: they execute every
   integration test and the long OWASP/SpotBugs/JaCoCo gates that this story forbids workers
   from running. The integrator must run them on the merge result.

## Lessons for workers

- A Mockito `thenAnswer` for `ConversationRepository.find(...)` must return
  `Optional.of(conversation)`; returning the bare record fails with a `ClassCastException`
  inside `ConversationService.open`.
- When a mocked repository projection is returned to the caller, capture what the service
  persisted (for example with `doAnswer` on `insertConversation`) and feed it back into the
  mock, otherwise state assertions test the stub rather than the command.
- `CareUnitDirectoryService.connect` requires the patient context; do not call it from a
  repository stub that may run under a staff context — resolve the connection id once in
  `setUp` while the patient is bound.
- Inside a cloud worker, a stale `opencode.json` check is usually the CI profile under
  skip-worktree. Compare `git show HEAD:opencode.json` with the generator render before
  treating it as a real drift.
- `scripts/frontend-check.sh` can be red because of unrelated `FIX-ROUTES-01`; record it as
  pre-existing rather than trying to fix frontend files from a backend-only scope.
