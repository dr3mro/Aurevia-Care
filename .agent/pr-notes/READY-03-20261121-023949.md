# READY-03 · Per-subject rate limiting with 429 and Retry-After (WEB-04)

## Summary

Added an instance-local, per-subject rate limiter behind the protected-API interceptor. Each allowed call is counted in a one-minute window keyed by `organization + ":" + subject`; when the allowance is exhausted the interceptor sets `Retry-After` and throws `ApiException(429, "RATE_LIMITED", "too many requests")`, rendered by the existing `ApiErrorHandler` as a machine-readable body. Windows older than two minutes are evicted on every call. The limit comes from `smartclinic.rate-limit.per-minute` (default 600). On rejection the interceptor sets the header, clears the request-scoped tenant context and throws, because Spring does not call `afterCompletion` for an interceptor whose `preHandle` threw. Counters are process-local by design; the edge WAF supplies the global limit (WEB-01), which is stated in the `RateLimiter` class Javadoc.

## Findings

- **Constructor call sites (surprise, resolved without scope violation).** 17 tests outside `apps/api/src/test/java/com/aurevia/smartclinic/web` construct `new TenantContextInterceptor(environment)`. Changing the existing signature would have forced edits outside the declared scope, so the legacy `(Environment)` constructor was preserved and a second `@Autowired (Environment, RateLimiter)` constructor was added for Spring and for the new HTTP test. The legacy constructor still reads the same property from `Environment` and uses `Clock.systemUTC()`; production uses the injected `Clock` bean. Next worker: do not collapse these constructors without first widening the task scope to those 17 files.
- **Tenant-context leak on the 429 path (real defect found by review, reproduced red, fixed).** Spring's `HandlerExecutionChain` skips `afterCompletion` for an interceptor whose `preHandle` throws. Setting `TenantContext` and then throwing the 429 would leave the rejected request's `(organization, subject, correlation)` bound to the servlet thread, and a later request failing early could echo the stale correlation through `ApiErrorHandler.correlation()`. `enforceRateLimit` now calls `TenantContext.clear()` immediately before throwing; the regression assertion sits inside the test, before its `@AfterEach`, so it cannot be masked by test cleanup. The senior-backend subagent reported this from static file reads only (no shell was available to it); the failure was then reproduced and the fix verified locally with executed commands (tool evidence). Next worker: any new throw after `TenantContext.set` must clean up explicitly.
- **`opencode.json` CI-profile artifact (environment, not a defect).** `git ls-files -v opencode.json` shows `S` and the worktree file equals `.github/opencode.ci.json`, so `check-pack.py` reports it stale. This is the recorded OPS-CW-003-01 false positive; the temporary restore documented in Test evidence §5 made the real gate pass with no file change.
- **Per-instance semantics.** The `RateLimiter` bean is a singleton per Spring context, so tests share a counter within one `@SpringBootTest` class. Default 600/min is comfortably above the request count of any existing HTTP test class (largest observed ~58), and each HTTP integration class uses a distinct datasource property and therefore a distinct context. No existing test began returning 429.
- **Config-wiring gap (review finding, closed).** A directly constructed `RateLimiter` cannot prove the `@Value` property name is right. `RateLimiterConfigurationTest` now builds a tiny `AnnotationConfigApplicationContext` with a pinned `Clock` bean and a non-default property (2) and asserts the third call is rejected, plus a default-600 case. No threshold or exclusion was changed.
- **No remaining product defect observed.** No BUGS.md entry is warranted from the final change.

## Lessons for workers

- Before changing a shared Java constructor's signature, run `grep -rn 'new <Class>' apps/api/src` first; if callers sit outside the story scope, add an `@Autowired` overload instead of editing out-of-scope tests.
- In a swarm worker, check `git ls-files -v opencode.json` before trusting `check-pack.py`/`gen-opencode.py --check`; `S` plus worktree == `.github/opencode.ci.json` means the only failing check is the known measurement artifact, and the trusted `restore_config` sequence is the safe way to run the gate.
- For a plain helper that needs an injected `Clock` and a property, keep it a plain POJO and expose it as a small `@Bean` in the same domain package; that keeps direct unit construction with a mutable fake clock possible without annotation-driven magic inside the class.
- When a `ThreadLocal` is set in `HandlerInterceptor.preHandle`, every throw after the set must clear it explicitly: Spring does not call that interceptor's `afterCompletion` on a `preHandle` throw. Put the regression assertion inside the test method, not only in `@AfterEach`, or the cleanup will hide the leak.
- After a main merge, re-check `git diff origin/main...HEAD --name-status`: an auto-resolved conflict can leave edits in out-of-scope files (here two `scripts/` files). Restore those files to `origin/main` before committing so the pull request stays within its declared scope.
- 100% JaCoCo on a shared private method does not prove every caller calls it: if auth branches (JWT vs synthetic) both funnel into one helper, add a distinct HTTP test per branch so a future regression that drops the call from one branch is caught.
