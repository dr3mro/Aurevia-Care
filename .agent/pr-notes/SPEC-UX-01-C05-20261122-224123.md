## Findings

- Story step 3 asks for a skipped `it.skip("GAP: ...")` test when a clause is partly
  built. That conflicts with `AGENTS.md` ("no test left `@Disabled`, `.skip` or
  `xit`") and `scripts/check-constraints.py:52-53`, which fails any added skip in a
  `.ts` file. The advisor brief resolved the conflict the same way: keep every new
  test green, record the missing behaviour in `## Gap` plus the `task-requests`
  block below. Decision follows the higher-authority rule; the PR stays green and
  the gap is explicit for the integrator.
- The status is `Partly proven`, not `Proven by tests`. `docs/design/token-contract.md`
  §8.1 records that `ThemeTokens` is a six-field subset, that the focus-ring token is
  a defective v0 box-shadow string, and that the value which actually paints is a
  raw literal at `apps/staff-web/index.html:12`. The new test deliberately does not
  assert `dark.focusRing === light.focusRing`, because §8.1 requires that existing
  defect-encoding assertion in `tests/theme/tokens.test.ts` to be replaced, not
  copied into a second file.
- Pre-existing, out-of-scope defect observed with a tool: committed conflict markers
  exist at HEAD in `apps/api/src/main/java/com/aurevia/exchange/hl7/Hl7ParseException.java:6,10`,
  `Hl7Parser.java:14,18` and `Hl7Segment.java:10,14` (verified with `git show HEAD:...`
  and `git ls-files -u` showing no unmerged index entries). `git merge --no-edit
  origin/main` reported "Already up to date." Not fixed here: outside task scope and
  owned by another worker. Evidence source: executed shell command.

## Lessons for workers

- When a spec story asks for a skipped "GAP" test, do not write it: `scripts/check-constraints.py`
  rejects added `.skip`/`xit` in any `.ts` file and `AGENTS.md` forbids skipped tests.
  Record the missing behaviour in the clause doc's `## Gap` and in a `task-requests`
  block instead; the integrator turns that into real tasks.
- Do not pin a known defect as an expected value in a new test. Repeating
  `dark.focusRing === light.focusRing` from `tests/theme/tokens.test.ts` would have
  created a second assertion that the contract §8.1 adoption must delete. Prove the
  parameterisation with sentinel values instead, and put the defect in `## Gap`.
- `tsc --noEmit` prints nothing on success. Paste the `npm run typecheck` final line
  into the notes so the evidence is visible; Vitest green alone is not the
  frontend definition of done (`bash apps/staff-web/check.sh` is).
- The staff-web coverage scope is `src/**/*.{ts,tsx}`. A new file under `tests/`
  cannot lower per-file coverage, but the full `check.sh` still must be run and its
  coverage summary pasted; do not infer 100% from the config alone.
