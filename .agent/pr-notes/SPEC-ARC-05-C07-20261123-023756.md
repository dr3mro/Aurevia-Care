# SPEC-ARC-05-C07 — confirm order and patient identifiers before linking external data

## Summary

Adds one clause-focused JUnit 5 test class and one clause evidence note for ARC-05's rule
"Confirm order and patient identifiers before linking external data" (SMARTCLINIC_V1_SPEC.md:124).
The rule was already implemented in `DurableEventService.linkExternal`; this change adds proof only.
Twelve active tests cover the positive link, the role gate, concealment of unprocessed, mismatched,
rejected and cross-tenant data, the live existence re-check, the thin controller, and a real
`POST /api/v1/delivery/external-links` request through MockMvc. No production code, existing test,
contract or migration was changed.

## Findings

- The context-optimizer initially judged the clause "Partly proven" because no HTTP-level test existed
  for `POST /api/v1/delivery/external-links` and the route is unpublished in `contracts/openapi.yaml`.
  This change adds the MockMvc HTTP test for that route; the OpenAPI gap is pre-existing, baselined in
  `contracts/openapi/missing-routes.txt:186`, tracked outside this test-only task and recorded in the
  clause note's Evidence rather than claimed as fixed.
- `test-engineer` recommended a real route test; it is included as
  `externalLinksRouteLinksOnlyAnAuthorizedClinicianAfterConfirmation`.
- Pre-existing, unrelated committed conflict markers remain in Javadoc of
  `apps/api/src/main/java/com/aurevia/smartclinic/exchange/hl7/{Hl7ParseException,Hl7Parser,Hl7Segment}.java`
  (`<<<<<<< HEAD` / `>>>>>>> origin/swarm/BUILD-37-469`). They are inside comments, do not affect
  compilation, predate this task and are outside its scope; they were not edited. `git merge --no-edit
  origin/main` reported "Already up to date", so no conflict needed resolving here.
- The six Python tooling failures and the `worker-check.sh` stop are the documented `opencode.json`
  stale-profile worker-image false positive; verified once and not re-diagnosed or edited.
- Applied the coverage auditor's Optional hardening: the mismatch tests now supply a second *existing*
  order/patient pair (`OTHER_ORDER`/`OTHER_PATIENT`), and the REJECTED test also seeds a rejected receipt
  carrying valid `ORDER`/`PATIENT`. Each guard is now the only conjunct that can fail, so removing it
  would break a named test. Re-ran the targeted command after the edit: `EXIT:0`, 12/12 and 25/25.

## Lessons for workers

- Read the full `confirmed` chain before naming negatives: `consume` turns an unknown order/patient into
  a REJECTED receipt, so to take `orderExists=false` / `patientExists=false` in `linkExternal` you must
  seed an ACCEPTED receipt directly with `putReceipt`; otherwise the outcome guard short-circuits and the
  test passes for the wrong reason.
- A cross-tenant concealment test needs an authorized subject in the second tenant (e.g. a clinician),
  not a worker, or it returns 403 instead of the intended 404.
- Authorization precedes the receipt lookup: pin that ordering with a 403 assertion for a missing id.
- A direct controller call proves delegation, not route reachability; one standalone MockMvc POST with
  the synthetic-auth headers and the real interceptor closes that gap without a database.
- In a cloud worker, confirm the `opencode.json` stale failure once with `git ls-files -v` (`S`) and
  `git show HEAD:opencode.json`, run the remaining stages individually and do not regenerate the file.
