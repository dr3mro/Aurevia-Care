## Lessons for workers

- Re-execute and read the Surefire reports **before** writing a green count into evidence documentation; `mvn -q` suppresses the "Tests run" line, so exit 0 alone is not a test count. A read-only reviewer correctly flagged this ordering risk.
- A targeted `mvn -Dtest=…` still compiles the whole test tree. When an unrelated test source on `main` breaks compilation, record the exact command and final error and fall back to merge-commit evidence with an explicit caveat; when the break is already fixed on `main`, verify with `grep`/`git log` and do not reapply it.
- After recording a re-execution, re-read every HEAD reference and phrasing ("a targeted Maven attempt", "not by this worker") elsewhere in the note; stale prose beside a correct result is still a false claim.
- A resolved item under an "Open items" heading is self-contradictory; rename the heading or move the item when correcting it. Do not change any criterion status or caveat to make a narrative cleaner.
- Scope a conflict-marker check to the files you touched: pre-existing committed markers on the base branch are not your merge conflict. Prove their provenance with `git grep ... <base>` before deciding not to fix them.
- `scripts/check-verdicts.py` short-circuits when every changed path is documentation; the `## Review verdicts` section should still list only reviewers actually run, not claim verdicts that were never given.
