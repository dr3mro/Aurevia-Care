## Authorization boundaries and audit events

No new audit event or authorization rule was added. The tests assert the existing boundaries:

- 404 `NOT_FOUND` for a patient naming another patient's subject, with no patient-existence probe,
  no link probe, no `requireActive` call and no write — existence concealment.
- 403 `FORBIDDEN` when a connection verified for one unit is used to open a conversation for a
  second recipient unit.
- 422 `INVALID_ASSIGNEE` for a target eligible only in another unit, with no assignment, work event
  or success audit.
- `CONVERSATION_OPEN` success audit on a valid verified-connection open.

The missing `CONVERSATION_DISCLOSE` audit event is the security gap recorded in the doc `## Gap`.

## Findings

1. **Brief corrections (advisor guidance, not rules).** The brief listed a "fixed clock" fixture,
   but `ConversationService` has no `Clock` dependency; a fixed `Instant` is used in the synthetic
   projection instead. The brief listed `V91__staff_messaging.sql` and `V62__messaging_governance.sql`
   as the messaging migrations; those are unrelated features, and the conversation migration with
   the immutable-recipient guard is `V33__conversation_lifecycle.sql`. The brief expected one skipped
   GAP test; that spelling is incompatible with the gate (finding 2).
2. **Tooling conflict on the GAP test (tool evidence).** The story and brief asked for a complete
   `@Disabled("GAP: ...")` test. A draft with that annotation compiled and ran green
   (`tests=4 skipped=1`) but `python3 -I scripts/check-constraints.py` returned EXIT=1 with
   `disabled test: @Disabled(...)`; `quick-check.sh`, `quality-gate.sh` and `integrator-gate.sh` all
   invoke that check. The four legacy GAP tests predate the gate (committed 08:41–08:42 on
   2026-11-22; the gate was added at 09:41), so they are grandfathered. AGENTS.md also forbids a
   test left `@Disabled`. The gate-compliant resolution, confirmed by both the plan reviewer and the
   test engineer, is no skipped test: the exact GAP (missing artifacts, files to change, task count
   and the complete test to enable) is recorded in the doc `## Gap`. The PR stays green.
3. **No add-recipient or disclosure path exists.** Context Optimizer searched `messaging`,
   `contracts/` and `db/migrations/` for `DISCLOSE`/`disclos`/recipient/participant and found none;
   `exchange_disclosure` in V19 is XCH-01, not messaging disclosure. Status is therefore
   "Partly proven", not "Proven by tests".
4. **Existing coverage cited, not duplicated.** `ConversationServiceTest` and `ConversationFlowTest`
   already exercise the other refusal and immutability branches; they are named in the doc.
5. **Environment false positives** are recorded under `## Test evidence` and were not re-diagnosed.

## Lessons for workers

- Before writing a clause GAP test, check whether `scripts/check-constraints.py` rejects the
  annotation on an added line: a new `@Disabled` in Java fails `quick-check.sh` even though older
  grandfathered GAP tests use it. Carry the exact gap in the in-scope clause doc `## Gap` instead.
- `git ls-files -v opencode.json` showing `S` explains every `check-pack.py`/`test_check_pack`
  "stale" failure in a cloud worker; verify with the committed profile and do not regenerate it.
- In a mocked domain test, assert the persisted values and the no-write/no-audit outcome, not just
  that a method was called; and clear `TenantContext` in `@AfterEach` so parallel tests are safe.
- `scripts/check.sh` (and a bare `mvn verify`) runs the full gate and times out a worker; use targeted
  `-Dtest=...`, compile-then-`spotbugs:check`, and the individual policy scripts instead.
