## Findings

- Brief imprecision: the brief said to use `src/fixtures/synthetic.ts` fixtures for the note editor. That module has no `NoteRevision` or `SoapContent`; it only exports organization/facility/staff/person/instant fixtures. The test therefore uses a local `draftRevision(content)` test-data builder (domain type from `./features/chart/domain`) seeded with `syntheticFacility.organizationId` and `syntheticInstant` from `src/fixtures/synthetic.ts`. The plan reviewer raised this as Required and accepted the fix.
- Test engineer required three design fixes, all adopted: prove typed work survives the edit→conflict transition via `onContentChange` + `rerender` rather than asserting a statically seeded value; replace the brittle `role="alert"` absence query with conflict-specific queries and prove Retry-only invocation for the server case; add the no-handler/default-noop negative case.
- Two TypeScript errors and one ESLint error were found by `check.sh` and fixed in the same change: `createElement(I18nProvider, …)` needed a typed props variable (children supplied as an additional argument) and two `getByRole` calls needed `HTMLButtonElement` generics. Final `check.sh` is green.
- No clause-doc registry exists in `docs/spec`; `check-docs.py` passes without one. The planned `docs/spec/clauses/platform/index.md` belongs to a separate dependent task and was deliberately not created (out of scope).
- No reproducible product defect was found; the clause is implemented and the new evidence passes. `BUGS.md` was not touched.

## Lessons for workers

- In a proof-only staff-web task, the post-code `check.sh` still runs typecheck, type-aware ESLint, build and the WEB-08 budget; a Vitest-only green is not done. `createElement` with a provider that declares required `children` needs a typed props variable (children as an extra argument) to satisfy both `tsc` and `react/no-children-prop`.
- Assert note-editor DOM with role generics (`getByRole<HTMLTextAreaElement>`, `<HTMLButtonElement>`) and re-query after `rerender`; a captured node can report a stale `.value`.
- The shared docs checker has no clause index to update here; respect a task's two-path scope instead of creating the planned index, which belongs to a dependent task.
- jsdom `Not implemented: navigation` lines from `UnsupportedBrowserPage` are pre-existing console noise in the full staff-web run, not test failures; confirm the 2980/2980 result before treating them as a defect.
