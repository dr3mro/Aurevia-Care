## Findings

- **The brief is wrong about the duplicate response.** It asks for `second outcome=duplicate`. `DurableEventService.consume` appends a `DUPLICATE` audit fact but returns the *original* `ConsumerReceipt`, whose `outcome` is still `accepted`; `JdbcDeliveryStoreIntegrationTest.receiptsReplayAndLinksAreDurable` and `DurableEventServiceTest.consumeDeduplicatesInsideTheSenderAndTypeNamespace` assert the same. The test therefore asserts equal receiptIds and equal `accepted` outcomes, and proves the repeat through the `duplicate` audit row plus the one-row count. The advisor's plan reviewer independently flagged this as Required and the test already satisfied it.
- Plan-reviewer Required gaps and resolution: (1) duplicate assertion — resolved as above; (2) test isolation — each test uses its own namespace, aggregate id and external event ids, and test 2's version 5/6 use null identifiers, so `maxVersion` cannot leak between tests; (3) prove namespace/type boundary — test 1 now varies sender, namespace and eventType while holding the external id fixed, each yielding an accepted distinct receipt; (4) one audit mechanism — direct `JdbcDeliveryStore` reads through the `as(org, subject, ...)` `TenantContext` helper, filtered on `action=consume` and `resourceId`, used for every audit assertion. ## Lessons for workers

- Read the production branch before trusting a brief's expected value: a repeated consume returns the original immutable receipt, so `duplicate` lives in the audit outcome, not in the response body. Assert both the returned receipt identity and the audit fact.
- `JdbcDeliveryStore.maxVersion` is `max(aggregate_version)` for `(org, namespace, sender, event_type, aggregate_id)` over **all** receipts regardless of outcome. One shared integration database therefore needs a distinct namespace and aggregate id per test or JUnit's unordered execution makes a v5/v6 test flip another test's v1 event to `held_out_of_order`.
- In this worker image, `git ls-files -v opencode.json` → `S` explains the `test_check_pack` failures; confirm once and move on. Targeted `-Dtest=...` plus individual policy scripts prove a test-only change without the ten-minute full gate.
