# BUILD-41 (fix pass) — remove the export's unreferenced document copies; in-scope work is green

## Summary

Fix pass for BUILD-41 / OPS-07 on `swarm/BUILD-41-495`, continuing from the earlier
findings instead of restarting them. Earlier passes had already implemented tenant
export, proven 100% coverage and repaired route parity, and concluded that only
out-of-scope blockers remained. An independent simulated QA review in this pass
found one genuine, still-open **in-scope** defect (D-1): `TenantExportService.start()`
wrote a promoted per-document snapshot for every authorized document but recorded
no key for it, so those copies were unreferenced and could never be expired.

This pass fixes that at its cause. A failing regression test was written first
(RED: expected 2 stored objects but found 3), then the three dead write
statements were removed so the manifest is the only artifact a job owns and
`expire()` removes it. The authorized source objects keep their own documents-domain
lifecycle. No migration, contract, threshold, exclusion or protected file was
changed by this pass.

Evidence provenance: **tool** commands executed by this worker; plus two **simulated
reviewer** reports (senior-backend, QA) obtained with read-only briefs. No human,
clinical or patient-participant evidence.

## Findings

- **Fixed (D-1):** `TenantExportService.start()` created a promoted snapshot per
  authorized document with a random `ObjectKey`, but the job row stored only the
  manifest key and the manifest cited the *source* object id. `expire()` could
  therefore remove only the manifest; the snapshots were unreferenced and had no
  cleanup path (V89 forbids DELETE). Fixed by deleting the three dead writes and
  documenting why the manifest is the only owned artifact.
- **Residual completion gap (simulated QA, not fixed here):** no single test drives
  HTTP → real `ExportController` → real `TenantExportService` → `JdbcExportStore` →
  PostgreSQL. `ExportControllerTest` drives the controller through standalone
  MockMvc with a mocked service; `TenantExportIntegrationTest` drives the store
  against real PostgreSQL. Requested as a follow-up task below.
- **Contract debt (tool + simulated QA):** the three export routes are baselined in
  `contracts/openapi/missing-routes.txt`, not published in `contracts/openapi.yaml`
  or the generated staff-web client. Route parity is green; generated clients still
  cannot call them. Publishing is outside BUILD-41's declared scope and is
  requested below. Note that the baseline file itself is outside the declared
  scope; its earlier addition by commit `433ba5e1` is flagged as a `scope` violation
  by `worker_gate.validate_candidate` in a swarm worker that supplies `STORY_BODY`.

## Lessons for workers

- An "out-of-scope blocker" hand-off is not proof that the in-scope work has no
  defects: an independent QA reviewer found a real retention leak that all earlier
  verification passes had missed because every export test only checked the manifest.
- A side effect that writes an object but records no durable key is a leak even
  when all tests pass; assert the object-store file count after start and expiry.
- Write the regression test first and capture the exact RED assertion before
  deleting the code; deletion reduces coverage scope and leaves no new branch to
  map, which is safer than adding an expiry path for an object nobody references.
- A failing test that passes once a build artifact exists is not hermetic: run the
  script suite with and without `apps/api/target/surefire-reports` to tell a real
  defect from an order-dependent fixture.
- In this cloud worker `opencode.json` is a CI profile under `skip-worktree`;
  compare with `.github/opencode.ci.json` and `git show HEAD:opencode.json` before
  believing a check-pack failure. Never regenerate or commit that file.
- Respect protected paths: put the worker_gate fixture repair in the hand-off, not
  in a worker commit; a PR touching `scripts/` is never auto-merged.
