# SPEC-MSG-07-C04 — MSG-07 clause 4 (API test)

## Summary

Added one new API/acceptance test class and one clause evidence document for
MSG-07 clause 4: "Revoking a connection stops new messaging and future attachment
access through that connection." Eight active tests prove both governance guards
at service level (same connection active then revoked), the wrong-role,
inactive-member, other-tenant and missing-context negatives, and the one wired
HTTP route (`POST /api/v1/messaging-governance/connections/{id}/revocation-effects`).
Status is **Partly proven**: the messaging half has a real enforced conversation
path, but the mediated attachment-download path never calls the attachment guard
and no controller route exposes it. No production code, existing test, OpenAPI
contract, migration, dependency or tracker was changed.

`@Disabled("GAP: ...")` HTTP test. That instruction is wrong for this repository's
gates — `scripts/check-constraints.py:56` rejects every added `@Disabled` line,
enforced by `scripts/quick-check.sh:20`, `scripts/quality-gate.sh:13` and
`scripts/check.sh:21` (confirmed empirically with a temporary probe file and with
`git show d1f084a7:.agent/pr-notes/SPEC-MSG-03-C08-20261122-233716.md`, the
accepted precedent for an identical conflict). Per AGENTS.md I kept the pull

recorded in the clause document's `## Gap` instead. Everything else in the brief

## Lessons for workers

- Before writing a mandated `@Disabled("GAP: ...")` test, run
  `python3 -I scripts/check-constraints.py` on a probe: the `JAVA` rule rejects
  every added `@Disabled` line even when existing clause tests are grandfathered.
  Put the enable-ready test in the clause doc's `## Gap` and keep the PR green.
- Check the role matrix before writing an "other tenant" negative: a
  `tenant_admin` cannot reach the SEND/DOWNLOAD connection lookup, so
  `requireMessagingAllowed`/`requireAttachmentAccess` would deny 403
  `FORBIDDEN` before doing the tenant concealment check. Use a conversation
  role in the foreign tenant.
- In a cloud worker, `git ls-files -v opencode.json` showing `S` explains the
  `check-pack` stale-config failure and the six `test_check_pack` unit failures;
  run the remaining gate stages individually and never regenerate that file.
- A bare `-Pno-security spotbugs:check` is vacuously green; use
  `-Dspotbugs.skip=false -DskipTests compile spotbugs:check`.
