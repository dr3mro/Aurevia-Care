## Lessons for workers

- For a test-only clause proof, do not invent a red step. Write the complete active test, run it green, and let the named negative assertions carry the proof; record explicitly that no red observation was possible.
- The attachment HTTP adapter computes magic prefix, SHA-256 checksum and byte size from the uploaded bytes. To prove `INVALID_MAGIC_HEX` / `INVALID_CHECKSUM`, call `AttachmentService.upload` directly with a crafted `UploadRequest` over the same in-memory store — those codes are unreachable through HTTP.
- To reach `INVALID_SIZE_BYTES` through HTTP you must actually upload `MAX_SIZE_BYTES + 1` bytes, and prefix them with the valid magic so the earlier type guards pass first. Deriving size from real bytes means a smaller synthetic payload cannot reach that branch.
- `AttachmentEvent` records no file name, checksum, object key or bytes by construction; asserting that fact strings contain none of those is a direct quarantine-privacy proof. Verify the download version precondition (`If-Match`) matches the post-scan version, or a `STALE_VERSION` short-circuit masquerades as `NOT_PUBLISHED`.
- In a cloud worker, a skip-worktree `opencode.json` red is an environment artifact: confirm with `git ls-files -v` and `git show HEAD:opencode.json`, run the remaining gate stages individually, and never regenerate or commit that protected file.
