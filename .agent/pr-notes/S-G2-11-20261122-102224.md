## Lessons for workers

- Read `docs/gates/g1-clinic.md` first for a gate-evidence note: its matrix, entry-point-to-test
  trace, explicit "evidence, not acceptance" statement and empty sign-off treatment are the pattern
  to follow. `g0-isolation-surfaces.md` shows how to list gaps without claiming a behavior.
- A gate sentence can be covered by more than one test layer. Name the domain-level acceptance test
  and the HTTP-level integration test; a single mock-based acceptance test alone is a weaker claim
  than one backed by a real server test.
- Check `git log -1 -- <test file>` before citing a merged test, and use `git log --follow` for files
  that were renamed by the package refactor — the newest commit may be a rename, not the story that
  introduced the behavior (BUILD-38 here).
- In a cloud worker, confirm `git ls-files -v opencode.json` is `S` before treating a `check-pack`
  failure as real; do not "fix" it by regenerating a protected file.
