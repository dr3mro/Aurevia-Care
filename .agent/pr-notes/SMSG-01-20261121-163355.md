# SMSG-01 — Staff messaging decision pack

## Summary

Added one new file, `docs/decisions/staff-messaging/README.md`, containing a
decision pack that proposes new staff-to-staff messaging requirements (instant
chat, email-like messages, inside a facility and between facilities, with
attachments). It states plainly at the top that agents/workers must not edit
`PROJECT_V1_SPEC.md` and that a person amends the specification after
answering four open questions. No other file was created or changed, no
dependency was added, and no tracker or protected file was edited. This is a
documentation deliverable only; no requirement became approved V1 scope.

## Affected requirements

- MSG-03 (attachment controls), MSG-07 (audit/retention/legal holds) and ARC-07
  (patient-communication record contract) inform the proposal and are mapped in
  the document's "Relationship to existing requirements" table.
- MSG-01 to MSG-07 and ARC-07 were read to establish that the existing scope is
  patient-to-unit only and that staff-to-staff messaging is new scope.
- No new requirement IDs were minted. `scripts/check-docs.py` rejects any
  requirement-ID token matching `[A-Z]{2,4}-\d{2}` that is not defined in the
  specification, so proposed requirements use descriptive labels; a person
  assigns formal IDs when amending the spec.

## Findings

- No existing-code defect was found; no production change was attempted.
- Decision: proposed requirements are described with descriptive labels, not

  in the specification. A person assigns formal IDs in the amendment.
- Decision: cross-organization facility messaging is described as disabled
  pending an approved agreement; the pack does not assume it is permitted.
- Decision: "revocation stops future access" is re-anchored for staff-to-staff
  to staff membership/role/unit assignment and cross-facility agreement
  termination, not to a patient connection.
- No unfinished items.

## Lessons for workers

- A proposed spec amendment must not invent IDs such as `MSG-08`:
  `scripts/check-docs.py` fails on any requirement-ID token not defined in
  `PROJECT_V1_SPEC.md`. Use descriptive labels and let the spec owner number
  them.
- Reuse the *patterns* of the patient-messaging requirements (MSG-03 attachment
  validation/quarantine/checksum, MSG-07 audit/retention/holds, ARC-07 record
  shape and atomic commit) but explicitly drop the patient-binding clauses
  (verified patient connection, patient record-access policy, care-unit inbox).
- For a docs-only change, the step-6 gate is `python3 -I scripts/check-docs.py`;
  the full `scripts/check.sh`, Java and integration gates remain integrator-owned.
- New decision-pack files must live in a business-domain folder
  (`docs/decisions/staff-messaging`), never under a story/task/gate ID.
