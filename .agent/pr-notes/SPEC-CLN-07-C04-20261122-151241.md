# SPEC-CLN-07-C04 — Voiding an association captures a reason and preserves history

## Summary

Test-only proof of SmartClinic V1 requirement CLN-07 clause 4 through the real
HTTP API: a clinician's reasoned void of a document association records the
reason, advances the version, appends a `void` event to the append-only history,
and leaves the retained original bytes intact; every misuse is refused. No
production code, migration, contract or existing test is changed.

## Affected requirements

- CLN-07 (row 57 of `SMARTCLINIC_V1_SPEC.md`): "Voiding an association captures a reason and preserves history."

## Risk class

Cross-boundary (HTTP controller → domain service → JDBC repository → V17
database guard and append-only event table), but **test-only**: the change adds
an integration test and a clause-evidence document. No behavior is altered.

## Data changes

None. No migration added or edited; V17 already supplies RLS + FORCE RLS, the
`active → voided` update guard requiring a reason and exactly `version + 1`,
no-delete/no-truncate triggers and an append-only event table. The test uses a
unique synthetic database (`smartclinic_doc_void_it`), dropped after the run.

## Authorization boundaries and audit events

Exercise only existing boundaries: `DOCUMENT_VOID` is clinician-only
(`DocumentPolicy`); a peer tenant is concealed as 404 by forced RLS; the actor
is derived server-side by the V17 `set_document_event_actor_from_actor()` trigger
from the authenticated subject and the reason is bounded/trimmed by
`DocumentInputs.reason`. `DocumentController.VoidRequest` carries only `reason`,
so a client cannot forge an actor. No new audit event is introduced; the service
already appends success, denial and not-found audit rows.

## Lessons for workers

- The history event's authenticated actor is a tenant-local identity UUID in the
  JSON field `actor` (not `actorId`), derived by the V17 trigger from the
  authenticated subject; resolve it with a forced-RLS identity-id lookup before
  asserting.
- A `missing If-Match` test must OMIT the header: a helper that defaults
  `null → "1"` makes 428 unreachable. Guard order in the void path is
  428/422 (precondition) → 422 (id/reason) → 403 → 404 → 409 → 412, so every
  negative must send otherwise-valid reason and `If-Match` to isolate its branch.
- Read unchanged state after a refusal through the owner's HTTP GET under
  `FORCE RLS`; a raw JDBC count from a connection without `app.current_org` can
  hide rows and false-green. Never use `-Pno-security,fast` for integration tests
  and always read the Surefire `tests=` count.
- In a cloud worker, confirm the `opencode.json` "stale" pack failure once with
  `git ls-files -v` + `git show HEAD:`, run the remaining gate stages
  individually, and leave the full gate to the integrator; never regenerate or
  commit that skip-worktree file.
