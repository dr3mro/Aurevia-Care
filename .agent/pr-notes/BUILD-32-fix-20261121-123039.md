## Data changes

`db/migrations/V86__recurrence_templates.sql` (reserved version V86, `Change: expand`):
three additive tables `recurrence_template`, `appointment_series`, `series_occurrence`.
Each has `organization_id`, a composite PK including it, `created_at`, ENABLE + FORCE RLS and
a policy `USING/WITH CHECK (organization_id = public.app_org())`. Append-only reject-mutation
triggers for `UPDATE`, `DELETE` and `TRUNCATE` cover every role including the migration owner;
SELECT/INSERT are granted only to `aurevia_app` and UPDATE/DELETE/TRUNCATE revoked.
`recurrence_template` enforces exactly one termination via
`CHECK ((occurrence_count IS NULL) <> (end_local_date IS NULL))`. No backfill, no UPDATE of
existing rows, no destructive DDL; brief ACCESS EXCLUSIVE locks are bounded by table creation.
Rollback is a forward-fix migration; no capability is removed. No migration was added or
edited in this pass.

## Lessons for workers

- To reach 100% on a large touched class, run the full unit suite plus every integration test
  that exercises its pre-existing paths. A class subset leaves `AppointmentService` /
  `AppointmentRepository` branches uncovered; adding `SeriesHttpIntegrationTest`,
  `AppointmentListIntegrationTest` and especially `it/SchedulingBookingTest` closes the gap.
  Always re-read the JaCoCo XML and confirm `missed == 0` on each changed class.
- JaCoCo counters print as `missed/covered` in this report; a branch value of `1/4` is a MISSED
  branch, not 25% coverage. Parse `mi`/`ci`/`mb`/`cb` directly. A `n/a` counter means the class
  has no branches of that type, which is fine.
- `scripts/check-pack.py`/`test_check_pack.py` staleness under `skip-worktree` is a known false
  positive in this worker environment — verify with `git ls-files -v opencode.json` and
  `git show HEAD:opencode.json` before treating it as your defect; do not regenerate it locally.
- Integration tests in one class share a database; give each scenario distinct dates or an
  earlier successful series makes later ones fail with `SERIES_CONFLICT`.
- `AppointmentView` is nested (`{"appointment": {...}, "history": [...]}`); assert nested fields
  when checking reschedule history over HTTP.
- The generic "frontend definition of done" block in the swarm prompt applies only to stories
  that touch a frontend module; for a backend-only scope, state that explicitly rather than
  installing toolchains or fabricating typecheck evidence.
