# BUILD-54 — Patient app: OS-backed credential storage and no persistent clinical cache

## Summary

Added a transient, in-memory-only clinical cache, an idle-timeout sign-out guard, and a
re-authentication gate for sensitive account changes under `apps/patient-mobile/src/api`.
`clearToken` (the sign-out path already used by the app shell) now also discards all
transient clinical memory in a `finally` block, so sign-out and idle timeout leave no
clinical data in the process. Only the single session credential uses the OS secure store.

## Affected requirements

- PAT-02 (primary): OS-backed local credentials, no persistent clinical cache, authorize
  downloads, confirm intent for a local copy (download confirmation already existed in
  `features/reports/downloadFlow.ts` and was not changed).
- PAT-03 (supporting): renewed authentication for sensitive account changes.

## Findings

- `bash scripts/check.sh` (repo-wide) failed at `check-pack: opencode.json is stale: run
  scripts/gen-opencode.py`. This is the documented cloud-worker CI-profile artifact:
  `git ls-files -v opencode.json` shows `S` (skip-worktree) and the worktree file hash
  differs from `git show HEAD:opencode.json`. No agent, config, `opencode.json` or `scripts/`
  file was touched by this change, so the failure is environmental and pre-existing, not a
  regression. Left untouched per scope/protected-file rules.
- The new guards are provided as reusable API boundaries only. `createSignOutOnIdle` and
  `createSensitiveActionGuard` are not instantiated in `src/app`/features because those paths
  are outside this task's scope. Next step for the integrating worker/host: instantiate the
  idle guard in the app shell and call `touch()` on user activity (its `onIdle` already calls
  `clearToken`); call `recordAuthentication()` on sign-in, `reset()` on sign-out/idle, and
  `authorizeSensitiveAction()` before any sensitive account change (deny and prompt for
  sign-in when `reason === 'reauth_required'`). No UI wiring is claimed here.
- Token storage was already OS-backed before this change (`tokenStore.ts` and the existing
  `features/reports/credentials.ts`); this story hardens the clinical-memory half and adds
  the idle/re-auth boundaries.

## Lessons for workers

- In a cloud worker, `scripts/check.sh` / `gen-opencode.py --check` can report a stale
  `opencode.json` because the worktree copy is the CI profile under `skip-worktree`; treat
  it as a measurement artifact and verify with `git ls-files -v opencode.json` rather than
  editing the protected generated file.
- With `@jest/globals` + `verbatimModuleSyntax`, `jest.fn()` is `Mock<UnknownFunction>` and
  is not assignable to a typed callback such as `() => void | Promise<void>`; declare the
  mock signature (`jest.fn<() => void>()`) to keep `tsc --noEmit` green.
- Wiring sign-out memory clearing into the existing `clearToken()` entry point (rather than
  adding a parallel `signOut()` that the out-of-scope shell would not call) is what makes the
  in-scope change actually clear clinical memory at sign-out.
