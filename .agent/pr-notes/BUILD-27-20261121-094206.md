# BUILD-27 — Persist document associations, quarantine state and versions with JDBC

## Summary

Added a durable PostgreSQL `DocumentStore` for the X-03 document slice: artifact metadata, checksum, scan verdict, quarantine state, verified object metadata, PDF jobs, immutable PDF bindings, release decisions and an append-only fact ledger. V81 creates seven tenant tables with forced RLS. `QuarantineService`, `PdfBindingService` and `DocumentGuard` are now Spring beans wired to the JDBC adapter; the in-memory fake moved to `src/test`. The pre-existing CLN-07 association/render repository (V17/V75) already persists void reasons, history and rendered versions and is unchanged.

## Data changes

V81 adds `document_authorization`, `document_artifact`, `document_verified_object`, `document_pdf_job`, `document_pdf_binding`, `document_release`, `document_event`. Additive `Change: expand`, no existing object altered, no backfill, no lock/volume impact beyond new empty tables. Each table: `(organization_id, …)` key, ENABLE + FORCE RLS, `tenant_isolation` policy using/with `app_org()`, explicit grants to `orevia_app`. Immutable ledgers (`document_pdf_binding`, `document_release`, `document_event`) reject UPDATE/DELETE/TRUNCATE for every role via `reject_immutable_mutation()` triggers; artifact/job binding triggers block rebinding. Object bytes are never stored (verified by an `information_schema` assertion in the integration test). Rollback is dropping the new tables; forward-fix is a later contract migration if removal is ever needed.

## Authorization boundaries and audit events

Every store read takes the active organization and forced RLS confines it; inserts write `organization_id` explicitly so `WITH CHECK` rejects a foreign tenant. `putAuthorizationFor` stores a deliberately mis-bound grant in `grant_organization_id` while the RLS column remains the active tenant, so the service still answers `WRONG_TENANT` without weakening the policy. Existing `DocumentGuard` actions and `EventType` wire keys are reused for the append-only `document_event` ledger; no new audit purpose or permission was invented.

## Findings

- No new HTTP controller or OpenAPI entry was added: `contracts/` is outside the task scope and a new endpoint would be undocumented. The X-03 services are exercised through their public domain entry points, as the pre-existing X-03 unit suite does; the CLN-07 HTTP entry already exists via `DocumentController` → `DocumentService`. If a future story exposes quarantine/binding over HTTP, it must add the controller, OpenAPI entry and an HTTP-level integration test.
- `scripts/wiring-baseline.json` still lists `InMemoryDocumentStore` (moved), `DocumentStore` (now durable), `QuarantineService` and `PdfBindingService` (now beans). `check-wiring.py` passes and only prints "fixed" notes; the baseline is outside this scope and must be trimmed by the integrator.
- CLN-07 `document_association` and `rendered_document` intentionally retain original bytes (V17/V75, "Retain original bytes"); the "no bytes in the database" rule was applied to the new V81 tables, verified by `information_schema`.
- The real-PostgreSQL test had to seed a `user_identity` row for `clinician-a` because V17's `set_document_created_by_from_actor()` rejects an association whose `app.actor` is not an authenticated user of the active tenant; the association table also generates its own ID, so the test captures `RETURNING id`.

## Lessons for workers

- When mocking `NamedParameterJdbcTemplate` for JaCoCo, route returned rows through the supplied `RowMapper` (including `RETURNING` lambdas). Returning raw strings leaves lambda methods uncovered even when line coverage is 100%.
- Under `FORCE ROW LEVEL SECURITY`, a synthetic foreign grant cannot be inserted with the foreign org in the RLS column; store the claimed org in a separate text column and keep `organization_id` as the active tenant.
- V17 association inserts require `app.actor` to resolve in `user_identity` and generate the association ID server-side; capture `RETURNING id` instead of asserting the supplied subject ID.
- `check-pack.py` "opencode.json is stale" inside a cloud worker is the CI-profile `skip-worktree` artifact, not a real drift: confirm with `git status --short opencode.json` and `git show HEAD:opencode.json` before editing anything protected.
- Do not run `scripts/check.sh` as a swarm worker: it invokes full `mvn verify`; run its policy stages, SpotBugs, `db/check.sh`, targeted tests and a targeted `jacoco:report` instead, and let the integrator run the full gate.
