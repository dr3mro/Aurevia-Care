## Lessons for workers

- Copy the **whole** neighbour `seed(...)` — organization, `user_identity`, `membership`
  **and** `role_assignment`. Omitting the role yields a 403 `missing action permission` at
  the HTTP entry point, not a 404 or a tenant error.
- Assert the SQLState (`23503` FK, `23502` NOT NULL) and a message fragment, not just
  `assertThrows`: a policy (42501) or privilege error would otherwise be a false green
  for a constraint test.
- When probing a NOT NULL column under FORCE RLS, use a superuser connection for that one
  insert and comment why; use the NOBYPASSRLS migrate role with a matching
  `app.current_org` for the composite-FK probe so RLS cannot mask it.
- Do not generalise a four-table V1 schema proof into a catalog-wide claim; later feature
  modules intentionally use named or non-UUID keys, and that belongs in a separate
  conformance task.
- In this cloud worker, `check-pack`/`worker-check` red is an environment artifact
  (skip-worktree CI profile), not a change defect. Confirm once, run constituent stages
  individually, and never edit or regenerate the protected `opencode.json` to force green.
