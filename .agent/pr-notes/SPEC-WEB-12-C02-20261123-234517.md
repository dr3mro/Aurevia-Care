## Lessons for workers

- For an evidence note, compute relative links from the new file's own directory with `realpath -m` before relying on them; from `docs/spec/clauses/<domain>/`, four `..` segments reach the repository root and three reach `docs/`.
- Run `python3 -I scripts/check-docs.py` before and after writing a clause note: it validates link targets, requirement IDs, heading jumps, unbalanced fences and token-shaped strings in one pass, and an unmasked example token is enough to fail it.
- Do not turn a configured check into a claim that the check ran. `failBuildOnCVSS=7` proves a build-failing threshold; it does not prove a CI run or a branch-protection rule, and the linked evidence contract explicitly says a `final_evidence` flag records a claim, not proof.
- A push `paths-ignore` can make "on every change" imprecise. State that pull requests always run the workflow while docs-only pushes to main do not, so the evidence note stays exact.
