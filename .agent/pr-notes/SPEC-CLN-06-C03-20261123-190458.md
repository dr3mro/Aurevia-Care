## Findings

- The advisor brief is stale on one point: it says "the follow-up routes are not in contracts/openapi.yaml". All five are published (`/api/v1/follow-ups/{id}/tasks` 3492, `/suggest` 7146, `/tasks/{taskId}/complete` 7171, `/{id}/confirm` 7200, `/{id}/override` 7229). The clause note was corrected rather than a spurious contract task being filed.
- The brief's `@Disabled("GAP: ...")` fallback cannot be used: `scripts/check-constraints.py` rejects an added `@Disabled`/`@Ignore` in Java and that would fail `quick-check.sh`, `worker-check.sh` and `quality-gate.sh`. No genuine gap existed, so no test was skipped and the note stays "Proven by tests".
- Adjacent, OUT OF SCOPE, verified contract-documentation gap: `/api/v1/follow-ups/{id}/confirm` returns 428 (`IfMatch.parse`) and 412 (`FollowUpService.confirm`) at runtime but `contracts/openapi.yaml` lines 7200-7229 declare neither an `If-Match` parameter nor 428/412 responses. This does not change the booking rule proved here. Filed as a task request below rather than fixed in this worker's scope.
- Six `test_check_pack` failures and `check-pack` exit 1 are the known skip-worktree profile artifact, confirmed once with `git ls-files -v` and `git show HEAD:opencode.json`. No protected file was edited.
- Pre-existing and out of scope: committed conflict-marker text inside Javadoc of `Hl7ParseException.java`, `Hl7Parser.java` and `Hl7Segment.java` was reported by an earlier run; this worker did not touch those files and Java compiles cleanly.

## Lessons for workers

- Verify before editing an evidence task that already claims "Proven by tests": a green baseline plus an explicit acceptance→test map is the proof; never manufacture a red test or a gap to satisfy a "test first" instruction.
- A brief is guidance, not permission to break a gate. When it asks for `@Disabled`, check `scripts/check-constraints.py` first: an added disabled test fails the worker, quality and integrator gates.
- Clause notes can go stale as the repository moves. Before restating "route not in OpenAPI" or a migration name, grep `contracts/openapi.yaml` and `db/migrations/` again; describe only what the test actually asserts.
- In a cloud worker, treat `check-pack`/`test_check_pack` `opencode.json is stale` as a measurement artifact when `git ls-files -v opencode.json` is `S`; confirm with `git show HEAD:opencode.json`, record once, run the remaining gate stages individually and never regenerate or commit that file.
