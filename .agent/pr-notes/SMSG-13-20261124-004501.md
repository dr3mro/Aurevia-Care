# SMSG-13 — Staff web: staff mail view (folders, compose, drafts, reply, forward, attachments)

## Summary

Added a self-contained, presentational staff-mail slice under the declared scope
`apps/staff-web/src/features/staffmsg/mail` only. It renders five folder counts derived from
the published folder routes, a message list and reading pane, a compose form with a
person/role/unit-mailbox To+Cc picker, subject/body/attachment names, serialized versioned
draft autosave, an inline 412 conflict surface with compare/reload/copy that keeps typed
work, and an explicit recipient-confirmation dialog driven by the contract's 428. English
and Arabic labels and RTL layout are built in. Synthetic fixtures only; no PHI, no new
dependency, and no route, navigation, contract, generated-client or shared-bundle edit.

Route registration is deliberately **not** in this slice: `SMSG-19` owns `features/staffmsg/routes.ts`,
`index.ts` and the README and depends on SMSG-13. The advisor brief's Step 0 "blocker — confirm
the owning entry point" was therefore **wrong**: the task graph and SMSG-14's accepted notes
("routes belong to SMSG-19", "no route registration (SMSG-19)") already answer it. I carried on
from the story and AGENTS.md instead of stopping, as the prompt permits. Prerequisites
FIX-STAFF-MAIL-FACILITY (#1378) and FIX-STAFF-ATTACHMENT-WIRING (#1448)
are both `[x]` on main and were verified, not re-implemented. AUD-20261122-07 is out of scope.

## Findings

1. **Brief correction:** Step 0 called the absent scope path and one-level route glob a blocker.
   SMSG-19 owns routes/index/README and depends on SMSG-13; SMSG-14/15/16 were accepted as
   presentational-only. No task-request was needed and no protected file was edited.
2. **WEB-10 e2e-spec tripwire** (verbatim above) was a stale pin on main, not a defect of this
   slice: the WEB-10 evidence commit (6951647b) pinned nine specs even though BUILD-60 (4698687f,
   already an ancestor of HEAD) had added five more journeys. Its own comment says "a new journey
   must replace this pin". The pin was refreshed to the real fourteen-spec set under the
   coverage-repair mandate (see `## Coverage repair (attempt 1)`); no threshold or exclusion changed.
3. **Server-side recipient expansion is authoritative.** `MailService` expands roles/facilities
   from tenant-scoped active staff. This slice expands roles from the injected synthetic
   directory for display/confirmation only; if the shell injects a directory that differs from
   the server's, a role/unit-mailbox confirm can return `409 RECIPIENT_CONFIRMATION_MISMATCH`.
   SMSG-19 must inject the real scope and SMSG-21 must verify the journey. A contract change that
   returned resolved recipients in the 428 body would remove this gap; not in this scope.
4. `resolveRecipientValues` uses the supplied directory without re-applying
   `isSelectableRecipient` (devsecops Optional, defense in depth only; server stays authoritative).
5. The 412 compare panel shows the loaded overview beside the typed draft because there is no
   GET-draft endpoint; no response text is logged or shown as an error message.
6. Autosave is serialized and version-aware (see Coverage). Repeated rapid typing no longer
   creates duplicate private drafts, and a superseded response patches the newer typed work
   with the saved draft identity before the queued save.
7. No new dependency; package.json and lockfile untouched.

## Lessons for workers

- Read the task graph, not just the brief: a "blocker" can already be assigned to a dependent
  story (here SMSG-19). A sibling's accepted notes are stronger evidence than an advisor's Step 0.
- The shared descriptor types GET/POST only; an accepted in-repo precedent
  (`features/chart/api.ts`) overrides method/URL for PUT with a documented rationale. Keep the
  cast local and assert the runtime method in `api.test.ts`.
- A 428 is not a stale-version conflict: transport maps it to `precondition-required`, which the
  shared state view would render as Compare/Reload/Copy. Intercept it in the container and show
  a real confirmation instead; omit `confirmedRecipients` on the probe or the server answers 409.
- With autosave, never count mocked calls by index. Build descriptors by method/URL predicate and
  key failures by path, or a once-queue rejection meant for send is consumed by the PUT.
- For per-file 100% v8 coverage, every JSX ternary needs a discriminating assertion: the compact
  test must assert `data-breakpoint="compact"`, not a style string present in both branches.
- `prettier` is not pinned here; an ad-hoc `npx prettier` disagrees with authoritative files.
  Trust the repo's `check.sh` gates instead of reformatting a whole feature.
- `test:coverage` runs the *whole* Vitest suite, so a stale artifact-set tripwire in an unrelated
  evidence test fails the coverage gate even when every touched source file is at 100%. Read the
  failing assertion before assuming a coverage gap: this one was a pin mismatch, fixed by replacing
  the pin with the real on-disk set, not by skipping a test or lowering a threshold.

## Coverage repair (attempt 1)

only failing assertion was the WEB-10 GAP tripwire comparing a hardcoded nine-entry `currentSpecs`
list against the fourteen e2e `.spec.ts` files actually committed under `apps/staff-web/e2e`. Root
cause (tool/git evidence): BUILD-60 (4698687f) added five journeys — `adminflow`, `financeflow`,

`apps/staff-web/tests/spec/platform/automate-critical-journey-supported-role-real-browser.test.ts`

if any of the fourteen journeys is removed. No threshold, exclusion, ignore directive or skip was
added; the other two tripwire assertions (`workflows === []`, `visualChecks === []`) are unchanged
and still pass — the five added specs contain none of the visual-check vocabulary
(verified with a scoped grep).
