## Summary

Adds one HTTP-level clause test and one evidence note for MSG-07 clause 7:
"Requests for copies follow the site's record access procedure." No production
code, migration, contract or existing test is changed. The note records the
honest status `Partly proven`: the code validates, authorizes, routes, stores
and audits a copy request, while the site's approved record-access procedure is
external and human-gated and the POST route is absent from the published
OpenAPI contract.

## Findings

- Partly proven is the honest status. The code records and routes a request and
  appends a non-sensitive audit fact, but it cannot prove the request follows
  the site's approved record-access procedure. That procedure is external and
  human-gated and is not in this repository. No signed policy pack, staff intake
  and approval workflow or G5 evidence artifact exists. See the clause note's
  Gap section.
- `POST /api/v1/messaging-governance/copy-requests` is implemented in the
  controller but absent from the generated OpenAPI contract and baselined as
  missing in `contracts/openapi/missing-routes.txt:247`. Left untouched as
  out of scope; a separate contract task is requested below.
- The plan reviewer suggested the status value `Partly built` for consistency
  with sibling notes, but the story requires exactly one of `Proven by tests`,
  `Partly proven` or `Not built`; `Partly proven` was used per the story.
- Worker-environment artifacts: the `opencode.json is stale` pack failure and the
  six `test_check_pack` failures were confirmed once (skip-worktree `S` and
  generated committed profile) and not re-diagnosed on later passes.
- All three post-code reviewers answered GO with no Critical or Required

  to the malformed resource id was adopted in the 422 test; no production code

## Lessons for workers

- For a test-only clause slice, prove the implemented half with a real HTTP
  entry point and keep the external human-gated half in the doc's Gap with the
  story's mandated Status value; do not invent a red test that the code cannot
  satisfy (there is no ownership or version check in `requestCopy`, so a
  cross-tenant or stale-version refusal test would be red).
- Validation in `requestCopy` runs before context and authorization, so input
  rejection produces no audit fact. Asserting a `DENIED` audit for a 422 case is
  wrong. Register an allowlisted role with `active=false` to isolate the
  membership guard from the role allowlist.
- Filter store audit assertions by `resourceId`: `GET /audit` appends its own
  `audit_read` fact, so whole-trail size assertions are brittle.
