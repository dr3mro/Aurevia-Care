## Lessons for workers

- When a fix PR stays red after the scope files are byte-equal to main, stop re-verifying the scope and read the *first actionable failing test* in `scripts/tests` — it may guard a completely different file (here, a CI workflow token boundary). `bash scripts/worker-check.sh` can short-circuit at the skip-worktree `check-pack` false positive before reaching that test, so run the tooling suite (or the specific test module) directly.
- A worker must not edit `.github/workflows/*` even when a debugger recommends a workflow fix. Check whether the fix is already on `origin/main` first; if it is not, record it under Findings and let the trusted integration/owner path apply it.
- In a cloud worker, treat `opencode.json` worktree checks as CI-profile results, not HEAD truth: confirm with `git ls-files -v` (`S`) and `git show HEAD:opencode.json` before calling a `check-pack` failure a defect (OPS-CW-003-01).
