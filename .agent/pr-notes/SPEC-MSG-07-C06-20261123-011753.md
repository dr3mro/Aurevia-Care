## Lessons for workers

- A partly built clause story mandates complete-but-`@Disabled` GAP proofs, while
  `check-constraints.py` mechanically rejects any added `@Disabled`. Treat the story's rule
  as the documented waiver, record the exact failing command and final line under Findings,
  and let the integrator own the tooling exemption — editing `scripts/` or weakening the
  gate is the real violation. Four merged sibling clause tests show this is the established
  pattern for clause evidence.
- In a cloud worker, verify the `opencode.json` skip-worktree profile once with
  `git ls-files -v` and `git show HEAD:opencode.json`, then run the remaining
  `worker-check.sh` stages individually. Re-running the same `check-pack`/`test_check_pack`
  artifact wastes a round.
- A disabled clause test still runs `@BeforeAll`: the targeted `-Dtest=...` run migrates a
  real PostgreSQL database and seeds forced-RLS rows, so broken fixture SQL surfaces even
  when every assertion is skipped. That makes it a meaningful green check for a GAP proof.
- JaCoCo instruments `src/main` only. A test-and-doc-only change adds no production counter,
  so there is no 100% percentage to report and none should be fabricated; say this plainly
  and leave the full `verify` to the integrator.
