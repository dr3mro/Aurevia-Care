## Findings

1. **Confirmed from committed source (not just earlier notes): the `needs-fix` label is a
   self-perpetuating automation loop that no fix worker can break.** Reading `scripts/swarm.py` in this
   pass: `fail()` (lines 2400-2428, plus the issue-monitor requeue at 978-981) adds `needs-fix`;
   `pr_flow()` (line 3009, `if "needs-fix" in labels: wants_wave = True; continue`) then keeps
   dispatching waves and never requests a fresh Delivery run or integration for the new head;
   `plan_integration()` (line 2569, `blocked = {"needs-fix", "needs-human", "needs-debug"}`) excludes
   the PR; the fix-worker branch of `publish()` (lines ~2095-2107) only posts
   "Worker … pushed a fix … The integrator will retest" and calls `gh pr ready` — it never removes
   `needs-fix`. The only in-code clears are `send_to_debugger()` (line 2925) and the `needs-human`
   terminal branch of `fail()` (line 2424), neither of which applies to a green fix. So a green fix
   push leaves the PR permanently unmergeable. Clearing it, or making a successful fix publish clear
   it, is a maintainer/owner action on protected tooling that this worker may not edit.
2. **The BUILD-23 code fix itself is complete and correct.** Independently reproduced in this pass:
   byte equality (sha256 `94d0d9ac…`), exactly one non-stale baseline line, all targeted gates green,
   parity green, Doxygen green, both frontend checks green with no `error TS…`, and 100% JaCoCo on all
   four touched production classes. Earlier "re-run in-scope tests and call the rest pre-existing"
   passes were right about the code; this pass adds fresh proof and the concrete label-loop code path.
3. **Declared-scope mismatch remains (real hand-off issue, not a code defect).** The inherited fix
   touched `contracts/openapi/missing-routes.txt`, outside BUILD-23's declared scope (`.../web`,
   `.../web` tests, packaged contract copy). A strict `worker_gate.py` rerun with the story-body scope
   would flag it as `scope`. I confirmed the integrator's own gate (`scripts/integrator-gate.sh`) runs
   only `scripts/check.sh` + `scripts/docs.sh`, not `worker_gate.py`, so it does not cause the CI
   failure. Owner decision needed: extend the declared scope, or document the route in
   `contracts/openapi.yaml`, regenerate `apps/staff-web/src/api/generated/openapi.d.ts` and remove the
   baseline line (FIX-OPENAPI series).
4. **Full `scripts/check.sh` / `mvn verify` deliberately not run** (worker time limit, >10 minutes);
   the integrator and Delivery own them. The integrator gate was inspected, not bypassed.
