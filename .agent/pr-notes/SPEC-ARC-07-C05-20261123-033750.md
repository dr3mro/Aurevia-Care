## Findings

- **Clause gap (not fixed here).** `ConversationService.reply` commits publication, audit and the queue/state update, but never inserts `public.delivery_outbox`. The table exists (V55) and is written only by `events.JdbcDeliveryStore.publishAtomically`. A production task is requested below; the clause document's Status is `Partly proven` and the would-prove test is preserved there.
- **Story versus gate conflict (resolved toward the gate).** The task text asks for a literal `@Disabled("GAP: ...")` test, but `scripts/check-constraints.py` rejects every added skip in Java and runs in the worker, quality and integrator gates. The plan reviewer ruled NO-GO on the skip. The delivered design uses eight active tests (including an honest absence marker) and keeps the complete would-prove method as fenced Java in the clause document (`docs/` is EXEMPT). If the owner insists on a literal skipped JUnit test, that needs an owner-side change to the protected gate script, not a worker-side workaround.
- **Queue visibility is derived.** `ConversationRepository.workQueue` filters `state <> 'closed'`; a reply changes state/version but not queue membership. The proof asserts the durable state/version and `work_item_event` rather than claiming a `GET /work-queue` change.
- **Pre-existing, out-of-scope.** `git grep -nE '^(<<<<<<<|>>>>>>>) '` finds committed conflict markers in the Javadoc of three HL7 files (`exchange/hl7/Hl7ParseException.java`, `Hl7Parser.java`, `Hl7Segment.java`). They are on `origin/main`, inside comments, compile cleanly, and were not touched by this task.
- **Environment artifacts.** The `check-pack` / `python-coverage` / six `test_check_pack` failures are the CI profile under `skip-worktree`, not change defects; evidence and disposition are recorded above.
- **Evidence provenance.** Tool-generated: Maven/Surefire, Flyway/PostgreSQL, SpotBugs, policy scripts, db check, frontend check. Reviewer evidence: read-only simulated subagents. No simulated-user or human-participant evidence.

## Lessons for workers

- A clause-gap story that asks for a skipped JUnit test conflicts with `check-constraints.py`; keep the would-prove test in the clause doc (`docs/` is EXEMPT) and use an active absence marker in Java instead of adding a skip.
- For targeted PostgreSQL clause runs use `-Pno-security -Dgroups=integration -Dtest=<Class>` and confirm the Surefire count; adding `,fast` excludes integration tests and makes the run vacuously green.
- `check-pack: opencode.json is stale` in a cloud worker is the CI profile under `skip-worktree`; confirm with `git ls-files -v opencode.json` and `git show HEAD:opencode.json`, run the other stages individually and never regenerate the protected file.
- The messaging work queue is a derived projection of conversation state, so prove queue updates with state/version plus `work_item_event`, not with `GET /work-queue`.
