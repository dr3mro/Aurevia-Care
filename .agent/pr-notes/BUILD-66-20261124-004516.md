## Lessons for workers

- A missing view is often a missing document, not missing code: before adding a
  test to force a status, survey `docs/spec/clauses/product/` and the existing
  `*Test` files. Authoritative clause `Status` headings settle the row status.
- A test file's name is not proof. Check the constructor it uses: a test that
  builds a service with a synthetic/no-arg constructor asserts a kernel, not the
  production-wired path. Check `new XService(` in `src/main` before citing a unit
  test as a request-path gate.
- `check-docs.py` validates Markdown links, IDs, fences, heading jumps and table
  width, but not bare backtick paths inside table cells. Verify those paths and
  their assertions with your own grep loop and record it in the notes.
- When a brief gives an older notes filename or a slightly wrong path, follow the
  prompt's notes path and the file on disk; record the discrepancy in `## Findings`
  rather than silently following the wrong detail.
- In a cloud worker a `check-pack.py`/`test_check_pack` "opencode.json is stale"
  result is the known skip-worktree artifact (`git ls-files -v opencode.json`
  shows `S`); never regenerate or commit that protected file. This documentation
  change was checked with `check-docs.py` only; the full gate stays with the
  integrator.
