# BUILD-47 — Staff web: physical therapy episodes, outcome scales and signed progress

## Summary

Added the `apps/staff-web/src/features/therapy` feature: tenant-scoped referral worklist with acceptance,
episode overview (evaluation, problems, baseline, frequency/duration, interventions), goals, versioned
outcome scales that keep each measurement's unit, session and progress notes, and an attested discharge
that closes the referral. Signed notes render read-only; a change creates a new editable addendum draft
linked to the signed original. English and Arabic bundles, the seven resilient-screen states, and full
synthetic fixtures are included. No files outside the approved scope were changed; no dependency was added.

Entry point → test trace: `TherapyPage` (`TherapyPage.test.tsx`, states/commands/tenant switch) →
`TherapyScreen` (`therapy-screen.test.tsx`, worklist, signed-note, addendum, discharge) → `api.ts`
(`therapy-api.test.ts`, descriptors and wire mapping) → `domain.ts` (`therapy-core.test.ts`, invariants).
`TherapyPage` is a lazy route component for BUILD-52 to register; no route was added here because the
app's `import.meta.glob` auto-registers any `features/*/routes.ts` and the exact-route-list tests are
outside this story's scope (see Findings).

## Affected requirements

- **PT-01** — referral acceptance into an episode; evaluation, problems, baseline, goals, planned
  frequency/duration, interventions; versioned outcome scales with units; signed session, progress and
  discharge notes; approved summary to referrer with return acknowledgment; discharge closes referral.
- **WEB-09** — loading, empty, error (correlation ID), timeout/offline, forbidden, stale-version conflict
  and session-expired states; command failures keep typed work; status messages via `role="status"`.

None. No Flyway migration, backfill or OpenAPI edit. `contracts/openapi.yaml` has no therapy paths, so

replaced, tenant/correlation/If-Match/Idempotency-Key owned by `buildRequestDescriptor`). No PHI or

Tenant comes only from `X-Active-Organization` via `useActiveOrganization`; worklist, episode, note and
referral lookups are scoped by organization and tenant-local id. Write commands send `If-Match` and a
fresh `crypto.randomUUID()` idempotency key. The client does not create audit events; the server owns
sign/discharge audit and authorization (D12: clinical editability is a server decision mirrored here).

green until that story owns them.

## Findings

- `contracts/openapi.yaml` contains no therapy endpoints. Wire types are local to `api.ts` and command
  paths are substituted after `buildRequestDescriptor`, matching the scheduling feature. BUILD-52 or a
  later API story should publish the real contract and regenerate the client; the wire shapes are the
  single place to update.
- No `routes.ts` was added. `src/app/routes.tsx` auto-discovers `features/*/routes.ts`; adding one
  immediately registers `/therapy` and breaks the exact-route-list assertions in `src/app/routes.test.tsx`
  and `tests/app/AppShell.test.tsx`, which are outside this story's scope. BUILD-52 must register the
  `/therapy` lazy route and update those expectations together.
- `scripts/check.sh` pack step fails on the environment's skip-worktree CI `opencode.json`; see Test
  evidence. No repository config file was touched.
- `formatMeasurement` joins value and unit with a plain space (design doc deviation 11); the displayed
  unit is still preserved verbatim and Arabic output uses Arabic-Indic digits as the shared formatter
  dictates. A site digit policy is an ADM-01 decision, not a feature-local change.

## Lessons for workers

Check how the app registry discovers routes before adding `routes.ts` to a new feature: the
`import.meta.glob('../features/*/routes.ts')` in `src/app/routes.tsx` auto-registers routes, and the
exact-route-list tests in `src/app/routes.test.tsx` and `tests/app/AppShell.test.tsx` then fail until
the navigation story updates them. Keep the route out of a feature-only scope and hand it to that story.

## Why this is not finished

The implementation and all applicable frontend gates are complete; this section records the one
non-code check failure so it is not rediscovered. Command: `bash scripts/check.sh`. Error:
`check-pack: opencode.json is stale: run scripts/gen-opencode.py`. Most likely cause: the cloud worker
mounts the CI `opencode.json` under `skip-worktree` (`git ls-files -v opencode.json` → `S`), so the pack
check measures that profile rather than the committed one; `git diff -- opencode.json` is empty and
`git show HEAD:opencode.json` differs from the worktree file. What was tried: confirmed the flag and the
byte difference, confirmed the committed profile is untouched, and ran every other check in
`scripts/check.sh` individually — all passed. Exact next step for the integrator/trusted job: run the
pack check against the HEAD profile (`git show HEAD:opencode.json`) or in an environment without the CI
profile overlay; do **not** regenerate or commit `opencode.json` from this story.
