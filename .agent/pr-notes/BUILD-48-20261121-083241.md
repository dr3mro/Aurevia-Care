# BUILD-48 — Staff web: duplicate patient review worklist with dry run and second approval

## Summary

Implemented the duplicate-review worklist, side-by-side comparison, dry run and
second-reviewer approval inside `apps/staff-web/src/features/duplicates` on branch
`swarm/BUILD-48-419` (start SHA `b1445c7`). Synthetic data only.

- `domain.ts` — wire types mirroring the Java consolidation records, plus pure
  guards: `hasUnresolvedBlockers`, `approvalBlocker` (no ticket / same reviewer /
  unresolved dependency / clear), IAM-04 confirmation validation, projections,
  local form validation and the approval body builder.
- `messages.ts` — parity-checked en/ar dictionary; machine-code → message mapping
  (`SECOND_REVIEWER_REQUIRED`, `UNRESOLVED_DEPENDENCY`, generic fallback).
- `api.ts` — tenant-scoped descriptors for `GET /api/v1/duplicate-reviews`,
  `GET /{survivorId}/{duplicateId}`, `POST` open and `POST /{reviewId}/consolidate`
  with `If-Match` = duplicate patient version and a fresh `Idempotency-Key` per write.
- `DuplicatesScreen.tsx` — accessible worklist table, side-by-side identity cards,
  conflicting-demographics table, dependency states, dry run, and the open/approve
  panel (two identifier confirmations or one bounded alternate-process code).
- `DuplicatesPage.tsx` — container: the seven WEB-09 states via `ApiPage`, pair
  selection, open-ticket command, second-reviewer approval, in-flight guards and
  conflict/refusal handling. Approval eligibility is advisory in the UI; the API
  remains authoritative.

No new dependency, no migration, no change outside the declared scope. No push,
tag or `gh` call.

## Affected requirements

- **IAM-04** — same-tenant duplicate review worklist; both identities with
  conflicting demographics and dependencies; non-mutating dry run; a second
  authorized reviewer approves and the opener is refused; two issuer-scoped
  identifiers (or a documented approved alternate process) confirmed before commit;
  unresolved ambiguous dependencies block approval; original ids/signatures and
  source references are untouched by this UI slice.
- **WEB-09** — loading, empty, error (with correlation id), timeout/offline,
  forbidden, stale-version conflict and session-expired states; typed work is
  retained on validation failure and conflict; a global error boundary remains
  owned by the app.

## Authorization boundaries and audit events

- Tenant comes only from `useActiveOrganization()` and is sent as
  `X-Active-Organization` by the shared builder; organization and actor are never
  taken from the request body or URL.
- Writes carry a fresh `crypto.randomUUID()` idempotency key per user action and
  a synchronous in-flight `useRef` guard; the approve command also carries
  `If-Match` = `ReviewDetail.duplicate.version` (the version the server compares).
- 403 → `ForbiddenState`; 409/412 → conflict state plus a code-specific refusal;
  401 → session-expired. No new audit event is added by this UI slice; the server
  owns `DUPLICATE_WORKLIST`, `DUPLICATE_REVIEW`, `CONSOLIDATE` and identifier
  confirmation audits.
- No name, MRN, reason or identifier appears in a URL, page title, log or browser
  storage. Routes (owned by BUILD-52) carry opaque ids only.

## Findings

- The story says to read the consolidation API in `contracts/openapi.yaml`, but that
  file (and `contracts/contract/openapi.yaml`) contains no duplicate/consolidation
  paths. The authoritative contract was read from the backend instead:
  `apps/api/src/main/java/com/aurevia/patient/consolidation/ConsolidationController.java`,
  `ReviewDetail.java`, `DuplicateReview.java`, `Consolidation.java`,
  `ConsolidationService.java` and `DuplicatePolicy.java`. The generated client has
  no paths for these routes, so `api.ts` borrows the published `/api/v1/facilities`
  path for the shared header builder and substitutes only the URL — the same
  pattern already used by `features/patients/api.ts`. Publishing these routes in
  the OpenAPI contract is a contract-owner follow-up.
- No `routes.ts` was added. `app/routes.tsx` auto-registers `features/*/routes.ts`
  via `import.meta.glob`, and `src/app/routes.test.tsx` plus
  `tests/app/AppShell.test.tsx` assert an exact route list. Adding a route here
  would break those app-level tests, which are outside this story's scope. TODO
  BUILD-52 explicitly owns registering the new feature routes and navigation, so
  this feature ships as a self-contained, directly testable module. The
  `duplicates route registration` test asserts the feature does not claim a
  shared route.
- `currentSubject` is an injected prop (default `synthetic.reviewer.second`)
  because staff-web has no principal context; `SessionContext` exposes only
  `onSessionExpired`. The client-side same-reviewer block is therefore advisory —
  the server's 409 `SECOND_REVIEWER_REQUIRED` remains the authoritative gate and is
  mapped to a clear refusal. Wiring a real session subject is a staff-web owner
  follow-up (READY-11/OIDC).
- Shared hand-off inherited from READY-23/READY-25: `ApiPage`/`StateView` render
  Error Retry, Conflict Compare/Reload/Copy and sign-in with inert defaults, so
  those recovery controls are displayed but not wired here; that needs a shared
  component change outside this scope. Typed reason and confirmation state are
  retained on validation failure and conflict.
- Evidence provenance: commands and results above came from executed tools; the
  two design reviews were simulated/static reviewers, not human or clinical
  acceptance.

## Lessons for workers

- `contracts/openapi.yaml` can lag the backend: for a backend-backed screen, read
  the controller and view records too, and follow the patients feature's
  "borrow a published path for headers, substitute the URL" pattern.
- Do not add a feature `routes.ts` unless the story owns the app-level route
  registry tests: the glob auto-registers it and breaks exact-list assertions in
  `src/app/routes.test.tsx` and `tests/app/AppShell.test.tsx`.
- `Button` has no `aria-label` prop; for a row action whose accessible name must
  include opaque ids, use a native `<button>` with token-based inline styles.
- With `exactOptionalPropertyTypes`, pass `FormField` errors with a conditional
  spread; a bare `error={maybeUndefined}` fails typecheck.
- Confirmation modals and a radio-style mutual exclusion between identifier
  confirmation and alternate process reduce invalid 422s; here mutual exclusion
  is validated locally and mirrored from the server's `[a-z_]{2,32}` code rule.
- The full `bash apps/staff-web/check.sh` is the only reliable 100% coverage
  measure — running Vitest with coverage on a single feature folder fails every
  other repo file's per-file threshold; the integrator owns the full Java gate.
