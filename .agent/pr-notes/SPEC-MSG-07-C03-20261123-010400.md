## Lessons for workers

- A `clinician` cannot call `GET /api/v1/messaging-governance/audit`: `AUDIT_READ` is a governance
  permission. Verify a filed `chart_link` fact via an authorized `privacy_auditor` subject, and
  assert the fact itself through `store.auditEvents(ORG)`.
- `jsonPath("$[?(@.action == 'x')]").exists()` can pass on an empty filter result; use
  `hasSize(1)` (or assert a concrete field) to make an HTTP audit assertion non-vacuous.
- Validation in `linkToChart` runs before authorization: malformed-id and bad-sourceType tests
  prove 422 guards, never role or tenant refusal. Use fully valid requests for role/tenant cases
  and a distinct foreign subject (`foreign-clinician`) or seeding `"clinician"` in the other org
  would turn the cross-tenant test into a 201.
- The clause test uses the in-memory fake; say so in the clause doc so the Evidence list is not
  read as claiming JDBC/RLS coverage. Keep the durable-store claim with the integration suite.
