## Lessons for workers

- In the XCH-01 order flow, seed an approved authorization in `@BeforeAll` before
  any release test; `OrderService.create` checks the grant before the patient, so
  a cross-tenant patient with a bad grant returns 403 and makes a 404 assertion
  silently wrong. Pair every negative with a control 201 and a zero-row assertion.
- The destination work-item projection is deliberately bounded: do not assert
  `encounterRef`, `orderCode`, `sourceActor` or `responsibleClinician` on it —
  those live only on the order response/row.
- `sourceActor` is `clinician-a` (caller), `responsibleClinician` is `dr-a`
  (command); conflating them is an easy false failure.
- A swarm worker must not run `worker-check.sh` in full (it runs every integration
  suite); run the targeted `-Dtest=` plus the individual policy scripts, SpotBugs
  on compiled classes and `db/check.sh`, and leave the full gate to the integrator.
- The authoritative notes path is the timestamped `.agent/pr-notes/<task-id>-<timestamp>.md`
  from the prompt; the brief's older short path is superseded.
