## Findings

1. **Live organization wiring is out of scope (owner follow-up).** `src/app/OrgSwitcher.tsx` still keeps `selectedId` in local `useState` and exposes no context, and `src/App.tsx` mounts no `ActiveOrganizationProvider`; `src/app` and `src/App.tsx` are outside this task's scope, so they were not edited. The new context defaults to `syntheticFacility.organizationId`, which is exactly the tenant `OrgSwitcher` initially selects, so today's behavior is unchanged and no cross-tenant row mix is introduced. However, **switching organization in the running app does not yet refetch or clear rows** — the hook does so only when a provider supplies the switcher's selected id. The owning app-shell/router story must mount `<ActiveOrganizationProvider value={{ organizationId: selectedId }}>` around the shell and keep it in sync with the select. This PR does **not** claim end-to-end live org isolation.
2. **Abort is cooperative at the transport boundary.** `src/api/transport.ts` `send()` creates its own `AbortController` and accepts no external signal, so the hook cannot cancel the underlying `fetch`; it aborts its own controller and discards late responses. Making `send` accept a signal would touch a file outside this scope.
3. **The session-expired "Sign in" button is still inert.** `StateView.forTransportError` renders `<SessionExpiredState />` without an `onSignIn` callback. The required context notification now fires, but the visible button does nothing until a follow-up either extends `StateView.forTransportError(error, onSignIn?)` or lets `ApiPage` render `SessionExpiredState` with the callback. Changing the shared state-view signature was avoided to keep this change additive.
4. No response is cached between organizations and nothing is written to `localStorage` / `sessionStorage`; data exists only in component state and is cleared on any key change.

## Lessons for workers

- Commit the new request key **in the same state object** as the cleared loading result; a key-only update lets a stale result match the current key and paint old-tenant rows. Derive the returned view during render when `state.key !== currentKey`.
- With `exactOptionalPropertyTypes`, declare optional callback props as `isEmpty?: ((data: T) => boolean) | undefined` so callers and tests can be explicit.
- Under `verbatimModuleSyntax`, `instanceof` needs a **value** import; `import type { TransportError }` compiles but fails at runtime.
- Guard one-shot session callbacks by **error identity** (a ref), not effect dependencies alone, so StrictMode's second effect run cannot notify twice.
- To avoid an uncoverable `??` branch under 100% branch coverage, prefer an existing non-nullable fixture field (`syntheticFacility.organizationId`) over `syntheticOrganizations[0]?.id ?? ''` when a default tenant id is needed.
- Compute `depsKey = JSON.stringify(deps)` outside the effect and depend on the composed key; putting an inline `deps` array in the effect list causes a refetch loop.
