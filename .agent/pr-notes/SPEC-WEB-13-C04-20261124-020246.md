## Lessons for workers

- For an already-built clause, a read-only exact-equality tripwire plus a synthetic refusal
  test is the smallest honest proof. Do not add `it.skip("GAP: …")` when the rule is met:
  `scripts/check-constraints.py` rejects an added skip in a `.ts` file.
- When a module `check.sh` fails, reproduce the single failing test with your new files moved
  aside before assuming your change is at fault. A stale exact-list tripwire on `main` is an
  owner fix; record the exact next step and a task-request instead of editing the test.
- Run the individual frontend stages (gen:api:check, typecheck, lint, build, bundle-size,
  coverage) to isolate which stage is actually red; never run two frontend `check.sh` scripts
  in parallel because each runs its own `npm ci` and wipes the other's `node_modules`.
- `check-docs.py` verifies relative Markdown links: from `docs/spec/clauses/platform/` the
  repository root is four levels up (`../../../../`).
- In cloud workers `opencode.json` is the CI profile under `skip-worktree`; confirm with
  `git ls-files -v opencode.json` (`S`) and never regenerate or commit it.
