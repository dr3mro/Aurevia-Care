# ORDER-05 — Staff web order entry panel in the chart

## Summary

Added a self-contained, synthetic order entry panel exported as `OrderEntryPanel` under
`apps/staff-web/src/features/orderentry/entry`. It searches a versioned lab/imaging catalog,
captures selected items with their versions, requires a clinical question for imaging,
lets the clinician edit priority, preparation instructions and delivery mode, shows
allergies and relevant active orders with a duplicate warning, and saves a draft under
the version it opened. A stale write preserves every typed value and offers compare,
reload or copy. Role, tenant and all catalog/order/allergy data arrive as props; the panel
performs no network call and creates no real order.

## Affected requirements

- **LAB-01** — catalog items carry specimen, code, version and preparation; selected items
  are captured with the exact catalog version.
- **RAD-01** — imaging items require a clinical question before a draft can be saved;
  allergy and active-order context is shown before ordering.
- **WEB-09** — forbidden, conflict (compare/reload/copy) and status states are rendered;
  typed work survives a stale version; tenant switch clears prior state synchronously.

## Review owner

Senior React and Vite (primary), with Senior TypeScript and Test Engineer. A bounded
advisory review was run with the `orevia-senior-react` subagent before implementation;

## Data changes

None. No migration, backfill, DDL, lock or volume impact. The panel uses the synthetic
fixtures in `fixtures.ts` and does not persist anything.

## Authorization boundaries and audit events

`canOrder` limits the panel to the `clinician` role (PRD-06: clinical users decide and
attest); performing roles such as `lab` are deliberately excluded, so the check does not
reuse `navigationFor` (which lists viewing routes for `lab`/`radiology`). All lookups are
scoped by the `organizationId` prop: catalog search, active-order duplicate checks and
the saved-draft seed. The save command carries the opened version as the `If-Match`
precondition through `onSaveDraft`. No audit event is emitted by this presentational
synthetic panel; the real command is owned by the ORDER-02 API.

## Migration and rollout considerations

None. The panel is not yet mounted on a route: wiring the export into the chart screen and
the barrel/import instruction are owned by ORDER-08 (`apps/staff-web/src/features/orderentry/index.ts`
and README), so this story deliberately stops at the exported panel.

## Clinical and architecture review

No signed data, cross-organization sharing, prescribing or critical-result action is
implemented here, so no clinical sign-off is required for this UI slice. The imaging
clinical-question rule is taken from RAD-01; ordering privilege from PRD-06/IAM-01. The
panel keeps tenant scoping in props and the version precondition in the save callback,
matching the ORDER-02 API contract (`POST /api/v1/order-entry/drafts`,
`PUT /api/v1/order-entry/drafts/{id}`). A simulated senior-React review was received and
its actionable findings applied; there is no real clinician, patient or Arabic-speaking
reviewer evidence, which remains a separate G5 launch gate.

## Findings

- **Pre-existing generated-client drift (tool evidence).** At HEAD (commit `ee4d04a0`,
  ORDER-02), `contracts/openapi.yaml` declares `/api/v1/order-entry/drafts`,
  `/api/v1/order-entry/drafts/{id}`, `.../place` and `/api/v1/order-entry/orders/{id}`,
  but `apps/staff-web/src/api/generated/openapi.d.ts` did not contain them, so
  `npm run gen:api:check` failed on clean `main`. `git diff --exit-code HEAD -- contracts/openapi.yaml
  apps/staff-web/src/api/generated/openapi.d.ts` before the repair confirmed both matched
  HEAD. I ran the repository's pinned generator (`npm run gen:api`, openapi-typescript
  7.4.2) — no hand edit — which regenerated only that derived file. This is outside the
  declared `entry` scope; it was the minimum required for the mandatory frontend gate and
  is transparent here rather than a silent deviation.
- **Message-bundle registry update (tool evidence).** `apps/staff-web/tests/messageParity.test.ts`
  intentionally fails until every `messages.ts` under `src` is registered. The new
  `features/orderentry/entry/messages.ts` required three minimal lines in that existing
  test (import, `BUNDLE_SOURCES` entry, `fromKeysAndText('orderEntry', entryKeys, entryText)`).
  This is also outside the declared scope and is recorded here for the same reason.
- **Repo `scripts/check.sh` not fully observed.** It stops at `check-pack: opencode.json is
  stale`. `git ls-files -v opencode.json` → `S` (skip-worktree) and the worktree bytes differ
  from `git show HEAD:opencode.json`, matching the documented cloud-worker artifact
  (OPS-CW-003-01 in `MEMORY.md` and `.agent/pr-notes/2026-11-20.md`). The file was not
  touched; HEAD is the authoritative profile. All module-level gates passed.
- **Unwired panel.** The panel is exported but not mounted on a route; ORDER-08 owns the
  barrel export and the exact chart placement line, and ORDER-06/07 own delivery and
  tracking. No task was missing, so no `task-requests` block is needed.
- **WEB-09 "leaving with unsaved changes asks first"** is not implemented by this panel:
  it is a navigation/shell concern outside `entry`, and the story's four named tests plus
  the stale-version requirement do not cover it. The repo already has a `data-testid`
  precedent for unsaved-change notices in `features/chart/NotePage.tsx`; a shell-level
  follow-up would own the `beforeunload` guard.

## Lessons for workers

- When a story adds a feature `messages.ts`, the repo-wide
  `apps/staff-web/tests/messageParity.test.ts` registry must be updated in the same change
  or `check.sh` fails; plan for that line even when the declared scope names only the
  feature folder.
- After any merged contract change, run `npm run gen:api` in `apps/staff-web` before the
  module check. ORDER-02 added order-entry paths without regenerating the checked-in
  client, leaving clean `main` red at `gen:api:check`.
- `Button` does not accept `aria-label`; use a native `<button type="button">` (with the
  tokenized `controlStyle`) for icon/name-labelled row actions instead of trying to extend
  it from a scoped story.
- With `exactOptionalPropertyTypes`, a value of type `string | undefined` cannot be passed
  to `CodedEntry.displayLocal` (`string?`); use a conditional spread
  `{...(x === undefined ? {} : { localName: x })}`, as `ChartScreen`-era code does.
- V8 branch coverage counts both sides of `?.` and the `?:` in conditional spreads. Stub
  `navigator.clipboard` in the test that clicks Copy and add an allergy without a local
  name, otherwise those branches stay red.
- In a cloud worker, a red `check-pack` on `opencode.json` is almost always the
  `skip-worktree` CI profile artifact; confirm with `git ls-files -v` and
  `git show HEAD:opencode.json` and never regenerate or commit that file from a worker.
