## Lessons for workers

- The `*/clauses` packages are the fast, mocked, synthetic unit tier; mirror the owning service test (`ClinicalNoteServiceTest`) and cite the existing HTTP/integration test as the entry-point proof instead of duplicating the DB suite.
- In a cloud worker, `git ls-files -v opencode.json` = `S` explains `test_check_pack` / `gen-opencode.py --check` failures. Confirm HEAD equals the generator render and never regenerate or commit that protected file.
- Do not run `scripts/check.sh`, `scripts/worker-check.sh` or any full `mvn verify` from a swarm worker: they reach all integration tests and time out. Run the targeted `-Dtest=...` suite, the individual policy scripts and compile-then-SpotBugs, then leave the full gate to the integrator.
- On a shared, fast-moving `main`, re-run the targeted test **after** merging: a clean merge can still leave the tree uncompilable from another worker's change. Report the exact failing command and identify the offending file by commit before attributing a regression to this story.
- A clause-proof task that adds only tests and docs produces no new production coverage; say so explicitly instead of claiming an unmeasured JaCoCo number.
- A green scoped test can still be blocked by a tooling bug on protected `scripts/`. Prove the bug reproduces on clean `origin/main`, record it for the repair flow, and never edit a protected file or suppress a check to force a green result.
- Record the executed command and Surefire/doc final line in the evidence itself; "Proven by tests" without a command is not independently checkable by a reviewer.
