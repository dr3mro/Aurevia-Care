## Lessons for workers

- When a clause is only partly built, check `scripts/check-constraints.py:56` before writing
  a `@Disabled` GAP test: a new skipped test fails the gate. Describe the complete
  would-prove test in the clause doc's `## Gap` instead, with its enable trigger, and keep
  the suite green.
- Run the targeted integration test with `-Pno-security -Dgroups=integration` and WITHOUT
  `fast`; confirm the Surefire count and `Skipped: 0` before trusting a green run.
- A shared clause-test database needs a distinct key/code per test; otherwise repeated or
  reordered runs collide with 409s and false failures.
- In a cloud worker, `git ls-files -v opencode.json` → `S` explains the `check-pack.py`
  failure. Confirm once, run the remaining gate stages individually, and never regenerate
  or commit that file.
