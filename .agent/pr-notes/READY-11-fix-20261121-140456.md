1. **The re-dispatch cause is tracker state, not missing or failing code.** All nine scoped files are byte-identical to the merged `fefe3f2`, every worker gate is green, and HEAD contains the restore commit `4e7c41e`. TODO.md still carries READY-11 as `[-] agent: swarm-1`, so the hourly planner keeps re-claiming it. 2. **LOW, pre-existing, not introduced (confirmed again in this pass):** `SecurityConfiguration.isBearerRequest` uses case-sensitive `startsWith("Bearer ")`. RFC 7235 auth-schemes are case-insensitive, so a client sending `bearer …` falls into the browser chain. Deliberately **not** changed: making it case-insensitive would widen the set of requests exempt from CSRF, and the helper is shared with the AUD-20261120-03 chain, so it needs a dedicated security-reviewed story with tests touching both matchers — not a silent edit inside a verification re-dispatch.
3. **Pre-existing, out of scope (WEB-05):** both non-synthetic chains use `anyRequest().authenticated()`, so `GET /health/live` and `/health/ready` require a credential outside `synthetic-auth`. WEB-05 needs these unauthenticated; belongs to a health-lifecycle story, not READY-11.
4. **Local generated-file artifact:** worktree `opencode.json` is a `skip-worktree` CI profile and `check-pack.py` reports it stale until regenerated locally. Regenerated with `scripts/gen-opencode.py` (not committed). Documented in MEMORY.md; not a HEAD defect.
5. **`scripts/check.sh` intentionally not run:** it calls `apps/api/check.sh` → `mvn verify` (OWASP, JaCoCo gate, all PostgreSQL integration tests), reserved for the integrator and over the 5-minute worker limit. Component gates were run instead; integrator runs the full gate and DB checks.
