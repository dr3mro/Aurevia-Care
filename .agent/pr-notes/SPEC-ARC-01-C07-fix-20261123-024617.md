## Lessons for workers

- In a cloud worker, treat worktree `check-pack.py`/`test_check_pack` failures as the
  OPS-CW-003-01 artifact: confirm once (`git ls-files -v opencode.json` = `S`, compare to
  `git show HEAD:opencode.json`), record the command and final line, run the remaining
  policy stages individually, and never regenerate or re-diagnose it on a later pass.
- A draft PR can be fully correct: check the earlier notes for a recorded local-check
  false positive before changing code, and focus the fix pass on clean evidence and
  hand-off notes.
- `check-verdicts.py` fails closed on a missing or malformed verdict: the fix notes file
  (not the earlier one) must carry exactly `- <reviewer>: GO` lines for the three required
  reviewers, and the gate must be re-run against the new file before committing.
- Repeat the `task-requests` block in a fix-pass notes file: the notes become the PR
  description and that block is the only scheduling mechanism for an out-of-scope task.
