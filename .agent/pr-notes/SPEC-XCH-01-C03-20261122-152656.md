## Lessons for workers

- Reusing a production constant (for example `OrderInputs.SEPARATOR`) in an expected-value assertion is vacuous: if the constant changes, the test still passes. Use a literal and precompute derived values (UUID v3 fingerprint) offline.
- In a cloud worker, `worker-check.sh` can die at `check-pack` on the skip-worktree CI profile; confirm once with `git ls-files -v opencode.json`, then run the remaining stages individually and never regenerate that file.
- `git grep` conflict markers may be pre-existing in HEAD. Check `git show HEAD:<path>` before treating them as your own merge damage.
