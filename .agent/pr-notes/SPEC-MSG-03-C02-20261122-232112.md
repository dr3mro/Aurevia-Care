# SPEC-MSG-03-C02 — MSG-03 clause 2 API test

## Summary

Added one synthetic API clause test and its clause document for MSG-03: "Before
sending, show the recipient and pending files and require explicit send." The tests
prove the pending-file review and explicit-confirm gates through the real service
commands, and prove that a recipient set must be explicitly confirmed before mail
publication. They also show that no pre-send API returns the *resolved* recipient
list, so the clause document records `Partly proven` and the gap is requested as a
separate story. No production code, existing test, contract or migration changed.

## Lessons for workers

- For a clause test, read the neighbouring `clauses` test and doc first, then name
  every assertion after a production guard; a `pending()` projection has no reason
  field, so assert the quarantine detail through `view().audit()` or the refusal
  message.
- A pure-helper confirmation test (`MailRules.confirmationMatches`) adds no clause
  value when an existing test already covers it; drive `MailService.send` with a
  role recipient and a mocked directory/store to prove the confirmation gate
  instead. Mockito mocks here need no new production store.
- `git ls-files -v opencode.json` returning `S` plus `git show HEAD:opencode.json`
  matching `gen.render(ROOT)` proves the stale-pack failure is the CI overlay, not
  a defect: record it once and run the remaining gate stages individually.
- Check `git status --short` before finishing: pre-existing conflict markers at
  `origin/main` are not yours to resolve when they are outside the task scope.
