## Findings

- **Brief correction (B3):** the brief asks to assert currency `"USD"` on `finance_invoice_item` rows. That table has no `currency` column (`V45__finance.sql:72-90`); currency lives on `finance_invoice.currency` and on each `finance_ledger_entry.currency` (guarded to match). The test asserts the single currency on the invoice row plus each item's `invoice_id`, `line_no`, `quantity`, `unit_amount_minor` and exact integer `amount_minor`, and adds a second EUR invoice for per-invoice isolation. Reported to the plan/test/backend reviewers before coding; all answered GO on the corrected plan.
- **Brief correction (B1/B2):** overflow input uses `quantity = 2` (Integer) and `unitAmountMinor = 9223372036854775807` (Long), because `LineRequest.quantity` is `Integer`; and ORG_B is seeded with an active `finance` member because `authorize()` runs before `patientExists()`, else the peer-tenant case would be 403 instead of 404.
- Environment false positives (tool evidence, recorded once, not re-diagnosed): `git ls-files -v opencode.json` → `S opencode.json` (CI runtime profile installed under `skip-worktree` by `agent-run.sh`); `git show HEAD:opencode.json` shows a correctly generated committed local profile. The six `check-pack` unit-test failures, the `worker-check.sh` stop and the `python-coverage.sh` failure all trace to that one artifact. Remaining gate stages were run individually and passed.
- Out of scope / pre-existing: `contracts/openapi.yaml` documents the finance list route; the POST create route used by this test is listed in `contracts/openapi/missing-routes.txt`, a traceability discrepancy already recorded in `docs/spec/clauses/product/track-self-pay-invoices-payments-refunds-receipts.md`. Not fixed here.
- Pre-existing committed conflict markers (inside Javadoc comments) in `apps/api/src/main/java/com/aurevia/exchange/hl7/{Hl7ParseException,Hl7Parser,Hl7Segment}.java` are present in HEAD and unrelated to this task; left untouched as out of scope.
- No patient data, credentials or raw logs are stored in this note. All fixtures are synthetic.

## Lessons for workers

- Check the Java record field types before choosing an overflow fixture: `FinanceContract.LineRequest.quantity` is `Integer`, `unitAmountMinor` is `Long`; overflow must come from the long unit, or Jackson returns 400 before `FinanceInputs` runs.
- `FinanceService.create` authorizes before it checks patient visibility; a peer-tenant 404 test needs an active `finance` member in the peer organization or it will return 403.
- `finance_invoice_item` has no currency column; one-currency-per-invoice is proven by the invoice row, item integer arithmetic and the ledger currency trigger, not by an item currency assertion.
- In cloud workers `worker-check.sh` stops on the `opencode.json` skip-worktree false positive; confirm with `git ls-files -v`, then run the remaining gate stages individually rather than editing the protected generated file.
- Negative HTTP assertions must capture error bodies with `onStatus(status -> true, ...)` and assert the `code` field; a status-only assertion cannot prove which rule refused the request.
- Put every `.github/pull_request_template.md` section in the worker notes file, even for proof-only stories ("none" where not applicable); the verdict gate treats the notes as the PR description.
