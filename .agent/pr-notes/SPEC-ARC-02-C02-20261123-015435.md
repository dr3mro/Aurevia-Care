## Findings

- `CommandAuthorization`/`CommandCatalog` look like a central authorization gate but have no production caller; the live policy is in each `*Service.authorize(...)`. Do not treat that class as the ARC-02 implementation.
- IAM-01 clause 6 (`WriteChecksCurrentScopeTest`) and ARC-02 clause 3 (`IsolationAcrossSurfacesTest`) already cover scope binding and RLS mechanics. This class is deliberately framed around action-matrix policy, per-object concealment after a successful action check, and service-level (non-HTTP) enforcement, with corroborating cross-references in the note rather than duplicated assertions.
- Facility-scope narrowing within one tenant (IAM-01 clause 4) remains "Not built"; that is a different clause and is out of scope here.
- Pre-existing committed conflict markers in unrelated HL7 files on `main` are untouched.

## Lessons for workers

- When a clause already has neighbouring proof, make each negative test assert the *cause* (structured error reason, owning-tenant control, or direct service call), not just the status, or it silently becomes a duplicate and a tautology.
- Copy private helpers (`seedUser`, `headers`, `onStatus(status -> true, ...)`, TenantContext binder) inline into the single new test file; there is no shared test-utility file and adding one would breach the two-file scope.
- Seed every object a test reads in `@BeforeAll` with its own tenant context; never let one test read another test's HTTP write.
- No `fast` profile for integration tests; run the named class with `-Dtest=...` and read the Surefire report count. Compile before `spotbugs:check`.
- `git ls-files -v opencode.json` showing `S` explains the six `test_check_pack` failures and the `worker-check.sh` `check-pack` stop; verify against `git show HEAD:opencode.json` once and do not re-diagnose.
