## Lessons for workers

- For a clause-verification story, read the production path first: if the behaviour exists,
  write the green acceptance test rather than a `@Disabled` GAP test; reserve `@Disabled`
  for genuinely absent or partial behaviour.
- The recollect success response carries only the new `LabAccession`. To prove the original
  changed state and that both event streams were appended, read both specimens back through
  `GET /api/v1/lab/accessions/{id}` (`AccessionView`), not the POST response.
- A scenario that already exists on `main` cannot produce a classic red first run; the gap
  is the missing test and the green run is the proof. Say so explicitly in the notes rather
  than claiming a red was observed.
- `worker-check.sh` runs every integration test; in a swarm worker use the targeted
  `-Dtest=...` run plus `scripts/quick-check.sh` and record why, leaving the full gate to
  the integrator.
- In this cloud worker `git ls-files -v opencode.json` shows `S`: temporarily restore
  `git show HEAD:opencode.json` bytes to run `check-pack.py`/`quick-check.sh`/`unittest`,
  then put the CI bytes back. Never commit or regenerate `opencode.json`.
