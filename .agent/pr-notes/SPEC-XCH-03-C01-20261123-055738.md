## Lessons for workers

- For a clause test over an already-implemented rule, assert the *observed*
  durable fields rather than assuming symmetry: `clarify` writes the question to
  both `reason` and `question`, so a "reason is null" assertion is wrong.
- Prove a negative test is non-vacuous with a one-method fault-injection probe
  (flip the expected status, observe the real one, restore, rerun green) and
  record the exact failure line.
- A dedicated database name plus one order per test keeps append-only ledgers
  isolated between tests and between parallel workers.
- `opencode.json is stale` in a cloud worker is the CI profile under
  `skip-worktree`; confirm once with `git ls-files -v`, run remaining gate stages
  individually and never regenerate or edit that protected file.
