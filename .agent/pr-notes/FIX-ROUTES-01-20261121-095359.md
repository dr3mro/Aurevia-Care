## Summary

Removed the hard-coded 20-pattern route lists from the two staff-web route registry tests. Both tests now derive the expected feature patterns from the same source the router uses — `import.meta.glob('../features/*/routes.ts', { eager: true })` fed through `collectFeatureRoutes` — and assert only the app-owned structure: leading welcome page, ordered fixed pages, trailing `*` catch-all, optional `/design-preview` before `*`, no duplicate patterns. No production file, feature route file, dependency or coverage threshold was changed.

Scope (both files are the only changes):

- `apps/staff-web/src/app/routes.test.tsx` — `createRoutes` → "resolves every existing path".
- `apps/staff-web/tests/app/AppShell.test.tsx` — "route registry" → "registers only welcome, the development preview and a catch-all".

## Findings

1. Defect (the story): both tests compared `createRoutes(false)` with a fixed 20-pattern list. Seven feature routes added by later stories (`/orders`, `/orders/:id`, `/operations/queues`, `/lab/accessions`, `/lab/accessions/:id`, `/finance`, `/finance/:id`) made `main` red: 27 registered routes against 20 expected. Fixed by deriving the middle of the list from `collectFeatureRoutes` over the real glob.
2. Subtlety found during verification: a literal `slice(0, 5)` check for the fixed pages is **not** robust. `collectFeatureRoutes` sorts module paths descending, so a newly added feature whose name sorts after `system` is inserted between `/` and the four fixed system pages. The test failed with such a module. Resolved by asserting the fixed pages as an ordered subsequence of the full list, while the separate `toEqual(['/', ...featurePatterns(), '*'])` still pins `/` first and `*` last. No production file was changed to work around this.
3. No defect in `routes.tsx` or any feature `routes.ts` was found; they were intentionally left unchanged.

## Lessons for workers

When a test asserts a route registry, derive the expected middle from the same collector the application uses (`import.meta.glob` + `collectFeatureRoutes`) instead of enumerating patterns. Assert only the app-owned invariants — fixed pages as an ordered subsequence, first/last pattern, uniqueness, preview placement. Do not assert absolute indices for fixed pages: `collectFeatureRoutes` sorts module paths descending, so a new feature module can sort ahead of the `system` module and shift them. Before claiming "adding a route changes nothing", actually add a temporary synthetic feature module, run the tests, then delete it and confirm the working tree is clean.
