## Findings

- Clause status: **Proven by tests**, `## Gap: None` in
  `docs/spec/clauses/authz/invite-deactivate-staff-assign-bounded-roles-configure.md`.
  The implementation already exists in `StaffService`/`StaffRepository`/`FacilityService`
  with `V1`/`V2`/`V4` schema support and OpenAPI entries; this task added proof only.
- The new test deliberately does not re-assert the later IAM-02 sentences (grantor/effective
  dates beyond the invite record, next-request fail-closed on revocation, expired grants),
  which belong to separate clause stories. It asserts the invite record's grantor and
  effective window because they are part of "retain immutable membership history".
- Backend reviewer MEDIUM finding resolved: as `aurevia_app` the mutation refusal comes
  from missing `UPDATE`/`DELETE` grants, so it does not discriminate the V4 trigger. The
  test now also connects as the table owner (`aurevia_migrate`, NOBYPASSRLS with FORCE
  RLS) and asserts SQLSTATE `44000` for both a membership `UPDATE` and a role-grant
  `DELETE`, which only the append-only trigger can raise. Re-run green (8.131 s).
- Backend reviewer LOW findings resolved in the clause doc: removed the inaccurate
  "identical local identifiers" and ordered-history wording, and corrected the effective-
  date attribution (V4 stamps `created_at`; `valid_from` comes from V1 defaults and the
  repository grant insert).
- Whole-gate scripts stop at a pre-existing worktree-profile artifact, not a defect in
  this change; proven by the clean-HEAD detached worktree check above. No `opencode.json`,
  script, agent, workflow or tracker file was edited.
- Pre-existing defect observed, deliberately NOT fixed (outside task scope): six committed
  conflict markers sit inside Javadoc comments in
  `apps/api/src/main/java/com/aurevia/exchange/hl7/Hl7ParseException.java`
  (lines 6, 10), `Hl7Parser.java` (14, 18) and `Hl7Segment.java` (10, 14). `git show HEAD:...`
  confirms they are already committed in the base branch (HEAD equals `origin/main`), so
  `git merge --no-edit origin/main` was "Already up to date" and raised no conflict. They do
  not break Java compilation because they are comment text, but they should be cleaned by an
  XCH-01/XCH-04 owner; this task did not touch them.

## Lessons for workers

- When a task is "prove this clause by tests", survey the domain packages, web controllers,
  migrations and OpenAPI contract first: the clause was already fully built, so the right
  output was a new acceptance test plus a clause doc, never production edits or a
  `@Disabled` placeholder.
- In a cloud worker, `check-pack` and the six `test_check_pack` failures are the CI profile
  under `skip-worktree`. Confirm with `git ls-files -v opencode.json` and a clean detached
  worktree at HEAD instead of regenerating or editing the file; report the artifact and run
  the remaining gate steps individually.
- Run the new `@Tag("integration")` class directly (`-Dtest=ClassName`) against real
  PostgreSQL before considering any broader gate; it is fast (~9 s of tests) and reveals
  fixture/status-code mistakes that unit mocks cannot.
