## Lessons for workers

- In a cloud worker, `git ls-files -v opencode.json` showing `S` explains `check-pack.py` and `test_check_pack` failures; verify with `git show HEAD:opencode.json` and never regenerate or commit that file. Do not re-diagnose it on a later pass.
- For a documentation-only change, `python3 -I scripts/check-docs.py` plus `check-secrets.py` are the applicable gates; a green docs gate does not make the repository-wide unit suite green when pre-existing out-of-scope tests fail.
- Before treating a red full suite as your own regression, locate the failing files: if they are owned by other tasks and outside your task's `scope`, record the command, error and exact next step under Findings instead of editing protected files.
- A checklist about CI must derive required checks from the branch-protection gate job and each job's `if`/matrix conditions, not from the list of jobs that appear in a run; a job skipped on pull requests or limited to tags is evidence, not a required status check.
- Confirm which workflow actually publishes a digest before telling a person to record one: `Agent image` writes `published-image.txt`, while `Swarm slot images` pushes mutable tags with no digest.
