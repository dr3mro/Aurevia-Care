## Lessons for workers

- A wall-clock "reveal by elapsed time" assertion needs a buffer sized for the SLOWEST runner, not the local one. A +3 s window passed 3x locally yet is the only plausible flake in a 4108-test, JaCoCo-instrumented full build; +20 s with a 45 s poll keeps the proof and removes the risk. Repeat the class 2-3x and read the Surefire `flakes="0"` and method names, not just the BUILD SUCCESS line.
- Keep comments true in the same change: widening a poll from 60 to 90 attempts means updating the Javadoc "up to 30 seconds" to "up to 45 seconds" — the plan reviewer correctly made this a Required gap.
- On a "Delivery failed" hand-off with no failing command, do not claim a proven root cause. Record the hypothesis as unconfirmed, reproduce every check you can locally (targeted class, contract suites, policy scripts), request the failing command/job from the integrator, and make the smallest in-scope reliability improvement that cannot weaken the proof.
- AGENTS.md forbids a swarm worker from running `scripts/check.sh` / `apps/api/check.sh` / `mvn verify` (full OWASP, SpotBugs, JaCoCo and every integration test). Run the targeted `-Dtest` suite plus the individual policy scripts; leave the full gate to the integrator.
- The quality gate needs the notes file to exist with `## Review verdicts` before it runs; write the notes first, then run `bash scripts/quality-gate.sh BASE_SHA NOTES_FILE`. Keep unresolved `Critical:`/`Required:` lines out of `## Review verdicts` — only the three `GO` lines belong there.
- In a cloud worker, `git ls-files -v opencode.json` showing `S` explains `check-pack.py`/`test_check_pack` failures; confirm once with `git show HEAD:opencode.json` and never regenerate or commit that file.
