# AUD-20261121-10 — Unify two divergent subject-identifier validation rules at the request boundary

Task: AUD-20261121-10. Branch: `swarm/AUD-20261121-10-479` (base `928d886`). One story, synthetic fixtures only. No dependency, migration version, tracker, agent, script or workflow file changed. No push, tag or `gh` call.

## Summary

The same "lowercase subject" key was validated by two regexes. The strict rule `[a-z0-9][a-z0-9-]{1,63}` rejected dots and underscores; the loose rule `[a-z0-9][a-z0-9._-]{1,63}` accepted them. A canonical `Subject` primitive now owns the single loose rule in `api/contract`, and the three callers inside the declared production scope delegate to it: `ConversationInputs` (strict → canonical), `StaffService` and `StaffInvitationService`. The staff cursor is now built from the primitive's shared regex fragment instead of restating the alphabet. A real HTTP parity test drives `POST /api/v1/staff` and `POST /api/v1/conversations` with the identical subject and asserts both endpoints accept or reject it identically for valid, dotted, underscored, maximum-length and Arabic/RTL inputs (plus colon, too-short, too-long and absent).

The canonical rule is the **loose** one. AUD-20261121-15 already established it at the identity boundary and committed `SubjectValidationConsistencyTest`, whose `dottedAndUnderscoredParityIsPendingTheConversationMigration` explicitly named this story as the one that must make dotted/underscored agree. That assertion was flipped to parity.

## Lessons for workers

- An earlier story can leave an explicit "pending the next story" divergence assertion in a test outside your scope. Grep for the task ID in `src/test` before flipping a shared validator: that assertion must be updated in the same change or the suite goes red.
- When driving `StaffService.invite` through MockMvc or a unit test, stub `findUserIdBySubject(ACTOR)` as well as `hasActiveMembership`/`activeRoles`; a missing actor identity returns 403 and masks whether subject validation worked.
- Shared `@BeforeEach` stubs plus Mockito's default strictness break rejection-only tests (`UnnecessaryStubbingException`). Use `lenient()` or `@MockitoSettings(strictness = Strictness.LENIENT)` for a parity fixture that exercises both success and failure paths.
- `test_java_conventions.py` rejects `{@link #method(...)}` as well as simple class names: always write the fully qualified target, including the enclosing type before `#`.
- Auto-generated audit scopes can omit test paths and sibling callers; keep production edits inside the declared paths, write the mandatory tests in the matching test packages, and ask for a follow-up task for the remaining callers rather than silently widening scope.
- Confirm the canonical rule from committed cross-story tests before choosing between two candidate regexes; here AUD-15's `SubjectValidationConsistencyTest` fixed the loose rule unambiguously.
