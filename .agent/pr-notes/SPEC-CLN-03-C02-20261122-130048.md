# SPEC-CLN-03-C02 — CLN-03 clause 2 API test

## Summary

Added the API evidence test for the CLN-03 clause "Track verification, source and
effective dates, including explicit unknown and none states." The clause is fully
implemented in `com.aurevia.chart.record`, so the test is active (not
`@Disabled`) and green: one positive HTTP/PostgreSQL test proves provenance,
explicit `ABSENT`/`UNKNOWN` states, effective dates and version-bound verification
with actor and instant; four negative tests prove the rule refuses an unknown
assertion without a reason, an inverted effective period, a non-clinician verifier
and a stale version. Added the clause evidence document. No production code,
existing test, contract or migration was changed.

## Affected requirements

CLN-03 (clause 2). Acceptance mapping:

| Clause element | Test method | Asserted behaviour |
|---|---|---|
| track source / effective dates / explicit none | `provenanceSourceEffectiveDatesAndExplicitStatesAreTrackedThroughHttp` | `source`, `effectiveFrom`/`effectiveTo`, `presence: ABSENT` returned by HTTP and persisted in `chart_entry` |
| explicit unknown state | same test | `presence: UNKNOWN` with `unknownReason` persisted; `UNVERIFIED` until verified |
| track verification | same test | verify with `If-Match: "1"` returns `VERIFIED`, actor, instant and version 2; a fresh GET and the stored row agree |
| refuse unknown without reason | `unknownAssertionWithoutAReasonIsRefused` | HTTP 422 |
| refuse inverted effective period | `effectiveEndBeforeEffectiveStartIsRefused` | HTTP 422 |
| refuse wrong role | `roleWithoutClinicalAuthorityCannotVerifyAnEntry` | HTTP 403 for `reception` |
| refuse stale verification | `staleVersionCannotVerifyAnEntry` | HTTP 412 and the entry stays `UNVERIFIED` |

## Lessons for workers

- When a clause-probe task finds the behaviour already built, write a real HTTP test
  using the `it/chart/record/ChartRecordIntegrationTest` fixture pattern: seed the
  `patient_record` with a `dob` (V7 requires `dob` or `dob_unknown_reason` or the
  `@BeforeAll` fails), tag `@Tag("integration")`, and run only your class with
  `-Dgroups=integration -Dtest=<Class>`, never the full `mvn verify`.
- `git grep -nE '^(<<<<<<<|>>>>>>>) '` can report markers committed in unrelated
  files. Confirm with `git show HEAD:<path>` before treating them as conflicts from
  your own merge; preserve unrelated changes and record them as a finding instead.
- In a cloud worker the six `test_check_pack` failures are OPS-CW-003-01, not a
  regression. Check `git ls-files -v opencode.json` (`S`) once, record the command
  and final line, and do not regenerate the protected file.
