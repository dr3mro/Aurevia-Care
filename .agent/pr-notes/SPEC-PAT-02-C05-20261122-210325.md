## Findings

- **Deliberate deviation from story step 3.** The story asked for an `it.skip("GAP: ...")` test in
  the spec, but a probe proved `scripts/check-constraints.py:52-53` rejects any added `it.skip(` in
  a `.ts` file (exit 1), and that check runs from `scripts/check.sh`, `scripts/quick-check.sh`,
  `scripts/quality-gate.sh` and the integrator gate; AGENTS.md also forbids skipped tests. The
  complete GAP test is preserved verbatim in the clause doc's `## Gap` and here, and a
  `task-requests` block asks for the wiring task. The plan-reviewer made this shape a Required
  finding, so it is deliberate, not an oversight. The only pre-existing GAP skip in the repository
  is a Java `@Disabled` test already merged on `origin/main` (grandfathered, not an added line).
- **Unwired path (the reason for `Partly proven`).** `apps/patient-mobile/src/app/patientPages.tsx:270`
  passes `placeholderAction` as `onDownload`; `ReleasedReportsScreen.tsx:187` only forwards the
  tap. `RootNavigator.tsx:124` is an attachment-download placeholder for a different clause and is
  deliberately not cited here. No production file was changed to fix this.
- **No production defects found.** The kernel correctly refuses to authorize on cancel and requests
  the exact revision on confirmation; the gap is wiring, not logic.
- **Doc wording nits fixed.** The supporting tests at `reports-screen.test.tsx:172-205` assert alert
  title, message, button count and both callbacks by index, not the literal button text; the doc now
  says "title and message and both button callbacks" (raised as Optional by the code reviewer and
  DevSecOps).
- **Red phase not applicable.** This is a proof/characterization spec for already implemented
  behavior and no production code changed; fault detection is through exact-argument, zero-call and
  both-button assertions rather than a red-to-green production edit.
- **Out-of-scope observation, not introduced here.** `git merge --no-edit origin/main` reported
  "Already up to date" (HEAD equals origin/main). A repo-wide

Preserved complete GAP test (same fenced example as the clause doc, quoted here for the next
worker; deliberately not an active test file):

```tsx
it.skip("GAP: the reports page confirms intent before authorizing a local copy", async () => {
  const originalAlert = Alert.alert;
  const alerts: AlertButton[][] = [];
  Alert.alert = (_title, _message, buttons) => {
    if (buttons) alerts.push(buttons);
  };
  try {
    const authorize = recorder(async (reportId: string, revision: number): Promise<DownloadAuthorization> => {
      expect([reportId, revision]).toEqual(['report-1', 2]);
      return authorization;
    });
    const view = await render(
      <ReleasedReportsPage
        transport={{ get: async () => [report], post: async () => ({}) }}
        locale="en"
        organizationId="org-1"
        patientId="patient-1"
        onSessionExpired={() => undefined}
        authorizer={{ authorizeDownload: authorize.fn }}
      />,
    );
    const download = await view.findByTestId('download-report-1');
    await fireEvent.press(download);
    expect(alerts).toHaveLength(1); // fails today: the host passes placeholderAction
    expect(authorize.calls).toEqual([]); // no server call before an affirmative choice
    alerts[0]?.[1]?.onPress?.(); // Download
    await waitFor(() => expect(authorize.calls).toEqual([['report-1', 2]]));
  } finally {
    Alert.alert = originalAlert;
  }
});
```

## Lessons for workers

- Before writing an `it.skip` for a gap, run `python3 -I scripts/check-constraints.py --base HEAD
  --require-base` on a probe: Markdown is exempt, `.ts` is not. Keep the complete test verbatim in
  the clause doc and notes with a task request instead, so the quality gate stays green.
- For patient-app clause proofs, reuse `recorder()` and the synthetic `report`/`authorization`
  fixtures from `report-core.test.ts`, stub `Alert.alert` as in `reports-screen.test.tsx`, and drive
  the composed real chain rather than restating isolated branches; this satisfies both the test
  engineer and the plan reviewer without duplication.
- `bash apps/patient-mobile/check.sh` is the definition of done, not Jest alone; `tsc --noEmit`
  prints nothing on success, so paste the `npm run typecheck` final line separately.
- When a reviewer cites an unwired placeholder, confirm which requirement it serves before naming
  it in the gap: an attachment `onDownload` is not the released-report intent clause.
- Report status as `Partly proven` when a kernel is unit-tested but the screen host never calls it;
  "Proven by tests" would overstate the end-to-end path.
