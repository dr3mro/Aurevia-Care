# SPEC-IAM-01-C01 — IAM-01 clause 1 (API test)

## Summary

Adds the clause-verification acceptance test for IAM-01 clause 1, "Maintain Organization,
Facility, UserIdentity, Membership and RoleAssignment", and the clause status document.
The clause is already implemented, so the test is active (no `@Disabled`) and green:
one positive end-to-end proof plus four negative refusals against real PostgreSQL with
synthetic fixtures. No production code, contract, migration, existing test or tracker
was changed.

## Affected requirements

IAM-01 (clause 1). Related boundary decisions referenced only as context: IAM-02, ARC-02, OPS-02.

## Risk class

Safety-critical (identity, tenant scope and permission enforcement are exercised), but the
change is test-and-documentation only: no production behavior or deployment is altered.

## Review owner

Senior Java and Spring Boot / Senior Spring Security and OIDC (advisory). No clinical or
human review required for a synthetic-data test-only change.

## Data changes

None. No migration, backfill, lock or volume impact. The test creates and drops its own
database `orevia_iam01_clause1_it` and uses only synthetic subjects (`admin-a`,
`reception-a`, `admin-b`, `clause-user-a`) and UUIDs `1111…`/`2222…`.

## Authorization boundaries and audit events

The test asserts: an active `tenant_admin` membership plus the `FACILITY_WRITE`,
`STAFF_INVITE` and `STAFF_READ` action permissions are required; a `reception` role is
denied (403); a subject without membership in the selected organization is denied (403);
cross-tenant subject/facility reads are concealed (404); a missing active-organization
selection is rejected (422); invalid and duplicate inputs are rejected (422/409). The
role grant's `granted_by` is asserted to equal the authenticated actor's user id. No new
audit events are produced by the change itself; the existing STAFF_ADMIN/FACILITY audit
paths are exercised through their normal entry points.

## Migration and rollout considerations

None. Flyway migrations are applied unchanged by the test (`filesystem:../../db/migrations`,
v90). Organization rows are provisioned out-of-band by migration/IaC per the V2 header and
the PROJECT.md IAM-01/ARC-02 decision; there is no V1 self-service organization CRUD
endpoint, which is a design decision, not a gap in the enforced rule.

## Findings

- No code defect found. The clause is fully implemented in
  `V1__tenant_schema.sql`, `V2__rls_roles_policies.sql`, `V4__staff_lifecycle.sql`,
  `tenancy.FacilityService/FacilityRepository`, `staff.StaffService/StaffRepository`,
  `staff.StaffInvitationService`, `authz.ActionPolicy`, `authz.history.*`,
  `tenant.TenantContext/TenantGuardTransactionManager`, `web.TenantContextInterceptor`,
  `web.FacilityController`, `web.StaffController`, `staff.StaffInvitationController` and
  the `contracts/openapi.yaml` facility/staff paths. Documented in
  `docs/spec/clauses/authz/maintain-organization-facility-useridentity-membership-roleassignment.md`.
- Organization has no application-level CRUD endpoint by design (provisioned out-of-band);
  the test proves the Organization tenant boundary is enforced on every write rather than
  asserting a CRUD API that does not exist in V1.
- Environment artifact only: three `test_check_pack` failures from the skip-worktree CI
  `opencode.json` profile (see Test evidence item 8). Not caused by and not fixable inside
  this task's scope.

## Lessons for workers

- When a clause's entities are already maintained by existing services, prove the clause
  through the HTTP entry points and read the durable rows back under forced RLS; a unit
  test of a single policy class would not prove end-to-end maintenance or tenant scope.
- Reuse the neighbouring integration tests' fixtures exactly (two synthetic orgs with
  identical local codes, `X-Synthetic-Subject` + `X-Active-Organization` headers, Flyway
  filesystem migrations, own database per class) so the integrator's gate recognizes the
  pattern.
- In this worker image, `git ls-files -v opencode.json` = `S`: three `test_check_pack`
  failures are the known CI-profile artifact, not a change defect. Do not regenerate
  `opencode.json`, do not weaken checks, and leave the full gate to the integrator.
