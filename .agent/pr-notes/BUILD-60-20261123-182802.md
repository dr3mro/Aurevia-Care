## Findings
- **Pre-existing role-gate defect (not introduced here).** `src/app/useRole.ts:10` fixes the signed-in role to `reception`; `AppShell` denies `/radiology`, `/pharmacy` and `/lab/accessions` even though the screens and routes exist. The four existing radflow/pharmacy route-based tests are red on this checkout (tool evidence above). I did not change `src/` or those tests. New journeys mount the real screens with the real providers, following BUILD-59.
- **No production therapy or finance screen exists.** `src/app/navigation.ts:189,209` declares `/therapy` and `/finance`, but there is no `src/features/therapy` or `src/features/finance` and no route registration; self-contained harnesses with `/api/v1/**` stubs are therefore the only e2e-only way to exercise those roles here. `BUILD-47` is `[x]` yet no therapy directory exists in this checkout — stale tracker claim, recorded for the integrator.
- **Contract-faithful stubs.** All new stubs answer with `{code: ...}` and record `X-Active-Organization`, `X-Correlation-Id`, `X-XSRF-TOKEN` and, for the export POST, `Idempotency-Key`. Denials use codes from the specification (403 `FORBIDDEN`, 404 `NOT_FOUND`) except pharmacy's 409 `INVALID_TRANSITION` (RX-02 clause 5) and radiology's existing 422 `LABEL_MISMATCH`.
- **Playwright gate is separate.** `check.sh` excludes e2e from Vitest and from `tsconfig.json`; the targeted Playwright run and the `tsconfig.lint.json` typecheck are required in addition.
- **Environment flake observed once:** the pre-existing `smoke.spec.ts` "language toggle ... without violations" case timed out at 30 s in one run; all other smoke cases passed. Not caused by this change; no test config changed.
- **Reads versus commands (devsecops Optional):** the real `buildRequestDescriptor` puts tenant, correlation, idempotency and `If-Match` on descriptors but the transport adds CSRF only for commands, so the admin manifest-read stub requires tenant plus role and the spec asserts the tenant header; command stubs still require and assert all boundary metadata. The pharmacy stub records only `METHOD /path`, so its journey's tenant/correlation/CSRF metadata is not asserted (Optional, no gate impact); changing the shared pharmacy stub's store shape would affect the pre-existing journey and is left to a follow-up.

## Lessons for workers
- In this checkout the pre-login shell fixes the role to reception, so specialty routes render a forbidden page. Mount the real screen in a dev-only harness with its real providers (BUILD-59 pattern) and record the gate defect for an owner instead of "fixing" the route test.
- Install Playwright browsers and OS libraries first (`npx playwright install chromium`, `npx playwright install-deps chromium`); a missing `libglib-2.0.so.0` is environmental, not a failing journey.
- Keep Playwright `page.evaluate` response bodies typed as `unknown`: `await response.json()` is `any` and fails the strict lint gate on assignment.
- Assert store facts, not only recorded calls: a direct denied command is still recorded as a call, so "no call" can be false while no state changed.
- Do not require CSRF or correlation headers on a synthetic GET: the real staff-web GET descriptor carries only the tenant header, so an over-strict stub makes the real typed client look forbidden.
- A harness filename and the `page.goto` path must match exactly; Vite's SPA fallback silently serves the app shell for an unknown harness URL, which looks like a broken component.
