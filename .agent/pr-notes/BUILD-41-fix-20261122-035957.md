## Findings

- Root cause (confidence high, tool evidence): `8f363e02` changed `worker_gate.main()`
  from `failing = failing_classes(REPORTS)` to reading `reports = Path(args[1])` and
  calling `usable_reports(reports)`, which globs a path without checking it exists. Two
  tests mock only `Path.is_dir -> True` and call `main(["1"])` with no second argument,
  so they enter `usable_reports()` against the non-existent legacy default directory and
  raise `FileNotFoundError`. The regression is pre-existing on `origin/main` and
  unrelated to BUILD-41.
- Order dependency (proved this pass): the two errors vanish whenever
  `apps/api/target/surefire-reports` exists with parseable `TEST-*.xml`, which is why
  local Maven-then-Python runs can look green while CI (policy job before Java job)
  stays red.
- Bounded fix plan (from the step-5 debugger report, treated as notes, for the owning
  maintainer): in `scripts/tests/test_worker_gate.py`
  (`test_integration_failure_still_fails_the_gate`, ~lines 328-336) create a
  `tempfile.TemporaryDirectory()`, write one parseable `TEST-FooTest.xml`
  (`<testsuite failures="1" errors="0"></testsuite>`) into it and call
  `worker_gate.main(["1", reports_dir])`; drop the `Path.is_dir` mock, keep the
  `failing_classes` mock returning `{"RxTransmissionFlowTest"}` and the `== 1` assertion.
  Do the same in `scripts/tests/test_worker_gate_coverage.py`
  (`test_maven_failure_with_failing_reports_still_fails`, ~lines 552-555), reusing its
  `write_report` / `suite_xml` helpers; extend `run_main` / `patch_common` so `reports=True`

## Lessons for workers

- JaCoCo coverage of a JDBC store depends on the integration test: a unit-only pattern
  left `JdbcExportStore` at 91/186 instructions; including `TenantExport*Test`
  (`TenantExportIntegrationTest`, real PostgreSQL) brought it to 186/186. Always run the
  full pattern `-Dtest='Export*Test,...,TenantExport*Test'` when claiming 100%.
- When a change alters the contract of a shared function (`worker_gate.main()` now needs
  an explicit fresh report directory), update *all* callers and unit tests in the same
  commit; mocking `Path.is_dir` is not a substitute for a real directory once the
  function globs it.
- A test that passes only because a previous command created a build artifact
  (`apps/api/target/surefire-reports`) is not hermetic. Give it its own
  `TemporaryDirectory` with a parseable `TEST-*.xml`.
- Before re-running a fix, inspect `git log origin/main..HEAD`: earlier workers may
  already have applied it, and the correct job is independent verification plus a fresh
  notes file. Do not redo what earlier findings record as tried.
- Distinguish a pre-existing failure on `main` from a branch defect. A failure that
  reproduces on a clean `origin/main` belongs to its owning change, not to the story whose
  PR happens to be red.
- Respect protected paths: a swarm PR touching `scripts/`, `.opencode/`, `.github/`,
  `opencode.json` or a tracker is never auto-merged, and `worker_gate.validate_candidate`
  flags it as a scope violation. Put the finding in the notes hand-off instead.
- In this cloud worker `opencode.json` is a skip-worktree CI profile: `git ls-files -v`
  shows `S`, `gen-opencode.py --check` judges the CI bytes and reports false staleness,
  while `git show HEAD:opencode.json` equals `gen.render(ROOT)`. Never regenerate or
  commit that file.
