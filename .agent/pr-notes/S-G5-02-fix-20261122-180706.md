## Findings

### Confirmed root cause of the red gate (tool evidence, pre-existing)

Both errors reproduce on this clean checkout with no `apps/api/target`, and
disappear when a single valid `TEST-*.xml` exists in the shared Surefire
directory. Trace: the tests patch `worker_gate.Path.is_dir` to return `True` but
call `main(["1"])` with no report-directory argument, so `main` falls back to
the shared path `REPORTS = "apps/api/target/surefire-reports"`. On Python 3.11
`Path.glob` raises `FileNotFoundError` for a missing parent directory. The
branch changes only the launch document and notes files and introduces none of
this; `git diff origin/main...HEAD -- scripts/` is empty.

### New this pass: the defect breaks required CI, not only local workers

Earlier notes called this "likely worker-environment-only" because the
integrator runs Maven before some checks. That is inaccurate. Direct tool
evidence from `.github/workflows/delivery.yml`: the `script-tests` job (a
required check) runs `python3 -I -m unittest discover -s scripts/tests -q` on a
fresh checkout with no Maven step, so it has no Surefire directory. The same
ordering exists in `scripts/check.sh`, which runs `bash
scripts/python-coverage.sh` before the per-module `check.sh` scripts that invoke
Maven. The two errors therefore fail CI on any clean checkout, and a person must
land the fix through a trusted change; it will not self-heal on a later pass.

### Why this PR cannot carry the fix

Editing `scripts/` here cannot turn this PR green: `worker_gate.validate_candidate`
compares every changed path with the task scope (`docs/launch`) and emits a
`scope` violation for a script path, and `scripts/swarm.py::guard()` labels an
ordinary PR touching `scripts/*` as `needs-human` so it is never auto-merged.
The change must land in a separate repair/trusted change with a scope that
includes `scripts/`.

No `task-requests` block is included because none can express this repair:
`scripts/swarm.py::scope_ok()` rejects any scope matching protected `scripts/*`,
so a request with the real scope would be silently dropped, and a request with a
non-protected scope would create a mis-scoped task. The owning path is a
maintainer / watchdog `FIX-` repair or the daily notes reconciliation applying
the patch below directly. This is the same hand-off recorded in
`.agent/pr-notes/BUILD-41-fix-20261122-035957.md` and
`.agent/pr-notes/QA-SOURCE-01-fix-20261122-133038.md` for the same pre-existing
defect.

### Exact patch needed (NOT applied — out of scope, protected path)

Both test files already import `tempfile` and `Path`;
`test_worker_gate_coverage.py` already has `write_report(directory, filename,
xml)` and `suite_xml(name, failures, errors)` helpers.

Required — make the two tests own a real report directory. In
`scripts/tests/test_worker_gate.py`, replace
`MainTest.test_integration_failure_still_fails_the_gate` (~line 328) with:

```python
    def test_integration_failure_still_fails_the_gate(self):
        # A repair task is strict: its failing class fails the gate even with no
        # hand-off scope declared. Own a real report directory so the gate reads
        # usable results without depending on a Maven run creating the shared one.
        with tempfile.TemporaryDirectory() as reports:
            (Path(reports) / "TEST-RxTransmissionFlowTest.xml").write_text(
                '<testsuite name="RxTransmissionFlowTest" tests="1" errors="1" failures="0"/>')
            with mock.patch.object(worker_gate, "failing_classes",
                                   return_value={"RxTransmissionFlowTest"}), \
                 mock.patch.object(worker_gate, "changed_paths", return_value=[]), \
                 mock.patch.dict(os.environ, {"STORY_ID": "FIX-01"}, clear=True):
                self.assertEqual(worker_gate.main(["1", reports]), 1)
```

In `scripts/tests/test_worker_gate_coverage.py`, replace
`MainTest.test_maven_failure_with_failing_reports_still_fails` (~line 552) with:

```python
    def test_maven_failure_with_failing_reports_still_fails(self):
        # A strict repair task that names no class stays red on any failing class.
        # Use a real private report directory, not the shared Surefire path, and do
        # not mask is_dir: the real directory must satisfy worker_gate itself.
        reports = self.root / "reports"
        reports.mkdir()
        write_report(reports, "TEST-FooTest.xml", suite_xml("pkg.FooTest", "0", "1"))
        with mock.patch.object(worker_gate, "changed_paths", return_value=[]), \
             mock.patch.object(worker_gate, "failing_classes", return_value={"FooTest"}), \
             mock.patch.dict(os.environ, {"STORY_ID": "FIX-01", "STORY_BODY": ""}, clear=True):
            self.assertEqual(worker_gate.main(["1", str(reports)]), 1)
```

Both keep the original assertion (`== 1`) and add no skip, exclusion or lowered
threshold. With this change `usable_reports()` reads a real, parseable XML file
and neither test touches the shared directory, so both errors go away without a
Maven run. Verify with `python3 -I -m unittest discover -s scripts/tests -p
'test_worker_gate*.py'` (no `apps/api/target`) → `Ran 143 tests … OK`.

No production-code hardening is proposed: `usable_reports` is only reached
after `main` checks `is_dir`, and a guard whose only trigger is a mocked error
would be uncoverable by real input (AGENTS.md Coverage rule 3). Keep the repair
test-only.

## Lessons for workers

- On a fix pass whose local checks failed, run the exact command that failed
  (`bash scripts/python-coverage.sh` or its `unittest discover` core) before
  concluding the in-scope change is fine. A passing documentation gate does not
  make the PR green.
- A test that patches `Path.is_dir` but globs the shared `apps/api/target`
  directory is environment-dependent: it passes only after Maven created that
  directory. Tests must own a real temporary report directory via the
  `main(["<mvn-status>", "<reports-dir>"])` second argument.
- Check the CI workflow, not only the local worker, when judging whether a
  failure is "environment-only". `delivery.yml` `script-tests` runs the Python
  suite with no Maven step, so this defect is a real required-check failure.
- `scripts/` is a protected path and outside this story's scope. Editing it here
  creates a `scope` violation in the worker gate and a `needs-human` label;
  record the finding under `## Findings` for the integrator or daily-notes
  reconciliation (a `task-requests` entry cannot carry a protected `scripts/*`
  scope) and write `## Why this is not finished` instead.
- The six `test_check_pack` failures in this cloud worker are the documented
  skip-worktree/CI-profile artifact (OPS-CW-003-01); confirm once with
  `git ls-files -v`, `cmp` and `git show HEAD:opencode.json`, then stop
  re-diagnosing them.
