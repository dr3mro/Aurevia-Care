## Findings

- The app-level status-change to push trigger is unbuilt: no screen, provider or API client calls `notificationContent` or `dispatchNotice` on a status change; the precedent clause document records `placeholderAction` handlers in `patientPages.tsx` and `RootNavigator.tsx`. This story proves only the built helpers.
- There is no production caller for `dispatchNotice`/`notificationContent`; the API context uses `GenericPushNotice.appointmentUpdate()` and records status only in an audit key. The API files were read as context only and not changed.
- No real APNs/FCM gateway exists; the provider boundary is synthetic and always reports delivery. Real-device, real-provider and G5 evidence cannot be created by a code change.
- The story's `it.skip` instruction conflicts with the coverage rules; resolved as described under Test evidence, with the missing behaviour recorded in `docs/spec/clauses/patient-access/prefer-push-notifications-status-changes-generic-text.md` and in the task requests below.
- Test-engineer findings (tautological constant comparisons, no positive control, a status-change name with no clinical fixture in play, a misplaced assertion on the test's own input) were all fixed and re-reviewed GO.
- No defect in production code was observed; BUGS.md was not edited (worker scope forbids it).

## Lessons for workers

- When a story asks for a skipped GAP test but the coverage rules and `scripts/check-constraints.py` reject skips, write enabled regression tests and put the missing behaviour in `## Gap` plus a `task-requests` block; state the conflict in `## Findings`.
- Prove "generic text" with exact literal assertions, not by comparing a shared constant to itself, and drive the clinical fixture through the authenticated path so the negative assertions are not vacuous.
- Give a tenant-negative test a positive control in the same boundary, otherwise "no send" cannot be distinguished from a dispatch loop that never sends.
- Swarm reviewer sessions may lack `node_modules`; treat their static assessment as review evidence and record the canonical `bash apps/patient-mobile/check.sh` output from the primary agent as tool evidence.
