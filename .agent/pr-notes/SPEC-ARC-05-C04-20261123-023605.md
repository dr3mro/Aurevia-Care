## Findings

- Clause is fully implemented in production (`DurableEventService.retry` 172-196,
  `backoffSeconds` 84-86, `MAX_ATTEMPTS=3`, `DeliveryActions.allows` 30); no GAP
  and no `@Disabled` test was needed.
- Survey finding: the cited HTTP integration test reaches `DEAD_LETTERED` through the
  separate `/dead-letter` endpoint (line 278), not retry exhaustion. The doc is
  worded narrowly and attributes attempt-budget exhaustion to the new in-memory test.
- Out-of-scope production nit (not changed): `backoffSeconds` Javadoc says
  "zero-based attempt number" while `retry` passes a one-based `nextAttempt`;
  functional behaviour is correct and pinned by tests.
- Known worker-environment false positive recorded once: `git ls-files -v opencode.json`
  returns `S opencode.json` (skip-worktree CI runtime profile installed by
  `agent-run.sh`, OPS-CW-003-01); `git show HEAD:opencode.json` parses correctly.
  This explains all 6 `test_check_pack` failures and the `worker-check.sh` stop.
  Not re-diagnosed; the committed file was not regenerated or committed.
- Code reviewer's Optional nit was fixed: the backoff comment and doc now say the
  60 s cap holds "across the retry budget's reachable attempt range" instead of
  "however large the attempt number grows" (Java masks the `1L << attempt` shift
  distance at 64). No behaviour change; tests and docs checks re-run green after the edit.
- Pre-existing condition (not touched, out of scope): committed HEAD contains
  conflict-marker text inside Javadoc of unrelated `exchange/hl7/Hl7Parser.java`,
  `Hl7Segment.java` and `Hl7ParseException.java`; Maven compiles cleanly because the
  markers are inside comments. No merge was needed (0 behind `origin/main`).
- SpotBugs, OWASP/NVD and JaCoCo full gate are integrator-owned; their absence here
  is not a gap in this test+doc-only change.

## Lessons for workers

- When a reviewer's NO-GO was based on a stale plan brief, re-brief them with the
  actual written file: `retry(failedId, "1")` on a FAILED event at version 2 is a
  genuine 412, whereas the planned `retry(failedId, "2")` on a version-1 event was not.
- In a cloud worker, `S opencode.json` from `git ls-files -v` explains
  check-pack/test_check_pack failures; verify with `git show HEAD:opencode.json`,
  run the remaining gate stages individually, and never regenerate or commit that file.
- For an already-implemented clause there is no red phase; make the proof credible by
  asserting statuses, codes, audit outcomes and peer-tenant state, not just calls.
