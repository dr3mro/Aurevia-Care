## Findings

- **Advisor brief deviation (correct, in scope):** the brief named `messages.ts`, but `tests/messageParity.test.ts:164-167` auto-discovers every `src/**/messages.ts` and `BUNDLE_SOURCES` at `:141-157` only accepts a fixed list; registering a new file would require editing that out-of-scope test. The bundle was therefore named `labels.ts` (and its test `labels.test.ts`), following the sibling `staffmsg/directory/labels.ts` pattern the brief itself cited. The global registry test stays green. (Tool evidence.)
- **Deliberate divergence from the plan reviewer:** the reviewer asked the presentation type to mirror `SettingsCommand` from SMSG-10. This story's acceptance criteria explicitly require an out-of-office *reply* and a *sound-enabled* default-off toggle, neither of which exists in that API record, and the story forbids inventing a client. `NotificationSettings` is therefore a presentation model; task-request (b) requires the future route/client to define the explicit field mapping (`muted` → conversation mute set, `outOfOffice` + `delegateSubject` → server command) rather than sending this object verbatim.
- **Reachability:** intentionally non-reachable until follow-ups land. SMSG-16 must not be treated as user-visible acceptance: mounting the badge in the header and publishing the settings route/client are requested in `task-requests`. `AppShell.tsx` already has an empty notifications `<div role="status">` mount point for the badge follow-up.
- **Coverage- and review-driven fixes applied in this change:** (1) DND equal hours now mean *whole day*, matching `NotificationContract.DndWindow.contains` (`apps/api/.../notify/NotificationContract.java:72-79`) — the first plan used the opposite convention; (2) plural badge labels added with discriminating singular/plural assertions after the coverage audit; (3) "copy my changes" now stores a frozen snapshot so it survives a reload, after the code review; (4) optional `onSignIn` is wired into the expired-session state view; (5) the lexer-level RTL/forbidden-string scan and explicit `aria-describedby`/status-absence assertions were added.
- **Deferred to follow-ups (reviewer Optional findings):** full Arabic ICU plural categories (dual/few/many) are a site localization decision; the `min`/`max` hour bounds and the no-PHI-in-compare-panel rule must be enforced by the future server route; the global UX-01 registry must be updated when a future story intentionally adds a `messages.ts`; the unsaved-changes guard currently covers `beforeunload` only (in-app navigation ownership belongs to the route-wiring follow-up).
- **Environment note:** the full Vitest log prints "Not implemented: navigation (except hash changes)" from the pre-existing `UnsupportedBrowserPage` test; this change adds no navigation and the gate is green.
- **Evidence provenance:** executed tool commands and file reads; read-only specialist reviews. No human, clinical, simulated-user or real-patient evidence was claimed.

## Lessons for workers

- Before adding a `messages.ts` to any staff-web feature, check `tests/messageParity.test.ts`: its `import.meta.glob` registry fails a new bundle until a fixed `BUNDLE_SOURCES` list outside the story scope is edited. A feature-local `labels.ts` follows the `staffmsg/directory` precedent and keeps the gate green.
- Check the authoritative backend rule before encoding a domain invariant in a UI preview. `NotificationContract.DndWindow.contains` treats equal start/end as a whole-day window; assuming "equal means off" would have silently disagreed with the service.
- Assert the *specific* bundle entry for each plural branch (`toBe`), not just that a digit and a placeholder substitution appear — a tautological expected value lets a flipped branch pass.
- Per-file V8 coverage counts arrow handlers inside JSX: changing every input (including both numeric hour fields) is required to avoid missed functions on `SettingsPage.tsx`.
- Run the canonical `bash apps/staff-web/check.sh` early, not just the local folder tests: it caught the global message-registry failure that a targeted Vitest run could not see.
- When a state view offers "copy my changes", freeze a snapshot. Rendering the live draft and clearing the copy on reload destroys the very work the action exists to preserve.
