# QA-SOURCE-02 — Wire released-report downloads in the signed-in patient app

## Summary

The signed-in patient Reports page no longer calls a no-op for Download. A press now asks for explicit intent, reads the OS-backed credential, requests fresh server authorization for the exact tapped revision through the deployed `GET /api/v1/patient/reports/{reportId}/download?revision=N` route, validates that authorization against the verified patient and current release, and only then forwards it to a narrow `DocumentHandoff` seam. No clinical bytes, checksum or document reference is retained by the app. The retired POST path/body is gone from the in-scope client and tests.

## Affected requirements

- PAT-02 — patient-visible released reports and authorized download.
- Contract evidence: `apps/api/src/main/java/com/aurevia/messaging/reports/ReleasedReportController.java:23,42-55`; `contracts/openapi/missing-routes.txt:72-73` (route remains an OpenAPI parity gap, out of scope).

## Risk class

Cross-boundary (patient-facing app, OS credential, deployed HTTP contract). Not safety-critical: no clinical bytes are handled in this slice and no live clinical sign-off is claimed. All review and user evidence here is synthetic/simulated.

## Review owner

Senior React Native and Expo boundary, routed by the brief to `aurevia-code-reviewer`, `aurevia-coverage-auditor` and `aurevia-devsecops`. `aurevia-context-optimizer`, `aurevia-test-engineer` and `aurevia-plan-reviewer` were consulted before implementation; their findings are recorded below.

## Data changes

None. Mobile-only change. No migration, no RLS, no backfill, no backend change and no schema or OpenAPI edit.

## Authorization boundaries and audit events

- The client is bound to `patientId` from verified `PatientPageProps`; a blank identity fails closed with `INVALID_PATIENT` and a foreign authorization fails with `WRONG_PATIENT`.
- The session credential is read from `SecureCredentialStore` immediately before the request; the credentialed `Transport` also reads `loadToken` per request. The token is never placed in the URL, the page state, an alert or a log.
- `parseAuthorization` still rejects malformed, mismatched, wrong-patient and withdrawn responses; a 401 routes to the existing `onSessionExpired` callback. No audit event is added by this mobile-only change; the server continues to audit download at `ReleasedReportService.download`.

## Migration and rollout considerations

None. The installed build's default handoff is a documented deferred seam: the deployed GET returns a reference, not bytes or a signed URL, so a platform save action remains a dependency (see Findings and task-requests).

## Findings

- **Resolved in repair attempt 1 (orchestrator expanded scope to `apps/patient-mobile/src/spec/patient-access`):** the spec had stubbed `postJson` and asserted `postCalls[0] === ['/api/v1/released-reports/report-1/download', 'token-1', { revision: 2 }]` plus `postCalls.length` in the negative cases. After the GET switch its `getJson` stub returned `[]`, so four tests failed with `MALFORMED_AUTHORIZATION` instead of the expected refusal codes. Fix: the `transport` helper now returns the canned payload on `getJson`; every negative case asserts `getCalls.length === 1` and `postCalls.length === 0`, the happy path asserts the exact GET path and token, and a malformed-authorization test was added. The canonical gate is now green at 100% with no threshold, exclusion, ignore comment or skipped test changed. The first task-request below is satisfied and needs no separate story.
- **Deployed response shape mismatch:** `ReleasedReportService.java:224-225` `ReportDownload` returns only `reportId, revision, documentId, checksum, language`. The brief requires `parseAuthorization` unchanged, and it still requires `patientId` and `releaseState`, so a real successful GET response is rejected with `MALFORMED_AUTHORIZATION`. Fixtures in the in-scope tests use the 7-field authorization as before. This story therefore does **not** prove deployed-contract interop. Needs a backend change or an owner decision; recorded as a task-request.
- **No document handoff route:** no controller or native module returns report bytes or a signed URL for `documentId`. The page's installed `deferredDocumentHandoff` is an explicit, documented pending seam that retains nothing; the injected seam is what the page-level test proves. The download is not end-to-end until the backend route and platform save action land.
- **Contract parity gap:** `contracts/openapi/missing-routes.txt:73` lists `GET /api/v1/patient/reports/{}/download` as undocumented; out of scope for this mobile-only change.
- **Brief contradiction (resolved by orchestrator scope decision in repair attempt 1):** the original brief demanded a green `bash apps/patient-mobile/check.sh` while forbidding the only edit that would make it green. The worker followed the scope rule and reported the red gate; the orchestrator then expanded `src/spec/patient-access` into scope and dispatched the repair, which is now green.
- **Plan reviewer history:** `aurevia-plan-reviewer` first answered NO-GO on the out-of-scope spec, the unchanged parser, the stateless page and the handoff seam. After the dependencies were recorded, the branch map was written under `## Coverage`, and it was clarified that the injected-handoff page test asserts exact forwarding while a test-only hook would violate AGENTS.md, it answered GO. ## Lessons for workers

- Before wiring a page to a new client import, check the headless test's `jest.mock('expo', …)` graph: a full Expo mock also removes `requireNativeModule`, so a newly imported native module needs a synthetic adapter in that in-scope test.
- When a client moves from POST to GET, migrate every `postCalls.length` assertion to `getCalls` too: a `postCalls === 0` assertion stays green even when nothing was requested and proves nothing.
- `recorder` helpers capture an argument tuple, so a single-argument callback assertion is `[[value]]`, not `[value]`.
- A brief can demand a green canonical gate while forbidding the out-of-scope edit needed for it; follow AGENTS.md scope, record the exact red command and final lines, and file a task-request instead of touching the file.
- Coverage collected from a subset of test files understates a page file; only the full module coverage command proves the page's 100%, so run both the targeted inner loop and the module coverage command.
- When a client moves a request to a new transport seam, a stub that still returns the old canned shape makes every negative assertion collapse to the generic parse error. Feed a valid payload through the new seam, then assert the exact new path/token in the happy path and keep a per-code negative case for each refusal branch.
