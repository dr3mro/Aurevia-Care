## Summary

Added one HTTP-level integration test class and one clause evidence document. No
production code, existing test, migration or contract was changed. Clause 1 is
already fully implemented, so the tests are active (no `@Disabled` GAP) and the
pull request stays green.

Discovery before writing the test: the `chart` domain itself
(`apps/api/src/main/java/com/aurevia/chart/record/`) only holds basic
chart-entry capture and has no signing state machine. The clause is implemented
in the neighbouring `com.aurevia.clinical.notes` package —

actors and checksums, and a legal-predecessor guard). The contract routes are
`POST /api/v1/clinical-notes`, `/{id}/sign`, `/{id}/amend`,
`/{id}/sign-addendum`, `/{id}/entered-in-error` and `GET /{id}`. Neighbouring
fixtures/styles reused: `it/clinical/ClinicalNoteRevisionIntegrationTest`
(tagged `@Tag("integration")`, random-port Spring Boot, `synthetic-auth`,
Flyway against a dedicated PostgreSQL database, `X-Synthetic-Subject` and
`X-Active-Organization` headers, `If-Match` version precondition) and
`it/clinical/ClinicalNoteServiceTest`.

## Lessons for workers

- When reusing the local `field(json, key)` helper from the clinical-note
  integration tests, a JSON `null` is returned as the four-character string
  `"null"`, not `""`; assert that literal when checking absent signature fields.
- Give each clause suite its own database name (for example
  `orevia_cln05_c1_it`) so parallel clause workers do not drop each other's
  data.
- A test-only change has no new production branches: the honest coverage
  statement is that no production file changed, and a targeted JaCoCo run over
  the exercised classes is the worker-area evidence, while full `mvn verify`
  stays with the integrator.
- In a cloud worker, `check-pack`/`test_check_pack` staleness with
  `git ls-files -v opencode.json` → `S` is an environment artifact; record it
  once and run the remaining gates individually.
