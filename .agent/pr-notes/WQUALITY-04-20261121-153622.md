# WQUALITY-04 — Frontend dependency scanning in the frontend check

## Summary

Added an npm production-dependency audit to `scripts/frontend-check.sh` and a
synthetic, stub-driven Python test suite. Both frontend modules
(`apps/staff-web`, `apps/patient-mobile`) now run
`npm audit --omit=dev --audit-level=high` as a gating step; a second, warning-only
full audit detects development-only findings. Registry/npm failures are reported
as `INFRASTRUCTURE` failures (never passes). The only bypass is the exact value
`FRONTEND_AUDIT=skip`, which prints a loud notice. No `package.json`, lock file,
workflow or tracker was changed.

## Findings

1. **F1 — KNOWN WORKER ARTIFACT, not a defect of this change.** In this worker
   checkout `git ls-files -v opencode.json` reports flag `S` (skip-worktree):
   the worktree file is byte-identical to `.github/opencode.ci.json`, while
   `git show HEAD:opencode.json` is the committed local profile. Therefore
   `check-pack.py`, `gen-opencode.py --check`, `bash scripts/check.sh` and the
   three `test_check_pack.py` cases fail on the CI profile. Proven pre-existing:
   a clean `git worktree add --detach … HEAD` runs `test_check_pack.py` 9/9 OK
   because it checks out the committed local profile. This is OPS-CW-003-01 /
   IMP-01 and the newest daily note's lesson; I did not regenerate or edit
   `opencode.json` (out of scope, protected file). Evidence source: executed
   tool commands.
2. **F2 — story/design ambiguity resolved, no owner decision needed.** The
   story's fixed command `npm audit --omit=dev` excludes dev dependencies, so
   it cannot produce a "dev-only finding warns" case on its own. All three
   specialist reviewers independently recommended the same resolution: keep
   the specified command as the only gating audit, and add a second,
   warning-only `npm audit --audit-level=high` (no `--omit=dev`) to detect
   dev-only high/critical findings. Implemented exactly that; the full audit
   never sets `fail`.
3. **F3 — reviewer hardening applied.** DevSecOps and the shell reviewer
   recommended classifying an unusable npm binary (exit 126/127) as
   infrastructure and checking error signatures before severity. Added the
   `audit_is_infrastructure` helper (status >= 126 OR error regex) and tests
   for exit 126 (`test_unusable_npm_binary_is_infrastructure`) and `ENOLOCK`
   (`test_missing_lockfile_is_infrastructure`). The regex also covers
   `ENOAUDITENDPOINT`, `ECONNREFUSED`, `command not found` and `npm ERR!`.
4. **F4 — accepted residual risk (fail-closed, no pass-through).** npm audit's
   human-readable output is classified by exit code plus error signatures, not
   parsed JSON. An unrecognised outage is still a non-zero exit, so it is
   reported as `FAIL` (a failure, not a pass); recognised registry/CLI failures
   are labelled `INFRASTRUCTURE` as the story requires. Raw npm output is
   echoed on failure paths for diagnosability; it contains no credentials or
   PHI. Switching to `--json` parsing would deviate from the story's exact
   command and add a Python parser dependency, so it was not done.
5. **F5 — environment note.** Real `npm audit` on `apps/patient-mobile` reports
   3 moderate production findings (`minimatch` via `expo`), which correctly exit
   0 under `--audit-level=high`. No dependency or lock file was changed;
   remediation is a separate story. Real staff-web audit is clean.
6. No reproducible product defect was found; nothing was added to BUGS.md.
   No observation came from a simulated user or a human participant.

## Lessons for workers

- In this worker image the worktree `opencode.json` is the CI profile under
  `skip-worktree`; the three `test_check_pack` failures and `check-pack.py`
  staleness are that artifact, not your change. Verify with
  `git ls-files -v opencode.json` and a clean worktree at HEAD; never regenerate
  it from a worker.
- When a story names an exact audit command but also asks for dev-only warnings,
  two calls are the honest design: the named command gates, a warning-only full
  audit informs. A stub token that real npm never emits is a false-green test.
- Under `set -euo pipefail`, capture a failing command with
  `out=$(cmd 2>&1) || status=$?` in the parent shell; assignments inside a
  `( subshell ) || fail=1` never propagate. Use `${FRONTEND_AUDIT:-}` so an
  unset variable cannot abort the script.
- Isolate script tests from a dirty parallel-worker tree by copying the script
  into a temp mini-repo with fake modules and a stub executable on `PATH`;
  assert on the stub's invocation log to prove every branch ran.
- `--no-audit` in `npm ci` contains the substring "audit": match audit
  invocations with an anchored log-line comparison, not `assertIn("audit", …)`.
