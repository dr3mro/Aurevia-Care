# SPEC-IAM-02-C02 — API test: record who granted each role and its effective dates

## Summary

Adds a real-PostgreSQL acceptance test for IAM-02 clause 2 and a clause-evidence
document. The clause is already implemented in production code, so no production
code, contract or migration was changed. The test proves that a role grant's
granter and effective-date window are recorded and readable through the HTTP
entry point, and that cross-tenant, wrong-role, malformed and mutation attempts
are refused. Synthetic data only.

## Findings

1. **Clause is fully built.** Source survey found the implementation in
   `apps/api/src/main/java/com/aurevia/authz/history/`:
   `RoleHistoryController` (`GET /api/v1/authz/role-history/{subject}`),
   `RoleHistoryService` (tenant-admin gate, audit, 404 concealment),
   `RoleHistoryStore` / `JdbcRoleHistoryStore` (RLS-bounded reads from
   `public.role_change_history`), `RoleHistory` and its nested `RoleChange`
   (`actor`, `effectiveFrom`, `effectiveTo`). Who-granted is captured by
   `db/migrations/V71__build_02.sql` `capture_role_change()` from `granted_by`

## Lessons for workers

- To seed a role grant with a specific granter, set **both** `app.actor` and
  `app.grantor_subject` to that subject. Clearing `app.actor` fails V70's
  `set_granted_by_from_actor()` with "role grantor must be an authenticated user
  of the active tenant"; `app.grantor_subject` exists precisely for the invite
  case where actor and grantor differ.
- For clause-evidence tests, give each test its own disposable database name.
  Parallel swarm workers otherwise drop each other's fixtures in `@BeforeAll`.
- Compare `timestamptz` values with `= '<iso>'::timestamptz` in SQL rather than
  asserting on `::text` substrings, which are sensitive to the server time zone.
