# AUD-20261121-27 — CHANNEL regex unification: BLOCKED at the scope check

No production or test code was changed. This story's own "Expected fix" requires a new
file in `api/contract`, which is outside every one of its four declared scope prefixes.
AGENTS.md (rules for agents, item 3) and the worker prompt ("Stay inside the task scope")
make the TODO.md scope binding, so I stopped before writing any test or production file.

## Summary

The audit finding is real and was confirmed by tool evidence: the same field rule
`Pattern.compile("[A-Z][A-Z0-9_]{1,31}")` under the field name `CHANNEL` is declared
exactly twice in `src/main`:

- `apps/api/src/main/java/com/aurevia/smartclinic/prescription/rx/RxInputs.java:20`
- `apps/api/src/main/java/com/aurevia/smartclinic/exchange/critical/CriticalInputs.java:23`

Both are enum-like channel codes validated at the request boundary (`RxInputs.channel`
and `CriticalInputs.channel`), each raising a field-specific `422 INVALID_*` via
`ApiException`. The audit is correct that a change to the shared rule would have to be
made twice and could drift between the prescription and critical-result endpoints.

The story's expected fix is "add one typed channel primitive in `api/contract`, delegate
both callers to it, and add canonical/lowercase/max-length/Arabic-RTL tests in each
module." The typed primitive is the load-bearing part: both callers must delegate to the
*one* primitive, and `api/contract` is the only package both domains may import without
introducing cross-domain coupling (RxInputs already imports
`com.aurevia.smartclinic.api.contract.CanonicalUuid`).

That location is not in scope. `api/contract` resolves to
`apps/api/src/main/java/com/aurevia/smartclinic/api/contract` (and its test to
`apps/api/src/test/java/com/aurevia/smartclinic/api/contract`), a sibling of
`prescription/rx` and `exchange/critical`, matched by none of the four scope prefixes.

## Findings

- **Scope conflict (blocking).** AUD-20261121-27 scope (TODO.md line 362) is
  `apps/api/src/main/java/com/aurevia/smartclinic/prescription/rx`,
  `apps/api/src/main/java/com/aurevia/smartclinic/exchange/critical`,
  `apps/api/src/test/java/com/aurevia/smartclinic/prescription` and
  `apps/api/src/test/java/com/aurevia/smartclinic/exchange`. The description (line 364)
  requires "one typed channel primitive in `api/contract`". `api/contract` is a sibling
  directory matched by none of the four prefixes (tool-verified `NO-MATCH` above), so
  AGENTS.md rule 3 forbids writing it under this task.
- **No in-scope home for a shared primitive.** The two callers live in two different
  top-level domains and neither imports a type from the other. Defining the primitive in
  one domain package and importing it from the other would invert a domain boundary; it
  would also create a competing primitive to the one AUD-26-style follow-ups will add to
  `api/contract`. Rejected deliberately.
- **Direct precedent.** AUD-20261121-26 (same audit run, same generator, same broken
  "primitive in api/contract" expected fix with scope omitting it) was blocked at the scope
  check with no production change and filed a task-request. Its resolution was a separate,
  correctly-scoped task AUD-20261121-21 whose scope includes `api/contract` (still `[ ]`).
- **No duplicate covers CHANNEL.** `grep` of TODO.md for `channel`/`CHANNEL` found only
  this AUD-20261121-27 entry for the duplicated regex; the other hits are BUILD/UAT/spec
  clause tasks about channel *behaviour*, not the CHANNEL validation primitive. A new
  correctly-scoped task is therefore required; see `task-requests` below.
- **Minor drift, no impact:** the story cites `RxInputs.java:21`; the live file has the
  declaration at line 20 (line 21 is blank). The finding itself is confirmed.
- No defect was introduced by this run; the duplication remains open and is captured in
  the task-request.

## Lessons for workers

- Before starting an audit (`AUD-`) story, `grep TODO.md` for its regex or title: the daily
  audit can emit a task whose "Expected fix" names a directory its `scope` does not contain.
  A broken scope means stop and hand off, not improvise an in-scope substitute.
- Treat the authoritative TODO.md `scope` as binding over the narrative "Expected fix";
  the story text is a description, not permission to override AGENTS.md rule 3.
- A shared typed primitive must live in a package both callers may import. Placing it in
  `prescription/rx` or `exchange/critical` to satisfy a narrow scope creates the
  cross-domain coupling the unification is meant to remove, and risks a competing primitive.
- When a story's fix requires a location no task covers, file a `task-requests` block in
  the notes rather than editing `tasks/` or `TODO.md`.
