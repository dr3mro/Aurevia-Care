# BUILD-22 · Backup and restore drill script with a checksum report

Task: BUILD-22

## Summary

Added an OPS-04 backup/restore drill under the new business-named
`infra/recovery/` directory. `restore_drill.py` finds the latest backup from a
catalog (ordered by parsed instant), restores it into a scratch database through
an injectable command runner after an explicit `--confirm-scratch`, probes row
counts and checksums, compares them against a recorded source snapshot, writes a
dated, exclusively created Markdown report and exits non-zero on any mismatch.
The reconciliation core is database-independent: a rehearsal supplies two JSON
snapshot fixtures and never contacts a database. Every report is labelled with
its `Kind` and a rehearsal carries an explicit "NOT a conducted drill" line;
no DSN is persisted and command failures are sanitised. All bundled data is
synthetic.

## Affected requirements

- OPS-04 (RPO ≤ 15 min, RTO ≤ 4 h; restore database, objects and IdP
  dependencies into a clean environment; reconcile hashes, source versions,
  in-flight deliveries and audit coverage before reopening writes; verify

  reconciliation automation and the dated evidence envelope, not the restore
  approval or the measured RPO/RTO.
- Cross-reference only: the four recovery scope classes (`core_chart`,
  `order_data`, `documents`, `document_associations`) from the
  [recovery runbook](../../docs/operations/recovery/runbook.md) (READY-54).
  No new threshold, requirement ID or approval path was introduced.

## Clinical and architecture review

Simulated specialist review only (no human participant). The drill covers the
OPS-04 R1 hash/row-count reconciliation and produces the dated report envelope
that the READY-54 runbook/evidence template expects. It does not claim the R2–R5
gates, a restore actually happened, measured RPO/RTO, or G5 acceptance. A real
conducted drill and human sign-off remain a separate gate.

Three bounded read-only specialist reviews were run (tool/reviewer evidence,
not human review). All findings were accepted and fixed in this change:

| Reviewer | Finding | Disposition |
|---|---|---|
| DevSecOps | Rehearsal report indistinguishable from a conducted drill | Fixed: `Kind` + explicit rehearsal marker in every report; asserted in unit tests and `check.sh`. |
| DevSecOps | Scratch DSN persisted in report | Fixed: conducted report names only the backup label; test asserts a DSN marker never appears. |
| DevSecOps / Senior Shell | Destructive `dropdb` with no isolation guard | Fixed: `--confirm-scratch` required before any command; negative test proves zero commands run without it. |
| Senior Shell | `CalledProcessError` escaped as exit 1 and leaked the DSN | Fixed: `SubprocessRunner` converts it to `DrillError` with command name/status only; `main` returns 2; tests assert no DSN in stderr. |
| Senior Shell | Rehearsal and conducted options not exclusive | Fixed: argparse mutually exclusive required group plus rejection of stray conducted-only flags; two tests. |
| Senior Shell | Dated report could be overwritten | Fixed: `open("x")` exclusive creation; refusal test added. |
| Senior Shell | `latest_backup` ordered raw timestamp text | Fixed: compare parsed instants, tie by label; offset-ordering and malformed-time tests added. |
| Senior Shell | `--now` offset mislabelled as UTC; `Z` replaced anywhere | Fixed: trailing-`Z`-only handling, naive rejection, UTC normalisation; two tests. |
| Senior Shell | `check.sh` accepted any nonzero exit | Fixed: exact status 1 asserted; stderr surfaced on unexpected status. |
| Test Engineer | `load_backup`/`load_snapshot` leaked `TypeError`/`AttributeError` as exit 1 | Fixed: widened handlers; wrong-container and non-object-manifest tests added. |

## Lessons for workers

- For a Python tooling module in `infra/`, the build-failing 100% line gate is
  the stdlib-`trace` `coverage_gate.py` pattern; branch coverage is proven by a
  named test per branch, because `coverage.py` is unavailable here.
- A `RecordingRunner` that only returns canned stdout for `psql` calls (not for
  `dropdb`/`createdb`/`pg_restore`) keeps conducted-mode tests deterministic.
- In this worker `opencode.json` is skip-worktree with the CI profile: a red
  `check-pack.py`/`test_check_pack` is a measurement artifact, not a reason to
  regenerate a protected file.
- Reuse an existing domain folder name only after checking the tracker for a
  pending rename that could collide; hand the reconciliation to the integrator.
