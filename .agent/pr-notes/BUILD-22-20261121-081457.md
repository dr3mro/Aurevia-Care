# BUILD-22 · Backup and restore drill script with a checksum report

Task: BUILD-22

## Summary

Added an OPS-04 backup/restore drill under the new business-named
`infra/recovery/` directory. `restore_drill.py` finds the latest backup from a
catalog, restores it into a scratch database through an injectable command
runner, probes row counts and checksums, compares them against a recorded source
snapshot, writes a dated Markdown report and exits non-zero on any mismatch.
The reconciliation core is database-independent: a rehearsal supplies two JSON
snapshot fixtures and never contacts a database. All bundled data is synthetic.

## Affected requirements

- OPS-04 (RPO ≤ 15 min, RTO ≤ 4 h; restore database, objects and IdP

  reconciliation automation and the dated evidence envelope, not the restore

  `order_data`, `documents`, `document_associations`) from the

  No new threshold, requirement ID or approval path was introduced.

## Lessons for workers

- For a Python tooling module in `infra/`, the build-failing 100% line gate is
  the stdlib-`trace` `coverage_gate.py` pattern; branch coverage is proven by a
  named test per branch, because `coverage.py` is unavailable here.
- A `RecordingRunner` that only returns canned stdout for `psql` calls (not for
  `dropdb`/`createdb`/`pg_restore`) keeps conducted-mode tests deterministic.
- In this worker `opencode.json` is skip-worktree with the CI profile: a red
  `check-pack.py`/`test_check_pack` is a measurement artifact, not a reason to
  regenerate a protected file.
- Reuse an existing domain folder name only after checking the tracker for a
  pending rename that could collide; hand the reconciliation to the integrator.
