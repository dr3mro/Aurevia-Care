## Findings

1. **Confirmed from committed source (not just earlier notes): the `needs-fix` label is a
   self-perpetuating automation loop that no fix worker can break.** I read `scripts/swarm.py` in
   this pass: `fail()` adds `needs-fix` and a `fix-N` label (line 2412); the issue-monitor requeue
   re-adds it (line 981); `pr_flow()` (line 3009, `if "needs-fix" in labels: wants_wave = True;
   continue`) keeps dispatching waves and never requests a fresh Delivery run for the new head;
   `plan_integration()` (line 2569, `blocked = {"needs-fix", "needs-human", "needs-debug"}`) excludes
   the PR; the fix-worker `publish()` branch (lines 2101-2106) only posts
   "Worker … pushed a fix … The integrator will retest" and calls `gh pr ready` — it never removes
   `needs-fix`. The only in-code clears are `send_to_debugger()` (line 2925) and the `needs-human`
   terminal branch of `fail()` (line 2424), neither of which applies to a green fix. Because the
   integrator never re-runs a needs-fix PR, `fail()` is not called again, the `fix-N` attempt count
   does not advance, and the PR is never escalated to `needs-human` either: it loops indefinitely.
   Clearing the label, or making a successful fix publish clear it and `pr_flow` re-evaluate the
   green head, is a maintainer/owner action on protected tooling this worker may not edit.
2. **The BUILD-23 code fix itself is complete and correct.** Independently reproduced in this pass:
   byte equality (sha256 `94d0d9ac…`), exactly one non-stale baseline line, all 60 targeted tests
   green, parity green, all fast policy checks green, both frontend checks green with no
   `error TS…`, and 100% JaCoCo on all four touched production classes. Earlier "re-run in-scope
   tests and call the rest pre-existing" passes were right about the code; this pass adds fresh
   proof and the concrete label-loop code path.
3. **Declared-scope mismatch remains (real hand-off issue, not a code defect).** The inherited fix

## Lessons for workers

- When a green fix PR is repeatedly returned, confirm the blocker's exact code path once, then stop:
  a repeated verification-only note does not move a PR blocked by a label outside worker scope. The
  concrete path is `scripts/swarm.py`: `fail()` → `needs-fix`/`fix-N`; `pr_flow`/`plan_integration`
  skip it; fix `publish()` only comments and undrafts; no successful-fix clear exists.
- Reset `apps/api/target/jacoco.exec` before the coverage batch and include `BrowserSessionHttpTest`.
  `OpenApiContractController` has no JaCoCo BRANCH counter — a parser that assumes one will crash;
  guard for a missing counter.
- The frontend definition of done is mandatory even on a data-only backend pass: run both
  `check.sh` scripts, paste the `tsc --noEmit` final lines, and treat any `error TS…` as a hard stop.
- `contracts/openapi/missing-routes.txt` is outside BUILD-23's scope; adding a line there is
  required for parity but would be flagged by a strict `worker_gate.py`. The integrator does not run
  that gate, but the scope still needs an owner decision.
- `git grep '^(<<<<<<<|>>>>>>>) '` can surface markers from other stories' merges that are already
  in `origin/main`; check whether they are in scope and in HEAD before treating them as your own
  merge damage.
- In this worker image, `opencode.json` is under `skip-worktree` with CI bytes. For `check-pack.py`
  and `test_check_pack`, temporarily write `git show HEAD:opencode.json`, then restore the exact CI
  bytes and reconfirm the sha256; do not commit or leave the HEAD bytes in the worktree.
