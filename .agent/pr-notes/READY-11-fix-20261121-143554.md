2. **Local `opencode.json` is a `skip-worktree` CI profile (re-confirmed this pass).** `git ls-files -v opencode.json` = `S`; the worktree copy hashed `50005c9…` while HEAD and the freshly generated file both hash `0dc2ac8…`. `python3 -I scripts/gen-opencode.py` regenerated it, `--check` then exited 0 and `git status` stayed clean. This is a local artifact, not a HEAD defect; it makes `quick-check.sh`/`check-pack.py` fail on first invocation in a fresh worktree until regenerated.
3. **LOW, pre-existing, not introduced:** `SecurityConfiguration.isBearerRequest` uses case-sensitive `startsWith("Bearer ")`. RFC 7235 auth-schemes are case-insensitive, so a client sending `bearer …` falls into the browser chain. Deliberately **not** changed: making it case-insensitive would widen the set of requests exempt from CSRF, and the helper is shared with the AUD-20261120-03 chain, so it needs a dedicated security-reviewed story with tests touching both matchers — not a silent edit inside a verification re-dispatch.
4. **Pre-existing, out of scope (WEB-05):** both non-synthetic chains use `anyRequest().authenticated()`, so `GET /health/live` and `/health/ready` require a credential outside `synthetic-auth`. WEB-05 needs these unauthenticated; belongs to a health-lifecycle story, not READY-11.
5. **`scripts/check.sh` intentionally not run:** it calls `apps/api/check.sh` → `mvn verify` (OWASP, JaCoCo gate, all PostgreSQL integration tests), reserved for the integrator and over the 5-minute worker limit. Component gates were run instead; the integrator runs the full gate and DB checks.
