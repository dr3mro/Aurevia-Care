# SPEC-XCH-02-C02 — XCH-02 clause 2 (API test)

## Summary

Add one synthetic, database-free API clause test and one clause document proving that
XCH-02 clinical-review acknowledgment is made by an authorized human and bound to a
timestamp and the exact reviewed revision. No production code, contract, migration or
existing test is changed. The rule is already built and already proven end-to-end at
the HTTP + PostgreSQL layer; this story adds a focused service-level clause proof with
explicit negative cases.

## Lessons for workers

- When a denial path legitimately writes a DENIED audit row, do not hide a blanket
  `verify(audit, never()).append(...)` inside a shared "no write" helper — split
  state-write and audit assertions so the denial audit is asserted explicitly
  instead of being contradicted by the helper.
- A database-free service snapshot deliberately nulls `reviewedBy` because V20
  derives the actor from the transaction context. Never claim such a test proves
  human identity; attribute that element to the existing HTTP + PostgreSQL
  integration test and keep the service test to authorization, timestamp and
  revision.
- For a proof-only clause story with no production change, the test is green on
  its final run. Do not fabricate a red-to-green cycle; record the first run's
  harness failure honestly and fix the assertion, not the production code.
- On this worker image, `check-pack` "opencode.json is stale", missing `coverage`
  and missing pre-run `surefire-reports` are environment artifacts. Confirm once
  with `git ls-files -v opencode.json` / `git show HEAD:opencode.json`, then run
  the remaining `worker-check.sh` stages individually; never regenerate the
  skip-worktree file or re-diagnose the same artifact on a later pass.
