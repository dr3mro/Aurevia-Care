## Lessons for workers

- Re-read the existing scoped file and the prior notes before changing anything: a "fix"
  dispatch can arrive when the story file is already complete and green; in that case
  re-verify, record the evidence and commit the notes rather than manufacturing a diff.
- Distinguish story gates from repo-wide gates: `bash apps/staff-web/check.sh`,
  `scripts/frontend-typecheck-check.sh` and `scripts/coverage-check.sh` are the story's
  applicable gates and are green; a red repo-root `scripts/check.sh` caused by a
  pre-existing shellcheck finding in protected `scripts/` is not a reason to edit scripts
  or workflows from a scoped worker.
- In a cloud worker, `git ls-files -v opencode.json` showing `S` explains a stale-pack
  result; record it as an environment artifact instead of regenerating protected config.
- Locate message bundles by searching for `en:` / `ar:` records under `src`, not only by
  file name: `app/navigation.ts` and `app/shellText.ts` are real bundles a name-only search
  misses.
- Three feature bundles keep their records private; reconstruct the bundle from their
  exported `keys` and `*Text` accessor rather than trying to import the record.
- For "contains an Arabic letter", use explicit Arabic letter ranges, not the whole
  `0600–06FF` block, which also matches digits and punctuation.
