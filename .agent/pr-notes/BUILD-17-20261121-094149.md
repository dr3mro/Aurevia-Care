## Summary

BUILD-17 (ADM-02). Added two tenant-scoped **operational queue queries** as pure domain projections, plus one shared immutable work-item model with `assign` and `resolve` actions that both require a reason and name an owner for assignment:

- `clinical/queues/UnsignedEncounterQueue.query` derives `unsigned_encounters` items from real `ClinicalNoteRevision` facts. An encounter is open while it has an editable draft and no signature-bearing revision, so signing it removes the item without a queue write.
- `config/rosters/MissingCoverageQueue.query` derives `missing_coverage` items from coverage roster facts that lack a named owner or backup.
- `config/queues/OperationalQueueItem` carries `organizationId`, id, queue, created time, state, owner, reason and a frozen action history; actions return a new item and never mutate the original.
- `config/queues/QueueAction`, `OperationalWorkState`, `clinical/queues/EncounterNoteFact` and `config/rosters/CoverageRosterFact` are small immutable supporting types. Names are business-domain names, no story/task/requirement IDs in folders, packages or classes.

All fixtures use synthetic UUIDs, synthetic subjects and synthetic timestamps; no patient data, credential or real domain name.

## Affected requirements

**ADM-02** (operational queues: unsigned encounters and missing coverage; authorized operators assign, resolve, retry or escalate with reason). Supporting: CLN-05 (`NoteState` signs/attestations reused, not duplicated), ADM-01 (coverage rosters), XCH-05 (missing coverage origin), ARC-01/ARC-02 (tenant-owned keys and isolation), OPS-02 (reasoned, attributable operator actions). Queue vocabulary matches `docs/operations/s_g5_11/queue-catalog.md` (`unsigned_encounters`, `missing_coverage`, states `open`/`assigned`/`resolved`, action verbs `assign`/`resolve`).

## Authorization boundaries and audit events

Every fact and every returned item carries an `organizationId`; both queries filter on the active tenant and copy that id onto the item, so identical local encounter/unit ids in two tenants never merge. The work item records the acting `actor`, owner and reason, but this domain model does **not** enforce the ADM-02 operator allowlist (`tenant_admin`, `privacy_auditor`, `operator`) or attach an `audit_id`: there is no operator registry, audit appender or command boundary in the scoped paths. Those checks must be enforced by the future command/controller boundary before live enablement. No audit event was added or changed; no clinical payload is logged or returned by these types.

## Clinical and architecture review

No clinical decision, release, prescribing or critical-result action is taken by this slice; the unsigned-encounter query reads only the already-existing `NoteState` lifecycle and no patient field. CLN-05 semantics are reused through `NoteState.editable()` and `signatureBearing()`, with synthetic tests proving that a signed encounter, an amendment draft beside a signed original and an addendum-bearing encounter all leave the queue. Reviews were simulated/read-only; no human clinician or operator acceptance is claimed. The architecture boundary is deliberately narrow: this is a pure domain projection inside `clinical`/`config`, not a new module or cross-module contract.

## Findings

1. **Scope conflict with the end-to-end definition (needs integrator/owner decision).** AGENTS.md's "done means working end to end" requires a Flyway migration with RLS, a `Jdbc*` store, an injected controller, an HTTP-level integration test and an OpenAPI entry. This story reserves no migration version and its `scope` names only `clinical` and `config` main/test directories, so none of those can be added. The scoped slice is complete and 100% covered, but it is **not** reachable from an HTTP entry point and does not survive a restart. I did not mark TODO.md (swarm worker) and recommend this story stay open or get a follow-up story for persistence/wiring.
2. **No durable operator actions or audit references.** Work items are re-derived, and `assign`/`resolve` return immutable values; nothing persists the assignment, reason or actor. ADM-02's `audit_id` per action and the operator allowlist are intentionally absent because no audit/operator boundary is in scope. A follow-up must add them before live enablement.
3. **Partial ADM-02 action/state set.** The authoritative catalog also defines `escalated`, `escalate` and `retry`. The task asks specifically for "assign, resolve and reason" on these two queues, so `escalate`/`retry` and the other five queues are deferred, not silently claimed.
4. **Declared assumption needing a site ruling:** suppression is encounter-wide. Any signature-bearing revision (`SIGNED` or `ADDENDUM`) removes the encounter even if a newer `AMENDMENT_DRAFT` is unsigned. This follows the explicit "signed encounter leaves the queue" acceptance criterion but is narrower than a per-note reading of `docs/operations/s_g5_11/queue-catalog.md:16` ("encounters with a draft that has not been signed"). It is documented in `UnsignedEncounterQueue`'s Javadoc and covered by `anAmendmentDraftWithASignedOriginalLeavesTheQueue` and `aSignatureBearingAddendumAlsoRemovesTheEncounter`. The independent reviewer asked for this to be explicit rather than silently treated as a spec literal.
5. **Tooling artifact, not a defect.** `opencode.json` is a skip-worktree CI-profile overlay in this worker; `check-pack.py` and three `test_check_pack` cases fail until the committed HEAD file is temporarily restored. Known issue `OPS-CW-003-01` / MEMORY `IMP-01`; no file was changed.
6. No reproducible product defect was found, so BUGS.md was not edited (also a protected tracker for swarm workers).

## Lessons for workers

- Survey the domain before adding a type: `NoteState.editable()` and `signatureBearing()` already encode CLN-05 signature semantics, so the unsigned-encounter queue is a short projection instead of a duplicated state machine.
- With a narrow scope and no migration, a pure immutable projection with static queries is preferable to an in-memory holder in `src/main`: it avoids new `InMemory*`/`Service`/`Store` wiring findings, cannot leak across tenants, and is fully deterministic to test.
- Targeted `clean ... test jacoco:report` + reading `jacoco.csv` proves 0 missed counters per touched class without the forbidden full `verify`; JaCoCo counters are `missed/covered` (`0/22` is 100%).
- In a cloud worker, check `git ls-files -v opencode.json` first: flag `S` means the `check-pack` failure is a CI-profile measurement artifact. Restore the HEAD file under a `trap`, run the gate, restore the overlay, and never commit the protected file.
- `check-wiring.py` prints stale-baseline notes on a clean tree; those are not new findings and must not be "fixed" by editing the protected baseline.
- When the catalog wording and an explicit acceptance criterion can be read differently (here, encounter-wide vs per-note signing), implement the acceptance criterion, declare the interpretation in Javadoc and notes, and add a synthetic test that pins it rather than silently choosing.
- Root `.gitignore` ignores **any** directory named `coverage/` (JaCoCo output). A Java package named `config.coverage` is therefore untracked and cannot be committed; name the domain package `config.rosters` instead and check `git check-ignore -v <new file>` before staging a new package.
