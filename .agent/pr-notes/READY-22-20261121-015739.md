# READY-22 — Chart page `/patients/:id/chart` and note editor on the real API

Status: **complete** — all applicable gates green locally; no backend, contract, migration or dependency change. Synthetic data only; no patient data in URLs, logs, page titles or browser storage (draft text is component state only).

Evidence sources: **executed tool commands** (`read`/`grep`/`git`, `npm run typecheck`, Vitest, `bash apps/staff-web/check.sh`), **skill routing** (`smartclinic-delivery`, `smartclinic-senior-react`, `smartclinic-senior-typescript` loaded in full), **simulated reviewer** (advisory `smartclinic-senior-react` subagent read the finished slice and returned four findings; all four were addressed or explicitly disclosed below, with tests — the reviewer did not execute checks itself). No simulated-user, clinician, patient or human-participant evidence.

## Summary

Added two API-backed staff-web containers over the existing Java endpoints. `ChartPage` loads the patient and the longitudinal chart through `GET /api/v1/patients/{id}` and `GET /api/v1/chart/records/patients/{patientId}/entries`, supports an optional `nextCursor`, and renders the existing `LongitudinalChart` with patient name + opaque id. `NotePage` loads `GET /api/v1/clinical-notes/{id}`, uses the existing `NoteEditor`, saves with `If-Match`, and wires sign / sign-addendum / amend / entered-in-error with explicit confirmation. A 409/412 keeps typed text and shows `ConflictState` with Compare, Reload and Copy my changes. Both routes are registered lazily in `routes.tsx`. `domain.ts` and `fixtures.ts` were left untouched.

## Affected requirements

- **CLN-03** — longitudinal problems/allergies/medications/vitals mapped from `ChartEntry` with original code/text, source, verification, effective date and separated clinical/data-entry authors.
- **CLN-05** — draft save with `If-Match`, sign with attestation, amendment/addendum, entered-in-error banner, immutable signed revisions read-only in the existing editor.
- Also exercised: UX-01 (en/ar, RTL, mixed-script name), WEB-09 (loading/empty/error/forbidden/session-expired/conflict states), ARC-03 (tenant, correlation, idempotency and version metadata on descriptors).

## Authorization boundaries and audit events

- Every request descriptor carries the active organization from `useActiveOrganization()` through the shared `buildRequestDescriptor`; tenant derivation, authorization and audit remain server-side.
- Draft writes and all four note commands send `If-Match: <version>`; draft creation sends a fresh `Idempotency-Key` per user action. No client-side authorization decision or audit event was added.
- The opaque patient id is the only identifier placed in a route; the display name comes from the authenticated patient response and is rendered with `MixedScriptText`.

## Migration and rollout considerations

None. Routes are code-split lazy imports (`ChartPage` 1.47 KB gzip, `NotePage` 2.80 KB gzip — both far below the 250 KB WEB-08 budget). No feature flag is needed: both screens were already listed in `navigation.ts` as pending routes. Rollback is reverting the scoped commit.

Required before real-patient use and **not** granted here: a qualified clinician must review the CLN-05 sign/attestation and entered-in-error semantics shown to staff, and an architect must approve publishing the chart/note/patient command paths to `contracts/openapi.yaml` (see Finding 2). ## Findings

1. **Scope deviation (disclosed).** `apps/staff-web/tests/app/AppShell.test.tsx` is outside the declared scope. Its `route registry` test hardcodes the exact pattern list and necessarily fails once the two required routes are registered. I made the minimal expectation-only change (added the two patterns to both expected arrays), as READY-21 did for `/schedule`. No assertion weakened and no test skipped. The integrator/owner should confirm.
2. **API contract gap.** `ChartController`, `ClinicalNoteController` and `PatientController` implement all the required endpoints, but `contracts/openapi.yaml` / generated `openapi.d.ts` declare none of them. Like READY-21, `api.ts` builds descriptors locally with `buildRequestDescriptor` from a real contract path and substitutes only URL and method; tenant, correlation, idempotency and `If-Match` headers stay owned by the shared builder. `gen:api:check` is green (no drift). Publishing these paths belongs to a separate contract story.
3. **SOAP projection.** The API stores note `content` as one string while the existing domain/editor use four SOAP fields. The mapper places the string in `subjective` and serializes non-empty fields back with `\n\n` on save, so an unchanged note round-trips; structured SOAP is a future API/domain contract change.
4. **Attestation text.** The API has no attestation-template resource; the sign request requires the client to supply an attestation string. The confirmation shows the fixed bilingual statement from `messages.ts` as the text that will be recorded, and displays the `attestation` actually returned by the API after signing. A site-approved template belongs to configuration.
5. **No note list on the chart page.** The chart API returns entries only (no note ids and no `GET /api/v1/clinical-notes` list), so `ChartPage` renders the longitudinal chart and the note route is reached by id rather than from a chart-side note list. `ChartView` has no cursor today; an optional `nextCursor` is consumed defensively if a future API adds it.
6. **Display time zone.** `ChartEntry` has no facility time-zone field, so vital instants are labelled UTC (the existing `formatInstant` receives `'UTC'`). Facility-zone labelling needs an API projection change.
7. **In-app navigation guard (partial).** "Ask before leaving" is implemented as a `beforeunload` guard plus a visible `role="status"` warning while the draft is dirty, so the user is told there are unsaved changes. Client-side navigation through the shared `Link`/`navigate` never fires `beforeunload`, so leaving via the rail can still discard typed text without a prompt; intercepting it requires a navigation-guard contract in the shared router, outside this scope. The advisory reviewer rated this high; the residual gap is recorded here for the owning router story.
8. **Non-error console output.** Pre-existing tests intentionally render provider-missing consumers and a `'MARKER-NON-ERROR-VALUE'` value; the resulting stack traces in the Vitest log are not failures (all 446 tests pass).

## Review findings resolved (simulated `smartclinic-senior-react`)

1. **Failed command left a modal over the conflict/error view (high).** Fixed: `handleSign` and `handleEnteredInError` now close their confirmation in the `catch` before rendering the failure, so Compare/Reload/Copy or Retry is the active surface. Tests assert the dialog is gone and the recovery buttons are present.
2. **Shared `Dialog` traps every Tab on Cancel, making the required confirm action keyboard-unreachable (high).** Fixed without editing the shared component (out of scope): `NotePage` now uses a local in-flow `ConfirmationDialog` with native focus order — Cancel is focused first, and every control is Tab-reachable. Test asserts focus can sit on the confirm button and survives a document Tab keydown; jsdom cannot synthesize the browser's native Enter-to-click, so activation is asserted via a click on the focused native button.
3. **Client-side navigation bypasses the unsaved-changes guard (high).** Partially addressed: a dirty-draft warning is now rendered and the `beforeunload` guard remains; the router-level interception is outside scope and is disclosed in Finding 7 above.
4. **Signing while dirty silently certifies stale saved content (high).** Fixed: `onSign` refuses to open the confirmation while the draft is dirty and shows a bilingual "save before signing" status; the sign command therefore never presents screen text that was not saved. Test asserts no `/sign` call and no dialog while dirty.
5. Reviewer reported no patient data in URLs, storage, titles or logs, and confirmed message parity.

## Lessons for workers

- Registering any new route in `routes.tsx` breaks `tests/app/AppShell.test.tsx`'s hardcoded pattern list — update that expectation in the same change or reserve the file in scope.
- With per-file 100% function coverage, every mapper callback (including an array `.map` inside a `useEffect`) must be exercised; a test with a non-empty history is required even when the empty case renders fine.
- `RequestDescriptor.method` is typed `'GET' | 'POST'`; a local PUT descriptor must cast the method at the boundary until a contract story adds the path, and tests must compare with `(request.method as string) === 'PUT'`.
- Route both patient and command mocks by URL/method rather than call order: `useApi` refetches after every successful command, so ordered `mockResolvedValueOnce` queues run out and return the wrong shape.
- `getByText`/`findByText` on domain values can match several cells (the chart preserves original text and display text in separate columns); use `findAllByText` or scope with `within`.
- The shared `Dialog` placeholder traps every `Tab` on its close button. Never put a required confirmation action inside it; render an in-flow labelled confirmation with native focus order, or fix the shared component in its own story. 100% coverage does not catch this — assert focus reachability, not just DOM presence.
- A command that carries no content (sign, entered-in-error) must refuse to run while the editor is dirty, otherwise the user certifies the last saved revision rather than what is on screen.
