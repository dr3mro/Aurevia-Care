# BUILD-32 (fix pass) — Scheduling: recurrence templates and series booking

## Summary

Fix/verification pass for BUILD-32 (CLN-01). The implementation was already committed
on this branch in `28ba333` ("CLN-01 recurrence templates and atomic series booking");
no production defect was found in this pass and **no production code was changed**.
`SeriesRequest` accepts a fixed occurrence count **or** an inclusive local `endDate`.
`RecurrenceTemplate` expands occurrences from the facility IANA zone as civil dates
plus a local clock time, so a daylight-saving change keeps the local appointment time.
`AppointmentService.bookSeries` checks every occurrence for overlap on its protected
clinician/room resources inside one tenant-guarded transaction and rejects the entire
series with the complete clash list (`409 SERIES_CONFLICT`) before any row is written.
V86 stores the template, series and immutable occurrence index; editing one occurrence
keeps its `appointment_event` history and the original planned start.

This pass re-ran the targeted unit tests, the HTTP integration test, per-class JaCoCo
coverage, SpotBugs, the database policy check and the applicable policy checks, and
confirmed 100% coverage on every changed class. The prior worker's "Why this is not
finished" flag was not a real defect — it reflected the five-minute worker command cap
(the full `mvn verify` is reserved for the integrator/Delivery) and the known
`opencode.json` skip-worktree measurement artifact. Both are documented below.

## Data changes

`db/migrations/V86__recurrence_templates.sql` (reserved version V86, `Change: expand`):
three additive tables `recurrence_template`, `appointment_series`, `series_occurrence`.
Each has `organization_id`, a composite PK including it, `created_at`, ENABLE + FORCE
RLS and a policy `USING/WITH CHECK (organization_id = public.app_org())` (V86 lines
85-90). Append-only reject-mutation triggers for `UPDATE`, `DELETE` and `TRUNCATE`
cover every role including the migration owner (lines 101-105); SELECT/INSERT are granted
only to `orevia_app` and UPDATE/DELETE/TRUNCATE revoked (lines 110-112). No
backfill, no UPDATE of existing rows, no destructive DDL; brief ACCESS EXCLUSIVE locks
are bounded by table creation. Rollback is a forward-fix migration; no capability is
removed.

## Authorization boundaries and audit events

Authorization is re-checked inside the transaction with `APPOINTMENT_BOOK` via the
existing `AppointmentService.authorize` (active membership + role). Identifiers come
from synthetic `X-Synthetic-Subject` / `X-Active-Organization` (synthetic-auth profile)
and forced RLS; no caller-supplied organization, author or version. New audit event
`SERIES_BOOK` on success (scope `SCHEDULING`, resource `APPOINTMENT`); denials reuse the
existing `APPOINTMENT_BOOK/DENIED` audit. All fixtures are synthetic (ORG A/B share local
codes). No patient data, credentials or real identifiers used.

## Lessons for workers

- To reach 100% on a large touched class, run the full unit suite plus every integration
  test that exercises its pre-existing paths. A 3-class or even a 133-class unit subset
  leaves `AppointmentService`/`AppointmentRepository` branches uncovered; adding
  `SeriesHttpIntegrationTest`, `AppointmentListIntegrationTest` and especially
  `it/SchedulingBookingTest` closes the gap. Always re-read the JaCoCo XML and confirm
  `missed == 0` on each changed class before claiming 100%.
- JaCoCo counters print as `missed/total`, not `covered/total`; a line like `1/4` is a
  MISSED branch, not 25% coverage. Parse `mi`/`ci`/`mb`/`cb` directly to avoid this trap.
- `scripts/check-pack.py`/`test_check_pack.py` staleness under `skip-worktree` is a known
  false positive in this worker environment — verify with `git ls-files -v opencode.json`
  and `git show HEAD:opencode.json` before treating it as your defect.
- Integration tests in one class share a database; give each scenario distinct dates or
  an earlier successful series will make later ones fail with `SERIES_CONFLICT`.
- `AppointmentView` is nested (`{"appointment": {...}, "history": [...]}`); assert nested
  fields when checking reschedule history over HTTP.
