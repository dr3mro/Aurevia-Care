## Findings

- **Root cause (independently reproduced, tooling, not docs).** `scripts/worker_gate.py`
  `usable_reports()` calls `Path(reports_dir).glob("TEST-*.xml")` at line 63 on a
  path that may not exist. `main()` line 260 normally short-circuits on
  `reports.is_dir()`, but two unit tests patch `Path.is_dir` to `True`, so the scan
  runs on the absent default directory `apps/api/target/surefire-reports` and
  raises `FileNotFoundError` instead of returning a fail-closed verdict. Wrapping
  the scan in `try/except OSError: return False` is the bounded fix. This makes the
  Python unit suite — and therefore the worker's local gate — fail independently
  of this story's documentation.
- **Pre-existing and out of scope.** The two errors reproduce on clean
  `origin/main` with no `apps/api/target/surefire-reports` directory; the branch
  changes only Markdown files. `FIX-WORKER-REPORTS` (`tasks/00011000-FIX-WORKER-REPORTS.md`,
  PR #680) is already `[x]` and introduced `usable_reports()` without the
  missing-directory guard. Per AGENTS.md this unrelated tooling defect must be
  raised with an owner task, not folded into the S-G5-02 docs story; see the
  `task-requests` block below. No `scripts/` file was edited in this pass.
- **Environment false positive.** The six `test_check_pack` failures come from the

## Lessons for workers

- A documentation-only story cannot make a Python tooling bug green. When the
  debugger's root cause sits outside the declared scope, raise a `task-requests`
  entry and write `Why this is not finished` instead of expanding the diff into
  protected `scripts/`.
- Treat carried-forward debugger reports as evidence to reproduce, not as
  instructions that override the scope rule. The plan reviewer is right to reject
  a scoped violation even when the proposed fix is technically correct.
- In this worker image, record the OPS-CW-003-01 skip-worktree artifact once with
  `git ls-files -v`, worktree/HEAD md5s and the failing final line, then run the
  remaining gate stages individually; do not edit `opencode.json` or chase the
  same false positive again.
- Keep fenced `task-requests` blocks in their own section and keep angle-bracket
  placeholder text out of the required `Test evidence`, `Coverage` and `Why this
  is not finished` sections, because `worker_gate.has_placeholder()` scans them.
