# SPEC-XCH-07-C03 — Keep qualifiers, qualitative results and incompatible units visible (API test)

## Summary

Independent HTTP-level proof of SMARTCLINIC_V1_SPEC.md XCH-07 clause 3 against real PostgreSQL under enforced row-level security. Two new files only: a `@Tag("integration")` `RestClient` test and a clause-evidence document. No production code, migration, contract, client, tracker or protected file was changed. The clause is already fully implemented in production; this story adds proof and the clause record.

## Affected requirements

XCH-07 (clause 3 only): "Keep qualifiers such as less-than and greater-than, qualitative results and incompatible units visible without treating them as directly comparable measurements."

Acceptance mapping:

| Acceptance scenario | Test method |
|---|---|
| Qualified (`<`, `>`), qualitative and incompatible-unit results stay visible as exclusions and are never plotted | `qualifiedQualitativeAndIncompatibleResultsRemainVisibleButAreNotTrendedOverHttp` |
| Non-clinical role refused on read and write | `receptionCannotRecordOrReadTrendObservations` |
| Cross-tenant patient concealed | `clinicianOfAnotherTenantCannotReadThisPatientsTrend` |
| Unknown qualifier refused | `unknownQualifierIsRefused` |
| Qualified result without a numeric value refused | `qualifiedNumericWithoutAValueIsRefused` |

Cross-boundary for the evidence path (real HTTP + PostgreSQL + FORCE RLS + role/tenant boundaries), but **no production change**: routine verification effort with safety-relevant negative cases. doc/WORKFLOW.md: cross-boundary evidence, not a safety-critical production change.

No task-request is filed because this story does not depend on that gap.
- **Documented worker-image artifacts, not defects of this change:** (a) `opencode.json` is the CI runtime profile installed under `skip-worktree` (`S opencode.json`); the committed local profile in `HEAD` is correct, so `check-pack.py`, `gen-opencode.py --check`, 6 `test_check_pack` tests, `worker-check.sh` and `python-coverage.sh` fail on this artifact only. The integrator owns these gates. (b) The `coverage` Python module is not installed in this worker, so `python-coverage.sh` falls back to plain unittest and inherits the same artifact. (c) No local Docker, so image smoke stays in GitHub Actions.
- **No red phase was possible:** the clause is already fully implemented, and this story forbids production edits, so the tests are green from first run. Fault detection is by specific assertions on wire values, reasons and statuses (a wrong exclusion reason or a plotted qualified value would fail the rule-met test). This was accepted in the plan review.
- **Pre-existing committed conflict markers** are present inside Javadoc comments in `apps/api/src/main/java/com/aurevia/smartclinic/exchange/hl7/Hl7ParseException.java`, `Hl7Parser.java` and `Hl7Segment.java` (confirmed in `HEAD`); this change does not touch them. ## Lessons for workers

- For a proof-only story on already-built behavior, do not try to manufacture a red run or edit production: assert exact wire values/statuses and document that fault detection comes from those assertions, not from a red-to-green cycle.
- In a cloud worker, `S opencode.json` from `git ls-files -v` plus `git show HEAD:opencode.json` is sufficient evidence for the stale-pack false positive; record the failing final line once, run the remaining gate stages individually, and never regenerate or commit that file.
