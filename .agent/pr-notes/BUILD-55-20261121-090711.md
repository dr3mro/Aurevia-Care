# BUILD-55 — Patient app: Arabic, RTL and accessibility pass on every screen

## Summary

UX-01 pass over the patient app shell (`apps/patient-mobile/src/app`, the only permitted scope). Three defect classes were found and fixed with tests written first:

1. **Missing text language / control labels on Arabic screens.** `accessibilityLanguage` is now set on every localized text run and on every accessible control in `ScreenStack`, `SignedOutScreen` and all five `ScreenStateView` states. The locale travels with the already-localized `ScreenMessages` bundle, so no screen can forget it.
2. **Untranslated "Reference:" prefix and mixed-script identifier.** Added `referencePrefix` to both message bundles (`en: "Reference:"`, `ar: "المرجع:"`) and rendered the opaque correlation id in its own Latin text node (`accessibilityLanguage="en"`) in a mirroring `flexDirection: 'row'` run.
3. **Facility-zone dates were hard-coded to `en-GB` and showed a bare clock value.** `facilityZoneFormatter` now takes the active locale, renders day + month + time in the facility IANA zone and pins `numberingSystem: 'latn'`, so an Arabic screen shows `21 نوفمبر، 13:00` (Latin digits) rather than `13:00` or Arabic-Indic digits.

Added `accessibility.test.tsx` (a render per in-scope screen in both directions, complete key sets, labelled controls, language-tagged runs) and `rtlStyles.test.ts` (build-failing guard against physical margin/padding/border/inset/text-align properties and against shrinking clinical text).

No dependency, migration, contract or file outside `apps/patient-mobile/src/app` was changed.

## Findings

1. **Out-of-scope feature screens still have accessibility and localization gaps (not changed).** The four tabs render presentational screens under `src/features` (outside the declared scope). `AppointmentListScreen.tsx` renders `Pressable` controls ("Confirm", "View details", "Revoke device") without `accessibilityRole`/`accessibilityLabel` and hard-codes English text; `ReleasedReportsScreen.tsx`, `ConversationInbox.tsx`, `AttachmentReviewScreen.tsx`, `InstructionAcknowledgmentScreen.tsx` and `features/enrollment/screens.tsx` have similar fixed strings/labels. These are the owning feature stories' work; this worker changed no file outside `src/app` and did not claim those controls are covered by "every control is labelled". Next worker/owner: route a per-feature accessibility pass.
2. **`scripts/check.sh` opencode.json staleness is an environment artifact (verified, not introduced here).** `git ls-files -v opencode.json` → `S` (skip-worktree) and `git status --short` shows no change to it; the worktree CI profile differs from `git show HEAD:opencode.json`. The documented behaviour (MEMORY.md dispatch-3 entry) is that `agent-run.sh activate_ci_config` installs the CI profile under skip-worktree, so `gen-opencode.py --check`/`check-pack.py` judge that profile rather than HEAD truth. Per worker rule 8 I did not edit `opencode.json` or regenerate it; the trusted integrator/publisher owns the authoritative gate. The canonical module gate `bash apps/patient-mobile/check.sh` is green.
3. **Tab-button text language cannot be set from this scope.** React Navigation's `tabBarAccessibilityLabel` is a string-only option; there is no in-scope API to attach `accessibilityLanguage` to the bottom-tab accessible element. The tab labels are fully localized and labelled in both locales (asserted in `RootNavigator.test.tsx`); VoiceOver language for the tab chrome follows the device locale. A native pass must confirm this on device.
4. **No directional icons exist in the app shell.** The only new multi-node run uses `flexDirection: 'row'`, which mirrors under RTL; there is no back/forward chevron or other mirrorable glyph in `src/app` to flip. `rtlStyles.test.ts` guards against physical properties and bare `left`/`right` in all app-shell styles.
5. **Mixed script in scope was limited to the correlation id.** The id is now isolated in its own `accessibilityLanguage="en"` node with a localized prefix; longer mixed-script clinical free text lives in feature screens (Finding 1) and is out of scope.

## Lessons for workers

- In this pinned `@testing-library/react-native` v14, `view.UNSAFE_getAllByType` does not exist. Walk `view.toJSON()` recursively (as `accessibility.test.tsx` does) or use `getAllByRole` when you must inspect every host node.
- `toHaveTextContent('literal')` matches the exact whole string here; a container with a localized prefix plus an id needs `getByText(...)` or a `RegExp`.
- `Intl.DateTimeFormat('ar', { numberingSystem: 'latn', hour12: false, hour/minute })` produces the same digits as `en`. Include day and month to make the locale observable in a test — and because an appointments list should show the civil day, not a bare clock value.
- On native, put `accessibilityLanguage` on the accessible element (the `Pressable` carrying `accessibilityLabel`) as well as on the inner `Text`; otherwise VoiceOver reads the label in the device voice.
- In a cloud/swarm worker, a stale `opencode.json` from `scripts/check.sh` is usually the skip-worktree CI profile. Confirm with `git ls-files -v opencode.json` and `git status` before treating it as a change defect, and never regenerate a protected file from a worker.
- Keep the active locale inside the already-localized message/state bundle (here `ScreenMessages.locale`) when many child components need `accessibilityLanguage`; it avoids threading a new prop through every wrapper.
