## Decisions

- Plan review round 1 returned NO-GO with four Required gaps; all are addressed in the revised plan awaiting re-review: (a) an in-scope `realtime.ts` producer that opens the SSE stream with `fetch` + `ReadableStream` and descriptor headers (EventSource cannot send tenant headers), falls back to identifier-only polling with cursor resume, and feeds `MessengerPanel`; (b) attachment send is staged UI only because `InstantSendRequest` forbids extra fields and has no upload route — the explicit Send assertion checks the request body has exactly `facilityId`, `conversationId`, `body` and that no file bytes are transmitted; (c) branch-complete tests for `perFile: true` 100% coverage including every optional wire field and each connection/delivery/component branch; (d) a named `MESSENGER_VIEW_TIME_ZONE = 'UTC'` constant for deterministic day separators.
- Navigation/route wiring and real attachment upload are outside this task's scope; both will be recorded as findings with `task-requests` entries.

## Lessons for workers

- Read the generated contract schemas before designing a UI command: `InstantSendRequest` forbids extra fields, so "attachments" must be staged UI until an upload contract exists. Do not invent a wire field to satisfy a visual requirement.
- `EventSource` cannot send `X-Active-Organization` or `Last-Event-ID`; open the SSE endpoint with `fetch` and descriptor headers, and make the abort/reader cleanup observable in tests.
- A `role="status"` connection label changes faster than a synchronous `getByText` assertion; drive the fake stream and assert the `data-connection` attribute with `waitFor`.
- Fixture files are production source for coverage purposes: a `?? ''` fallback in `fixtures.ts` counts as a branch and must be exercised or replaced with a literal.
- The full staff-web suite contains a stale CI tripwire that fails on current `main`; check whether a failure touches your files before treating it as a defect of the change, and record the exact command and final line.
