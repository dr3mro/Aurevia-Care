# SPEC-ARC-03-C04 — ARC-03 clause 4 (API test): Require version preconditions for draft writes and irreversible transitions

## Summary

Added one HTTP-level integration test and one clause document. The test drives the
real `POST /api/v1/appointments/holds` draft and the irreversible
`POST /api/v1/appointments/{id}/confirm` command through production Spring wiring on
PostgreSQL with two synthetic tenants. It proves a matching version advances and
persists, a second confirm is refused, and missing, malformed, stale, wrong-role and
cross-tenant calls are refused without changing stored state. No production code,
existing test, contract, migration, script or tracker is changed.

## Findings

- First targeted run was red for a fixture reason, not a missing behavior: `AppointmentRepository.find(id)` returned empty because it has no `@Transactional` and the GUCs are set only by `TenantGuardTransactionManager` on transaction begin (the events exemplar's store wraps its own query in `transactions.execute`). Fixed by injecting the shared `TransactionTemplate` and wrapping the `as()` action in `transactions.execute(...)`; the peer-empty assertion is paired with a positive owner read so it is not vacuous. Plan-reviewer's Required finding is resolved.
- Fault injection (temporary, fully reverted) confirmed the new 428 assertion fails when the boundary guard is bypassed; no production code remains changed.
- Fixed 2027 Sunday slots match the neighbouring `StatesBookedCheckedProgressCompletedCancelledShowTest` convention and lie inside the current booking window; they become past after mid-2027. A future worker should replace them with computed successive Sundays if the suite is still running then.
- `python3 -I -m unittest discover -s scripts/tests` has six pre-existing `test_check_pack` failures in this cloud worker because `opencode.json` is a skip-worktree CI profile; confirmed once with `git ls-files -v` and checksums; no protected file was edited.
- No second scope path is needed; no task request is needed.

## Lessons for workers

- An RLS-bounded Spring `Jdbc*Repository` with no `@Transactional` returns empty outside a transaction even when `TenantContext` is set: always wrap direct reads in the shared `TransactionTemplate` (backed by `TenantGuardTransactionManager`) and pair a cross-tenant empty assertion with a positive owner read.
- A negative precondition test needs a valid `If-Match` when the service also authorizes: the web boundary parses the header before the service checks the role, so a missing header would mask the intended 403/404 with 428.
- In a test-only story there is no production red by construction; a controlled, reverted fault injection gives real red evidence without leaving a production diff.
- For documentation tasks and test-only Python gates here, `python3 -I scripts/check-docs.py` is authoritative; the `test_check_pack` failures from the skip-worktree `opencode.json` are an environmental false positive, so prove the remaining tests pass separately instead of editing protected files.
