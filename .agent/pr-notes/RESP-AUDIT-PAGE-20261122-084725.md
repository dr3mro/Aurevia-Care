# RESP-AUDIT-PAGE — Staff web: responsive `AuditPage` (features-admin)

## Summary

Made `AuditPage` responsive at every supported width (320–1280 px) in both LTR and RTL without changing behaviour, text, API calls or exported names. The page now uses the shared `page` grid (logical safe-area padding, single-column `minmax(0, 1fr)`), `stack`, `grid-2` and `cluster` classes from `apps/staff-web/src/theme/responsive.css` and reads the active band from `useBreakpoint`. Filter fields stack on phones and take two columns from the medium breakpoint; the filter section, clear action, event region and paging action all get wrapping room. Exposed `data-breakpoint`, `data-audit-page`, `data-audit-part` and `data-audit-fields` so structure can be asserted in jsdom. Added a new responsive test file mocking `matchMedia` for compact, medium and expanded, including an Arabic RTL case and a breakpoint-crossing resize. The test also asserts the relevant rules in the shared stylesheet as text (44px coarse target, 16px input, `.stack` wrapping, safe-area mapping, RTL inset mapping, logical-only properties), explicitly labelled as proxies — jsdom cannot paint pixels or evaluate media queries.

Entry point to test trace: route `/admin/audit` → `AuditPage` (`src/features/admin/AuditPage.tsx`) → `AuditContent` → `Form`/`ApiPage`/`AuditEventList` → assertions in `tests/responsive/features-admin/AuditPage.responsive.test.tsx` (structure, labels, roles, keyboard order, RTL) and the unchanged `src/features/admin/AuditPage.test.tsx` (query string, filters, paging, tenant key).

## Findings

- Pre-existing conflict markers (tool evidence, `git grep -nE '^(<<<<<<<|>>>>>>>) '`) remain in committed unrelated files: `apps/api/src/main/java/com/aurevia/smartclinic/exchange/hl7/{Hl7ParseException,Hl7Parser,Hl7Segment}.java`. They are in HEAD, outside this task's scope, and were not touched. They will break Java compilation/docs for whoever owns those files; flagged for the integrator.
- The RTL label `auditEvents` is used simultaneously by `ApiPage`'s `section.page`, `AuditEventList`'s `section` and `AdminTableRegion`'s `divrole=region`, so `getByRole('region', { name: ... })` is ambiguous. The new test uses `getAllByRole(...).length > 0` and text queries instead of changing a child component outside scope. A future story could give those regions distinct accessible names.
- jsdom cannot measure pixels, evaluate media queries or detect keyboard provenance. The tests assert classes/data attributes/DOM order only; painted sizing, 44×44 boxes, 200%-zoom reflow and safe-area padding remain Playwright/E2E evidence (`RESP-E2E-*` tasks), as `docs/design/responsive-layout.md` section 13 requires.
- `Form` and `FormField` (already responsive) own the 16px input text, `.touch` coarse target and sticky submit footer; `AuditEventList`/`AdminTableRegion` own the table region and row wrapping. `AuditPage` supplies the page grid and wrapping wrappers and does not duplicate those rules.
- Simulated `smartclinic-ux-reviewer` (read-only, no shell access, so it reviewed current file contents rather than the git diff) returned no functional or scope defect. Its evidence-quality findings were addressed:
  - F1/F2 — test names and comments overclaimed painted verification and three acceptance points had no local signal. Fixed by renaming the tests to "layout proxy"/"layout hooks", documenting that painted size/reflow/zoom stays with Playwright, and adding stylesheet-string assertions for the 44px coarse rule, 16px input rule, `.stack > *` wrapping, `.page` safe-area padding and `:root[dir='rtl']` inset mapping.
  - F3 — assertions on `Form`/`Button`/`I18nProvider` hooks belong to children. Fixed by renaming the describe block to "responsive AuditPage and its shared children" and adding a comment that those are integration checks, not AuditPage-owned rules.
  - F4 — nested `.page` on the root and on `Form` doubles the inline gutter (roughly two page paddings at 320 px). Child-driven, no clean fix inside this scope; passed through to a future `Form`/stylesheet story.
  - F5 — `data-audit-fields` mirrors the CSS breakpoint and `useBreakpoint` falls back to `expanded` without `matchMedia`, so the attribute can read `two-column` while CSS is single-column. Kept as an explicitly labelled jsdom proxy, not layout truth.

## Lessons for workers

- `responsive.css` has wrapping rules for `.app-shell > *`, `.cluster > *`, `.stack > *`, `.grid-2 > *` and `.card-list > *`, but **not** for `.page > *`. There is also no dedicated `.audit-filters` / `.audit-events` class. Rather than editing the stylesheet (out of scope), wrap page children in `stack`/`cluster`/`grid-2` and let those classes provide `min-inline-size: 0` and `overflow-wrap: anywhere`. Record the missing `.page > *` rule here for a future stylesheet story.
- `Form` only switches its own inner container to two columns when it counts more than six fields; the audit form has five. Put a `grid-2` div around the fields passed to `Form` to get stacking on phones and two columns from 768 px without changing `Form`.
- Nested `page` classes are expected here: `Form` and `ApiPage` each render their own `section.page`. Do not try to remove them from a page-level story.
- Reuse the `matchMedia` stub pattern from `tests/components/ApiPage.responsive.test.tsx` (one state object per query, `addEventListener`/`removeEventListener`) so `useBreakpoint` change listeners can be fired deterministically with `act()`.
- Child components already expose `data-breakpoint`; asserting a class on the child is enough — do not re-implement responsive behaviour in the parent.
- In a Vitest jsdom module, `import.meta.url` is not a `file:` URL, so `readFileSync(new URL(...))` fails with `ERR_INVALID_URL_SCHEME`. Use `dirname(fileURLToPath(import.meta.url))` with `join`, as `tests/theme/responsiveStylesheet.test.ts` and `tests/tooling.test.ts` do.
- When a test asserts CSS from the stylesheet text, account for grouped selectors: the wrapping rule is `.app-shell > *, .cluster > *, .stack > *, ... { ... }`, not a standalone `.stack > * { ... }` block.
