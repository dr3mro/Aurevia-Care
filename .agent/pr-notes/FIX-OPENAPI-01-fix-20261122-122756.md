## Lessons for workers

- Before re-implementing a fix story, run `git diff --stat origin/main..HEAD`. If
  the branch contains only notes files, the code work is already merged — repeating
  scoped re-verification cannot move a stale CI base and wastes the pass.
- A Fix PR gate failure that reproduces on an old `merge_commit_sha` but is green
  on a worktree containing the fix is a stale-base problem: the remedy is a
  trusted re-sync/re-push of the PR branch so GitHub recomputes the merge commit,
  not another file edit. The fix worker does not hold that capability.
- Confirm the `opencode.json` "stale" message is the CI-profile skip-worktree
  artifact (`git ls-files -v opencode.json` = `S`, `git show HEAD:opencode.json`)
  before treating `scripts/check.sh` as a real failure; it is OPS-CW-003-01.
- Keep the trusted steps' token usage intact. Only the agent conflict-resolve step
  must avoid the secret-named token; lines 45/74/197-206 of
  `.github/workflows/swarm-integrator.yml` are trusted fetch/push/warn steps and
  are intentionally unchanged.
- Do not edit trackers, workflows, scripts or `.opencode/` as a swarm fix worker;
  route durable lessons through notes so the reconciliation PR owns them.
