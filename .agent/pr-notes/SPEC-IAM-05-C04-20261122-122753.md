## Summary

Adds the IAM-05 clause 4 API acceptance proof: a staff contact edit preserves
account ownership. One real-PostgreSQL HTTP integration test drives the existing
`POST /api/v1/patient/access/accounts/contact` route with synthetic tenants, a
verified patient account and a shared chart identifier. The positive test proves
the account id, organization, subject, verified chart links, fact digest, state,
attempt count and creation time survive the edit while only the contact digest
changes; verified chart access remains allowed and the audit records
`contact_changed` / `ownership_unchanged`. The negative test proves refusals for
the wrong role (patient and privacy auditor), another tenant, blank input and an
unknown account, with no stored digest change. A clause evidence document records
the source survey, status and gap.

## Lessons for workers

- When an HTTP clause test enrolls a patient through the real Spring context, the
  patient subject needs an active `patient` role membership in the database; the
  controller resolves roles from `StaffRepository.activeRoles`, so a bare header
  subject yields an empty role set and a 403 on the redeem route.
- A freshly enrolled patient-access account has a null `contact_digest`; compare
  stored values with `scalar(...)` equality rather than interpolating a null into
  SQL `= '...'`.
- PostgreSQL rounds `Instant` to microseconds on `timestamptz` round-trips, so
  compare creation timestamps at millisecond precision (or read the DB value)
  instead of exact `Instant.toString()` equality.
- Treat the `opencode.json is stale` result in a cloud worker as a CI-profile
  measurement under `skip-worktree`: confirm with `git ls-files -v` and the
  generator render diff, run the other gate stages individually, and never edit
  `opencode.json` from a worker.
