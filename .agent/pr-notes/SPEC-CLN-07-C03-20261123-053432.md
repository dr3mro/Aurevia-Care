# SPEC-CLN-07-C03 — Image rotation is presentation metadata (CLN-07 clause 3)

## Summary

Test-only acceptance proof for CLN-07 clause 3. A new real-PostgreSQL HTTP integration
test proves that a bounded quarter turn is retained as `rotation_degrees` metadata,
that the synthetic original PNG bytes and their database-derived SHA-256 are never
mutated, and that rendering emits the turn as a PDF `/Rotate` page directive on a new
immutable revision. A clause note records the survey, the evidence and the verdict.
No production code, test, contract, migration, tracker or dependency was changed.

## Findings

- The brief's suggested negative "reception-a link → 403" is inaccurate: `DocumentPolicy`
  grants reception `DOCUMENT_LINK` and `DOCUMENT_READ`. The genuine wrong-role refusal is
  reception rendering (403), which the test now uses. The plan reviewer confirmed this.
- `docs/reference/glossary.md:82` maps "Rotate view" to `PdfBindingService`, which has no
  rotation code. Correct server owners are `DocumentInputs`, `DocumentService`,
  `PdfRenderer` and V17; the staff web has a local `rotateDocument` helper
  (`apps/staff-web/src/features/chart/domain.ts`). Out of this test-only scope; recorded
  for a docs task, not edited.
- The committed `origin/main` HEAD (`3ed0895c`) already contains unresolved conflict
  markers in three HL7 Javadoc files (`Hl7ParseException.java`, `Hl7Parser.java`,
  `Hl7Segment.java`). They are inside comments, so compilation and all local checks pass.
  They predate this story and were not touched. Owner: integrator/daily reconciliation.
- The clause is implemented in one reachable server-side path; the artifact/upload
  services and `/api/v1/documents/artifacts/**` routes contain no rotation behavior and
  were deliberately not used as evidence. No second server implementation exists.
- OWASP and the full JaCoCo/CI gate remain integrator-owned; no human, clinical or

## Lessons for workers

- A test-only clause proof can be non-vacuous without a production change: assert exact
  metadata values, byte equality, digest equality and RLS concealment, and run one
  scratch red rehearsal with a flipped expected value (revert immediately).
- For forced-RLS readback, connect as a `NOBYPASSRLS` app role and set `app.current_org`
  in that same session; a superuser or bypass role would make the cross-tenant negative
  silently false-green. Assert the role attribute as a precondition when the DDL is
  `IF NOT EXISTS`.
- Check the actual Spring enum name for a 422 response (`UNPROCESSABLE_CONTENT` here),
  and remember `PdfRenderer` encodes PDF text as UTF-16BE hex, so provenance assertions
  on PDF bytes must compare hex, not literal ASCII.
- A wrong-role negative must reach the `!allowed` branch: use an active member whose
  role lacks the specific action and assert the exact denial message, not just 403.
- When the environment shows `opencode.json` under `skip-worktree`, confirm once with
  `git ls-files -v` and `git show HEAD:opencode.json`, run the remaining gate stages
  individually, and never regenerate or commit the protected file.
