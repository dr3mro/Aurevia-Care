# BUILD-45 · Staff web: prescriptions (draft, search drug catalog, attest, route, status)

## Summary

Added a self-contained staff-web prescriptions feature under
`apps/staff-web/src/features/prescriptions` (16 new files, no files outside scope).
It renders the approved drug catalog search with tagged alternatives, a
verified-allergy warning, a complete prescription draft form with prescriber
attestation and channel choice, an append-only status timeline (submitted,
delivery confirmed, accepted, rejected, clarification, renewal, cancelled),
a version-conflict flow that keeps typed work and offers compare/reload/copy,
and an ambiguous-transmission reconcile action. A bounded senior-react review
found four actionable defects; all in-scope ones were fixed and retested (see
Findings). All fixtures are synthetic; no dependency, contract, tracker or
workflow file was changed.

## Affected requirements

- RX-01: draft fields, catalog search by generic/trade name and formulation,
  tagged alternatives, verified-allergy match/unknown warnings, override reason.
- RX-02: attestation and channel choice, submitted/delivery-confirmed/
  accepted/rejected events with stable submission ID, ambiguous transmission
  verified before retry (reconcile), version precondition on a second submit.
- WEB-09: loading, empty, error (correlation ID), forbidden, conflict,
  session-expired and timeout/offline states via the shared `StateViews`;
  a conflict never discards typed work.

## Authorization boundaries and audit events

Every descriptor carries `X-Active-Organization` from the active tenant;
tenant switching clears the draft and catalog. Write commands carry a fresh
`Idempotency-Key` per user action, and an update carries `If-Match` with the
version returned by the previous response. No PHI, credential, real name or
real domain appears in code or fixtures; all values are `synthetic-*`.
No audit event is introduced by this UI; the owning API command must audit.

## Migration and rollout considerations

None from this change. The prescription command paths are not yet published in
`contracts/openapi.yaml` (verified: only `GET /api/v1/catalogs/{family}` exists
for catalog/ drugs); the API module seeds the shared descriptor builder with a
declared contract path and replaces only the URL, matching the established
`features/scheduling/api.ts` pattern. The backend story must publish the real
paths and refresh the generated client before live use.

## Findings

1. **No prescription API in the checked-in contract.** `contracts/openapi.yaml`
   has no prescription path; only `GET /api/v1/catalogs/{family}` can serve the
   drug catalog. The feature therefore defines its own wire types (as
   `features/scheduling/api.ts` does) and overrides descriptor URLs. The backend
   story must publish the real paths/schemas and regenerate the client; this
   worker did not touch the contract (out of scope).
2. **Route registration deliberately omitted (scope conflict).** Adding
   `features/prescriptions/routes.ts` makes `app/routes.tsx`'s `import.meta.glob`
   auto-register `/pharmacy`, which breaks two out-of-scope exact-route-list
   assertions: `src/app/routes.test.tsx:20` and `tests/app/AppShell.test.tsx:130`.
   BUILD-52 (scope `apps/staff-web/src/app`, `depends: … BUILD-45 …`) owns route
   and navigation registration. Hand-off for that worker: register one lazy route
   `{ pattern: '/pharmacy', component: lazy(() => import('../features/prescriptions/PrescriptionsPage')…) }`
   (or re-add the feature `routes.ts` exporting it) **and update both exact-list
   tests in the same change**, plus the `/pharmacy` navigation entry for
   clinician/pharmacy roles. Until then the screen is reachable only via direct
   component render in tests.
3. **Allergy source is synthetic.** `syntheticAllergies` in `fixtures.ts` stands
   in for the verified patient allergy list because no patient-allergy API is in
   scope. The integrating story must pass real verified allergies from the chart.
4. **Prescription event semantics are display-only.** The UI renders the API's
   event kinds verbatim; it never infers acceptance from delivery or from a
   rendered timeline item (RX-02 distinction between delivery evidence and
   pharmacy acceptance is preserved). A subsequent review noted that dispensing
   evidence had no event kind; `dispensed` was added and is rendered with its
   own word ("Dispensed (evidence of supply)" / Arabic equivalent), keeping it
   distinct from `accepted`.
5. **Senior-react bounded review (tool evidence, simulated review).** A
   read-only senior-react subagent reviewed the feature against the spec and
   design docs. It found five items; four were fixed and retested:
   - High: conflict "Reload" re-fetched the catalog, not the conflicting
     prescription. Fixed with `getPrescription(id, org)`; reload now reads the
     authoritative version, updates `response`/`existing.version`, keeps the
     typed draft, and falls back to a catalog reload when no record exists yet.
     Test asserts a later submit uses `If-Match: 4`.
   - Medium-high: Retry buttons were inert (`StateViews` defaults `onRetry` to
     `noop`). The page now maps error kinds to views with working retry: catalog
     reload and last-command retry (submit or reconcile) with a fresh
     idempotency key from the API layer.
   - Medium: no unsaved-changes guard. Added a `beforeunload` listener gated on
     the draft differing from the last opened/saved draft, mirroring
     `features/chart/NotePage.tsx`. No patient data is placed in the message.
   - Low: hardcoded English placeholders and a non-mirroring `→` in the compare
     dialog. Placeholders now come from `messages.ts`; the separator is a
     localized key (`→` in en, `←` in ar). Latin catalog/ingredient runs are
     annotated `lang="en"` inside the Arabic UI.
   - Low (not changed): the shared `MixedScriptText` labels any run with the
     caller-supplied locale; some other features pass the interface locale for
     Latin text. That component is outside this scope; this feature now passes
     `lang="en"` for Latin catalog names and ingredients.

## Lessons for workers

- In this repo every `features/*/routes.ts` is auto-globbed into the router. A
  parallel feature story that adds such a file breaks the two exact route-list
  tests in `src/app/routes.test.tsx` and `tests/app/AppShell.test.tsx` until the
  route-registration story updates them. Leave registration to that story or
  coordinate the test update, otherwise the module `check.sh` cannot go green.
- Controlled radio/checkbox inputs do not fire `onChange` when clicked while
  already checked; rerender with the new value before clicking the other option.
- A disabled submit button cannot be clicked in jsdom, so exercise the form's
  submit guard with `fireEvent.submit(form)` to cover the disabled branch.
- Vitest/V8 branch coverage counts inline `??`, `||` and ternary sides: name a
  test for every side before claiming 100%.
- `StateView.forTransportError` has no callback argument and `ErrorState`
  defaults `onRetry` to a noop. Any screen using it must render its own typed
  kind-to-view mapping if WEB-09 requires a working Retry; otherwise the button
  looks functional but does nothing.
- A conflict "Reload" must re-read the conflicting resource, not whatever the
  page's other loader happens to fetch. Assert the refreshed precondition is
  used by a later write, not just that a request was sent.
