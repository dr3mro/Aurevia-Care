2. Staff web has no finance feature: `apps/staff-web/src/features/finance/` is ABSENT (feature folders are `admin chart duplicates patients scheduling system`), no feature `routes.ts` exports a finance route, yet `apps/staff-web/src/app/navigation.ts:117` advertises `/finance`. TODO.md READY-30 is `[-]` with 2 attempts. This is why the status is `Partly built` rather than `Built and verified`.
3. Generated command-client discrepancy: `CommandCatalog.java:177-178` declares `issueInvoice` as `POST /api/v1/invoices`, but `FinanceController.java:52` serves `POST /api/v1/finance/invoices`. `CommandClientGenerator.java:70,233,268` generates paths from that definition, so `contracts/openapi/generated/client.ts`, `manifest.json`, `openapi.yaml` and `apps/staff-web/src/api/generated/openapi.d.ts` advertise a create route the controller does not expose. `FinanceService` authorizes independently and the HTTP tests hit the real controller route, so this is not a proven authorization failure. Recommended fix: correct the catalog path and regenerate, in a separate task (outside this note's scope).

## Lessons for workers

- For a product-level clause note, check both the API and the client UI/gate state before choosing `Built and verified`; a nav item alone does not mean the feature exists.
- Compare `CommandCatalog` paths with the controller `@RequestMapping` when citing generated clients as evidence — the generator copies catalog paths verbatim and can drift.
- A clause with no code change has no coverage gate; say so explicitly instead of inventing a command or reporting a coverage number you did not measure.
- Re-run `grep` with the correct literal/regex mode before recording "found none"; a literal search of an alternation pattern falsely reports no matches.
