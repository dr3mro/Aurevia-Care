## Lessons for workers

- For an evidence note, rule 3 decides the status: a clause that needs a cloud
  account, a signature or a human decision is `Not built` when that evidence is
  absent, even if adjacent CI or evaluator machinery exists. Label such
  machinery as non-proving rather than calling it a partial implementation.
- Back every absence claim with a recorded, reproducible search and note the
  negative result; exclude vendored `node_modules` from project-wide `find`s so
  a false hit does not weaken the claim.
- From `docs/spec/clauses/release/`, root targets need four `../` and `docs/`
  targets need three. A shell `-f` check reports a false MISS until the folder
  exists, because path traversal cannot cross a missing directory — create the
  folder first, then verify.
- `scripts/check-docs.py` only accepts requirement IDs defined in the spec:
  WEB-11 and OPS-06 are safe; `G5`, `C01`–`C05` and `S-G5-07` are not IDs under
  its regex. `#` followed by `##` passes the heading-jump rule.
