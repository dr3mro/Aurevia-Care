## Decisions, defects and deviations

- Decision: the list reuses `APPOINTMENT_READ` (the action used by the single-record `AppointmentService.get`) and audits under `APPOINTMENT_READ` with resource id `ALL`, adding no role and no new action key, per story step 3.
- Decision: the required `from`/`to` range is inclusive at both ends and at most 31 days wide (`to.isAfter(from.plus(31 days))` is rejected); this matches the existing audit-list contract wording for its instants.
- Decision: `resource` is a tenant-local scheduling-resource code and matches either the appointment's clinician code or its room code (`c.code = :resource OR r.code = :resource`), the two resource kinds in V8. Codes are validated with the existing `SchedulingInputs.code` rule (`INVALID_RESOURCE`).
- Decision: each list item is a full `AppointmentView`, so the bounded page (at most 200 rows) loads each row's append-only history through the existing repository method rather than returning an empty history. This is honest to the requested item type at the cost of one small history read per row; a batched history query is a possible later optimization.
- No product defect found. No migration version used. No existing test was weakened, skipped or deleted.
- Deviation (transparent): the TODO `scope` field lists only the `scheduling` packages and `contracts/openapi`, while the explicit story steps require `web/AppointmentController.java`, an `it/` integration test and the regenerated staff-web d.ts. Those files were changed because the steps cannot be satisfied otherwise and the build is not green without them. The swarm `scope` is planner collision metadata, not an enforced file allowlist (`scripts/swarm.py:guard` checks protected infra files only). Files changed outside the literal scope: `apps/api/src/main/java/com/aurevia/smartclinic/web/AppointmentController.java`, `apps/api/src/test/java/com/aurevia/smartclinic/it/scheduling/AppointmentListIntegrationTest.java`, `apps/staff-web/src/api/generated/openapi.d.ts`.
