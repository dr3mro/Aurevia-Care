## Summary

Verified the already-merged replacement of the process-local `@Repository`
`InMemoryDeliveryStore` with `events/JdbcDeliveryStore`, a `@Repository` over the existing V55
tables. Confirmed the delivered state:

1. `JdbcDeliveryStore` implements every method of the unchanged `DeliveryStore` port with fully
   parameterised SQL through the tenant-guarded `TransactionTemplate`; the outbox row, its
   audit fact and its idempotency key commit in one transaction in `publishAtomically`.
2. Production wiring uses the JDBC store — the only `@Repository` implementing `DeliveryStore`
   in `src/main` is `JdbcDeliveryStore`; `InMemoryDeliveryStore` has no Spring annotation and
   lives only under `src/test`. Proved by
   `JdbcDeliveryStoreIntegrationTest.productionBeanIsTheJdbcStore`.
3. Real-PostgreSQL acceptance covers the four required scenarios: a separate connection reads
   the committed outbox row after the HTTP command completes (process-loss-after-commit),
   `publishAtomically` reuses the original immutable event id and writes exactly one row for a
   duplicate, a replay keeps the original event id, and tenant B cannot read tenant A's rows
   with identical local identifiers (forced RLS).

No controller, domain-service signature, contract, migration or `pom.xml` was changed by this
story. No new migration version was used (V55 already owns the tables; this story reserves none).

   (tool): exit 1 at `check-pack: opencode.json is stale`. Confirmed `git ls-files -v
   opencode.json` → `S` (skip-worktree), `git diff HEAD -- opencode.json` empty, so the committed
   profile is unchanged; the worktree holds the CI profile that `gen-opencode.py --check` judges
   stale (OPS-CW-003-01). The protected file was not edited. All later worker-check stages
   (frontend, SpotBugs, integration tests, `db/check.sh`, Java conventions) were run individually
   and are green above.
2. **The implementation was already merged** under `AUD-20261120-06`; this re-dispatched pass
   duplicated no code and changed no production file. Its value is the missing BUILD-25 evidence
   and notes. No existing test was weakened, skipped or deleted and no threshold was lowered.
3. **Deferred from the original database review — state write and audit commit use separate
   transactions for commands other than publish** (simulated reviewer, confirmed property). This
   is pre-existing in `DurableEventService`, not introduced by the adapter; moving the boundary
   into the service would roll back denial-path audits unless redesigned, which exceeds "replace
   the store". `publishAtomically` already provides the one atomic state/audit/outbox commit the
   port requires. Owner follow-up: inject a shared `TransactionTemplate` into the service, wrap
   each command and add a failure-injection test; not done here (out of scope).
4. **Residual — `receiptById` can pick one of several same-id receipts within a tenant**
   (simulated reviewer). The port signature takes only `(organizationId, externalEventId)` and
   changing it is outside this story; this matches the replaced adapter's behaviour. Owner
   follow-up: extend the key to the full `(namespace, sender, event_type, external_event_id)`.
5. The JDBC adapter was already proven against real PostgreSQL by the merged integration test;
   no new defect was observed in this pass. `timestamptz` microsecond truncation is expected and
   the test asserts immutable ids/outcome rather than textual timestamps.

## Lessons for workers

- On a re-dispatched attempt, check `git log -- <path>` and the existing `.agent/pr-notes/` before
  rewriting code: the implementation may already be merged, in which case finish the missing
  evidence rather than duplicating the change (as done here and in READY-37 attempt 2).
- A re-run can prove 100% for a touched class without the ten-minute gate: run that class's unit
  test and its tagged integration test in one `-Dtest=` invocation, then `jacoco:report` and read
  the class counters from `jacoco.xml`.
- `worker-check.sh` fails at `check-pack` in cloud workers because the CI `opencode.json` sits
  under `skip-worktree`; confirm with `git ls-files -v` and an empty `git diff HEAD -- opencode.json`,
  then run the later stages individually. Do not edit the protected file.
- `scripts/check.sh` calls `apps/api/check.sh` (`mvn verify`), so a worker told not to run the full
  gate should use the targeted commands above instead.
