## Findings

- **Task-mandated `@Disabled` vs constraint gate.** `scripts/check-constraints.py:56` flags any added `@Disabled` line. This change has exactly one, `FileSentUnitEntersConversationInboxPatientTest.java:361`, with a single `GAP:` reason, because story step 3 explicitly requires the complete test to be marked `@Disabled` when the clause is only partly built. I did not add a second suppression, skip, exclusion or threshold change. `check-constraints.py` exits 1 for this line (and `worker-check.sh`/`quick-check.sh`/`quality-gate.sh` therefore fail at that stage). This is a process conflict between the clause-evidence task template and the later constraint gate: the precedent `@Disabled` clause tests were merged on 2026-11-22 at 08:41, before the constraint rule landed at 09:41. The brief anticipated this and delegated the decision to the integrator. Integrator decision needed: allow a single `GAP:`-reasoned `@Disabled` in spec-clause evidence tasks, or reconcile the task template with the constraint gate. No worker-side workaround was attempted.
- **Pre-existing conflict markers (out of scope, not introduced here).** `apps/api/src/main/java/com/aurevia/smartclinic/exchange/hl7/{Hl7ParseException,Hl7Parser,Hl7Segment}.java` contain `<<<<<<< HEAD` / `>>>>>>> origin/swarm/BUILD-37-469` lines inside Javadoc comments. They are committed in `HEAD` (`git show HEAD:…` confirms), are javac-safe, and are unrelated to MSG-03. I did not edit them.
- **Environment artifacts (documented false positives, not defects of this change).** Worktree `opencode.json` is the CI profile under `skip-worktree` (`S`), so `check-pack.py`, `gen-opencode.py --check`, `worker-check.sh`, `python-coverage.sh` and the six `test_check_pack` unit tests fail exactly as on the unmodified base. No protected file was regenerated.
- **Honest status.** `AttachmentService.publish/inbox/fileIntoChart` have no production caller. `inbox(unit)` is a computed unit-scoped list, not a persisted conversation inbox; there is no attachment-to-conversation-message link and no patient-supplied marker; `patientId` is grant-derived, so "patient-supplied" rests on the patient uploader subject plus the `PUBLISHED` fact. The doc therefore says `Partly proven`, not `Proven by tests`.

## Lessons for workers

- Before writing a clause-evidence test, check `scripts/check-constraints.py`: a new `@Disabled` line fails the constraint gate even though the task template requires one for partly-built clauses. Confirm whether the integrator has a `GAP:` allowance for these tasks; do not invent a suppression.
- `scripts/worker-check.sh` can stop at the opencode.json CI-profile false positive before running its own later stages; run `frontend-check.sh`, SpotBugs (compile first), `db/check.sh` and the targeted Maven test individually and record each final line.
- A disabled `@SpringBootTest` class still runs its `@BeforeAll` in integration suites, so its Flyway/seed fixture must be valid and use a unique database name even though its only test method is skipped.
- Capture the exact Surefire `tests/errors/skipped/failures` attributes from the XML report; a quiet `mvn -q` run prints no test summary on success.
- When asserting a negative state filter, keep a distinct fixture in each excluded state at assertion time. Transitioning the only CLEAN file to FAILED leaves no CLEAN row to exercise the filter and makes the test name overclaim (caught by `smartclinic-code-reviewer` here).
