# RESP-CHART-PAGE — responsive staff-web `ChartPage`

## Summary

Made `ChartPage` responsive at every supported band (320–1280 px, LTR and RTL)
without changing behaviour, text, API calls or exported names. The page now
uses the shared `.page` utility (safe-area-aware logical gutters, single reading
column, centred maximum width), exposes the resolved band as `data-breakpoint`,
and wraps the wide clinical tables in one labelled, keyboard-scrollable
`.table-region` on compact only. Long identity text gets logical wrapping;
`Load more` keeps the shared `touch` target. A new jsdom responsive test drives
the real route through its normal providers with synthetic data and asserts
structure, labels, roles, keyboard order and RTL at compact/medium/expanded.

Files changed (only the declared scope):
- `apps/staff-web/src/features/chart/ChartPage.tsx`
- `apps/staff-web/tests/responsive/features-chart/ChartPage.responsive.test.tsx`

## Affected requirements

- **WEB-07** — responsive staff web from 320 px; no page-level horizontal scroll;
  the labelled scroll region owns wide tables and all clinical columns stay
  reachable. Evidence: `.page` + compact-only `.table-region` and the
  compact/medium/expanded tests.
- **UX-01** — logical properties only, RTL mirroring without a direction
  override, no hidden clinical field, long English/Arabic wrapping, 44 px
  coarse-pointer target on the action, 200 % zoom readability (no fixed block
  size on clinical regions). Evidence: logical-property assertions, RTL test,
  long-string tests, touch-target test.

component now works at all widths/directions with the listed properties (2);

inline styles for identity wrapping (3); the new scoped test mocks `matchMedia`

## Findings

- **Simulated UX review (tool: read-only reviewer subagent, no edits) returned
  three findings.** F2 and F3 were fixed in the test file: the "no hidden
  clinical column" check now asserts the *exact* ordered header text and count
  for each of the four tables (8/8/8/3) and that no header is `display:none`;
  `expectLogicalWrapping` now also rejects fixed `block-size`, `min-block-size`
  and `max-block-size`, not just `height`. F1 is explicitly deferred (below).
- **F1 deferral — medium-band overflow region.** The reviewer noted that the
  design specifies a labelled region at medium "only when content overflows",
  while this component follows the already-merged `DataTable` convention of
  adding the region on compact only. jsdom cannot detect overflow, and adding a
  `ResizeObserver` plus a real tablet measurement would change behaviour and
  need Playwright evidence outside this scope. The wide tables use `width:100%`
  with wrapping cells, so no clinical column is hidden and no page-level
  horizontal scroll is introduced at 768–1024 px; pixel proof is owned by the
  existing `RESP-E2E-FEATURE-CHART` task (no horizontal scroll and every value
  reachable at phone/tablet/desktop), and table internals by the pending
  `RESP-LONGITUDINAL-CHART` task. No new task is required. Reviewer also
  confirmed no text/behaviour/API/export change by static reading (it had no
  shell to run a diff).
- **Pre-existing committed conflict markers (outside scope, not touched).** The
  required `git merge --no-edit origin/main` produced no conflict, but the
  follow-up `git grep -nE '^(<<<<<<<|>>>>>>>) '` reports markers already
  committed in HEAD in `Hl7ParseException.java:6/10`, `Hl7Parser.java:14/18`
  and `Hl7Segment.java:10/14` (`origin/swarm/BUILD-37-469`). Verified with
  `git show HEAD:<file>`; they predate this story, are outside its scope and
  were left untouched. Owner/integrator should resolve them.
- The patient display name is intentionally rendered twice (page header and the
  chart's own summary section), so jsdom tests use `getAllByText` for that value.
- `ChartPage` contains no form inputs; the 16 px input-text rule is not
  applicable here. The wide coded tables are owned by the separate pending
  `RESP-LONGITUDINAL-CHART` story, so pixel-level table behaviour is left to the
  Playwright tasks, as the story directs. jsdom cannot measure pixels.

## Lessons for workers

- Reuse `useBreakpoint()`, `data-breakpoint` and the `responsive.css` utilities
  (`.page`, `.table-region`, `touch`) for feature pages; jsdom asserts classes,
  attributes and structure, never painted pixels.
- `ChartViewResponse.nextCursor` is `string | null | undefined` under
  `exactOptionalPropertyTypes`: a synthetic fixture must pass `nextCursor ??
  null`, not a bare `undefined`, or `tsc --noEmit` fails with TS2375.
- When a value appears in two sections of one page, use `getAllByText` in tests
  rather than weakening the query.
- `git grep` conflict markers after a merge can be HEAD debt, not merge
  fallout; confirm with `git show HEAD:<file>` before editing files outside scope.
- `responsive.css` has **no dedicated identity/clinical-value wrapping class**
  (the same gap `MixedScriptText` documents). Per the story, the stylesheet was
  not edited; logical inline styles (`minInlineSize: 0`, `overflowWrap:
  'anywhere'`, `textAlign: 'start'`) were used on the page wrapper and the
  identity paragraph instead. A future shared `.clinical-value` utility would
  remove this duplication.
