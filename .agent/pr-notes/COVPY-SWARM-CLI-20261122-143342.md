## Findings

- **Task prose vs numeric range.** The task text describes this slice as "slot
  rotation, release and audit helpers, the argument parser and every subcommand of
  `main` with its output", but in the current 3973-line `scripts/swarm.py` those
  functions are not in lines 2450-2800 (slot rotation is ~2899+, `main` is ~3693+).
  The assigned numeric range actually holds the Delivery-gate, draft-recovery,
  integration-planning and repair helpers. I followed the explicit instruction
  "Cover only the uncovered lines in that range" and the coverage report, matching
  the sibling COVPY-SWARM-SCHEDULE worker (whose prose also did not match its range
  exactly). No line in 2450-2800 was unreachable; all three statements and the one
  branch had a test.
- **Coverage gap outside all five split ranges.** The five tasks assign lines 1-2800;
  nothing assigns `swarm.py` lines 2801-3973 (including `main`). If COVPY-GATE switches
  `python-coverage.sh` to `--full` before that gap is assigned and covered, it will
  still fail. Flagging for the integrator/owner; I did not touch those lines because
  step 3 forbids covering outside the assigned range.
- The full Python suite has 8 failures that exist identically before and after this
  change: six `test_check_pack` failures whose first line is the known
  `opencode.json is out of date` CI-profile-under-`skip-worktree` false positive
  (OPS-CW-003-01) and two `test_worker_gate` errors from sandbox fixtures
  (`integration run failed without fresh, usable test results`). Per AGENTS.md these
  are worker-environment false positives; no protected file was edited for them.

## Lessons for workers

- When a coverage slice is split by line number, filter the coverage JSON to the
  numeric range; the prose description of a slice can be stale. The measurable
  acceptance test is "zero missing lines and branches in the range", not the prose.
- A whole-pass helper that normalizes a `gh_json` answer (`runs if isinstance(runs,
  list) else []`) has two ternary outcomes; test both with list and non-list fakes.
- For an early return that avoids an expensive call (`repair_task` skipping the log
  fetch for worker-only failures), assert the skipped call is *absent*, not only that
  the return value is `None`.
- This worker image has no `pip`; `apt-get update && apt-get install -y
  python3-coverage` is the working way to get branch coverage for the Python suite.
