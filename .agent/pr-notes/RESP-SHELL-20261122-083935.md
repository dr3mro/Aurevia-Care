# RESP-SHELL — Staff web responsive application shell

## Summary

Made the single authenticated staff shell (`apps/staff-web/src/app/AppShell.tsx`) responsive
across the three layout bands from decision 0004, using the existing `useBreakpoint` hook and
the classes already present in `apps/staff-web/src/theme/responsive.css`:

- **compact (< 768 px):** the full rail is replaced by the existing `NavigationDrawer` (menu
  button opens an off-canvas dialog from the inline-start edge). The header is slim: menu
  button, product title, organization switcher and one collapsed user-menu button. Theme,
  locale and sign out live behind that button, reachable in two taps.
- **medium (768–1279 px):** an icon rail with a decorative glyph per screen-map group. Each
  link keeps its full translated label as an accessible name and native `title`; a visual
  tooltip additionally opens on keyboard focus and after a sustained touch press, and is
  cancelled on blur, release, pointer cancel or pointer leave.
- **expanded (≥ 1280 px):** the original full labelled rail and direct header controls, kept
  DOM-compatible with the untouched `AppShell.test.tsx`.

Kept the skip link (first focusable element), all four landmarks, focus to `<main>` on every
route change, theme/locale toggles and sign out. The rail stays at the inline-start side under
both LTR and RTL because only logical properties (`inset-inline-start`) are used. Main content
uses the `page` class; the root uses `app-shell`, and header/footer apply the safe-area block
insets with logical padding. No new dependency, no change to any other file.

  attribute them to `origin/swarm/BUILD-37-469`.
- `NavigationDrawer` restores focus to its opener when it closes. The compact
  focus-to-main test passes, confirming React runs that passive-effect cleanup before the
  shell's `[path]` focus effect; if a future change adds a delayed drawer close, re-check this
  ordering.
- `responsive.css` still has no shared `.control`/`.action` utility and no `.hint` tooltip
  class, so the icon rail uses the existing `.touch` class plus an inline-free tooltip span
  whose `hidden` attribute is toggled by React. Do not edit the stylesheet from a component
  story; a stylesheet story owns that follow-up.
- jsdom preserves logical CSS properties and `max(...env(safe-area-...))` values in the style
  attribute, so safe-area and inline-start assertions are real attribute checks, not painted
  pixel claims.

## Lessons for workers

- Read the dependency worker notes before this story: they record that the no-`matchMedia`
  fallback is `expanded`, that the rail group must keep an inline `inset-inline-start` and no
  physical `left`/`right`, and that `apps/staff-web/check.sh` is the canonical gate while the
  repo-wide `scripts/check.sh` runs the forbidden Java/DB integration gates.
- `Link` in `src/app/router.tsx` accepts no `className`, `aria-label` or event handlers. For an
  icon-only link, render a real `<a>` with `aria-label` and `onClick` that calls
  `event.preventDefault()` then `navigate(route)`; otherwise jsdom logs "Not implemented:
  navigation" and a browser would reload.
- `role="tooltip"` + `hidden` is simplest to assert with `element.querySelector('[role="tooltip"]')`
  and `hasAttribute('hidden')`; fake timers plus `runAllTimers()` avoid naming the delay in the
  test and avoid flakiness.
- jsdom serializes logical properties (`padding-block-start`, `padding-inline`, `inset-inline-start`)
  into the style attribute; assert those and explicitly assert physical `paddingLeft`/`paddingRight`
  are empty so an inline physical value cannot silently outrank the logical rule.
