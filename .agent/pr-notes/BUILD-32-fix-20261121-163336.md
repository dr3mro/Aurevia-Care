## Data changes

`db/migrations/V86__recurrence_templates.sql` (reserved version V86, `Change: expand`): three additive
tables `recurrence_template`, `appointment_series`, `series_occurrence`. Each has `organization_id`,
a composite PK including it, `created_at`, ENABLE + FORCE RLS and a policy
`USING/WITH CHECK (organization_id = public.app_org())`. Append-only reject-mutation triggers for
`UPDATE`, `DELETE` and `TRUNCATE` cover every role including the migration owner; SELECT/INSERT are
granted only to `aurevia_app`. `recurrence_template` enforces exactly one termination via
`CHECK ((occurrence_count IS NULL) <> (end_local_date IS NULL))`. No backfill, no UPDATE of existing
rows, no destructive DDL; brief ACCESS EXCLUSIVE locks bounded by table creation. Rollback is a
forward-fix migration; no capability is removed. No migration was added or edited in this pass.

## Lessons for workers

- Do not re-run the slow full `mvn verify` as a worker. The decisive coverage command is the targeted
  130-class unit suite plus `SeriesHttpIntegrationTest`, `AppointmentListIntegrationTest` and
  `SchedulingBookingTest`; a subset leaves the large touched class (`AppointmentService`) below 100%.
  `SchedulingBookingTest` lives under `.../aurevia/it/` and must be added explicitly because the
  `grep -v '/it/'` filter that builds `UNIT` excludes it.
- JaCoCo counters print as `missed/covered`: `1/4` is a MISSED branch. Match class names by the exact
  JaCoCo name using `/` separators (`com/aurevia/.../AppointmentService`), not dotted names, or the
  parser reports every class missing. Parse direct-child `counter` elements only, list nested classes
  separately, and treat an absent BRANCH counter as `n/a` (no branches, 0 missed) rather than defaulting
  it to `-1`, which otherwise produces a spurious `MISSED` verdict.
- Run SpotBugs with `-f apps/api/pom.xml` from the repo root and compile first (add `-Djacoco.skip=true`);
  without `-f` Maven fails with `MissingProjectException`, which is not a code defect.
- `check-pack.py` / `gen-opencode.py --check` staleness under `skip-worktree` is a known false
  positive in this worker environment. Verify with `git ls-files -v opencode.json` and compare the
  worktree/CI/committed hashes before treating it as your defect; do not regenerate it locally.
- The generic "frontend definition of done" block in the swarm prompt applies only to stories that
  touch a frontend module; for a backend-only scope, state that explicitly with the diff evidence
  rather than installing toolchains or fabricating typecheck evidence.
- An empty `<STORY …>` block is not a licence to invent work. Recover the task from `TODO.md` and the
  branch history, inherit the prior findings, and say in the notes that no new criteria were supplied.
