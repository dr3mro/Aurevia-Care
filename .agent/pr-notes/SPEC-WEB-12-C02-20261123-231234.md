## Lessons for workers

- Quote the file, not the brief: this brief's OWASP version was one major behind the pom. Verify every version and path with a direct read before writing an evidence note, and label trackers that disagree as stale decision records.
- A status of "Partly built" is the honest choice when one required component is absent, not merely unrun; "Built but not verified" would wrongly imply every component exists.
- Keep evidence notes to configuration and code paths that are actually present. A launch-checklist row marked `open`, a synthetic evidence fixture or a runbook line saying "NOT YET IN PLACE" is a gap, never proof.
- For `docs/spec/clauses/**` notes, `python3 -I scripts/check-docs.py` validates relative links, requirement IDs and structure; the `../../../../` prefix is correct for a clause file four levels below the repository root. `scripts/check-secrets.py` also rejects token-shaped strings quoted in prose.
