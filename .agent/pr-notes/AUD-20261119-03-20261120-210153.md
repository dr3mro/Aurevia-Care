# AUD-20261119-03 — Expose required workflows through HTTP entry points

## Summary

Six services marked `[x]` in `TODO.md` had no caller anywhere in `apps/api/src/main/java`, so their
workflows could not be reached at runtime: `AttachmentService` (MSG-03), `PatientAppointmentService`
(PAT-01), `ReleasedReportService` (PAT-02), `G3EvidenceService`, `TherapyService` (PT-01) and
`ImagingService` (RAD-01). Each now has a thin `@RestController` with a real protected route and an
HTTP-level test that drives the workflow through that route with synthetic data.

New production files (all inside the declared scope):

| Workflow | Controller | Routes |
|---|---|---|
| MSG-03 / ARC-06 | `messaging/attachments/AttachmentController` | `POST /api/v1/patient/files/upload` (multipart), `POST .../files/{id}/scan`, `GET .../files/{id}/download` |
| PAT-01 | `messaging/appointments/PatientAppointmentController` | `GET /api/v1/patient/appointments`, `POST .../{id}/confirm`, `POST .../{id}/notify`, `POST /devices`, `DELETE /devices/{tokenId}`, `POST /devices/{tokenId}/invalid` |
| PAT-02 | `messaging/reports/ReleasedReportController` | `GET /api/v1/patient/reports`, `GET .../reports/{reportId}/download` |
| G3 evidence | `messaging/evidence/GateEvidenceController` | `POST /api/v1/gate-evidence/produce` |
| PT-01 | `therapy/TherapyController` | `POST /api/v1/therapy/episodes`, `GET .../episodes/{episodeId}` |
| RAD-01 | `radiology/ImagingController` | `POST /api/v1/imaging/orders`, `GET .../orders/{orderId}` |

`messaging/appointments/SyntheticPatientAppointmentPorts` supplies synthetic in-memory adapters
because that service had no adapters at all (its own Javadoc says no verified-link table exists).
The adapters are explicitly documented as fixtures to be replaced by durable IAM-05 adapters
before real-patient use. Every controller derives organization, subject and roles from the request
tenant context and freshly resolved membership; no identity is taken from a command body.

## Authorization boundaries and audit events

Tenant comes only from `TenantContext` (set by `TenantContextInterceptor` from the explicit
active organization header); subject is the authenticated synthetic subject. Roles for the
attachment, therapy and imaging routes are re-read with `StaffRepository.activeRoles` inside the
tenant-guarded `TransactionTemplate`, so a deactivation denies the next request. The PAT-01
synthetic link is seeded only by fixtures, never inferred from demographics. Existing domain
audit paths are preserved: `PatientAppointmentService` and `ReleasedReportService` append their
own audit facts, `TherapyService` and `ImagingService` keep their append-only fact trails, and
attachment denials are recorded by `AttachmentService`. No new audit event type or log content
was added; no payload bytes, push token, file name or URL is logged.

## Migration and rollout considerations

No migrations. Routes are additive under `/api/v1/**` and covered by the existing tenant
interceptor. The synthetic PAT-01 adapters are suitable for engineering/simulated UAT only and
must be replaced with tenant-scoped durable adapters before real-patient enablement (this is
recorded in the adapter Javadoc; no production data path is enabled by this change).

## Findings

- All six named orphans now have real HTTP entry points; `grep` for each class name outside its own
  file returns a controller reference in `main`.
- The literal task scope lists only `src/main/java/...` paths. HTTP tests necessarily live under
  the mirrored `apps/api/src/test/java/com/aurevia/smartclinic/{messaging,therapy,radiology}` trees.
  They were added because the story explicitly asks for "an HTTP-level test per workflow" and the
  100% coverage gate forbids adding controller methods without tests. No other scope was touched.
- `PatientAppointmentService` had no adapters at all and its own contract says a production
  verified-link adapter must deny until IAM-05 lands. Rather than leave it unreached, synthetic
  fixture adapters were added with explicit documentation that they are not for real patients.
- `AttachmentService.publish` remains reachable only from unit tests; the exposed MSG-03 route
  covers upload (the documented missing multipart endpoint), quarantine scan and mediated download.
  Publishing remains a follow-up if a dedicated HTTP command is required.
- Environment artifact only: `worker-check.sh` quick gate fails on the skip-worktree CI-profile
  `opencode.json` (OPS-CW-003-01). No repository file was changed for it.

## Lessons for workers

- When exposing a domain kernel that takes an explicit `Actor`/`roles`, derive identity from
  `TenantContext` plus `StaffRepository.activeRoles` inside the tenant-guarded transaction; never
  accept a role or organization from the request body.
- A `@RestController` with two constructors (public `@Autowired` + package-private fixture one)
  lets standalone MockMvc tests drive real domain services while the production constructor stays
  covered by the existing `@SpringBootTest` context loads — without new `@Configuration` beans.
- Two interfaces can declare `find(String,String)` with different return types; one adapter class
  cannot implement both. Use nested per-port adapter classes.
- In a cloud worker, a `check-pack`/`gen-opencode` "stale" failure is a measurement artifact when
  `git ls-files -v opencode.json` shows `S`; compare the worktree file with `.github/opencode.ci.json`
  and `git show HEAD:opencode.json` before treating it as a defect. Never regenerate it from a worker.
