# RESP-DRAWER — staff-web off-canvas navigation drawer

## Summary

Added a phone-breakpoint off-canvas navigation drawer as two new files. A labelled
menu button opens a modal, role-scoped navigation drawer that reuses the existing
`navigationGroupsFor(role)` screen-map model, so items a role cannot use are never
rendered. The drawer traps focus, closes on Escape / link choice / backdrop tap /
explicit close button, returns focus to the menu button, locks page scroll while
open, opens from the inline-start edge with logical inset properties (so the
document `dir` mirrors it under RTL), and drops its slide transition when
`prefers-reduced-motion: reduce` is set. This is a new component only: the
application shell is not wired to it in this story (that is RESP-SHELL).

## Affected requirements

- WEB-07 — supported clients / compact layout; off-canvas drawer at phone widths.
- UX-01 — English and Arabic labels, RTL mirroring through `dir`, WCAG 2.2 AA
  keyboard and focus behaviour (focus order, trap, visible close control, no
  gesture-only action).

## Findings

1. `bash apps/staff-web/check.sh` fails at `npm run gen:api:check` because the
   checked-in `apps/staff-web/src/api/generated/openapi.d.ts` does not match
   `contracts/openapi.yaml`. Verified from committed state: regenerating to
   `/tmp/openapi-check.d.ts` differs from the tracked file; `git status` shows
   neither path modified by this worker. The contract's last change is commit
   `f85d4adb` (PRINT-02). This predates RESP-DRAWER and is outside the two-file
   scope, so no file was changed. A task request is recorded below.
2. The drawer is not yet mounted by `AppShell` — that wiring belongs to
   RESP-SHELL (which depends on this story). Consequently no runtime entry point
   exists in the app until that story merges; the entry point here is the
   component's menu button and its tests.
3. Modal background inertness: focus is trapped and a backdrop covers the page,
   but the surrounding application is not marked `inert`/`aria-hidden` because
   that would require editing `AppShell` (out of scope). RESP-SHELL should set
   `inert` on the shell content while the drawer is open.
4. The menu-button label reuses the existing translated navigation label
   (`navigationLabel(locale, 'navigation')` → "Sections" / "الأقسام") rather than
   a new "Open navigation" key: adding a key to `shellText.ts`/`messages.ts` is
   outside scope. No label is hard-coded, so UX-01 localization holds.
5. Bounded read-only `orevia-senior-react` review (simulated, no edits):
   - Resolved in scope — drawer heading ids were `nav-heading-…`, colliding with
     the rail once both mount; they are now `nav-drawer-heading-…` on both the
     `id` and `aria-labelledby`, with a regression test that mounts the real
     `AppShell` and the drawer together.
   - Resolved in scope — the menu and close controls now carry the shared
     `touch` class (`responsive.css`: 24 px floor, 44 px on coarse pointers),
     with a class assertion for each control.
   - Out of scope, already recorded above — no shell entry point (RESP-SHELL)
     and no `inert` on the background (needs `AppShell.tsx`).
   - Accepted limitation — the inline inset transition has no off-screen
     starting state, so the slide does not visibly animate on mount; the
     reduced-motion branch still correctly removes the transition property.
     A real painted slide and the background inertness belong to the
     RESP-SHELL / responsive Playwright slices (jsdom cannot paint motion).
   - Accepted design — `aria-controls` points at the drawer, which is
     conditionally mounted, so the IDREF is dangling while closed. Keeping the
     drawer mounted hidden would require the shared CSS class and a different
     focus model; the conditional mount keeps the focus trap deterministic.

## Lessons for workers

- When a canonical `check.sh` fails on a pre-existing generated-artifact drift,
  run every remaining step individually and record each command and final line;
  do not regenerate or edit generated files outside your scope to make it green.
- `@testing-library/react`'s `fireEvent.click` does not focus a button in jsdom;
  for a modal that must return focus, capture the opener in an effect rather than
  relying on `document.activeElement`.
- `react-hooks/exhaustive-deps` rejects reading a ref directly in cleanup — copy
  `menuRef.current` to a local inside the effect first (use `!` where the node is
  guaranteed by render, to avoid an uncoverable branch).
- Always `event.preventDefault()` on an in-app anchor before calling the router
  `navigate()` helper, or jsdom logs a real "Not implemented: navigation" error
  and a browser would reload the page.
- Scope note from an earlier run applied here: Testing Library cleans up only per
  `it`, so each test re-renders and opens its own drawer.
