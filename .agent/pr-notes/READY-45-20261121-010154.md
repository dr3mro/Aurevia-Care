# READY-45 — Automated accessibility and end-to-end harness for the staff web

## Summary

Added a Playwright + axe-core harness for the staff web under `apps/staff-web/e2e`,
wired an `e2e` npm script, documented how to run it, and kept the canonical unit
check green. The suite runs four Chromium tests against synthetic fixtures: home
title and skip-link keyboard order, a serious/critical axe gate on the
development-only `/design-preview` route in English and Arabic, RTL direction
via the real language toggle, and no horizontal scroll at 768 px. No production
source, API, migration, workflow or shared tracker was changed.

## Findings

1. `?lang=ar` is not implemented in this app: `I18nProvider` holds locale in
   state and exposes a toggle but never reads a URL parameter. The RTL test
   therefore clicks the visible `Language` button instead, as the story allows.
   Anyone wanting deep-link locale tests must first add URL parsing to the app
   (outside this story's scope).
2. `AppShell` programmatically focuses `<main>` on load. The keyboard test
   resets the sequential focus starting point with a test-only
   `tabindex="-1"` on `document.body` before pressing Tab; without this, the
   first Tab stays on `BODY` and the second lands on the skip link. This is a
   harness accommodation, not a production change, and is commented in the spec.
3. `python3 -I scripts/check-pack.py` exits 1 with "opencode.json is stale".
   Verified pre-existing and unrelated: `git status --short opencode.json` is
   empty (skip-worktree), `git show HEAD:opencode.json` differs from the worktree
   file because `agent-run.sh` activates the CI profile, and the same false
   positive is recorded in MEMORY.md as OPS-CW-003-01. No config file was changed;
   the committed profile is HEAD truth.
4. The local worker needed `npx playwright install chromium` **and**
   `npx playwright install-deps chromium` (missing `libglib-2.0.so.0` and other
   OS libraries). This is why the suite cannot be appended to `check.sh` in this
   story; a person must provide the CI job and image.
5. The webServer binds IPv4 loopback explicitly (`--host 127.0.0.1`):
   plain `npm run dev` bound `localhost` to `::1` here, so the Playwright URL
   probe at `127.0.0.1:5173` timed out. A reviewer also found that a supplied
   `E2E_BASE_URL` conflicted with the local `webServer` in CI; fixed by making
   `webServer` undefined whenever that variable is set, and documented in the
   README. The external target must still be a dev build exposing
   `/design-preview`.
6. No serious or critical axe violations were observed on `/` and
   `/design-preview` in English or Arabic during the local run. This is a
   synthetic automated result only.
7. Reviewer finding (test engineer, simulated): the suite is smoke-only and
   axe runs only on routes available in a dev build; WEB-10's full evidence
   (each supported role's critical journey against staging, light/dark visual
   checks, retained report on every release candidate) is still unmet. An axe
   run on the real `/` route was added here; real role screens and the CI job
   remain person-owned (READY-46 tracks the CI row). Do not mark WEB-10 complete
   on this evidence alone.
8. Reviewer finding (senior React, simulated): `tsconfig.json` includes only
   `src`, `tests` and `vite.config.ts`, so the two new e2e TypeScript files are
   linted but not type-checked by any gate. Fix belongs to the module owner
   (add `e2e` to the tsconfig `include`, or a dedicated `tsconfig.e2e.json`);
   `tsconfig.json` is outside this story's scope, so no change was made.
9. Reviewer finding (senior React, simulated): `engines.node` said `>=20.19`
   while the pinned `@axe-core/playwright@4.14.0` requires `>=22.12.0`. Fixed in
   scope by raising the engine to `>=22.12.0` in `package.json` and the lockfile
   root entry (`.nvmrc` is 22.23.5; CI uses Node 22).
10. Reviewer note (informational): the story explicitly asks to fail only on
   serious/critical impact, so moderate and null-impact axe findings do not
   block. A stricter WCAG gate would use `withTags([...])` and fail on any
   violation. Left as specified.

## Lessons for workers

- A second test runner that uses `*.spec.ts` will be collected by Vitest's
  default discovery. Scope the unit scripts (here `--exclude 'e2e/**'`) or, when
  in scope, add `test.exclude` in `vite.config.ts`, before declaring the unit
  gate green.
- Playwright's `webServer.url` must match the address the dev server actually
  binds; pin `--host 127.0.0.1` when the baseURL is IPv4.
- When asserting focus order, account for app effects that move focus on load
  and reset the sequential focus starting point in the test.
- Pin new devDependencies exactly with `npm install --save-dev --save-exact` and
  `npm view <name> version` when the story forbids carets.
- In a cloud worker, treat `check-pack.py`/`gen-opencode.py --check` results on
  the skip-worktree `opencode.json` as CI-profile measurements, not HEAD truth.
- When a new dependency raises the minimum Node version, update `engines.node`
  (and the lockfile root entry) in the same change; `.nvmrc`/CI may already be
  new enough and hide the mismatch.
- If a second runner's files are excluded from the module `tsconfig.json`, they
  escape `tsc`; ask the module owner to include them, because lint alone misses
  type errors.
