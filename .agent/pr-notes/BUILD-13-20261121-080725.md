## Findings

1. **Known tooling false positive, no change made.** First `bash scripts/quick-check.sh` run exited 1 at `check-pack: opencode.json is stale`. `git ls-files -v opencode.json` shows flag `S` (skip-worktree): the worktree file is the CI profile copied by `agent-run.sh`, while `git show HEAD:opencode.json` is the correct committed local profile (`HEAD` file differs from `.github/opencode.ci.json`). Restoring the HEAD file makes `gen-opencode.py --check` and `check-pack.py` pass. This is BUGS `OPS-CW-003-01` / MEMORY `IMP-01`; no protected file was edited or committed.
2. **Implementation already present.** FIN-01 production code and full HTTP/PostgreSQL coverage were already on `main` (S-G4-05, READY-18). No production defect was found while writing the acceptance tests; this story contributes the missing fast-gate ledger tests only.
3. **Test-authoring correction (not a production defect).** The first draft asserted that a replay leaves the invoice version at `2`; it correctly leaves it at `3` (the version after the first payment). The test now compares the replay version with the original outcome's version. Evidence: initial `mvn -Dtest=FinanceLedgerTest test` failed 1/8 with `expected: <2> but was: <3>`; after the edit, 8/8 green (10/10 after the review fixes).
4. **Scope boundary honoured.** The existing `it/finance` integration tests are outside this task's `scope` and were run for coverage evidence but not edited.
5. **Independent review gaps — all fixed.** The read-only specialist review confirmed criteria 1–4 were asserted and raised: *F1* one-currency was only incidental; *F2* "reason required" was tested for CREDIT but not REFUND/VOID; *F3* ledger immutability was not asserted; *F4* `add` overflow was untested (only `multiply`). Fixes: added `everyLinkedEntrySnapshotsTheInvoicesSingleCurrency` (invoice + PAYMENT/REFUND/CREDIT entries all SAR, a second invoice USD), `reversalsAndVoidsRequireAReason` (null/blank refund and void → 422 `INVALID_REASON`, money unchanged), `UnsupportedOperationException` on `entries().clear()` plus an unchanged-first-entry assertion, and a two-line sum-overflow case → 422 `AMOUNT_OVERFLOW`. Re-ran: 10/10 green; full finance set green; coverage still 0 missed.
6. **`unittest discover` shares the same `opencode.json` overlay false positive.** Without the swap, `python3 -I -m unittest discover -s scripts/tests -q` fails 3 `test_check_pack` cases (`test_check_mode_detects_drift`, `test_committed_opencode_json_is_generated`, `test_repository_pack_is_valid`), all comparing the CI-profile worktree file with generated HEAD-truth. With the HEAD file restored it is green, and `scripts/quick-check.sh` (which runs the same 436 tests) passed end-to-end. Not caused by this change; no tracker or config file was edited.

## Lessons for workers

- In a swarm worker, `opencode.json` is a skip-worktree CI-profile overlay. Policy checks that read the worktree file report a false "stale" finding. Temporarily write `git show HEAD:opencode.json` over it, run the gate, then restore the overlay; never edit or commit the file.
- `mvn test` with JaCoCo's `prepare-agent` followed by `mvn jacoco:report` gives a per-class CSV coverage report without the >10-minute full `verify` — enough to prove the touched domain is at 100% when the story forbids the full gate.
- For a "no-op replay" assertion, compare against the original outcome's version/state rather than a guessed literal: the version advances on the first post and the replay must not advance it again.
- When the production code for a story is already on `main`, say so plainly and deliver the missing in-scope evidence instead of manufacturing a production change.
- Turn each acceptance phrase into its own named assertion before calling a test done: "one currency" needs a per-entry check across all entry types, "needs a reason" needs a negative refund/void case, "immutable" needs a frozen-list/unchanged-entry check, and "fixed precision" needs both multiply and add overflow. A passing suite with these phrases only covered incidentally is not acceptance evidence.
