# READY-31 — Operations: `/operations/queues` for the operational queues

## Summary

Added the self-registering `features/operations` staff-web feature for ADM-02/OPS-05. `QueuesPage` loads all five real list endpoints in parallel with per-queue failure isolation, shows one tab per queue with a row count, a computed oldest age from the server instants, a keyed accessible table and the row actions the API actually exposes (`assign`, `retry`, `escalate`, `review`). Every action opens a reason dialog, refuses an empty reason, is sent once, and surfaces a failed send as the shared error state without an automatic repeat. `OperatorHome` provides the role-aware home content (one count-bearing link per queue); it is exported for the application shell to mount because `'/'` is app-reserved by READY-51. Routes are registered only in `features/operations/routes.ts`.

## Affected requirements

- **ADM-02** — operational queues; authorized operators act with a recorded reason.
- **OPS-05** — queue age and error visibility for operations monitoring.
- Also touched by design convention: UX-01/WEB-09 (bilingual labels, all screen states, accessible tables and dialogs).

## Findings

- **Scope deviation (disclosed).** Registering `/operations/queues` changes the global route table, so two exact-registry assertions had to gain one expected pattern: `apps/staff-web/src/app/routes.test.tsx:20` and `apps/staff-web/tests/app/AppShell.test.tsx:130,140` (both arrays). These files are outside the declared scope. The change is expectation-only — no assertion weakened, no test skipped — and is required by AGENTS.md coverage rule 7 ("if an existing test must change because behavior changed on purpose, say so"). READY-21 used the same disclosed pattern for `/schedule`; its note is in `.agent/pr-notes/READY-21-20261121-010154.md`. The integrator/owner should confirm.
- **`OperatorHome` is exported but not mounted.** `/` is reserved by `app/routes.tsx:RESERVED_PATTERNS` and `app/WelcomePage.tsx` is outside this scope, so the operator home content cannot be wired here. A follow-up owning `app/WelcomePage.tsx` should render `<OperatorHome />` for `useRole() === 'operator'`; until then requirement 3 is present as a tested component but not reachable from `/`.
- **No cursor paging.** None of the five list endpoints offers a cursor (`/exchange/work-items`, `/delivery/dead-letters`, `/instructions/overdue-follow-ups`, `/duplicate-reviews`, `/clinic/worklist` all return bounded arrays; the clinic worklist has only `limit`). The "if the API offers it" clause is therefore not exercised.
- **No timestamp for duplicate reviews.** `DuplicatePair` carries no server instant, so that tab shows "Not available from this endpoint" instead of inventing an age; every other tab computes age from its server timestamp with an injected clock.
- **Action labels vs endpoint names.** `escalate` is the clinic worklist handoff endpoint; `review` covers verify-patient, dead-letter review, follow-up resolve and duplicate-ticket opening; `retry` on a dead letter uses the same review endpoint with the `requeued` resolution (there is no other reason-recording requeue command). These are the closest real endpoints to the story's four verbs. No chart consolidation is offered from this screen.
- **Specialist review (advisory, source inspection; no shell).** The bounded Senior React review found three command-contract blockers and four medium issues, verified by tool reads of the Java controllers/contracts and fixed in this change:
  - *H1* dead-letter review sent `resolution: 'retry'`, but `DurableEventContract.Resolution` only parses `requeued`/`resolved` — now sends the valid wire keys, distinct per action.
  - *H2* duplicate review called `consolidate` with a composite `survivor:duplicate` id and no identifier confirmation — now opens a review ticket at `POST /duplicate-reviews` with both pair ids; no merge is attempted.
  - *H3* work-item verification omitted the issuer-scoped MRN and attestation — `QueueRow` now carries `localMrn`/`mrnIssuer` from the projection and the dialog reason is sent as `attestation`.
  - *M1* invented version/revision `1` preconditions — removed; the one guarded command (follow-up resolve) now uses the server `revision` from the wire, and no `If-Match` is fabricated.
  - *M3* a tab switch while the dialog was open could send a row to the wrong queue — `PendingAction` now captures `queue` at open time (covered by a dedicated test).
  - *M5* feature-owned states stayed English in Arabic — `displayQueueText` translates them from `messages.ts` with a parity-checked key set, leaving server text verbatim.
  - *L1* oldest age compared ISO strings lexicographically — now compares `Date.parse` numerically, with a fractional-seconds test.
  - Not fixed (disclosed): *M2* reason dialog still lacks native `<dialog>` focus trap / Escape / focus restore (the shared `Dialog.tsx` traps Tab on its close button only and would make the reason field unreachable; jsdom has no `showModal`); *M4* clinic `assign` and work-item `verify-patient` do not persist a `reason` field in their contracts, so the UI solicits the text but the server can only record it as `assigneeSubject`/`attestation`; *L2* tabs are buttons with `aria-pressed` in a labelled group rather than a full `tablist`/arrow-key composite. All three need an owner decision or a shared-component change outside this scope.
- **Reason dialog focus handling** remains the open accessibility follow-up above; it is labelled, keyboard reachable and has an explicit Cancel control, but does not contain Tab or restore focus.
- **`scripts/check.sh` red on the worker's CI-profile `opencode.json`** (see Test evidence). Not changed here; protected file and known environment artifact.

## Lessons for workers

- Adding any `features/*/routes.ts` module breaks the two hard-coded route registries (`src/app/routes.test.tsx`, `tests/app/AppShell.test.tsx`); include their expectation-only updates in the same change and disclose the scope deviation, or reserve those files in scope.
- With per-file 100% function coverage, every inline JSX arrow callback (tab click, row action, input `onChange`) must be exercised by a test; delete unreachable guards (a disabled button already prevents a second click) rather than writing a test that only touches a line.
- In this cloud worker, `opencode.json` is under skip-worktree and is the CI profile; `scripts/check.sh` and `gen-opencode.py --check` judge that profile, not HEAD. Use `git show HEAD:opencode.json` to inspect the committed profile and do not "fix" it from a worker.
- 100% coverage of a mocked `send` proves the UI's own values, not that the payload is accepted by the server. Read the Java controller, request record and enum/parser for every command and add assertions against the real wire keys and required fields before claiming an action works.
- Never invent an `If-Match`/revision value to satisfy a guarded endpoint; carry the server's version in the projection or omit the action. A composite list-row id is not a ticket id for a separate command.
