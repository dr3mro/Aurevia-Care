# SPEC-XCH-04-C03 — API evidence: unmatched / conflicting reports enter the reconciliation queue

clause 3. The clause is already implemented, so the new test is enabled (no

## Lessons for workers

- When an API clause is already implemented, prove it three ways in the clause
  test — HTTP response, persisted row and audit event — plus a "not imported"
  row count. An assertion on only the 202 body is a weak proof.
- Assert a JSON array as an array (`isArray()`, `size()`, element value); a
  `body.contains("sourceId")` check also matches the `detail` string and can
  pass with an empty mismatch list.
- The shared `authorize()` writes DENIED audits with `resource_type=RESULT_REPORT`
  and uses the requested status (`open`) as the read-denial resource id; assert
  the actual contract, not the intuitive one.
- Always seed a peer-tenant reader role and a positive control before asserting
  RLS concealment; an empty page from a role that would return 403 otherwise is
  a false green.
- In a cloud worker, `git ls-files -v opencode.json` → `S` explains
  `check-pack.py` and `test_check_pack` failures; confirm once, run the other
  gate stages individually, and never regenerate or commit that file.
