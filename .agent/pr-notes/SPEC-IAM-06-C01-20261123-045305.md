## Lessons for workers

- Copy the config-entry **and config-approval** seed block verbatim: without the
  approval row the clinician grant silently returns 403 DENIED, which looks like the
  negative case and makes the positive test a false failure.
- The audit `actor_id` is a `user_identity.id` UUID filled by the V3 trigger from
  `app.actor`; query the expected id under the active organization and compare UUIDs,
  never the `X-Synthetic-Subject` string.
- One grant writes three audit rows (`EMERGENCY_GRANT`, `EMERGENCY_ALERT`,
  `EMERGENCY_REVIEW_OPEN`). Give each test a distinct `X-Correlation-Id` and filter on
  `action` plus `resource_id` so row ordering cannot make assertions flaky.
- A wrong-role denial is committed as a DENIED audit row because the service returns
  the failure from the guarded transaction and throws only after commit; a
  missing-reason 422 is written before the transaction and has no audit row.
