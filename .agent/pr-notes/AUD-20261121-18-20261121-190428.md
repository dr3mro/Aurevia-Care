# AUD-20261121-18 — Digest-pin the mutable build-stage base images in Dockerfile.app

## Summary

`Dockerfile.app` mixed a digest-pinned final stage (`postgres:17-alpine@sha256:…`) with two floating build stages (`FROM node:22-alpine` and `FROM maven:3.9-eclipse-temurin-21`). Under a fixed source commit the production image's compiler/toolchain could change on an upstream tag move, so the build was not reproducible and the dependency surface could drift without a repository change. Pinned both build stages to the tag's multi-arch image-index digest, kept the same major versions, and added the same `# <tag> (digest pinned; Dependabot bumps it)` comment used by the existing postgres pin. No application code, build inputs, or CI files changed.

Change (only file in scope, `Dockerfile.app`):
- `FROM node:22-alpine@sha256:1314fb30ec37592d5845e5a160d522c0e680972aa534549940b8d73bde88481a AS web`
- `FROM maven:3.9-eclipse-temurin-21@sha256:99e61abcff91a9b1333463bd8451fb18495d6eba9250ac66a338b518f8278320 AS api`

## Lessons for workers

- Resolve an image's pin from the Docker Hub tag API (`https://hub.docker.com/v2/repositories/<ns>/<repo>/tags/<tag>`): take the top-level `digest` field when `media_type` is `…/oci.image.index.v1+json`, not a digest from `images[]` (those are per-platform). Keep `tag@sha256` so Dependabot still has a version signal to bump.
- Verify multi-arch suitability before pinning a base used by native amd64+arm64 builds: confirm the index lists both `linux/amd64` and `linux/arm64` and that the top-level digest is not any per-arch digest.
- In a cloud worker a red check-pack is usually the CI-profile `opencode.json` under `skip-worktree`; confirm with `git ls-files -v` and `git show HEAD:opencode.json`, never regenerate/commit it, and restore any temporary swap byte-for-byte.
- `scripts/check.sh` runs the full module gates (Java/OWASP/db) and can exceed 5 minutes; bound it with `timeout` and leave the authoritative full gate to the integrator. Docker is absent locally; image smoke is CI-only.
- For a config/build-file-only story, prove the fix with a red→green structural assertion in the shell plus authoritative source reads, and state explicitly that code-coverage tooling is not applicable rather than fabricating a coverage number.
