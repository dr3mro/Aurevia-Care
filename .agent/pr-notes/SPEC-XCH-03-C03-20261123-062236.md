# SPEC-XCH-03-C03 — Capture retained recipient copies and permitted purposes (XCH-03 clause 3, API test)

## Summary

Test-only evidence task. Add an HTTP-level integration test that proves accepting a released order captures an immutable retained recipient copy stamped with its permitted purpose and retention policy, that an accepted post-acceptance change retains a new linked revision under the original purpose, and that the rule refuses captures outside its boundaries. Add a clause evidence document. No production code, existing test, migration, contract or dependency changes.

## Affected requirements

XCH-03 (SMARTCLINIC_V1_SPEC.md line 65): "The recipient accepts, rejects with reason, or requests clarification. Changes after acceptance create a linked version or cancellation request, and require recipient response. Capture retained recipient copies and permitted purposes. Revocation blocks future sender-hosted retrieval and records downstream notification. Apply law and policy to recipient retention."

Cross-boundary (HTTP → service → RLS-bound ledger) but test-only; no production boundary is changed. Clinical/tenant-safety behaviour is exercised with synthetic fixtures only.

## Lessons for workers

- For HTTP error assertions, compare the numeric status (`response.getStatusCode().value()`) rather
  than a named `HttpStatus` constant for codes whose enum name changed between Spring versions
  (422 is `UNPROCESSABLE_CONTENT` here). The neighbouring reference test already uses numeric 422.
- Capture Surefire evidence at the moment of the run: the XML `tests/failures/errors/skipped` counts
  and the `.txt` final line. With `mvn -q`, a green run prints no summary to stdout.
- Never read `$?` after `cmd | tail`; it is `tail`'s status. Use `${PIPESTATUS[0]}` or run the command
  without a pipe. This initially mis-recorded the tooling suite as green.
- A peer-tenant negative must call the real composite read route (`GET /{id}` carries `/retained`);
  inventing a `/retained` sub-route yields a vacuous 404 that proves nothing about RLS.
- `JsonNode.asBoolean()` returns false for a `MissingNode`, so a `false` assertion alone does not
  prove the field is present. Assert `isMissingNode()` (or `isBoolean()`) first.
- When `git ls-files -v opencode.json` shows `S`, `test_check_pack` failures are the known CI-profile
  skip-worktree artifact. Record the evidence once and leave the protected file and full gate to the
  integrator.
