# AUD-20261121-09 — Unify the two divergent UUID validation rules at the request boundary

## Summary

Added one canonical UUID text primitive, `com.aurevia.smartclinic.api.contract.CanonicalUuid`, alongside the existing `Cursor`/`IdempotencyKey`/`RequestDigest`/`CatalogCode` wire primitives. It enforces the strict `8-4-4-4-12` hex shape and returns canonical lowercase text. Migrated the two prescription-boundary validators first:

- `prescription/PrescriptionInputs.uuid` no longer uses `UUID.fromString` (which accepted non-canonical `1-1-1-1-1`).
- `prescription/rx/RxInputs.uuid` no longer uses its local strict `Pattern` and no longer returns the caller's original casing.

Both now delegate to the one primitive and translate its rejection into their own unchanged `INVALID_<FIELD>` 422 error. Identical client input is now accepted/rejected identically at both boundaries, and uppercase canonical input yields one canonical lowercase identifier instead of being silently preserved on one endpoint and rewritten on the other.

Design reviewed by a bounded simulated `smartclinic-senior-backend` review (subagent `ses_e007eac6affeyIU6eQVm9gcwgZ`); no blocking findings. Review was simulated, not human or clinical.

## Affected requirements

- ARC-03 — shared, bounded, deterministic request-boundary validation (entry point: `POST`/`PUT` RX-01 and RX-02 request paths through `PrescriptionInputs.uuid` / `RxInputs.uuid`).
- RX-01, RX-02 — prescription request-field validation.
- No new requirement, table, endpoint or wire field introduced.

## Findings

1. **Divergence removed for the migrated callers.** `1-1-1-1-1` is now rejected by both validators (previously accepted by `PrescriptionInputs` via `UUID.fromString`); uppercase canonical hex is accepted by both and normalized to lowercase (previously preserved raw by `RxInputs`). Both still return 422 `INVALID_<UPPER(field)>` with their original detail messages, so existing wire errors are unchanged.
2. **Deliberate behavior convergence:** RX-02 uppercase canonical input now returns lowercase. This is required by "one canonical rule"; the out-of-scope `RxContractTest` uses a lowercase canonical fixture and is unaffected (verified green above).
3. **Remaining callers were enumerated (tool: executed grep over `apps/api/src/main/java`) and intentionally left untouched** because they are outside this task's scope:

## Lessons for workers

- When a story says "migrate X and its tests" but those tests live outside the declared scope, write new in-scope test classes for the migrated validators and prove the out-of-scope assertions by **running** them (targeted `-Dtest=`), rather than editing files you do not own.
- To unify validators while preserving field-specific `INVALID_<FIELD>` wire codes, keep the shared primitive status-free (`IllegalArgumentException` + one `INVALID_MESSAGE`, like `CatalogCode`) and translate in each caller's try/catch. JaCoCo needs explicit tests for both the success and catch side of every caller.
- In a cloud worker, run `git ls-files -v opencode.json` before trusting `check-pack.py` / `test_check_pack` failures: an `S` flag means the CI profile is checked out under `skip-worktree`. Compare `git show HEAD:opencode.json` with the generator's `render(...)`; do not regenerate or edit it.
- `scripts/check.sh` calls `apps/api/check.sh` → full `mvn verify`; in a time-boxed worker run the post-`check-pack` policy gates individually instead, and leave the full gate to the integrator.
