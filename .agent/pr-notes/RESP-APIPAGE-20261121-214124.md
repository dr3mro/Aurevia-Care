# RESP-APIPAGE — Staff web responsive `ApiPage`

## Summary

`ApiPage` now renders every required screen state inside one labelled `page`
region, taking the responsive grid, maximum reading width, logical safe-area
padding and wrap-friendly `minmax(0, 1fr)` column from
`apps/staff-web/src/theme/responsive.css` instead of any new CSS. The resolved
`useBreakpoint()` class is exposed as `data-breakpoint` on that region so the
structure can be asserted in jsdom, where media queries cannot be evaluated.
A new test mocks `matchMedia` for compact, medium and expanded and checks the
wrapper, accessible name/role, all four states, keyboard order and the
right-to-left case. No behaviour, text, API call or exported name changed; no
new dependency; no file outside the two-file scope was edited. Synthetic data
only (`SYN-0001`-style placeholders and Arabic test strings).

## Affected requirements

- WEB-07: supported client widths down to 320 px; the `page` class supplies the
  compact single-column grid and the 768 px inline-padding step defined in
  `responsive.css` (no data or workflow is gated by width).
- UX-01: logical properties and safe-area insets come from the shared class,
  no subtree direction override, long English and Arabic runs can wrap, all
  states keep their accessible name and DOM order.

## Findings

- **Pre-existing generated-client drift blocks `bash apps/staff-web/check.sh` at step 1.** `contracts/openapi.yaml` contains `/api/v1/printing/handouts` and `/api/v1/printing/handouts/download` plus `PrintReason`, `HandoutKind` and `HandoutSource` component types (from merged PRINT-07), but `apps/staff-web/src/api/generated/openapi.d.ts` does not. Both files are unchanged in this worktree and identical to HEAD. Regenerating the client is outside this task's two-file scope; a separate owner task should run `npm run gen:api` in `apps/staff-web` and commit the result.
- `ApiPage` itself renders no inputs and no interactive controls, so the 16 px `.field` text rule and the 44 px coarse-pointer `.touch` rule do not apply here; the components that own those elements apply the shared classes. The wrapper adds no CSS that could hide a clinical column or field.
- `data-breakpoint` is test-observable metadata, not a second layout source: actual reflow stays with the media queries in `responsive.css`. It is the only reason `ApiPage` subscribes to the two `matchMedia` listeners, a deliberate trade-off for jsdom-testable structure explicitly requested by the story.
- The "keyboard order" assertion checks DOM order plus absence of a positive `tabindex` (valid because no wrapper tab stop was added); it does not simulate Tab keypresses.
- Repeated `className`/`data-breakpoint`/`aria-label` across the four state returns was left as-is to keep the change minimal; a future refactor could extract a local region helper.
- ADR-0004 is still `Proposed` and WEB-07 in `PROJECT_V1_SPEC.md` still states the old 1280/768 floors. Code follows the decision as the story directed; the owner amendment remains pending.

## Lessons for workers

- In a fresh worker, `npm ci` is required in `apps/staff-web` before `npx vitest`: without it, `npx` installs a standalone Vitest that cannot resolve `vitest/config` and `@vitejs/plugin-react`.
- ESLint rejects unused callback parameters even with a leading underscore here; use zero-argument stubs for mocked `addEventListener`/`removeEventListener`.
- When `check.sh` fails at `gen:api:check`, verify the generator inputs with `git diff --exit-code HEAD -- contracts/openapi.yaml apps/staff-web/src/api/generated/openapi.d.ts` before assuming your change caused it. Do not regenerate out-of-scope files.
- A region present in every state makes `findByRole('region')` resolve during loading; await state-specific text first and take `closest('section.page')` to assert the terminal state's wrapper.
- To test a generic wrapper responsively in jsdom, expose the resolved breakpoint as a data attribute and leave layout to shared CSS media queries; do not invent classes absent from `responsive.css`.
