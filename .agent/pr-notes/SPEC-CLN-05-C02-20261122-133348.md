## Summary

Adds a clause-scoped API proof test for CLN-05 clause 2 and its evidence record. The clause is already
fully implemented by `ClinicalNoteService.sign`; no production code, existing test, contract or
migration was changed. The new test proves all five sub-rules (sign permission, signer attestation,
correct patient context, draft version, required fields) with one positive case and five negative
cases, using synthetic fixtures only.

Files added (both inside the task scope):
- `apps/api/src/test/java/com/aurevia/smartclinic/chart/clauses/RequireSignPermissionSignerAttestationCorrectPatientTest.java`
- `docs/spec/clauses/chart/require-sign-permission-signer-attestation-correct-patient.md`

## Affected requirements

CLN-05 (clause 2). Related but unchanged: ARC-02 (tenant scope), OPS-02 (audit), WEB-05 (OpenAPI route
debt noted in Findings).

Safety-critical for the workflow it proves (clinical signature: permission, attestation and patient
context), but this change is test-and-documentation only with no production behaviour change.
Routine by change footprint; reviewed against the safety-critical checklist because of the domain.

Senior Java and Spring Boot / Spring Security (sign permission), Test Engineer (proof tests),

None. No Flyway migration, backfill, table, lock or volume impact; no rollback or forward-fix.

No authorization boundary or audit event was added or changed. The tests assert the existing ones:

in the test, doc or notes.

## Clinical and architecture review

The test records what a simulated clinical author/signer may do; it is synthetic review only, not
real clinical acceptance. No signer identity is client-supplied in the append (the database owns
version and actors); the test asserts the attestation and signed instant are carried on the revision.
Patient release, PDF rendering and entered-in-error are out of this clause's scope and unchanged.
Architecture boundary: `chart.clauses` is the clause-proof test package; the implementation remains
in `clinical.notes`, so no duplicate domain type was introduced.

## Findings

1. Clause 2 is fully built. Implementation found in the source survey:
   `apps/api/src/main/java/com/aurevia/smartclinic/clinical/notes/` — `ClinicalNoteService`
   (`sign`, `authorize`/`allows`, `requireVersion`, `requireFields`, `requirePatient`, `append`),
   `ClinicalNoteController.sign` (`POST /api/v1/clinical-notes/{id}/sign`), `NoteInputs`,
   `NoteChecksum`, `NoteState`, `NoteRepository`, `RevisionInput`, `ClinicalNoteRevision` and
   `TenantContext`. Schema: `db/migrations/V15__clinical_note_signing.sql` (append-only, forced RLS,
   trigger-owned version/actors/checksum). The `chart/record` package is a separate longitudinal-chart
   workflow and does not implement signing. Existing proof:
   `it/clinical/ClinicalNoteServiceTest` and `it/clinical/ClinicalNoteRevisionIntegrationTest`.
2. OpenAPI debt found but not changed: all seven `/api/v1/clinical-notes` routes are baselined in
   `contracts/openapi/missing-routes.txt` rather than published in `contracts/openapi.yaml`. That is a
   separate WEB-05 documentation gap, outside this task's scope; the clause doc records it as such.
3. Environmental false positive: six `test_check_pack` failures from the skip-worktree CI profile
   (`opencode.json`), verified once with `git ls-files -v` and HEAD-vs-generator comparison; not a
   defect of this change and not re-diagnosed further. No tracked file was modified by the test run
   (`git status --short` shows only the two new scoped paths).
4. A true red phase is not applicable here: the clause is already implemented and the task forbids
   production changes. Each test asserts a concrete outcome (status/code/captured revision/audit) and
   would fail if its guard were removed, so the proof is not vacuous.
5. Specialist review (`smartclinic-test-engineer`, simulated review of the test/doc; evidence is the
   report plus the primary agent's re-run, not an independent execution by the reviewer) found two
   short-circuit weaknesses: `signRefusesABlankOrMissingSignerAttestation` and
   `signRefusesADraftWithMissingRequiredFields` asserted only HTTP 422 while `patientExists` was left
   unstubbed, so removing their guard could still yield 422 `INVALID_PATIENT_CONTEXT` and keep the
   tests green. Fixed by stubbing `patientExists=true` and asserting the concrete codes
   `INVALID_ATTESTATION` and `INVALID_CONTENT`; with patient context valid, a relaxed rule reaches
   the append and produces 412 `STALE_VERSION`, so each test now fails on rule removal. The doc's
   entry-point wording was also corrected to say the clause test calls the service directly while
   the unchanged integration test proves the HTTP route. Re-ran targeted test (7/7), `check-docs`
   and `check-names`, all exit 0.
6. Pre-existing conflict markers on `origin/main` (HEAD `ba1bf87a`), unrelated to this task and left
   untouched because they are outside scope: `git grep -nE '^(<<<<<<<|>>>>>>>) '` reports markers in
   `apps/api/src/main/java/com/aurevia/smartclinic/exchange/hl7/Hl7ParseException.java`,
   `Hl7Parser.java` and `Hl7Segment.java`. `git show HEAD:<path>` confirms each marker is committed,
   and each sits inside a Javadoc comment, so `javac`, the targeted test and SpotBugs still pass;
   they are residue of an earlier `origin/swarm/BUILD-37-469` merge and would pollute the generated
   developer reference. The merge in this task returned `Already up to date` and introduced no
   conflict. Integrator: open a separate task to remove these three marker pairs; do not attribute
   them to this PR.

## Lessons for workers

- The `*/clauses` packages are the fast, mocked, synthetic unit tier; mirror the owning service test
  (here `ClinicalNoteServiceTest`) rather than duplicating the DB integration suite, and cite the
  existing HTTP test as the entry-point proof.
- In a cloud worker, `git ls-files -v opencode.json` = `S` explains `test_check_pack` /
  `gen-opencode.py --check` failures. Confirm HEAD equals the generator render and never regenerate
  or commit that protected file.
- Do not run `scripts/check.sh` or `scripts/worker-check.sh` from a swarm worker: they reach the full
  `mvn verify` / all integration tests and time out. Run the targeted `-Dtest=...` suite, the
  individual policy scripts and the compile-then-SpotBugs command, then leave the full gate to the
  integrator.
- Clause-proof tasks that add only tests and docs produce no new production coverage; say so
  explicitly instead of claiming a JaCoCo number that was never measured.
