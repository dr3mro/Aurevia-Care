# ORDER-02 — API: place a lab or imaging order with a delivery mode

## Summary

Adds an order-placement kernel and thin HTTP adapter under `com.aurevia.orderentry.place`, plus the matching `contracts/openapi.yaml` entries. A clinician saves an editable vendor-neutral draft, edits it under `If-Match`, then places it with `If-Match` plus `Idempotency-Key`. Placement snapshots the catalog items and versions, clinical question, priority, preparation instructions, destination partner and the chosen delivery mode (`ELECTRONIC`, `PRINT`, `BOTH`) into an immutable `PlacedOrder`. A retry with the same tenant/subject/key returns the one original order; reuse of the key for a different draft is a 409. Wrong role is 403, a foreign tenant's draft/order is concealed as 404, and a stale version is 412.

This mirrors the existing `radflow.worklist.WorklistService` domain-kernel pattern: the kernel is a Spring `@Service` with no HTTP, persistence or outbox dependency, and its storage boundary is deferred to the integration story exactly as that precedent documents. Work stay inside the declared scope; no dependency was added.

## Data changes

No Flyway migration, table, backfill or SQL change — `db/migrations` is outside this task's scope. The kernel holds drafts, placed orders and the idempotency index in concurrent in-memory maps, matching `WorklistService`/`WorklistEvent` precedent. Lock/volume impact is process-local only. Rollback is a plain commit revert. A durable, tenant-owned forced-RLS migration, a Jdbc implementation behind the service boundary and an HTTP-level integration test are requested as a follow-up task (see `task-requests` below); without them this slice is not end-to-end durable.

## Authorization boundaries and audit events

- Tenant comes only from `X-Active-Organization` via `TenantContextInterceptor`; the acting subject comes from the synthetic-auth header; neither is read from the request body.
- Active roles are re-resolved from `StaffRepository.activeRoles(subject)` inside a tenant-guarded `TransactionTemplate` on every request, so deactivation/role changes take effect immediately (IAM-01/IAM-02).
- Placement requires the `clinician` role. Wrong role is 403 `FORBIDDEN`; a foreign tenant's draft or order is 404 `NOT_FOUND` (existence concealed); a stale version is 412 `STALE_VERSION`; missing `If-Match` or `Idempotency-Key` is 428.
- Facility is carried on the request and bound to verified membership in the persistence integration story (same deferred boundary documented by `WorklistController`).
- No audit events were added in this slice: the kernel has no persistence/outbox dependency, so the transactionally appended DENIED/SUCCESS audit rows belong with the durable-store story.

## Migration and rollout considerations

None in this commit (no migration in scope). When persistence is added it must use a reserved version with `RLS` + `FORCE RLS`, a durable `(tenant, subject, command, key)` uniqueness constraint for idempotency, and an HTTP-level integration test through `PlaceOrderController`.

## Findings

- **Environment artifact (not a code defect).** The worktree `opencode.json` is the CI profile copied by the worker harness under `skip-worktree` (sha256 `50005c9c…`) and differs from HEAD (`0dc2ac8e…`). `python3 -I scripts/gen-opencode.py` regenerates byte-for-byte HEAD's version, and with that version in place `python3 -I scripts/check-pack.py` exits 0 and all 26 `test_check_pack` tests pass. Restored the worktree file unchanged. This is why `bash scripts/check.sh` and the 5 `test_check_pack` cases fail locally; it is unrelated to this change and the integrator (which checks out the committed profile) will not see it.
- **Deferred durability.** The kernel is process-local by design and out-of-scope for a migration (AGENTS' end-to-end rule needs the follow-up persistence story listed below). Do not treat a green 100% JaCoCo run as proof of durability.
- **Contract rules.** `OpenApiContractRulesTest` requires a tag and an `Idempotency-Key` header on every write operation and does not allow extending its debt allowlists. Added `tags: [order-entry]` and an optional retry-correlation `IdempotencyKeyOptional` header to the draft commands; placement uses the required header.
- No defects were found in existing code; no existing test was weakened, skipped or changed.

## Lessons for workers

- Before writing a new domain kernel, read `radflow/worklist/WorklistService` + `WorklistController`: they define the accepted shape (in-memory kernel, roles supplied by the controller from `StaffRepository` inside a `TransactionTemplate`, persistence explicitly deferred).
- `contracts/openapi.yaml` is enforced by JUnit (`OpenApiContractRulesTest`): every operation needs `operationId`, `summary`, `tags`, 401+403, tenant headers, and every POST/PUT/PATCH/DELETE needs an `Idempotency-Key` header parameter (a `$ref` to a header component satisfies it). Adding paths without these fails the full unit suite.
- `scripts/tests/test_java_conventions.py` requires at least two `List.copyOf(` occurrences in any record with a `List`-typed component — add a defensive `items()` accessor, not just constructor copying.
- In a cloud worker, a red `check-pack` / `test_check_pack` is usually the skip-worktree CI profile, not your change: compare `sha256sum opencode.json` with `git show HEAD:opencode.json | sha256sum` and temporarily regenerate to prove it before reporting a defect. Never commit the regenerated file from a worker.
