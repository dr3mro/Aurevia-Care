# READY-30 — Finance: `/finance` invoices with issue, payment, refund and void

Attempt 2 verification run. The finance feature was implemented and committed on
this branch by the earlier run (`4cd5258 feat(staff-web): add self-registering
finance invoice screens`); this run re-verified it against every gate, made no
production-code change (none was needed), and records the exact evidence below.

## Summary

The self-registering finance feature under `apps/staff-web/src/features/finance`
is complete and verified. It provides integer-minor-unit money helpers (`money.ts`),
an API client for every finance endpoint named in the story (`api.ts`), a status-
filtered cursor-paged invoice list (`InvoicesPage`), an invoice detail screen with
itemized lines, balance and a linked payment/refund/credit ledger
(`InvoiceDetailPage`), and issue/payment/refund/credit/void commands. Refund,
credit and void require a reason and an independent approver id; void is also
withheld once the invoice has a ledger trail, matching the server's guard. The
payment form keeps one `Idempotency-Key` across failed retries of the same payment
and rotates it only after a stored payment. Instants are rendered explicitly in
UTC; row links carry the invoice id in their accessible name; each form moves
focus to one live error summary. Routes `/finance` and `/finance/:id`
self-register via `features/finance/routes.ts`. All data is synthetic; this run
added no dependency, migration, OpenAPI file or file outside the feature folder.

## Affected requirements

- **FIN-01** — integer minor units with one currency per invoice; draft/issued/
  partially_paid/paid/void states; linked immutable payment, refund and credit
  entries with reason and approval; stable payment reference/idempotency; balance
  shown from the API; finance-only fields with no clinical narrative.
- **PRD-04** — self-pay invoices, payments, refunds and receipts; no claims
  adjudication, payer integration, card data or accounting ledger.
- Route registration follows READY-51 (`features/<name>/routes.ts` exporting
  `routes: AppRoute[]`); `app/routes.tsx` and `app/navigation.ts` were not touched.

## Authorization boundaries and audit events

The active organization comes only from `useActiveOrganization()`
(`X-Active-Organization` via the shared request builder); every descriptor
carries it. Invoice ids are opaque and `encodeURIComponent`-escaped before use in
a command path or a `/finance/:id` link; no patient name, reason, approver id,
reference or money value enters a URL, page title, log or browser storage.
Authorization, replay deduplication, approval invariants and audit remain
server-side (`FinanceService`/`FinanceActions`); this slice adds no audit event
and does not duplicate those checks. The UI action table mirrors the server
lifecycle so it never offers a command the API would reject on state grounds.

## Lessons for workers

- Adding a self-registering feature route makes `src/app/routes.test.tsx` and
  `tests/app/AppShell.test.tsx` fail when they hard-code the full registry; that
  is a separate owned task (FIX-ROUTES-01), not an in-scope cleanup for a feature
  worker. Do not edit those files from a feature story.
- A failed canonical gate is not automatically a coverage or code defect: check
  which stage produced the red result before changing production code. Here
  typecheck, lint, build, bundle budget, generated-client check and every test
  except two out-of-scope assertions were green.
- Verify a prior attempt's committed state before redoing work: read the earlier
  notes file, `git log -- <paths>` and the current test files. A repair claimed in
  notes may not be present in the tree.
- `Intl.NumberFormat`'s `maximumFractionDigits` is typed optional even for
  currency style, so a non-null assertion with a rationale is needed under strict
  TypeScript; mocked `crypto.randomUUID()` values must be UUID-shaped because its
  return type is a template literal type.
- The shared `Link` in `src/app/router.tsx` forwards only `to`/`children`/`target`/
  `ariaCurrent`; a hyphenated `aria-label` typechecks but is dropped. Put
  distinguishing identity in the link text instead.
- A void is not a pure lifecycle question: a fully refunded invoice returns to
  `issued` but keeps its ledger and the server rejects the void. Gate destructive
  UI on both state and ledger contents.
