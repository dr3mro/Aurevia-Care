## Summary

Adds a published, market-approved medication catalog version to RX-01. A versioned search returns the catalog version it used together with route-bearing approved items; a prescription draft binds that version when a medication is selected and keeps it across later publications. Unapproved, future and retired items are rejected on selection. V76 adds the registry and columns; no existing record signature, test, migration or dependency was changed.

## Affected requirements

RX-01 (primary). ARC-01/ARC-02/OPS-02 for the tenant-owned, forced-RLS append-only registry in V76.

## Risk class

## Review owner

Senior Backend, Senior Database, Test Engineer and Physician Reviewer (bounded advisory reviews, run in parallel). Primary agent owns the edits and all executed evidence.

## Data changes

`db/migrations/V76__build_09.sql` (reserved version V76, `Change: expand`):
- `drug_catalog_entry.route text NOT NULL DEFAULT 'unspecified'` (additive metadata; the sentinel is deliberate, ALTER TABLE does not fire the V43 row triggers).
- `prescription_draft.catalog_version integer` (nullable; a draft with no medication has no catalog version).
- New append-only `public.medication_catalog_version` registry: `(organization_id, version, market, published_at, provenance)`, PK `(organization_id, version)`, ENABLE+FORCE RLS, tenant policy, GRANT SELECT/INSERT, REVOKE UPDATE/DELETE/TRUNCATE to `smartclinic_app`, new immutability function and triggers. V43 functions were not touched.
- No seed rows: organizations do not exist at Flyway time under forced RLS. Readers fall back to documented baseline version 1 until a version is published.
- Rollback/forward-fix: additive expand only; no destructive DDL. Removing the columns is a separate contract migration. Lock/volume impact negligible (two metadata columns and one small append-only registry).

## Findings

1. `check-pack.py --check` and `gen-opencode.py --check` initially failed with "opencode.json is stale". This is the documented cloud-worker CI-profile overlay, not a change defect: `git ls-files -v opencode.json` is `S` (skip-worktree), the worktree file differs from `git show HEAD:opencode.json`, and the generator's output equals HEAD. The worker gate was run with the committed profile temporarily in the worktree and the original CI profile restored byte-for-byte afterwards; no protected file was committed. (Evidence: tool commands; BUGS OPS-CW-003-01.)
2. Two new read endpoints (`/api/v1/drug-catalog/search-with-version`, `/api/v1/prescription-drafts/{id}/catalog-version`) are not described in `contracts/openapi`, because `contracts/` is outside this story's scope. The integrator/owner should add the OpenAPI entries and regenerate client types if these endpoints are published.
3. Decision: a draft is "built from" the catalog at medication selection, so a draft with no medication has `catalogVersion: null`. The version is bound once via `COALESCE(catalog_version, :catalogVersion)`; publishing a newer catalog never rebinds an existing draft.
4. Decision: tenants with no published version read baseline version 1 (`provenance: synthetic-baseline`) so pre-registration catalogs and existing tests remain readable. A published row takes precedence immediately.
5. Defect found and fixed during the run: `PrescriptionRepository.catalogVersion` first used `jdbc.query(...).stream().findFirst()`, which throws NPE when a draft stores NULL. Replaced with `queryForObject(..., Integer.class)`; regression covered by the HTTP integration test.
6. The senior-backend reviewer's suggestion to stamp the version at draft creation was deliberately not adopted: it would change create-draft behavior and the accepted meaning of "built from" without an explicit owner decision. Recorded here for the Product Owner.

## Lessons for workers

- A stream mapper that can legally return null makes `findFirst()` throw NPE (`Optional.of(null)`); use `queryForObject` for a nullable scalar column.
- In a cloud worker, check `git ls-files -v opencode.json` before treating a `check-pack.py`/`gen-opencode.py --check` failure as your own: a skip-worktree CI profile is not HEAD truth.
- Run the Java conventions unit test early: one unqualified `{@link DrugEntry}` failed the whole worker gate even though compilation and all tests passed.
- For 100% coverage on a modified large class, include that class's existing test files in the targeted `-Dtest=... jacoco:report` run; new tests alone leave untouched methods red.
- Prefer composing the existing domain fold (`DrugCatalog`) over copying its filter logic into a new catalog type; key the map by `entryId + ":" + version` so no unreachable null branch is introduced.
