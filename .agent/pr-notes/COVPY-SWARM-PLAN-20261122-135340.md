## Findings

- The full `scripts/tests` suite is red in this cloud worker for reasons unrelated to this
  change (confirmed by running the affected modules in isolation):
  - `test_check_pack.py` — 6 failures, all `opencode.json is stale: run scripts/gen-opencode.py`.
    `git ls-files -v opencode.json` returns `S` (skip-worktree), so `agent-run.sh` installed the
    CI runtime profile over the worktree file; this is OPS-CW-003-01, a known worker false
    positive. The committed HEAD profile is generated correctly. Not fixed here: the integrator
    owns the full gate and `scripts/gen-opencode.py` is a protected file.
  - `test_worker_gate.py` / `test_worker_gate_coverage.py` — 2 errors,
    `FileNotFoundError: [Errno 2] No such file or directory: 'apps/api/target/surefire-reports'`.
    No Java build ran in this worker. Environmental, not a defect of this test file.
- Pre-existing conflict markers exist in three unrelated Java files
  (`apps/api/src/main/java/com/aurevia/smartclinic/exchange/hl7/Hl7ParseException.java`,
  `Hl7Parser.java`, `Hl7Segment.java`) at HEAD from `origin/swarm/BUILD-37-469`. They are outside
  this task's scope and were left untouched; no markers exist under `scripts/tests`.
- Coverage 7.17.4 had to be bootstrapped: the image has no `pip`/`ensurepip`, so the bundled
  `pip-24.0` wheel under `/__t/Python/3.11.18/.../ensurepip/_bundled/` was used with
  `PYTHONPATH` to install it, then `python3 -m pip install --break-system-packages coverage`.
  The tracked `.coverage` artifact was restored with `git restore .coverage` afterwards.

## Lessons for workers

- Before installing Python tooling in this image, check the bundled pip wheel under
  `/__t/Python/<version>/<arch>/lib/python*/ensurepip/_bundled/`; `pip` and `ensurepip` are absent
  and the shell denies `curl`, so bootstrapping from the local wheel is the reliable path.
- `coverage` rewrites the tracked `.coverage` file on every run; set `COVERAGE_FILE` to a
  temporary path or restore the artifact with `git restore .coverage` before committing.
- Measure your part with `coverage json` and filter `missing_lines`/`missing_branches` to your
  line range: the `coverage report` percentage for a whole shared script hides which task owns
  the remaining gaps.
- Do not treat the cloud worker's `check_pack` and `worker_gate` failures as defects of a
  test-only change; confirm with `git ls-files -v opencode.json` and a module-isolated run,
  record the command and final line, and leave the full gate to the integrator.
