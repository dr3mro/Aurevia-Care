# SPEC-CLN-04-C05 (fix pass) — Development captures milestone domain, observation and date

## Summary

The story's own deliverables were already on this branch from the first worker: a focused CLN-04 clause-5 Java API test (`DevelopmentCapturesMilestoneDomainObservationDateTest`, 7 tests), its clause evidence document, and that worker's notes. They passed 7/7 at the time they were written.

This fix pass resumes from the integrator's finding (issue #876 / PR #875, "fix attempt 1 of 3"): after merging current `origin/main`, the branch no longer compiled. Main extended the record `MessagingAuditContract.ExportRecord` from six to seven components by adding `ExportProvenance provenance`, but the main-owned test `OffboardingCommandTest` still used the six-argument constructor in four places. That broke Maven `testCompile` for the whole module, so the story's own test could no longer be verified and the pull request could not go green.

Repair applied — the smallest behavior-preserving change that unblocks compilation:

- Added the nested-type import `MessagingAuditContract.ExportProvenance` to `OffboardingCommandTest`.
- Added one synthetic constant `private static final ExportProvenance PROVENANCE = new ExportProvenance("tenant-archive", "rev-1", "offboarding")`, following the identical pattern in `MessagingAuditDomainTest` and `MessagingGovernanceServiceTest`.
- Passed `PROVENANCE` as the seventh argument at all four `new ExportRecord(...)` call sites.

No assertion, production class, contract, migration or tracker was changed. The consumer `OffboardingCommand.begin` reads only `export.id()`, `export.organizationId()` and `export.expiresAt()`; no code in `tenant/retention` reads `provenance()`, so no test outcome can change. Merging this branch into main also repairs main's latent compile break.

## Lessons for workers

- After merging main into a long-lived swarm branch, re-run test compilation even for a test-only story: main can change a record signature and a stale constructor call in an unrelated package breaks `testCompile` for the whole module.
- Check `git ls-files -v opencode.json` (flag `S`) before treating any `test_check_pack.*` / `check-pack.py` "stale" failure as your own; verify the committed profile with `git show HEAD:opencode.json` and leave the worktree file and protected generator scripts untouched.
- Swarm workers run targeted `-Dtest=...` suites plus the individual policy scripts and leave the full `verify` and integration tests to the integrator/Delivery.
- For CLN-04 clause tests, the implementation lives in `clinical.templates` (domain service plus `InMemoryTemplateStore`), not `chart/record`; reuse the fixtures and style of `TemplateNoteAcceptanceTest` and `TemplatePersistenceTest`.
