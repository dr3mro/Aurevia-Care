## Findings

1. **Delivery gap, not a behaviour gap (status = Proven by tests).** Every clause noun is implemented in `TherapyService` and durable via `JdbcTherapyStore` over V77/V85, but `TherapyController` publishes only accept and read; the tracking commands are invoked directly on the injected service and `/api/v1/therapy/episodes` is absent from `contracts/openapi.yaml`. The clause note records both gaps and estimates two follow-up tasks. No task was created and no production/contract/migration file was changed here.
2. **Story fallback vs. hard gate.** The story's step 3 asks for an `@Disabled("GAP: ...")` test when a clause is partly built, but `scripts/check-constraints.py:56` rejects any newly added Java `@Disabled` and `:108` scans untracked files in full (`scripts/tests/test_check_constraints.py:61-65` pins this). A new GAP-disabled test would fail the constraint gate and break the green pull request. The clause behaviour is fully built, so all tests are active and the gap is documented in the note instead.
3. **Brief vs. worker directive.** The brief's Done-when names `bash scripts/worker-check.sh`, but that script runs every integration suite and the known-false-positive `check-pack` stage. The worker directive forbids running every integration test; AGENTS.md directs workers to run targeted tests plus individual policy scripts and leave the full gate to the integrator. I ran the individual stages and recorded each result above.
4. **Environment false positive (confirmed once, not re-diagnosed).** `opencode.json` is under skip-worktree (`S`), so `check-pack`/`test_check_pack` report staleness against the CI profile; the committed profile is generated correctly. All 1181 other tooling tests pass.
5. **Optional review findings applied.** Code reviewer noted the generated contract advertises a stale `/api/v1/therapy/referrals/{id}/accept` path and `missing-routes.txt` baselines the two real routes; that detail is now in the clause doc's `## Gap`. Stylistic `assertEquals(true, note.signed())` was replaced with `assertTrue(note.signed())`. DevSecOps' Optional (no HTTP-level negatives for future tracking routes) is already disclosed as service-level in both notes and the clause doc.

## Lessons for workers

- Rehydration: before rewriting, check `git log --all -- <scope paths>` — a prior worker's green files may exist on an unmerged branch and can be restored verbatim, then verified against current `HEAD`.
- A new `@Disabled("GAP: ...")` in `src/test` fails `check-constraints.py`; document the gap in the clause note and keep the behaviour tests active instead.
- For a test-only API evidence task, `worker-check.sh` is not a single runnable gate: run the targeted `-Dtest=...` integration test plus each policy script individually, and prove the `opencode.json` false positive with `git ls-files -v` and `git diff --stat`.
- Pick a database name unique to the evidence class; re-read the episode version immediately before each state-changing service call so a stale precondition does not mask the behaviour under test.
