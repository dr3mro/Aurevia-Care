# SPEC-IAM-05-C02 — IAM-05 clause 2 API test

## Summary

Added a scoped, real-PostgreSQL HTTP integration test that proves IAM-05 clause 2 —
"A verified patient account may link to several independently verified charts" —
plus the clause evidence document. One verified patient account redeems three
distinct single-use invitations for three different verified charts; the rule is
checked through the `links` and `access` HTTP entry points under forced row-level
security. Negative tests show that a chart absent from the active tenant and a
different verified account are refused. No production code, existing test,
contract or migration was changed.

Files added (only these two are in task scope, plus this notes file):

- `apps/api/src/test/java/com/aurevia/patient/clauses/VerifiedPatientAccountLinkSeveralIndependentlyVerifiedTest.java`
- `docs/spec/clauses/patient/verified-patient-account-link-several-independently-verified.md`

Acceptance mapping (task steps 1–5): step 1 implementation survey → Findings 1–3;
step 2 positive + negative tests → `verifiedAccountLinksToSeveralIndependentlyVerifiedCharts`,
`chartAbsentFromTheActiveTenantCannotBeLinked`, `anotherAccountCannotClaimOrReadTheLinks`;
step 3 gap handling not needed (clause built, no `@Disabled`); step 4 clause doc with the
four required headings; step 5 checks under Test evidence.

## Findings

1. **Existing implementation and gap decision.** The clause is fully built:
   `IdentityProofingController` (routes `/api/v1/patient-identity/**`),
   `IdentityProofingService.links/hasAccess/linkWithInvitation`,
   `IdentityProofingRepository`, `IdentityActionPolicy`, `PatientAccount`,
   `ChartLink`, and `db/migrations/V10__patient_identity_proofing.sql` (`DISTINCT ON
   (org, account, chart)` fold, forced RLS, append-only triggers). Status in the clause
   doc is therefore `Proven by tests` and Gap is `None` for clause behavior. Evidence
   source: subagent reviewer plus direct file reads; no test was disabled.
2. **Pre-existing tooling false positive (environmental).** `git grep -nE
   '^(<<<<<<<|>>>>>>>) '` shows committed conflict markers inside Javadoc in
   `apps/api/src/main/java/com/aurevia/exchange/hl7/Hl7ParseException.java`
   (lines 6–10), `Hl7Parser.java` (lines 14–18) and `Hl7Segment.java` (lines 10–14).
   They are inside `/** ... */` comments, so `javac` and all Java tests pass; `git status`
   is clean, so they are already in HEAD, not introduced here. They are outside this
   task's scope and were left untouched — a separate task should resolve them.
3. **`opencode.json` check-pack false positive (environmental).** `git ls-files -v
   opencode.json` returns `S` (skip-worktree) and `git diff HEAD -- opencode.json` is
   empty; the six failing `test_check_pack` tests read the CI profile substituted over
   the worktree file. This is OPS-CW-003-01 in AGENTS.md/MEMORY.md. The file is
   protected and was not regenerated or edited. The integrator's full gate is authoritative.
4. **Public contract baseline.** The seven `/api/v1/patient-identity/**` routes are in
   `contracts/openapi/missing-routes.txt`, not `contracts/openapi.yaml`. This is a
   repository-wide, already-tracked contract task, not a gap in this clause's behavior;
   it is disclosed in the clause doc's `## Gap` section.
5. **Detection value (review finding).** The three-chart positive case is the new
   fault detection; the 403/409/404 negatives overlap existing
   `IdentityProofingIsolationTest` cases. The task explicitly requires a negative test,
   so they were retained as clause-local evidence.
6. **Package convention.** The task scope mandates `com.aurevia.patient.clauses`;
   `check-names.py` passes. The reviewer preferred the older `it.patientidentity`

## Lessons for workers

- A scoped clause test must keep the exact package path in its scope even when an older
  `it.<domain>` convention exists elsewhere; `check-names.py` accepts `clauses` because
  it is not an ID-shaped name.
- In this worker image, `check-pack` and six `test_check_pack` cases fail on
  `opencode.json` because the CI profile sits under skip-worktree. Confirm with
  `git ls-files -v opencode.json` (`S`) and record it; never regenerate that protected file.
- Run `git grep -nE '^(<<<<<<<|>>>>>>>) '` after a merge: committed markers inside Javadoc
  do not break `javac` and can hide in plain sight. Report them, but do not fix files
  outside the task scope.
- For test-only stories, there are no new JaCoCo branches to map; state that plainly
  instead of claiming a coverage run that the worker time budget forbids.
