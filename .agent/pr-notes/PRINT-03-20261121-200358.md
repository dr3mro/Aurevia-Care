## Summary

Added a pure domain kernel in `printing.chart` that builds a printable, versioned consolidated chart extract for one visit or one inclusive date range. It reuses existing domain types and the existing handout renderer rather than duplicating them: `ChartEntry` (chart.record), `NoteState.signatureBearing()` (clinical.notes), `ReleaseState.visibleAt()` (exchange.release), `HandoutService` / `HandoutKind.CHART_SUMMARY` (printing) and `ArtifactInputs` / `PdfRenderer.direction()` (documents). The extract contains demographics, allergies (including explicit absent/unknown), active problems, active medications, vitals with value/unit/time, signature-bearing notes and currently-visible released results. Unsigned drafts, entered-in-error notes and withheld, withdrawn, corrected or not-yet-effective results are excluded and recorded as non-sensitive reasons for the preview. Null tenant, scope, demographics and projection times fail with a structured 422 rather than a null-pointer error. The clinician's section choice is part of the content checksum, so it is recorded with the immutable handout version. English and Arabic are supported; Arabic renders RTL.

Files (all inside the declared scope):

## Affected requirements

- CLN-03: structured chart families (allergies, active problems, medications, vitals with unit and measurement time), presence assertions and provenance carried from `ChartEntry`.
- CLN-05: only signature-bearing note revisions print; unsigned drafts are excluded with a `UNSIGNED_DRAFT` reason; entered-in-error and amendment drafts are not signature-bearing.
- CLN-07: immutable versioned A4 PDF in English or Arabic with direction-aware layout, embedded fonts and provenance, produced through the existing `HandoutService` / `PdfRenderer`.

Acceptance mapping: draft exclusion → `excludesUnsignedDraftNotesAndWithheldResults`; withheld-result exclusion → the same test plus `aFutureAuthorizedResultIsNotYetVisible`; section choices recorded → `sectionChoiceChangesVersionAndIsRecorded`; Arabic layout → `arabicExtractUsesRightToLeftLayoutAndArabicLabels`; range filter → `rangeFilterExcludesFactsOutsideRange` and `clinicalTimeFallsBackThroughEffectiveFromRecordedAtAndEpoch`.

## Risk class

Cross-boundary domain kernel: it reads vocabulary from chart.record, clinical.notes and exchange.release and delegates PDF versioning to printing. The release exclusions are safety-relevant (withheld results and unsigned drafts must never reach a patient handout) and are covered by explicit negative tests. No live release enablement, no real-patient or clinical-participant evidence is claimed.

## Authorization boundaries and audit events

Tenant scope: `extract()` rejects a null actor (403 FORBIDDEN) and an actor whose `organizationId()` differs from the request tenant (403 WRONG_TENANT), matching `HandoutService`. Language and scope selectors are validated before any render. No role is checked here — the HTTP print permission is PRINT-02's scope. No audit event is added by this kernel; the rendered handout metadata records `producedBy` and `producedAt` via `HandoutService`. Excluded items carry only a section key, an opaque item id and a stable reason key — never withheld clinical content.

## Clinical and architecture review

No real clinical or patient-participant review was performed; this is synthetic engineering evidence. A bounded read-only simulated `aurevia-senior-backend` subagent reviewed all five new files (evidence source: reviewer, not a tool run) and returned **no blocking findings**. It confirmed the release rules, scope/active filtering, deterministic versioning, defensive copies, SpotBugs-safe constructors and the `ChartExtractConfiguration` wiring. Its three non-blocking findings were all addressed before the final commit:
1. Null tenant / scope / demographics / projection times could escape as NPE or 500 — now explicit `ApiException(422, "INVALID_REQUEST", …)` guards, covered by `rejectsNullBoundaryValuesWithStructuredErrors`.
2. `NoteState.ENTERED_IN_ERROR` and `ReleaseState.CORRECTED` were unproven; entered-in-error notes were labelled as unsigned drafts — both values now appear in `excludesUnsignedDraftNotesAndWithheldResults`, with a dedicated `ExclusionReason.ENTERED_IN_ERROR` so the preview states the correct reason.
3. An unqualified Javadoc `{@link}` in the test file (not scanned by tooling) — now fully qualified.

The reviewer also noted that the skill's full "Done" gate (Flyway/RLS migration, `Jdbc*Store`, thin controller, HTTP integration test, OpenAPI entry) is intentionally not satisfied by this kernel: the task scope assigns HTTP wiring to PRINT-02/PRINT-07, and no new table is required because the extract is derived from existing chart data. The release exclusions follow the existing `NoteState.signatureBearing()` and `ReleaseState.visibleAt()` domain rules rather than new free-text rules, so clinical sign-off for live patient release remains a separate G5 gate and is not asserted here.
