## Lessons for workers

- When a fix pass finds the branch equals `origin/main` on all scoped content and
  the targeted tests are green, the correct action is to verify and record
  completion evidence — not to re-apply the fix or add another notes-only
  re-verification commit. Repeating the re-merge or re-documenting a deliberately
  removed API defeats the earlier owner revert.
- `git rev-list --left-right --count HEAD...origin/main` plus an empty
  `git diff origin/main -- <scoped files>` is the fastest proof that a stale-merge
  fix is fully present before spending time on tests.
- A red `check-pack: opencode.json is stale` in a cloud worker is the skip-worktree
  CI profile, not a change defect. Confirm with `git ls-files -v opencode.json`
  and `git show HEAD:opencode.json`; a temporary, trap-restored swap to the HEAD
  bytes proves both pack checks green without editing the committed file.
- The draft/ready decision in `scripts/swarm.py publish()` is driven by the agent
  result and the worker-gate result, not by whether the notes contain a
  "Why this is not finished" heading; the agent-run wrapper restores HEAD config
  before running that gate. Do not expect a notes heading alone to break or cause
  a re-dispatch loop.
- The module `check.sh` scripts install pinned dependencies with `npm ci` when
  `node_modules` is absent; unset `CHECK_SCRIPT`, `BRANCH_PREFIX` and
  `BASE_BRANCH` when running them directly, and capture `npm run typecheck`
  separately for the mandatory frontend definition of done.
- Do not run the full `mvn verify` or whole integration suite as a worker; run
  only the touched test classes and leave the full gate to the integrator.
