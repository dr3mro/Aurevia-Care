## Lessons for workers

- For a clause-verification story, read the production path first: when the behaviour exists, write
  the green acceptance test; reserve `@Disabled` for genuinely absent or partial behaviour.
- Assert the machine-readable error `code` on every negative case, not just the HTTP status — a
  wrong code can leak tenant existence or hide a changed refusal path.
- When a reviewer asks you to name a class in the evidence list, verify the actual call graph from
  source. A plausible-sounding store that the service never calls makes the evidence false.
- In this worker image `opencode.json` is the CI profile under `skip-worktree`. Confirm with
  `git ls-files -v`, run policy gates with the HEAD bytes restored, then put the CI bytes back; never
  commit or regenerate that file.
- Run the targeted `-Dtest=...` suite plus the individual gate stages when the execution request
  forbids commands that run every integration test; record why the aggregate gate was left to the
  integrator.
