## Lessons for workers

- When a fix PR stays red across many rounds and local checks are green, inspect
  the **merge mechanics** before re-running tests: `guard()` in `scripts/swarm.py`
  re-runs on every integration pass, and `MAX_PR_FILES` labels any PR with more
  than 30 changed files `needs-human`. Repeated notes files alone can permanently
  block a PR.
- A PR diff is base-vs-head tree state: a file added and later deleted on the
  branch is not in `gh pr diff --name-only`. Consolidating redundant notes files
  can genuinely lower the file count (deleting them is not the same as leaving
  them).
- Always distinguish three failure classes before claiming "hand off": (1) a real
  in-scope defect (fix it), (2) a pre-existing out-of-scope regression on `main`
  (owner fixes it), (3) a PR-mechanics blocker such as `needs-human` (maintainer
  clears it). This loop persisted because rounds 1–23 only ever classified (2).
- In this cloud worker `opencode.json` is a skip-worktree CI profile. Never
  regenerate or commit it; verify HEAD truth with `git show HEAD:opencode.json`.
- A targeted `mvn -Dtest=... test jacoco:report` is the correct worker coverage
  command; the full `mvn verify` / every integration test is the integrator's.
- Re-derive the 100% JaCoCo numbers from `apps/api/target/site/jacoco/jacoco.xml`
  rather than trusting a prior note; the export package was 0-missed on this pass.
