## Findings

- The plan reviewer's first pass was NO-GO with two Required gaps: (1) the original
  exception was unbounded (any FK to `organization` would pass) and (2) the insert
  execution context was implicit. Both were fixed: the exception set is now pinned to
  exactly `exchange_authorization.destination_org`, `exchange_order.destination_org`
  and `exchange_work_item.destination_org`, and the Javadoc/assertions state that both
  inserts run as `orevia_migrate` with `app.current_org`/`app.actor` bound and
  require SQLSTATE 23503 rather than 42501/23514. The re-review returned GO.
- The `organization` registry table itself has a column named `organization_id`, so a
  naive "parent has organization_id" test would misclassify the three `destination_org`
  FKs; the final test pins the exact exception set instead.
- pgjdbc bound `setString` as `varchar`, whichPostgreSQL rejects for a `uuid` column;
  the two membership inserts now use `CAST(? AS uuid)`.
- Pre-existing and out of scope: `origin/main` contains committed conflict markers
  inside a Javadoc comment in `exchange/hl7/Hl7ParseException.java`, `Hl7Parser.java`
  and `Hl7Segment.java`. They compile as comment text; they were not touched.
- After the reviewers returned GO, three Optional hardening notes were applied: the
  `seedUser` fixture now binds parameters instead of concatenating SQL, the catalog
  assertions use exact comma-token matching rather than substring `contains`, and the
  doc no longer claims a Spring context or controller is exercised. The targeted test
  was re-run after these edits: exit 0, Surefire `tests="2" errors="0" skipped="0"
  failures="0"`; `check-docs.py`, `check-secrets.py`, `check-constraints.py` and
  `check-names.py` remained exit 0.

## Lessons for workers

- Pin schema-rule exceptions to an exact allowlist, not a broad category: an unbounded
  "targets the global registry" exception would let a new cross-tenant pointer pass.
- A catalog assertion needs a count floor and a known-FK sentinel, otherwise a broken
  query returning zero rows passes vacuously.
- In pgjdbc, use `CAST(? AS uuid)` or `setObject(UUID)` when inserting into `uuid`
  columns; `setString` alone fails with "column is of type uuid but expression is of
  type character varying".
- OPS-CW-003-01 recurs: confirm the `S` flag and CI-profile hash once, then run the
  remaining gate stages individually instead of re-diagnosing or editing `opencode.json`.
