## Findings

1. **Fixed — checkpoint version not bound (MEDIUM, correctness/state-machine).** Reviewer
   evidence: `ControlledImportService.java` used `ImportProgress` only for
   `hasCommitted`/`recordBatch`; `manifestVersion` was never compared. A stale v7
   checkpoint resumed against v8 reported all sequences `ALREADY_COMMITTED`, staged
   nothing and could still be finalized. Fix: report-level refusal in `commitBatches`
   (new `CommitReport.reason`) and a `refused(progress, "version")` branch in `signOff`,
   each with a negative test. Evidence source: simulated reviewer (file reads), fixed
   and verified by tool runs.
2. **Fixed — sign-off trusted client-supplied identity (MEDIUM, trust boundary).**
   Reviewer evidence: `/api/v1/**` is authenticated, but authorization read only
   `signOff.role()`/`approver()` from the body; an authenticated user could assert a
   role and another user's name. Fix: the controller now binds `approver` to
   `TenantContext.current().subject()` and refuses an absent or different subject.
   Full verification of the claimed role against a verified membership needs the
   identity boundary and is requested as a follow-up task below. Evidence source:
   simulated reviewer, fixed and verified by tool runs.
3. **Deferred (LOW) — reverse after sign-off returns HTTP 500.** `ControlledImportService.reverse`
   throws `IllegalStateException`, which `ApiErrorHandler` maps to 500 rather than the
   409 that ARC-04/ARC-05 prescribe for an invalid transition. Outside this story's
   acceptance criteria; requested as a follow-up task below. No change made.
4. Environment artifact (not a change defect): `check-pack.py` / `test_check_pack`
   failures are the skip-worktree CI `opencode.json` profile (`git ls-files -v` = `S`);
   HEAD's committed profile was left byte-for-byte untouched.
5. `check-docs.py` failure at `docs/reference/partner-api-guide.md:200` is a
   pre-existing out-of-scope defect from commit `b6031d34`; the owning document's
   task should fix it, not BUILD-44.
6. Deliberate scope boundary: client-held checkpoint, no new persistence/JDBC/RLS,
   no OpenAPI/client regeneration. V90 `import_record_provenance` from BUILD-43 is
   the durable target; the evaluator owns global batch-plan validity while this
   slice reconciles each batch's count and hash.

## Lessons for workers

- With no findings in a fix-pass prompt, a bounded independent specialist review can
  surface real acceptance defects that pass coverage; act on impact + evidence, not
  on whether a diff already exists.
- A `manifestVersion` field that exists to bind a checkpoint is worthless unless
  every consumer checks it; add the negative test at both the resume and finalize
  entry points.
- Authorization derived from a request-body `role` string is self-assertion; bind
  the named approver to the authenticated subject, and route verified role lookup
  to the identity boundary when a store is needed.
- In a cloud worker, `check-pack.py` / `test_check_pack` failures and an early
  `scripts/check.sh` exit are usually the skip-worktree CI `opencode.json` profile;
  confirm with `git ls-files -v` and `git show HEAD:opencode.json`; never regenerate
  or commit `opencode.json` from a worker.
- A docs-check failure on a file outside `scope` is not this story's to fix; record
  the introducing commit under Findings and move on.
