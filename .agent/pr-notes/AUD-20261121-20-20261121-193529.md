# AUD-20261121-20 — Extract the duplicated SHA-256 digest and blank checks in tenant/importing

## Summary

`ControlledImportService` and `OnboardingImportService` each contained a byte-for-byte
copy of a private `sha256(byte[])` method (manual lowercase-hex encoder), a
`private static final char[] HEX`, and a private `isNonBlank(String)`. These compute the
canonical digests that validate import signatures and manifest content, so two
independent copies could drift and silently change an attestation/checksum rule.

Added one shared primitive, `com.aurevia.smartclinic.tenant.importing.ImportDigests`,
which owns the single `HEX` encoder, the lowercase-hex SHA-256 computation and
`isNonBlank`. Both services now hold an injected `ImportDigests`, route every hash
through a package-private `digest(byte[])` delegator, and call
`ImportDigests.isNonBlank(...)` directly. The duplicated private methods, `HEX`
constants and the nested `DigestFactory` (moved into `ImportDigests`) were deleted.
`api/contract` was deliberately NOT used: that boundary belongs to the separate
AUD-20261121-13 story and is outside this task's declared scope. The `[0-9a-f]{64}`
validation regex at `OnboardingImportService` is also left untouched (AUD-20261121-13).

New tests: `ImportDigestsTest` (known SHA-256 vector in lowercase, fail-closed path,
`isNonBlank` null/blank/text) and `ImportDigestParityTest` (a fixed-output `MessageDigest`
stub proves both services return the same lowercase hex for the same bytes, and both
throw the same `IllegalStateException` message when the algorithm is unavailable).
The two pre-existing failing-factory tests were migrated to wrap their lambda in
`new ImportDigests(...)`.

## Findings

- Bounded senior-backend reviewer returned **no actionable findings** (simulated reviewer;
  static review of the in-scope diff, no execute tool). It confirmed the encoder is
  byte-for-byte identical to the repository's canonical `messaging.evidence.EvidenceHash`
  (nibble encoding correct for negative bytes, same `IllegalStateException("SHA-256 is
  unavailable", cause)`), so caller output is unchanged; migration is complete with no
  leftover private helpers; controllers still inject the services and Spring's
  default-constructor resolution stays unambiguous (no `ImportDigests` bean required).
  It also found no `CT_CONSTRUCTOR_THROW`, `MS_MUTABLE_ARRAY` or `EI_EXPOSE_REP` concern,
  and no new Javadoc link/ID-name issue. Source: subagent review report.
- Shared primitive intentionally lives in `tenant/importing`, not `api/contract`: the
  latter is AUD-20261121-13's separately owned scope, and the task permits reusing it only
  if owned separately. This story therefore does not overlap that story's four
  `[0-9a-f]{64}` regex callers.
- `ImportDigests` is package-private at the method/constructor level; it is a single-package
  primitive with no cross-module caller, so no new public API or wiring is introduced
  (`scripts/check-wiring.py` stays green with no baseline change).
- The one-line `digest(byte[])` delegator in each service is a deliberate package-private
  seam that keeps all hashing flowing through the shared primitive and makes the
  "identical output from both callers" acceptance criterion directly testable.
- Pre-existing environment noise (not change defects): 5 `test_check_pack` failures from
  the CI-profile `opencode.json` skip-worktree artifact; OWASP/NVD unavailable locally.
  Left to the integrator/owner exactly as the newest reconciled daily note records.

## Lessons for workers

- When two services in one package carry byte-identical private helpers, extract one
  package-level primitive that owns both the algorithm seam (`DigestFactory`) and the
  encoding, then keep only a thin package-private delegate in each caller; this preserves
  the existing injected-failure tests while making the rule single-sourced.
- A fixed-output `MessageDigest` stub is a deterministic way to assert that two callers
  produce byte-identical lowercase-hex output, without depending on real hash values or
  timing/races.
- Confirm a "red" policy check is the CI-profile `skip-worktree` artifact with
  `git ls-files -v opencode.json` and `git show HEAD:opencode.json` before regenerating
  anything; never commit that file from a worker.
