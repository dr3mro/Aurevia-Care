## Lessons for workers

- For a finance state test, a PAID invoice void returns 409 `INVALID_TRANSITION`
  (legal-transition guard); 422 `VOID_AFTER_POSTING` is reachable only from ISSUED
  **with ledger entries** — pay fully, then fully refund to restore issued.
  Assert both codes or a wrong implementation passes.
- `EntryRequest.reference` is mandatory and is validated before authorization:
  a wrong-role negative with an empty body returns 422, not the 403 it is meant
  to prove. Always send a complete, unique body on negative HTTP tests.
- Finance mutating responses are `{invoice, items, entries}` and list responses
  are `{items, nextCursor}`; the scheduling harness's flat `$.state` path does
  not apply. Use a pointer helper such as `text(response, "/invoice/state")`.
- To prove a cross-tenant 404, the peer actor must hold the action's permission;
  a low-privilege peer returns 403 at authorization first.
- `mvn -Pno-security,fast -Dgroups=integration` silently runs zero integration
  tests (`fast` sets `excludedGroups=integration`); always confirm the Surefire
  count from a run without `fast`. A bare `spotbugs:check` is vacuously green —
  compile first.
- In this cloud worker, `opencode.json` is under `skip-worktree` (`git ls-files
  -v` shows `S`); `check-pack.py` and the six `test_check_pack` unit tests judge
  the CI runtime profile, not the committed one. Verify once with
  `git show HEAD:opencode.json` and do not regenerate the generated file.
