# SPEC-XCH-02-C02 — XCH-02 clause 2 API evidence

## Summary

Added HTTP-level test evidence that a clinical exchange-task acknowledgment is
made only by an authorized clinician and is bound to that acting human, the
injected clock timestamp and the exact reviewed revision. The clause was already
implemented in `exchange.task` and `db/migrations/V20__exchange_task_states.sql`;
this is a test-only, two-file story. No production code, existing test,
migration, contract or generated client was changed. All fixtures are synthetic.

## Affected requirements

XCH-02 — sentence proven: "Acknowledgment is made by an authorized human with
timestamp and revision." Acceptance mapping:

- authorized human → `receptionCannotAcknowledge` (403), `labCollectorCannotAcknowledge` (403),
  `otherTenantClinicianCannotAcknowledge` (404), positive actor assertion against
  `user_identity.id`.
- timestamp → `reviewedAt` asserted equal to the fixed clock instant in the
  response, the task row and the spoof negative.
- revision → `reviewedRevision` / `clinical_revision` asserted equal to the exact
  version carried by `If-Match`; `staleRevisionCannotAcknowledge` (412) and
  `missingIfMatchCannotAcknowledge` (428) cover the failure paths.

No clinical sign-off, human participant or real patient data is involved.

## Authorization boundaries and audit events

The test reuses the `synthetic-auth` profile and the `X-Synthetic-Subject` /
`X-Active-Organization` / `If-Match` headers of `ExchangeTaskIsolationTest`.
It proves tenant isolation (ORG_A vs ORG_B forced RLS), clinician-only clinical
review authorization, and that the acting actor is derived from the transaction
context by V20 rather than accepted from the request body. It asserts the
`EXCHANGE_ACKNOWLEDGE` / `SUCCESS` audit row and the `clinical_review` transition
row with its derived actor. No audit event was added or changed in production.

## Migration and rollout considerations

None. V20 already supplies ENABLE/FORCE RLS, the guard trigger that requires a
revision and timestamp for a clinical change and derives the actor from
`app.actor`, and the transition actor trigger. No migration version was reserved
or consumed.

Branch-to-test map for the production decisions the clause depends on (all
branches already existed on main; none introduced by this change):

- Clinician-only clinical review allowlist (`ExchangeActionPolicy.allows`,
  clinical branch true) → `acknowledgeByClinicianBindsHumanClockAndReviewedRevision`
  (200, derived actor/clock/revision in response and row).
- Clinician-only allowlist false for reception → `receptionCannotAcknowledge`
  (403, row unchanged).
- Clinician-only allowlist false for lab collector → `labCollectorCannotAcknowledge`
  (403, row unchanged).
- Active-membership check (`ExchangeTaskService.authorize`) true on all allowed
  calls; the revoked-membership false side is covered by the pre-existing
  `ExchangeTaskIsolationTest.revokedMembershipDeniesTheNextProtectedRequest`.
- RLS concealment / `loadForUpdate` empty → `otherTenantClinicianCannotAcknowledge`
  (404, ORG_A row unchanged).
- Version precondition mismatch (`ExchangeTaskService.requireVersion`) →
  `staleRevisionCannotAcknowledge` (412, row unchanged).
- Absent `If-Match` (`IfMatch.parse`) → `missingIfMatchCannotAcknowledge`
  (428, row unchanged).
- Clinical reviewed revision binding (`reviewedRevision = current.version()` in
  `ExchangeTaskService.execute`) → positive test asserts 1 in response, row and
  transition; spoof test asserts the same against forged JSON fields.
- Clinical timestamp binding (injected `Clock`) → positive and spoof tests assert
  `reviewedAt` / `clinical_reviewed_at` equals the fixed instant.
- Clinical actor derivation (V20 `xch02_actor_id()` from `app.actor`) → positive
  and spoof tests assert `reviewedBy` / `clinical_review_actor_id` / transition
  `actor_id` equals the clinician's `user_identity.id`, never the subject string.
- `TransitionRequest` has no actor/timestamp/revision field →
  `requestBodyCannotSpoofReviewEvidence` proves extra JSON fields are ignored.

Non-vacuity (test-engineer review, tool-backed Surefire count): every assertion
uses a value a broken binding would change — DB-derived `user_identity.id` vs the
textual subject, the fixed instant vs the wall clock, revision 1 vs the forged
99 / stale 2, and 403/404/412/428 vs 200. All five refusal tests use
`assertAcknowledgmentRefused`, which re-reads five evidence columns plus the
version and asserts zero `clinical_review` transition rows, distinguishing a
refusal with no write from a refusal after a partial write. Adjacent service
branches not needed for this clause (inactive membership, CAS lost update,
illegal transition) remain covered by the pre-existing
`it/exchangetask/ExchangeTaskServiceTest`. No test is skipped, disabled or
order-dependent; each task is seeded per case so JUnit method order cannot affect
an assertion. No coverage threshold, exclusion or suppression was added.

## Lessons for workers

- When seeding a cross-tenant negative, put the target row in the *other*
  tenant's schema scope and call with the actor active in their own tenant; a
  row seeded in the caller's own tenant legitimately returns 200 and the test
  fails for the right reason.
- Read the helper's return type before wrapping it: `get()` in
  `ExchangeTaskIsolationTest`-style fixtures already returns a parsed `JsonNode`,
  so `json(get(...))` is a compile error.
- Confirm `opencode.json` staleness once with `git ls-files -v`, `cmp` against
  `.github/opencode.ci.json` and `git show HEAD:opencode.json`; then run the
  remaining worker-check stages individually instead of re-diagnosing or
  regenerating the protected file.
