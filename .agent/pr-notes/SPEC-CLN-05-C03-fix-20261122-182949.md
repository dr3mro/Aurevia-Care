## Lessons for workers

- When a fix pass is notes-only, verify whether the current tree is already gate-green before
  assuming the reported cause still holds: `bash scripts/quality-gate.sh origin/main <notes>` and
  `git merge-base --is-ancestor <fix-sha> HEAD`. A stale findings file from an earlier attempt can
  describe a blocker that a later upstream commit has already removed; re-filing its task request
  creates spurious work.
- The verdict gate fails closed when a non-docs file (here the scoped `.java` test) is in the diff
  against the base: `scripts/check-verdicts.py:75-77` requires a `## Review verdicts` section with one
  `aurevia-` prefixed GO line per required reviewer. Put that section last so no following `##`
  heading truncates it, and never place `Critical:` or `Required:` lines inside it.
- Do not run full `mvn verify` in a swarm worker: run the targeted `-Dtest=ClassName` test plus
  individual policy scripts and standalone SpotBugs (`-DskipTests compile spotbugs:check`), and leave
  the full gate and JaCoCo 1.00 check to the integrator. A bare `spotbugs:check` without compile is
  vacuously green, and `-Pfast` can hide integration tests.
- In a cloud worker, `git ls-files -v opencode.json` showing `S` explains `check-pack.py` and
  `scripts/check.sh` failures: verify with `git show HEAD:opencode.json` and never regenerate or commit
  that protected file.
