## Lessons for workers

- For a documentation task, read the checker before writing: `scripts/check-docs.py` validates relative links, requirement IDs and structure (heading jumps, unbalanced fences, ragged tables, token-shaped strings, unclosed comments). Mirroring an existing checked-in runbook avoids all of them at once.
- Confirm every cited job name, test name and log string by grepping the tree. A near-miss name was caught and corrected by the first worker before review; this pass re-confirmed all of them.
- When an earlier worker's deliverable already passes its gate, verify rather than rewrite: re-run the gate, grep each concrete claim, and add the fix-pass hand-off notes instead of churning the document.
- A read-only specialist may claim a workflow wiring that another has disproved; grep `.github/` and `scripts/*.sh` for the flag or symbol before stating that a check runs on GitHub.
- Do not run `scripts/check.sh` in a swarm worker; the Markdown gate for a docs-only change is `python3 -I scripts/check-docs.py`.
