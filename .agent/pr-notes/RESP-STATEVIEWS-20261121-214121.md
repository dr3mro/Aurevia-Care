# RESP-STATEVIEWS — Staff web: responsive `StateViews` component

## Summary

Made the seven required staff-web state views (loading, empty, error, timeout,
forbidden, conflict, session-expired) responsive at compact, medium and expanded
layouts in LTR and RTL. `StatePanel` now uses the existing `page` utility for
safe-area-aware logical padding and a centred reading measure, adds a logical
inline-style centring/reading column (no dedicated state-panel class exists in
`responsive.css`), exposes `data-breakpoint` for structural tests and wraps long
English/Arabic text instead of truncating it. State action buttons are wrapped
in `touch` grid targets inside a `stack` (phones) or `cluster` (medium/expanded)
row, so they are full width on phones and reach the 44 px coarse-pointer floor
via the existing stylesheet. No exported name, label, callback or transport
behaviour was changed. Added a dedicated responsive test file that mocks
`matchMedia` for all three bands and asserts structure, roles/labels, keyboard
order and RTL isolation.

## Lessons for workers

- `responsive.css` provides `page`, `stack`, `cluster`, `touch`, `grid-2`,
  `card-list`, `field`, `sheet`, `app-shell`, etc., but **no state-panel/centring
  utility**. For centred state views use `className="page"` for safe-area
  logical padding plus logical inline styles (`place-items: center`,
  `text-align: start`, `max-inline-size: 44rem`, `overflow-wrap: anywhere`,
  `min-inline-size: 0`); propose a `.state-panel` utility in a separate story
  rather than editing the stylesheet from a component task.
- To make a native `Button` full width on phones and 44 px on a coarse pointer
  without editing `Button.tsx`, wrap it in `<div class="touch" style={{display:'grid'}}>`
  inside a `.stack` (phones) or `.cluster` (medium/expanded). The flex column
  stretches the wrapper, the single grid column/row stretches the auto-sized
  button, and `.touch` supplies the coarse-pointer floor. Do not add a new CSS
  rule or pass a new prop to `Button`.
- jsdom cannot paint pixels. Assert the `stack`/`cluster`/`touch` classes,
  `data-breakpoint`, logical inline-style strings, roles, labels and DOM focus
  order; leave measured 44 px widths, 320 px reflow and 200 percent zoom to the
  Playwright responsive tasks.
- When two state views are rendered inside one `it`, call `unmount()` between
  them; Testing Library cleanup runs per test, not per render.
- `apps/staff-web/check.sh` stops at `gen:api:check`. If that fails from
  contract/client drift outside your scope, prove it is pre-existing by stashing
  your files and rerunning, then run `typecheck`, `lint`, `build`,
  `check-bundle-size.mjs` and `test:coverage` individually and paste each final
  line. Do not regenerate generated types from an unrelated story.
