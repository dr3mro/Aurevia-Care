# FIX-OPENAPI-01 — Refreshed route-parity baseline for routes added by parallel workers

## Summary

The route-parity gate from the earlier FIX-OPENAPI-01 pass was already merged
(commits `faba1353`, `ef78576f`), but it was **red on current `main`**: parallel
workers added controller routes after the baseline was captured. This pass
refreshes `contracts/openapi/missing-routes.txt` with those 16 routes so the gate
is green again. No production code, controller, contract, migration, dependency,
coverage threshold or exclusion was changed. All evidence below comes from
executed tools; a bounded `orevia-test-engineer` review was requested. No
simulated user or human participant was involved.

- Baseline: **322 → 338** `METHOD /path` entries (16 insertions, 0 deletions), still sorted and unique.
- Newly baselined routes: pharmacy substitution proposals (PHARM-04, commit `5928080d`), versioned staff mail (SMSG-05, commit `2777558b`), and the source-address-gated `GET /health/metrics` scrape.
- The gate did exactly what the story asks: it failed the build and **named** each new undocumented route. The in-scope debt list is the mechanism for recording it; FIX-OPENAPI-02/03/04 will document these routes and shrink the list again.

## Findings

1. **The merged gate broke because parallel workers added routes.** SMSG-05
   (staff mail, 11 routes), PHARM-04 (pharmacy substitutions, 4 routes) and a
   metrics endpoint (`GET /health/metrics`) landed after the baseline was
   captured — exactly 16. The gate correctly failed and named them; this pass
   records them as debt. FIX-OPENAPI-03 owns the 11 mail routes and
   FIX-OPENAPI-04 owns the 4 substitution routes plus the metrics route.
2. **`worker-check.sh` and `check.sh` cannot complete in this cloud worker.**
   `git ls-files -v opencode.json` → `S` (skip-worktree); HEAD sha256 starts
   `0dc2ac8e…`, worktree sha256 starts `50005c9c…`. `check-pack` therefore
   judges the CI profile copied under `skip-worktree`, not HEAD. Out of scope
   (worker rules forbid editing `opencode.json`, `.opencode/` and `scripts/`);
   previously recorded as OPS-CW-003-01. All later gate steps were run
   individually in the earlier pass; this pass ran the two affected test
   classes directly.
3. **`GET /health/metrics` sits outside `/api/v1`.** WEB-05 names only
   `/health/live` and `/health/ready` as routes outside the versioned prefix.
   `web/MetricsController.java:43` and `web/SecurityConfiguration.java:113`
   gate the scrape by source address. This is a pre-existing design decision,
   not introduced here; it is baselined rather than silently dropped so the
   contract/route mismatch stays visible. No task in `tasks/` covers resolving
   it, and it is outside this task's scope; a task-request is recorded below so
   the integrator can give the decision an owner instead of leaving permanent
   debt.
4. The earlier pass made out-of-scope repairs (V91→V92 migration renumber, a
   Javadoc reference and a spec-doc reference) that are already merged in
   `main`; this pass did not touch them.
5. **`git grep -nE '^(<<<<<<<|>>>>>>>) '` still reports conflict markers in
   `main`, in `apps/api/src/main/java/com/aurevia/exchange/hl7/`
   (`Hl7ParseException.java`, `Hl7Parser.java`, `Hl7Segment.java`).** They are
   inside Javadoc text, already committed in HEAD, and were NOT introduced by
   `git merge --no-edit origin/main` (which reported `Already up to date`). They
   do not break compilation — the parity test compiled and passed — but they
   are a real documentation defect from a parallel merge. Fixing them is outside
   this task's strict scope, so it was left for the owning story/integrator.
6. **Green parity does not close the open route/evidence defects.** BUGS entries
   `WEB-05-INSTANT`, `WEB-05-MERGE-GAP` and `OPS-PARITY-CLASSIFICATION` remain
   open; the last one notes that the worker gate cannot distinguish a newly
   introduced gap from existing debt. This fixture refresh does not address
   them.
7. **Contract-authority interpretation is still awaiting owner confirmation.**
   The earlier pass chose `contracts/openapi.yaml` (X-01 staff-API contract)
   over the X-04 command catalogue and asked the integrator/owner to confirm it
   before FIX-OPENAPI-02..04; no confirmation is recorded and TODO still shows

## Lessons for workers

- A route-parity baseline must be refreshed from the live gate failure, not
  hand-edited: take the "Controller routes missing from the contract" section of
  the surefire failure, union it with the existing baseline, sort, and re-run.
- The gate is supposed to go red when another worker adds a route. Read the
  `NEW undocumented controller routes` section before concluding the gate is
  broken; the fix is to document the route or record it as debt, not to weaken
  the gate.
- Prove both directions with the real context: remove one baseline line and
  add one documented line, then restore. Synthetic unit tests alone do not
  prove the Spring enumeration path.
- In a cloud worker, check `git ls-files -v opencode.json` before investigating
  a `check-pack: opencode.json is stale` failure; it is a skip-worktree
  measurement artifact, not a change defect.
