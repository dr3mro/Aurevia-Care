## Summary

Added one HTTP-level integration test class and one honest evidence document for the
last sentence of ARC-01 (`PROJECT_V1_SPEC.md:116`): "Record clinical effective
time, ingestion time, author, source system, source ID and version where applicable."

## Findings

1. The brief says the create case returns 201; the running route returns 200
   (confirmed by `ClinicalNoteRevisionIntegrationTest.java:201` and this run). The
   test and document use 200. The brief is guidance, not a rule to follow against
   observed behaviour.
2. The brief's `forgedAuthorOrWrongRoleIsRefused` case cannot be written green on
   this route: `clinicalAuthorSubject` is caller-declared text constrained only by
   a tenant FK, so an unknown/cross-tenant author becomes SQLSTATE 23503 → HTTP 500
   (`ClinicalNoteService` does not call `SqlFailureTranslator` and `ApiErrorHandler`
   has no `DataIntegrityViolationException` handler). The wrong-role half is tested
   (403); the author-forgery half is documented under `## Gap` with a separate
   production task. No `@Disabled` test was added.
3. Source system, source ID and source-document version are not on the clinical-note
   route. The document names the actual sites (V25 trending behind
   `POST /api/v1/trends/observations`, V23 critical results, V17 document
   associations, V90 onboarding import and its controllers, `ExportModel.Provenance`)
   and avoids the brief's "only import/export" wording. The committed contract has
   no `/api/v1/clinical-notes` path and no consolidated provenance schema.
4. Known worker-image false positive: the tooling pack check judges the CI profile
   installed under `skip-worktree`, not HEAD's committed profile. Confirmed once
   with `git ls-files -v`, `.github/opencode.ci.json` and `git show HEAD:opencode.json`;

## Lessons for workers

- Trust the running route over a brief's HTTP status: clinical-notes create returns
  200, not 201; check the neighbour test's asserted status first.
- The repository re-reads the stored instant, so a response `effectiveAt` uses
  PostgreSQL text form (`2024-06-01 10:15:30+00`), not the submitted ISO text
  (`2024-06-01T10:15:30Z`). Assert a prefix or compare parsed instants, not equality
  with the submitted string.
- A caller-declared author protected only by a foreign key becomes a 500 when the
  service does not translate the FK. Do not write a "refused" test expecting a 4xx
  against such a route; document the gap and request a production task.
- `@Disabled("GAP: …")` on a new Java file fails `check-constraints.py`; pick a
  running slice, write green tests there and put the uncovered fields in the doc.
- Copy the neighbour DB harness but give each clause test its own database name and
  bind `app.current_org` before every direct JDBC read as the migration owner.
- In a cloud worker, the tooling pack check fails on the CI profile under
  `skip-worktree`. Confirm with `git ls-files -v`, compare `.github/opencode.ci.json`
  and `git show HEAD:opencode.json`, temporarily restore HEAD's bytes under a trap
  to get the plain unit-test result, then restore the worker bytes exactly.
- Unique content fixtures per negative case make "no row" counts independent of
  test order; assert the structured `code` field rather than a substring of the body.
