## Lessons for workers

- For spec evidence notes, check the ID set `scripts/check-docs.py` actually derives before writing IDs: `PAT-01/02/03` are not in it, so naming them makes the docs gate fail; cite `PRD-03` or "patient self-access" instead.
- A clause about an "approved manual process" is a human/signed-decision clause: record status `Not built` unless the repository holds the signed procedure and G5 evidence. A generic support-case workflow is adjacent, not proof.
- Verify every relative link target with a shell `[ -f path ]` loop computed from the note's own directory depth before running `check-docs.py` (`docs/spec/clauses/product` needs `../../../../` for the repository root and `../../../` for `docs/`).
- Keep proxy/authority work in its own bounded story; do not duplicate its rules into the patient self-access slice (daily note `2026-11-19` lesson).
