## Summary

Adds `infra/cloud`, a Terraform module for isolated staging and production AWS accounts: private network, encrypted and backed-up RDS, private KMS-encrypted S3, ECS Fargate services for the API and workers, encrypted SQS with a dead-letter queue, and least-privilege IAM roles. All environment-specific values come from variables/tfvars; no credential, real account id or patient data is committed. A stdlib-only Python gate parses the Terraform and fails on a public bucket, unencrypted storage, a backup-free database or a wildcard IAM policy, with 100% line coverage.

## Migration and rollout considerations

Migrations are a separate deployment step using the repository's `check-migrations.py` expand/contract gate before a new task definition is served. The same digest is promoted to both environments rather than rebuilt.

## Findings

- **Environmental (not a defect in this change):** on this cloud worker, `git ls-files -v opencode.json` reports flag `S` (skip-worktree) and the worktree file is byte-identical to `.github/opencode.ci.json`, not to the committed HEAD profile. `scripts/check-pack.py`, `test_check_pack` and therefore `scripts/check.sh` judge the CI profile and report `opencode.json is stale`. Verified without editing any protected file: `git show HEAD:opencode.json` equals `gen-opencode.py`'s local render (`ci=False`) exactly, while the worktree file equals the CI render. This is the already-documented OPS-CW-003-01 measurement artifact. The committed profile is correct; no regeneration was attempted because `opencode.json` is outside this task's scope and is protected.
- **Tooling limitation:** Terraform is not installed in the worker (`command -v terraform` → missing), so `terraform validate`/`fmt` could not run. The offline parser, balanced-delimiter checks and a bounded IaC review are the compensating evidence; the integrator/Delivery pipeline is the place for a real `terraform validate` if added there.
- **Repository convention:** `*.tfvars` is git-ignored to protect secrets, so the synthetic per-account values are committed as `environments/*.tfvars.example`; `README.md` documents copying them to a local git-ignored `*.tfvars` for real applies. No secret or real account value is committed.

## Lessons for workers

- In a cloud worker, always check `git ls-files -v opencode.json` before trusting a `check-pack.py` or `test_check_pack` failure: flag `S` means the worktree holds the CI profile and the "stale" result is a measurement artifact, not a reason to regenerate the committed file.
- A stdlib `trace --count` coverage run is vacuous without `--missing`; assert the `>>>>>>` marker on an under-covered probe so the gate cannot silently pass.
- Keep the HCL policy parser fail-closed: an attribute that cannot be resolved (variable, unknown resource, missing field, `.tf.json` file, second policy document) is a breach, never a pass. Exact-token wildcard checks miss `s3:*`; check for `*` inside every action token.
- When an encrypted CloudWatch log group uses a customer-managed key, the key policy needs an explicit `logs.<region>.amazonaws.com` grant; the ECS task role's IAM policy alone is not enough. Likewise SQS SSE-KMS needs producer/consumer KMS permissions.
- Do not infer a check's behaviour from reading code alone when a reviewer says it will fail — run it. In this environment stdlib `trace --missing` honours `#pragma NO COVER`, contrary to a reviewer's inference.

## Why this is not finished

The story's own gate is complete and green (`bash infra/cloud/check.sh`, exit 0, 100% line coverage). The repository-level `bash scripts/check.sh` still exits 1 at `scripts/check-pack.py` with `opencode.json is stale: run scripts/gen-opencode.py`. Most likely cause (verified above): the worker's worktree `opencode.json` is the CI profile under `skip-worktree`, so the pack gate measures it instead of the committed HEAD profile. What was tried: inspected the skip-worktree flag, compared worktree to both profiles, and confirmed `git show HEAD:opencode.json` exactly matches the generator's local render. No `opencode.json` edit was attempted because it is a protected file outside `infra/cloud`. Exact next step: the integrator/Delivery job should run the pack gate with the committed HEAD profile in place (the worker's `restore_config` does this in CI); no code change in this story is required.
