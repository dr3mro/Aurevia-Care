# ORDER-10 — Clinician workflow guide for prescriptions and orders (electronic or printed) and UAT scenario

## Summary

Added two documentation files under the business-named folder
`docs/operations/clinician-orders/`:

- `README.md` — one plain clinician workflow that starts from the patient chart,
  covers writing a prescription (RX-01/RX-02) and placing a lab or imaging order
  (LAB-01, RAD-01), choosing electronic / print / both, what the patient
  receives, failed and ambiguous sends (including print fallback and
  partner-status verification before retry), cancel and amend, and how to see
  the result. It also documents the three XCH-02 state families and that a
  transmission acknowledgment never closes a clinical task.
- `uat.md` — a person-runnable, numbered scenario (18 steps) with synthetic
  fixtures, negative role check, each delivery mode, failed-send-to-print, the
  three ambiguous-send answers, cancel before/after acceptance, amend, result
  linking, an Arabic pass, pass criteria, evidence-to-capture and limitations.

No code, schema, contract, dependency, script or tracker file was changed. No
folder or class was named after a task, story or requirement ID; the only new
folder is the business-domain name `clinician-orders`.

## Findings

- No defects found in the repository by this work.
- The guide deliberately keeps the three state families (workflow, transmission,
  clinical review) separate and treats "print" as document production only, to
  avoid implying electronic delivery or pharmacy acceptance — a recurring
  safety distinction in RX-02/XCH-02.
- The lab/imaging order-entry screens described by ORDER-05..ORDER-08 are owned
  by other workers; this guide documents the specified clinical workflow, not a
  claim that those screens are present at this commit.

## Lessons for workers

- For a docs-only story scoped to a new `docs/operations/<domain>/` folder, the
  applicable gate is `python3 -I scripts/check-docs.py` (plus `check-secrets.py`);
  there is no Java/TypeScript/Python coverage command to run.
- `check-docs.py` resolves relative links against the file's own directory, so a
  file two levels under `docs/operations/` reaches the spec via
  `../../../.opencode/config/PROJECT_V1_SPEC.md`, and a sibling guide via `README.md`.
- Name the new operations folder after the business domain (here
  `clinician-orders`), never after the story or a requirement ID.
