# SPEC-ARC-07-C02 — ARC-07 clause 2 acceptance proof

## Summary

Add a test-only acceptance proof that a conversation reply stores the sender's
identity and active role, the exact immutable body, a server-generated
timestamp and a monotonic per-conversation sequence, plus the refusals that
must store nothing. The clause is already fully implemented; this story adds
one DB-backed HTTP integration test class and one clause-proof document. No
production code, existing test, contract or migration changes.

## Affected requirements

ARC-07 (`SMARTCLINIC_V1_SPEC.md` line 128). Clause under test: "Store each
message with sender identity, sender role, immutable content, server timestamp
and conversation sequence."

## Risk class

Routine (test and documentation only). Safety concern is limited to proving
that tenant and role refusals store no message row.

- immutable content — `storedMessageContentIsImmutable`: direct `UPDATE` as migration owner throws a `SQLException` naming the append-only rule, and the original body survives in row and view.
- per-conversation sequence advances — `secondReplyAdvancesSequence`: two replies stored and viewed as sequences 1 and 2.

## Lessons for workers

- For any clause proof, mirror the existing `authz/clauses` DB-backed HTTP fixture: own database, Flyway `filesystem:../../db/migrations`, synthetic headers, org fixtures `1111…`/`2222…`, and a fresh conversation per test. Seed an active `patient_link` before the conversation; a staff reply needs no messaging directory because only patient callers re-resolve the connection.
- Assert the real wire value (`senderKind` is lowercase `staff`), and remember `ConversationInputs.body` trims text, so submit whitespace-free bodies when asserting verbatim storage.
- `opencode.json is stale` in a cloud worker is the CI profile under skip-worktree: confirm with `git ls-files -v` (`S`) and `git show HEAD:opencode.json`, then record it. Never regenerate the protected file.
