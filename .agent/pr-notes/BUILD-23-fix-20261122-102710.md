## Lessons for workers

- When main advances between fix passes, re-run the **drift/parity gates against a fresh merge** before declaring inherited fixes green; a byte-identical copy from last pass is not evidence for this pass. The drift test's own message ("refresh the copy") is the exact remedy.
- Do not re-apply a fix that a later main commit already contains. Check ancestry (`git merge-base --is-ancestor`) and run the single regression test before editing a workflow or script — both earlier blocker theories were already resolved on main (`4bc9e562`, `25bd8176`).
- Paste the `tsc --noEmit` final lines from both frontend `check.sh` scripts into the notes even on a data-only backend pass, and treat any `error TS…` as a hard stop.
- Reset `apps/api/target/jacoco.exec` before the coverage batch and include `BrowserSessionHttpTest`; accumulated exec data can overstate a targeted run.
- Inside a cloud worker, worktree `opencode.json` is the CI profile under `skip-worktree`; report which profile was measured rather than treating it as HEAD truth, and attribute `test_check_pack.py`/`check-pack` failures to it rather than to the change.
- Check the exact **PR head SHA** for checks; local tracker/merge commits can trail it.
