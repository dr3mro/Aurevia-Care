# RADFLOW-05 — Browser test and guide: imaging order, schedule, link study, sign, addendum and acknowledgment

Task: RADFLOW-05 · Requirements: RAD-01, WEB-09 · Branch: `swarm/RADFLOW-05-486` · Scope: `apps/staff-web/e2e/radflow`, `docs/operations/radiology-workflow`. Synthetic data only; no dependency, production source, tracker, workflow or protected file changed.

## Summary

Adds a real-browser Playwright journey for the radiology workflow and a plain-language operations guide. The journey has two legs: (1) the real `/radiology` worklist screen driven by a stateful, in-test API mock that covers intake → schedule → **wrong-patient link refusal** → correct study link → handoff, including site scoping and all four mismatch verdicts; (2) a dev-only Vite-served harness that mounts the exported `ImagingReportCard` and `AddendumBanner` through their real providers and synthetic fixtures, proving the five signed sections in order, the open addendum's scope, the exact-revision acknowledgment closing the banner, and the Arabic right-to-left view. The guide documents the six steps for clinician and radiology users, the refusal rules, screen states, verification commands and the honest limits of this slice.

Entry-point-to-test trace: `/radiology` (registered by `src/features/radworklist/routes.ts`) → `RadWorklistPage` → `api.ts` commands → mocked `GET /api/v1/appointments` and `POST /api/v1/radiology/worklist/orders/{id}/{schedule|studies|report}` → `label-check` verdict and `worklist-status` assertions in `radiology-journey.spec.ts`. Referrer leg: `/e2e/radflow/referrer-harness.html` → `referrer-harness.tsx` → `ImagingReportCard`/`AddendumBanner` → ordered `[data-section]`, `[data-version="3"]` and acknowledge-button assertions.

## Findings

1. **Pre-existing generated-client drift (not caused by this change).** `bash apps/staff-web/check.sh` fails at `gen:api:check` because `src/api/generated/openapi.d.ts` does not match `contracts/openapi.yaml` on this branch. No file in that path was touched here. Owner action: regenerate the client in a scoped story and reconcile with whichever parallel worker changed the contract.
2. **The referrer components are not wired to a production route.** `ImagingReportCard` and `AddendumBanner` are exported (RADFLOW-04) but no feature `routes.ts` imports them, contrary to that story's note claiming the chart imports them. The browser leg therefore uses a dev-only harness. A follow-up story should mount them in the chart and add a real acknowledgment command; the harness acknowledgment updates local state only.
3. **No production "sign" screen exists in this slice.** Signing is an API action; the report shown to the referrer is already signed. The journey covers the worklist handoff and the referrer's signed-report view; the guide states this explicitly.
4. **Playwright is not invoked by GitHub Actions.** No workflow or reusable action references `playwright` or `npm run e2e`; the journey currently runs locally via `npm run e2e`. Workflow changes are outside this worker's scope and protected.
5. **Browser environment gap (resolved locally, not a code defect).** Playwright's Chromium needs system libraries absent from this worker image; `npx playwright install-deps chromium` fixed it. CI runners that host the eventual e2e job must install them too.
6. **Addendum receipt has no clinical content (H1, simulated radiology review).** The notice names only a revision number: no changed text, signer or signing time. The guide now discloses this and warns that acknowledging a bare revision number is not clinical acceptance; attaching content is API work outside this story.
7. **Critical communications are out of this slice (H2).** RAD-01 also names critical communications; the guide now states explicitly that neither the guide nor the journey exercises that path and that report visibility is not a critical-result acknowledgment.
8. **Mock contract and server-side check (M1).** The mock now returns the real API's `422 LABEL_MISMATCH` and the journey adds a direct boundary POST proving a mismatched link is refused without moving the order. The guide states the exact code and that the screen still sends no such command.
9. **Wording precision (M2/L1/L2/L3).** The test is named "hand off as reported" rather than "sign off"; step 5 says signing is an API action; the guide states the referrer leg uses a different fixture order, cites `RadWorklistPage.test.tsx` for the WEB-09 states, and scopes addendum notices to tenant plus order rather than to a patient identifier.

## Lessons for workers

- The staff-web `tsconfig.json` excludes `e2e/`: `npm run typecheck` passing says nothing about a new Playwright spec or harness. Run an explicit `tsc` with the strict flags over the new e2e files.
- A POST through the real client needs an `XSRF-TOKEN` cookie or `transport.ts` throws `csrf-missing` before `fetch`; add it via `context.addCookies` with the page origin before clicking any command.
- `page.route()` mocks must hold mutable state and return the current row on GET: React StrictMode issues two initial GETs in dev, and `useApi` reloads after every command.
- A harness under `e2e/` is served by Vite dev but is not emitted by `vite build`; assert a harness sentinel so a staged `E2E_BASE_URL` that falls back to the real SPA fails clearly rather than confusingly.
- `scripts/check.sh` transitively runs `mvn verify`; when a task forbids full integration tests, run the relevant policy and module gates individually and say why in the notes.
- Root `scripts/frontend-check.sh` also runs `prettier --check .`: notes and docs written as part of a frontend story must be Prettier-formatted too, not only the `.ts/.tsx` files.
- Mirror the real API's failure status and code in a browser mock; a made-up 409/coin tells the next test writer the wrong contract. When the UI guard prevents a negative command from being sent, add an explicit direct-boundary POST if the guide claims the server refuses it.
