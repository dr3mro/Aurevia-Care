- The imaging rule is implemented only in the in-memory `ImagingService` kernel. `ImagingController` has no schedule or accession route and its service-taking constructor is package-private; there is no radiology migration/RLS/FORCE RLS, no `Jdbc*` store, and no OpenAPI entry (five routes in `contracts/openapi/missing-routes.txt:49-50,220-222`). Status is therefore `Partly proven`; the end-to-end chain is recorded as one bounded Gap and requested below.
- `main` already contains literal conflict markers inside Javadoc comments in `apps/api/src/main/java/com/aurevia/exchange/hl7/{Hl7ParseException,Hl7Parser,Hl7Segment}.java` (committed, pre-existing, out of scope). Compilation and all tests pass; recorded, not edited.
- Worker-image false positives confirmed once and not re-diagnosed: skip-worktree `opencode.json`, absent Python coverage package, and missing NVD key were not edited or worked around.
- `worker_gate.py` reported `scope` violations only while the two new files were untracked (`git status --porcelain` collapses an untracked directory to `…/clauses/`); the paths are exactly the task scope and are re-checked after staging/committing.

## Lessons for workers

- `ImagingService` copies a supplied owner verbatim; a blank owner is only refused for STAT urgency. Assert preservation on the routine false side instead of asserting `null`.
- Run the service-level proof when the controller's fixture constructor is package-private and the missing routes do not exist; do not use reflection or edit production code to force an HTTP test.
- In a worker before the first commit, `worker_gate.py` can read untracked directories as out-of-scope paths; stage or commit the scoped files before trusting that verdict.
- Confirm the skip-worktree `opencode.json` false positive once with `git ls-files -v` and the committed profile, record it, and run the remaining gate stages individually instead of regenerating a protected file.
