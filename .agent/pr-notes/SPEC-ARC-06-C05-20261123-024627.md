## Findings

- Red-run corrections: Jackson 3 serializes `EventType` as uppercase enum names and this Spring version names 422 `UNPROCESSABLE_CONTENT`; both are test-side assertion fixes, not production defects.
- Task text and branch text suggest `@Disabled("GAP: ...")` for a missing control, but `scripts/check-constraints.py:56` rejects any added `@Disabled`/`@Ignore` in Java. Because the signed-URL control exists (at the storage adapter boundary) and the logs/analytics/notification channels have no code path, the honest green option was static evidence in the clause document instead of a disabled test. Workers must not edit `tasks/`, so this needs orchestrator reconciliation.
- Follow-up candidate (out of scope): caller-supplied `ScanRequest.detail`, `CompleteRequest.note`, `RemoveRequest.reason` and `FailRequest.detail` are persisted verbatim into `document_event.detail` with only a 200-character bound. That is an append-only audit ledger, not an ordinary operational log/URL/analytics/notification channel, so it was not made red here. A production story should sanitise it in `QuarantineService` / `PdfBindingService` with its own tests.
- The document routes are not in `contracts/openapi.yaml`; they are described in `contracts/documents/document-artifacts.md` and listed as gaps in `contracts/openapi/missing-routes.txt`. No new route was added, so no contract change was needed.
- Known worker environment false positive recorded once: stale worktree `opencode.json` under `skip-worktree` breaks `check-pack.py`, `worker-check.sh`, `python-coverage.sh` and six `test_check_pack` tests. Integrator owns the full gate.

## Lessons for workers

- Jackson 3 `tools.jackson.databind.JsonNode` has `properties()` but no `fieldNames()`; enumerate keys with `node.properties().forEach(entry -> names.add(entry.getKey()))`.
- A synthetic constant whose *name* contains `SECRET` is flagged by `check-secrets.py` as a possible password assignment even with a harmless value; name the protected-value marker neutrally (e.g. `MARKER`).
- Before asserting a ledger fact on a refusal, check whether the refusal path records one: cross-tenant `DocumentGuard.notFound()` is concealment and records nothing, so only the same-tenant wrong-role 403 can be asserted through the ledger.
- `check-constraints.py` rejects added `@Disabled` even when a story text invites a GAP-marked test; prefer real evidence or cite an existing dedicated test, and record the conflict for the orchestrator.
