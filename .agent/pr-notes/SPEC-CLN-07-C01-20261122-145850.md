## Summary

Proof-by-test for CLN-07 clause 1: "Link original PDFs and images to chart, order or result as authorized." Added one focused Mockito service-level test with three positives (chart, order, result) and three negatives (no active membership, role without link permission, unknown chart), plus the clause evidence document. The clause is fully implemented today, so no test is disabled and no production code was changed.

## Authorization boundaries and audit events

The positives confirm a `clinician` with active membership and a visible chart/order/result can attach an original, writing `appendEvent("link")` and a `SUCCESS` audit row. The negatives confirm both real guards in `DocumentService.authorize`: no active membership -> 403 `FORBIDDEN` "no active membership"; active member with `patient` role (no `DOCUMENT_LINK` permission in `DocumentPolicy`) -> 403 `FORBIDDEN` "missing document permission". Both write a `DENIED` audit row keyed by the **subject UUID** and perform no insert, history event or `SUCCESS` audit. Unknown chart -> 404 `NOT_FOUND` before insert. No new audit event was added. Actor and tenant come only from `TenantContext`; the request body never supplies them.

## Lessons for workers

- In a proof-by-test story the plan reviewer still requires a concrete `## Gap`: name the exact files to change and the number of tasks, then check whether an existing task already owns the work before filing a `task-request`.
- `DocumentService.link()` audits a denial with the **subject id** as resourceId (`subjectId`), not the generated association id; assert `eq(SUBJECT)` in the `DENIED` audit verify.
- Do not treat `reception` as a negative role for `DOCUMENT_LINK` — `DocumentPolicy` explicitly allows it; use `patient` or `security_scanner`.
- Run SpotBugs only after `compile` (`-DskipTests compile spotbugs:check`); a bare `spotbugs:check` is vacuously green.
