## Lessons for workers

- Before re-fixing a red PR, verify the inherited fix with byte-level checks (`cmp` / `sha256sum` / line grep) and re-run the exact red gates against the merge result; do not re-run "in-scope tests and call the rest pre-existing" when a contract change on main can reintroduce drift or parity failures.
- A new public route must be declared where the parity test can see it; clean-main parity is not evidence that your branch passes, because the route only exists after your change.
- Reset `apps/api/target/jacoco.exec` before the coverage batch and include `BrowserSessionHttpTest`; accumulated exec data can overstate a targeted run.
- In a cloud worker `opencode.json` is the CI profile under `skip-worktree`; confirm with `git ls-files -v` and never commit that file. Judge policy results against the committed file, restoring HEAD bytes only under a trap and re-verifying the CI hash afterwards.
- The frontend definition of done is mandatory even on a data-only backend pass: run both `apps/staff-web/check.sh` and `apps/patient-mobile/check.sh`, paste the `tsc --noEmit` final lines, and treat any `error TS…` as a hard stop.
- Respect the worker time limit: use targeted tests, standalone JaCoCo, standalone SpotBugs and standalone policy checks; let the integrator run the full gate.
