## Summary

Add an HTTP-level, real-PostgreSQL clause evidence test and clause evidence document for XCH-02 clause 3: "A transmission acknowledgment cannot close a clinical task." No production code, migration, contract, dependency or existing test changes. Six active tests prove that a delivery receipt leaves clinical review unreviewed and unbound, that clinical closure is refused on that path, that a storage writer cannot combine a delivery with a clinical resolution, that only clinicians may acknowledge/resolve, that a clinician can still close the task through the proper path, and that another tenant's delivery receipt cannot reach the task.

## Lessons for workers

- To actually run `@Tag("integration")` tests use `-Pno-security -Dgroups=integration` without `fast`, then open the Surefire XML and confirm `tests`, `failures` and `skipped` — a filtered run that executes nothing is a false green.
- Under `-Pno-security`, a bare `spotbugs:check` reports "Spotbugs plugin skipped"; add `-Dspotbugs.skip=false` and require `BugInstance size is 0` after a real `compile`.
- Do not run `mvn clean` before the Python tooling tests: `test_worker_gate` fixtures assume `apps/api/target/surefire-reports` exists and raise `FileNotFoundError` otherwise.
- For a "cannot do X" clause, include a positive control showing X succeeds through the proper path; otherwise a globally broken command makes the negative test pass for the wrong reason.
- When asserting a database trigger guard, satisfy the other constraints (version + 1, valid evidence) so only the intended guard can reject the write, and assert the SQLSTATE plus the exception message.
