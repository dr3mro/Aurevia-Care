## Findings

- **Resumed work.** The earlier run's two in-scope files were found in commit 85f3693d and restored unchanged. - **Advisor brief deviations (recorded, not silent).** The brief asked for a plain JUnit domain-kernel test with one `@Disabled("GAP: ...")` durable-path test. I followed the story and AGENTS.md instead: (a) neighbouring clause tests use the same Spring HTTP-plus-PostgreSQL setup, the story says to use the neighbours' fixtures/style/database setup, and AGENTS.md requires an HTTP-level integration test through the controller; (b) `scripts/check-constraints.py:56` rejects any added Java `@Disabled` or `@Ignore` line in both `scripts/quick-check.sh` and `scripts/quality-gate.sh`, and AGENTS.md forbids a test left disabled, so a new gap test would fail the gate. The gap is documented in the clause document's `## Gap` with the would-be test, the files to change and the task count.

The critical flag is derived at the trust boundary by `ResultEntryService.flag` from command-supplied bounds and XCH-05 is proved by the durable `public.critical_result` row. The earlier run confirmed this with a red probe and the context optimizer confirmed it by source read. The clause document records it under `## Gap`.
- **Clause status rationale.** `Proven by tests` is scoped to the trigger itself (creating route facts and starting the durable alert on issued revisions, refusing them otherwise). The downstream XCH-04 reconciliation/notification and XCH-05 acknowledgment/escalation events are separate requirement IDs with their own stories; they are enumerated in `## Gap`, not claimed here.

## Lessons for workers

- A resumed task's earlier commit may not be an ancestor of the current branch; search git history for the story id before redesigning the work, and continue from the recorded evidence.
- `scripts/worker_gate.py` rejects any angle-bracket token in `## Test evidence` or `## Coverage`; quote assertion messages with words, not angle-bracket notation, or a completed task is failed for a notes-format defect.
- Before encoding an advisor's claimed event in a test, verify the fact on the wired bean: an empty `LabPolicyCatalog` means no in-memory `CRITICAL_RESULT` event even when the observation is flagged critical and the durable alert is written.
- `LabResultService.events(orgId)` is cumulative for the Spring context; filter by reportId and use a unique accession per test so negative tests stay meaningful.
