## Findings

1. Clause 5 is **partly built**. Original identifiers are preserved as first-class columns (`V9__duplicate_review_consolidation.sql`, `DuplicateRepository.insertAssociation`, `ConsolidationService.consolidate`) and proven by the green tests. Signed artifacts, signatures and source references have no dedicated `preserved_*` columns, no service code copying them and no read-path proof; the `@Disabled` test documents this. Status in the clause doc is `Partly proven`.
2. The `/api/v1/duplicate-reviews/**` routes are baselined in `contracts/openapi/missing-routes.txt` rather than published in `contracts/openapi.yaml`. Contract work is outside this test-only scope; noted in the clause doc.
3. Known worker-environment false positive OPS-CW-003-01: `git ls-files -v opencode.json` → `S` (CI profile copied over the worktree file under skip-worktree), and the worktree file equals `.github/opencode.ci.json`. This makes `check-pack.py`, six `test_check_pack` unit tests, `scripts/python-coverage.sh` and `scripts/check.sh` fail locally with `opencode.json is stale`. The committed HEAD profile is generated correctly; the integrator owns the full gate. I did not edit the protected `opencode.json`, generator or scripts.
4. Worker image lacks Python `coverage` (`python coverage: WARNING coverage is not installed`) — documented worker limit.
5. Pre-existing, committed conflict markers (inside Javadoc comments, so compilation is unaffected) remain on HEAD in files outside this task's scope: `apps/api/src/main/java/com/aurevia/exchange/hl7/Hl7ParseException.java`, `Hl7Parser.java`, `Hl7Segment.java` (`<<<<<<< HEAD` / `>>>>>>> origin/swarm/BUILD-37-469`). My `git merge` had no conflicts; I did not touch them. Flagged for the integrator.

## Lessons for workers

- For a clause-evidence task, trust columns over comments: a migration header claiming preservation is not proof. Read the table definition and the service/store call before choosing `Proven by tests` vs `Partly proven`, and use the story's `@Disabled("GAP: ...")` step to keep the PR green.
- `web.PatientController.RegisterRequest.identifiers` and `consents` are opaque JSON **strings**: escape the inner quotes when building an HTTP request body, or registration returns 400 (`Cannot deserialize value of type java.lang.String from Array value`).
- In a cloud worker, a `check-pack.py` "opencode.json is stale" failure is the known skip-worktree CI-profile false positive. Verify with `git ls-files -v opencode.json` (`S`) and do not regenerate or edit the protected file.
- Keep the GAP test SQL as string constants so the test class compiles even though the target columns do not exist; that is what lets the PR stay green while documenting the missing behaviour.
