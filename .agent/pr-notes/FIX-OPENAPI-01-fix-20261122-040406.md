## Lessons for workers

- When a fix pass finds the branch already equals `origin/main` and all targeted
  tests are green, the correct action is to verify and record evidence, not to
  re-apply the fix or add a new test/allow-list edit — repeating the re-merge or
  re-documenting a deliberately removed API defeats the earlier revert.
- `git merge-base --is-ancestor origin/main HEAD` plus an empty `git diff
  origin/main -- <files>` is the fastest way to prove a stale-merge fix is fully
  present before spending time on tests.
- A red `check-pack: opencode.json is stale` in a cloud worker is the
  skip-worktree CI profile, not a change defect; confirm with `git ls-files -v
  opencode.json` and compare worktree vs `git show HEAD:` before reporting it.
- Unset `CHECK_SCRIPT`, `BRANCH_PREFIX` and `BASE_BRANCH` when running the module
  `check.sh` files directly so the root swarm gate does not override them.
- A global `git grep` for conflict markers can flag Javadoc text already committed
  on main; check `git show origin/main:<path>` and the branch diff before treating
  it as a merge defect.
