# SPEC-XCH-05-C03 — Use site-approved backup contact channels if an alert is overdue or the system is down

## Summary

Test-and-doc-only proof of XCH-05 clause 3. The rule is already fully implemented,
so no production code, migration, contract, existing test or dependency was
changed. One new synthetic API-level clause test drives
`CriticalResultService.escalate` — the command called by
`CriticalResultController` — and proves that an overdue or system-down alert uses
the site-approved backup channel and recipient and appends an
`ESCALATION_ATTEMPT` fact, while seven negative cases prove the rule refuses
wrong channel/recipient, wrong role, inactive backup recipient, stale version and
wrong state. A new clause document records the exact sentence, status, evidence
and gap. All 8 tests are active; no `@Disabled`, skip, suppression, exclusion or
threshold change.

Evidence provenance: all gate commands below were executed by the primary agent
(tool evidence). Review verdicts come from the named read-only specialist agents
(simulated reviewer evidence). No simulated-user walkthrough and no human,
clinical or unit participant was involved in this story.

## Lessons for workers

- For a mock-based clause proof, apply per-test overrides (inactive backup
  recipient, restricted role) only *after* the setup helper drives the row to the
  target state; overriding before it makes the setup's own `assign` fail with a
  roster gap or missing permission.
- To prove a two-operand guard, call it twice: once with both operands wrong and
  once with the first correct but the second wrong, then assert the same stable
  code and the absence of the success fact.
