## Lessons for workers

- Re-verify earlier passes' green claims with your own commands before accepting or
  extending them; do not trust notes as execution evidence.
- Distinguish three different failure classes before editing code: in-scope defects
  (fix them), out-of-scope/owner decisions (hand off, never edit), and
  environment-protected artifacts (document, never regenerate).
- In this cloud worker `opencode.json` is the CI profile under `skip-worktree`;
  compare with `.github/opencode.ci.json` and `git show HEAD:opencode.json` before
  believing a `check-pack` failure. Never regenerate or commit that file.
- A `worker_gate` "scope" violation on `contracts/openapi/missing-routes.txt` for a
  controller-adding story is a scope-definition defect, not a missing fix: reverting
  it simply converts the deviation into a hard route-parity test failure.
- A "failing" test that depends on `apps/api/target/surefire-reports` existing is not
  caused by the current branch; reproduce on a clean reports directory first.
