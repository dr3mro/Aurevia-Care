## Summary

Task SPEC-ARC-07-C06 / requirement ARC-07, clause "Use durable client message IDs to deduplicate retries." This PR adds a complete five-test HTTP-over-PostgreSQL gap proof (all `@Disabled("GAP: …")` as the story mandates) and a clause-evidence document with `Status: Not built`. No production code, existing test, migration, contract, dependency or tracker was changed. Synthetic fixtures only; evidence is tool output plus read-only specialist review, no human/clinical/patient-participant evidence.

The neighbouring top-level `com.aurevia.smartclinic.staffmsg` instant/mail channels do deduplicate with active green tests (V91 `client_message_id` + unique key, `InstantMessagingService.send`, `MailService.send`/`JdbcMailStore.replay`, V95 claim). ## Lessons for workers

- Survey the whole requirement and its neighbours before writing a gap test: a rule can be built for a sibling domain (staff messaging) and still be absent from the clause's surface (patient communication). Cite the neighbour as a pattern, never as proof.
- A tenant-scoping test must share every local identifier across the two organizations; otherwise a global or subject-only replay lookup passes and proves nothing.
- Give negative retry tests a fresh version unless staleness is the behaviour under test, otherwise a 409/412 can come from the wrong guard.
- Check whether an "exception" exists in code, not only in the brief: `check-constraints.py` rejects added `@Disabled`, and the quality gate runs it, so a gap-evidence task needs an owner-owned allowance recorded in the hand-off.
