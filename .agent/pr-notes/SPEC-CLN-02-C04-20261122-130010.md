# SPEC-CLN-02-C04 — Eligible roles can record vitals or open the encounter

## Summary

CLN-02 clause 4 is **already built** in the scheduling domain: `WorklistPolicy` holds the
authoritative role matrix (`VITALS_RECORD` → `clinical_assistant` + `clinician`,
`ENCOUNTER_OPEN` → `clinician` only) and `CheckInService.openEncounter` enforces the encounter
half at a tenant-guarded service entry point with a DENIED/SUCCESS audit trail. This task adds
the dedicated clause proof (6 active tests, synthetic fixtures only) and the clause evidence
document. No production code, existing test, contract or migration was changed.

Source survey (step 1) found, for the clause: `scheduling.checkin.WorklistPolicy`,
`scheduling.checkin.CheckInService` (`openEncounter`, private `authorize`),
`scheduling.checkin.ClinicController` (HTTP entry), `scheduling.AppointmentService` /
`AppointmentState` (state machine), `chart.record.ChartService` + `ChartActionPolicy`
(vitals entry in the CLN-03 slice), `api.authorization.CommandCatalog` / `CommandAuthorization`
(generic gate owning the clerical CLN-02 actions), Flyway migrations under `db/migrations` and the
generated contract under `contracts/openapi`. No separate workflow file implements the clause.

## Affected requirements

CLN-02 (clause 4). Acceptance mapping: positive rule-met proof for opening an encounter
(`clinicianOpensEncounterAfterIdentityWasVerified`) and recording vitals
(`eligibleClinicalRolesMayRecordVitals`); negative refusals for wrong role
(`receptionCannotOpenEncounterEvenAfterIdentityWasVerified`), ineligible clinical role
(`clinicalAssistantCannotOpenEncounterThoughItMayRecordVitals`), ineligible/admin/auditor/unknown
roles (`ineligibleRolesCannotRecordVitals`) and missing role
(`missingRoleFailsClosedForBothActions`).

## Lessons for workers

- `List.of(...)` rejects null elements — assert a null-role fail-closed case in its own assertion
  rather than embedding `null` in a `List.of` loop.
- Before treating `git grep` conflict markers as your own merge damage, check `git status` and
  `git show HEAD:<file>`; markers can be committed inside Javadoc from an unrelated story. Respect
  scope rather than fixing them in a clause-proof task.
- `scripts/coverage-check.sh` triggers a full `mvn verify` whenever any `apps/api/` path changes,
  including a test-only file; for a swarm clause-proof task the worker leaves that gate to the
  integrator and proves the touched production classes with a targeted `jacoco:report` instead.
