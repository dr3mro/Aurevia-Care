# SPEC-CLN-07-C01 — CLN-07 clause 1 (API test): link original PDFs and images to chart, order or result as authorized

## Summary

Added one synthetic HTTP-level integration test class and one clause status note proving the
first CLN-07 sentence only: an authorized clinician or reception user can attach an original
PDF or image to a chart, an order or a result through `POST /api/v1/documents/associations`,
and the rule refuses a wrong role, another tenant, an unknown subject and a revoked membership.

the database is a class-private, freshly migrated name.

## Lessons for workers

- Reuse the HTTP clause-test fixture shape (`@SpringBootTest(RANDOM_PORT)`, `synthetic-auth`, a
  class-private Flyway-migrated database) and seed canonical order/result subjects with
  `session_replication_role=replica` inside `try`/`finally` restoring `origin`; without it the
  actor triggers and cross-module foreign keys block a direct synthetic insert.
- A chart unknown-subject test does not reach the `insert` → `written == 0` → 404 branch because
  `chartExists` short-circuits first; add a separate unknown-order test to cover that branch.
- `DocumentPolicy.DOCUMENT_LINK` is granted to both `clinician` and `reception`; prove both roles
  positively when the clause says "as authorized".
- In this cloud image the `opencode.json` skip-worktree artifact makes `test_check_pack` red and
  the full `worker-check.sh`/`check.sh` gates time out; run the targeted `-Dtest=...` suite plus
  individual policy scripts and compile-then-`spotbugs:check` instead, and leave the full gate
  to the integrator.
