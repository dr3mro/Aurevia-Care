## Lessons for workers

- Before treating `check-pack.py` or `test_check_pack` failures as real in a cloud
  worker, run `git ls-files -v opencode.json`: `S` plus a worktree file that
  differs from `git show HEAD:opencode.json` means the CI profile is overlaid
  under skip-worktree. Confirm once, run the other gate stages individually and
  never regenerate or commit that protected file.
- `worker_gate.py` reports untracked new files as their containing directories,
  which can look like a scope violation. Stage the new files and write the notes
  file before trusting its candidate verdict.
- For a clause-proof story, the plan reviewer requires the evidence document to
  enumerate the whole surveyed chain (service, contract types, actions, inputs,
  repository, controller, HTTP test, migration and contract baseline), not just
  the test names. Put that in the plan before writing code.
