# SPEC-XCH-04-C04 — XCH-04 clause 4 API evidence

## Summary

Adds one HTTP-level integration test and one evidence document proving that an XCH-04 corrected result keeps the original revision, notifies prior recipients, and reopens review after a clinician acknowledged it. The clause is already implemented on `main`; this story adds evidence only. No production code, contract, migration, dependency or existing test was changed.

- `apps/api/src/test/java/com/aurevia/exchange/clauses/CorrectionsPreservePriorVersionsNotifyPriorRecipientsTest.java` (new)

## Affected requirements

XCH-04 (PROJECT_V1_SPEC.md:66). Acceptance mapping:

- Clause sentence → `correctionPreservesPriorRevisionNotifiesPriorRecipientsAndReopensAcknowledgedReview` (version 2, `previousId`, two revisions, one notification with `superseded_version=1`, prior `acknowledged`, new `unreviewed`, `XCH04_REVIEW_REOPENED` audit).
- Refusal of malformed correction → `correctionWithoutSupersedesIsRefused` (422 `SUPERSEDES_REQUIRED`).

- Wrong role → `actorWithoutImportRoleCannotPostCorrection` (403 `FORBIDDEN`).
- Other tenant → `correctionByActorWhoIsNotAMemberOfTheActiveTenantIsDenied` (403 `FORBIDDEN`, origin lineage unchanged).

## Lessons for workers

- For a clause-evidence story in a cloud worker, confirm the `opencode.json` skip-worktree artifact once (`git ls-files -v` → `S`, HEAD vs generated), record the failing command and final line, then run the remaining gate stages individually instead of re-diagnosing or editing protected files.
- Scope DB-name collisions by using the story's unique database name and `DROP DATABASE ... WITH (FORCE)`; scope every negative assertion by accession and resource id so test execution order cannot change the result.
- State honestly when there is no red phase: for evidence-only tests of already-implemented behaviour, do not fabricate a red run — prove the refusals and the persisted absence of writes instead.
