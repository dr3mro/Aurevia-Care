## Findings

- Rejection cause: the first worker's hand-off note embedded a literal Git
  conflict-marker grep in its "Test evidence" section. The gate's placeholder
  detector matches an angle-bracket-wrapped token; the pipe between the marker
  halves forms such a token, so candidate validation returned a
  `notes-placeholder` violation and the run was recorded as not finishing
  cleanly. This note describes that check in words instead of pasting the
  pattern, and contains no placeholder-shaped token.
- The implementation itself is sound: the e2e journey passes in both locales,
  the module gate is green at 100% coverage, and no defect was found in the
  existing order-entry components.
- Playwright browser binaries and OS libraries were absent in this worker and
  had to be installed; this is environment-only setup and is not committed.
- The full `scripts/check.sh` / `mvn verify` was not run because this worker
  prompt forbids commands that run every integration test; the integrator and
  Delivery run the full gate. The scoped frontend gate, e2e journey, policy
  checks and documentation check were run instead.
- No migration version is used by this story.

## Lessons for workers

- Never paste a literal Git conflict-marker grep into a notes "Test evidence"
  section: the worker gate's placeholder detector matches the pipe between the
  marker halves and rejects the note. Describe the check in words instead.
- Install the Playwright browser and its OS libraries before treating an e2e
  story as blocked; a missing system library is an environment issue.
- In a cloud worker the worktree `opencode.json` is the CI profile under
  `skip-worktree`; validate pack drift against the committed HEAD file, not the
  worktree copy.
- Remove Playwright's generated `test-results/` directory before finishing: it
  is outside the task scope and trips worker-gate scope validation.
