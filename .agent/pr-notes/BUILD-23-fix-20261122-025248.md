The alternative — adding a path to `contracts/openapi.yaml` and regenerating `apps/staff-web/src/api/generated/openapi.d.ts` — is larger and is owned by the FIX-OPENAPI tasks. ## Lessons for workers

- When a contract is edited on `main` after a story packaged a copy, the drift test is the real gate — re-run it against the merge result, not just the story's other tests, before declaring a PR ready. A byte-for-byte `cp` plus `cmp`/sha256 is the whole fix.
- A new public route must be declared somewhere the parity test can see (`contracts/openapi.yaml` or `contracts/openapi/missing-routes.txt`). Clean-`main` parity is not evidence that your branch will pass: the route only exists after your change.
- JaCoCo evidence from an accumulated `jacoco.exec` can overstate a targeted run. Reset `apps/api/target/jacoco.exec`, run the complete in-scope batch (include `BrowserSessionHttpTest` for the browser-session/logout lines), then generate and parse the report.
- In a cloud worker, `opencode.json` is the CI profile under `skip-worktree`; confirm with `git ls-files -v` and hashes, restore HEAD bytes only under a trap for local gates, then restore the CI bytes and re-verify the hash. Never commit that file.
- Respect the worker time limit: `apps/api/check.sh` is a full `mvn verify`; use `scripts/quick-check.sh` plus standalone SpotBugs instead, and let the integrator run the heavy gate.
