## Findings

1. **Brief defect (owner: senior developer / task advisor).** The brief's central premise was wrong:
   CLN-05 is implemented in `clinical.notes`, not unbuilt. Evidence: `ClinicalNoteService.updateDraft`
   calls `requireEditable` (409 `IMMUTABLE_REVISION`), `NoteState.editable()` only permits drafts,
   `V15__clinical_note_signing.sql` enforces an append-only ledger, and active tests
   `ClinicalNoteRevisionIntegrationTest.signedRevisionsCannotBeEditedOrReSigned` and
   `PlatformAcceptanceTest.staleDraftCannotOverwriteSignedNote` already prove the rule. An all-`@Disabled`
   test plus `Not built` doc would have been factually wrong and would have failed `check-constraints.py`.
2. **Chart-slice survey (recorded in the doc, not a gap in this clause).** `chart.record` has only
   record/verify/get/list; `ChartActionPolicy` has only CHART_READ/CREATE/VERIFY; V13 `chart_entry` has no
   signed state, signer, checksum or template version; verification is not signing. Adjacent out-of-scope
   signing: `therapy.TherapyService.signNote`, the `signInterpretation` command in `CommandCatalog` with
   `SpecialtyActions.RAD_SIGN_INTERPRETATION`, and `radflow.report.ReportRules` / `ReportController`.
   Adding chart-level signing would be a separate product decision, not a CLN-05 defect.
3. **OpenAPI context (already tracked).** Neither `/api/v1/clinical-notes` nor `/api/v1/chart/records` is
   published in `contracts/openapi.yaml`; this is recorded as context in the doc, not re-reported as this
   clause's gap (see the capture-chief-concern clause note and the existing FIX-OPENAPI tasks).
4. **Environment artifacts, not change defects.** Worktree `opencode.json` is the CI profile under
   `skip-worktree`; it explains the `worker-check.sh`, tooling-unittest and python-coverage failures
   above. No protected file was edited and no artifact was re-diagnosed on a later pass.
5. **Pre-existing, outside scope (informational).** `origin/main` already contains unresolved conflict
   markers inside Javadoc comments of three `exchange/hl7` files (`Hl7Parser.java`, `Hl7Segment.java`,
   `Hl7ParseException.java`). Verified present in `HEAD`, untouched by this change; compilation is
   unaffected because they are inside comments. Flagged for the integrator, not fixed here.

## Lessons for workers

- Survey **adjacent** packages before declaring a clause unbuilt. CLN-05's sign/edit lifecycle lives in
  `clinical.notes`; a `chart.record`-only survey produces a false "Not built" status.
- An added `@Disabled` is rejected by `scripts/check-constraints.py`. Where a feature already exists, an
  active proof through the real HTTP entry point is both honest and gate-green.
- Guard order governs the expected status: authorize → version precondition → immutable-state check, so
  the same edit returns 403, 412 or 409 depending on which boundary fails.
- Use `SMARTCLINIC_PG_ADMIN=postgres` for a standalone `-Dgroups=integration -Dtest=...` run, and never
  combine it with the `fast` profile (whose `excludedGroups=integration` wins).
- In a cloud worker, `git ls-files -v opencode.json` → `S` explains every `check-pack` / `test_check_pack`
  failure; verify with `git show HEAD:opencode.json`, run the remaining stages individually, and never
  regenerate or commit that file.
