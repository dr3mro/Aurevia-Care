# SPEC-MSG-02-C04 — MSG-02 clause 4 (API test): assign, transfer within the unit, resolve with reason and audit

## Summary

Adds a database-free clause-proof test and a clause evidence document. MSG-02
clause 4 is already implemented in `messaging/conversations`; no production,
contract, migration or tracker file is changed. One authorized lab staff member
assigns, transfers inside the unit and resolves a work item with a trimmed
reason and one `SUCCESS` audit row per action, while five negatives prove the
rule refuses a patient caller, a cross-unit target, a stale version, a closed
thread and a blank reason without writing the projection or the append-only
event ledger.

rows carry the authenticated actor `lab-a`, the from/to wire states and the

## Lessons for workers

- Under `-Pno-security`, SpotBugs is skipped. A `spotbugs:check` that logs
  "Skipping … spotbugs report goal" proves nothing; add `-Dspotbugs.skip=false`
  and compile first, then confirm `BugInstance size is 0` in the output.
- For a test-only clause proof, run the targeted `test` phase, not `verify`:
  JaCoCo's build-failing gate sees only the selected test at `verify`. State
  explicitly in the notes that no production line changed.
- Before treating `check-pack.py` or `test_check_pack` staleness as a defect in
  a cloud worker, run `git ls-files -v opencode.json`; `S` plus a HEAD file that
  matches the generator means the worktree is the CI profile under
  skip-worktree. Confirm once, record the command and final line, and do not
  regenerate or re-diagnose it.
- To prove a "within the unit" rule, stub the out-of-unit target as an active
  member with a role from another unit; otherwise the test only proves the
  inactive-target branch and would pass for the wrong reason.
