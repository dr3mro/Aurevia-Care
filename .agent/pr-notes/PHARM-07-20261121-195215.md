# PHARM-07 — Patient app: simple prescription status in plain words

## Summary

Adds a `features/prescriptions` slice to the patient app (React Native / Expo). It shows each released prescription with one of four plain status words — **Sent to pharmacy**, **Pharmacy accepted**, **Pharmacy needs to check with your doctor**, **Handed over** — in English and Arabic with RTL layout. The status is derived from append-only RX-02 events with a single clinical-safety rule: a pharmacy acceptance is **not** dispensing evidence, so only a `dispensingEvidence` event may yield "Handed over" or any readiness implication. Prescription projections are held only in the shared in-memory clinical cache, which the existing sign-out path already clears; no disk/persistent clinical cache is introduced.

## Affected requirements

- RX-02 — plain status wording and the dispensing-evidence vs acceptance distinction.
- PAT-02 — patient-visible released information, no persistent clinical cache, Arabic/RTL.

## Risk class

Routine (patient-facing presentation). No signing, cross-organization sharing, patient-association change, prescribing or critical result is introduced. The RX-02 "never imply ready without dispensing evidence" invariant is a patient-safety wording concern and is enforced by a pure domain function plus dedicated tests (see Coverage).

## Findings

1. **One-line out-of-scope registry update (applied, necessary, no gate weakened).** Adding the legitimate business-domain folder `apps/patient-mobile/src/features/prescriptions` makes the pre-existing exact-set test `src/features/domain-layout.test.ts` fail (`+ "prescriptions"`). This is the documented pattern from BUILD-53 (worker note `.agent/pr-notes/BUILD-53-20261121-083229.md`), whose fix pass added exactly one line to the same test's `DOMAIN_FOLDERS`. I applied the same minimal edit: `+ 'prescriptions', // RX-02, PAT-02 - prescription status domain`. The test's three safety assertions (exact-set membership, no story-ID directory, entry point per domain) remain intact; no threshold, exclusion or skip was changed. The declared scope was `apps/patient-mobile/src/features/prescriptions`; this registry line is the sole deliberate deviation, required for the mandatory frontend gate to pass and consistent with repository precedent.
2. **`bash scripts/check.sh` exit 1 is an environment artifact, not a change defect** — the skip-worktree CI `opencode.json` profile (see Test evidence). Confirmed by `git ls-files -v` (`S`) and an empty `git diff HEAD -- opencode.json`. No protected file was touched.
3. **Shared-cache design decision.** `store.ts` holds the prescription projection in `api/clinicalCache.ts` under namespace `'reports'` with the prefixed key `'rx:visible-prescriptions'`, so the existing `clearToken → clearClinicalCache` sign-out path clears it without new wiring. Adding a dedicated `'prescriptions'` namespace would require editing `api/clinicalCache.ts`, outside this task's scope; the prefix guarantees no collision with report entries. Trade-off: prescriptions share the `'reports'` namespace label, but the prefix and the single sign-out clear preserve the privacy invariant that nothing survives sign-out.
4. **No HTTP/navigation wiring (deferred; task-request raised below).** As with the existing released-reports feature, the screen is presentational and the typed client is injected by the app shell (outside scope). Nothing in the running app imports `PrescriptionsScreen` / `loadReleasedPrescriptions`, so PAT-02 reachability is not end-to-end. The acceptance criteria for this story (wording, evidence rule, sign-out clear, Arabic) are fully met at the component and loader level, but a follow-up story must wire a `PrescriptionsPage` into `patientPages.tsx` and a navigation entry in `RootNavigator.tsx`. A `task-requests` block is included below.

## Senior-mobile review outcome

A bounded simulated `aurevia-senior-mobile` review (tool file reads + reasoning; the reviewer did not re-run commands) returned four findings:

1. **No runtime entry point (blocking for end-to-end "done", scope-caused).** Disposition: accepted as an orchestration gap, not a worker defect — documented in Findings 4 and raised as a `task-requests` entry. Not claimed as end-to-end done.
2. **Cancelled/renewed prescriptions fell through to an in-progress word (patient-safety relevant).** **Fixed:** added `cancelled` and `renewal` event kinds (`types.ts`), `isCancelled` (`status.ts`), renewal-resets-to-sent in `plainStatusFor`, and loader exclusion of cancelled prescriptions with negative tests in `status.test.ts` and `loader.test.ts`. A cancelled item can no longer be shown with "Sent to pharmacy", "Pharmacy accepted" or "Handed over".
3. **Load error was always English.** **Fixed:** `loadReleasedPrescriptions` now takes an optional `locale` (default `en`) and returns `PRESCRIPTION_COPY[locale].error`; Arabic error covered in `loader.test.ts` and `prescriptions-screen.test.tsx`.
4. **`clearPrescriptions()` cleared the whole cache despite its name (low).** **Fixed:** renamed to `clearSessionClinicalCache` with documentation that it intentionally clears the whole session clinical cache; test updated.

The reviewer found no blocking defect in the shared-`clinicalCache` namespace decision (prefixed key cannot collide; `clearToken` clears in a `finally` block). All fixes are inside the declared scope and the full gate remains green after them.

## Lessons for workers

- Before adding a top-level folder under `apps/patient-mobile/src/features`, expect `src/features/domain-layout.test.ts` to fail: it asserts an exact set, not just business-domain naming. The established resolution (BUILD-53) is a one-line `DOMAIN_FOLDERS` registry entry — check the scope line first and document the deviation.
- `StatusPill` prepends a shape-distinct glyph to its text content, so `toHaveTextContent('Handed over')` fails with `✓Handed over`; assert on the pill's `accessibilityLabel` for the exact plain word (or use a regex).
- A defaulted parameter (`locale = resolveScreenLocale()`) is an Istanbul branch: render once without the prop to cover it.
- With `verbatimModuleSyntax: true`, use `import type` for type-only imports; `jest` is not an ambient value — plain recorder closures avoid the `jest.fn()` import requirement entirely.
- A declarations-only `types.ts` reports 0/0 in Istanbul; the module-wide 100% threshold is the authority, so do not add a dummy statement to "cover" it.
- Encode the clinical rule once in a pure function (`plainStatusFor`): only `dispensingEvidence` may produce the handed-over/ready status; acceptance and delivery confirmation must not. Then test the exact words and the absence of a ready claim explicitly.
- RX-02 has more events than the four display words: model `cancelled`/`renewal` even when they are not shown, and exclude terminals at the loader boundary so a cancelled item never inherits an in-progress or handed-over word. A renewal resets a stale acceptance to "sent".
- Localize generic load errors too: a locale-aware screen that renders an English-only error string is an accessibility/localization defect; pass the locale to the loader and use the translated copy.
