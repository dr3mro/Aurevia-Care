## Lessons for workers

- On a READY-11 re-dispatch, verify the worktree first (`cat .agent/base-sha`, `git rev-parse HEAD`, ancestry, `git diff fefe3f2 HEAD -- <scoped>`) before repeating any work; the recurring re-dispatch is a tracker-state problem a worker cannot fix, so do not fabricate a code change.
- The focused test command alone does **not** give 100% on the shared `TenantContextInterceptor`; run the full fast unit suite (`mvn -q -B -f apps/api/pom.xml -Pno-security,fast test jacoco:report`) before reading JaCoCo for that class. A bare `-Pno-security test` pulls in integration tests that need DB roles set by `worker-check.sh`/`db/check.sh`.
- In cloud workers, the worktree `opencode.json` is a `skip-worktree` CI profile; `check-pack.py`/`check-pack` unit tests will report it stale. Treat those as CI-profile results, not HEAD defects, and never regenerate it from a worker.
- As of HEAD `09f50e16`, `worker-check.sh` and `quick-check.sh` fail at shellcheck SC2015 in protected `scripts/agent-run.sh:51`; this is not a story defect and must not be "fixed" inside a story PR. Route it to a pipeline task.
- Do not "fix" the case-sensitive `Bearer` matcher inside READY-11: it widens CSRF-exempt requests and is shared with AUD-20261120-03; route it to a dedicated security story.
- Frontend definition of done needs the canonical `check.sh` scripts, not a standalone Jest/Vitest run; both include `tsc --noEmit` and a 100% coverage gate. `tsc` success is silent, so record exit 0 and zero `error TS…` lines as the evidence.
- Do not run the full `mvn verify` as a worker; wrap long gates in `timeout 300` and rely on `worker-check.sh` for the PostgreSQL integration/DB-policy tiers.
