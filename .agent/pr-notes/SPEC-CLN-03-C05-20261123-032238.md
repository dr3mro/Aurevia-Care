# SPEC-CLN-03-C05 — Retain original code and text after mapping

## Summary

HTTP-level acceptance evidence for CLN-03 clause 5: mapping a chart entry to a
diagnosis catalog must never overwrite the clinician's submitted original code
or text. The clause is already implemented, so this change adds only a test
class and a clause document; no production code, contract, migration, dependency
or existing test was changed. Five synthetic-tenant tests prove the original
text, code and code system stay byte-identical at record, verification, single
read, patient-chart read and stored row, with a positive mapping case and
hit-absent negatives (other tenant, unapproved draft, local code, no code).

## Lessons for workers

- To prove retention, make the submitted text observably different from the
  mapped text and assert both: for ordinary catalog codes `originalCode` equals
  `mappedCode`, so a code with no catalog hit (`PROC-77`) is needed to detect a
  verify-time bug that derives the original code from the mapping.
- A patient-chart GET uses a separate repository SELECT from the single-entry
  GET and the verify response; assert originals on all three paths plus the
  stored row before claiming persistence.
- `mvn -Pno-security,fast -Dgroups=integration` silently skips integration
  tests; use `-Pno-security -Dgroups=integration` and read the Surefire report
  count. Run SpotBugs only after compiling, or it is vacuously green.
- `scripts/worker-check.sh` runs every integration test and `scripts/check.sh`
  runs the full `mvn verify`; a swarm worker should run the individual policy
  scripts and targeted `-Dtest=...` suites instead.
- Under `-Pno-security`, `spotbugs.skip=true` by default (`apps/api/pom.xml:201`);
  a CLI `spotbugs:check` then exits 0 without analysing anything. Add
  `-Dspotbugs.skip=false` and read `spotbugsXml.xml`'s `total_bugs` before
  claiming static analysis was run.
