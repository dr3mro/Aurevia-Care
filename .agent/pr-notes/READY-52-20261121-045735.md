# READY-52 — API: structured JSON request log with a correlation ID and a redaction test (WEB-06)

## Summary

Adds a servlet filter in the new `com.aurevia.smartclinic.observability` package that
gives every HTTP request an opaque correlation id, publishes it to SLF4J MDC and the
response header, and emits one fixed-field JSON log line after the request. No file in
`web/` was changed and no dependency was added. All fixtures are synthetic; no patient
data, token or real identifier appears in code, tests or logs.

## Findings

1. **Full-chain correlation divergence (review finding, not changed).** A bounded
   `smartclinic-senior-backend` review observed that the pre-existing
   `web/TenantContextInterceptor` (registered on `/api/v1/**`, `preHandle`) reads and
   overwrites `X-Correlation-Id` with its own value using a *looser* allowlist
   (`[A-Za-z0-9._-]{1,128}`, no UUID requirement) and binds that value into
   `TenantContext` and the audit trail. The new filter therefore logs its own id while
   the interceptor may echo and audit a different one. The story explicitly forbids
   editing `web/`, and the obvious in-scope workaround (wrapping the request header)
   would break existing out-of-scope integration tests that deliberately send non-UUID
   ids (`ConcurrentTenantIsolationTest` lines 214, 445 and 630 use `conc-*` / `pool-*`
   and assert `audit_event.correlation_id LIKE 'conc-%'`). Decision: keep the filter's
   mandated UUID-only rule and record this as a follow-up needing a Product Owner /
   Architect decision to unify correlation ownership (meaningful deviation from the
   story's literal acceptance is **not** claimed). In isolation the filter satisfies all
   four story tests; a valid UUID header keeps all three values equal.
2. **Known tooling artifact (resolves the reviewer's build-gate questions).** The
   reviewer flagged that `-Pno-security,fast test` had not exercised SpotBugs, JaCoCo
   or the private constructor. The full `-Pno-security verify` did: JaCoCo 100% on both
   touched classes (0 missed on every counter) and a separate `spotbugs:check` run
   passed with no `HRS_REQUEST_PARAMETER_TO_HTTP_HEADER` finding (the header value
   passes through a private helper, so no suppression is needed). `worker-check.sh`
   and the Python suite still fail at `check-pack.py` with `opencode.json is stale`
   because this worktree holds the CI profile under `skip-worktree`; verified that
   `git show HEAD:opencode.json` **equals** `gen_opencode.render(.)` while the worktree
   copy does not. This is the documented OPS-CW-003-01 false positive, unrelated to
   this change; `check-names.py` and `check-wiring.py` pass.
3. **OWASP dependency scan could not complete locally.** With no `NVD_API_KEY` and
   even with `dependency-check.autoUpdate=false`, `dependency-check:check` timed out
   in the NVD API poll (EXIT=124 after 240 s). The integrator/CI holds the key and runs
   this gate. SpotBugs, the other required static analysis, passed.
4. **Filter is wired and active in the real chain.** The SpotBugs verify run's log
   shows `CorrelationIdFilter` emitting lines for real integration requests, e.g.
   `route:"/api/v1/clinical-notes/{id}/entered-in-error"` — a matched pattern, not a
   raw path. This confirms the bean registers and the route resolution works through
   the full servlet chain, beyond the direct unit calls.
5. No new `@SuppressFBWarnings`, no new dependency, no `.github/workflows`,
   `.opencode/`, `scripts/` or tracker edit. No push, tag or `gh` call.

## Lessons for workers

- Before adding a correlation/logging filter, read `web/TenantContextInterceptor`: it
  already owns `X-Correlation-Id` with a looser allowlist. Any UUID-only filter placed
  before it diverges unless the request is wrapped — but integration tests rely on
  non-UUID correlation ids reaching the audit trail, so that is an owner-level policy
  decision, not a local fix.
- `JsonNodeFactory.instance.objectNode()` plus `ObjectNode.put`/`toString` (Jackson 3,
  `tools.jackson.*`, transitive from `spring-boot-starter-web`) builds an escaped,
  fixed-field JSON line with no checked exception, no new dependency and no unreachable
  catch branch — ideal for a 100%-coverage log formatter.
- A `final` utility class with a private no-arg constructor is the repo's accepted
  pattern (`NoteInputs`); JaCoCo filters such constructors, so no reflection test is
  needed. Verify from the report rather than assuming.
