## Lessons for workers

- A test-only Java change does not move JaCoCo (test classes are not instrumented); say so explicitly instead of claiming an unrun 100% number.
- `git ls-files -v opencode.json` showing `S` plus three `test_check_pack` failures (and `coverage is not installed`) are worker-environment artifacts; never regenerate `opencode.json` as a worker.
- Snapshot `scripts/check.sh` can stop at a pre-existing shellcheck finding in a protected script before reaching module checks; when reporting it, prove it is pre-existing with `git diff origin/main` and attribute it to the pipeline owner.
- Detect list responses from the response schema shape (array or `$ref` to a `*Page` schema), never from `cursor`/`limit`/`nextCursor` themselves, or a mutated fixture can disappear from the check and pass vacuously.
- When a synthetic fixture is made by `String.replace`, assert the string actually changed; a no-op replacement gives a vacuous green.
- Surefire sets `basedir` to the module (`apps/api`), so the repo-root contract is `../../contracts/openapi.yaml` — two parent levels, not one.
- JUnit does not order multiple `@BeforeAll` methods deterministically; create roles and the database they own in one `@BeforeAll` to avoid a leftover-state-dependent green.
