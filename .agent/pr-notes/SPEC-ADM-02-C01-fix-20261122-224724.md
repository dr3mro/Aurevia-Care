## Lessons for workers

- A "complete but `@Disabled`" spec-clause test provides no evidence and fails
  `check-constraints.py`. Record missing behaviour in the clause doc's Gap and a `task-requests`
  follow-up instead of adding a skipped test you cannot enable.
- A fix pass on already-green, already-reviewed work is a verification/finalization pass:
  re-run gates and the reviewers on the current checkout, write the fix notes at the
  `<task-id>-fix-<stamp>.md` path, and commit. Do not rewrite deliverables when every reviewer
  answers GO and there are no Required findings — edits would invalidate the review timing.
- Do not run `scripts/check.sh` in a swarm worker (it delegates to full `mvn verify`, >10 min and
  ends the run as a timeout). Run targeted `-Dtest=...` plus the individual policy scripts,
  SpotBugs after compile, and the Java conventions unittest; leave the full gate to the integrator.
- In a cloud worker, `git ls-files -v opencode.json` returning `S` explains all `test_check_pack`
  and `check-pack` failures (OPS-CW-003-01); confirm once, run remaining stages individually and
  do not edit that file.
