## Lessons for workers

- When local gates are green but the integrator appears stuck, query the **public**
  check-runs API for the *actual PR head SHA* (not just your local HEAD — a local-only
  merge commit returns HTTP 422) and read PR labels read-only before writing another
  verification note. Absence of `gh` is not absence of evidence: `webfetch` to
  `api.github.com` needs no token.
- Trace the label state machine before concluding "the code is broken": the debugger
  re-adds `needs-fix` (`swarm.py:3149`) while `plan_integration` filters it
  (`swarm.py:2586`). Green CI + `needs-fix` = process blocker, not a gate failure. Do
  not make another code commit to "fix" it — only a new SHA and the same green CI result.
- A `check-runs` entry may be `in_progress` when first queried; re-read the single
  check-run by id a few minutes later rather than reporting an inconclusive verdict.
- In cloud workers a `check-pack`/`gen-opencode --check` failure usually means the CI
  profile is active under `skip-worktree`; verify with `git ls-files -v` before treating
  it as real. Never edit or regenerate that protected file to pass.
- Maven Central is unreachable here and the AWS SDK BOM is not cached; a temporary
  Google-mirror settings file in the repo root (removed before commit) resolves it. The
  `write` tool rejects `/tmp/opencode`, so use a repo-root temp file via shell.
- Workers must not run the full `mvn verify` (>10 min, ends the run as a timeout); run
  targeted test classes plus `jacoco:report` for the touched area instead.
