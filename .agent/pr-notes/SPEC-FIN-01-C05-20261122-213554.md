## Findings

- Test-engineer review found one real plan gap before coding: a combined `List.of("tenant_admin","privacy_auditor")` would short-circuit `noneMatch` at `tenant_admin` and never evaluate the `privacy_auditor` operand. Fixed by two separate invocations with single-element role lists and `clearInvocations` between them.
- Environment artifact (not a change defect): the worktree `opencode.json` is the CI profile installed under `skip-worktree` (`S`). It causes `check-pack.py`, 6 `test_check_pack` tests, `worker-check.sh` and `python-coverage.sh` to fail on "opencode.json is stale". Confirmed once with `git ls-files -v` and `git show HEAD:opencode.json`; the file was not regenerated. Integrator owns the full gate.
- Worker-image limit: `coverage` is not installed, so `python-coverage.sh` cannot run its coverage check. No `scripts/*.py` file was changed.
- Pre-existing and out of scope: conflict markers inside Javadoc comments in `apps/api/src/main/java/com/aurevia/exchange/hl7/Hl7ParseException.java`, `Hl7Parser.java` and `Hl7Segment.java` are committed in HEAD. They are inside comments, do not break compilation, and were not touched.
- Pre-existing and out of scope: `GET /api/v1/finance/reconciliation` is listed as accepted route-parity debt in `contracts/openapi/missing-routes.txt:47`. The HTTP behavior is proved by `FinanceFlowTest.reconciliationIsFinanceOnlyAndStableAcrossReplay`; the contract was not edited.
- Evidence is tool output from executed commands plus simulated/static specialist reviews; no human, clinical or real-patient evidence was claimed. All fixtures are synthetic and contain no PHI, secret, token or real domain name.

## Lessons for workers

- For a three-way `||` role predicate evaluated inside `noneMatch`, use separate calls with single-element role lists. A combined list stops at the first allowed role and silently misses the later operands.
- Use `clearInvocations(repository, audit)` between positive variants so each `verify(...SUCCESS)` counts exactly one audit row and the second stub actually overrides the first.
- A clause-proof-only story changes no production code: 100% coverage means no new production branch exists, but still map each exercised branch to a named test and confirm with a targeted JaCoCo run.
- Do not re-diagnose the skip-worktree `opencode.json` artifact. Confirm it once (`git ls-files -v` → `S`, `git show HEAD:opencode.json`) and run the remaining gate stages individually.
