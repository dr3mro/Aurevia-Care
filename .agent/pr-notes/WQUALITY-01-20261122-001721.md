# WQUALITY-01 — Swarm quality: the integrator tells failed, pending, missing and approval-required Delivery apart

## Summary

`scripts/swarm.py` now classifies current-head Delivery evidence with a pure `delivery_state(runs, head_sha)` function returning exactly `passed`, `failed`, `pending`, `missing` or `approval-required`. Only runs whose `headSha` equals the PR head count; the newest such run wins, so a re-run supersedes an earlier failure. Cancelled, failed and timed-out runs are `failed`; a run/job waiting for a contributor or environment approval is `approval-required`; a queued or running job is `pending`; no matching run (or a skipped run with no usable evidence) is `missing`. A skipped run is *not* trusted as passed — the caller applies the documented Markdown-only exception only after inspecting the changed files.

`delivery_gate(pr, head, runs)` applies the integrator policy: `passed` merges; `failed` goes to the fix workers; `pending` waits without a label; `missing` and `approval-required` comment on the PR and dispatch a fresh Delivery run, never merging. The trusted CLI integrator enables this check in GitHub Actions (`GITHUB_ACTIONS == "true"`); direct merge-mechanics callers keep their existing behavior. The run listing is filtered by commit and enriched with job-level gates, because an environment approval is only visible on a job. 38 new tests cover every state, the SHA rule, supersession, the documentation exception and the integrator wiring.

## Findings

1. **Reviewer fix applied (defect, simulated reviewer evidence).** `delivery_state` originally mapped a bare `skipped` conclusion to `passed`. `paths-ignore` makes a docs-only change produce no run at all, so `skipped` cannot prove a Markdown-only change and could let a PR merge without verification. Fixed by returning `missing` for `skipped` and applying the documentation exception in `delivery_gate` from the actual changed files; tests added for skipped-on-docs (merges) and skipped-on-code (requests a run).
2. **CI enablement is implicit (design note).** The integrator workflow's exact CLI invocation is asserted by `scripts/tests/test_task_files.py:273-276`, and the workflow is outside this task's scope, so the check is enabled inside `integrate_batch` when `GITHUB_ACTIONS == "true"` rather than by a new workflow flag. This is correct for the real integrator job but would silently disable the gate for a future non-Actions caller. A follow-up could pass an explicit flag from `.github/workflows/swarm-integrator.yml` and keep the env default as defence in depth.
3. **Pre-existing environment artifact (tool evidence).** The worktree `opencode.json` is the CI profile under `skip-worktree`. With that file, six `test_check_pack` tests failed (`opencode.json is stale`); after restoring the committed profile with `git show HEAD:opencode.json > opencode.json`, the full suite was green (911 tests). The CI profile was restored after measurement. This is a known measurement artifact, not a change defect.
4. **Pre-existing committed conflict markers (tool evidence, out of scope).** HEAD contains unresolved markers in `apps/api/src/main/java/com/aurevia/exchange/hl7/Hl7ParseException.java`, `Hl7Parser.java` and `Hl7Segment.java`. They are unrelated to this story and were not touched; the integrator should route them to an owner.
5. **`statusCheckRollup` absent (tool evidence).** Executed grep found no `statusCheckRollup` in `scripts/swarm.py` at HEAD; the evidence source is the Delivery run listing plus `gh run view --json jobs`, which is also the only place job-level environment gates are visible.

## Lessons for workers

- Scripts protected by `PROTECTED` are mergeable by this swarm, but the workflow that calls them is not. Before changing a CLI call signature, grep the tests for an exact `assert_called_once_with`: `test_task_files.py` pins `integrate_batch(queue, gate)`, so behavior must be enabled inside the function (or by an env default), not by adding a positional argument.
- A bare CI conclusion such as `skipped` is not evidence of a documentation-only change. Apply docs exceptions from the changed file list, never from a run label.
- When `python-coverage.sh` reports "coverage is not installed", it silently falls back to plain unittest. Install the `coverage` wheel into `/tmp/opencode/covlib` and set `PYTHONPATH` with `REQUIRE_PY_COVERAGE=1` so the changed-line/branch gate actually runs; the diff-based gate, not the whole-file percentage, is the rule for an existing script with legacy gaps.
- The worktree `opencode.json` in a cloud worker is the CI profile under `skip-worktree`; measure pack tests against `git show HEAD:opencode.json` and restore the worker profile afterwards.
