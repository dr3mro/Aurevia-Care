## Lessons for workers

- For a "prove this clause" story, check the domain state machine, the controller
  endpoints and the migration/history trigger before assuming a GAP. A fully built
  clause needs an enabled HTTP-level test and status "Proven by tests", not a
  `@Disabled` placeholder.
- Give each HTTP integration test its own disposable database name and distinct
  fixture slot dates when several workers share one PostgreSQL server; it avoids
  both cross-worker clashes and within-class exclusion-constraint conflicts.
- In this cloud worker a red pack check / six Python pack tests mean the CI profile
  is checked out under `skip-worktree`; confirm with `git ls-files -v opencode.json`
  and `git show HEAD:opencode.json` instead of regenerating the file.
- `ActionPolicy` deliberately lets reception book/check-in/cancel/no-show but only
  clinician start/complete; pick the actor per transition or a correct happy-path
  chain will fail with 403.
- Booking fixtures use hard-coded 2027 instants while `ClockConfiguration` uses
  `Clock.systemUTC()`: once the real clock reaches early 2027, `MIN_NOTICE_NOT_MET`
  will make these (and `SeriesHttpIntegrationTest`) fail. This is inherited, not
  introduced here; it needs a separate, broader clock-injection / relative-date
  task and cannot be fixed inside a clause-evidence scope.
