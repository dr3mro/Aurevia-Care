# READY-07 — Staff web state views and a global error boundary (WEB-09)

## Summary

Added the six required screen-state views with bilingual (en/ar) labels, correct
live-region semantics and tokenized styling; added a class-based global error
boundary that generates a correlation ID, logs only that ID plus the error class
name, and offers a working Retry. Mounted the boundary in the in-scope
`AppShell`. Added `StateView.forTransportError` mapping all 11 `TransportError`
kinds to the appropriate blocking state. No existing screen logic was changed.

## Affected requirements

- WEB-09 — every screen defines loading, empty, error, forbidden, conflict,
  session-expired and timeout/offline states; a global error boundary shows the
  correlation ID and logs without patient data.
- UX-01 — English and Arabic bundles, RTL document direction, logical layout.
- WEB-06 — no patient data or response text in logs; only ID and error name.
- Depends on READY-06 (`TransportError` kinds), already merged.

Routine (contained UI components) with one cross-boundary dependency: the
presentation layer now imports the typed `TransportError` from `src/api`. No
clinical decision, patient association, prescribing or tenant-boundary logic is

## Findings

1. **Scope conflict (step 4 vs `scope`).** The story says to wrap the app in
   `src/main.tsx` / `App.tsx`, but the declared scope is only
   `src/components`, `src/app` and `src/features`. I did not edit out-of-scope
   files. The boundary is mounted in `src/app/AppShell.tsx` (in scope) around
   its entire returned tree, so all route screens and shell markup below it are
   covered while both providers remain above it. Residual: errors thrown in
   `AppShell`'s own body before `return`, in either provider, or in
   `App.tsx`/`main.tsx` are not caught, and React boundaries never catch event
   or async errors. READY-19 owns `App.tsx`; it can relocate the boundary to the
   true root in its own story. `App.tsx`'s plain `<p role="status">Loading</p>`
   fallback and `screenLoading.test.tsx` were deliberately left unchanged
   (out of scope).
2. **Kind mapping decisions.** `session-expired` → `SessionExpiredState`,
   `forbidden` → `ForbiddenState`, `conflict` and `precondition-required` →
   `ConflictState`, all other kinds → `ErrorState`. Only six view components
   were requested, so `csrf-missing`, `not-found`, `invalid`, `rate-limited`,
   `server`, `offline` and `timeout` share the generic blocking view; its copy
   says the request could not be completed and offers Retry, and never shows
   response text. `csrf-missing` cannot be fixed by retrying until a CSRF cookie
   exists (browser/session concern, READY-11); this is a known limitation, not a
   patient-safety issue. 428 maps to the stale/precondition view because it is a
   version precondition rejection.
3. **Reviewer-driven fix.** The bounded React review identified that the
   boundary's fallback Retry was a no-op that left the user stuck. Fixed by
   adding `ErrorBoundary.retry` (clears failed state and remounts children) and
   a regression test. The review also confirmed the boundary must stay below
   `ThemeProvider`/`I18nProvider` because `ErrorState` uses hooks; it does.
   `getDerivedStateFromError` is static and generates the ID once per failure;
   the test asserts the call happened, not a count (StrictMode may double-invoke
   it).
4. **Residual accessibility gap.** Blocking states use `role="alert"` and
   `aria-live="assertive"`; unlike accessibility-patterns.md §7 they do not
   programmatically move focus to the alert. Not added here: these views are
   rendered by many screens and a global focus move could steal focus during
   transient states. Follow-up with a screen-level focus test.
5. **Expected test noise.** React 18 and jsdom print `Uncaught [BoomFailure…]`
   for the intentionally throwing child test and existing provider-throw tests.
   Those are not this boundary's log line: the test asserts the boundary's own
   single one-string call equals `${correlationId} BoomFailure` and contains
   neither the error message nor the secret prop.
6. No defects were found in existing code. No GitHub operation, push, tag or
   `gh` call was made.

## Lessons for workers

- When a story step names a file outside its `scope`, stay in scope and mount
  the closest in-scope equivalent; record the residual gap in `Findings` rather
  than silently editing the out-of-scope file.
- In this module, co-locate new tests under `src/...` when `tests/` is outside
  the declared scope; coverage already excludes `**/*.test.{ts,tsx}`.
- Testing Library cleans up only after each `it`. Two renders in one test make
  `getByRole` ambiguous — call `first.unmount()` before the second render.
- Under `exactOptionalPropertyTypes`, declare optional props as
  `foo?: T | undefined` so a caller can pass a possibly-undefined value without
  a spread workaround.
- A class error boundary cannot use hooks; render a hook-based fallback only
  when the boundary is mounted below the providers.
- Give every Retry button a real recovery action; a no-op Retry is a UX defect
  that a reviewer will (correctly) flag.
