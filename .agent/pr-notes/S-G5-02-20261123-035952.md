## Lessons for workers

- `python3 -I scripts/check-docs.py` enforces relative-link resolution, GFM table
  cell parity, heading-level jumps and spec requirement IDs; count unescaped
  pipes in every new row and `test -f` every reused link before editing.
- Before using a task ID as a `blocked` reason in a launch decision pack, check
  the task's actual mark in TODO.md and the relevant production wiring. The doc
  gates validate structure, not the truth of a rationale; a stale blocker laundered
  into a green check is still a false clinical-safety statement.
- When a senior-developer brief conflicts with current code/tracker evidence, the
  brief itself says to note the error and carry on from the story and AGENTS.md.
  Record the contradiction with exact file/line evidence in Findings and get the
  plan reviewer to re-review the corrected plan before editing.
- A decision pack that must "record no approval" keeps `Status: Not approved`,
  a status legend with only `open`/`blocked`, and placeholder Name/Date/Decision
  cells; add evidence cells that describe artifacts a person supplies, never
  values that imply the repository already holds a signed approval.
