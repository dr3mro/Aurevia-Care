## Lessons for workers

- When a clause is already implemented, treat it as an outcome-assertion proof:
  identify the one assertion that would fail on regression (here, different issuer
  201) and do not rely on status-only setup calls as evidence.
- Add a positive-control read before asserting a cross-tenant 404, or a broken id
  extraction can make the 404 pass vacuously.
- Assert the error body `code` and `message`, not just 409: the fallback
  `DuplicateKeyException` handler also returns 409 with different text.
- Use a dedicated DB plus distinct org UUIDs and subject names for an HTTP clause
  test even when the sibling uses different ones; `DROP DATABASE ... WITH (FORCE)`
  plus `NOBYPASSRLS` roles and `SET app.current_org` keep forced RLS honest.
- Do not add `fast` to a targeted `-Dtest` integration run; its
  `excludedGroups=integration` wins and gives a false green with zero tests.
- Stage new files before running `worker_gate.py`, otherwise untracked directories
  are reported as out-of-scope paths.
- In a cloud worker, confirm the `opencode.json` "stale" result once
  (`git ls-files -v` → `S`, compare HEAD bytes), record the final line, run the
  remaining gate stages individually and never regenerate the protected file.
