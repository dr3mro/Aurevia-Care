# BUILD-67 — Reception worklist and check-in screen: match the approved design

## Summary

Rebuilt the reception "Today" screen in `apps/staff-web/src/features/scheduling` to match
`docs/design/approved/reception-worklist.png`: a 230 px dark navigation rail that becomes a
top bar when narrow, a Today header with facility/time-zone and facility/language/booking
controls, five state cards, a tenant/facility-scoped worklist with filters and one lifecycle
action per row, a check-in panel and a booking-check panel. State is conveyed by word, glyph
and dot as well as tint; every visible string is bilingual. Tenant, lifecycle and bilingual
contracts stay intact. Synthetic data only.

## Clinical and architecture review

State is conveyed by word, distinct glyph and dot in addition to tint. The stale-slot alert
and single-pick latch reinforce CLN-01; the server still owns real slot exclusivity. The
facility switcher scopes the displayed worklist but not the API query, because the published
contract has no facility parameter. Handoff is disabled until an active assignee is present,
including when the "Unassigned" option yields an empty string. The identity checklist remounts
per appointment so a tick cannot carry over between patients. Real-patient approval is not
claimed: this is synthetic UI evidence only.

## Lessons for workers

- Read the coverage summary after every worker run: per-file 100% gates fail on a single unused fallback function or unreachable guard, so delete dead code rather than inventing a test for it. Use `defined(...)` instead of `?? ''` when a fixture is guaranteed to be present.
- A facility or tenant filter must be applied at the boundary and tested with both sides (select LAB, select MAIN); a header control that changes only a caption is a acceptance gap.
- In staff web, `bash apps/staff-web/check.sh` is the definition of done; also paste the separate `npm run typecheck` final line. `npm run lint` enforces `max-lines-per-function` 150 — split large `describe` blocks and extract helpers before adding more tests.
