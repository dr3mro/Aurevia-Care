## Lessons for workers

- For a launch-readiness evidence table, separate "a test exists in this checkout" from "the requirement is signed off": the spec's last line of section 8.1 names the four infrastructure-owned rows, and `docs/security/threat-model.md` lists `GAP:` lines where a filter unit test is not enough.
- Use `grep -rn "WEB-0"` first, then a per-ID `grep -rln` over source and test trees, then a path-existence check; it is faster and more defensible than reading every candidate file.
- `scripts/check-docs.py` enforces resolvable relative links and even table pipe counts. backtick-quoted paths in table cells are not treated as links, which avoids false broken-link findings on long evidence paths.
- Reuse the owner names and row intent already in `docs/operations/production-readiness/README.md` and `launch-checklist.md` instead of inventing new owners; the Product Owner decides scheduling, not the worker.
