1. **Brief was wrong about surface and `@Disabled` — corrected, no work stopped.** The task advisor brief assumed the delivery-outbox surface and instructed `@Disabled("GAP: …")` tests for an unbuilt clause. `scripts/check-constraints.py:56` rejects any added Java `@Disabled` and `scripts/quality-gate.sh:13` enforces it, so a literal disabled test would fail the gate (and AGENTS.md forbids skipped tests). A repo precedent (`docs/spec/clauses/messaging/use-durable-client-message-ids-deduplicate-retries.md:60-68`) removes disabled placeholders and records the gap in prose. The plan-reviewer required switching to a surface where the clause IS built. The pharmacy substitution decision has an `Idempotency-Key` route, a one-time-close business guard (`SubstitutionService.decideInside:225-226`) and a durable `UNIQUE (organization_id, proposal_id)` on its signed revision (`V94:48`). All three tests are therefore ACTIVE and green; the note is honest (`Partly proven`, scoped to substitutions, delivery gap documented).
2. **Clause status is `Partly proven`, not `Proven by tests`.** The delivery/event surface remains unbuilt: `DurableEventService.publish:109` dedups only by retry key and `V55:53` is key-scoped, so a fresh key with the same business identity writes a second outbox row. The note's Gap describes one cross-boundary implementation task to close it. No task was created by this worker (trackers are owned by the integrator).
3. **Error-code correction to the brief.** The brief suggested `422/409` for missing/different payload. On the substitution route the real codes are `428 IDEMPOTENCY_KEY_REQUIRED` (absent header, `IdempotencyKey.parse`) and `422 INVALID_IDEMPOTENCY_KEY` (malformed key); the different-key case is refused by `409 CLOSED_PROPOSAL`. Tests assert these exact codes.
4. **Claim eviction is test-only.** V94's `pharmacy_substitution_decision_no_update_delete` trigger makes the claim immutable; the test disables that trigger only in the dedicated throwaway database `orevia_expired_retry_key_it`, deletes just the proposal's `approve` claim, and restores the trigger in `finally`. `@BeforeAll` drops/recreates the DB; `@AfterAll` drops it. No production or shared database is touched.

## Lessons for workers

- Before writing a clause test, check `scripts/check-constraints.py` first: an added `@Disabled` is a red gate, not a green PR. If the advisor brief prescribes one, look for a surface where the clause is already built, or record the gap in prose and file a task request.
- `Idempotency-Key.parse` returns 428 for an absent header and 422 for a malformed one; `HttpStatus.UNPROCESSABLE_ENTITY` was renamed to `UNPROCESSABLE_CONTENT` in Spring 7 (Boot 4.2).
- A version precondition is checked before a state guard: to prove `CLOSED_PROPOSAL` rather than `STALE_VERSION`, present the committed version (`If-Match: 2`) on the retry.
- `mvn -Pno-security,fast -Dgroups=integration` runs no integration tests; use `-Pno-security -Dgroups=integration` and read the Surefire count.
