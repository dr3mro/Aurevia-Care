## Lessons for workers

- Before writing a spec-clause evidence note, run `python3 -I -c ...` against `check-docs.py`'s `spec_ids` logic (or grep the spec table) to confirm every requirement ID you plan to cite is defined. `PAT-01` and `ARC-03` appear in task names/Javadoc but are NOT defined IDs; using them in a checked Markdown file would fail `check-docs.py`.
- From a file under `docs/spec/clauses/product/`, root files are four levels up (`../../../../`) and `docs/operations/` is three levels up (`../../../operations/`) — verify every relative link before running the docs check.
- For a negative/scope clause, record the exact grep commands and their results as evidence; "no such class exists" is only credible with a command you actually ran.
