## Lessons for workers

- `scripts/check-docs.py` resolves a relative Markdown link from the file's own
  directory, not from the repository root: from `docs/operations/exercises/`,
  root files need `../../../`, sibling `docs/operations/<area>` files need
  `../<area>/`, and `docs/WORKFLOW.md` needs `../../WORKFLOW.md`.
- Before citing a command in operations documentation, read the script or its
  `check.sh` and run it on the synthetic fixtures; evaluator unit tests are fast
  and give real final lines. A plausible-looking command that does not exist is
  worse than an honest `NOT YET IN PLACE:` marker.
- `scripts/check-docs.py` skips `.agent/` notes, so requirement IDs in notes do
  not affect the gate, but IDs in the scoped Markdown files must all exist in
  the specification.
- The offline evidence evaluators judge declarations only. Never phrase a
  synthetic rehearsal as proof that a restore, alert, revocation or human
  approval occurred.
