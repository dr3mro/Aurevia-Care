# SPEC-CLN-05-C05 — CLN-05 clause 5 API test evidence

## Summary

Added an active HTTP-level clause test and its clause-evidence document for
"Entered-in-error preserves the prior revision and records actor, reason and affected
recipients." The clause is already implemented in the chart's signed-note ledger
(`com.aurevia.smartclinic.clinical.notes`); this task adds proof only. No production code,
existing test, contract or migration was changed.

## Affected requirements

CLN-05 (clause 5). Mapping: prior revision preserved → `enteredInErrorAppendsASupersedingRevisionAndRecordsActorReasonAndRecipients`
(HTTP `supersedesVersion=2`, version 3, GET history and direct ledger query show the
signed row untouched); actor → `enteredErrorActor=clinician-c` (a different organization-A clinician from the
`clinician-a` signer), stamped by the V15 trigger from `app.actor`, not copied from the
prior revision; reason → `enteredErrorReason=wrong patient`; affected recipients →
`affectedRecipients=["lab-a","clinic-b"]`. Refusals: unsigned draft (409
`INVALID_TRANSITION`), stale version (412 `STALE_VERSION`), blank reason (422
`INVALID_REASON`), wrong role (403 `FORBIDDEN`), other tenant (404 `NOT_FOUND`),
malformed recipients (422 `INVALID_RECIPIENTS`).

## Risk class

Routine (test-and-documentation slice; no production behaviour changed). The underlying
clinical behaviour is safety-relevant, so the positive test checks the stored ledger as
well as the HTTP view, and five negative paths assert that refusals append nothing.

## Findings

1. Source survey: `com.aurevia.smartclinic.chart.record` (`ChartController`, `ChartService`,
   `ChartRepository`, `ChartEntry`, `RecordEntryCommand`, verification state types) implements
   CLN-03 only. The clause is implemented by `ClinicalNoteService.markEnteredInError`,
   `ClinicalNoteController`, `NoteRepository` and `db/migrations/V15__clinical_note_signing.sql`
   in the chart's note ledger. The new test therefore lives in the required `chart.clauses`
   package but exercises `clinical.notes` through HTTP.
2. Independent Test Engineer review: the original actor assertion used the same subject as
   the signer, so an implementation that copied the signer would still have passed. Fixed
   by seeding a second clinician and recording the error as that distinct subject; the HTTP
   field, the stored `entered_error_actor` and the stored `data_entry_subject` now all assert
   the different subject. Two LOW findings were also fixed: the wrong-role and cross-tenant
   negatives now re-read the view to prove no revision was appended, and a malformed-
   recipients negative now covers the boundary the clause doc credits to `NoteInputs`.
3. The clause was already built and covered by `ClinicalNoteServiceTest` and
   `ClinicalNoteRevisionIntegrationTest`; a red-first phase was not possible without
   changing production code, which is out of scope. The new test asserts observable outcomes
   and would fail if the append/actor/reason/recipients behaviour were removed.
4. Environment-only defect (not a change defect): the cloud worker's skip-worktree CI
   `opencode.json` makes `check-pack.py`, `gen-opencode.py --check` and six `test_check_pack`
   cases fail. Already recorded in AGENTS.md / BUGS as OPS-CW-003-01; no action taken here.
5. Pre-existing, unrelated documentation defect (not changed here): conflict-marker text is
   committed inside the Javadoc of `exchange/hl7/Hl7ParseException.java`, `Hl7Parser.java`
   and `Hl7Segment.java`. It does not affect compilation or this clause and is outside the

6. No reproducible product defect found in this clause. No `task-requests` needed.

## Lessons for workers

- In Spring 6.2 HTTP 422 is `HttpStatus.UNPROCESSABLE_CONTENT`, not
  `UNPROCESSABLE_ENTITY`; assert the numeric status plus the error code (`INVALID_REASON`)
  when a test only cares about the protocol status.
- When checking a shell command's exit code through a pipe, use `${PIPESTATUS[0]}`; `$?`
  reports `tail`'s status and can turn a failing gate into a false green.
- To prove that a row records the *current* actor, make the actor different from the signer
  and author in the fixture. Identical identities make the assertion incapable of detecting
  an implementation that copies an earlier identity instead of stamping the request one.
- A cloud-worker `opencode.json is stale` failure is a CI-profile/skip-worktree artifact:
  confirm once with `git ls-files -v opencode.json` and the HEAD/worktree hashes, then let
  the integrator run the full gate instead of editing the protected generated file.
