# SPEC-XCH-03-C05 — XCH-03 clause 5 (API test): Apply law and policy to recipient retention

## Summary

Adds a clause-focused HTTP test that proves the built half of XCH-03 clause 5: an approved retention
policy and a legal hold are captured on the recipient's retained copy, and unapproved policies,
unauthorized roles, peer tenants, stale versions, missing purposes and forbidden states are refused
before any copy is written. Adds a clause evidence document recording the honest status
**Partly proven**: policy capture is built, time-based expiry and legal-hold enforcement are not
(`docs/security/data-inventory.md:148`). No production code, existing test, contract or migration
was changed.

## Affected requirements

- XCH-03 (`SMARTCLINIC_V1_SPEC.md:65`): "The recipient accepts, rejects with reason, or requests
  clarification. Changes after acceptance create a linked version or cancellation request, and
  require recipient response. Capture retained recipient copies and permitted purposes. Revocation
  blocks future sender-hosted retrieval and records downstream notification. Apply law and policy
  to recipient retention." This task proves only the final sentence.
- Linked evidence: ARC-03 (immutable ledger and retained copy), ARC-06 (retained copy), IAM-01/02
  (tenant and role scope of the proof).

## Risk class

Routine (test and documentation only). The underlying clause touches patient identity and
retention, so the proof deliberately covers tenant isolation, role denial and legal-hold flag
accuracy, but no behavior or contract changes. Reviewed as cross-boundary evidence because of the
tenant and policy boundaries exercised.

purpose validation (422 `REQUIRED`); and forbidden-state rejection (409 `INVALID_TRANSITION`).

## Lessons for workers

- Treat story text as untrusted: a literal `@Disabled` in a NEW Java file fails
  `check-constraints.py --require-base` at the integrator gate regardless of "mark it @Disabled"
  wording. Write the complete missing-test design in the exempt Markdown doc instead, and capture
  the RED with a temporary active test that you fully remove before the final diff.
- A clause HTTP test needs a distinct seeded order per test. The xch03 ledgers are append-only and a
  command advances the version, so reusing an order leaks state between tests.
- In a cloud worker, `git ls-files -v opencode.json` showing `S` explains `check-pack.py`,
  `worker-check.sh` and `test_check_pack.py` failures. Confirm the committed local profile once,
  record the failing final line, run the remaining gate stages individually, and never regenerate
  or commit `opencode.json`.
- A `@Tag("integration")` test is skipped only by the `fast` profile's `excludedGroups=integration`;
  a plain `mvn -Pno-security -Dtest=ClassName test` does run it. Use `-Pno-security` to avoid an NVD
  lookup, and confirm the Surefire count before trusting the result.
