# SPEC-PAT-02-C04 — Avoid persistent clinical caches (PAT-02 clause 4)

## Summary

Added a clause-only Jest acceptance proof that the patient app keeps clinical payloads in
process memory and never persists them, plus the clause evidence doc. No production code,
existing test, contract or migration changed; the clause was already implemented.

Scope (only these two new files):
- `apps/patient-mobile/src/spec/patient-access/avoid-persistent-clinical-caches.test.ts`
- `docs/spec/clauses/patient-access/avoid-persistent-clinical-caches.md`

Implementation found (step 1 of the story): `apps/patient-mobile/src/api/clinicalCache.ts`
exports `ClinicalNamespace`, `cacheClinical`, `readClinical`, `clearClinicalCache` and
`clinicalCacheSize` over one process-local `Map` with no storage imports. Sign-out wiring is
`api/tokenStore.ts` (`clearToken` calls `clearClinicalCache` in a `finally`) and
`api/idleSession.ts` (`createSignOutOnIdle` routes the idle deadline through `clearToken`).
Released-projection stores in `features/prescriptions/store.ts` and
`features/handouts/store.ts` reuse that shared cache; `features/tracker/cache.ts` has its own
process-local `TrackerCache` with the same clear-on-sign-out contract. Status is therefore
"Proven by tests" and all tests are active — no `it.skip`/`.skip`/`xit` was needed.

## Lessons for workers

- A clause-proof task whose implementation already exists and whose scope forbids production
  edits cannot show a red baseline; write the negative assertions for the forbidden states and
  say plainly that no red phase was possible rather than claiming test-first.
- Spy on the single real persistent write API (`expo-secure-store.setItemAsync`) and reset it
  in `beforeEach`; that is a deterministic proof of "never persisted" without a timing or
  race-based test.
- Keep the clause doc's Evidence strictly to units the test actually calls; list sign-out and
  idle wiring as context only, and check whether a neighbouring cache really shares the
  implementation before claiming it does.
