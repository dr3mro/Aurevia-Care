# ISS-748 — Return uniform ErrorBody for malformed JSON binding failures

## Summary

`ApiErrorHandler` had no handler for Spring/Jackson body-binding failures, so a malformed or empty command body got Spring's default 400 body (`{"timestamp":...,"status":400,"error":"Bad Request","path":...}`) instead of the uniform `{code,message,correlationId}` ErrorBody. Added one `@ExceptionHandler(HttpMessageNotReadableException.class)` that returns 400 with the stable code `MALFORMED_REQUEST_BODY`, a constant message and the bound correlation id. No request text or exception detail is echoed. The domain 422 path is unchanged. Only three in-scope files changed; no new class, package, dependency, route, migration or contract edit.

None (task declares no requirement IDs).

## Risk class

Cross-boundary — a global `@RestControllerAdvice` changes the error body for every route on this exception type. No data, authorization, route, migration or OpenAPI change; grep found no suite asserting Spring's default 400 body, so regression risk is low.

## Authorization boundaries and audit events

No tenant, role, patient-link or audit-event change.

## Findings

- **The brief was wrong about `{}`.** It claimed `{}` is valid JSON that reaches domain 422; the red HTTP run proved it returns Spring's default 400 on this Jackson 3 stack, so the existing test comment ("An empty JSON object is rejected earlier by Jackson as a 400") was correct and was left unchanged. The `{}` case now asserts the uniform 400 error body. If Jackson defaults ever change so `{}` binds, this test becomes a useful canary and should be updated with the new documented behavior.
- **No `@Valid`, `MethodArgumentNotValidException` or `BindException` exists in `src/main`.** The story's "where applicable" validation handlers would be dead, uncoverable code, so they were deliberately omitted. If validation annotations are introduced later, add a handler plus tests at that time.
- **Optional reviewer notes, not fixed here:** the unused `exception` parameter is kept for consistency with the existing `handleDuplicate`/`handleMissingContext` handlers and is documented by `@param`; `docs/reference/modules/api-api.md:77` lists the old error-code set and is now incomplete (task requested below); the two pre-existing handlers that include `exception.getMessage()` in 403/422 bodies were not touched; a non-UUID but allowlist-valid correlation header still diverges between `CorrelationIdFilter` and `TenantContextInterceptor` (pre-existing, needs an owner decision).
- Environment artifacts recorded once, not re-diagnosed: OPS-CW-003-01 (`opencode.json` CI profile under `skip-worktree`) explains the six `test_check_pack` failures; OWASP/NVD is not run locally without `NVD_API_KEY`. Neither is caused by this change.
- No patient data, credentials or raw logs appear in tests or notes.

## Lessons for workers

- Do not assume which body shape triggers the binding path. On this Jackson 3 stack `""`, `"{"` and `"{}"` all throw `HttpMessageNotReadableException`; verify against the real HTTP stack before writing status assertions, and keep the 422 domain path proven by a syntactically complete but domain-invalid body.
- Send a canonical UUID `X-Correlation-Id` in HTTP tests that compare the body correlation id to the response header: `CorrelationIdFilter` and `TenantContextInterceptor` each generate their own id when the header is absent, so the two would diverge.
- `HttpMessageNotReadableException` has no single-String constructor; construct it with `(String message, HttpInputMessage)` (a `null` input message is fine for a handler that never reads it).
- Set `TenantContext` with the record constructor `new TenantContext(org, subject, purpose, correlationId)`, not four separate arguments.
- For a global `@RestControllerAdvice` change, assert a constant message and the stable code, and assert the parser's detail text is absent, so the test fails if request text is ever echoed.
