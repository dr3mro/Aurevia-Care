# BUILD-52 — Staff web: register the new feature routes and navigation

## Summary

Registered the role model for the staff-web route table so the navigation rail and
a pasted URL enforce the same access. Added the two BUILD-51 tenant data-exchange
entries to the screen map (`/operations/exports`, `/operations/imports`) with
English and Arabic labels, and made `AppShell` render the fixed forbidden page
instead of a screen when the active role cannot open the matched route. Every
feature `routes.ts` is already discovered by the `import.meta.glob` in
`src/app/routes.tsx` and every page is loaded with `React.lazy`, so each feature
keeps its own chunk; the forbidden page is now lazily imported in the shell too,
so adding the guard does not merge it into the shell bundle.

Scope kept to `apps/staff-web/src/app`. No dependency, migration, tracker or
workflow file was changed. All data is synthetic; no push, tag or `gh` call.

## Affected requirements

- **UX-01** — the new rail entries carry paired English/Arabic labels; the shell
  denial uses the shared, RTL-aware `ForbiddenState` through `ForbiddenPage`.
- **WEB-09** — a role without access sees the plain forbidden state instead of a
  screen, on a direct link as well as in the rail (no data is revealed).
- Screen map (section 2 of `docs/design/screens-and-navigation.md`) and the IAM-01
  role names constrain which roles receive each entry.

## Lessons for workers

- When a shell guard must match the rail, derive it from the same navigation
  table and key it on the registered route pattern (`matched.pattern`), not the
  bound pathname — `matchRoute` replaces `:id`, so a pathname lookup silently
  fails open for every parameterised route.
- Import a feature page from the shell with `React.lazy`, never statically: a
  static import makes Rollup emit `INEFFECTIVE_DYNAMIC_IMPORT` and folds the
  feature's page into the shell chunk.
- Before blaming a red `check.sh` on your diff, confirm the failing files on a
  clean HEAD with `git stash push -u` / `git stash pop`; record the command and
  final lines, then prove 100% coverage for your own files with a CLI-only
  `--exclude` of the pre-existing failures.
- The two `privacy_auditor` exact-list assertions in `navigation.test.tsx` are
  legitimate behaviour changes when a nav row is added; update them with an
  explanatory comment rather than treating them as a regression.
