## Summary

Test-only story for CLN-01 clause 5. Discovery found the clause already implemented in the scheduling
domain, so no production code, contract or migration was changed. Added one HTTP-level integration test
class on real PostgreSQL that proves the recorded reason and authenticated actor for availability
overrides, cancellation and no-show, plus refusal paths (missing reason, stale version, peer tenant,
outside availability without an override). Added the clause evidence document. All tests and the
worker fast gate pass; the full JaCoCo/Delivery verify remains with the integrator as AGENTS.md
requires for swarm workers.

Discovery (tool evidence: file reads and executed grep): the clause is implemented today by
`com.aurevia.web.AppointmentController` (`POST /api/v1/appointments`,
`/api/v1/appointments/{id}/cancel`, `/api/v1/appointments/{id}/no-show`, `/reschedule`),
`com.aurevia.scheduling.AppointmentService` (`createOne`, `checkAvailability`,
`transition`, `cancel`, `noShow`), `AppointmentState.requiresReason()`, `SchedulingInputs.reason()`,
`AppointmentRepository`/`AppointmentEvent`/`AppointmentView`, and `db/migrations/V8__scheduling.sql`
(`override_reason`, `appointment_event.reason`, trigger `appointment_event_actor` deriving `actor_id`
from `app.actor`, forced RLS and the state-machine guard). The follow-up override path in
`scheduling/followup` (CLN-06) is a different clause and was not re-tested here. The action routes are
currently listed in `contracts/openapi/missing-routes.txt` rather than `contracts/openapi.yaml` — a
separate tracked contract-publication debt, not a missing behaviour.

## Lessons for workers

- For a clause-verification story, read the production path first: if the behaviour exists, write the
  green acceptance test rather than a `@Disabled` GAP test; reserve `@Disabled` for genuinely absent
  or partial behaviour.
- In this worker image the worktree `opencode.json` is the CI profile under `skip-worktree`. Confirm
  with `git ls-files -v` and `cmp` with `.github/opencode.ci.json`, temporarily restore
  `git show HEAD:opencode.json` bytes to run `check-pack.py`/`quick-check.sh`/`unittest`, then put the
  CI bytes back. Never commit or regenerate `opencode.json`.
- When asserting a database-derived actor, compare against the subject's `user_identity.id` UUID, not
  the `X-Synthetic-Subject` string; the V8 trigger resolves the subject to its identity id.
