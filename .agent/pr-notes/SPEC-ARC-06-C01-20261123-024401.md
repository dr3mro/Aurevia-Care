## Findings

- The clause is fully built and reachable; no `@Disabled` test or production file was needed. All five tests are active and green.
- Wire format discovered by the red runs: enum values serialize UPPERCASE (`QUARANTINED`, `CLEAN`), so state/verdict assertions use `equalsIgnoreCase`; Spring Boot 4.1.2 names 422 `UNPROCESSABLE_CONTENT`, not `UNPROCESSABLE_ENTITY`.
- `QuarantineService.complete` checks `NOT_CLEAN` before `OBJECT_UNVERIFIED`; the unverified-object assertion must therefore follow a clean scan, and the earlier version must be the current one.
- The brief's phrase "upload response carries no ... original name" is slightly imprecise: `Artifact` legitimately serializes `fileName` and `objectKey`. Privacy of the original name is asserted on the mediated download handle instead, which is what ARC-06 requires. No rule was weakened to accommodate this.
- `contracts/openapi.yaml` does not yet publish the twelve document-artifact routes; this is a pre-existing contract gap tracked separately (FIX-OPENAPI) and outside this task's scope. The clause doc cites the contract file and records the gap explicitly rather than claiming parity.
- Pre-existing, committed conflict markers in `apps/api/src/main/java/com/aurevia/smartclinic/exchange/hl7/{Hl7ParseException,Hl7Parser,Hl7Segment}.java` exist in HEAD; they are unrelated to this scope and were left untouched.
- Rejection paths deliberately append `access_denied` document events, so the test never asserts an empty ledger. The ledger assertion is only `events.size() > 0`; audit fact types/outcomes are not separately proved by this clause (Optional reviewer finding, accepted).
- Cloud-worker environment artifacts were confirmed once and not re-diagnosed: the CI `opencode.json` profile is installed under `skip-worktree` (`git ls-files -v opencode.json` → `S`), which makes `check-pack.py` and six `test_check_pack` tooling tests fail. ## Lessons for workers

- `worker-check.sh` runs the entire integration suite, so in a swarm worker it is safe only to run it once to capture the `check-pack.py` false positive; run the remaining stages individually and leave the full gate to the integrator. Never use `-Pno-security,fast -Dgroups=integration`: `fast` sets `excludedGroups=integration` and gives a vacuous green.
- A "no row was stored" assertion over a FORCE-RLS table is meaningless unless the verification connection sets `app.current_org` and a positive control shows the same query sees a committed row in that tenant and none in the peer tenant.
- When asserting state transitions through HTTP, derive `If-Match` from the actual version sequence; a guard that runs earlier (version or state) will mask the intended failure and produce a misleading code.
