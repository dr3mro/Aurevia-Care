# SPEC-CLN-05-C03 — Save signer, effective time, signed time, content checksum and template version

## Summary

Added an API-level acceptance test and clause evidence doc for PROJECT_V1_SPEC.md CLN-05
clause 3. The clause is already implemented; this story adds proof only. A clinician signs a
synthetic draft through `POST /api/v1/clinical-notes/{id}/sign` and the test asserts that the
signer, effective time, signed time, content checksum and template version are present on both
the returned revision and the real PostgreSQL `clinical_note_revision` row. Two negative tests
prove a role without sign permission and a stale version are refused with no sign metadata saved.

Only the two scoped files were added:

- `apps/api/src/test/java/com/aurevia/chart/clauses/SaveSignerEffectiveTimeSignedTimeContentTest.java`
- `docs/spec/clauses/chart/save-signer-effective-time-signed-time-content.md`

No production code, existing test, contract or migration was changed. No task-requests block is
needed.

CLN-05 (clause 3 only).

Routine (test and documentation proof of an already-implemented clinical rule). Clinical note

## Findings

- The chart domain (`com.aurevia.chart.record`) implements CLN-03 recording and
  verification but has no signing endpoint. CLN-05 signing is implemented in
  `com.aurevia.clinical.notes` backed by `db/migrations/V15__clinical_note_signing.sql`
  and the `POST /api/v1/clinical-notes/{id}/sign` route. The doc records this source-survey result.
- Pre-existing, out-of-scope: committed conflict markers in three `exchange/hl7` Javadoc comments,
  and the worktree `opencode.json` CI-profile mismatch (OPS-CW-003-01) that makes `check-pack.py`
  and 6 `test_check_pack.py` unit tests red in cloud workers. Neither was introduced or changed by
  this story; both are documented above with exact commands and paths.
- Coverage gates (`mvn verify`, full integration suite) were intentionally left to the integrator,
  per the swarm instruction, to avoid a 10+ minute timeout.

## Lessons for workers

- For a `clauses` test, copy the HTTP integration fixture from a neighbouring `*/clauses` test
  (dedicated DB, `DROP DATABASE ... WITH (FORCE)`, Flyway `filesystem:../../db/migrations`,
  `synthetic-auth`, `X-Synthetic-Subject` + `X-Active-Organization`) rather than the mocks-only
  chart/record unit test. Give each clause test its own database name so parallel classes do not
  collide.
- The sign endpoint returns `effective_at` as PostgreSQL timestamptz text; compare persisted
  instants with `getObject(..., OffsetDateTime.class).toInstant()`, not raw `getString`, and compare
  the signed revision's effective time to the draft's value rather than to the submitted ISO string.
- In cloud workers, `git ls-files -v opencode.json` returning `S` means a stale `check-pack.py` or
  `test_check_pack.py` failure is the documented CI-profile false positive, not a change defect;
  record it with evidence and do not edit the protected file.
