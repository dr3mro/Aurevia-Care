## Lessons for workers

- When a slice adds controller routes, publish them in `contracts/openapi.yaml` in the same change
  and regenerate the client; adding the routes to `missing-routes.txt` would hide rather than fix
  the gap (the baseline must only shrink).
- A GET that really returns a JSON array must use a named array schema whose name does not end in
  `Page` (for example `PendingStaffAttachments`); an inline array or a `*Page` name makes the
  pagination rules treat it as a paginated list and fail the exact-set assertions.
- Every new operation needs `operationId`, `summary`, `tags` and 401/403 responses; every POST needs
  the `IdempotencyKeyOptional` header component. Route-parity green is not enough: read the service
  for the real 409/422 statuses and the controller for the real response media type before declaring
  a contract entry truthful. A command's verdict vocabulary may differ from the stored state
  vocabulary.
- A route with a raw `@PathVariable String id` is not automatically "safe" just because valid ids
  are UUIDs: the service's key validator emits a real 422 for a malformed segment. Declare that
  422 on every id-taking operation and assert it in the same test that checks the 409s; otherwise
  the contract is truthful for happy-path clients only.
- In cloud workers, a `check-pack: opencode.json is stale` result usually means the CI profile is
  active under skip-worktree. Compare `git show HEAD:opencode.json` with the worktree file before
  treating it as a real failure; never edit that protected file to make the gate pass.
