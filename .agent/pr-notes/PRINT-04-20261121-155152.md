# PRINT-04 — Staff web: shared print preview dialog, print styles and A4 layout

## Summary

Added a standalone, reusable handout preview dialog and a browser-print stylesheet under
`apps/staff-web/src/features/print/`. The dialog renders the handout PDF in an embedded
frame, offers a handout language choice (English/Arabic) and a required reason choice
(give to patient / referral / patient request), and exposes Print, Download and Close.
It renders loading, error (with correlation id and working retry), forbidden and refused
states; refusals are shown as translated words, never as raw codes. Focus is moved into
the modal, contained on Tab/Shift+Tab, released on Escape and restored to the opener on
close. The print stylesheet sets A4 with 15 mm margins and hides application chrome for
the browser's own "print this page" path. The dialog is deliberately **not wired** into
any screen: route registration and per-kind Print buttons belong to PRINT-05..PRINT-08.

All files are synthetic-only; no API call, route, dependency, tracker or protected file
was changed. No real patient data, identifiers or credentials appear anywhere.

## Affected requirements

- **WEB-09** (resilient screens): all four required states plus the ready state are
  rendered by `PrintPreviewDialog`; error shows the correlation id and a working Retry;
  the reason validation keeps the selected language/reason; Escape, initial focus,
  Tab containment and focus restoration are implemented; all labels are bilingual.
- **CLN-07** (immutable localized PDFs, provenance): the dialog previews the server's
  handout by URL with a language choice and a title, and the print stylesheet preserves
  A4/15 mm paper geometry. PDF rendering, immutability and versioning remain the API's
  responsibility (PRINT-01), and the audit reason is passed to the owning screen, which
  records it through the API (PRINT-02).

## Risk class

Routine — a contained, unmounted UI primitive with no data, contract, permission or
migration change. It is intended to be reused by later print flows, so its state and
keyboard behaviour are fully covered here.

## Data changes

None. No migration, no schema, no backfill, no fixture with real data.

## Authorization boundaries and audit events

The component does not call the API and does not audit. `PrintReason` is passed to
`onPrint` so the owning screen can send it to the audited endpoint; no permission is
inferred from presentation, and a forbidden/refused result is rendered only when the
caller supplies that state.

## Migration and rollout considerations

None. The module is not reachable from `main.tsx`, so it adds nothing to the emitted
chunk budget (WEB-08); the generated client is untouched.

## Findings

- No reproducible defect was found in the touched code. All 49 new tests and the full
  staff-web gate are green.
- Print styles are rendered as a `<style>` element containing a TypeScript string rather
  than a `.css` import: there is no CSS pipeline in this module, coverage counts only
  `.ts/.tsx`, and a string constant is directly assertable. The rules use `@page` for
  paper geometry (A4, 15 mm) and `@media print` to hide `header`, `nav`,
  `[role="navigation"]`, `[data-app-chrome]` and `[data-print-controls]`, leaving
  `[data-print-handout]` visible.
- The dialog intentionally has no conflict or session-expired variant: those belong to
  the owning page/transport layer (WEB-09 `StateView`), and this component performs no
  versioned write and no network call. Adding them here would be unreachable code.
- Environment artifact only: `scripts/check.sh` red on the skip-worktree CI-profile
  `opencode.json` (see Test evidence). Do not regenerate it to "fix" this job.

## Lessons for workers

- A shared `Dialog` that traps Tab on a single close button is not reusable for a dialog
  with real controls; implement a live `querySelectorAll` cycle and assert it with
  `fireEvent.keyDown(document, {key:'Tab', shiftKey:true})` in jsdom.
- In jsdom, `document.body.focus()` does not move `document.activeElement`; render a real
  focusable button outside the dialog when testing the "focus was outside" path.
- `verbatimModuleSyntax` + `exactOptionalPropertyTypes`: keep optionality in the state
  union, use `import type`/`export type`, and never pass `undefined` explicitly to a
  `?:` prop that is not declared `| undefined`.
- Type-only `.ts` files can report oddly under V8 per-file coverage; co-locate exported
  types with a runtime module instead of adding a types-only file.
- Worker-environment `opencode.json` is under `skip-worktree`; a stale `check-pack`
  result there is a profile measurement artifact, not a reason to edit generated files.
