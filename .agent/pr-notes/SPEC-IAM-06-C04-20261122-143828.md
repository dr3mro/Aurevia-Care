## Summary

Proof-only API test and clause evidence for IAM-06 clause 4: platform support access
to clinical data is denied by default and is opened only by a separate, independently
approved and audited incident. Added one new HTTP-level test class (six active tests)
and one new clause evidence document. No production code, existing test, contract,
migration, script or tracker was changed.

Entry point to test trace: `POST /api/v1/access/support/check`,
`POST /api/v1/access/support/incidents` and
`POST /api/v1/access/support/incidents/{reference}/approve` in `AccessController`
→ real `SupportAccessService.checkAccess` / `createIncident` / `approveIncident`
→ real `AccessRules` validation → synthetic Mockito `AccessRepository` RLS boundary
→ assertions in `PlatformSupportAccessClinicalDataDisabledDefaultTest`.

## Lessons for workers

- For a proof-only IAM clause, the standalone MockMvc harness with the real controller
  and real domain services and a mocked RLS repository gives a genuine HTTP entry-point
  trace without needing PostgreSQL in the worker; assert the audit tuple and captured
  tenant context, not just the response status.
- In cloud workers, confirm `git ls-files -v opencode.json` shows `S` before treating
  any `check-pack.py` / `test_check_pack` failure as a real defect; never regenerate or
  commit that file.
- `git grep` for conflict markers can surface pre-existing committed Javadoc debris.
  Confirm it is inside comments and out of scope rather than treating it as an
  unresolved merge; report it instead of editing production code.
