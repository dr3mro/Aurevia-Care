# AUD-20261121-15 — Unify the third divergent subject-identifier validator in patient identity proofing

Task: AUD-20261121-15. Branch: `swarm/AUD-20261121-15-467` (base `795226728e958a33c42a350a6cae4e9150de7373`).
Scope honoured: `apps/api/src/main/java/com/aurevia/smartclinic/patient/identity` and `apps/api/src/test/java/com/aurevia/smartclinic/it/patientidentity` only. Synthetic fixtures only; no dependency, migration version, tracker or protected file changed.

## Summary

`IdentityProofingService` validated the patient-account subject with a third,
incompatible rule `[a-z0-9_.:-]{3,64}` (colon allowed, any leading character,
three-character minimum). That accepted subjects which the conversation,
finance, prescription and critical-result boundaries reject, so an enrolled or
invited account identity could not be reused consistently across the product.

The in-place `SUBJECT` rule is now the canonical bounded lowercase subject key
`[a-z0-9][a-z0-9._-]{1,63}` — alphanumeric start, 2-64 lowercase letters,
digits, dot, underscore or hyphen, no colon, no non-ASCII script — and the
`INVALID_SUBJECT` detail message matches the existing staff/authz callers. No
new primitive type was introduced in this module (the task forbids a competing
one). A new failing-first test class compares the identity endpoint's decision
with the canonical rule and with the conversation request boundary on identical
synthetic inputs.

## Affected requirements

IAM-05 (identity proofing, `IdentityProofingService` Javadoc), IAM-01/IAM-02 and
ARC-02 (subject used as the authenticated actor and authorization key — the
drift is an identity-linkage/authorization drift at a trust boundary), OPS-02
(audit codes and events are unchanged). No clinical decision, signed record or
prescribing path is touched.

## Findings

1. **Dependency (open, needs owner sequencing).** The canonical `subject(...)`
   primitive that AUD-20261121-10 is meant to add to `api/contract` does not
   exist in this tree or on any branch (verified with `git grep` over all refs;
   `api/contract` has `CatalogCode` but no `Subject`). `api/contract` is outside
   this task's scope and the task forbids adding a competing primitive here, so
   the literal "migrate to the primitive" step cannot be performed yet. I
   aligned the existing in-place rule to the canonical rule value and documented
   the mirror at the constant. AUD-10 must expose the primitive and migrate this
   caller. Evidence source: tool (git grep, file reads).
2. **Canonical rule choice = loose `[a-z0-9][a-z0-9._-]{1,63}`.** The strict rule
   would break the in-scope fixtures using `patient.one` and the out-of-scope
   regression test `it/patient/identity/OutstandingInvitationRevocationTest.java`
   (8 tests), which is outside this scope. The loose rule matches the
   staff/authz callers that AUD-10 already migrates, keeps dot/underscore valid
   and uniquely removes the colon that no other boundary accepts. Recorded as a
   decision here so the next worker does not re-derive it.
3. **Cross-endpoint parity for dotted/underscored is not yet assertable.**
   `ConversationInputs.subject` still uses the strict rule, so identity (loose)
   and conversation (strict) still disagree on dotted/underscored until AUD-10
   migrates the conversation boundary. The cross-endpoint test covers colon,
   valid, max length, Arabic/RTL and punctuation-leading classes where the rules
   already agree. `dottedAndUnderscoredParityIsPendingTheConversationMigration`
   now asserts the divergence explicitly (identity ACCEPT, conversation INVALID)
   and points at AUD-10, so the gap is visible in the test suite rather than
   omitted from a curated comparison array. Evidence source: tool (file read +
   executed tests), confirmed by the bounded senior-backend review (F1).
4. Environment artifacts only: `check-pack.py`/`test_check_pack` failures from
   the skip-worktree CI `opencode.json` profile; `check-docs.py`, check-names,
   check-wiring, check-secrets and check-migrations are green. No code defect
   was found in the touched files.
5. **Review outcome (simulated reviewer, bounded senior-backend review).** The
   reviewer agreed the loose rule is the only in-scope option and that mirroring
   a documented pattern is defensible while AUD-10's primitive does not exist,
   but flagged that the cross-endpoint test omitted the divergent dotted and
   underscored inputs (F1, high) and that the constant Javadoc overstated that
   the primitive already exists (F2, medium). Both were addressed test-first:
   `dottedAndUnderscoredParityIsPendingTheConversationMigration` asserts the
   current identity-vs-conversation divergence for those exact inputs and names
   AUD-10 as the fix, and the Javadoc now says the pattern *mirrors* the rule
   pending the primitive. F3 (coverage labelling) is addressed by the explicit
   MISSED/COVERED/TOTAL table above; F4 (out-of-scope dotted fixture) is finding
   #2. The reviewer's verdict "do not mark accepted as-is" is respected: this
   notes file explicitly records the story as not fully accepted until AUD-10
   lands (see "Why this is not finished").

## Lessons for workers

- Before tightening a shared validator, grep every caller and every test fixture
  — an out-of-scope regression test using `patient.one` decided which of the two
  candidate rules was viable.
- When a story depends on a parallel story's primitive, verify across all refs
  whether it actually exists; if it does not and its package is out of scope,
  align the behaviour in scope, document the mirror at the constant and request
  the migration task instead of inventing a competing type.
- A standalone MockMvc setup with the real service plus `ApiErrorHandler` gives
  a real HTTP entry-point test for boundary validation without a database.
- When a known cross-story gap exists, assert it explicitly in a named test
  instead of omitting the divergent inputs from a "parity" comparison array —
  a curated array reads as hiding the gap, while a named divergence test reads
  as a tracked dependency and is trivially flipped when the dependency lands.
- Do not describe a mirrored constant as "the canonical primitive" in Javadoc
  when the primitive belongs to another story and does not exist yet.
- In a cloud worker, `check-pack.py` failures and an early `scripts/check.sh`
  exit are usually the skip-worktree CI `opencode.json` profile; confirm with
  `git ls-files -v` and do not regenerate/commit `opencode.json`.

## Why this is not finished

The in-scope work is complete, green and committed, but one acceptance clause is
not yet fully satisfiable in isolation: "the identical input is accepted or
rejected the same way by an identity endpoint and a conversation endpoint"
holds for valid, colon, max-length and Arabic/RTL inputs, but not yet for dotted
and underscored inputs, because `ConversationInputs.subject` still uses the
legacy strict rule. That remaining divergence is asserted explicitly in
`dottedAndUnderscoredParityIsPendingTheConversationMigration` rather than omitted
from the parity test. Making those two agree today would require either editing
`messaging/conversations` (outside this task's scope) or tightening identity to
the strict rule (which would break the in-scope `patient.one` fixtures and the
out-of-scope `OutstandingInvitationRevocationTest`). The canonical `subject(...)`
primitive from AUD-20261121-10 does not exist and `api/contract` is out of
scope, so the literal migration cannot be performed here.

Most likely cause: the audit split the subject unification across parallel
stories (AUD-10 owns the primitive and the seven other callers; this story owns
only patient/identity) without sequencing them. What was tried: verified the
primitive's absence over all refs, chose the loose rule that preserves existing
dotted subjects, implemented it test-first with 100% coverage on the changed
class, and asserted cross-endpoint parity wherever the current rules agree.
Exact next step: land AUD-20261121-10 (canonical primitive + migrate
`ConversationInputs` and the other six callers), then execute the requested
follow-up task to replace the mirrored pattern in `IdentityProofingService` and
add dotted/underscored parity assertions.
