# LABFLOW-02 — API: reject a specimen with a reason, notify the clinician and create a linked recollection

## Summary

Added the `com.aurevia.labflow.rejection` slice: a bounded rejection-reason vocabulary, a rejection/recollection/history HTTP adapter and a transaction-oriented domain service. A rejection retains one of five bounded reason codes (free-text detail required and retained for `other`), records the ordering clinician as the notification target, notifies that clinician and — only when the site policy switch is enabled — the patient, all in one tenant-guarded transaction with the immutable history event and audit facts. Recollection mints a new specimen id linked through `replaces_accession_id` while reusing the rejected specimen's patient and `sourceOrderRef`, so both specimens stay on a single order and the rejected specimen's history is preserved.

No new table, migration, dependency or configuration file was added: the slice reuses the existing `lab_accession` / `lab_accession_event` forced-RLS schema, `LabAccessionRepository` and the domain types `LabAccession`, `AccessionState`, `LabInputs`, `LabActionPolicy`, `AuditAppender` and `TenantContext`, following the `labflow.collection` sibling pattern. All fixtures use synthetic identifiers.

Cross-boundary (new API routes reusing the lab accession persistence boundary). No schema, contract or deployment change.

## Data changes

None. No Flyway migration, backfill, lock or volume impact. Reuses `public.lab_accession` and `public.lab_accession_event` (V26 forced RLS) and `public.audit_event` (V3). Rollback is removal of the new package only; no data is orphaned because no new column or table exists.

## Authorization boundaries and audit events

- Authorization is re-derived inside the transaction from `TenantContext.subject()` via `LabAccessionRepository.hasActiveMembership` / `activeRoles` and `LabActionPolicy`; `SPECIMEN_REJECT` and `SPECIMEN_RECOLLECT` are verifier duties, `ACCESSION_READ` for history. Organization and actor are never read from the request body.
- Audit purpose `LAB_SPECIMEN_REJECTION`: `LAB_SPECIMEN_REJECT` / `LAB_SPECIMEN_RECOLLECT` / `LAB_ACCESSION_READ` with outcomes SUCCESS, DENIED, NOT_FOUND, CONFLICT, plus `LAB_SPECIMEN_REJECTION_NOTIFY` (resource type NOTIFICATION) with resource ids `clinician:<target>` and, under policy, `patient:<patientId>`. Audited denials are committed before the deferred exception, preserving the collection slice's audit-before-throw invariant.
- Tenant isolation: all reads/writes run under forced RLS; cross-tenant reject and history return 404 (proved end to end).

## Migration and rollout considerations

None. Patient notification is default-off via `aurevia.lab.rejection.notify-patient` (Spring `@Value` default `false`); a site must opt in explicitly. No secret, patient data or real domain name is present in code or fixtures.

## Clinical and architecture review

Simulated laboratory-user scenario exercised through the HTTP integration test: reject a haemolysed / other-with-text specimen, observe the retained reason and clinician notification in history and audit, then recollect and confirm one order with a linked new id. ## Findings

A bounded simulated `aurevia-senior-backend` review (file reads only) returned six findings. Dispositions:

1. **HIGH (open, out of scope) — OpenAPI contract and regenerated client omit the three new endpoints.** Verified by tool: `contracts/openapi.yaml` has no `/api/v1/lab/specimens/{id}/reject|recollect|history` path, `contracts/openapi/generated/manifest.json` lists only `accessionRequisition` and `collectSpecimen`, and the generated `openapi.yaml`/`client.ts` contain only the `collect` path. These files are outside this story's two-path scope, so they were not edited. Requested as a follow-up task below. The integration test exercises the endpoints over HTTP, so the runtime is proven; only the published contract lags.
2. **HIGH (open, out of scope) — notification target is client-supplied and no message is dispatched.** Verified by tool: `LabAccession` exposes only a bounded `sourceOrderRef` and no clinician field; there is no order aggregate or messaging port available inside this scope. This slice therefore records an auditable notification fact and retains the supplied target — it does not claim delivery. Deriving an authoritative clinician and dispatching real notifications (with per-patient consent rather than only a site flag) needs a separate, owner-scoped task, requested below. The existing legacy `LabAccessionService.reject` uses the same retained-target representation, so this slice is consistent with the codebase; the safety gap is real and should not be treated as resolved.
3. **MEDIUM (fixed) — audit insert in the `DuplicateKeyException` catch cannot commit on PostgreSQL.** A 23505 aborts the transaction, so the subsequent `audit.append` would fail rather than yield the intended 409. Removed the audit append from the catch; the ordinary duplicate case is still audited by the pre-check, and the race now returns a clean 409. `recollectRefusesAConcurrentDuplicateInsert` now asserts no CONFLICT audit is attempted on that path.
4. **LOW (fixed) — three reason codes unexercised.** Added `allFiveBoundedReasonCodesAreAccepted`, which parses all five wire values and asserts `requiresDetail()` for each.
5. **LOW (open, out of scope) — duplicated `authorize`/`staleVersion` logic between `labflow.collection` and `labflow.rejection`.** Extracting a shared helper requires editing the sibling collection package (outside scope). Requested as a follow-up task below.
6. **LOW (fixed) — `recollect` used `state() != REJECTED` instead of the shared state machine.** Now uses `canTransitionTo(AccessionState.RECOLLECTED)`, consistent with `reject` and the DB guard trigger.

Other reviewer checks were clean: no uncovered branch, audit-before-deferred-throw maintained on all committed paths, tenant isolation proved, thin injected controller, no new table/migration, no requirement-ID names, no `@SuppressFBWarnings`, no unqualified Javadoc links, no throwing constructor, no exposed mutable lists.

## Lessons for workers

- When a new labflow slice needs domain primitives, reuse `lab.accession` (`LabAccession`, `LabAccessionRepository`, `AccessionState`, `LabInputs`, `LabActionPolicy`) and mirror `labflow.collection`'s thin-controller/injected-service pattern instead of copying the legacy `LabAccessionService` transition code.
- For an audited refusal, append the audit row and defer the exception (`AtomicReference` + return `null` from the transaction callback); throwing inside the callback rolls back the audit.
- With Mockito, a broad `findById(anyString())` stub overrides a specific-id stub; use a single `thenAnswer` that branches on the id when a test needs two different rows (e.g. rejected specimen and its random-UUID recollection).
- A `@Value` policy switch (default off) keeps "where policy allows" testable without editing protected configuration files: construct the policy with `true`/`false` in unit tests and override the property on the `@SpringBootTest` for end-to-end proof.
