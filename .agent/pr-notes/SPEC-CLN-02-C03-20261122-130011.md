# SPEC-CLN-02-C03 — Transfer handoff requires an active assignee

## Summary

Added a focused CLN-02 clause-3 API test and its evidence document. The clause is
already implemented in `CheckInService.handoff`; this test-only story proves the
rule from the normal service entry point without changing production code. One
positive test shows a valid transfer, and three negative tests show refusals for
no assignee, a deactivated source assignee and an inactive receiving member,
each asserting that neither the worklist item nor the append-only handoff ledger
is written. No `@Disabled`, no test skipped, no threshold or exclusion changed.

## Lessons for workers

- In a `clauses` test package, the established pattern is mocked repositories
  plus a mocked `TransactionTemplate` that executes the real guarded callback;
  this proves the rule from a normal service entry point without a database and
  keeps the PR fast and green (`authz/clauses/FacilityScopeEnforcementTest`).
- Before writing a clause document's `## Status`, read the current production
  implementation; earlier clause docs under `docs/spec/clauses/` may describe a
  gap that has since been closed.
- `scripts/check.sh` delegates `apps/api/check.sh` to `mvn verify` and
  `scripts/worker-check.sh` runs every integration test; when the story forbids
  the full gate, run the individual stages and say which were run and why the
  composite gate was left to the integrator.
- Do not re-diagnose the `opencode.json` skip-worktree artifact: one
  `git ls-files -v` / `git show HEAD:` confirmation is enough; record the
  failing command and its final line and continue with the remaining gates.
