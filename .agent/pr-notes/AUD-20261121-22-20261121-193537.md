# AUD-20261121-22 — Remove the stale story-ID package reference in radiology Interpretation

## Summary

Replaced the stale two-line comment above `Interpretation.checksum()` in
`apps/api/src/main/java/com/aurevia/smartclinic/radiology/Interpretation.java`.
The old comment named the removed story-ID package `g1.s_g1_05` as the owner of the
SHA-256 utility. The new comment names the real domain owner the code actually calls:
`NoteChecksum.sha256` from `clinical.notes`. This is a comment-only change; no
executable line, branch, method or class was added, removed or altered.

Before:
```java
// Intentional reuse of the g1.s_g1_05 SHA-256 utility: keep one digest rule
// rather than adding a fourth local copy; no clinical rule crosses packages.
```
After:
```java
// Reuse NoteChecksum.sha256 from the clinical.notes domain rather than
// adding a fourth local copy; no clinical rule crosses packages.
```

## Findings

- Confirmed by tool evidence: the stale reference occurred exactly once, at
  `Interpretation.java:89`, and nowhere else in the radiology package. The code at
  line 91 already called `NoteChecksum.sha256(...)` imported from
  `com.aurevia.smartclinic.clinical.notes`, so the new comment names a real, existing
  owner. `scripts/check-names.py` misses this class of defect because it only inspects
  paths and `package` declarations, not comment bodies.
- No other stale story-ID package reference was found in the declared scope.
- No behavior, signature or coverage change; no defect in production logic observed.
- Simulated specialist review (`smartclinic-senior-backend`, read-only, no files
  edited): no actionable findings. It confirmed the comment names a real owner —
  `com.aurevia.smartclinic.clinical.notes.NoteChecksum.sha256(String)` exists, is
  imported at `Interpretation.java:6` and is the exact method invoked at line 91 — and
  that no additional test is warranted for a comment-only change (a test that only
  touches a comment would breach the "no test that exists to touch a line" rule).

## Lessons for workers

- A `grep -rnE '<story-id-pattern>' <scope>` over comment bodies is the red/green
  assertion for stale-ID documentation fixes; `scripts/check-names.py` cannot catch an
  ID used as a pseudo-package inside a comment, so run the grep explicitly and record
  both sides in notes.
- When a comment names an owner, verify the owner exists and is imported at the call
  site before editing, then name it exactly (`NoteChecksum.sha256` in `clinical.notes`)
  so the trace resolves without Javadoc or a link directive.
- For comment-only Java changes, a focused `-Dtest=<Class>` run plus `jacoco:report`
  measures the touched class at 100% without the prohibited full verify; state
  explicitly that no new branch exists.
