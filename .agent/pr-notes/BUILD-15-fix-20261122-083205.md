## Lessons for workers

- When a story is re-dispatched many times, one clean verification pass is enough — spend the pass obtaining the *automation* evidence (labels, exact gate conditions) rather than another identical re-verification. Here that evidence again shows a stale `needs-fix` label, not a failing check.
- Trace who is supposed to remove a blocking label. If the success path that would clear it is gated behind the label itself (`plan_integration` gated behind `needs-fix`), it is a deadlock only a trusted integrator/owner can break.
- Recommitting the same notes cannot change a label and re-triggers the same wave. State the single exact trusted next step and stop; do not invent a code change to look productive.
- In cloud workers `opencode.json` is skip-worktree (`S`) with the CI profile. A `test_check_pack`/`gen-opencode.py --check` red is a measurement artifact — confirm with `git show HEAD:opencode.json` versus `gen.render(ROOT)` before treating it as yours.
- Do not run `scripts/check.sh`, `scripts/coverage-check.sh` (full `mvn verify`), `apps/api/check.sh` or `scripts/docs.sh` as a worker; the full PostgreSQL/static-analysis/documentation gate is reserved for the integrator/Delivery.
