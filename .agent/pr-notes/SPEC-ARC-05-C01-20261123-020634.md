## Findings

- The advisor brief said invalid input returns 400. Verified by tool: `DeliveryInputs` raises
  `ApiException(422, ...)` and `ApiErrorHandler` renders it verbatim; the response was
  `422 UNPROCESSABLE_CONTENT` (Spring 6+ renamed `UNPROCESSABLE_ENTITY`, same code). The test asserts
  422 and the stable codes `INVALID_IDEMPOTENCYKEY` / `INVALID_DIGEST`, matching the contract README
  and the specification.
- The advisor brief suggested `@Disabled` if rollback could not be proven. Verified by tool:
  `scripts/check-constraints.py:56` rejects an added `@Disabled`/`@Ignore` in Java, so that fallback
  would fail the gate. A deterministic test-only trigger made the rollback proof active instead;
  all six tests are active.
- Pre-existing, out of scope: committed `main` contains conflict markers inside Javadoc in
  `apps/api/src/main/java/com/aurevia/smartclinic/exchange/hl7/{Hl7ParseException,Hl7Parser,Hl7Segment}.java`
  (present in both `HEAD` and `origin/main`). They are comments, do not break compilation, and were
  not touched by this test-only story.
- Pre-existing, out of scope: the delivery routes are listed in
  `contracts/openapi/missing-routes.txt:31-32,178-187`; no OpenAPI or generated client change was made.
- Optional (devsecops): the fixture creates the cluster-wide `smartclinic_migrate` / `smartclinic_app`
  LOGIN roles with empty passwords and leaves them in place, matching the neighbouring
  `JdbcDeliveryStoreIntegrationTest`. Blast radius is an ephemeral CI PostgreSQL cluster; if this
  fixture is ever pointed at a shared instance those roles should be owned and cleaned up there.
- Evidence provenance: all commands above were executed locally (tool evidence). Specialist verdicts
  below are simulated/static reviews. No human, clinical or real-patient evidence is claimed.

## Lessons for workers

- Confirm the actual HTTP status and `HttpStatus` constant by running the test: Spring 6+ uses
  `UNPROCESSABLE_CONTENT` for 422, not `UNPROCESSABLE_ENTITY`.
- `check-constraints.py` rejects an added `@Disabled` even when an advisor brief suggests one for an
  unprovable clause; a deterministic test-only DB trigger can make an all-or-nothing rollback proof
  active and green without touching production code or a migration.
- In a cloud worker, `git ls-files -v opencode.json` → `S` plus a worktree file matching
  `.github/opencode.ci.json` byte-for-byte confirms the stale-pack message is environmental; run the
  remaining quick-check stages individually and never regenerate that protected file.
