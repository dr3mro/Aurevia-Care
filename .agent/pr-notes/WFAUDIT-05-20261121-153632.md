# WFAUDIT-05 — Reject an unknown or missing worker in the agent inventory

## Summary

`scripts/check-pack.py` now fails closed on agent-inventory drift instead of
silently collapsing or ignoring it. Six fail-closed cases were added, each
reporting the offending file path: (1) an agent file absent from `opencode.json`,
(2) a configured agent with no file, (3) a skill referenced by an agent but
missing on disk, (4) a skill directory with no `SKILL.md`, (5) a duplicate agent
name (duplicate `orevia-*` key in `opencode.json`, detected before
`json.loads` collapses it), and (6) a worker role named in `docs/WORKFLOW.md` or
the orchestrator prompt with no corresponding agent file. The previous single
`set(agents) != set(definitions)` diagnostic was split into the two precise
cases so each names the file. The real repository still passes with zero errors.
All additions are covered by new tests; every existing test is kept.

## Findings

- The on-disk `docs/WORKFLOW.md` (21 lines) names only the `QA` worker role
  explicitly; the longer workflow narrative injected in the orchestrator
  context names twelve roles. `ROLE_AGENTS` maps all twelve to real agent files,
  so the check passes against either text. Limitation: a brand-new role name
  added to the docs but absent from `ROLE_AGENTS` is not detected — the mapping
  is the deterministic bridge between prose role names and kebab-case agent
  files, and must be extended when a new role is documented. No defect found.
- No production defect was observed; this is a hardening check. No BUGS.md entry
  is required.

## Lessons for workers

- `scripts/check-pack.py` can be exercised in isolation by materializing the
  committed `opencode.json` profile (`git show HEAD:opencode.json > opencode.json`)
  because the worktree copy is a skip-worktree CI profile (OPS-CW-003-01);
  restore it afterwards and never commit it.
- When adding a fail-closed check, add its RED test first against the old
  script, and keep one assertion per drift case naming the offending path.
- `coverage.py` is unavailable; stdlib `python3 -m trace --count --missing`
  gives line coverage. Its final temp-file cleanup can raise after writing the
  `.cover` files — read the cover file, not the runner's exit code.
