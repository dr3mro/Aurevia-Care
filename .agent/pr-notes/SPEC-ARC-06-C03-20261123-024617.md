# SPEC-ARC-06-C03 — authorize upload completion and each mediated download

## Summary

Adds a synthetic, database-free API clause test for ARC-06 clause 3 and a new
clause evidence document. The test proves that upload completion and every
download are authorized by current role and bound tenant, that denials fail
closed with non-sensitive ledger facts and no state change, and that a clinical
download returns only a five-field mediated handle with no payload, original
file name or URL. No production code, existing test, contract, migration or
dependency was changed.

## Affected requirements

ARC-06 (primary). Supporting boundaries exercised: ARC-02 (tenant-scoped reads
and fail-closed context), ARC-03 (`If-Match` preconditions and machine-readable
statuses), IAM-01 (role/action policy from fresh active membership), OPS-02
(`UPLOAD_COMPLETED`, `DOWNLOADED` and `ACCESS_DENIED` audit facts).

## Risk class

Routine — one new synthetic JUnit class and one new clause document; no

asserted, not modified.

## Authorization boundaries and audit events

Tenant and subject are derived from `TenantContext`; roles come from
`StaffRepository.activeRoles` inside the tenant-guarded transaction and never
from a request body. `document_reviewer` may complete and download;
`pdf_renderer` may do neither; a patient-role principal is refused by the
controller before the service. An ORG_B actor on an ORG_A artifact gets 404 with
no fact and no ORG_A store lookup. Asserted facts: `UPLOAD_COMPLETED` and
`DOWNLOADED` on success with `detail` limited to a benign note or null, and
`ACCESS_DENIED` with the stable code as detail on every denial/conflict. No new
audit event type was introduced.

## Lessons for workers

- A final Spring service cannot be mocked here; construct the real service over
  mocked boundaries rather than adding a suppression or changing production code.
- When a clause test asserts implemented behaviour, demonstrate non-vacuity by
  temporarily inverting one assertion, recording the failure, and restoring it.
- In a cloud worker the `skip-worktree` `opencode.json` profile makes
  `check-pack.py`, `worker-check.sh`, six `test_check_pack` cases and
  `python-coverage.sh` red; confirm `git ls-files -v opencode.json` → `S` once,
  run the remaining stages individually, and never regenerate that file.
- `guard.deny`/`conflict`/`stale` append an `ACCESS_DENIED` fact, but 401
  (no context), 404 (concealment), 428 (missing precondition) and the
  controller's patient-role 403 append none: assert zero facts only for those.
