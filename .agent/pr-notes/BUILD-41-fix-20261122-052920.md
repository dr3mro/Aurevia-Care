# BUILD-41 (fix pass) — remove the orphaned export manifest on a refused job insert

## Summary

Fix pass for BUILD-41 / OPS-07 on `swarm/BUILD-41-495`, continuing from the earlier
findings instead of restarting them. The in-scope tenant-export implementation was
already complete, tested first and 100% covered. A prior pass had fixed one leak in
`start()` (unreferenced per-document copies). This pass closes a second, independent
leak on the **failure path**: `start()` promotes the manifest object before the job
row is inserted; when `store.save(job)` returned false the method threw without
removing that object, leaving bytes (provenance + audit history) that no job row
referenced and that no `expire(jobId)` call could ever reach.

A failing regression test was written first (RED: expected 1 stored object but found
2), then `TenantExportService.start()` was changed to delete the just-promoted
manifest in the `!store.save(job)` branch before throwing. No production branch was
added; the new production line is covered by the new test. No migration, contract,
threshold, exclusion or protected file was changed by this pass.

Evidence provenance: **tool** commands run by this worker; plus two **simulated
reviewer** reports (senior-backend and QA, read-only briefs). No human, clinical or
patient-participant evidence. No PHI or credential appears in any note or test.

## Findings

- **Fixed this pass (orphan on refused insert):** `start()` promoted the manifest
  before inserting the job row; a `store.save` result of false threw while leaving
  the promoted object with no owner and no expiry path. Fixed with a compensating
  `objects.delete(manifestKey)` and a regression test that counts stored objects.
- **BUILD-41-QA-1 (simulated QA, not fixed — low severity, failure path):**
  `TenantExportService.expire()` (`TenantExportService.java:159-165`) removes the
  object before `store.markExpired(jobId)`. If `markExpired` returns false the
  method throws 409 with the object already gone, the row still `COMPLETE` and no
  `EXPORT_EXPIRE` audit; a retry then fails at `objects.expire` with
  `EXPORT_OBJECT_MISSING`, so that job can never reach `EXPIRED` or be audited as
  expired. `TenantExportServiceTest.expireRefusesWhenTheJobWasNotMarked` asserts
  only the 409, not the leftover state. Reachability requires a concurrent state
  change or DB failure (the real `JdbcExportStore.markExpired` returns 0 only when
  the row is no longer `COMPLETE`), so this is a low-impact edge. A bounded fix must
  keep the object and row consistent on both failure orders and add a test that
  asserts final job status/audit in the failure path; a naive reorder trades this
  divergence for the opposite one (row EXPIRED, object retained). Left for a
  dedicated follow-up rather than risking a 100%-covered, heavily churned branch.
- **Test-hardening gaps (simulated QA, not product bugs):** `ExportModelTest` does
  not assert `record_count` for a two-record manifest (G1), does not distinguish the
  artifact-level `schema_version` from the manifest-level field (G2), and does not
  assert an `ExportedDocument` `id` (G3). Production writes all three; only the
  assertions are weak.
- **Contract debt (tool + simulated QA, out of scope):** the three export routes are
  baselined in `contracts/openapi/missing-routes.txt`, not published in
  `contracts/openapi.yaml` or the generated staff-web client. Route parity is green;
  generated clients still cannot call them. Publishing is outside BUILD-41's
  declared scope and was requested in earlier passes' notes. The baseline file
  itself is also outside the declared scope and is flagged by `worker_gate` when
  `STORY_BODY` supplies it — an owner reconciliation, not a worker edit.
- **No automatic expiry (simulated QA):** nothing schedules
  `TenantExportService.expire`; after `expiresAt`, `download` is refused (410) but
  the object remains until the explicit expire endpoint is called. Retention
  automation belongs in the retention/offboarding slice (BUILD-42), not here.
- **Full-stack HTTP integration gap (simulated QA):** `ExportControllerTest` drives
  the controller with a mocked service; `TenantExportIntegrationTest` drives the
  store against real PostgreSQL. No single test drives HTTP → real controller →
  real service → `JdbcExportStore` → PostgreSQL. Requested as a follow-up in
  earlier passes' notes.
- **Environment only (verified by tool, pre-existing on main):** the six

## Lessons for workers

- A side effect that writes an object before a durable row exists needs compensation
  on every failure path, not just the happy path; count stored objects after both a
  refused insert and a successful expiry.
- An independent reviewer (senior-backend) found a second leak that all earlier
  verification passes missed because every export test only checked the happy path
  or the expired path. Review failure branches, not just acceptance headlines.
- Write the regression test first and capture the exact RED assertion before adding
  the compensating statement; a compensating statement inside an existing branch
  adds no new JaCoCo branch but still needs an outcome assertion.
- A failing test that passes once a build artifact exists is not hermetic: run the
  script suite with and without `apps/api/target/surefire-reports` to tell a real
  defect from an order-dependent fixture.
- In this cloud worker `opencode.json` is a CI profile under `skip-worktree`;
  compare with `.github/opencode.ci.json` and `git show HEAD:opencode.json` before
  believing a check-pack failure. Never regenerate or commit that file.
