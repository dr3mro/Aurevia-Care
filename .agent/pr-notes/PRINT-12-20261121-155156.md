# PRINT-12 — Printing guide, permission matrix and clinician acceptance scenario

## Summary

Documentation-only story. Added `docs/operations/printing/` with three files:

- `README.md` — what can be printed (five handout kinds), from where (staff-web
  Print buttons and the shared preview dialog), who may print, refusal rules
  (drafts, withheld results, wrong scope/tenant, ambiguous channel, stale
  version), reprints and versions, output/layout, and the sanitized audit entry.
- `permissions.md` — a role-against-kind permission matrix using the
  specification's defined roles, with seven permission rules (default deny,
  server-side re-derivation, source-state gate, tenant/facility scope, reason
  is not a permission, reprints are prints, prescription channel matters).
- `uat.md` — a plain-step synthetic clinician scenario (18 steps), pass criteria
  and evidence-to-capture guidance, explicitly labelled simulated, not a real
  pilot.

No code, schema, API contract, CI, tracker or script file was changed. No folder
or file was named after a task, story, gate or requirement ID — the new folder
is the business domain `printing`.
