## Lessons for workers

- A clause-proof test in a `*.clauses` package cannot call a package-private constructor from the neighbouring production package; use the public constructor plus `ReflectionTestUtils.setField` for a fixed clock, or keep a documented real-clock bounded assertion. Check constructor visibility before writing the fixture.
- Name each negative after the exact guard it drives. A "another tenant" refusal isolates the connection check only when the second tenant's subject is seeded with a valid role and unit assignment; the missing unit assignment needs its own test.
- For a test-only story there is no red phase: the proof passes against existing production code. Record that explicitly instead of inventing a failing test or editing production code.
- In a cloud worker, `git ls-files -v opencode.json` showing `S` explains every `test_check_pack` and `check-pack` failure; confirm once, then run the remaining gate stages individually. Never regenerate or commit that protected file.
