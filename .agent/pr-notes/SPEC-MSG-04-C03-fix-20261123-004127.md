## Lessons for workers

- A fix pass must create its notes at the exact path in the prompt: `check-verdicts.py` fails closed with
  "cannot read the notes file" when that file is absent, regardless of an earlier worker's notes file.
- When the integrator's finding is only "did not finish cleanly" with no detail, re-run the actual
  checks rather than guessing at a code defect; a missing/ truncated hand-off artifact can be the whole cause.
- For a closed-vocabulary clause proof, assert the literal wire keys, not only `Kind.from(k.wire())`
  round-trips — a rename can preserve round-tripping. Naming each enum constant also makes deletion a
  compile error, the strongest removal signal available in a test-only change.
- With "Examples include" wording and an extra `Kind.GENERAL`, do not describe the vocabulary as having
  exactly the named members; say the examples are members of a bounded, typed enum.
- Never combine `-Dtest=SomeClass` with `verify`: the JaCoCo BUNDLE 100% rule fails a partial run.
- The skip-worktree `opencode.json` CI profile is a known cloud-worker artifact. Confirm once with
  `git ls-files -v` / `git show HEAD:…`, record the failing command and final line, run the other gate
  stages individually, and never regenerate or commit that file.
- Keep a clause proof inside the clause: no template, approval, context, clinical-authorization or
  other-clause assertions, even when the surrounding service makes them easy to add.
