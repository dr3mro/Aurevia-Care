## Lessons for workers

- A fix pass on a complete documentation deliverable should first read the notes file on disk: a truncated PR-description snapshot captured by the integrator is not proof of unfinished work. Re-verify with executed commands and record that honestly instead of inventing a change.
- Before calling any merged test gate evidence, verify the cited method names with `grep` and the merge commit with `git log --oneline -1 -- <file>`, and confirm the controller route annotations. Names and packages drift in refactors (for example `09cdc1fd` renamed story-id packages to business domains); a plausible-looking citation that no longer resolves is worse than no citation.
- A targeted `mvn -Dtest=…` still compiles the whole test tree. An unrelated broken test source on `main` can block every targeted run; record the exact command and final error line, do not fix files outside `scope`, and fall back to merge-commit evidence with an explicit caveat.
- Do not claim a gate criterion proven from a design document, an open task title or a service-level test with an in-memory store alone. Name the HTTP and durable-store tests that prove the same behaviour and state explicitly what is not proved (physical delivery, on-device verification, referral-status entity).
- When a later change widens a shared record, grep all call sites in tests before merging. A constructor-parameter change one slot before a new test was added left `main`'s test tree uncompilable.
