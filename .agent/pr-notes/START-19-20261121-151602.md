## Findings

- The command authorization gate, catalog, generator and `contract` primitives (except `ApiException`, `IfMatch`, `SqlFailureTranslator`) have no production caller outside this package and its tests; the generated-artifact drift gate does not prove live controller wiring. Recorded under `## Things to know` with the citation to `contracts/openapi/README.md`.
- Only `ApiException` (113 call sites), `IfMatch` (21) and `SqlFailureTranslator` (3) are consumed outside the package; `ApiErrorHandler` is wired by Spring component scan. Counts were obtained with `grep` over `apps/api/src/main/java` and are cited in the guide.
- Two error-code families coexist (`ApiErrorCode` vs. module-owned codes such as `PRECONDITION_REQUIRED`), and both in-memory ledgers are synthetic/non-durable; documented as known weaknesses.
- WEB-04 is only partly satisfied by this package (error shape and bounded inputs); rate limiting, CORS allowlist and size/time caps are not implemented here — documented honestly rather than overclaimed.
- Bounded read-only senior-backend fact-check (evidence source: reviewer, tool-verified citations) found three factual errors in the first draft, all corrected before the final commit: (1) the `audit_event` table is created in `V1__tenant_schema.sql`, while V3 adds the hash functions/triggers — the guide now cites both; (2) `ApiErrorCode` has no digest constant — "digest" was removed from its code-family list and the 500 `INTERNAL_ERROR` correctly attributed to `RequestDigest`; (3) generated client functions are `fn(ctx, [path parameters,] idempotencyKey, ifMatch, body, transport)` — path parameters are inserted after `ctx` (e.g. `deactivateStaff`, `approveConfiguration`). Reviewer confirmed all test counts (5/3/3/18/9/20/11), 24 commands, statuses/codes, no-controller/no-listener claim, wiring limits and artifact facts as accurate.

## Lessons for workers

- For a documentation-only story, `python3 -I scripts/check-docs.py` is the authoritative local gate: it fails broken relative links and undefined requirement IDs in the new page. Compute links from the new file's directory (here `../../../` reaches the repo root) and verify every requirement ID against PROJECT_V1_SPEC.md before writing; note that UX-01 is not a defined table-row/bold-lead ID and must not be used in Markdown.
