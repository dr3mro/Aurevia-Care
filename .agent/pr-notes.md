## Defects found

- **Blocked, not fixed (Java main, requires out-of-scope test change).** `PatientAppointmentService.java:93–99` (`confirm`): `store.confirm(...)` succeeds, a generic push is dispatched and `PATIENT_APPOINTMENT_CONFIRM/SUCCESS` is audited, then the post-commit `store.find(...)` at line 98 can return empty and the method throws `404 NOT_FOUND`. The caller then receives a 404 for a confirmation that was committed and notified — a misleading outcome and audit/response inconsistency (medium). Correct fix: build the response from `current.confirmed(at, expectedVersion + 1)` and drop the re-read. **This cannot be applied in this worker's scope:** the out-of-scope test `confirmConcealsAnAppointmentThatDisappearsBeforeTheResponse` (`apps/api/src/test/.../PatientAppointmentServiceTest.java:190–198`) explicitly asserts that 404, so changing the behaviour would break the fast tier. Owner decision / Java-test-scoped follow-up required. Confirmed by the bounded senior-backend reviewer (simulated).
- **Reviewer observations, not defects (Java main):** the 404/concealment paths do not emit an audit `DENIED` event (OPS-02 does not require it and no test asserts it); audit keys embed workflow status (`PUSH_NOTIFY_<STATUS>_SENT`), which is state, not clinical PHI, and the push template itself is fixed and clean.
- **Reviewer observations, not defects (mobile):** unused `Clock` interface (app-wiring); `InvalidTokenEvent` has no in-path sink (delivery is app-wiring); `deriveConfirmation` drops a stale `confirmedAt` when a visit becomes unavailable (UX choice); callbacks pass local ids (parent owns tenant scoping). None is a PAT-01 safety/isolation breach.
- No reproducible in-scope production or test defect was found by either bounded reviewer. All identifiers in code/tests are synthetic (`patient-1`, `patient-2`, `org-a`, `dev-1`, `synthetic-token`); no patient data, credentials or raw logs appear.
