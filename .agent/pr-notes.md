## Defects found and fixed (in scope, red-first)

1. **Wrong-actor acknowledgment on a shared chart (MSG-05/IAM-05).** `InMemoryInstructionFactStore.putAcknowledgmentIfAbsent` deduped by `(org, instruction, revision)` only, so a second verified account linked to the same chart received the first account's `Acknowledgment` (wrong `actor`), and per-account receipt was impossible. Fixed by keying receipts per `(org, instruction, revision, actor)` like first views, keeping a per-revision `acknowledgments(...)` list for overdue detection, and making `committedAcknowledgment` replay filter by the authenticated subject. Regression: `acknowledgmentIsAttributedToTheAuthenticatedAccountOnASharedChart`, plus updated `firstViewAndAcknowledgmentAreUniquePerViewerAndRevision`.
2. **Mobile auth gate accepted an empty credential (MSG-05/PAT-02).** `client.ts::requireAuth` rejected only `null`, so an empty OS-backed token exposed full instruction content. Fixed to reject `null` **or** `''`; added `fails closed on an empty credential, not just a missing one` asserting all five protected boundaries reject.
3. **CODING_STYLE cleanups:** merged two identical `InstructionFactActions.allows` switch branches; removed duplicate `EMPTY_SCREEN_FACTS` in favour of the exported `EMPTY_FACTS`; removed the unused `newId` fixture field; corrected the tenant-admin Javadoc to state that action permission and unit assignment are separate (IAM-01) and added `tenantAdminNeedsUnitAssignmentForOwningUnitActions` documenting it. Also added mobile negative coverage for cross-tenant/other-chart writes, unit lookup and acknowledged-excluded-from-overdue.

No other reproducible in-scope defect was found. No PHI, real identifier or credential appears in code, fixtures or these notes.
