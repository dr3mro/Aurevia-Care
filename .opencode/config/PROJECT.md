# Aurevia delivery record

The authoritative product requirements are in PROJECT_V1_SPEC.md. Repository discovery and the G0 platform baseline are implemented and evidenced in `tasks/` and `docs/gates/`; later gates and real-patient launch approvals remain open. Gate notes record evidence, not human acceptance.

| Decision | Baseline |
|---|---|
| Platform | Modular Java/Spring backend, PostgreSQL, staff React web and patient React Native/Expo |
| Delivery | WIP one, G0 through G5, targeted verification before broader gates |
| V1 workflow | Clinic, lab and patient access pilot first. Radiology, PT and pharmacy enable per site. |
| Patient communication | MSG-01 through MSG-07 and ARC-07. Verified care unit connections, scoped threads, secure files and versioned instructions. |
| Real-patient prerequisites | Market approval, policy pack, partner contracts and site-specific operational and clinical evidence |

| 2026-11-18 | ARC-03, OPS | Deferred from S-G0-01: idempotency keys, managed OIDC/MFA/CSRF, staff lifecycle history (S-G0-02), search/files/workers/export isolation and concurrent stress. Synthetic `X-Synthetic-Subject` is gated on the `synthetic-auth` profile and is not an authentication mechanism. |
| 2026-11-19 | Build, OPS-06 | One supported baseline: **Java 21** bytecode (`maven.compiler.release=21`), built on CI JDK 21 (`.github/actions/java-verify`). The local JDK 27 is tolerated only because `--release 21` is used; the Mockito **subclass** maker is required for those local runs because the inline maker cannot instrument JDK 27 classes, and is harmless on JDK 21 — it is a JDK 27 workaround, not a baseline requirement. Spring Boot 4.2.0, PostgreSQL driver 42.7.14, JaCoCo 0.8.16. Evidence: `apps/api/pom.xml`, `.github/actions/java-verify/action.yml`, `src/test/resources/mockito-extensions/org.mockito.plugins.MockMaker`. |
| 2026-11-19 | OPS-06 | CI action majors aligned: `checkout@v7`, `upload-artifact@v7`, `download-artifact@v8` (all tags verified with `git ls-remote`; Dependabot proposals already merged as PRs #1–#3). `setup-java@v6` and `cache@v6.1.0` are used in the composite action and integrator/fix gate after Dependabot review. No tag could not be resolved. |
| 2026-11-18 | OPS-02, OPS-06 | OWASP Dependency-Check 13.0.0 (`failBuildOnCVSS 7`) and SpotBugs 4.10.5.0 run in `mvn verify`. NVD key is read from `NVD_API_KEY` via `nvdApiKeyEnvironmentVariable` and never stored in the repo; scans succeed from cached data when unset. CVEs in the older stack were fixed by upgrading dependencies, not by suppression. Justified SpotBugs annotations are used only for Spring-injected collaborators and the allowlist-validated echoed header. |
| 2026-11-19 | IAM-01, IAM-02, OPS-02 | S-G0-02 staff lifecycle: deactivation is an append-only 'revoked' membership event (never an UPDATE), so the latest membership event per (org, user) determines current status and a deactivation denies the next request with zero staleness. Role grants are append-only rows carrying `granted_by` and `valid_from`/`valid_to`, enforced as effective-date gates. Bounded G0 roles reuse `tenant_admin` (allowed) / `reception` (denied). Cross-tenant and nonexistent staff concealed with 404. Staff audit purpose is `STAFF_ADMIN`; concurrency stress deferred to S-G0-04 and arbitrary role reassignment to S-G0-03. |
| 2026-11-19 | ADM-01, ARC-02, OPS-02 | S-G0-03 configuration foundation: a draft is an immutable `config_entry` version and a named approval is a separate immutable `config_approval` row (`UNIQUE(org, entry_id)`), so status is derived on read (`pending`/`approved`) never stored. One effective version per key is chosen deterministically by latest `effective_from <= now()`, not enforced by rejecting overlaps at write time; future-dated approvals do not displace the current version early. Self-approval by a tenant_admin is allowed for G0; values are opaque bounded text with UTC `effectiveFrom`; audit purpose `CONFIG_ADMIN`, scope `CONFIG`. Catalogs, broader audit query and OPS-06 infrastructure beyond migration checks remain later slices of this story. |
| 2026-11-19 | OPS-06 | Swarm workers prefer the slot-specific `OPENCODE_API_KEY_<n>` secret and fall back to `OPENCODE_API_KEY` for repository compatibility. Every agent-run command marks the checked-out `$PWD` as a Git safe directory because container workers can have a different owner than the checkout. Evidence: `.github/workflows/swarm.yml`, `scripts/agent-run.sh`, `scripts/tests/test_swarm.py`. |
| 2026-11-19 | OPS-06 | S-G0-03d migration change-safety gate: `scripts/check-migrations.py` enforces contiguous `V<n>__name.sql` versions and expand/contract discipline offline — statement-start destructive DDL needs `Change: contract`, plus `Forward-fix:` and an earlier `Change: expand` reference. Detection is anchored and strips comments, strings and dollar bodies because the append-only triggers and `REVOKE ... TRUNCATE` in V4/V5/V7 are legitimate. A header is a developer declaration (structure and references are proven, not SQL/label agreement); human review and `db/check.sh` stay authoritative. Environment accounts, signed builds and monitored rollout are deferred to cloud/human-gated S-G5-07 instead of a vacuous self-attesting manifest. Evidence: decision `docs/decisions/0002-ops06-migration-change-safety.md`, 34 `test_check_migrations.py` cases, stdlib `trace` 100% line coverage, policy wiring with `--require-baseline` in `scripts/check.sh`, `scripts/quick-check.sh`, `.github/workflows/delivery.yml`. Review found and fixed omitted DROP object types, a string/comment ordering false negative, same-line/split-line bypasses, duplicate-version keying and an unverified Forward-fix; forward-fix existence remains an intentionally unverified future commitment. |

| 2026-11-26 | OPS-06 | The developer reference keeps repo-relative links in `docs/reference` so `check-docs.py` validates them in the checkout; `scripts/docs.sh` rewrites the corresponding generated root-level HTML hrefs to GitHub `blob`/`tree` URLs pinned to the 40-hex commit that built the site, with a post-rewrite `--check` pass. Identity comes from `GITHUB_REPOSITORY`/`GITHUB_SHA` in CI or a GitHub-only origin remote plus `HEAD` locally, and fails closed when invalid; Doxygen internal links and TypeDoc sub-sites are untouched. Rationale: `pages.yml` publishes only generated HTML at a site-root path, so relative links cannot resolve there; pinning to the commit prevents branch drift. Evidence: task `01324000`, PR #1754, 23 named tests, `bash scripts/python-coverage.sh` green, local build rewrote 1,556 links in 15 pages with zero relative hrefs remaining; live Pages retest after merge is still pending. |
