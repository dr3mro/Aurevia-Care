## Phase 5 plan (recovery identity and failure classification)
1. Add pure operation helpers in `scripts/swarm.py`. An operation id is `workflow-slug/job-slug/step-slug`, using the existing lowercase hyphen slug grammar; the reserved segment `run` denotes a job-level or workflow-level fallback. The hidden marker is `<!-- swarm-operations:id1,id2 -->`. The parser accepts only that complete comma-separated grammar, rejects empty, duplicate, malformed or colliding ids, and returns no recoverable set on invalid evidence. A failed job contributes each failed step; a failed job with no failed steps contributes `workflow/job/run`; a run with no failed jobs contributes `workflow/run/run`.

It emits the step ids plus `workflow/job/run` only for a fully successful job, and emits `workflow/run/run` only after the entire nonempty job/step set succeeds. Missing, malformed, duplicate, failed or skipped jobs/steps produce no qualifying operation. Recovery requires a trusted non-PR `swarm-issue` with matching `swarm-workflow` and a valid operations marker whose every id is in that successful set.
