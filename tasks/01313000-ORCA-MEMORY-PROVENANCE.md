## Plan
1. Red tests first in `scripts/tests/test_orca_memory.py`, then implement in a new `scripts/orca_memory.py` with module and function docstrings stating inputs, outputs, errors and the passivity invariant.
2. Evidence kinds reuse the allowed labels from `scripts/orca_benchmark.py:31-45` (`tool`, `reviewer`, `simulated-user`, `human`, `unavailable`). Confidence is an explicit local policy assumption required by `10-memory-design.md:19` ("derived from evidence kind, never stored as an unexplained number"): authoritative kinds tool/human = 1.0, reviewer = 0.9, simulated-user = 0.6, unavailable = 0.0. `Blackboard.publish` takes caller-supplied confidence; this module derives it and never invents a second retrieval rule. The map is pinned by exact-value tests so an owner decision can change it deliberately. An unknown kind raises `ValueError`. `provenance(path, line, kind, revision, fact)` validates non-empty strings, an integer line >= 1 and a strict boolean fact (`isinstance(True, int)` is true, so use `type(fact) is bool`), then returns a plain dict with `location`, `path`, `line`, `kind`, `confidence`, `revision` and `fact`.
3. `select_memory(rows, budget, current_revision)` takes an iterable of provenance rows, a non-negative integer row budget and a non-empty current revision. Stale revisions are dropped with the same equality rule as `orca_core.evidence_fresh()`. Fresh rows are ordered by descending confidence, then fact before assumption, then path and line for deterministic output. Mandatory kinds (`tool`, `human`) are never truncated by the budget; optional kinds fill the remaining slots. `budget=0` keeps mandatory rows and drops all optional ones: this is deliberately the opposite of `compile_context`'s character budget, where `limit <= 0` keeps text whole, because this budget counts rows for scoped retrieval and a zero allowance must not silently dump the whole tracker. The divergence is documented in the docstring and pinned by a named test. Empty input returns an empty tuple. Invalid rows (missing keys, wrong types, unknown kind), a non-iterable `rows`, a negative or non-integer budget and a blank or non-string revision raise `ValueError`. Output is a tuple of row dicts; inputs are never mutated.
4. `orca_memory.py` must not import `orca_core` (the boundary test in `test_orca_core.py:643` forbids production scripts importing it) or any runtime script. The tiny freshness/ordering primitives are mirrored with identical semantics; a named equivalence test loads both modules through `helpers.load()` and asserts the same result for fresh and stale revisions. This avoids a second retrieval or confidence rule while keeping the offline core passive.
5. Branch map with named tests: five kind-confidence values (`test_confidence_*`); unknown kind (`test_unknown_kind_is_rejected`); provenance validations blank `path`, blank `revision`, non-int line, `line < 1`, non-bool `fact`, non-str kind (`test_provenance_rejects_*`); fresh kept and stale dropped (`test_select_memory_filters_stale_revisions`); each sort layer — confidence descending, fact before assumption, path then line — asserted in `test_select_memory_is_deterministic`; mandatory kinds survive a small budget and the zero budget (`test_mandatory_kinds_survive_*`); optional kinds fill remaining slots (`test_optional_kinds_fill_remaining_slots`); zero-budget divergence from `compile_context` (`test_zero_budget_keeps_only_mandatory_rows`); empty input (`test_empty_rows_return_empty_tuple`); select_memory validations non-iterable rows, negative/non-int budget, blank/non-str revision, missing keys, wrong types and unknown kind (`test_select_memory_rejects_*`); inputs unmutated; equivalence with `evidence_fresh` (`test_freshness_matches_orca_core`); impact-specific AST passivity test matching `test_orca_core.py:650-665`, rejecting `__import__`, `import_module`, `glob`/`rglob`/`walk`, file I/O, Git, network, subprocess, tracker writes and runtime imports.
