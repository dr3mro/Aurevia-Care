  - details:
    A tag on a green main commit cannot publish after a newer push cancels that commit's push run: the release precondition counts only successful `push` runs, and the run-level conclusion becomes `cancelled` while every job (including `Delivery gate`) succeeded. The same check is duplicated in `release-app-image.yml`. Fix with one fail-closed helper that binds exact SHA, default branch, repository identity and trusted events, then requires the `Delivery gate` **job** to have succeeded through the Actions jobs API; a run-level `cancelled` is accepted only with that job-level proof. Give default-branch dispatch the same NVD key as push. Do not touch the cancellation rule, the gate contract or any threshold.
    Specialist evidence (read-only): aurevia-github-workflow GO, aurevia-senior-python GO, aurevia-test-engineer GO, aurevia-devsecops NO-GO with four Required items (run identity, trusted check, NVD parity, duplicate path). All Required items are included in this scope. A later live check overturned one design assumption: `gh workflow run delivery.yml --ref <sha>` returns HTTP 422 `No ref found`, so exact-SHA dispatch cannot be the recovery. The final design therefore verifies the gate job of the original trusted run; the earlier test-engineer/devsecops disagreement is resolved by requiring the actual `Delivery gate` job conclusion rather than either raw run-level conclusion or a dispatch-only path.
