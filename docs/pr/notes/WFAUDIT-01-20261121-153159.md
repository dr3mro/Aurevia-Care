## Findings

1. Primary defect: `.github/workflows/swarm-integrator.yml` `integrate` runs the
   full gate on merged PR code in the same job that holds `GH_TOKEN` (
   `SWARM_TOKEN` or `github.token`), `NVD_API_KEY` and write permissions.
   `run_gate` strips three token names from the gate subprocess but that is not
   a boundary: the parent process still holds the token and a same-UID test
   process can read it from `/proc/<pid>/environ`; runner tokens are not in the
   strip list. Evidence: workflow lines 48-118 and `scripts/swarm.py:2387-2436`.
2. `.github/workflows/swarm-worker.yml` `publish` pushes the worker bundle with
   a write token and trusts the unvalidated `checks` flag from `work`; there is
   no validation job and no SHA cross-check between validation and publication.
   Evidence: workflow lines 249-292 and `scripts/swarm.py:1523-1627`.
3. `.github/workflows/fix-pr-gate.yml` `handoff` acts on `passed` without
   re-checking the PR's `merge_commit_sha`; its `validate` job also holds
   `NVD_API_KEY` while running candidate code. Evidence: workflow lines 23-130.
4. The integrator split is blocked on two new trusted `scripts/swarm.py`
   subcommands (`integrate-validate`, `integrate-publish`) that a person must add
   first; their contract is specified in the scope document. Until they exist,
   a person must not apply the integrator hunk alone.
5. Removing `NVD_API_KEY` from validation jobs leaves OWASP using cached NVD
   data (the documented fallback). A separate credentialed cache-refresh job
   that runs no candidate code is the recommended mitigation.

## Lessons for workers

- When a task says "take the diff from a scratch copy", the repository-scoped
  edit tool cannot write outside the worktree; copy the files into
  `/tmp/opencode`, edit them with shell/Python, generate `diff -u --label a/...
  --label b/...`, and prove applicability with `git apply --check` (read-only).
- Re-extract the diff from the finished Markdown and compare it byte-for-byte
  with the verified patch before finishing; a hand-copied fenced block can drift.
- `run_gate`-style environment stripping is not a security boundary when the
  parent process holds the token; job-level isolation is the control. Reuse the
  `fix-pr-gate.yml` validate/handoff pattern for similar audits.
- `python3 -I scripts/check-docs.py` scans every Markdown file outside
  `.agent/` and `docs/archive/`; use only requirement IDs defined in the spec
  (OPS-06, WEB-12 here) and avoid relative links to files that do not exist.
