## Lessons for workers

- When a green fix PR is repeatedly returned, stop re-applying the fix after one diagnosis. Query the REST API (`pulls/{n}` labels and `commits/{head}/check-runs`), then read `scripts/swarm.py` `publish`/`plan_integration`/`pr_flow`. A `needs-fix`/`needs-human`/`needs-debug` label excludes the PR from `plan_integration` regardless of green checks, so "the integrator will retest" is then false.
- Re-applying an already-committed fix and writing another verification-only note does not move a green PR; it only adds a commit to the loop. Diagnose the hand-off mechanism first, and make the next note add a concrete new fact (this pass adds the definitive `Java and database verification=success` CI observation).
- Treat a scope violation in an inherited fix as a real hand-off finding: a strict worker-gate rerun can reject a PR whose CI is green.
- Reset `apps/api/target/jacoco.exec` before the coverage batch and include `BrowserSessionHttpTest`; accumulated exec data can overstate a targeted run.
- The frontend definition of done is mandatory even on a data-only backend pass: run both `check.sh` scripts, paste the `tsc --noEmit` final lines, treat any `error TS…` as a hard stop.
- Inside a cloud worker, worktree `opencode.json` is the CI profile under `skip-worktree`; report which profile was measured rather than treating it as HEAD truth.
