## Lessons for workers

- For a clause-proof test on already-built code, parameterize the shared `result(...)` fixture with
  the policy flag under test (here `readBackRequired`) rather than reusing a helper that hardcodes
  the default; otherwise the intended branch is unreachable behind an earlier guard.
- Model ledger state with a small `AtomicBoolean` flipped by the mocked `appendEvent`, so a
  successful first fact makes `hasEvent(...)` true for the following command. A duplicate-event test
  must actually record the first event, not just set the flag.
- When a clause says "separate events", assert the exact count and each distinct append call, not
  merely that some event of a type was written; two attempts must produce two `ESCALATION_ATTEMPT`
  facts.
