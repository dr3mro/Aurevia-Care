## Lessons for workers

- For HTTP tests over the real JDBC store, give every case a unique `contextReference`: the
  business key `UNIQUE(organization_id, patient_id, unit_id, context_reference)` makes `ON CONFLICT
  DO NOTHING` silently return another fixture's row and turns order-dependent tests into false
  greens.
- A 409 `CONFLICT` cannot be produced through the POST endpoint: it only creates ACTIVE connections
  with the request's own context. Seed the prior different-context or REVOKED connection with SQL
  (tenant-bound), and keep expired/consumed/inactive *relationships* as a separate 422 case.
- `@BeforeAll` runs before `@BeforeEach`, so an injected bean cannot be published through a static
  holder for seeding; seed static fixtures with a direct tenant-bound JDBC statement instead.
- Use `mvn -Pno-security -Dgroups=integration -Dtest=<Class> test` (never `-Pfast`; it sets
  `excludedGroups=integration` and gives a false green) and read the Surefire count; compile before
  `spotbugs:check` because a bare SpotBugs run is vacuously green.
- Do not add `@Disabled` to keep a clause test green: `check-constraints.py` fails on any added
  skip. If behaviour is truly absent, say so in the doc and ask for a task instead.
