# LABFLOW-01 — API: specimen collection with patient and accession match, and label data

## Summary

Added a self-contained `labflow/collection` slice that records a specimen collection only after
the presented patient and accession identity match the stored requisition, refuses and audits a
mismatch, and returns print-ready label data only for a collected specimen (an uncollected accession
is refused with 409 so a printed label never has a blank collection time). It reuses the existing RLS-bounded
`lab.accession` repositories/policy/inputs and `patient.PatientRepository`, so no new table or
migration is introduced. A thin injected controller exposes `POST /api/v1/lab/specimens/{id}/collect`
and `GET /api/v1/lab/specimens/{id}/label`.

Files (all inside the declared scope):

- `apps/api/src/main/java/com/aurevia/labflow/collection/SpecimenCollectionController.java`

## Affected requirements

LAB-01 (spec §5): accession a requisition with an issuer-scoped ID; record specimen type, site,
collector, collection time and quality; match patient and accession at collection; mismatch refuses
and is audited; label data returned for printing. Clause mapping: SPEC-LAB-01-C02 (record fields),
SPEC-LAB-01-C03 (match at collection). Rejection/recollection clauses (C04/C05) belong to
LABFLOW-02 and were not touched.

## Risk class

Safety-critical (docs/WORKFLOW.md): patient identity match, tenant isolation and OPS-02 audit are
involved. Defensive negative tests for mismatch, concealment, wrong role, stale version, illegal
state and lost update are included. Simulated/synthetic review only — no human or real-patient
evidence.

## Review owner

Senior Java and Spring Boot (primary). Senior Spring Security and OIDC (tenant/role boundary).
Test Engineer and QA (evidence). A bounded senior-backend review was requested; findings, if any,
are recorded under `## Findings`.

## Data changes

None. No migration, backfill, lock or volume impact, no rollback/forward-fix. The slice writes only
to existing `public.lab_accession` (state, specimen fields, quality via `LabAccessionRepository.update`,
immutable history via `appendEvent`), reads `public.patient_record` via `current_patients()`, and appends
to `public.audit_event` via `AuditAppender`. All are forced-RLS tables with existing `aurevia_app`
grants; no reserved migration version was consumed.

## Authorization boundaries and audit events

- Active tenant comes only from `TenantContext` (X-Active-Organization) — never from the request body
  or resource path. Every read/write/patient lookup runs in the tenant-guarded `TransactionTemplate`
  under forced RLS; a peer tenant's specimen is concealed as 404.
- Role check reuses `LabActionPolicy`: `SPECIMEN_COLLECT` allows `lab_collector`; label read reuses
  `ACCESSION_READ`. Inactive membership and wrong role return 403 and are audited `DENIED`.
- Audit purpose `LAB_SPECIMEN_COLLECTION`, resourceType `SPECIMEN`, scope `LAB`.
  Actions/outcomes: `LAB_SPECIMEN_COLLECT` with `SUCCESS` / `DENIED` / `NOT_FOUND` / `MISMATCH`;
  `LAB_ACCESSION_READ` with `SUCCESS` / `DENIED` / `NOT_FOUND`.
- Mismatch uses the failure-reference pattern (return null from the guarded transaction, then throw
  after commit) so the `MISMATCH` audit row is committed with the otherwise empty unit of work. The
  real-PostgreSQL integration test asserts that audit row is queryable via
  `GET /api/v1/audit-events?action=LAB_SPECIMEN_COLLECT&outcome=MISMATCH` and contains no patient MRN.

## Migration and rollout considerations

No data change. The new controller is registered automatically by component scanning; it adds two
routes under `/api/v1/lab/specimens` and does not alter any existing route. OpenAPI entry and client
regeneration are intentionally out of this worker's declared scope (`contracts/`); the integrator or
a follow-up contract story should add the two paths and regenerate the client before public release.
Full `mvn verify` / `db/check.sh` and SHA-linked CI are owned by the integrator and Delivery (see
Test evidence for why this worker did not run them).

## Clinical and architecture review

No signed data, cross-organization sharing, prescribing or critical-result workflow is added.
Patient identity is matched against the stored requisition before any write; the label carries only
identifiers and collection time, never clinical narrative. Real clinician/unit acceptance remains a
separate G5 gate and was not claimed. Architecture reuses existing domain boundaries (repository at
the SQL edge, invariant in the service, thin injected controller) rather than duplicating them.

## Findings

- Bounded senior-backend review (simulated, file reads only — reviewer ran no commands) found no
  blocking defect and confirmed acceptance is met. It confirmed the mismatch audit persists (the
  failure-reference pattern commits the audit before the deferred throw) and that tenant scoping is
  genuine (real-PG test: ORG_B 404 / ORG_A 200). Findings dispositions below.
- F1 (reviewer, safety) — a label could be produced for an `ACCESSIONED` specimen with a blank
  collection time. **Fixed**: `labelData` now refuses an uncollected specimen with 409 `INVALID_STATE`
  and an audited `CONFLICT`, with a unit test and a real-PG HTTP assertion. This also satisfies the
  "label data complete" acceptance.
- F2 (reviewer, low) — mismatch audit records the resource and outcome but not which identity field
  was wrong. **Deferred by decision**: the audit deliberately carries no patient identifier (asserted
  by the integration test), and a field code is beyond the stated acceptance; the audit remains
  attributable to specimen + actor + outcome.
- F3 (reviewer, low) — audit assertion was substring-based. **Fixed**: assertions now match
  `"action":"LAB_SPECIMEN_COLLECT"`, `"outcome":"MISMATCH"` and `"resourceType":"SPECIMEN"` keys.
- F4 (reviewer, maintenance trap) — mixed audit-then-defer vs throw-in-callback convention.
  **Addressed**: the class Javadoc now states the invariant conspicuously ("never place an audit
  append immediately before an in-callback throw").
- F5 (reviewer) — OpenAPI entry/client unconfirmed within allowed paths. Confirmed out of scope for
  this worker (contracts/); recorded under "Migration and rollout considerations" as a follow-up.
- The existing `lab.accession.LabAccessionRepository` maps `collected_at::text` to PostgreSQL's
  timestamp text form (e.g. `2026-11-19 10:15:30+00`), not canonical ISO-8601 `Z`. `SpecimenLabelData`
  therefore documents `collectedAt` as "collection time as recorded on the specimen" and the
  integration test asserts the label time equals the stored collection time. Normalising the shared
  `LabAccession` representation would be a separate, out-of-scope change.
- No OpenAPI entry/client regeneration was added (`contracts/` is outside this worker's scope). The
  two new routes are functional and covered end to end but need a contract story before publication.
- `opencode.json` false positive is an environment artifact, documented under Test evidence; no
  protected file is modified.

## Lessons for workers

- In a swarm worker, `agent-run.sh` copies the CI profile over `opencode.json` under `skip-worktree`;
  `check-pack.py` and `test_check_pack` then fail spuriously. Confirm with `git ls-files -v opencode.json`
  and restore `git show HEAD:opencode.json > opencode.json` before judging, instead of regenerating or
  committing the generated file.
- Plain Java records only expose the canonical constructor to JaCoCo in this toolchain; a single
  instantiation covers the record, so do not add "boilerplate" tests merely to touch accessors.
- `HttpStatus.UNPROCESSABLE_ENTITY` vs `UNPROCESSABLE_CONTENT` differ by Spring version while both map
  to 422; assert `getStatusCode().value()` in HTTP tests that must be version-portable.
- When a spec requires an audit row on a refused command, use the failure-reference pattern
  (commit an empty unit of work carrying the audit, then throw after the transaction) or the audit row
  rolls back with the exception.
