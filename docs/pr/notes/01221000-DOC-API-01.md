## Lessons for workers

- For a documentation-only story, a `/tmp` red/green scan is the only test-first option when `scripts/` is protected; record the scope conflict instead of silently dropping the "add a failing case" instruction.
- Check the notes-path convention of both `agent-run.sh` (`.agents/notes/`) and `worker_gate.py` (`docs/pr/notes/`) before finishing. Keeping both copies is cheaper than a gate send-back when they disagree.
- If `worker-check.sh` fails on a clean-base test artifact, record the exact failing command and final line, then run each later stage individually; never edit `scripts/` or `.opencode/` to force a green.
- Requirement-ID tokens inside `ConformanceFixtures` string literals are runtime fixture data, not comments; removing them changes behavior. Scan comments with string-literal stripping.
- Verify a supposedly obvious comment against the code: Spring picks the more specific mapping rather than declaration order, `FhirSupport.identifierValue` stops at the first system match, and `CriticalContract.canTransitionTo` is not the service's live state machine.
- Maven emits empty `package-info` interfaces even without package annotations; confirm JaCoCo exclusion from the report rather than assuming no class file.
- Ask the senior-backend specialist for per-package invariants before documenting: it caught several naive comment claims that would have been wrong.
