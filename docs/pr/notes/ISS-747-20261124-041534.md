## Decisions

- Keep the existing `'timeout'` kind for external aborts and drive retry suppression from
  `options.signal.aborted`, rather than adding an `'aborted'` kind (would ripple into WEB-09 state
  views and `ALL_KINDS`, both outside scope) or `AbortSignal.any` (would break the
  `controller.signal.aborted` catch mapping). Reviewer marked this Optional and acceptable.

  cookie read and issues no fetch. Non-aborted writes still fail closed on a missing/blank token.
- Callers that show a retry affordance on `'timeout'` must check `signal.aborted` first; documented
  in the `SendOptions.signal` TSDoc (devsecops Optional, code-reviewer Optional).

## Lessons for workers

- A caller-cancellation test must include the "signal present but **not** aborted" case; otherwise a
  `signal !== undefined` bug passes every aborted-signal test.
- An early-abort guard that must issue no fetch needs an explicit `expect(fetchMock).not.toHaveBeenCalled()`
  assertion; a typed rejection alone does not prove the network shortcut.
- Read the repository's GAP tripwire specs before claiming a full `check.sh` is green: some intentionally
  failing out-of-scope specs track known CI gaps.
- When a GAP tripwire fails because the gap was already closed, replace it with a positive proof of the
  enforcement chain (job step → canonical `check.sh` → budget script) instead of loosening the old
  assertion; parse YAML step forms tolerantly so a harmless reformat cannot hide the enforcement again.
