## Lessons for workers

- Drive negative-path proofs through the real HTTP controller when the story says "API": status plus JSON error code catches a behavior that only exists in a domain kernel. But stub authorization on the repository the service actually reads — `CatalogService` and `ConfigurationService` each query their own membership fold, so one shared unused stub silently turns a 404 into a 403.
- A tenant-concealment test must seed the record for the owner and make the repository answer depend on `TenantContext.current().organizationId()`; an unconditional `Optional.empty()` proves nothing about isolation.
- When a story's negative-path checklist names a behavior the scoped API does not implement, keep the pull request green and write the exact call and the owning task in `## Why this is not finished` instead of adding a failing or tautological test.
- When `tasks/_head.md` step 6 and the worker prompt disagree about the final gate, follow the more specific prompt rule: this one forbids any command that runs every integration test, so targeted `-Dtest=...` suites plus standalone SpotBugs and the policy scripts are the correct final gate for a scoped test-only change. Record the rule conflict in the notes instead of silently skipping the named script.
- Never wrap a service call in an outer `TransactionTemplate` just to "provide a transaction" when the service already opens its own. A caught `ApiException` from the inner call marks the shared transaction rollback-only, and the outer commit then throws `UnexpectedRollbackException` with no assertion on the refusal. Bind only the tenant context (as the interceptor does) and let the service own the transaction.
