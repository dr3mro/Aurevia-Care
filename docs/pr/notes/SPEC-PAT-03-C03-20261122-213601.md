## Findings

1. **Rule conflict resolved (was the repair blocker).** The first run's
   `it.skip("GAP: ...")` satisfied story step 3 but was mechanically flagged by
   `scripts/check-constraints.py`. The repair converts that case into an active
   test instead of waiving the gate; the constraint check now exits 0. No
   protected script, task, threshold or suppression was changed.
2. **Stale-render pitfall found and fixed.** The first un-skip attempt held the
   draft in closure `let` variables and called `view.rerender(...)`; with React
   19 and RNTL v14 the `screen` queries stayed stale, so submit still rendered
   disabled and no case was posted. The test now uses a small stateful wrapper
   (`WiredSupportScreen`, React `useState`) and awaits every `fireEvent`, so each
   interaction flushes a real re-render; the case is posted exactly once.
3. The brief's reuse claim was inaccurate: `spy<Args>()` and `supportStrings`
   are local to `screens.test.tsx` and are not exported. Local typed copies were
   written; no existing test was edited.
4. The brief's endpoint path was also wrong: it said
   `POST /api/v1/patient-access/cases`. The real route is
   `POST /api/v1/patient/access/cases` (verified in
   `apps/api/src/main/java/com/aurevia/messaging/enrollment/PatientAccessController.java:50,182`
   and `contracts/openapi/missing-routes.txt:268`). All occurrences in the test,
   clause doc and notes were corrected. The source survey was otherwise accurate.
5. `git grep` shows pre-existing conflict markers in three committed Java files
   (`exchange/hl7/Hl7ParseException.java`, `Hl7Parser.java`, `Hl7Segment.java`).
   They are on the base commit, outside this task's scope, and were left
   untouched. Neither in-scope file contains conflict markers.
6. The installed Account → support route still passes `placeholderAction` for
   all three callbacks and no patient-app client posts a case. That end-to-end
   gap is deliberately outside this proof-only repair and remains registered as
   the `task-requests` entry below.
7. Evidence provenance: all commands above were executed by this worker (tool
   evidence); reviewer verdicts below are simulated/static reviews. No human,
   clinical or real-patient evidence is claimed.
8. Review cycle: `aurevia-code-reviewer` GO (its Optional finding — the
   "Production symbols exercised" heading contradicting a not-imported bullet —

## Lessons for workers

- A story-mandated `it.skip`/`@Disabled` that `check-constraints.py` flags must be
  converted into a real active test or deleted; notes cannot waive the gate and
  protected scripts must not be edited.
- With React 19 + RNTL v14, drive component state from a stateful wrapper and
  `await` every `fireEvent`; plain closure `let` variables plus `rerender` leave
  `screen` queries stale and make assertions silently observe the old tree.
- Keep the clause document and notes in sync with the test name and skipped/active
  status in the same change; a stale "skipped" claim is a truthfulness defect.
