# READY-44 — Request metrics endpoint (WEB-06)

## Summary

Added an instance-local request metrics registry and a `GET /health/metrics` Prometheus scrape next to the READY-01 health probes. `RequestMetricsFilter` records one observation per completed request using the Spring `HandlerMapping.BEST_MATCHING_PATTERN_ATTRIBUTE` route pattern (never the raw URI), so ids cannot enter a label. Two series are exposed: `aurevia_http_requests_total{method,route,status}` and `aurevia_http_request_seconds_sum{method,route,status}`, with status as a class (`2xx`, `5xx`, ...). The endpoint needs no login but is answered only from loopback or a CIDR in `AUREVIA_METRICS_ALLOW` (default loopback); any other source receives a bare 404. No dependency was added. No migration, patient data, credential or raw log was introduced.

## Affected requirements

- WEB-06 — per-route request rate, error rate and duration; the structured JSON log evidence already exists in `LogRedactionTest` and was left unchanged.
- WEB-05 — `/health/metrics` is an additional exact unauthenticated route; the protected `/api/v1/**` surface remains authenticated.
- Alert thresholds documented from OPS-03 (99.9% monthly availability, p95 <= 500 ms reads and <= 900 ms commands) and OPS-05 (error rate, saturation, queue age), plus error-budget burn and failed external uptime probes.

## Risk class

Cross-boundary — new HTTP endpoint and two security-chain matcher changes. No clinical, tenant or patient data is read or emitted; metrics contain only aggregate route-level counters.

## Review owner

Senior Java and Spring Boot; Senior Spring Security and OIDC for the address gate and chain matchers; Test Engineer for the acceptance matrix.

## Data changes

None. No Flyway migration, backfill, lock or volume impact. No rollback or forward-fix needed.

## Authorization boundaries and audit events

`GET /health/metrics` is permitted in both production filter chains but gated by `MetricsAccessPolicy` on the servlet remote address. Default allows only IPv4 and IPv6 loopback; additional networks come from `AUREVIA_METRICS_ALLOW`. A malformed CIDR fails construction (fail closed). No tenant context, role or patient link is involved, and no audit event is added — the body contains no identifiers or request detail.

## Migration and rollout considerations

Configuration-only rollout: set `AUREVIA_METRICS_ALLOW` to a comma-separated CIDR list if the scraper is not on loopback. Leave unset for loopback-only exposure. The endpoint is safe to expose behind the load balancer because disallowed sources receive 404.

## Findings

- `bash scripts/worker-check.sh` exits 1 locally at the pack check because the worktree `opencode.json` is the CI profile under skip-worktree. This is pre-existing and documented in MEMORY.md (OPS-CW-003-01) and the delivery skill; no out-of-scope file was changed. Next step for the integrator: run the gate at HEAD, where `opencode.json` is the committed local profile. No code change is needed.
- `python3 -I -m unittest discover -s scripts/tests` reports 822 tests with 5 failures, all in `test_check_pack.py` for the same CI-profile reason (`opencode.json is stale`); all other tooling tests pass. The Java conventions subset is green.
- SPA-style single red-green cycle initially rendered counts as `1.0` because a long-valued branch of a ternary was promoted to double; fixed by formatting each branch to a String (`Long.toString` / `Double.toString`) so counts stay integral. This is behaviour-preserving for the metric contract and is covered by `RequestMetricsTest`.

## Lessons for workers

- In a cloud worker, `opencode.json` is the CI profile under skip-worktree. Do not edit it or regenerate it to satisfy `check-pack.py`; record which profile was measured and run the individual downstream gates instead. The integrator sees the committed local profile at HEAD.
- A ternary mixing `long` and `double` branches promotes both to `double`, so a Prometheus counter renders as `1.0`. Format each branch to a String to keep counters integral.
- For a new unauthenticated HTTP route outside `/api/v1`, permit the exact path in both the browser and bearer chains, then gate it inside the controller — the chain permit alone would expose it to every network.
