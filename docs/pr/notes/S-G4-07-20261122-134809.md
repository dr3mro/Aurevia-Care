## Lessons for workers

- Before citing a merged test as gate evidence, verify the cited method names and endpoint annotations with `grep` and confirm the merge commit with `git log --oneline -1 -- <file>`. Names drift during refactors (for example `09cdc1fd` renamed story-id packages to business domains); a plausible-looking method name that no longer exists is worse than no citation.
- Do not claim a gate criterion proven from a design document, an open task title or a service-level test with an in-memory store alone. Name the HTTP and durable-store tests that prove the same behaviour and state explicitly what is not proved (physical delivery, on-device verification).
- A targeted `mvn -Dtest=...` still compiles the entire test tree. An unrelated broken test source on `main` can block every targeted run; record the exact command, final error line and merge history, do not fix files outside `scope`, and fall back to merge-commit evidence with a clear caveat.
- When a later change widens a shared record (for example adding a constructor parameter), grep all call sites in tests before merging — BUILD-16 changed `ExportRecord` one slot before `OffboardingCommandTest` was added, leaving main's test tree uncompilable.
