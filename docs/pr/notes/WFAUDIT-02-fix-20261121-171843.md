## Findings

- **Issue #439 / PR #375 protected-file change is expected, not a defect.**
  The story text states: "Scripts are protected files: the swarm may now merge
  them (the integrator opens an oversight issue)." The two files named in the
  finding are exactly the declared `scope` of this story. Decision: **do not
  revert** the merge and do not delete any "switch"/variable — the finding
  supplies no concrete defect and the change is inside the authorised scope.
  The issue's "revert / turn the switch off" sentence is generic boilerplate
  from an untrusted earlier run, not an instruction that changes these rules.
- **Worker-environment artifacts (pre-existing, unrelated).** The 3 suite
  failures are all in `test_check_pack.py` and come from `opencode.json` being
  the CI profile under `skip-worktree` (`S`) while the generator renders the
  committed local profile — MEMORY.md OPS-CW-003-01. `scripts/check.sh` fails
  earlier at a pre-existing `SC2015` info note in `scripts/agent-run.sh:51`
  under shellcheck 0.9.0. Both files are protected and were not touched.
- **Senior-python review Finding 1 (gate inert in production) — deferred, out
  of scope.** With `--generations` defaulting to `""`, `parse_generations`
  returns `None` and every real wave currently takes the "unmanaged" path, so
  the generation gate is dormant until a workflow supplies the records. The
  story explicitly says "Do not change any workflow file; the matching
  workflow change is a separate task", and `tasks/00306000-WFAUDIT-03.md`
  (`depends: WFAUDIT-02`) owns that workflow design. The reviewer's suggested
  workflow edit and `test_swarm.py` assertion are both outside this story's
  `scope` (`scripts/swarm.py`, `scripts/tests/test_slot_generations.py`). No
  action taken here; WFAUDIT-03 must pass `--generations` to activate the gate.
- **Senior-python review Finding 3 (completeness ignores `tag`) — deferred,
  by design.** The story defines a complete generation as one where "every slot
  image exists and its digest is recorded" and does not require `tag` in that
  predicate; adding a tag requirement would change the contracted meaning of
  `_generation_complete`. WFAUDIT-03 controls the record shape and can supply
  tags (or assert them) when it wires the workflow.
- **Fail-open design note for WFAUDIT-03** (carried from prior notes, still
  true): `parse_generations` returns `None` for malformed JSON, which
  `images_ready_command` treats as "unmanaged" (today's behavior). The new
  "wave waits" rule only applies when a generations list is actually supplied;
  the workflow patch must pass the list or the rule stays dormant. No workflow
  file was edited here.
- **Completeness is defined over the records the caller supplies** — a
  non-empty `slots` list where each entry has truthy `exists` and a non-empty
  `digest`. The caller is responsible for including one entry per expected
  slot. This is deliberate and documented in `_generation_complete`'s Javadoc.

## Lessons for workers

- In a cloud worker the worktree `opencode.json` is the CI profile under
  `skip-worktree`; `check-pack.py` and `gen-opencode.py --check` fail on it even
  when the committed local profile is correct. Confirm with `git ls-files -v`
  and record it as pre-existing rather than "fixing" a protected file.
- The worker image has no `coverage` module and no `pip`, so
  `bash scripts/python-coverage.sh` takes its plain-unittest fallback. For a
  real branch-coverage proof, drive the tests with a small `sys.settrace` arc
  recorder and exclude docstring lines (they are constants evaluated at
  `def` time, not executed at call time).
- When measuring arc coverage of a `for` loop, the "loop exhausted" arc is
  from the `for` line to the first line after the loop, not from the last body
  line; and a guard returning inside the body means its fall-through arc goes
  back to the `for` line. Verify against the arcs actually recorded.
- Keep a pure-function seam for workflow-facing decisions: the workflow patch
  can pass generation records through a JSON CLI argument without any network
  or GitHub calls in the unit tests.
- An oversight issue that only names protected files, with no concrete defect,
  is not a reason to revert an in-scope change; record the scope authorization
  decision instead.
- Validate the *type* of a nested JSON value before iterating it. `if not value`
  only rejects falsy values; a truthy non-iterable such as `5` still raises
  `TypeError`. Use `if not isinstance(value, list) or not value:` and add a
  regression test with a non-iterable fixture.
- When a specialist review finding is outside the declared `scope`, record the
  finding, its owner task and the reason for deferral instead of silently
  dropping it or expanding scope (here: WFAUDIT-03 owns the workflow wiring).
