## Lessons for workers

- When a story declares requirement IDs, check that the discoverability surface
  (the index/table of contents) maps *every* declared ID, not just the runbook
  bodies. A body can address a requirement that the index row forgets to list.
- Re-read all in-scope files end to end at the start of a fix pass even when the
  prior pass reports green: the prior pass's correctness does not cover a
  completeness gap it never looked for.
- The applicable gate for a docs-only story is `python3 -I scripts/check-docs.py`
  plus the cheap `check-names.py`, `check-secrets.py` and `git diff --check`.
  Do not run the full Java/integration gate as a worker.
- A parallel maintainer folder rename can turn a previously green docs link gate
  red on the next merge — the folder-rename mapping for the G5 operations docs
  is `s_g5_05->capacity`, `s_g5_06->recovery`, `s_g5_07->delivery-safety`,
  `s_g5_08->tenant-lifecycle`, `s_g5_09->onboarding`, `s_g5_10->accessibility`,
  `s_g5_11->ops-queues`. `check-docs.py` checks link targets, not link text, so
  de-ID the visible text too.
