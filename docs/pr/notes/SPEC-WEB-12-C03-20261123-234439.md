## Lessons for workers

- For an evidence note, cite real `file:line` only and name the status that the evidence can
  carry: file-level pins without an enforcement gate are "Built but not verified", never
  "Built and verified" and not "Not built" when the config is present.
- Check `docs/pr/notes/<date>.md` for the newest reconciled daily note; an advisor brief can
  name an older archive copy.
- Separate build-time base digest pinning from run-time image tag resolution before saying a
  supply-chain clause is complete: `FROM ${BASE}` plus CI-side digest resolution is pinned, while
  a `:latest` image in a job container is not. An enforcement checker must understand that
  cross-file pattern or it will false-positive.
- In evidence notes, distinguish "present as file content" from "provenance verified"; no
  registry lookup was performed here, and stale tag comments make grep-based manual checks
  error-prone.
