## Lessons for workers

- Before adding a `@Disabled("GAP: ...")` proof to a Java file, run `scripts/check-constraints.py`: it rejects any added disabled test even with a GAP reason, and AGENTS.md's no-skipped-test rule is the higher-priority authority over a story or advisor brief that asks for one. Document the complete would-be test in the clause doc (docs are exempt) and use a passing structural assertion in Java instead; add a `task-requests` block so the gap gets an owner.
- A clause-proof story scope with "new files only" still lets you use the existing test-only fakes (`InMemoryServiceProfileStore`, `InMemoryInstructionFactStore`) behind a standalone-MockMvc harness with the synthetic-auth tenant interceptor; that gives HTTP-level entry-point proof without a new database or production wiring.
- In the in-memory store fake, profile rows are keyed by `(organizationId, id)` while `effectiveProfile` selects the max *version*. When adding a "draft/future must not displace the effective profile" fixture, give the extra versions distinct IDs; reusing the seeded ID overwrites the effective row and produces a misleading 404.
- `check-pack.py` failures from `git ls-files -v opencode.json` showing `S` are a cloud-worker artifact. Confirm once with the worktree/HEAD checksums, run the other gate stages individually and never regenerate or commit that protected file.
- Keep clause ownership explicit: the supervisor `overdueResponses` counter is MSG-06 clause 5; do not present it as proof of clause 3's escalation requirement.
