## Lessons for workers

- When a parallel maintainer refactor renames directories, a previously green
  docs link gate can go red on the next merge. Always re-run
  `python3 -I scripts/check-docs.py` after merging `origin/main`, even if the
  docs files themselves did not change.
- The folder-rename mapping for the G5 operations docs is
  `s_g5_05->capacity`, `s_g5_06->recovery`, `s_g5_07->delivery-safety`,
  `s_g5_08->tenant-lifecycle`, `s_g5_09->onboarding`, `s_g5_10->accessibility`,
  `s_g5_11->ops-queues`. Use it when repairing relative links; do not invent a
  new folder.
- `check-docs.py` checks link *targets*, not link *text*. De-ID the visible link
  text too when it names an old story-ID folder, so `grep -rn "s_g5_"` in scope
  is empty and the docs stay consistent with CODING_STYLE.md.
- A docs-only story has no `mvn verify` coverage gate and no frontend
  `tsc --noEmit` step; the applicable gate is `check-docs.py` (plus the cheap
  `check-names.py`, `check-secrets.py` and `git diff --check`). Do not run the
  full Java/integration gate as a worker.
