## Summary

Added one plain JUnit 5 test, `com.aurevia.contract.OpenApiContractRulesTest`, that parses the authoritative staff-API contract (`contracts/openapi.yaml`, the file `apps/staff-web/scripts/gen-api-types.sh --check` points at via `../../contracts/openapi.yaml`) with the SnakeYAML already on the test classpath and enforces five cross-cutting OpenAPI rules on every operation: unique `operationId`; summary and at least one tag; secured operations document 401 and 403; no path/query parameter named like a tenant or organization; and every POST/PUT/PATCH/DELETE declares `Idempotency-Key` or is on a short, `// TODO`-annotated allow list. A small synthetic contract held as a string fails each rule once; the real contract passes via the allow lists. No dependency, production code, contract, migration or configuration was changed.

## Findings

Real-contract gaps were allow-listed with `// TODO`, never edited in the contract:

1. All 21 operations lack a `tags:` field, so the tag rule is suppressed for: `getFacility`, `listFacilities`, `createFacility`, `createConfiguration`, `getEffectiveConfiguration`, `approveConfiguration`, `getConfigurationHistory`, `listCatalogFamily`, `getCatalogEntry`, `defineCatalogEntry`, `approveCatalogEntry`, `queryAuditEvents`, `listStaff`, `inviteStaff`, `getStaff`, `deactivateStaff`, `getStaffHistory`, `listAppointments`, `listLabAccessions`, `listFinanceInvoices`, `listOrders`.
2. All 7 POST operations lack an `Idempotency-Key` header: `createFacility`, `createConfiguration`, `approveConfiguration`, `defineCatalogEntry`, `approveCatalogEntry`, `inviteStaff`, `deactivateStaff`.
3. "Secured" is defined with OpenAPI semantics: a non-empty operation-level `security` array, or an inherited non-empty top-level `security` when the operation has no `security` key; an explicit `security: []` opts out. The committed contract declares no `security:` anywhere, so rule 3 currently passes vacuously and is a forward guard on future edits, not evidence that today's auth documentation is complete. The alternative definition (treat any operation carrying `X-Active-Organization` as secured) would require allow-listing 15 operations that document 403 but not 401; that conflates tenant scoping with authentication and was not chosen.
4. Pre-existing environment failure, not caused by this change: `opencode.json` is skip-worktree (`git ls-files -v opencode.json` → `S`) and its worktree copy is the CI profile, which differs from `git show HEAD:opencode.json`. Consequently `python3 -I scripts/check-pack.py` and three `test_check_pack` cases fail (`opencode.json is stale`). This is the already-recorded OPS-CW-003-01 artifact in MEMORY.md. `git status` and `git diff --stat` confirm the only working-tree change is the new test file.
5. `scripts/check.sh` was run once but fails at `check-pack.py` before reaching the module loop, so `apps/api/check.sh` (`mvn verify`) was intentionally not executed; the story forbids workers from running the full gate.

## Lessons for workers

- SnakeYAML 2.6 is already on the API test classpath via Spring Boot (`new Yaml().load(String)` works); verify with `dependency:tree` instead of adding a dependency.
- `Set.of(...).contains(null)` throws `NullPointerException` in Java; guard allow-list membership when a parsed field such as `operationId` can be absent.
- When a rule is vacuously satisfied by today's contract, keep it with a precise negative fixture and document the tradeoff rather than deleting it or inventing a broad interpretation.
- In a cloud worker, `opencode.json` is a skip-worktree CI profile: treat `check-pack.py`/`test_check_pack` staleness as an environment artifact and verify with `git show HEAD:opencode.json` before reporting it.
- A fixture built by `String.replace` on a YAML text block must remove whole indented blocks; deleting only a mapping key leaves orphaned sequence lines and produces a SnakeYAML parse error.
