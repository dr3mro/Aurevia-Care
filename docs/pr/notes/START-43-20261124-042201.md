## Repair attempt 1 — coverage-check failure (2026-11-24)

### What failed and why

The integrator/Delivery `coverage-check.sh` runs `mvn -q -B -f apps/api/pom.xml -Pno-security verify`, which executes the whole suite. It failed with 3 `UnexpectedRollbackException` errors — **not** a JaCoCo coverage miss — all in the pre-existing integration class
`apps/api/src/test/java/com/aurevia/tenancy/clauses/JobsExportsSearchAttachmentsIntegrationsApplySameTest.java`:

- `peerTenantCannotUseJobsExportsSearchAttachmentsOrIntegrations:483`
- `staleAndExpiredStatesAreRefused:586`
- `wrongRoleCannotStartAnExport:563`

All three went through the test helpers `exportDownloadRefusal`/`exportStartRefusal`. Those helpers wrapped the service call in a **second** `TransactionTemplate.execute`. `TenantExportService.download`/`start` already open their own tenant-guarded transaction; the `ApiException` refusal marks that shared transaction rollback-only, and the redundant outer template then tries to commit and throws `UnexpectedRollbackException` at `TransactionTemplate.java:149` before the status can be asserted. Reproduced deterministically in isolation (3 errors, 2 retries): this is a test-harness defect, not DB flakiness (the `aurevia_retention_duty_it` / closed-connection warnings in the tail are unrelated housekeeping from other suites).

### Fix (test source only, no production change)

Removed the redundant outer `transactions.execute(...)` wrapper from both helpers so the service owns its transaction and the refusal is caught outside it and rolls back cleanly. Assertions and expected statuses are unchanged (404 / 410 / 403). Doc comments explain why no outer transaction is used. No threshold, exclusion, suppression or production code was changed.

### Branch-to-test list (deterministic, already-existing tests)

No production line or branch was added or changed, so there is no new coverage to write; these are the refusal branches the repaired helpers now reach deterministically, each already asserted by a named test:
