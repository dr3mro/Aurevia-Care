- `SCALE_NOT_APPROVED` (422) → `refusesUnapprovedScaleWrongUnitAndNonPermittedValue`;

  and no version advanced.
- `FORBIDDEN` (403) wrong role → `refusesOutcomeByWrongRoleAndStaleVersion` (PT coordinator);
  `STALE_VERSION` (412) → same test after one successful reading.
- Tenant isolation → `concealsScaleAndReadingFromAnotherTenant` asserts ORG_B sees empty

## Lessons for workers

- Check `python3 -I scripts/check-constraints.py` before adding any `@Disabled` to a Java file: the
  added-line rule rejects it even when the story asks for a GAP placeholder. Preserve the complete
  test in the notes instead of shipping a gate-breaking skip.
- For a service + real-PostgreSQL evidence test, re-read the episode version after *every*
  successful write (evaluation and each reading); failed writes do not bump it, so one precondition
  can serve several negative assertions, but a successful write invalidates it.
- Use a distinct database name and a UUID scale key/referral id per test class and per method:
  `worker-check.sh` runs all `@Tag("integration")` suites in one Maven invocation, and scale
  version counters are allocated per `(organization, key)`.
- The domain approver is `CLINICAL_GOVERNANCE`, not `TENANT_ADMIN`; copying an admin actor into
  `approveOutcomeScale` fails with 403 before the assertion under test is reached.
