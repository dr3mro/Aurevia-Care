## Lessons for workers

- When a new e2e journey spec is committed, update the `currentSpecs` artifact pin in the same change: the tripwire compares the whole on-disk spec set, not a hand-listed subset of recognised journeys.
- Check whether a failing test is already red on `origin/main` before treating the current branch as the cause; a merge can simply expose a stale pin introduced by an earlier commit.
- If `scripts/frontend-check.sh` passes the five-minute worker cap, stop it and run its remaining stages individually rather than reading the timeout as a gate failure; record the exact cap and each stage result.
- For a test-data pin fix, quote the red assertion diff and the green rerun of the same command — that is the whole red/green proof; do not touch the assertion, thresholds or other tripwires to make it pass.
