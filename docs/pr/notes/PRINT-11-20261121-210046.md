# PRINT-11 · Patient app: released handouts (PAT-02, CLN-07)

## Summary

Added a self-contained patient handout feature under `apps/patient-mobile/src/features/handouts`:
domain contracts, bilingual (English/Arabic) copy, a validating client that filters withheld
handouts at the trust boundary and re-authorizes every download for the exact version, patient
and current release, an explicit save/share/cancel intent flow, a transient in-memory store
cleared by the real sign-out path, a presentational screen with Corrected context and RTL rows,
and 35 synthetic acceptance tests. 100% statement/branch/function/line coverage on every new
executable file.

## Affected requirements

PAT-02 (released documents, revision/correction context, per-download authorization, no
persistent clinical cache, explicit save intent), CLN-07 (immutable versioned handouts, checksum,
Arabic direction-aware copy). Aligned with UX-01 (English/Arabic, RTL), ARC-06 (checksum), XCH-06
(correction context). No migration requirement.

## Risk class

Safety-critical — patient-visible clinical document access, release-state enforcement and
patient-link binding. No real clinical or human evidence is claimed.

## Review owner

`aurevia-senior-mobile` (bounded advisory review actually executed; findings incorporated:
releaseState made required and parsed, download fails closed on any non-current state, complete
correction pair, real `clearToken()` sign-out test, every Alert button exercised),
`aurevia-senior-typescript` (typecheck rules applied). Patient flow is simulated by tests,
not a human participant.

## Data changes

None. No migrations, backfills or schema changes.

## Authorization boundaries and audit events

No server change: the client re-reads the OS-backed credential on every command, binds each
download to the exact handout id + version + verified patientId + current release, and discards
withheld projections before they reach the screen. No rendered bytes, credentials or clinical
content are cached; the handout list lives only in the shared in-memory clinical cache and is
cleared by `clearToken()` -> `clearClinicalCache()`. Audit events remain server-owned; none added.

## Migration and rollout considerations

None. The screen is not wired into app navigation or the reports tab: that is outside the
declared scope and needs a separate owner-approved change (see Findings).

## Findings

1. **RESOLVED — out-of-scope feature registry.** `apps/patient-mobile/src/features/domain-layout.test.ts`
   asserts exact-set equality between the on-disk feature directories and a hard-coded
   `DOMAIN_FOLDERS` list. Adding the required business-domain folder `features/handouts` made the
   full module gate fail with `+ "handouts"`. Repair attempt 1 registered the folder with one line
   (`'handouts', // PAT-02, CLN-07 - patient handout domain`); all three structural assertions remain
   intact and the full gate is green. Precedent: `docs/swarm/BUILD-53.md`,
   `docs/pr/notes/PHARM-07-20261121-195215.md`, `docs/pr/notes/TRACK-02-20261121-193546.md`.
2. **Navigation wiring not included.** `HandoutsScreen` is exported from the feature but is not
   mounted in `src/app/patientPages.tsx` / `RootNavigator`; those files are outside scope. The
   feature is therefore reachable to embedders and tests but not yet to an end user of the app.
   This needs an owner-approved follow-up.
3. `reports/reportClient.ts` `parseReleasedReport` does not populate `releaseState` even though
   `ReleasedReport.releaseState` exists; that pre-existing gap is untouched here. The handout
   client deliberately makes `releaseState` required so the withheld filter cannot be inert.
4. No new credential key or seam was introduced: the handout client accepts the existing
   `TokenStore` boundary (`reports/types.ts`), whose production implementation uses the shared
   `aurevia.patient.session` OS-backed key.

## Lessons for workers

- Before adding any top-level folder under `apps/patient-mobile/src/features`, expect
  `src/features/domain-layout.test.ts` to fail: it asserts an exact set, not just domain naming.
  Check the scope line first; if the registry is outside scope, document the hand-off rather than
  silently changing it.
- `StatusPill` renders a shape-distinct glyph plus its label, so assert with
  `toHaveTextContent(/Corrected/)` rather than exact text.
- With `verbatimModuleSyntax`, import `jest` from `@jest/globals` for `jest.mock`, and keep every
  type-only import (`TokenStore`, `Locale`, fixture types) on `import type`.
- Give the client trust boundary ownership of visibility (`releasedOnly`) instead of duplicating a
  withdrawn/withheld branch in the screen; duplicated rules create unreachable coverage branches.
