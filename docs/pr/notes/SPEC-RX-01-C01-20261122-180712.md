## Lessons for workers

- Before copying a clause-test pattern, check `scripts/check-constraints.py` against your new file: a new `@Disabled("GAP: …")` is rejected even when an older story used one. An enabled characterization test that asserts the missing field is absent proves the gap and keeps all gates green; document the required production change in `## Gap` and a `task-requests` block instead.
- Verify precondition semantics in source before naming a negative test: `IfMatch.parse` rejects `0` with 422; only a positive mismatched version reaches the service's 412. Also check the response wrapper: `GET /api/v1/prescription-drafts/{id}` returns `DraftView` (`/draft/...`), while create/select return a bare `Draft`.
- Do not add `fast` to a targeted `-Dgroups=integration` Maven run: the fast profile's `excludedGroups=integration` wins and silently produces a vacuous green; always read the Surefire XML and require `tests=N, skipped=0`.
- In a cloud worker, `worker-check.sh` and `python-coverage.sh` can stop at the stale CI-profile `opencode.json` (`git ls-files -v` -> `S`). Confirm once, run the remaining stages individually, and never regenerate or commit that protected file.
