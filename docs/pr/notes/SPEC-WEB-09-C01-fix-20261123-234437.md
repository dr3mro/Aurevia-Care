## Lessons for workers

- A draft pull request with no reported failing test is usually a worker-run
  status artifact. Reproduce the targeted test and typecheck first, then the
  mandatory frontend gate, and record honestly that no code change was needed
  instead of inventing one. A further notes-only pass cannot publish the task
  or change a label.
- Validate the notes file you actually ship: run `check-verdicts.py` with no
  `--base`, because the base-aware shortcut returns success on docs-only
  diffs without reading any verdict. Then run `quality-gate.sh` with the exact
  base and notes path.
- Do not "harden" a log assertion to inspect every `console.error` argument
  when a framework logs the caught error object itself. Filter to the
  application's plain-string lines and assert the full plain-string set.
- Say "Vitest 5.1.1 with the v8 coverage provider", not "Vitest v8". A spec
  under `tests/` is outside `coverage.include`, so it is uncountable, but its
  executions still add hits to covered `src` modules.
