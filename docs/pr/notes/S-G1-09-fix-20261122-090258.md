## Lessons for workers

- On a fix pass whose preceding worker reports "local checks: failed", reproduce each failing
  command before changing code — a red `gen-opencode.py --check` in a cloud worker is usually the
  CI profile under `skip-worktree` (OPS-CW-003-01), not a stale generated file. Verify HEAD truth
  with `git show HEAD:opencode.json` and `git ls-files -v opencode.json`; never regenerate or edit
  `opencode.json`/`.opencode/` as a worker.
- Do not rewrite a gate evidence note that a prior pass already verified. Re-verify the cited test
  methods and spec-row wording with `grep`, then record fresh tool evidence; avoid churn.
- `scripts/check.sh` runs the full `apps/api/check.sh` verify/integration suite and is forbidden for
  workers; for a docs-only change use `python3 -I scripts/check-docs.py` (plus check-names,
  check-secrets and `bash scripts/coverage-check.sh`) instead.
- Keep "engineering evidence proven" strictly separate from "human acceptance open"; a
  `GATE-PACK-*` or `S-G5-*` task prepares evidence and never records approval.
