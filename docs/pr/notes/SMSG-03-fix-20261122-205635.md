# SMSG-03 (fix pass) — API: instant conversations inside a facility

## Summary

Fix-and-close pass on the instant staff-chat slice at
`com.aurevia.staffmsg.instant`. The previous pass had already closed
the zero-peer group, read-cursor monotonicity and facility-scope gaps, but its
hand-off note was rejected by `worker_gate.py` with rule `notes-placeholder`:
the `Test evidence` section quoted a JUnit failure containing literal
angle-bracketed exception names, which the gate mistook for an unfilled
placeholder. No production file was wrong; the hand-off was.

Starting from the earlier findings, this pass produced a valid hand-off and
closed two further Required gaps found by the mandatory quality loop:

1. A caller whose staff role had been revoked could keep acting: `requireAccess`
   (send, markRead, messages, addParticipant, removeParticipant), `unreadCounts`
   and `conversations` did not re-check active staff status, so a subject whose
   organization membership was revoked but whose participant row was still open
   retained access. All three now call `requireActiveStaff`, guarded by a
   red-then-green test.
2. No single test proved reachability end to end: the only HTTP test mocked the
   service and the only real-database test bypassed the controller. Two new
   integration tests now drive MockMvc through the real controller, real service
   and real JDBC store against PostgreSQL, asserting a durable ledger row and a
   facility denial.

No migration, OpenAPI contract, generated client, tracker, script or workflow
file was edited. No push, tag or GitHub CLI call was made. All fixtures are
synthetic; no patient data or credential appears in code, tests or notes.

## Authorization boundaries and audit events

Tenant and actor come only from `TenantContext.current()`, and `context()` fails
closed with 403 when unbound; no request record carries an organization or actor
field. Every command re-checks active staff membership and roles through
`activeStaff`, and facility scope through `facilityWithinScope` against the V93
fold, for the actor and each peer at open, for each peer at group creation, for
the new subject at add, for the caller in `requireAccess` (send, markRead,
messages, add, remove) and in both list endpoints. This pass added the missing
caller-side active-staff check to `requireAccess`, `unreadCounts` and
`conversations`, so a revoked membership takes effect on the next request even
while a participant row is still open. The fold's facility argument is the
tenant's database facility code, not request-body input; a facility missing from
the tenant yields false. A former member still sees history up to `left_at` but
is refused on writes and cursor advances. Cross-organization access is concealed
as 404 by forced RLS. The controller passes the idempotency header only; sender
and role are bound by database triggers. No audit event type was added or
changed, as the MSG-07 audit is a separate task.

## Migration and rollout considerations

No migration to deploy. The endpoints are additive after V91 and V93 and need
no lock or backfill. The tightened active-staff check only narrows access: it
denies callers who no longer hold an active role, matching the app-wide IAM-01
zero-staleness policy. Read cursors restart empty on process restart, a
documented limitation that does not affect the immutable ledger.

## Findings

1. **FIX-INSTANT-OPENAPI (task `00002000`, out of scope).** The nine instant
   routes are absent from `contracts/openapi.yaml` and are carried by the
   shrinking baseline in `contracts/openapi/missing-routes.txt`. The generated

   edited here.
2. **FIX-INSTANT-READ-CURSOR (task `00015000`, out of scope).** Read cursors are
   a process-local `ConcurrentHashMap`; unread counts reset to everything after
   zero on a process restart. The immutable ledger is unaffected.
3. **FIX-INSTANT-SEND-CONTRACT (task `00021000`, out of scope).** The controller
   `send` method uses the body conversation id and ignores the URL path id. That
   task owns the mismatch fix and an HTTP mismatch acceptance test.
4. **Optional, unblocking.** Concurrent retries of one key can both miss the
   existing-message lookup; the database unique constraint still prevents two

   and the view and unread projections load all messages. None is in this
   story's acceptance and none was changed here.
5. **OPS-CW-003-01 (environment, once).** In this cloud worker `opencode.json`

## Lessons for workers

- The hand-off note is itself a gated artifact. Quoting a JUnit failure verbatim
  into `Test evidence` with angle-bracketed exception names trips
  `worker_gate.py` rule `notes-placeholder`. Paraphrase failure output without
  angle brackets in the gated sections.
- An open participant row is not proof of a current staff role. Re-check active
  membership on every command and list, not only when a conversation is opened;
  a single revoked-role test can cover every path.
- A controller mocked in one test and a real service called in another is not
  reachability. Drive one request through the controller, service and store
  into real PostgreSQL and assert a durable row.
- When adding a boolean collaborator check to a guarded method, add a
  default-allow stub in the test setup and override it per negative test; that
  keeps existing tests valid and makes the deny case explicit.
- In a cloud worker, confirm `git ls-files -v opencode.json` before treating a
  check-pack or worker-check staleness failure as a change defect, and leave the
  full `mvn verify` and all-integration run to the integrator.
