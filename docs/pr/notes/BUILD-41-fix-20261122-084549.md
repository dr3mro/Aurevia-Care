## Lessons for workers

- When reasoning about interruption safety, test both orderings of the two durable side effects. The earlier fix covered "object removed, row still COMPLETE"; the realistic and missed case was "row EXPIRED, object still present", which orphaned the object. Ask what a retry actually observes from the database, not what the happy path assumes.
- A comment that says a retry "can still finish the transition" while the code throws a conflict on the retry is a defect signal — verify comments against the actual branch conditions.
- Derive lifecycle predicates from the schema's real state set. With only COMPLETE and EXPIRED allowed, a failed `UPDATE ... WHERE status='COMPLETE'` means EXPIRED, not an arbitrary concurrent state.
- When a change alters a shared function's contract (`worker_gate.main()` now needs an explicit report directory), update every existing caller and unit test in the same commit; mocking `Path.is_dir` is not a substitute for a real directory once the function globs it.
- A test that passes only because a prior command created a build artifact (`apps/api/target/surefire-reports`) is not hermetic. Give it a `TemporaryDirectory` with a parseable `TEST-*.xml`.
- Before re-running a fix, inspect `git log origin/main..HEAD`; earlier workers may already have applied it, and the correct job may be independent verification plus a fresh notes file — but still take a fresh independent review seriously, since it can find a real gap earlier passes missed.
- Distinguish a pre-existing failure on `main` from a branch defect; a failure that reproduces on clean `origin/main` belongs to its owning change.
- Respect protected paths: a worker PR touching `scripts/`, `.opencode/`, `.github/`, `opencode.json` or a tracker is never auto-merged, `worker_gate.validate_candidate` flags it, and `scope_ok()` rejects protected paths in `task-requests`.
- In this cloud worker `opencode.json` is a skip-worktree CI profile. Never regenerate or commit it; verify HEAD truth with `git show HEAD:opencode.json`.
- Do not trust a prior pass's "Maven Central 429" note as permanent: this pass the same targeted Maven command succeeded.
