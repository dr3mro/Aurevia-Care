2. **The empty fix dispatch is the only anomaly.** No `FIX_COMMENT`, no `FINDINGS` block and
   no story title/body were supplied between the story markers. The story was reconstructed
   from `tasks/00094000-BUILD-63.md` (its stated details) and section 9 gate G3 / section 6.1

   `scripts/gen-opencode.py` produced an `opencode.json` **byte-identical** to
   `git show HEAD:opencode.json` (`cmp` → identical). This is BUGS OPS-CW-003-01, closed as a
   false positive in MEMORY.md. No config file was edited (workers must not touch it).
4. These are domain-service acceptance tests with mocked/in-memory ports, not
   HTTP-plus-PostgreSQL tests. HTTP/controller tests already exist on main for the same flows
   (`ReleasedReportControllerHttpTest`, `PatientReleasedRevisionsControllerHttpTest`,
   `PatientAppointmentControllerHttpTest`, `ConversationHttpSecurityTest`,
   `AttachmentControllerHttpTest`, `InstructionFactControllerTest`,
   `GateEvidenceControllerHttpTest`); the integrator runs that tier. Adding HTTP tests would
   require files outside the declared `acceptance/patient` scope, so none were added.
5. Mobile-platform coverage ("instructions and attachments on both mobile platforms" in the
   G3 gate text) is outside this task's API-test scope; no patient-mobile file was touched,
   so no `apps/patient-mobile/check.sh` run was required for this change.
6. **Pre-existing red on the branch base, out of scope:** on the clean branch (without main
   merged), `python3 -I scripts/check-docs.py` exits 1 with
   `docs/reference/partner-api-guide.md:200: table row has 4 cells, expected 3` — an unescaped
   `status=open|resolved` pipe in a table cell. `origin/main` commit `280dbd17`

   passed in the clean trial merge of main. The integrator merges main before its gate, so this
   is not attributable to this change and the docs file is outside the declared scope.

## Lessons for workers

- On a fix pass with an empty story marker, derive the task from `tasks/<id>.md` and the spec
  gate instead of guessing a defect; verify first and only change code when a real failure is
  reproduced.
- The worker `opencode.json` check is a known CI-profile-under-skip-worktree artifact. Confirm
  with an isolated generator run compared to `git show HEAD:opencode.json`; never regenerate
  or commit it from a worker.
- A clean trial merge (`git merge --no-commit --no-ff origin/main`) is a cheap way to reproduce
  an integrator "merged but checks failed" dispatch before changing any file; abort it so main
  content is not accidentally committed into a scoped task branch.
- All 2394 fast unit tests pass together, so the acceptance tests do not leak `TenantContext`
  into other suites; keep the `AfterEach` `TenantContext.clear()` in each class.
