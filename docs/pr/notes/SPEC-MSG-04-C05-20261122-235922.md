## Findings

- The brief's "fixed UTC clock" reuse is not possible from the `.clauses` package because the 3-arg
  `InstructionService` constructor is package-private in `messaging.instructions`; the public 2-arg
  constructor is used instead and no assertion depends on time.
- The context-optimizer confirmed no other file implements, configures or constrains this clause:
  no migration policy, no OpenAPI security scheme, no `CommandCatalog` command, no web role rule.
  "Configured" is the `clinician` key in `InstructionActions:39` evaluated against fresh active
  membership, plus the tenant-approved template's `clinical` flag.
- Pre-existing conflict markers are committed in unrelated `apps/api/src/main/java/com/aurevia/exchange/hl7/*.java`
  files (inside Javadoc comments). They predate this change and are outside scope; they were left untouched.
- The instruction routes are listed in `contracts/openapi/missing-routes.txt` (pre-existing contract
  gap tracked elsewhere); this test-only task does not touch the contract.
- Evidence provenance: all commands above were executed with tools; reviewer verdicts are simulated
  static reviews; no human, clinical or real-patient evidence was used.

## Lessons for workers

- A "configured authorization" clause may be hard-coded in an injected action matrix rather than an
  external config file: prove it by injecting a test-only matrix override, not by inventing a config gap.
- When a denial has several distinct 403 messages, assert the exact message as well as status and code;
  a generic 403 from a later guard does not prove the intended gate. To reach the intended guard, keep
  the subject unit-assigned with an active connection and an active non-sender role.
- For "no persisted effect", assert store-level revision/history/fact state before any legitimate
  mutating follow-up; `listForPatient` reports current revisions (so it stays at 1 after a successful
  replace) and throws 403 once the checking subject loses membership.
