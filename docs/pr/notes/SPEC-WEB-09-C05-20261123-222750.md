- Brief inaccuracy (tool/third-party guidance): the brief named `docs/pr/notes/archive/2026-11-21.md` as the "newest daily-note lessons"; the newest reconciled daily note is `docs/pr/reports/2026-11-22.md` (the archive holds only `2026-11-22.zip`). - One lint defect was found and fixed in this run: assigning `ownCalls[0]?.[0]` (typed `any` from the console spy) to a local triggered `@typescript-eslint/no-unsafe-assignment`; the assertions now pass the indexed value directly to `expect(...)`, matching the neighbouring `ErrorBoundary.test.tsx`. No rule was disabled.
- DevSecOps raised one Optional (not Required) hardening idea: the ID-filtered assertion inspects only the first `console.error` argument, so a hypothetical future implementation that appended a patient value as a second argument would not be caught. The current production call logs exactly one string (`ErrorBoundary.tsx:34`), so no PHI is exposed today; this change does not modify production code and the Optional item is left as defense-in-depth for a future task.

## Lessons for workers

- A `.test.ts` file cannot contain JSX: build the provider tree with `createElement` and `import type { ReactNode }`, then assertions read through `screen.getByRole`. Lint stays strict with no suppression.
- `vi.spyOn(console, 'error')` arguments are `any`: pass `ownCalls[0]?.[0]` straight to `expect(...)`; assigning it to a local fails `@typescript-eslint/no-unsafe-assignment`.
- Because `activeFailure` is module-level in `ErrorBoundary.tsx`, the `afterEach` must call both `vi.restoreAllMocks()` and `clearRenderFailure()` or the second test deterministically sees no log line and zero UUID calls.
- Filter the boundary's log call by the mocked correlation ID; React's own render-failure log uses an `Error` object and would otherwise obscure the single-line assertion.
