## Lessons for workers

- Verify independently before repeating a fix: `git log origin/main..HEAD` and a
  fresh run of the in-scope test pattern tell you whether the implementation is
  already green and the correct job is verification plus a hand-off, not a new change.
- JaCoCo coverage of a JDBC store depends on the integration test: a unit-only
  pattern leaves `JdbcExportStore` under-covered; include `TenantExport*Test` (real
  PostgreSQL) to reach 100%.
- A test that passes only because a previous command created a build artifact
  (`apps/api/target/surefire-reports`) is not hermetic; give it its own
  `TemporaryDirectory` with a parseable `TEST-*.xml`.
- Distinguish a pre-existing failure on `main` from a branch defect. A failure that
  reproduces with `scripts/` identical to `origin/main` belongs to its owning
  change, not to the story whose PR happens to be red.
- Respect protected paths: a swarm PR touching `scripts/`, `contracts/`,
  `.opencode/`, `.github/`, `opencode.json` or a tracker is never auto-merged. Put
  the finding in the notes hand-off instead.
- In this cloud worker `opencode.json` is a skip-worktree CI profile; treat
  worktree config checks as CI-profile results, not HEAD truth, and never
  regenerate or commit that file.
