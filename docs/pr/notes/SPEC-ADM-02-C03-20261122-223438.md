## Findings

- The clause is implemented in `com.aurevia.tenant.export`, not in
  `com.aurevia.configuration`; the test was placed in `configuration/clauses`
  to match the task scope while importing the real export domain classes.
- The test binds explicit scope, policy version, bounded retention expiry and the
  TENANT_EXPORT audit facts at the service and HTTP entry points; refusal negatives assert
  403/404/409/410 and the EXPORT_DENIED / EXPORT_EXPIRE facts. The store, permission guard

  forced-RLS invisibility is proven by the existing TenantExportIntegrationTest, and the
  clause doc states that limitation rather than overclaiming.
- OpenAPI publication for the three real export routes is pre-existing tracked debt
  (`contracts/openapi/missing-routes.txt` lines 116, 333, 334); recorded in the clause doc
  Gap, not edited here. No new production defect was found.

## Lessons for workers

- The notes-placeholder gate matches any angle-bracketed token in the Test evidence or
  Coverage section, including assertion diffs such as "expected 200 but was 403".
  Write assertion values without angle brackets in those sections.
- For an evidence-only clause story where production already exists, a fault-injection
  probe (temporarily break one assertion, observe the failure, restore, confirm
  byte-identity) proves the new test can fail without a production change.
- A stubbed `store.find` returning empty simulates an RLS-filtered lookup but does not
  prove database RLS; cite the integration test that exercises real forced RLS and keep
  the unit test's claim to service-level fail-closed behavior.
- The worktree `opencode.json` under `skip-worktree` makes `check-pack`,
  `worker-check.sh` and six `test_check_pack` Python tests red in a cloud worker; confirm
  with `git ls-files -v` and never regenerate or commit that generated file.
