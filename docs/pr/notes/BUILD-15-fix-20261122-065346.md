## Lessons for workers

- When two workers implement the same story, survey `main` and all prior notes before reimplementing: keep the feature/acceptance that already landed, contribute only the missing slice (here the HTTP entry-point test), and on conflict adopt the base file when it already carries equivalent coverage.
- A clean branch plus green local checks is not proof that CI is green. Confirm the recurring bounce is a real gate failure before spending another pass on no-op verification; check the PR's gate-triggering labels/title or read the exact failing run.
- In cloud workers `opencode.json` is skip-worktree (`S`) holding the CI profile. Before treating `check-pack.py` / `gen-opencode.py --check` "stale" failures as yours, compare `git show HEAD:opencode.json` with the generator's local profile; CI checks out HEAD and is unaffected.

- Do not run `scripts/check.sh`, `scripts/coverage-check.sh` (full `mvn verify`) or `scripts/docs.sh` as a worker; they invoke the full DB/static-analysis/documentation gate reserved for the integrator/Delivery.
