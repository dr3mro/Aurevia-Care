# READY-31 — Operations: `/operations/queues` for the operational queues

## Summary

This worker run verified the already-delivered `features/operations` staff-web feature (ADM-02 / OPS-05) and found it complete, fully covered and already merged to `main`. No in-scope code change was necessary; the branch is `0/0` with `origin/main` and the feature commits (`3fc6627`, `9327c91`, `38bb4e0`, merge `520afc5`) are present in `origin/main`.

The feature loads the five real list endpoints in parallel with per-queue failure isolation, renders one tab per queue with a row count, a computed oldest age from server instants, an accessible keyed table, and only the row actions the connected API exposes (`assign`, `retry`, `escalate`, `review`). Every action requires a reason, is sent once through the typed transport with no automatic retry, and a failed send surfaces the shared error state. `OperatorHome` exposes the role-aware home content (one count-bearing link per queue) for the shell to mount. Routes are self-registered in `features/operations/routes.ts` only.

This run's contribution is durable verification evidence and the acceptance/decision record below. All evidence is from **executed tool commands** in this run; one earlier bounded Senior React advisory review is described in the prior note (`docs/pr/notes/READY-31-20261121-073536.md`) and its findings were already applied. No simulated-user, clinician or human-participant evidence is claimed.

## Findings

- **Already delivered and merged.** The feature's commits are in `origin/main`; this branch is `0/0` with `origin/main` before this notes commit. This worker run made no code change because nothing in scope needed correction — the feature's own gates are green.
- **Global `check.sh` red is out of scope.** The two failing tests (`src/app/routes.test.tsx`, `tests/app/AppShell.test.tsx`) hard-code the exact route list and are owned by `FIX-ROUTES-01` (agent swarm-1), whose scope is exactly those two files. They now expect 20 patterns while features have registered 27. Per the swarm scope rule and READY-51 ("Do not edit `app/routes.tsx` or `app/navigation.ts`"), this worker did not touch them. The previous note recorded an expectation-only update to those files; that update is not present in the current tree, so `FIX-ROUTES-01`'s generic fix is the correct owner.
- **`OperatorHome` is exported but not mounted.** `/` is reserved by `app/routes.tsx:RESERVED_PATTERNS` and `app/WelcomePage.tsx` is outside this scope, so the operator home content cannot be wired here. A follow-up owning `app/WelcomePage.tsx` should render `<OperatorHome />` for `useRole() === 'operator'`; until then requirement 3 exists as a tested component but is not reachable from `/`.
- **No cursor paging.** None of the five list endpoints (`/exchange/work-items`, `/delivery/dead-letters`, `/instructions/overdue-follow-ups`, `/duplicate-reviews`, `/clinic/worklist`) offers a cursor (the clinic worklist has only `limit`), so the "if the API offers it" clause is not exercised.
- **No timestamp for duplicate reviews.** `DuplicatePairWire` carries no server instant, so that tab shows "Not available from this endpoint" rather than inventing an age; every other tab computes age from its server instant with an injected clock.
- **Action labels vs endpoint names.** `escalate` maps to the clinic worklist handoff; `review` covers verify-patient, dead-letter review, follow-up resolve and duplicate-ticket opening; `retry` on a dead letter reuses the review endpoint with the `requeued` resolution (the only reason-recording requeue command). No chart consolidation is offered from this screen because it needs a ticket id and independent identifier confirmation.
- **Open accessibility follow-up (disclosed in the earlier review).** The reason dialog is labelled, keyboard reachable and has an explicit Cancel control, but lacks a native `<dialog>` focus trap / Escape / focus restore; tabs are buttons with `aria-pressed` in a labelled group rather than a full `tablist`. These need a shared-component change outside this scope.

## Lessons for workers

- Confirm the branch/commit state before re-implementing a re-dispatched story: `git log --oneline -- <scope>` and `git rev-list --count HEAD..origin/main` showed this story was already delivered and merged, so code changes would have been redundant and risky.
- A scoped 100% proof is `npx vitest run --coverage --coverage.include='src/features/<name>/**' src/features/<name>`; a global `check.sh` can be red for unrelated hard-coded tests owned by another task — attribute the failure precisely instead of editing out-of-scope files.
- With per-file 100% function coverage, every inline JSX arrow callback (tab click, row action, input `onChange`) must be exercised by a test; delete unreachable guards rather than writing a test that only touches a line.
- Read the Java controller, request record and enum/parser for every command before claiming an action works: 100% coverage of a mocked `send` proves the UI's own values, not server acceptance of the wire keys.
- Never invent an `If-Match`/revision value to satisfy a guarded endpoint; carry the server's version in the projection or omit the action. A composite list-row id is not a ticket id for a separate command.
