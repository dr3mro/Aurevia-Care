## Findings

- Root cause of the remaining red check (confidence high, tool evidence): `8f363e02`
  changed `worker_gate.main()` from `failing = failing_classes(REPORTS)` to
  `reports = Path(args[1]) ...; usable = reports.is_dir() and usable_reports(reports)`.
  `usable_reports()` calls `Path(reports_dir).glob(...)` without checking existence.
  Two tests that mock only `Path.is_dir -> True` and call `main(["1"])` without a
  second argument still take that path and now raise `FileNotFoundError`. The commit
  modified `scripts/worker_gate.py` but did not update these two test call sites, so
  the regression is pre-existing on `origin/main` and unrelated to BUILD-41.
- Bounded fix plan (from the step-5 debugger report, treated as notes, to be applied
  by the owning worker): in `scripts/tests/test_worker_gate.py`
  (`test_integration_failure_still_fails_the_gate`, around lines 328-336) create a
  `tempfile.TemporaryDirectory()`, write one parseable
  `TEST-FooTest.xml` (`<testsuite failures="1" errors="0"></testsuite>`) into it, and
  call `worker_gate.main(["1", reports_dir])`; drop the `Path.is_dir` mock, keep the
  `failing_classes` mock returning `{"RxTransmissionFlowTest"}` and the `== 1`
  assertion. Do the same in `scripts/tests/test_worker_gate_coverage.py`
  (`test_maven_failure_with_failing_reports_still_fails`, around lines 552-555),
  reusing its existing `write_report` / `suite_xml` helpers (lines 56-65); extend

## Lessons for workers

- When a change alters the contract of a shared function (`worker_gate.main()` now
  needs an explicit fresh report directory), update *all* existing callers and unit
  tests in the same commit; mocking `Path.is_dir` is not a substitute for a real
  directory once the function globs it.
- Before re-running a fix, inspect `git log origin/main..HEAD`: earlier workers may
  already have applied it, and the correct job is independent verification plus a
  fresh notes file.
- Distinguish a pre-existing failure on `main` from a branch defect. A failure that
  reproduces on a clean `origin/main` belongs to its owning change, not to the story
  whose PR happens to be red.
- Respect protected paths: a swarm worker PR touching `scripts/`, `.opencode/`,
  `.github/`, `opencode.json` or a tracker is never auto-merged. Put the finding in
  the notes hand-off instead of editing the file, and note that `scope_ok()` also
  rejects protected paths in `task-requests`.
- In this cloud worker `opencode.json` is a skip-worktree CI profile: `git ls-files -v`
  shows `S`, the worktree file equals `.github/opencode.ci.json`, and six
  `test_check_pack` cases report a false staleness. `gen-opencode.py --check` (HEAD
  bytes) exits 0; never regenerate or commit that file.
