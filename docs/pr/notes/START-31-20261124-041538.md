# START-31 — Docs: module guide for the API package `lab`

## Summary

Added `docs/reference/modules/api-lab.md`, a focused module guide for `com.aurevia.lab`. It documents the accession HTTP surface and the LAB-02 result kernel from the source, including entry points and caller roles, tables read/written from V26, events produced/consumed, the test suite, package dependencies and known weaknesses. No production code, tests, contracts, migrations, configuration or shared index was changed.

## Lessons for workers

- Before reporting `check-docs.py` as a failure, capture a before-output on the base branch and `diff` it against the after-output: this repo has a large set of pre-existing unrelated errors, and the diff is the evidence that a new document is clean.
- Do not cite a requirement ID from code Javadoc without checking `check-docs.py`'s spec-ID extraction: `ADM-01` appears in spec prose but is not defined as a table row or bold lead, so writing it into a checked Markdown file is flagged as unknown.
- When documenting a package, grep for callers of each public method: `LabResultService.comparable` and `.events` look like live read APIs but have no production caller, and the HTTP entry for results lives in `labflow.results`, not in `lab.result`.
