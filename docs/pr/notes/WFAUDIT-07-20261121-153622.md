## Findings

- **Genuine pre-existing defect: `docs/swarm/BUILD-53.md:129` has an unclosed code fence.**
  The merge record stores a clipped worker log whose last ```` ``` ```` is never closed
  (file ends at line 137). A strict repo-wide fence rule would fail every commit and every
  reconciler rules PR. `docs/swarm/` files are immutable merge records written by
  `swarm.py:record_merge` from clipped PR bodies; `swarm.py:referenced_notes` already calls
  them "merge records". To keep the repository green without editing out-of-scope tracked
  history, the structural rules skip `docs/swarm/` via `RECORD_PREFIXES` (links and
  requirement IDs are still checked there). A maintainer should fix the bad record (or
  re-clip it) in a separate task and then remove the skip. Evidence: file read + executed
  analysis script (tool).
- **Five worker notes have pre-existing ragged tables:** `.agent/pr-notes/AUD-20261120-07.md`
  (lines 14, 15, 28), `S-G3-08.md:15`, `READY-12.md:17`,
  `READY-47-fix-20261120-234708.md:137`, `READY-47-20261120-210202.md:101`. They are why the
  structural rules are applied only to the existing `markdown_files()` set (which already
  excludes `.agent/` and `docs/archive/`), not to note files. Evidence: executed analysis
  script (tool).
- **`opencode.json` drift is a cloud-worker artifact, not a change defect.** `git ls-files
  -v opencode.json` reports `S` (skip-worktree); the worktree file is the CI profile copied
  by `agent-run.sh`, while `git show HEAD:opencode.json` equals `gen.render(ROOT)`. So
  `check-pack.py` and the 3 `test_check_pack.py` tests fail here but pass with the committed
  profile. Out of scope and untouched by this worker. Evidence: executed git and Python
  comparison (tool).
- The token pattern needs a `(?<![A-Za-z0-9])` word-boundary guard: a naive
  `sk-[A-Za-z0-9_-]{20,}` matches the ordinary word "risk-transitions" in TODO.md story
  scope strings. The guard prevents that false positive. Evidence: executed analysis (tool).

## Lessons for workers

- Before adding a repo-wide Markdown rule, run a scratch analysis over all `*.md` files:
  escaped pipes (`\|`) and headings inside fenced example blocks are the two classic false
  positives, and "risk-" matches naive `sk-` token patterns.
- Generated merge records under `docs/swarm/` are immutable history with clipped logs; a
  strict structural rule there turns every commit red. Scope structural validation to
  living docs and skip record directories, and report the bad record instead.
- Never apply new Markdown rules to the daily-note/archive files unless their existing
  tables and fences are first made clean — several pre-existing notes are ragged.
- No Python coverage tool is installed in this environment; use `python3 -I -m trace
  --count --coverdir=... --missing <runner.py>` for line coverage and map branches to
  tests in the notes, because `scripts/coverage-check.sh` does not cover Python.
