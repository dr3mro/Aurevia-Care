# RESP-ORGSWITCH — Staff web: responsive organization switcher

## Summary

Made the existing `OrgSwitcher` responsive without changing behaviour, text,
API calls or exported names. The native select now uses the existing
`responsive.css` utilities (`page`, `grid-2`, `field`, `touch`) and the
`useBreakpoint` hook: one DOM and one accessibility tree at every width, fields
stacked on phones and side by side from 768 px, a full-width 16 px select with
44 px coarse-pointer targets, logical safe-area padding, and a wrapping
`aria-live` confirmation that preserves the explicit switch acknowledgement
(IAM-01). Added a new jsdom test covering the three breakpoint states, the seven
named widths, keyboard order, long EN/AR strings and RTL.

Scope respected: only `apps/staff-web/src/app/OrgSwitcher.tsx` and the new
`apps/staff-web/tests/app/OrgSwitcher.responsive.test.tsx`. No dependency,
stylesheet, migration or tracker was changed. Synthetic fixtures only. No push,
tag or `gh` call was made.

## Affected requirements

- WEB-07, UX-01 (task requirements). IAM-01 is preserved, not changed: the
  `aria-live="polite"` `<output>` remains the explicit switch confirmation.
- Requirement-to-acceptance mapping:
  - 320/360/390/768/820/1024/1280 px, LTR and RTL → `data-breakpoint` +
    `data-org-switcher-view` from `useBreakpoint`; viewport-matrix test (7 widths)
    and `describe.each` over compact/medium/expanded.
  - Columns stack on phones → `.grid-2` (one column < 768 px, two columns ≥ 768 px).
  - Full-width select on phones → `.field` (`inline-size: 100%`); test asserts
    `full-width-select` on compact.
  - 16 px input text → `.field` (`font-size: 16px`); stylesheet contract already
    proven in `tests/theme/responsiveStylesheet.test.ts`, class attachment proven here.
  - 44 × 44 coarse pointers → `.touch` (44 px under `@media (pointer: coarse)`);
    test asserts the class and that no inline size overrides it.
  - Safe-area insets → `.page` logical `max(env(...), space)` padding.
  - Logical properties only / no `display:none` hiding → all inline styles are
    logical (`color`, `overflowWrap`); test scans physical keys and hide classes.
  - Long EN/AR strings wrap → `.grid-2 > *` rule for fields; logical inline
    `overflow-wrap: anywhere` for the `<output>` (missing class, see Findings).
  - Keyboard order → `label → select → output` DOM order, `tabIndex 0`, focus test.
  - Explicit switch confirmation → `output[aria-live=polite]`, change updates text.
  - Painted pixels, real 44 px boxes, 200 %/400 % zoom, real safe areas → left to
    the Playwright tasks (jsdom cannot lay out); documented, not claimed.

## Findings

1. Pre-existing defect outside this task's scope (flagged, not touched): three
   committed files under `apps/api/src/main/java/com/aurevia/exchange/hl7/`
   (`Hl7ParseException.java`, `Hl7Parser.java`, `Hl7Segment.java`) contain literal
   `<<<<<<< HEAD` / `>>>>>>> origin/swarm/BUILD-37-469` markers in HEAD
   (verified with `git show HEAD:…` and `git grep -lE '^(<<<<<<<|>>>>>>>) '` →
   3 files). They were present before this story, are outside the granted scope
   and will break Java compilation. The integrator/owner should resolve them;
   this worker did not edit them.
2. `responsive.css` wraps children of `.grid-2`, `.stack`, `.cluster`,
   `.card-list` and `.app-shell` but not `.page > *`; an unbroken long token in
   the confirmation would not wrap. Fixed with a logical inline
   `overflowWrap: 'anywhere'` on the `<output>`, asserted in the new test.
3. `I18nProvider` sets `document.documentElement.dir/lang` from its locale on
   mount; manually setting `document.dir` in a test is overwritten. The RTL case
   therefore renders with `<I18nProvider initialLocale="ar">` and asserts
   `dir="rtl"`, `lang="ar"` and the Arabic label `المؤسسة`.
4. A closed native `<select>` does not wrap its displayed value, so at 320 px an
   extremely long selected name could still be visually clipped even though the
   jsdom class/structure checks pass. The story's alternative bottom-sheet
   variant (`.sheet`, `data-org-switcher-view="bottom-sheet"`) would change the
   accepted structure and existing test expectations, so the full-width select
   was kept. Painted clipping is left to the Playwright responsive tasks.
5. Specialist finding (senior-react, read-only): `.page` caps at 1200 px and
   double-pads inside `AppShell`'s already-padded `<header>` on desktop. It is
   the only class supplying safe-area insets, so it was kept; visual review is a
   Playwright task, not an acceptance failure here.
6. `scripts/check.sh` and `scripts/python-coverage.sh` are red at HEAD for the
   skip-worktree `opencode.json` reason documented in Test evidence (single
   `check-pack` failure; five `test_check_pack` failures). Pre-existing and
   unrelated to this story; not fixed here because `opencode.json` is protected
   and outside scope.

## Lessons for workers

- `responsive.css` has no `.clinical-value` class (design doc §12 names one) and
  no `.page > *` wrapping rule. For a value rendered as a direct child of
  `.page`, use a logical inline `overflowWrap: 'anywhere'` rather than editing
  the stylesheet, and record the missing class here (story step 3).
- To test RTL in a component wrapped by `I18nProvider`, pass
  `initialLocale="ar"`; do not set `document.documentElement.dir` by hand, the
  provider's effect overwrites it and the label stays English.
- `git grep -nE '^(<<<<<<<|>>>>>>>) '` can surface conflict markers committed by
  other workers, even when `git merge` reports "Already up to date". Check
  whether they are in HEAD before attributing them to the current merge, and
  flag out-of-scope ones instead of editing them.
- Lock the touch contract in tests by asserting `style.minBlockSize` and
  `style.minInlineSize` are empty, so an inline size cannot silently outrank the
  `.touch` 44 px coarse-pointer rule (same pattern as `Button.responsive.test.tsx`).
