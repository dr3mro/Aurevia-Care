## Lessons for workers

- When a slice adds controller routes, publish them in `contracts/openapi.yaml` in the same change and regenerate the client; adding them to `missing-routes.txt` hides rather than fixes the gap.
- A GET that returns a JSON array must use a named array schema whose name does not end in `Page` (for example `PendingStaffAttachments`); an inline array or a `*Page` name fails the pagination rules.
- Route-parity green is not enough: read the service for the real reachable 409/422 statuses and the controller for the real response media types before declaring a contract entry truthful. A raw `@PathVariable String id` still emits a 422 for a malformed segment via the key validator — declare and assert it.
- Run the **whole** contract test family, not just the parity/rules/pagination trio: `OpenApiErrorRulesTest` also validates the committed contract and is cheap to include.
- In cloud workers, a `check-pack: opencode.json is stale` result usually means the CI profile is active under skip-worktree. Compare `git show HEAD:opencode.json` with the worktree file before treating it as a real failure; never edit that protected file to make the gate pass.
- Missing `node_modules` in a fresh runner is restored with `npm ci` from the committed lockfiles; it changes no tracked file and is required before `gen:api:check` or either module `check.sh` can run.
