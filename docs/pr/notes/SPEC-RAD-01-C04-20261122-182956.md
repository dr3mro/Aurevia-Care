# SPEC-RAD-01-C04 — Link addenda and critical communications (API evidence)

## Summary

Test-only story for RAD-01 clause 4 ("Link addenda and critical communications."). Added a focused
service-layer test class proving that an addendum links as a new revision superseding the prior
signed interpretation without rewriting it, and that a critical communication keeps its finding and
its confirmed read-back as two separate SHA-256-digested facts. Added the clause status document.
The clause behaviour is already fully implemented in the domain kernel; no production code,
existing test, contract, migration, script or tracker was changed.

## Findings

- The plan review caught one wrong assertion: `REFERRER_NOTIFIED` is emitted with a **null**
  `payloadDigest` (`ImagingService.notifyReferrer`, line 486-488); only `ADDENDUM_LINKED` carries
  `addendum.checksum()` (line 375). The test now asserts that split explicitly.
- RAD-01 clause 4 behaviour is fully implemented in the kernel but has no HTTP route, JDBC store,
  migration or OpenAPI entry. This is a service-layer proof only; the status doc records this under
  `## Gap` and points to the existing `AUD-20261121-05`. A `@Disabled` HTTP GAP test was deliberately
  **not** added: `scripts/check-constraints.py` rejects any added `@Disabled` in Java and the four
  existing GAP tests are grandfathered. No `task-requests` block is needed.
- `AUD-20261121-23` is a `WorklistService` (RADFLOW) follow-up, not an imaging follow-up, so it is
  not cited in the doc.
- The Python tooling suite's six `test_check_pack` failures and `python-coverage.sh` failure are the
  documented `opencode.json` cloud false positive, not caused by this change.
- `ImagingService.mayRecordCritical` 403 branch is already covered by the pre-existing
  `ImagingServiceTest.criticalCommunicationRequiresAssociationAndReadBack` (wrong-role
  `finance`/`NO_ROLE` actor); this focused clause class need not duplicate it.
- Optional code-review note: `addendaLinkAsNewRevisionsWithoutEditingTheSignedReport` asserts the
  full 8-event stream and uses absolute indices 6/7. This matches the neighbouring
  `ImagingServiceTest` convention; to make it independent of unrelated setup events a later pass
  could snapshot events before `addAddendum` and assert the two new ones relatively, as
  `criticalCommunicationKeepsFindingAndReadBackAsSeparateDigestedFacts` already does. Not changed
  here to keep the clause proof aligned with the existing fixture style.
- Pre-existing, unrelated to this change: committed conflict markers (`<<<<<<<`/`>>>>>>>`) exist in
  `apps/api/src/main/java/com/aurevia/exchange/hl7/{Hl7ParseException,Hl7Parser,Hl7Segment}.java`
  in both HEAD and origin/main (from `origin/swarm/BUILD-37-469`). `git merge --no-edit origin/main`
  reported "Already up to date"; these files are outside this task's scope and were left untouched.

## Lessons for workers

- `scripts/check-constraints.py` rejects any **added** `@Disabled` in Java. The `@Disabled("GAP: ...")`
  pattern in older clause tests predates that check. For a test-only clause story, prove the
  behaviour at the layer where it exists and record the reachability debt in the status doc instead
  of adding a skip.
- `ADDENDUM_LINKED` carries the addendum checksum; `REFERRER_NOTIFIED` carries a null digest. Assert
  the split rather than assuming the notification repeats the checksum.
- Before reporting `opencode.json is stale`, confirm with `git ls-files -v` (`S`), compare the
  worktree file with `git show HEAD:opencode.json`, and check that the committed file equals
  `gen_opencode.render(ROOT)`; do not regenerate or edit that protected file in a worker.
