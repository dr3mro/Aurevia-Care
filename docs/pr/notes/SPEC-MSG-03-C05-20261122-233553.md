## Findings

1. The MSG-03 clause is built and enforced in `messaging.attachments`: `AttachmentController.download`
   → `AttachmentService.download` → `AttachmentState.downloadable()` (PUBLISHED only). The
   independent clean verdict is recorded by `AttachmentService.scan`; explicit publication by
   `AttachmentService.publish` requires `CLEAN` state and binds a message and recipient unit.
2. NEIGHBOUR SURVEY — enforcement vs recording: `staffmsg.attachments.StaffAttachmentService` and
   `documents.QuarantineService` enforce the same ordering in their own domains with different
   routes and codes; `AttachmentState`/`EventType` and `V82__attachment_store.sql` encode and
   protect the state but do not themselves gate download. None of these were changed.
3. SECURITY GAP DISCLOSED, NOT FIXED (integrator action requested): `AttachmentController.download`
   derives the actor's `patientId` from the requested attachment, so the service's `participant()`
   `WRONG_UNIT` denial is unreachable through the HTTP route. Any principal with a DOWNLOAD role
   in the tenant can obtain the mediated handle of any published file. Proven at service level by
   `AttachmentAcceptanceTest.deniesDownloadToWrongUnitWrongPatientAndNonDownloader`. Fix requires a
   production change in `AttachmentController.download` plus new HTTP negative tests — one
   implementation task and one test task. Swarm workers cannot edit `tasks/` or `BUGS.md`; the
   integrator should create a durable task/defect entry from this note.
4. Contract debt (already tracked): the three patient-file routes appear only in
   `contracts/openapi/missing-routes.txt`. No contract edit in this test-only task.
5. Brief accuracy: the advisor brief placed `visible`/`requireVersion` in `AttachmentContract` and
   pointed to controllers "under `web`"; both live in `AttachmentService` and
   `messaging/attachments/AttachmentController.java` respectively. The story and repository were
   followed, not the inaccurate path hints.
6. Environment artifact confirmed once: the cloud worker installs the CI `opencode.json` under
   `skip-worktree` (`S`), which made six `test_check_pack` tests fail. `git show HEAD:opencode.json`
   equals the generator's local render, so HEAD is correct. While confirming this, a bare
   `python3 -I scripts/gen-opencode.py` was run and rewrote the worktree config; it produced
   byte-identical content to HEAD (verified with `git hash-object` on both config files), so no
   tracked file differs. The suite then exited 0. No protected file was committed.
7. Evidence provenance: tool evidence (executed Maven, policy scripts and Python suite),
   simulated read-only specialist reviews, and no human, clinical or real-patient evidence.

## Lessons for workers

- Never run a generator or formatter "to inspect" its output: `gen-opencode.py` with no flag
  rewrites `opencode.json` and `.github/opencode.ci.json`. To compare, import the module and call
  `render()` in memory against `git show HEAD:<file>` instead.
- The cloud worker's skip-worktree CI `opencode.json` makes `test_check_pack` red. Confirm once
  with `git ls-files -v` and the HEAD render, record the failing command and final line, then
  re-run after the config matches HEAD; do not regenerate or commit protected files.
- When a controller derives an access actor from the requested resource instead of the
  authenticated principal, a service-level participant denial cannot be proved through that HTTP
  route. Document the limitation instead of adding a green-for-the-wrong-reason or disabled test.
- Prefer one focused test class with exact status + `$.code` assertions over a 200-only proof;
  assert the mediated handle fields and the append-only event so a weakened gate cannot pass.
