# SPEC-IAM-01-C05 — IAM-01 clause 5 API test: Users explicitly switch active organization

## Summary

Adds a focused, synthetic-data HTTP-level test proving IAM-01 clause 5 ("Users explicitly switch
active organization") and a clause evidence document. The clause is already implemented at the
request boundary; no production code, existing test, contract or migration was changed. New files
only:

- `apps/api/src/test/java/com/aurevia/authz/clauses/UsersExplicitlySwitchActiveOrganizationTest.java`
- `docs/spec/clauses/authz/users-explicitly-switch-active-organization.md`

Entry point to test trace: `GET /api/v1/probe` (probe controller) with `X-Active-Organization`
header → `TenantContextInterceptor.preHandle` → `ClaimsTenantResolver.resolve` → `TenantContext`
bound and echoed by the probe.

## Findings

Implementation found today for clause 5 (read-only survey, tool evidence):
- `apps/api/src/main/java/com/aurevia/web/TenantContextInterceptor.java` — binds the
  explicit `X-Active-Organization` selection on every `/api/v1/**` request; synthetic profile
  requires a UUID header, OIDC profile delegates to the resolver; clears context at completion.
- `apps/api/src/main/java/com/aurevia/web/ClaimsTenantResolver.java` — accepts the
  selection only if it is a well-formed UUID present in the verified token's `orgs` claim.
- `apps/api/src/main/java/com/aurevia/web/AuthenticatedPrincipal.java` — frozen set of
  selectable organizations.
- `apps/api/src/main/java/com/aurevia/tenant/TenantContext.java` — the bound request
  tenant.
- Contract: `X-Active-Organization` is declared as the `ActiveOrganization` parameter by
  `api/authorization/CommandClientGenerator.java`. No dedicated "switch" endpoint exists; the
  explicit selection is carried per request (a deliberate IAM-01 interpretation in `PROJECT.md`).
- Migrations: tenant/membership tables exist (V1 onward) but no migration implements switching; the
  clause is a request-boundary rule, not a persisted state change.

Status recorded in the clause document: **Proven by tests**, Gap **None**.

## Lessons for workers

The worktree `opencode.json` in a cloud worker is a skip-worktree CI profile and legitimately fails
`check-pack`/`gen-opencode --check` and three `test_check_pack` cases. Check `git ls-files -v
opencode.json` and compare `git show HEAD:opencode.json` with `gen.render(ROOT)` before treating it
as a regression; never regenerate or commit that protected file from a worker. A local shellcheck
newer than CI can flag pre-existing SC2015 notes in `scripts/`; run the remaining checks directly
with `set -e` rather than editing protected scripts.
