## Summary

Adds FHIR R4 mapping for imaging studies (RAD-01), retained documents (CLN-07) and medication requests (RX-01) in the existing stateless `exchange/fhir` package, following the BUILD-35 mapper pattern exactly. Three new mappers and four new boundary projections map Study Instance UID/accession/modality, checksum/revision/void state and drug code/dose/route/frequency/quantity/prescriber/destination in both directions. Study linking is an explicit separate operation: it returns a mismatch result carrying no study when patient or accession labels do not match the order. No new dependency and no new migration.

## Affected requirements

RAD-01, CLN-07, RX-01 (plus reuse of the BUILD-35 FHIR boundary in `exchange/fhir`).

## Risk class

Cross-boundary (interoperability wire shapes for imaging, documents and prescribing). No clinical decision, persistence or authorization change: these are pure stateless projections with no production caller, as in BUILD-35. Clinical acceptance for the underlying workflows remains a separate G5 gate.

## Review owner

Senior Integrations (FHIR R4 wire shape) and Senior Java Build and Test Tooling (coverage, Javadoc, wiring). The Delivery, Senior Integrations, Senior Backend and Test Engineer skills were loaded and applied. Two bounded read-only specialist reviews were dispatched; their disposition is recorded under `## Findings`. No human participant evidence was used.

## Data changes

None. No Flyway migration, table, column, backfill, lock or volume impact. The new classes are stateless and only read existing domain records (`ImagingOrder`, `DocumentAssoc`, `Draft`) or parse supplied JSON.

## Authorization boundaries and audit events

No new authorization boundary or audit event. Every import path rejects a resource without the required patient/order/document identifiers before a projection is built; no label is inferred from unrelated fields. The study-link mismatch result deliberately carries a `null` study so a caller cannot associate a study by ignoring the outcome. All fixtures use invented identifiers and contain no patient data or credentials.

## Migration and rollout considerations

None. The package remains additive with no production entry point; wiring the mappings into a partner exchange endpoint is a separate story (same scope decision recorded for BUILD-35). No rollout, rollback or forward-fix is required for stateless mapping classes.

## Findings

- Fixture bug caught by a failing test (tool, fixed): the first run of `wrongPatientStudyIsRefusedWithoutLinking` returned `linked=true` because `FhirFixtures.imagingOrder(patientId, accession)` passed the constant `PATIENT` instead of the `patientId` parameter to the order's third constructor argument. Fixed to pass the parameter; the test then passed. No production code was changed for this.
- Known environment artifact (tool, not caused by this change): `check-pack.py` false positive from the skip-worktree CI `opencode.json`, as in BUILD-35 and OPS-CW-003-01. No tracker or config file was edited.
- Known environment artifact (tool, not caused by this change): the full `scripts/tests` suite and `scripts/python-coverage.sh` have pre-existing failures recorded in the reconciled 2026-11-20 notes (pack-profile and `TODO.md` tracker rules). The Java-conventions subset was run in isolation and passed.
- Scope decision (not a defect): like BUILD-35, these mappers have no production caller. A controller/partner adapter and HTTP-level evidence belong to a later story and were not added because the task scope is only the two `exchange/fhir` paths.
- Simulated Senior Integrations review (read-only, static; reviewer ran no commands) returned three actionable findings, all fixed and re-verified with 100% coverage:
  - F1 (HIGH) `Quantity.value` was a JSON string. Fixed in `MedicationRequestMapper` by writing `BigDecimal` numbers via the `decimal(...)` parser; non-numeric domain values now raise a structured 422 (`INVALID_MEDICATION_REQUEST`) instead of an unchecked exception. `draftRoundTripsThroughMedicationRequest` asserts `isNumber()` on both value nodes, and two negative tests cover the parser.
  - F2 (MEDIUM) identifiers were read by array position, so a swapped/augmented partner array could exchange Study Instance UID and accession — the very label the RAD-01 safety check depends on. Fixed with `FhirSupport.identifierValue(resource, system, errorCode)`, used by `ImagingStudyMapper.fromFhir` and `DocumentReferenceMapper.fromFhir`. `identifiersAreMatchedBySystemNotPosition` and the three `FhirSupportTest.identifierValue*` tests cover the new branches.
  - F3 (MEDIUM) `StudyLinkResult` allowed an inconsistent outcome/study pair. Fixed with a compact constructor in the final record that rejects a link without a study or a mismatch with one (`INVALID_STUDY_LINK_RESULT`), covered by `linkResultRejectsAnInconsistentOutcome`. SpotBugs exit 0 confirmed no constructor-throw finding.
  - Minor findings dispositioned without change: lowercase modality and the shared synthetic code system are partner-profile concerns needing a real contract (same deferral as BUILD-35 F6/F7); `fromFhir` collapses DocumentReference `superseded`/`unknown` to `active` because the domain has only `active`/`voided`; malformed hex/base64 checksums raising `IllegalArgumentException` is a partner-contract conformance concern for the later adapter story; no production caller is the recorded BUILD-35 scope decision, not a regression in this story.

## Lessons for workers

- Normalize every nullable domain string to `""` in the `fromDomain` adapter with `Objects.toString(value, "")`, then assert `assertEquals(source, fromFhir(toFhir(source)))`; it is a strict, cheap round-trip check that also catches dropped fields.
- Assert the literal FHIR wire shape in addition to object equality (typed identifier `system`, `coding[0].code`, `meta.versionId`, `dosageInstruction[0].timing.code.coding[0].code`); a self-round trip cannot detect a non-conformant shape when both directions agree on the same wrong field.
- A `for` loop over extensions adds a JaCoCo branch, and each `if` inside it adds another. With two independent `if`s over two emitted extensions, all true/false sides are covered; an `if / else if` would leave the final false side uncovered without an extra unknown-extension test.
- When a record exposes a derived boolean such as `linked()` implemented as `field != null`, JaCoCo counts it as a branch: call it from both a positive and a negative test.
- Jackson 3 is used here (`tools.jackson.databind`), not `com.fasterxml.jackson.databind`; build with `FhirSupport.JSON.objectNode()/arrayNode()` and read with `asString()`/`asInt()`.
- A FHIR `CodeableConcept` is `{coding:[{system,code}]}` while `interpretation`/`dataAbsentReason` are arrays of `Coding`; confusing them silently empties round-trip fields.
- A worker's `check-pack.py` result is a CI-profile measurement artifact when `git ls-files -v opencode.json` shows `S`; do not "fix" `opencode.json` in response.
