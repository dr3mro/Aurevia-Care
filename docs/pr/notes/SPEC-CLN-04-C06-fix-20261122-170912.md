This pass fixes the only red Delivery check identified by the latest debugger report: a genuine
async race in `apps/staff-web/tests/responsive/features-admin/FacilitiesPage.responsive.test.tsx`.
The test awaited only the `<table>` and then read data-driven rows synchronously with `getBy*`.
`FacilitiesList` renders the table with an empty `<tbody>` as soon as the API resolves
(`ApiPage.tsx:83-87`), while `PageSink` appends the rows in a `useEffect` after commit
(`PageSink.tsx:16-19`). Under CI timing the synchronous row query can win that race, producing
"Unable to find role rowheader … MAIN" with an empty `<tbody>` (deterministic in 3/3 CI runs).
Six data-dependent assertions now use awaited `findBy*`, which polls until the effect-appended
rows exist and still times out (and fails) if they never do. All structural assertions and all
behavioral assertions are unchanged. This is a test-only, non-weakening race fix.

Only one file was changed in this pass. No production code, Java source, `scripts/`, workflow,
contract, migration, coverage threshold or exclusion was touched.

## Lessons for workers

- When a test awaits a structural element (`table`) but asserts data-driven content synchronously
  with `getBy*`, look for an effect that appends the data after commit; use `findBy*` for every
  data-dependent assertion. A locally green suite does not disprove a CI-only timing race.
- Keep the reproduction of a flake temporary and out of the committed tree: a deferred-promise /
  raw-DOM-poll probe can document the timing window, but the authoritative red→green signal is
  the CI verdict on the exact SHA.
- A cited CI URL must be checked for which workflow it actually is; a debugger run is not the
  failing Delivery run and its annotations may describe a different diagnostic command.
- Clause proof tasks scoped to `chart/clauses` are fully unit-style: reuse
  `InMemoryTemplateStore` + `TemplateActor.of(...)`; no PostgreSQL fixture is needed.
- `check-names.py` accepts the business-domain package `com.aurevia.chart.clauses`;
  `clauses` is a spec-evidence folder used across domains, not a task or gate ID.
