## Lessons for workers

- A "complete but `@Disabled`" clause proof will be rejected by `check-constraints.py` as an
  added suppression: the story's GAP-waiver rationale does not survive the gate. If the
  domain/service layer already implements the clause, prove it there through the real
  `@Autowired` service and real DB instead of disabling it for a missing HTTP route; document
  the unbuilt route as a follow-up gap. If no layer exists, delete the dead test rather than
  shipping a skip.
- Assert the premise of a survival claim: capture `placeHold`'s returned `LegalHold` and
  assert it is active on the right resource/tenant. Otherwise a no-op would keep the test
  green. Release the hold at test end so a single-test rerun does not collide on 409.
- When a test binds a thread-local `TenantContext`, clear it in `@AfterEach`; otherwise the
  next proof inherits an identity and tenant-isolation assertions can pass for the wrong reason.
- In a cloud worker, verify the `opencode.json` skip-worktree profile once with
  `git ls-files -v` and `git show HEAD:opencode.json`, then run the remaining `worker-check.sh`
  stages individually. Do not regenerate, commit or re-diagnose it on a later pass.
- JaCoCo instruments `src/main` only. A test-and-doc-only change adds no production counter,
  so there is no 100% percentage to report; say this plainly and leave the full `verify` to
  the integrator.
