## Findings

1. **Fixed this pass:** `swarm-integrator.yml` `resolve` `CONFLICTED` env read
   `needs.integrate.outputs.conflicted` after `integrate` was renamed to
   `validate` → the agent would get an empty conflict list. Now reads
   `needs.validate.outputs.conflicted`.
2. **Fixed this pass:** `resolve`'s `if` read `needs.publish.outputs.conflicted`;
   `publish` is skipped when no PR was accepted, so an all-conflicts batch would
   skip `resolve`. Now reads `validate`'s output; the dead forwarding output on
   `publish` was removed. A negative GitHub dispatch for this case is in the
   document.
3. Carried from the prior audit: the primary credential/candidate mixture is
   `swarm-integrator.yml` `integrate`, not the worker. The `fix-pr-gate.yml`
   validate/handoff pattern is the model to copy. The worker and fix-PR patches
   are workflow-only; the integrator patch is blocked on two new trusted
   `scripts/swarm.py` subcommands, so a person must not apply that hunk alone.
4. `run_gate`'s environment stripping is not a security boundary on its own
   (same-UID `/proc` read plus runner tokens outside the strip list). Job-level
   isolation is the control; stripping remains defence in depth.
5. Removing `NVD_API_KEY` from validation jobs leaves OWASP using the restored
   NVD cache (the documented fallback). A separate credentialed cache-refresh
   job that runs no candidate code is the recommended mitigation.
6. Tooling artifact (not a product defect): this cloud worker's skip-worktree CI
   profile makes `check-pack.py` and three `test_check_pack` tests report a
   stale `opencode.json`; HEAD's committed file is exactly the generator output
   and all 527 tests pass with it.

## Lessons for workers

- When reviewing a proposed workflow split, check the **consumers** of renamed
  job outputs. A rename that updates `needs`/`if` but leaves a `env:` value or a
  forwarded output pointing at the old job is a silent failure; grep the patched
  file for the old job name.
- A `publish`/`handoff` job guarded by `if: accepted != ''` must not be the
  source of a downstream output such as `conflicted`; a skipped job's outputs
  are empty. Read such outputs from the always-running validation job.
- Regenerate a proposed diff from scratch copies after every edit, then
  re-extract it from the finished Markdown and compare byte-for-byte before
  finishing. A hand-copied fenced block can drift.
- In a cloud worker, `git ls-files -v opencode.json` showing `S` means pack
  checks measure the CI profile, not HEAD truth. Prove HEAD with
  `git show HEAD:opencode.json` against `gen-opencode.py` output before treating
  a "stale" finding as real, and restore the worker profile byte-for-byte.
- `scripts/check.sh` runs full `mvn verify` and all integration suites; a worker
  must not run it. Run the applicable policy gates individually instead and
  leave the full gate to the integrator/Delivery.
