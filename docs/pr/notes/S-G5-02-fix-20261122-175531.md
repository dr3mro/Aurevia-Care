## Findings

### Confirmed root cause of the red gate (tool evidence, pre-existing)

Both errors reproduce on this clean checkout (no `apps/api/target`):

```
ERROR: test_integration_failure_still_fails_the_gate (test_worker_gate.MainTest...)
ERROR: test_maven_failure_with_failing_reports_still_fails (test_worker_gate_coverage.MainTest...)
FileNotFoundError: [Errno 2] No such file or directory: 'apps/api/target/surefire-reports'
```

Trace: the tests patch `worker_gate.Path.is_dir` to return `True`, so
`worker_gate.main` calls `usable_reports(reports)` with the default shared path
`apps/api/target/surefire-reports`. `usable_reports` calls
`Path(reports_dir).glob("TEST-*.xml")`; on Python 3.11 `Path.glob` raises
`FileNotFoundError` for a missing parent. In CI the full gate runs Maven first,
which creates the directory, so the errors disappear there — this is why only
the worker's fast gate (Python tests before any Maven run) goes red. The branch
changes only three Markdown files and introduces none of this; `git diff
origin/main...HEAD -- scripts/` is empty.

### Exact patch needed (NOT applied — out of scope, protected path)

Land this in a separate trusted change under the daily notes reconciliation or
the integrator. Both test files already import `tempfile` and `Path`;
`test_worker_gate_coverage.py` already has `write_report(directory, filename,
xml)` and `suite_xml(name, failures, errors)` helpers.

**Required — make the two tests own a real report directory.** In
`scripts/tests/test_worker_gate.py`, replace
`MainTest.test_integration_failure_still_fails_the_gate` (~line 328) with:

```python
    def test_integration_failure_still_fails_the_gate(self):
        # A repair task is strict: its failing class fails the gate even with no
        # hand-off scope declared. Own a real report directory so the gate reads
        # usable results without depending on a Maven run creating the shared one.
        with tempfile.TemporaryDirectory() as reports:
            (Path(reports) / "TEST-RxTransmissionFlowTest.xml").write_text(
                '<testsuite name="RxTransmissionFlowTest" tests="1" errors="1" failures="0"/>')
            with mock.patch.object(worker_gate, "failing_classes",
                                   return_value={"RxTransmissionFlowTest"}), \
                 mock.patch.object(worker_gate, "changed_paths", return_value=[]), \
                 mock.patch.dict(os.environ, {"STORY_ID": "FIX-01"}, clear=True):
                self.assertEqual(worker_gate.main(["1", reports]), 1)
```

In `scripts/tests/test_worker_gate_coverage.py`, replace
`MainTest.test_maven_failure_with_failing_reports_still_fails` (~line 552) with:

```python
    def test_maven_failure_with_failing_reports_still_fails(self):
        # A strict repair task that names no class stays red on any failing class.
        # Use a real private report directory, not the shared Surefire path.
        reports = self.root / "reports"
        reports.mkdir()
        write_report(reports, "TEST-FooTest.xml", suite_xml("pkg.FooTest", "0", "1"))
        self.assertEqual(self.run_main(argv=["1", str(reports)], env={"STORY_ID": "FIX-01"},
                                       failing={"FooTest"}, reports=True), 1)
```

Both keep the original assertion (`== 1`) and add no skip, exclusion or lowered
threshold. With this change `usable_reports()` reads a real, parseable XML file
and neither test touches the shared directory, so both errors go away without a
Maven run.

**Optional defence in depth — harden the reader.** In `scripts/worker_gate.py`,
wrap the glob in `usable_reports` so a missing/unreadable directory is "no
usable results" rather than an exception:

```python
    try:
        reports = sorted(Path(reports_dir).glob("TEST-*.xml"))
    except OSError:
        return False
    for report in reports:
        ...  # unchanged ParseError/True loop
```

Add a unit test for the new branch. The `aurevia-coverage-auditor` review
(VERDICT: GO, Optional finding) pointed out that merely pointing at a missing
directory will **not** reliably enter the `except OSError` branch — on newer
Python `Path.glob` on a missing directory returns an empty iterator and falls
through to the existing `return False`. The test must force the error, e.g.:

```python
    def test_usable_reports_on_unreadable_directory_returns_false(self):
        # Force OSError so the new branch is exercised on every Python version.
        with mock.patch.object(worker_gate.Path, "glob", side_effect=OSError):
            self.assertFalse(worker_gate.usable_reports("any-dir"))
```

and prove 100% coverage of `scripts/worker_gate.py`. If the optional hardening
is not landed, the required test fixes above are sufficient to turn the worker
gate green and add no new production branch.

## Lessons for workers

- When a fix pass says "local checks: failed", run the script that actually
  failed (`bash scripts/python-coverage.sh`) before concluding the in-scope
  change is fine. A documentation gate passing does not make the worker gate
  green.
- A test that patches `Path.is_dir` but globs the shared `apps/api/target`
  directory is environment-dependent: it passes only after Maven has created
  that directory. Tests must own a real temporary report directory via the
  `main(["<mvn-status>", "<reports-dir>"])` second argument.
- `scripts/` is a protected path for swarm workers. When the root cause is
  there, document the exact patch in `## Findings` / `## Lessons for workers`
  and write `## Why this is not finished`; do not edit it in a worker PR, which
  would block auto-merge of the story's own PR.
- The six `test_check_pack` failures in this cloud worker are the documented
  skip-worktree/CI-profile artifact (OPS-CW-003-01); confirm once with
  `git ls-files -v`, `cmp` and `git show HEAD:opencode.json`, then stop
  re-diagnosing them.
