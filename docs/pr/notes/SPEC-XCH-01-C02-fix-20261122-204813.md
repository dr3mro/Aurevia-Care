## Lessons for workers

- When an integrator reports only "Delivery failed", query the public Checks API
  for the PR head SHA (`/repos/<owner>/<repo>/commits/<sha>/check-runs` and each
  failing `/check-runs/<id>/annotations`) before guessing. `Delivery gate` is an
  aggregate; the real error is in the named verification job.
- A check whose name has nothing to do with the changed module can still be the
  blocker; `scripts/frontend-check.sh` runs the whole staff-web suite on every PR,
  so a flaky unrelated Vitest test makes every PR red. Reproduce locally before
  changing anything — a local pass plus a CI failure means flake, not regression.
- Stay inside `scope`: diagnosing an out-of-scope blocker is useful, editing its
  file is not. Record the exact error and a task-request instead.
