## Lessons for workers

- When a slice adds controller routes, publish them in `contracts/openapi.yaml` in the same change
  and regenerate the client; adding them to `missing-routes.txt` hides rather than fixes the gap.
- A GET that returns a JSON array must use a named array schema whose name does not end in `Page`
  (for example `PendingStaffAttachments`); an inline array or a `*Page` name fails the pagination
  rules.
- Run the whole contract test family, not just parity/rules/pagination: `OpenApiErrorRulesTest` also
  validates the committed contract and is cheap to include. Route-parity green is not enough — read
  the service for the real reachable 409/422 statuses and the controller for the real media types.
- In cloud workers, a `check-pack: opencode.json is stale` result usually means the CI profile is
  active under skip-worktree; compare `git show HEAD:opencode.json` with the worktree file before
  treating it as a real failure, and never edit that protected file to make the gate pass.
- `python3 -m coverage` may be absent in a runner; `scripts/python-coverage.sh` then falls back to
  plain unittest and inherits pack failures that are not code defects. Record the environment limit
  rather than weakening a gate.
- This branch already carries many near-identical verification passes. Continue from them: re-run
  the gates with your own commands, record results in your own notes file, and avoid re-deriving the
  already-documented contract fix.
