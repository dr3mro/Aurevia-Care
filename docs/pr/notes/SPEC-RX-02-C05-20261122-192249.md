# SPEC-RX-02-C05 — Distinguish dispensing evidence from acceptance

## Summary

Adds a synthetic, database-free API-level clause test that proves dispensing evidence is a
fact distinct from pharmacy acceptance, plus a clause document recording the proof. The
clause is already implemented in production; this change is test and documentation only.
No production code, existing test, contract or migration was changed, and no dependency was
added.

- `apps/api/src/test/java/com/aurevia/prescription/clauses/DistinguishDispensingEvidenceAcceptanceTest.java` (new)
- `docs/spec/clauses/prescription/distinguish-dispensing-evidence-acceptance.md` (new)

The new test exercises the existing boundaries of `RxService.recordDispensing`: active
membership, `RxActions.DISPENSE` restricted to `pharmacy_staff` (a clinician is refused),

Tenant context is set and cleared around every test. No real patient data, credential or
PHI is used — only synthetic UUIDs and `pharmacy-1111` / `clinician-1111` subjects.

## Lessons for workers

- A clause document can only claim `Proven by tests` when it names the HTTP/entry-point tests that prove the rule end to end; a mocked service test alone is not an entry-point-to-test trace. The plan reviewer required this before coding.
- `bash scripts/worker-check.sh` fails at `check-pack.py` in the cloud worker because `opencode.json` is a `skip-worktree` CI profile (`git ls-files -v` shows `S`). Confirm once, run the remaining stages individually and never regenerate or commit that file.
- For a proof-only clause task, check the production command's actual guards before writing negatives — `recordDispensing` uses `locked(...)`, not `lockedByPrescriber(...)`, and has no entitlement guard; a prescriber-ownership negative would assert behavior the command never had.
