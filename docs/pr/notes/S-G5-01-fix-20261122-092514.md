## Lessons for workers

- Before blaming a build break on conflict markers, check whether the marker lines
  are inside a `/* … */` comment; `javac` on the affected files is a fast,
  definitive test. Earlier passes repeated an incorrect "main is red" claim for
  several fix rounds.
- In an OpenCode cloud worker, a red `check-pack.py` is usually the CI profile
  under `skip-worktree`. Compare `git show HEAD:opencode.json` with
  `gen_opencode.render(Path(root), ci=False)` before regenerating, and restore HEAD
  bytes locally to run the real gate. Never edit that protected file.
- On a fresh checkout, `scripts/python-coverage.sh` can fail with
  `FileNotFoundError: apps/api/target/surefire-reports`. Creating that gitignored
  directory resolves it; do not change `worker_gate.py` or add exclusions.
- `python3 -I scripts/check-docs.py` enforces heading-level jumps, GFM table cell
  parity, relative-link resolution and specification requirement IDs; count
  unescaped pipes in every new table row and use only IDs defined in the spec.
- When a pack must "record no approval", a status legend plus placeholder cells
  ("owner to enter", "to be named") keeps the document useful without inventing a
  market, region, contract or retention value.
