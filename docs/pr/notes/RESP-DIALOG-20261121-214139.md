# RESP-DIALOG — Staff web responsive `Dialog` component

## Summary

Made the shared staff-web `Dialog` responsive without changing its public
contract. The panel now uses the existing `sheet` class (full-screen sheet with
logical safe-area padding on compact, centred max-width panel from medium up),
wraps content in the existing `stack` class, and gives the close control the
existing `touch` class for coarse-pointer 44 × 44 targets. `useBreakpoint()`
drives compact-only sticky header and action-row chrome (logical inline styles,
because `responsive.css` has no dialog-specific classes) plus scroll padding so
sticky regions never obscure focus. Opening locks page scroll; Tab cycles
through focusable controls inside the dialog; Escape closes it; focus returns to
the opener. Direction is inherited from the document — no local `direction`
override and no physical CSS property was introduced. A new test file mocks
`matchMedia` for compact, medium and expanded and asserts structure, labels,
roles, keyboard order and the RTL case.

## Findings

1. **Pre-existing generated-client drift (tool evidence, out of scope).**
   `bash apps/staff-web/check.sh` fails at `npm run gen:api:check` with
   `Generated types are not up-to-date!`. `contracts/openapi.yaml` declares
   `/api/v1/printing/handouts` and `/api/v1/printing/handouts/download`
   (and `PrintReason`, `HandoutKind`, `HandoutSource`) that
   `apps/staff-web/src/api/generated/openapi.d.ts` lacks. `git status` shows
   only the two scoped files modified. Regenerating from
   `git show HEAD:contracts/openapi.yaml` and diffing against
   `git show HEAD:apps/staff-web/src/api/generated/openapi.d.ts` reproduces the
   drift at HEAD, so it is independent of this change. Fixing it requires
   editing `src/api/generated/openapi.d.ts`, outside this story's scope; exact
   next step is in "Why this is not finished".
2. **No dialog CSS classes in `responsive.css`.** There is no sticky-header,
   sticky-action-row or scroll-padding utility class. Per the story rule I did
   not edit the stylesheet: the sticky chrome and scroll padding use logical
   inline styles, and the missing utilities are recorded under Lessons.
3. **16 px input text is a child boundary.** `Dialog` does not render inputs;
   child inputs must carry the `.field` class from `responsive.css` (owned by
   the FormField story) to get 16 px text. This dialog wraps children in
   `.stack` (min-inline-size 0, overflow-wrap anywhere) and its close control
   uses `font: inherit`, so text scales with the root size at 200% zoom.
4. **Background inertness is partial.** The scrim is visual only; true top-layer
   and `inert` background would require a portal and app-root inert handling,
   outside this scope. The in-dialog Tab cycle keeps keyboard focus inside and
   focus returns to the opener, preserving the previous guarantee.
5. **Tab handling upgraded deliberately.** The previous placeholder pinned Tab
   to the close control; it now cycles through focusable controls inside the
   dialog to satisfy `accessibility-patterns.md` section 5 ("Tab cycles inside
   the dialog"). All original `Dialog.test.tsx` tests still pass; exported
   names, text and API calls are unchanged.
6. **Pre-existing `onClose` effect re-run (simulated reviewer, medium).** The
   focus/scroll effect depends on `[open, onClose]`; `DesignPreview.tsx` passes
   an inline arrow, so a parent re-render while open re-runs setup and moves
   focus back to the close control. Verified against the pre-change baseline:
   the original component already used `[open, onClose]`, so this is not
   introduced here. Fixing it (an `onClose` ref with an `[open]` dependency, or
   memoised call sites) changes focus behaviour and is a separate defect story;
   not done in this scope. The added scroll lock is restored and re-applied
   synchronously in the same effect cycle, so it is not observable as a flicker.

## Lessons for workers

- A red `gen:api:check` on a fresh worktree is often pre-existing
  contract/generated-client drift, not your defect. Confirm with
  `git status`, then regenerate from `git show HEAD:contracts/openapi.yaml` and
  diff against the checked-in client before touching anything outside scope.
- `responsive.css` provides `.sheet`, `.stack` and `.touch` for dialogs but no
  sticky-header/action-row or scroll-padding class; request those as a
  stylesheet story rather than re-adding new CSS in a component.
- jsdom serializes an inline numeric `0` as `"0"`, not `"0px"`: set logical
  insets as `'0px'` strings if asserting a pixel value.
- `useBreakpoint()` subscribes to media-query `change` events, so a
  `matchMedia` mock must implement `addEventListener`/`removeEventListener`
  (see the fixture in `tests/theme/breakpoints.test.ts`).
- The full Vitest text reporter lists only files with gaps; `No files with
  missing coverage` plus the 100% summary is the per-file confirmation. Name a
  test for each ternary/branch before declaring a frontend slice done.
