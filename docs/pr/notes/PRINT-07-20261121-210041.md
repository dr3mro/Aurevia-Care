# PRINT-07 — Staff web: Print chart summary and signed report from the chart

## Summary

Added a self-contained, test-first `features/print/chart` module. `PrintChartButton` is a single disclosure entry point for two sources: a chart summary and a signed report. A controlled `ChartSectionPicker` chooses a visit or an inclusive date range and the sections to include. `ChartPrintPreview` shows the chosen scope, the included section counts and an explicit left-out list with plain-language reasons (`unsigned`, `withheld`); a draft report is never printable and is listed as unsigned instead. Scope, section and reason choices live in the button, so closing a preview and re-previewing keeps them. All labels are a parity-checked English/Arabic bundle; values stay in their source script through `MixedScriptText`. Synthetic fixtures only; no dependency added; no file outside `apps/staff-web/src/features/print/chart` changed.

This is a component/entry-point slice: the button is exported for the owning chart and signed-report screens to mount, because those screens are outside this task's scope (see Findings and task-requests).

## Findings

1. **Generated-client drift blocks the module check (pre-existing, out of scope).** `bash apps/staff-web/check.sh` stops at `gen:api:check`; the checked-in `src/api/generated/openapi.d.ts` predates printing endpoints in `contracts/openapi.yaml`. Fix requires touching a generated file outside this task's scope; requested as a separate task.
2. **Global UX-01 bundle registry does not know this module's labels.** `tests/messageParity.test.ts` globs only `src/**/messages.ts` and compares against a static list. Naming this bundle `messages.ts` made an unrelated registry test fail; following the existing `features/pharmacyinbox/labels.ts` / `features/radworklist/labels.ts` precedent, the file is `labels.ts` and its own `labels.test.ts` checks key parity, non-empty values, Arabic script and placeholder parity. Registering it globally needs an out-of-scope edit; requested as a task.
3. **No screen in this scope mounts the button.** There is no signed-report screen in `apps/staff-web/src`, and `ChartScreen`/`NotePage` are outside `features/print/chart`. The acceptance is met at the exported-component level (report target renders through the same button); wiring and an end-to-end screen test need a follow-up task.
4. **Policy choice:** left-out items are listed only for sections the clinician selected — deselecting a section is an explicit choice, not a silent omission. The date-range policy treats a note with no effective date as out of scope; only in-scope drafts appear as `unsigned`.
5. **Simulated senior-react review — HIGH, fixed:** the Print action was rendered even for a non-printable draft report, so `onPrint` could be called with a refused model. Fixed with a tested `canPrintPreview(preview)` domain rule used to render the action only for a chart or a signed report; a draft now has no Print button and a test asserts `onPrint` is never called.
6. **Simulated senior-react review — MEDIUM, fixed:** hard-coded radio `name` and input `id`/`htmlFor` values collided when two buttons render on one page. The button's `useId()` is now passed as `controlId` to `ChartSectionPicker` and used for every control id and group name; a two-instance test proves independent reason selection and distinct label targets.
7. **Simulated senior-react review — LOW, fixed:** the required-reason alert was announced but not focused; a ref and effect now focus it, asserted in the reason-gate test. Provenance and the section-count line are now isolated with `MixedScriptText` for RTL, matching the rest of the preview.

## Lessons for workers

- Before adding a new bilingual `messages.ts` to staff-web, check `tests/messageParity.test.ts`'s static `BUNDLE_SOURCES`: a new `messages.ts` makes the registry test fail. A feature-local `labels.ts` with its own parity test keeps scoped work green; register it in a separate owned change.
- `apps/staff-web/check.sh` can be red at `gen:api:check` because of another story's contract change; run its remaining steps individually to prove your own slice and record the drift as pre-existing with a read-only regeneration diff.
- A controlled component's "already checked" radio will not fire `onChange` on a click. To cover the empty-array branch of `visits[0]?.id ?? ''`, render the *other* scope and click the visit radio.
- With `exactOptionalPropertyTypes`, spreading `effectiveOn: undefined` into an optional field is a type error; build the object without that key instead.
