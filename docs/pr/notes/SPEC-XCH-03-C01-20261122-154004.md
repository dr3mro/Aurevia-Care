## Findings

- The advisor brief named `privacy_auditor-1111` as the seeded wrong-role
  subject, but the reused fixture seeds `auditor-1111` with role
  `privacy_auditor`. The test uses `auditor-1111` so the 403 comes from the
  recipient-role policy rather than a missing membership. No fixture was
  renamed.
- The six XCH-03 routes are absent from `contracts/openapi.yaml` and listed in
  `contracts/openapi/missing-routes.txt`. Recorded as tracked contract debt in
  the clause document's `## Gap`; the contract was not edited.
- `origin/main` (and therefore this branch) already contains conflict-marker
  text inside Javadoc comments in
  `apps/api/src/main/java/com/aurevia/exchange/hl7/{Hl7ParseException,Hl7Parser,Hl7Segment}.java`.
  It is pre-existing, outside this task's scope, and Java still compiles; it
  is reported here for the integrator.

## Lessons for workers

- A successful XCH-03 command appends one event on top of the seeded `received`
  event: assert the absolute count (2) and the last event, not "1 event".
- Spring returns HTTP 422 as `UNPROCESSABLE_CONTENT` in this version; assert the
  numeric `getStatusCode().value()` to stay robust across enum renames.
- The clarification question lives on the order projection and is copied into
  the event's `reason` field; `ExchangeEvent` has no `question` property.
- Use a genuinely seeded identity for a wrong-role negative; otherwise a 403
  proves only "unknown subject" and not the action policy.
- `mvn -Pno-security,fast -Dgroups=integration` silently runs no integration
  tests; always use `-Pno-security -Dgroups=integration` and read the Surefire
  count from the class XML.
