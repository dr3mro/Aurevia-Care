# SPEC-LAB-02-C03 — LAB-02 clause 3: verification checks specimen, patient and observations

## Summary

Added a test-only HTTP proof of the already-implemented LAB-02 clause. One new MockMvc test
class drives the real `LabResultEntryController` → `ResultEntryService` → `LabResultService`
chain under `synthetic-auth`, capturing a preliminary report and verifying it as a different
subject. The positive test proves the specimen/patient/order labels are preserved and that both
stored observations are re-evaluated against approved reference ranges (flags `none` → `low` and
`none` → `high`) while the preliminary revisions stay unchanged. Eight negatives prove refusals for wrong patient, wrong
accession, wrong issuer, unknown specimen, wrong role, self-verification, stale version,
already-final state and another tenant. No production code, existing test, contract or
migration was changed.

## Lessons for workers

- Build the clause test with a REAL service chain (real controller + real `ResultEntryService` +
  real `LabResultService` with a policy catalog); mocking the service only proves error mapping,
  not the rule. Fresh instance in `@BeforeEach` keeps the in-memory ledger isolated per test.
- To prove observation re-evaluation, capture with no caller-supplied reference bounds (flag
  `none`) and supply an approved `ReferenceRange` effective before the fixed clock; then assert the
  final flag changed. Asserting only the final flag would pass even if capture already flagged it.
- For a genuine self-verification negative, a single subject holding both collector and verifier
  roles reaches the segregation check and yields `SELF_VERIFICATION`; a collector-only subject
  yields `FORBIDDEN` at authorization instead. Both are needed to prove distinct behaviours.
- In this repository Jackson is not a test dependency for MockMvc bodies: use raw JSON strings as
  `ResultControllerTest` does, and never name a local MockMvc helper `verify(...)` — it shadows
  Mockito's static `verify`.
- OPS-CW-003-01 recurs: the CI `opencode.json` installed under skip-worktree makes
  `check-pack.py`, `worker-check.sh`, `python-coverage.sh` and six `test_check_pack` tests red.
  Confirm once with `git ls-files -v opencode.json` → `S`, run the other stages individually, and
  never regenerate or commit that file.
