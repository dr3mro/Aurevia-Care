## Specification / acceptance mapping
- OPS-08 "commit in controlled batches; reconcile counts and hashes" —
  `ControlledImportService.commitBatches` applies batches in declared order,
  `reconcile` compares declared `expected_count` and `sha256` to values recomputed
  from source records; a rejected batch stops the sequence.
- OPS-08 "controlled batches that can be resumed" — `ImportProgress` is the
  resumable checkpoint (committed sequences + deduplicated source ids). Re-applying
  a committed batch returns `ALREADY_COMMITTED` and cannot duplicate a record.
- OPS-08 "source of truth changes only after authorized sign-off; reversible until then" —
  `commitBatches` leaves `progress.finalized = false`; `signOff` accepts only an
  authorized role bound to this manifest version, every batch and the recomputed
  content digest; `reverse` clears staging before sign-off and is refused after.
- OPS-08 "preserve provenance / historical signature evidence, no new attestation" —
  no code path creates a signature; the existing V90 provenance target and
  `ImportedRecord` projection from BUILD-43 are reused unchanged.

## Findings
- No product defect found in the changed code. `batchDigest` canonicalizes full
  source records (sorted map keys, sorted attachments, source id and preserved
  signature) before SHA-256, so key order cannot change a digest and any changed
  value does; `contentDigest` binds the manifest version and ordered batch
  digests, matching the OPS-08 sign-off contract in `docs/operations/s_g5_09`.
- `scripts/check.sh` and the 3 `test_check_pack` failures are the documented
  pre-existing CI-profile `opencode.json` artifact, not this change: `git ls-files -v opencode.json` = `S` (skip-worktree), worktree md5 `2225aa…` equals `.github/opencode.ci.json`, HEAD md5 `33f05d…` differs. Per BUILD-43 / MEMORY OPS-CW-003-01, do not regenerate or commit `opencode.json` from a worker.
- Deliberate scope boundary: no persistence layer, migration or OpenAPI change.
  The V90 `import_record_provenance` table (RLS, FORCE RLS, append-only) from
  BUILD-43 remains the durable target; a store-backed commit and the staff-web
  screens are separate stories. This slice is the domain state machine plus thin
  HTTP entry points, consistent with BUILD-43's pure-evaluator design.
- Sign-off authorization uses the three roles from the OPS-08 handoff
  (`tenant_admin`, `privacy_auditor`, `clinical_safety_lead`); any other role or a
  null/blank approver is refused. This is domain-level authorization only — real
  identity/OIDC enforcement belongs to the owning security boundary.

## Lessons for workers
- In a cloud worker, `check-pack.py` / `test_check_pack` failures and an early
  `scripts/check.sh` exit are usually the skip-worktree CI `opencode.json` profile;
  confirm with `git ls-files -v` and `git show HEAD:<file>` before treating them as
  real staleness. Never regenerate or commit `opencode.json` from a worker.
- MockMvc entry-point tests must use the same synthetic fixture values (attachment
  vs signature checksums) as the Java-built manifest whose digests they embed, or
  reconciliation legitimately reports a hash mismatch.
- When a new `@RestController` is added, extract the manifest/digest fixtures into
  a Java-built `ImportManifest` and format its computed digests into raw JSON —
  Jackson `databind` (ObjectMapper) is not on this module's test classpath.
- Java records holding `List`/`Set` need a compact constructor copy plus an
  overridden defensive accessor (SpotBugs EI_EXPOSE_REP) and a test that calls every
  accessor for 100% method coverage; avoid unqualified `{@link}` (use `{@code}`).
