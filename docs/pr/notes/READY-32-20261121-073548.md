## Findings

- **One out-of-scope expectation update (necessary, documented).** The task scope listed `apps/staff-web/src/features/system`, `apps/staff-web/src/main.tsx` and `apps/staff-web/tests`, but adding the mandated `features/system/routes.ts` makes the READY-51 eager glob discover a new module, so `createRoutes()` now returns four extra patterns. `src/app/routes.test.tsx:19-30` asserts that exact array and sits outside the literal scope. I updated only its expected-pattern list (and the identical, in-scope snapshot in `tests/app/AppShell.test.tsx:128-157`) to include `/signed-out`, `/session-expired`, `/forbidden`, `/not-found`. Per AGENTS.md rule 7 this is an existing test changed because behavior changed on purpose; the assertion is still an exact `toEqual` and no check was weakened. No production file outside the scope was touched.
- **Baseline constants.** The WEB-07 row of `docs/operations/production-readiness/README.md` names the four browsers but lists no numeric majors, so the story's fallback constants were used verbatim: Chrome 130, Edge 130, Firefox 130, Safari 17. `SUPPORTED_VERSION_WINDOW = 2` means version ≥ baseline−2 is supported; unknown user agents fail closed. IE is detected via `Trident/`/`MSIE` before the Chromium rules, and Edge before Chrome/Safari, because Chromium Edge also advertises `Chrome` and Chrome also advertises `Safari`.
- **Primary actions target `/`.** This module is a visual foundation with no real IdP route; identity tooling owns real sign-in (module README). The sign-in and go-home actions therefore navigate to the home route and were tested on all five pages.
- **Separate not-found pages by design.** The app's existing `src/app/NotFoundPage.tsx` remains the `'*'` catch-all (out of scope and untouched). The new feature page serves the explicit `/not-found` route; both are data-free.
- **No new npm dependency.** Vite's built-in `import.meta.glob` provides registration; existing `Button`, `StateViews`, `I18nProvider` and `ThemeProvider` were reused.
- **Bounded Senior React review (advisory, tool-read diff; reviewer did not re-run gates).** Four findings and their dispositions:
  1. *IE11 never executes the module entry, so it sees a blank page rather than the unsupported message.* Confirmed as a real product limitation, but the fix needs `index.html` (a classic `nomodule`/fallback script), which is outside this task's scope.   3. *Two divergent not-found pages; the `'*'` catch-all still points at the old app page with no primary action.* Correct, but the fix needs `src/app/routes.tsx`, which is outside scope. The explicit `/not-found` route registered here has the action and both messages; aligning the catch-all is a follow-up for the orchestrator.

## Lessons for workers

- Before adding a new `features/<name>/routes.ts`, grep **both** `src/app/routes.test.tsx` and `tests/app/AppShell.test.tsx` for exact route-array snapshots — a new feature folder silently changes `createRoutes()` through the eager glob. Snapshot files can live in `src/` as well as `tests/`.
- In an entry-point test that calls `vi.resetModules()`, do not compare imported component identities: the entry point re-imports the providers into fresh module instances. Assert on the component function `name` (or render and assert on output) instead.
- When a story says "use the state views", reuse the existing `StateViews` components for the states they already own (session expired, forbidden) and add a small feature-owned message map only for the genuinely new labels; keep a key-parity test.
