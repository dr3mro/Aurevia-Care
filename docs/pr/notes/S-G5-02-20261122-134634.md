## Lessons for workers

- When a decision pack is already thorough, check the explicit acceptance triplet
  (owner role / evidence location / status) before adding analysis — a missing
  column is usually the gap, not missing prose.
- In a cloud worker, a red `check-pack.py` with `git ls-files -v opencode.json`
  showing `S` means the CI profile is installed under skip-worktree; verify with
  `cmp` against `.github/opencode.ci.json` and never regenerate or commit that
  file.
- For a Markdown-only story, `python3 -I scripts/check-docs.py` plus a direct
  re-read is the applicable gate; `scripts/check.sh` starts the full Maven verify
  and must be left to the integrator.
- Verify a "not built / in memory / does not survive a restart" claim against the
  current tree before writing it into a decision record. `BUILD-26` and the
  catalog reachability gap were both already closed on `main`; a static review
  caught the stale claim before merge. Prefer `open` with cited code facts over
  `blocked` with an unverified gap.
