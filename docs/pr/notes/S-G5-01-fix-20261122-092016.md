## Lessons for workers

- In an OpenCode cloud worker the worktree `opencode.json` is the CI profile under
  `skip-worktree`; a red `check-pack.py` / `gen-opencode.py --check` there is usually
  a profile artifact. Confirm with `git ls-files -v` and by comparing
  `git show HEAD:opencode.json` with `gen_opencode.render(Path(root), ci=False)`
  before regenerating anything, and never edit that protected file.
- When a story reports "local checks: failed" repeatedly, run the cheap policy
  checks first, then check for committed conflict markers with
  `git grep ... HEAD -- <path>`: a build break on `main` masquerades as a per-story
  failure and cannot be fixed inside a narrow `scope`.
- `python3 -I scripts/check-docs.py` enforces heading-level jumps, GFM table cell
  parity, relative-link resolution and specification requirement IDs; count
  unescaped pipes in every new table row and use only IDs defined in the spec.
- When a pack must "record no approval", a status legend plus placeholder cells
  ("owner to enter", "to be named") keeps the document useful without inventing a
  market, region, contract or retention value.
