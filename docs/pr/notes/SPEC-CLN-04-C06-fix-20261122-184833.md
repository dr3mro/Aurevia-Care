## Findings

1. **Root cause of the earlier rejections — out-of-scope changed file.** A previous fix round
   added awaited assertions to the responsive facilities test. That path is not in this task's
   declared scope, so `worker_gate.py` emitted a `scope` violation from the committed three-dot
   diff. This pass returns the file to the exact `origin/main` content; the final against-main diff
   contains only the two deliverables and notes files.
2. **Pre-existing flaky responsive test on main.** The race between `ApiPage` resolving the table
   and `PageSink` appending rows in an effect is a main defect, byte-identical on `origin/main`;
   it should be repaired on main with a deterministic red test, not in a clause-proof pull request.
   A bounded follow-up task is requested below.
3. **No HTTP/OpenAPI entry for template approval.** The CLN-04 approval workflow is a domain
   service only: no `web` controller and no `contracts/openapi.yaml` path reference
   `TemplateService`, dictionaries or templates. Exposing it needs a separate production story
   (controller + contract + generated client + HTTP integration test); it is outside this clause's
   rule and not a reason to disable the proof.
4. **Pre-existing conflict markers in committed HEAD.** `exchange/hl7/Hl7ParseException.java`,
   `Hl7Parser.java` and `Hl7Segment.java` contain marker text inside Javadoc with identical text on
   both sides. They are in committed HEAD, compile and pass SpotBugs, and were left untouched.
5. **Known worker-environment false positive (OPS-CW-003-01).** The worktree `opencode.json` is the
   CI profile installed under `skip-worktree` (`git ls-files -v opencode.json` reports the skip
   flag); `check-pack.py` and some `test_check_pack.*` cases are red for that reason. No protected
   config was edited or regenerated; the integrator owns the full gate.
6. **Stale diagnoses from earlier passes (do not repeat).** Fix pass 1's compile error in
   `OffboardingCommandTest` is fixed on current main (BUGS DELIVERY-1983); fix pass 2's
   `worker_gate.py` file-not-found is a local Python artifact whose CI tooling job is green. Neither
   is the blocker addressed here.

## Lessons for workers

- `worker_gate.py` builds its changed-file list from the committed three-dot diff. Commit a scope
  cleanup before simulating the gate, or the simulation still reports the old out-of-scope path.
- Keep angle-bracket placeholder words out of the Test evidence and Coverage sections: the gate
  scans those two bodies for that pattern and rejects an otherwise correct hand-off.
- Do not repair a pre-existing flaky test on main inside a narrowly scoped proof story. Revert the
  edit and request a follow-up task so the proof pull request stays inside its declared scope.
- Clause proof tasks scoped to `chart/clauses` are fully unit-style: reuse `InMemoryTemplateStore`
  and a caller-supplied `TemplateActor` snapshot; no PostgreSQL fixture is needed.
- `check-names.py` accepts the business-domain package `com.aurevia.chart.clauses`;
  the folder name is domain vocabulary, not a task or gate identifier.
