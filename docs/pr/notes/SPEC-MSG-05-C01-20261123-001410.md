## Lessons for workers

- When seeding a role for a patient subject, select the membership of the grantee and take `granted_by` from a separate user identity; joining both predicates on one row silently inserts no role and the failure surfaces as 403 rather than a seed error.
- A JSON `facts` array needs an object-boundary helper: indexing raw field occurrences gives the wrong value when only one fact carries `genericKey` or `scope`.
- Confirm the negative's precondition before trusting it: a reception actor with no role at all also gives 403, so seed a real active membership with a non-permitted role to prove authorization rather than an unknown subject.
- Do not run `scripts/check.sh` or an all-integration suite in a swarm worker; run the targeted `-Dtest=...` and the individual policy/SpotBugs/DB stages, and leave the full gate to the integrator.
