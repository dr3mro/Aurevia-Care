## Findings
- **Pre-existing lab route defect (not introduced here).** `src/app/useRole.ts:10` hard-codes the synthetic staff role to `reception`; `src/app/navigation.ts:175-179` grants `/lab/accessions` only to `lab`. Direct navigation renders `ForbiddenPage`, so the existing `e2e/labflow/lab-journey.spec.ts` is already red on this checkout (tool evidence above). The brief's stated lab entry points (real routes) are therefore unreachable. I did not change `src/` or the existing test (both out of scope). The new bilingual journey mounts the real `CollectionDeskPage` and `ResultEntryPage` under a dev-only harness with the real providers, which is the established pattern for role-specific screens in this repository. Fixing the pre-login role wiring or lab route authorization needs a separate owner-approved story.
- **Playwright tooling absent in the worker image.** The browser binary and its OS libraries were installed with `npx playwright install chromium` and `npx playwright install-deps chromium`; no tracked file changed.
- **Stub glob pitfall found and fixed.** Playwright's `*` does not cross a path separator: `**/api/v1/appointments*` intercepts the query-string list GET and the bare book POST but not the nested check-in POST; a second `**/api/v1/appointments/**` route was required.
- **Flaky optimistic assertion removed.** `SchedulingScreen` announces "Command sent" on click and the subsequent reload clears it, so an assertion on `scheduling-status` was timing-dependent. Reception now asserts the reloaded appointment rows instead (new booked row with an enabled Check in button; seeded row with the checked-in badge and a disabled button).
- **Lab verification has no API command in production.** `ResultEntryPage` keeps verification in local state, so `api.calls` cannot prove that half of the journey. The spec instead asserts the typed value reaches the release summary before attestation, then asserts the localized verification status.
- **Optional hardening not applied (non-blocking).** DevSecOps suggested a catch-all 404 route in the reception and lab stubs so a future page change cannot fall through to a real `/api/v1/**` endpoint. Current mounted pages only call intercepted namespaces; this is left for a follow-up.

## Lessons for workers
- Install Playwright browsers and OS dependencies in a fresh cloud worker before trusting any e2e red/green result; a missing `libglib-2.0.so.0` looks like a test failure but is only environment.
- In this checkout the pre-login shell fixes the role to reception, so lab, radiology and other specialty routes render a forbidden page. Mount those real screens in a dev-only harness with their real providers instead of navigating to the route, and record the route-gate defect for the owner.
- Match Playwright route globs to the exact URL shape: a trailing `*` covers a query string, `**` covers nested path segments. Register both when a stub serves both a list endpoint and a nested command.
