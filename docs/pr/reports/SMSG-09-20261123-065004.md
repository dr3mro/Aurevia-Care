# SMSG-09 — API: audit, search, retention, export and legal hold for staff messages

## Summary

Implemented the bounded MSG-07 staff-message governance slice: an append-only, non-sensitive audit fact for every content, folder, hold, retention, export and audit-read action; tenant retention decisions with legal-hold precedence; hide-instead-of-purge folder placement; tenant-, participant- and folder-scoped search with cursor pagination; and a records-officer conversation export carrying every attachment checksum. All new files are inside the declared `staffmsg/governance` scope; existing V62/V91/V95 forced-RLS tables are reused, so no migration, contract, script, workflow or dependency file was changed.

## Affected requirements

- MSG-07 — audit, retention, legal hold, search, export (spec line 104).
- Supporting: ARC-02 (tenant isolation), ARC-03 (cursor pagination, machine-readable errors), OPS-02 (append-only audit, no PHI in facts), OPS-07 (export provenance/checksums).

## Risk class

Cross-boundary / safety-critical: tenant isolation, legal hold and records-officer export. Synthetic fixtures only; no human or clinical evidence is claimed.

## Review owner

Primary agent; read-only reviews by `aurevia-plan-reviewer`, `aurevia-code-reviewer`, `aurevia-coverage-auditor`, `aurevia-devsecops` (plus `aurevia-context-optimizer`, `aurevia-test-engineer`).

## Data changes

None. New durable facts reuse existing tables: `public.audit_event` (V1/V3, purpose-tagged `STAFFMSG_GOVERNANCE` so it never collides with the patient governance reader), `messaging_legal_hold`, `messaging_retention_policy`, `messaging_export` (V62), `staff_message`, `staff_mail_metadata`, `staff_mail_folder`, `staff_attachment_link` (V91), `staff_mail_draft`, `staff_mail_idempotency` (V95). No new table, column, backfill or reserved migration version. `MailFolder.TRASH` is the hide state; V91 revokes DELETE/TRUNCATE on the message ledger and link tables, so the hide cannot purge. Export checksums are assembled on demand from `staff_attachment_link.checksum`; only non-sensitive export metadata/provenance is persisted.

## Authorization boundaries and audit events

- Organization, subject, purpose and correlation id come only from `TenantContext`; roles come from the authoritative tenant-guarded folds via the store. No identity, role or organization is read from a request body.
- Roles: `HOLD_PLACE`, `HOLD_RELEASE`, `RETENTION_APPLY`, `EXPORT`, `AUDIT_READ` → `privacy_auditor` / `tenant_admin`; `OPEN`, `SEND`, `FORWARD`, `ATTACH`, `DOWNLOAD`, `FOLDER_MOVE`, `DELETE` → `clinician` / `unit_staff` / `reception`.
- Every protected method re-checks active membership and role; missing context → 401, no membership / wrong role / non-participant → 403, concealed or absent resource → 404, duplicate hold or repeat release → 409, malformed input → 422.
- `StaffMessageGovernanceContract.AuditEvent` has ten components and no body, checksum or clinical field. The service derives `SUCCESS` server-side and appends `DENIED` / `NOT_FOUND` / `CONFLICT` before throwing. Audit reads are themselves audited.

## Migration and rollout considerations

No migration. The Jdbc adapter composes existing `@Repository` stores and runs its one audit insert inside `TransactionTemplate` with forced RLS as the second boundary; `OffsetDateTime` is bound to `timestamptz`. No feature flag or rollout step is introduced by this slice. The durable-chain gap (contract/client publication and a real-DB integration test) is handed off below.

## Lessons for workers

- A `*Store` interface in `src/main` without a `Jdbc*` implementation is a new `check-wiring.py` finding; compose existing durable stores rather than writing a fake in production, and unit-test the adapter with mocked collaborators to keep 100% coverage.
- `scripts/check-constraints.py` rejects even `@SuppressWarnings("unchecked")` in a test; remove the annotation and accept the compiler warning instead.
- `test_java_conventions.py` requires FQN targets in every `{@link ...}` and at least two `List.copyOf(` occurrences in any file declaring a record with a `List<` component (store and read).
- Use `-Dtest='*<Name>*Test'` when a suite includes a `Jdbc<Name>StoreTest`; a leading-name-only glob silently skips it and leaves the adapter at 0% coverage.
- Role checks happen before object lookup: a cross-tenant test must use a role permitted for the action, otherwise it proves 403 (authorization) rather than 404 (concealment).
- Parallel swarm merges can strand a clause test behind a behaviour added in a sibling PR: if a full-verify coverage gate fails with 422 `UNAPPROVED_CHANNEL` in a test you did not touch, check `git log` on the service first, then seed the new precondition (e.g. approved-channel config) in that test's `setUp` instead of weakening the new guard or the test's assertions.
