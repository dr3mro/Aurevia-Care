## Lessons for workers

- Spring 7 renames the 422 status enum to `UNPROCESSABLE_CONTENT`; assert `getStatusCode().value() == 422` rather than an enum constant when a test must survive a framework upgrade. Likewise compare parsed `Instant` values with a tolerance — Jackson serializes at microsecond precision while `Instant.toString()` renders nanoseconds.
- An HTTP clause test gains real proof from the store, not just the response: assert the committed `audit_event` action/outcome/purpose/scope, the append-only `release_event`/`release_notification` ledgers and their absence on rejected commands. Filter by a unique `X-Correlation-Id` so parallel test classes cannot cross-contaminate.
- In a cloud worker, `git ls-files -v opencode.json` showing `S` explains `check-pack.py`/`test_check_pack` failures; confirm once with `git show HEAD:opencode.json` and never regenerate or commit that file. `worker-check.sh` and `scripts/check.sh` run every integration test and must be left to the integrator.
- When a plan review returns NO-GO, read each Required item literally: distinct synthetic revision ids per POST (a revision is one-way), non-blank review notes on every lift attempt (validation precedes role/version/state checks), separate correlation ids per denial, and never attribute an `audit_event` row to an actor when the repository writes `actor_id = NULL`.
