## Lessons for workers

- On a "did not finish cleanly" fix attempt, verify the committed work before
  rewriting it: re-run the focused test and the individual gate stages. A green work
  tree usually means the prior session ended early after hitting the
  `opencode.json` false positive.
- To prove the `opencode.json is stale` report without touching the protected file,
  import `scripts/gen-opencode.py` and compare `render(ROOT, ci=False/True)` with
  `git show HEAD:opencode.json` and `git show HEAD:.github/opencode.ci.json`; an `S`
  skip-worktree flag plus a byte match confirms OPS-CW-003-01.
- `-Pno-security` sets `spotbugs.skip=true`; add `-Dspotbugs.skip=false` or the
  "0 bugs" result is vacuous. Compile first, then run `spotbugs:check`.
- A clause story's step-3 `@Disabled` instruction and the constraint gate can
  conflict: check `scripts/check-constraints.py` and when the rule landed before
  adding a skipped test; document the conflict instead of evading the pattern.
- When `git grep` shows conflict markers, confirm with `git show HEAD:<path>` whether
  another worker committed them before attributing them to your own merge; do not
  edit files outside the task scope.
