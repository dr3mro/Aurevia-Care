## Lessons for workers

- When local gates are green but the integrator appears red, query the **public** check-runs API for
  the exact head SHA and the PR labels read-only before writing another verification note. Absence
  of `gh` is not absence of evidence (`webfetch` to `api.github.com` is read-only and needs no token).
- A green CI run with an open, `mergeable_state: clean` PR and a `needs-fix`/`needs-debug` label means
  the process blocked the merge, not the code: stop changing code and hand the label state to the
  integrator/person. Repeated notes-only commits only restart green CI and do not clear labels.
- When a slice adds controller routes, publish them in `contracts/openapi.yaml` in the same change
  and regenerate the client; never add them to `missing-routes.txt`. A JSON-array GET needs a named
  array schema whose name does not end in `Page`.
- In cloud workers a `check-pack`/`gen-opencode --check` failure usually means the CI profile is
  active under `skip-worktree`; verify with `git ls-files -v` and `git show HEAD:` before treating it
  as real. Never edit or regenerate that protected file to pass.
- Workers must not run the full `mvn verify` (>10 min, ends the run as a timeout); run targeted test
  classes plus `jacoco:report` for the touched area instead.
