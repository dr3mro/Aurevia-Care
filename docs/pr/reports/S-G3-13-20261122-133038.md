## Lessons for workers

- For gate-evidence stories, follow the existing `docs/gates/g1-clinic.md` / `g2-labs-and-exchange.md` shape: one matrix row per criterion, an explicit status, an entry-point-to-test trace, and a separate "Open items (not evidence gaps, not acceptance)" section. That structure keeps human acceptance out of a worker's note.
- Treat "Proven" as meaning a **merged test** exists, never a design doc, UAT script or open task title. When a named behaviour has no on-device or human evidence, say so in Open items with the owning task rather than silently upgrading it to Proven.
- Re-run the targeted acceptance suite and the patient-app check before calling a gate note done; they turn file-reading claims into executed evidence and catch the "green alone is not done" trap. Do not run `scripts/check.sh` or full `mvn verify` in a swarm worker — the integrator owns them.
- `git merge --no-edit origin/main` at the start and after the change keeps a parallel worker's branch current without touching protected trackers; verify with `git grep -nE '^(<<<<<<<|>>>>>>>) '` on the files you changed.
