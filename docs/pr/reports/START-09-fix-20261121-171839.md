## Findings

  20/20 green, no production change, no contract/controller edit, short `// TODO`
  allow list present. Rewriting it would add risk without addressing any gate.
- **Finding 1 — protected-script shellcheck failure (pre-existing, out of scope).**
  `bash scripts/check.sh` exits 1 at shellcheck `SC2015` on
  `scripts/agent-run.sh:51` (`[[ -f scripts/taskstore.py ]] && python3 ... || true`).
  `git log --oneline -3 -- scripts/agent-run.sh` shows the line came from commit
  `6acb0982` ("Stop storing TODO.md in git"), which is on the base branch, not from
  START-09. `scripts/` is worker-protected; not edited. Owner: maintainer / a
  protected-file repair task. Fix would be an explicit `if ...; then ...; fi` block.
- **Finding 2 — `opencode.json` skip-worktree artifact (known false positive).**
  `git ls-files -v opencode.json` → `S`; `python3 -I scripts/gen-opencode.py --check`
  → exit 1 because the worktree holds the CI profile copied by `agent-run.sh`, while
  HEAD holds the generator's local profile. MEMORY.md / BUGS.md `OPS-CW-003-01`
  records this as a measurement artifact; the trusted integrator gate runs from a
  fresh checkout with the committed profile. File not edited.
- **Finding 3 — coverage gate blocked by out-of-scope integration test (prior run,
  deterministic).** `scripts/coverage-check.sh` → full
  `mvn -q -B -f apps/api/pom.xml -Pno-security verify` died before JaCoCo with
  `Tests run: 2811, Errors: 1`, `JdbcPatientAccessStoreIntegrationTest.prepare:108
  ? PSQL ERROR: role "aurevia_migrate" does not exist`. Root cause (tool-verified
  by reading the file): two unordered `@BeforeAll` methods — `roles()` (lines 88-99,
  creates the roles) and `prepare()` (lines 102-119, `CREATE DATABASE ... OWNER
  aurevia_migrate`); JUnit may run `prepare()` first on a fresh cluster. The file
  `apps/api/src/test/java/com/aurevia/messaging/enrollment/it/JdbcPatientAccessStoreIntegrationTest.java`
  is outside START-09's scope and is not caused by this change. Owners: integrator /
  a separate repair task — fold the role-creation `DO $$` block into the top of
  `prepare()` and delete `roles()`.
- **Contract interpretation (from first run, retained).** The committed contract
  documents a body on only one 4xx shape (`403 → Forbidden → Error`); 401/404/409/422
  are bare `{description}`. A literal reading of "every 4xx/5xx response uses one
  shared error schema" would make the real contract breach on ~20 operations and need
  a long allow list, which the story forbids. The test therefore treats a response
  with no declared body as non-divergent, rejects any response that *does* declare a
  different body, and requires every operation to document the shared body at least
  once so an empty contract cannot pass. Stated in the class Javadoc.
- No production defect found; BUGS.md not edited (worker does not own it).

## Lessons for workers

- Before dispatching a fix pass, confirm the fix is inside the task's `scope`; when
  every remaining gate failure is in a protected script or an unrelated file, write
  the precise hand-off instead of rewriting a correct implementation.
- In a cloud worker, a `check.sh` that stops at shellcheck on a protected `scripts/`
  file, or a `gen-opencode.py --check` failure with `git ls-files -v` flag `S`, is an
  environment/base-branch artifact — record which file and commit introduced it and
  do not edit protected files to make the local gate green.
- A test-only change under `src/test` has no new JaCoCo target: the coverage gate is
  integrator-owned, and a full-verify failure in an unrelated integration test is not
  an uncovered branch of the touched code.
- Reading the production error handler and the committed contract before writing
  contract rules resolved the ambiguity about undocumented error bodies and kept the
  allow list to one operation.
- Two unordered `@BeforeAll` methods are a deterministic trap: any setup that creates
  a role another setup depends on must live in the same method or have explicit
  `@Order`; otherwise "green on main" depends on test execution order.
