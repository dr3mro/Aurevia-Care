# WFAUDIT-03 — publish slot images under immutable generation tags (proposed workflow patch)

## Summary

Added one proposed-patch document, `docs/operations/workflow-changes/slot-image-generations.md`. It records the problem (workers boot `<slot>:latest`, so a cancelled or partial publish changes what a wave runs; WFAUDIT-02's generation helpers are wired nowhere), designs a two-phase publish in `swarm-images.yml` (build/push `<slot>:g<run>-<sha12>`, verify every digest, then move `:latest` and `:last-good` with an ERR/TERM restore trap), wires `swarm.yml` to pass the last `slot-image-generations` ledger to `images-ready --generations` and to boot workers from the chosen generation, and supplies the exact unified diff, apply, GitHub verification and rollback steps.

## Findings

- The source defect is confirmed by file reads: `swarm.yml:160` boots `<slot>:latest`; `swarm-images.yml:58-59` pushes `:latest` directly; WFAUDIT-02's `--generations` input (`scripts/swarm.py:2887,2963`) is unused by `swarm.yml:109`. The new document closes the hand-off by proposing the workflow change without editing protected files.
- Environment artifact (not a defect from this change): `scripts/check.sh` fails at the first gate on the skip-worktree `opencode.json` CI profile; recorded with commands above.
- Bounded `aurevia-github-workflow` specialist review (evidence: file reads only, no commands) found four issues; all four were addressed in the scratch patch and re-verified before the document was updated:
  1. HIGH — `gh run download --dir DIR` keeps the artifact subfolder, so `DIR/generations.json` is wrong and the ledger would silently stay empty. Fixed with a path-independent `find DIR -type f -name generations.json -print -quit`; the dry-run stub now mimics the nested layout and the lookup succeeds.
  2. HIGH — `gh run list --status success --limit 1` can select a green run whose jobs were all skipped (no artifact). Fixed by scanning the newest 10 run ids and taking the first with a usable ledger; the stub returns artifact-free run 99 before run 100 and the loop selects 100.
  3. MEDIUM-HIGH — on a first publish there is no old `:latest` to restore, so a mid-phase-2 failure can leave a partial new pointer set. Mitigation kept: no ledger is uploaded so no wave uses it; the constraint wording was narrowed to "does not move an existing pointer" and scenario D plus a Residual-risk entry document the case.
  4. LOW-MEDIUM — `echo ... >> "$GITHUB_OUTPUT"` is not a job log line. Fixed by also echoing `generation=<tag>` to stdout; the verification step now matches the log.
- Evidence source for all findings: executed tool commands and direct file reads (no simulated-user or human evidence).

## Lessons for workers

- A proposed workflow patch must live in a document whose single `diff` block is verified with `git apply --check` **after** extraction from the committed document, not just from the scratch file; the `awk` extraction in the apply instructions was tested exactly as written.
- `jq -s` slurps a JSON array input as one element, so merging a new record with a previous ledger needs `jq -s '.[0:1] + .[1]'`; plain `jq -s .` produces a nested array and breaks WFAUDIT-02's `parse_generations`.
- In a cloud worker, `scripts/check.sh` failing at `check-pack: opencode.json is stale` is the documented skip-worktree CI profile (OPS-CW-003-01); confirm with `git ls-files -v opencode.json` and never regenerate or commit that protected file.
- For workflow-only stories, a synthetic stub dry-run of the exact shell block (stub `docker`/`gh`, real `jq` and helper) gives reproducible fail-closed evidence without a token or a GitHub run; make the stub mimic the real tool's quirks (nested artifact directory, green run without artifact), otherwise it cannot reveal the defects a reviewer found.
- `gh run list --status success` is not proof an artifact exists: a skipped-jobs run is green. Select by artifact presence, and locate the file with `find` rather than assuming the extraction path.
