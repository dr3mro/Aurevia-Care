## Lessons for workers

- For spec-clause proof tasks, survey the whole requirement first: the IAM-06 emergency-access code lives in `authz/access`, not in the `audit` package named by the task scope; the `audit` package only provides the OPS-02 append-only chain. The test package still follows the task's business-domain scope (`audit.clauses`).
- Use a unique database name per clause test (here `aurevia_emergency_scope_it`) and a distinct synthetic subject per grant, because `latestGrant` refuses stacked grants for one subject.
- In a cloud worker, treat a `check-pack`/`gen-opencode --check`/`test_check_pack` failure as a CI-profile measurement artifact until `git ls-files -v opencode.json` confirms `S`; never regenerate or edit that protected file.
- `mvn -Pno-security,fast -Dgroups=integration` does not run integration tests; for a single tagged test use the default profile with `-Dtest=ClassName` and read the Surefire report.
