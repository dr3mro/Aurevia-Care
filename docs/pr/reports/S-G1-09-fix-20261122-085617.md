## Lessons for workers

- On a fix pass for an evidence note, re-verify every cited test **method** and DB object by `grep`, not just that the file exists — a stale method name silently invalidates the evidence. Confirm the criteria wording against the exact spec row (`PROJECT_V1_SPEC.md:170` for G1).
- For a hand-off note, name the task that closes each open item, but keep "engineering evidence proven" strictly separate from "human acceptance open"; a `GATE-PACK-*` or `S-G5-*` task prepares evidence and never records approval.
- `scripts/check.sh` runs the full `apps/api/check.sh` verify/integration suite and is forbidden for workers; for a docs-only change use `python3 -I scripts/check-docs.py` plus `bash scripts/coverage-check.sh`.
- Conflict markers can be committed on `main` inside Javadoc. Run `git grep -nE '^(<<<<<<<|>>>>>>>) '` and inspect the surrounding lines before assuming they break the build; report out-of-scope markers rather than editing them.
