# Service level objectives and alert thresholds (OPS-03, OPS-04, OPS-05)

This page pins the operational targets from the [Aurevia Cloud V1 specification](../../.opencode/config/PROJECT_V1_SPEC.md)
to the signals that exist in this repository today. It is a **mapping, not a claim of
live monitoring**: a field, log line, evaluator or runbook entry below is code or a
declared envelope, not evidence that a production alert fired or that a person was
contacted. The [production readiness register](production-readiness/README.md) and
[launch checklist](production-readiness/launch-checklist.md) own the sign-off; this
page owns the target-to-signal trace.

A `NOT MEASURED YET` marker means the code has no runtime producer for the signal
and names the smallest follow-up story that would add one. No metric name is
invented here: every field, action key, constant and route written as code is
quoted from the file named beside it. Where the specification fixes no number,
the cell says so instead of supplying one.

## What is measured today, in one sentence

The API emits one structured JSON request line with `correlationId`, `method`,
`route`, `status` and `latencyMs` (WEB-06), and two status-only health routes
(WEB-05). Clinical, delivery and queue facts are persisted as domain records and
append-only audit events, and the recovery, capacity and queue contracts are
checked offline by evidence evaluators. None of those producers currently
publishes a request rate, error rate, p95, saturation, queue-age, delivery-age or
backup-age metric, and there is no alerting rule, on-call rota or external uptime
probe in this repository.

## Reading the table honestly

- The offline evaluators in `infra/s_g5_05` and `infra/s_g5_06` judge an evidence
  artifact, not a running system. A passing synthetic artifact is a rehearsal of
  the check and never final pilot evidence.
- The owner column gives the **role** named in the OPS-05 monitoring envelope and
  launch checklist. The rota, escalation contacts and response targets are
  approved site configuration (ADM-01); no person, phone number or address is
  stored here.
- Simulated reviews and synthetic fixtures produce no operational evidence. The
  G5 acceptance owner signs the real availability, load, restore and on-call
  evidence before any site is enabled.
- The 13 OPS-05 signals are enumerated in `s_g5_06/operational-runbooks.md`; the
  seven rows above are the objectives this page tracks. Additional signals
  (unmatched reports, missing coverage, unassigned patient messages, response
  breaches, failed instruction notifications, overdue instruction
  acknowledgments, rendering failures, error rates and saturation) keep the same
  owner mapping and the same distinction between a declared signal and an
  emitted metric.
