# Running the agent team in GitHub Actions

The agent team runs as the swarm: OpenCode workers on GitHub-hosted runners, coordinated only through `TODO.md`, pull requests and GitHub issues. [SWARM.md](SWARM.md) describes the whole flow; this page covers the image, the setup and the safeguards. The earlier issue-label team workflow (`story` label, `/oc` comments) has been retired.

## Files

- `.github/agent-image/Dockerfile` and `.github/workflows/agent-image.yml` build `ghcr.io/<owner>/<repo>-agent:latest` when the Dockerfile changes, monthly, or on demand; `swarm-images.yml` adds one layer per slot.
- `swarm.yml`, `swarm-worker.yml` and `swarm-integrator.yml` plan, work, publish and integrate. `fix-pr-gate.yml` validates repair pull requests.
- `swarm-watchdog.yml`, `swarm-issue-monitor.yml`, `daily-notes.yml` and `daily-audit.yml` keep it running without a person: failure and stall issues, issue hand-off to workers, the daily notes and the daily audit.
- `scripts/agent-run.sh` holds the agent steps and `scripts/swarm.py` the trusted logic; both are unit tested with fake `opencode` and `gh` under `scripts/tests`.
- `.github/opencode.ci.json` is the unattended permission profile, generated by `scripts/gen-opencode.py`.

## Setup

Follow the setup in [SWARM.md](SWARM.md#setup): run **Agent image** once, save `OPENCODE_API_KEY_<n>` per slot (or one `OPENCODE_API_KEY`), allow Actions to create pull requests, and save `SWARM_TOKEN`. Free models change and some retain prompts, so check each model's privacy note and use synthetic data only.

## What runs when

| Schedule (UTC) | Workflow |
|---|---|
| Every hour at :07 | `swarm.yml` safety-net wave, when work is waiting and no wave runs |
| Every hour at :37 | `swarm-issue-monitor.yml`: issues no worker was assigned |
| Every 15 minutes, and when a watched workflow finishes | `swarm-watchdog.yml`: failure and stall issues, closing finished ones |
| 05:10 daily | `daily-notes.yml`: reconcile yesterday's worker notes |
| 06:00 (summer) or 07:00 (winter) daily | `swarm-issue-monitor.yml`: 2:00 AM New York pass over issues with no progress for 24 hours |
| 07:17 daily | `daily-audit.yml` |
| 04:17 on the 1st | `agent-image.yml` refresh |

Everything else is event driven: a push to `TODO.md`, a finished wave, a pull request event or a manual dispatch.

## Safeguards

- Agent steps have no write token. Pushing, pull request creation, labels and issues happen in separate trusted jobs that run the scripts from `main`. The agent profile denies `gh`, `git push`, `git tag`, `curl`, `wget`, `ssh` and `docker`.
- Issues and comments are read only when written by the repository's automation or by an owner, member or collaborator; their text reaches agents as untrusted notes.
- Reviewers and the triage, audit and notes workers run read-only. Anything they write is validated before it lands: bounded text, safe scopes, no workflow, script or agent files, and the docs and secret checks Delivery runs.
- Do not make `Delivery gate` a required check on `main` while the integrator merges locally and pushes straight to `main`; a required check would reject its push.
- Use synthetic data only. Free models are not suitable for real patient data.
