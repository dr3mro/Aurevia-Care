# Running the agent team in GitHub Actions

Agents run OpenCode on GitHub-hosted runners with a free OpenCode model. They coordinate only through GitHub objects. All slow setup lives in a prepared image, so a run is: pull image, shallow checkout, agent, publish, stop.

| Step | Trigger | Who acts | Hand-off |
|---|---|---|---|
| Story | Label an issue `story`, or run the workflow with a story | Orchestrator | Branch `opencode/<story>-<run>` and a pull request (draft if checks failed) |
| Review | Automatic after a clean run | QA, DevSecOps and physician reviewers, one after another | One comment each on the pull request |
| Fix | A maintainer comments `/oc <change>` on the pull request | Orchestrator | New commit on the same branch |
| Merge | A human | Maintainer | Required checks pass |

## Files

- `.github/agent-image/Dockerfile` and `.github/workflows/agent-image.yml` build `ghcr.io/<owner>/<repo>-agent:latest` when the Dockerfile changes, monthly, or on demand.
- `.github/workflows/opencode-team.yml` is the team workflow. `scripts/agent-run.sh` holds the logic and is unit tested with fake `opencode` and `gh`.
- `.github/opencode.ci.json` is the unattended permission profile, generated by `scripts/gen-opencode.py`.

## Setup

1. Push to GitHub, then run the **Agent image** workflow once. Wait for it to finish before the first story.
2. Save an OpenCode API key from opencode.ai as the repository secret `OPENCODE_API_KEY`.
3. Optional: set the repository variable `OPENCODE_MODEL`. The default is `opencode/deepseek-v4.1-flash-free`. Free models change and some retain prompts, so check the model's privacy note.
4. Settings, Actions, General: allow Actions to create pull requests, and give the workflow read and write permission.
5. Create the `story` label. Require both image smoke checks and one human review on `main`.

## Why it stays fast and within limits

- Nothing is installed during a run. OpenCode, Git, gh, jq, Python and shellcheck are in the image.
- Runs queue behind one concurrency group (WIP one). The gate job is a few seconds on a stock runner, and the agent job only starts for a real trigger.
- The workflow never polls and has no schedule other than the monthly image build, so idle repositories use no Actions minutes or API calls.
- A model rate limit, a timeout (30 minutes per agent call, 75 for the job) or a failure ends the run, comments on the issue and skips the reviews. There are no retries.
- The pull request is opened once and reviews are posted in three comments, not many small calls.

## Safeguards

- The agent step has no GitHub token. Pushing and pull request creation happen in separate steps, so a prompt-injected issue cannot publish or read the token. The agent profile denies `gh`, `git push`, `git tag`, `curl`, `wget`, `ssh` and `docker`.
- Only the issue label, owner, member or collaborator comments, and writer dispatches start a run. Bot comments never do. Fork pull requests are refused.
- Reviewers run read-only. Any edit they make is discarded.
- Use synthetic data only. Free models are not suitable for real patient data.

## Known limits

- Pull requests made with the default `GITHUB_TOKEN` do not start other workflows, so the Delivery checks will not run on them automatically. Use a fine-grained token or GitHub App token for the publish step, or push an empty commit as a human.
- Unverified in this authoring environment: the GHCR image pull in Actions, the API key being read from `auth.json`, and OpenCode honoring `.github/opencode.ci.json` permissions. Run one test story and read the logs.
