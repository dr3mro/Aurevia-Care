## What was built

A deterministic, synthetic partner conformance harness plus a catalog of 13 named, replayable fixtures. No database, real partner, credential or patient data is involved, so the tests run in the fast tier and in the full gate.

Production classes (`g2/s_g2_10`):

| Class | Responsibility | Requirements |
|---|---|---|
| `EventKind` | Semantic partner event kind plus conformance rules: identifier matching, review opening, correction reopening, human-vs-transport acknowledgment | XCH-01–07, LAB-01, LAB-02 |
| `PartnerEvent` | Immutable event identity (sender + eventId), per-aggregate revision, issuer identifier, unit/payload; `comparable` enforces XCH-07 | XCH-01, XCH-04, XCH-07, LAB-01, LAB-02, ARC-05 |
| `Disposition`, `ProcessingResult` | Machine-readable processing outcome and reason code | ARC-03, ARC-05 |
| `RevisionRecord` | Immutable preserved revision; corrections append instead of replacing | XCH-04, LAB-02 |
| `ConformanceLedger` | Receiver emulation: sender/type-namespace dedup, per-aggregate version ordering, per-aggregate identifier binding, reconciliation of unknown and conflicting ids, bounded retry with dead-letter, replayable held events, immutable history, review open/close, release pinned to a revision | ARC-05, XCH-01–07, LAB-01, LAB-02 |
| `ConformanceFixture`, `ConformanceFixtures` | Named catalog with expected dispositions, per-aggregate identity bindings and a fresh configured receiver per scenario | all of the above |

## Acceptance mapping (entry point → test)

- `ConformanceFixtures.all()` → `everyFixtureProducesItsDeclaredDispositions`: replays all 13 catalog entries through `ConformanceLedger.apply` and compares every recorded `Disposition`.
- `ConformanceLedger.apply` duplicate path → `duplicateDeliveryHasNoSecondEffect` (one seen identity, one revision) and `dedupNamespaceIsScopedToSenderAndKind` (same id under another sender/kind is not deduplicated).
- `ConformanceLedger.apply` correction history → `correctionPreservesThePriorRevisionAndReopensReview` (3 revisions preserved, original rev 1 unchanged, correction reopens review).
- `ConformanceLedger.apply` retry loop → `partialOutageRetriesThenAppliesExactlyOnce` (3 attempts, one effect), `fullOutageDeadLettersWithoutCreatingAnEffect` (3 attempts, dead-letter, no effect) and `deadLetteredEventIsReprocessableAfterRecovery` (DEAD_LETTER → APPLIED, one revision, dead-letter history retained).
- `ConformanceLedger.apply` identifier match → `unmatchedIdentifierWaitsInTheReconciliationQueue`, `knownIdentifierOnWrongAggregateWaitsForReconciliation` and the unknown-aggregate case in `ledgerFailsClosedOnInvalidConfigurationAndRecordsEmptyState`.
- `ConformanceLedger.apply` version ordering → `outOfOrderRevisionIsHeldWithoutOverwritingTheLatest`.
- `ConformanceLedger.apply` ack semantics → `transmissionAckCannotCloseClinicalReviewButClinicalAckCan`.
- `ConformanceLedger.apply` release → `patientReleaseStaysBoundToTheOriginalImmutableRevision`.
- `PartnerEvent.comparable` → `trendingComparesOnlyNumericSameTestSameUnitObservations` including assertions on the actual F13 fixture events.
- Catalog integrity → `fixtureCatalogIsCompleteNamedAndTraceable` (13 unique ids, requirement strings, byId found/not-found).
