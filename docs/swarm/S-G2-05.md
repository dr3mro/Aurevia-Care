## Defects found

1. **Tool gap (outside this scope): `db/check.sh` applies migrations in lexicographic shell-glob
   order.** With a two-digit version the unguarded V23 ran third (V1, V23, V2, …) and failed with
   `psql: V23__critical_results.sql:43: ERROR: relation "public.patient_record" does not exist`.
   V19–V28 reserved by the parallel G2 workers hit the same gap. Mitigation inside the reserved
   migration: a prerequisite guard makes an out-of-order offline apply a no-op; Flyway applies by
   numeric version and always installs the prerequisites first, so the full schema is created in
   every real/CI apply. `db/check.sh` is now green. Recommended follow-up (owner: tooling): sort
   `db/migrations/V*.sql` numerically in `db/check.sh` instead of relying on glob order, then remove
   the compatibility guard. This is recorded here rather than in BUGS.md because workers must not
   edit shared trackers.
2. **Pre-existing local environment noise, not caused by this change:** `scripts/quick-check.sh` and
   the Python suite fail on this worker because the worktree `opencode.json` is the CI profile copied
   under `skip-worktree` (`gen-opencode.py --check`: “out of date”), and `PyYAML` is not installed
   (4 import errors). Two `test_agent_run` assertions also fail because that drift makes the fast
   check fail inside their temporary repositories. All component checks unrelated to those artifacts
   pass; no tracker or generated config was modified.
