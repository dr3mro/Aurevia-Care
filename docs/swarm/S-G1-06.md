## Design decisions and assumptions (need owner acknowledgement)

1. **"Applicable prior follow-up" semantics.** Implemented as: an applicable existing follow-up takes precedence over the configured interval, and the explanation names both the prior appointment id and the configured interval. This avoids silently overriding an already scheduled commitment. The alternative (earlier-of rule) is a one-method change with a test. This is a synthetic assumption; a clinical owner should confirm the policy before live enablement.
2. **No invented clinical default.** If neither an approved interval nor an applicable prior exists, `suggest` returns 422 `NO_FOLLOW_UP_RULE` rather than a default interval. ADM-01 site approval must provide the interval.
3. **ActionPolicy reuse (no shared edits).** `suggest`/task read → `APPOINTMENT_READ`; `override` → `APPOINTMENT_RESCHEDULE`; `confirm`/task create → `APPOINTMENT_BOOK`; task outcome → `APPOINTMENT_COMPLETE`. Consequence: `clinician` can read and record outcomes but cannot override or confirm; a dedicated CLN-06 action is a later IAM story. `ActionPolicy` was not edited (out of scope).
4. **Unwired slice.** No Spring annotations on new types, so `OreviaApiApplicationTest`'s component scan is untouched. Ports, V16 migration, a `web` controller and outbox wiring belong to a follow-up story. This slice is testable domain logic, **not a releasable live workflow**.
5. **Civil-date arithmetic.** Follow-up dates are `LocalDate` in the facility's IANA zone; instants are stored with zone context (UX-01), avoiding a DST hour shift.
6. **JaCoCo probe quirk found and fixed.** An always-throwing `conflict(...)` helper left its caller lines reported as uncovered even though a stack trace proved execution. Refactored the helper to return `ApiException` and throw at the call site; coverage then reached 100%. Reusable lesson for this repo: do not hide `throw` inside a helper when the bundle 100% line gate applies.
