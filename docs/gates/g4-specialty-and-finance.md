## Entry point to test trace

- **Wrong-patient study link.** HTTP `POST /api/v1/imaging/orders/{orderId}/studies`, `GET /api/v1/imaging/orders/study-link-reviews`, `POST /api/v1/imaging/orders/study-link-reviews/resolve` (`ImagingControllerHttpTest.mismatchQueuesAReviewAndReLinkAfterReviewThroughHttp`). `ImagingService` verifies patient, accession, role, version and tenant before setting a Study Instance UID; a mismatch mutates nothing and opens an OPEN review.
- **Radiology addendum.** HTTP `POST /api/v1/radiology/reports`, addendum publication and `GET /api/v1/radiology/reports/events`, `GET /api/v1/radiology/reports/addenda/open`, `POST /api/v1/radiology/reports/{id}/addenda/{version}/acknowledge` (`ReportControllerHttpTest`). A signed addendum links to the prior interpretation and emits a referrer-addressed notification and an OPEN addendum the verified referrer can read and acknowledge.
- **PT discharge.** HTTP referral accept and episode read (`TherapyControllerHttpTest`) over a `JdbcTherapyStore` behind `TherapyService` (`JdbcTherapyStoreIntegrationTest.signedNoteIsImmutableAndDischargeClosesTheReferral`). "Referral closure" in this domain is the episode reaching `DISCHARGED` after a signed discharge note; there is no separate referral-status entity. The signed note is immutable and tenant-scoped in the database.
- **Ambiguous prescription.** HTTP create/attest/transmit/verify/retry on the prescription routes (`RxTransmissionFlowTest`, `RxHttpSecurityTest`). One stable submission id is recorded once; retry is refused until partner status is verified absent, and a retry appends a fact without a second logical submission.
- **Finance replay.** HTTP invoice create/issue/payments/refunds (`FinanceFlowTest.refundReestablishesIssuedStateAndReplayIsANoOp`, `FinanceHttpSecurityTest`). A recorded reference replays the committed balance, version, entries and receipt numbers; a reused reference with a different payload is a conflict. Finance roles see amounts, not clinical narrative.
