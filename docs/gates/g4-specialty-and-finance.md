## Purpose

Section 9 of `SMARTCLINIC_V1_SPEC.md` (G4 — specialty and finance) lists the required evidence for radiology, physical therapy, pharmacy and self-pay. This note splits that evidence into the five criteria named in the gate task and maps each one to a merged test that exists on `main` today, with a status. It prepares evidence for a person to accept; it never records acceptance. Acceptance of G4 is a human Product Owner decision, and the clinical and privacy sign-offs that gate real use stay human decisions (G5). A merged test proves an engineering behaviour, not that a person has accepted it.

Only evidence merged on `main` is linked. A design document, a simulated UAT script, an open task title or a naming claim alone is not treated as proof of a behaviour. All five rows below are led by the BUILD-64 acceptance tests (PR #494, squash merge commit `206fff6b7b51591e774e54b9f28adfc02c2eecaf`, merged into `main`); each cited class, method and negative case was read directly. Where a domain-level acceptance test is backed by an HTTP-level or integration test, both are named so a reviewer can trace the entry point.

Requirement scope: RAD-01 supplies the study-link verification and addendum rules; PT-01 supplies the signed episode and referrer-summary rules; RX-02 supplies the stable submission identity and partner-status-before-retry rule; FIN-01 supplies the immutable linked ledger entries, reference deduplication and balance rules.

## Entry point to test trace

- **Wrong-patient study.** Domain entry `ImagingService.associateStudy(AssociateStudyCommand)` (`RadiologyWrongPatientStudyRefusedAcceptanceTest`); HTTP `POST /api/v1/radiology/worklist/orders/{orderId}/studies` (`WorklistControllerHttpTest.linking_a_study_for_the_wrong_patient_is_refused_over_http`) and `POST /api/v1/imaging/orders/{orderId}/studies` plus `GET /api/v1/imaging/orders/study-link-reviews` and `POST /api/v1/imaging/orders/study-link-reviews/resolve` (`ImagingControllerHttpTest.mismatchQueuesAReviewAndReLinkAfterReviewThroughHttp`). A mismatch queues an OPEN link review and never emits `STUDY_ASSOCIATED`.
- **Addendum to referrer.** Domain entry `ImagingService.addAddendum(AddendumCommand)` (`RadiologyAddendumReachesReferrerAcceptanceTest`); HTTP `POST /api/v1/radiology/reports/{orderId}/addenda` and `POST /api/v1/radiology/reports/{orderId}/addenda/{version}/acknowledge` (`ReportControllerHttpTest.addendum_notifies_the_referrer_and_acknowledgment_closes_it_over_http`). A signed addendum appends `ADDENDUM_LINKED` then `REFERRER_NOTIFIED` addressed to the verified referrer; an invalid addendum appends neither.
- **Therapy discharge.** Domain entry `TherapyService.acceptReferral`, `recordNote`, `signNote`, `sendSummary` and `acknowledgeReturn` against the injected store (`TherapyDischargeAcceptanceTest`); HTTP `POST /api/v1/therapy/episodes` and `GET /api/v1/therapy/episodes/{episodeId}` (`TherapyControllerHttpTest`); JDBC/persistence path `JdbcTherapyStore` with `TherapyEpisodeFlowTest.signsDischargeTransitionsEpisodeAndSendsApprovedSummaryWithReturnAcknowledgment`. Signing a discharge after a signed session closes the episode and binds the summary acknowledgment to its exact version.
- **Ambiguous prescription.** Domain entry `RxService.transmit`, `verifyPartnerStatus` and `retry` (`PharmacyAmbiguousTransmissionAcceptanceTest`); HTTP `POST /api/v1/prescriptions/{id}/transmit`, `POST /api/v1/prescriptions/{id}/verify-partner-status` and `POST /api/v1/prescriptions/{id}/retry` (`RxTransmissionFlowTest.ambiguousRetryIsBlockedUntilPartnerStatusIsVerifiedAbsent`). The stable submission id is inserted once; a partner status must be verified absent before a retry is issued, and a present status returns the prescription to SUBMITTED with no second send.
- **Finance replay.** Domain entry `FinanceService.postEntry` with its `FinanceRepository.findByReference` digest replay check (`FinanceLedgerReplayAcceptanceTest`, `FinanceService`/`FinanceRepository`); HTTP `POST /api/v1/finance/invoices/{id}/payments` and `/refunds` and `GET /api/v1/finance/reconciliation` (`FinanceFlowTest.refundReestablishesIssuedStateAndReplayIsANoOp`, `aReusedReferenceWithADifferentPayloadIsRejected`). A recorded reference is idempotent by digest; a reused reference with a different payload is a 409 conflict and never posts money twice.
