# Data dictionary

**Newest migration covered: `V90__onboarding_import.sql` (version 90).** This page describes every table created by the Flyway migrations present in `db/migrations`, from `V1__tenant_schema.sql` through `V90__onboarding_import.sql`. The SQL files are the authoritative source; where a summary here disagrees with a migration, the migration wins.

Focus: **ARC-01** (tenant-owned domain keys), **ARC-02** (forced row-level isolation) and **OPS-06** (expand/contract migration change safety). Requirement IDs in a table's `Migration` line are copied from that migration's header.

## How to read this document

- **Tenant ownership.** Every table except `organization` carries `organization_id` in its primary key, and every internal foreign key is composite `(organization_id, …)`. Local identifiers are unique only within a tenant, so the same local id in two tenants cannot collide. `organization` is the root keyed by `organization_id` alone.
- **Isolation.** `FORCE ROW LEVEL SECURITY` plus a `tenant_isolation` policy of `organization_id = public.app_org()` is the norm; `app_org()` reads the transaction-local `app.current_org` GUC and returns NULL when it is unset, so a statement with no tenant context returns no rows (fails closed). `exchange_work_item` is the one deliberate exception: it has a two-party read/insert/update policy (sender or verified destination). A few migrations (V24) spell the expression out inline instead of calling `app_org()`; the effect is the same.
- **Writes.** `Append-only` means the runtime role gets `INSERT` only (sometimes `SELECT, INSERT`), `UPDATE`/`DELETE`/`TRUNCATE` are revoked, and an immutability trigger rejects mutation for *every* role including the migration owner. `Bounded UPDATE` means the row advances through a guarded state machine (`version = OLD.version + 1`, ownership columns pinned, transitions enumerated) and `DELETE`/`TRUNCATE` are revoked. `Read-only` means the runtime role has `SELECT` only.
- **Migration.** The version that created the table and the version of its last structural or policy change. Several migrations wrap their DDL in `IF to_regclass(...) ... RAISE NOTICE ... RETURN` guards because the offline `db/check.sh` runner applies files in lexicographic filename order (a two-digit version before V2/V4/V7); Flyway applies by numeric version, so under Flyway the prerequisites always exist and the guard never skips the table. These are called out below as *conditional DDL*.
- **UNCLEAR:** marks a column whose meaning, unit or permitted values cannot be determined from the migration alone; a question is recorded instead of a guess.
- Types are written as they appear in the `CREATE TABLE` statement (`uuid`, `text`, `timestamptz`, `date`, `time`, `smallint`, `integer`, `bigint`, `numeric`, `boolean`, `bytea`, `jsonb`, `text[]`). `GENERATED BY DEFAULT AS IDENTITY` appears as `bigint identity`.

## 1. Tenant, identity, staff and configuration

### `organization`

**Purpose.** A tenant: the root of every tenant-owned key and the boundary of forced RLS.

| Column | Type | Meaning |
|---|---|---|
| organization_id | uuid | Tenant identifier; generated by default. |
| display_name | text | Human-readable tenant name. |
| created_at | timestamptz | Row creation instant. |

**Keys/constraints.** Primary key `organization_id`. There is no `organization_id` column because this *is* the tenant row.
**Isolation / writes.** Forced RLS, policy `organization_id = app_org()`. The runtime role has `SELECT` only (V2).
**Migration.** Created V1__tenant_schema.sql (IAM-01, ARC-01, ARC-02, OPS-02); RLS and grants V2; no later column change.

### `user_identity`

**Purpose.** A staff or actor identity inside a tenant, keyed by its authentication subject.

| Column | Type | Meaning |
|---|---|---|
| organization_id | uuid | Tenant. |
| id | uuid | Opaque local identity id. |
| subject | text | Authentication subject; the value carried in the `app.actor` GUC. |
| display_name | text | Human-readable name. |
| status | text | `active` or `deactivated`. |
| created_at | timestamptz | Row creation instant. |

**Keys/constraints.** PK `(organization_id, id)`; `UNIQUE (organization_id, subject)`; `status` CHECK. `subject` is referenced by composite foreign keys from clinical and ledger tables.
**Isolation / writes.** Forced RLS; append-only for every role (V4 triggers reject UPDATE/DELETE/TRUNCATE); the runtime role may `INSERT` (invite) but not rewrite history.
**Migration.** Created V1; RLS V2; append-only triggers V4; no later column change.

### `facility`

**Purpose.** A physical site inside a tenant; the civil time zone for scheduling and display.

| Column | Type | Meaning |
|---|---|---|
| organization_id | uuid | Tenant. |
| id | uuid | Opaque local facility id. |
| code | text | Site-local code; unique per tenant; used by composite FKs (e.g. emergency grants). |
| name | text | Human-readable site name. |
| time_zone | text | IANA time-zone name; default `UTC`, validated by the application (`ZoneId`), not by a CHECK. |

**Keys/constraints.** PK `(organization_id, id)`; `UNIQUE (organization_id, code)`.
**Isolation / writes.** Forced RLS; `SELECT, INSERT` granted, plus column-scoped `UPDATE (time_zone)` in V8; no DELETE/TRUNCATE path.
**Migration.** Created V1; RLS V2; last changed V8 (added `time_zone` column and its narrow UPDATE grant).

### `membership`

**Purpose.** An append-only event stream of a user's membership; the current status is folded on read at `now()`.

| Column | Type | Meaning |
|---|---|---|
| organization_id | uuid | Tenant. |
| id | uuid | Membership-event id. |
| user_id | uuid | Local `user_identity.id`. |
| status | text | `active` or `revoked` (deactivation is a new row, never an UPDATE). |
| valid_from | timestamptz | Start of the event's effective window. |
| valid_to | timestamptz | Optional end of the effective window. |
| created_at | timestamptz | Database-owned event time (`clock_timestamp()`), used to order events in one transaction. |

**Keys/constraints.** PK `(organization_id, id)`; FK `(organization_id, user_id)`; CHECK `valid_to IS NULL OR valid_to > valid_from`. Index on `(organization_id, user_id, valid_from DESC)`.
**Isolation / writes.** Forced RLS; append-only for every role; `INSERT` granted for invite/deactivate, no UPDATE/DELETE/TRUNCATE.
**Migration.** Created V1; RLS V2; immutability and timestamp triggers V4; an AFTER INSERT capture trigger added V71; no column change.

### `role_assignment`

**Purpose.** Append-only role grants with effective dates; the actor grantor is derived from the transaction context.

| Column | Type | Meaning |
|---|---|---|
| organization_id | uuid | Tenant. |
| id | uuid | Grant-event id. |
| membership_id | uuid | Membership event this grant belongs to. |
| role_key | text | Bounded role name (e.g. `tenant_admin`, `reception`, `privacy_auditor`). |
| granted_by | uuid | `user_identity.id` of the grantor; set trigger-side from `app.actor` (or `app.grantor_subject` during invitation acceptance). |
| valid_from | timestamptz | Start of the grant's effective window. |
| valid_to | timestamptz | Optional end of the effective window. |

**Keys/constraints.** PK `(organization_id, id)`; FKs to `membership` and to `user_identity` (grantor); CHECK `valid_to IS NULL OR valid_to > valid_from`; index on `(organization_id, membership_id)`.
**Isolation / writes.** Forced RLS; append-only for every role; `INSERT` granted, no UPDATE/DELETE/TRUNCATE.
**Migration.** Created V1; RLS V2; immutability and grantor triggers V4; grantor function redefined V70; role-change capture trigger added V71; no column change.

### `role_change_history`

**Purpose.** Append-only ledger of every role grant, change and revocation, populated by database triggers on `role_assignment` and `membership`.

| Column | Type | Meaning |
|---|---|---|
| organization_id | uuid | Tenant. |
| id | uuid | Ledger row id. |
| subject | text | Subject whose role changed. |
| role_key | text | Role affected. |
| change_kind | text | `GRANT`, `CHANGE` or `REVOKE`. |
| actor | text | Acting subject from `app.actor` (nullable). |
| recorded_at | timestamptz | Database time the event was recorded. |
| effective_from | timestamptz | Start of the role's effective window. |
| effective_to | timestamptz | End of the window; required for `REVOKE`. |

**Keys/constraints.** PK `(organization_id, id)`; CHECKs `effective_to >= effective_from`, REVOKE requires `effective_to`, non-empty subject and role key; index on `(organization_id, subject, effective_from DESC, id DESC)`.
**Isolation / writes.** Forced RLS declared here; append-only for every role. The runtime role has `SELECT` only; only the trigger function (granted to `aurevia_migrate`) can append.
**Migration.** Created V71__build_02.sql (IAM-02, ARC-02, OPS-02).

### `staff_invitation`

**Purpose.** Single-use, expiring staff invitations whose raw token is returned once and only its SHA-256 hash is stored.

| Column | Type | Meaning |
|---|---|---|
| organization_id | uuid | Tenant. |
| id | uuid | Invitation id. |
| subject | text | Subject to be created on acceptance. |
| display_name | text | Name for the new identity. |
| facility_id | uuid | Facility the invitee joins. |
| roles | text[] | Bounded, non-empty, distinct role keys (subset of `tenant_admin`, `reception`, `privacy_auditor`). |
| token_hash | text | SHA-256 hash of the raw invitation token. |
| invited_by | text | Subject of the tenant administrator who issued it (set trigger-side). |
| expires_at | timestamptz | Expiry; must be after `created_at`. |
| used_at | timestamptz | Consumption instant; set atomically by `accept_staff_invitation`. |
| revoked_at | timestamptz | Revocation instant; set by `revoke_staff_invitation`. |
| created_by | text | Issuing administrator subject (set trigger-side). |
| created_at | timestamptz | Row creation instant. |

**Keys/constraints.** PK `(organization_id, id)`; `UNIQUE (organization_id, token_hash)`; FK `(organization_id, facility_id)`; CHECKs on expiry and role array; a trigger enforces distinct roles and an active `tenant_admin` issuer.
**Isolation / writes.** Forced RLS; `SELECT, INSERT` plus column-scoped `UPDATE (used_at, revoked_at)`; no DELETE/TRUNCATE. Acceptance is one guarded transaction that consumes the token and appends identity, membership and role rows.
**Migration.** Created V70__build_01.sql (IAM-02, ARC-01, ARC-02, OPS-02).

### `appointment`

**Purpose.** A booked or held visit; the database is the authority for protected-slot non-overlap and the state machine.

| Column | Type | Meaning |
|---|---|---|
| organization_id | uuid | Tenant. |
| id | uuid | Appointment id. |
| version | integer | Positive revision; advances by exactly one per state change. |
| patient_id | uuid | Local patient id. |
| facility_id | uuid | Facility. |
| clinician_resource_id | uuid | Clinician resource; generated `clinician_kind` tag pins its kind. |
| room_resource_id | uuid | Optional room resource; generated `room_kind` tag pins its kind. |
| visit_type | text | Code from `visit_type`. |
| starts_at | timestamptz | Slot start. |
| ends_at | timestamptz | Slot end; must be after `starts_at`. |
| state | text | `held`, `booked`, `checked_in`, `in_progress`, `completed`, `cancelled`, `no_show`, `expired`. |
| series_id | uuid | Optional recurrence-series identifier. `UNCLEAR:` what defines a series and how it is created — the migration declares the column but no series table or generator. |
| expires_at | timestamptz | Required when `state = 'held'`. |
| override_reason | text | Optional reason for an override. `UNCLEAR:` which operation requires an override and what values are accepted. |
| created_by | uuid | Author id from `app.actor` (set trigger-side). |
| created_at | timestamptz | Row creation instant. |
| clinician_kind | text | Generated constant `clinician`. |
| room_kind | text | Generated `room` when a room is present, else NULL. |

**Keys/constraints.** PK `(organization_id, id)`; CHECKs `ends_at > starts_at` and held ⇒ `expires_at`; seven composite FKs (patient, facility, clinician/room kind and facility membership, visit type, author); two partial GiST `EXCLUDE` constraints prevent overlapping live slots (`held`, `booked`, `checked_in`, `in_progress`) for the same clinician or room. The update guard pins ownership, requires `version + 1` and enumerates allowed transitions.
**Isolation / writes.** Forced RLS; bounded UPDATE via the state machine; DELETE/TRUNCATE rejected by triggers.
**Migration.** Created V8 (CLN-01, ARC-01, ARC-02, OPS-02).

## 9. Finance

All four tables below were created by V45__finance.sql (FIN-01, ARC-01, ARC-02, ARC-03, OPS-02). ## Cross-cutting notes

### Requirement mapping

- **ARC-01 (domain keys).** Every tenant-owned table keys on `(organization_id, id)` or a domain-specific composite key that always begins with `organization_id`. Issuer-scoped uniqueness appears in `patient_record` (MRN), `lab_accession` (accession), `flow_policy` (locale/platform) and the XCH-04 lineage keys. The two-party `exchange_work_item` projection still carries `organization_id` in its key.
- **ARC-02 (isolation).** Forced RLS with a `tenant_isolation` policy is declared on every tenant table, including each new table added after V2 (later migrations cannot rely on V2's static list). The runtime role `aurevia_app` is a non-owner without `BYPASSRLS`; append-only facts are additionally protected by triggers that bind the migration owner. `exchange_work_item` is the single bounded cross-tenant exception, with sender/destination policies.
- **OPS-06 (migration change safety).** `scripts/check-migrations.py` enforces unique versions, expand/contract headers and prior-expand references. All migrations present are `Change: expand` (or unlabelled baseline files); there is no `contract` migration in this coverage range. Gaps in version numbers (V13–V14, V16, V18, V27–V32, etc.) are expected: workers own reserved versions and merge independently, and Flyway applies by numeric version.
