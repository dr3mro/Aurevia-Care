# Module guide: audit trail (`com.aurevia.audit`)

The `audit` package is the shared OPS-02 sink and review boundary for the backend: `AuditAppender` lets any domain service add one tamper-evident event inside its own guarded transaction, while `AuditRepository`, `AuditService` and the web adapter expose a bounded, tenant-confined, cursor-paged read of that trail with audit-of-read. It owns the value types and the authorization, validation and paging invariants for audit review; the table DDL, forced RLS and append-only hash-chain triggers that make the trail durable live in Flyway migrations, not in this package ([AuditAppender.java](../../../apps/api/src/main/java/com/aurevia/audit/AuditAppender.java), [AuditService.java](../../../apps/api/src/main/java/com/aurevia/audit/AuditService.java), [AuditRepository.java](../../../apps/api/src/main/java/com/aurevia/audit/AuditRepository.java)).

Primary requirement: OPS-02 (audit clinical reads, queries, exports, downloads, disclosures, auth, emergency access, mutations and administration with actor, purpose, scope, timestamp, action, resource ID, correlation ID and outcome; append-only, restricted, tamper-detecting). The clause tests filed with this package also prove IAM-06 recording of purpose, role, facility and user for sensitive actions ([PROJECT_V1_SPEC.md](../../../.opencode/config/PROJECT_V1_SPEC.md)).

## Entry points

This package declares no `@RestController`, no scheduled job, no command and no event handler. Its HTTP route lives in `com.aurevia.web` and its append API is a library call made by other domain services; the "Who may call it" column names the actor or layer that may invoke each entry point. Roles are re-derived server-side from the active membership and are never accepted from the client.

| Entry point | Kind | Who may call it / when | Source |
|---|---|---|---|
| `GET /api/v1/audit-events` (`AuditController.query`) | HTTP route in the `web` package | An authenticated subject with an active membership in the selected organization and `AUDIT_READ` permission; `ActionPolicy` grants that action to `tenant_admin` and `privacy_auditor` only. Reception, clinicians, unauthenticated callers and cross-tenant selections are refused (401, 403 or 422). Binds `cursor`, `limit`, `action`, `outcome`, `resourceType`, `from`, `to` | [AuditController.java](../../../apps/api/src/main/java/com/aurevia/web/AuditController.java), [ActionPolicy.java](../../../apps/api/src/main/java/com/aurevia/authz/ActionPolicy.java), [openapi.yaml](../../../contracts/openapi.yaml) |
| `AuditService.query(...)` | Domain service | Called by `AuditController.query` only; parses and validates every query parameter, authorizes, pages and records the read | [AuditService.java](../../../apps/api/src/main/java/com/aurevia/audit/AuditService.java) |

| `AuditRepository.hasActiveMembership(subject)` / `activeRoles(subject)` | Authorization lookup | Called by `AuditService.authorize` on every query, so revocation applies on the next request | [AuditRepository.java](../../../apps/api/src/main/java/com/aurevia/audit/AuditRepository.java) |

## Tables it reads and writes

`AuditRepository` is the single read boundary and `AuditAppender` plus `AuditRepository.appendAudit` are the write boundaries; both target `public.audit_event`. The table, its row-level security and its tamper-evidence are declared in migrations.

| Table / schema object | Relationship | Source |
|---|---|---|
| `public.audit_event` | Written by `AuditAppender.append` and `AuditRepository.appendAudit`; read by `AuditRepository.query`. V1 declares organization_id, id, occurred_at, actor_id, action, resource_type, resource_id, purpose, scope, correlation_id, outcome, seq, previous_hash and row_hash, with primary key on (organization_id, id), unique (organization_id, seq) and an (organization_id, occurred_at DESC) index | [V1__tenant_schema.sql](../../../db/migrations/V1__tenant_schema.sql), [AuditAppender.java](../../../apps/api/src/main/java/com/aurevia/audit/AuditAppender.java), [AuditRepository.java](../../../apps/api/src/main/java/com/aurevia/audit/AuditRepository.java) |
| Forced RLS and grants on `audit_event` | V2 enables and forces row-level security with the `tenant_isolation` policy `organization_id = app_org()`, grants SELECT and INSERT to `aurevia_app`, and revokes UPDATE and DELETE from it. A foreign tenant's rows are concealed, not merely filtered by the query | [V2__rls_roles_policies.sql](../../../db/migrations/V2__rls_roles_policies.sql) |
| `public.audit_event_before_insert()` trigger | V3 fires on every insert: it takes a per-organization advisory lock, assigns `seq` from `max(seq) + 1` (never from the caller), resolves `actor_id` from `app.actor` when the writer passes NULL, and links `previous_hash` and `row_hash` into a SHA-256 chain | [V3__audit_chain.sql](../../../db/migrations/V3__audit_chain.sql) |
| Actor-scope hardening of the insert trigger | V98 replaces the same function so the `user_identity` lookup is bound to `NEW.organization_id` as well as the subject, closing a cross-tenant actor stamp by a mismatched session context; the sequence, hash material and return contract are unchanged, so existing chains still verify | [V98__audit_actor_tenant_scope.sql](../../../db/migrations/V98__audit_actor_tenant_scope.sql) |
| `audit_event_no_update_delete` trigger and `audit_verify_chain(uuid)` | V3 rejects UPDATE or DELETE with SQLSTATE 44000 and verifies chain continuity, seq gaps and hash mismatches; verification refuses an organization other than the active tenant | [V3__audit_chain.sql](../../../db/migrations/V3__audit_chain.sql) |
| `public.has_active_membership(subject)` and `public.active_roles(subject)` | Read by `AuditRepository` for the authorization decision; they fold the V1 `user_identity`, `membership` and `role_assignment` tables, which V4 makes append-only for every role | [AuditRepository.java](../../../apps/api/src/main/java/com/aurevia/audit/AuditRepository.java), [V1__tenant_schema.sql](../../../db/migrations/V1__tenant_schema.sql), [V4__staff_lifecycle.sql](../../../db/migrations/V4__staff_lifecycle.sql) |
| `public.user_identity` | Read indirectly by the V3 and V98 insert trigger to resolve the actor id from the transaction-local subject | [V3__audit_chain.sql](../../../db/migrations/V3__audit_chain.sql), [V98__audit_actor_tenant_scope.sql](../../../db/migrations/V98__audit_actor_tenant_scope.sql) |

## Events published or consumed

**None.** No class in the package publishes or consumes a domain event, and no `@EventListener`, message sender or outbox call appears in its sources. The append-only `audit_event` row is the durable record: a successful review appends `AUDIT_READ` with outcome `SUCCESS`, and an authorization failure appends `AUDIT_READ` with outcome `DENIED` before the exception is thrown ([AuditService.java](../../../apps/api/src/main/java/com/aurevia/audit/AuditService.java), [AuditRepository.java](../../../apps/api/src/main/java/com/aurevia/audit/AuditRepository.java)). Durable inter-service events belong to the separate `events` package and its outbox.

## Things to know

- **The actor is never caller-supplied.** Both append paths insert `actor_id = NULL`; the V3 trigger fills it from `app.actor`, and V98 binds that lookup to the row's organization so a SECURITY DEFINER worker or a BYPASSRLS maintenance role cannot stamp a foreign actor. The correlation id comes from the tenant context ([AuditAppender.java](../../../apps/api/src/main/java/com/aurevia/audit/AuditAppender.java), [V98__audit_actor_tenant_scope.sql](../../../db/migrations/V98__audit_actor_tenant_scope.sql)).
- **Reads are audited and denials survive.** A successful query writes `AUDIT_READ/SUCCESS` in the same guarded transaction; a missing membership or permission writes `AUDIT_READ/DENIED` and then throws 403. A failure after the read would roll both the page and the success row back ([AuditService.java](../../../apps/api/src/main/java/com/aurevia/audit/AuditService.java)).
- **The trail is append-only and tamper-detecting.** V3 assigns the sequence and links each row to its predecessor with SHA-256, rejects UPDATE and DELETE, and exposes `audit_verify_chain(uuid)` only to `aurevia_app`; verification of another tenant's id fails instead of switching context ([V3__audit_chain.sql](../../../db/migrations/V3__audit_chain.sql)).
- **The cursor is an exclusive per-tenant sequence, not an offset.** The service fetches one row beyond the requested limit to compute `nextCursor`, orders by `seq DESC`, and bounds the limit to 1–200 with a default of 50. Filters accept only a 1–64 character allowlist and time bounds are parsed as UTC instants, so malformed input yields 422 rather than SQL ([AuditService.java](../../../apps/api/src/main/java/com/aurevia/audit/AuditService.java), [AuditRepository.java](../../../apps/api/src/main/java/com/aurevia/audit/AuditRepository.java)).
- **This package owns the primitive, not every producer.** With 29 importing production classes, `audit_event` is a cross-cutting sink: a reviewer looking for who writes a given action must search the calling services, not only this package ([AuditAppender.java](../../../apps/api/src/main/java/com/aurevia/audit/AuditAppender.java)).
- **There are no commands, jobs or event consumers here.** The only runtime entry point is the GET route; the durable side effect of any audit review is the row it appends ([AuditController.java](../../../apps/api/src/main/java/com/aurevia/web/AuditController.java), [AuditService.java](../../../apps/api/src/main/java/com/aurevia/audit/AuditService.java)).
