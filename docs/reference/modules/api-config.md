# Module guide: configuration and operational queues (`com.aurevia.config`)

The `config` package supplies the backend's cross-cutting runtime wiring and its operational-work domain model: a shared UTC clock, a production startup guard, and the immutable work-item and missing-coverage queue projections built from configured roster facts. It declares no HTTP controller, JDBC store, scheduled job or event handler, so every entry point is either a Spring lifecycle hook or a library call made by an owning package ([ClockConfiguration.java](../../../apps/api/src/main/java/com/aurevia/config/ClockConfiguration.java), [ProductionSafetyCheck.java](../../../apps/api/src/main/java/com/aurevia/config/ProductionSafetyCheck.java), [OperationalQueueItem.java](../../../apps/api/src/main/java/com/aurevia/config/queues/OperationalQueueItem.java)).

Primary requirement: ADM-01, under which tenant admins configure coverage rosters and other clinical or market policies with named approval, effective dates, audit and version history ([PROJECT_V1_SPEC.md](../../../.opencode/config/PROJECT_V1_SPEC.md)). The work-item model is ADM-02, and the roster derivation cites ADM-01 and XCH-05 alongside it; this package supplies only the work-item value model and the roster projection, not the configured-policy store ([MissingCoverageQueue.java](../../../apps/api/src/main/java/com/aurevia/config/rosters/MissingCoverageQueue.java)).

## Entry points

There are **no controller routes, commands, scheduled jobs or event handlers** in this package, and no class carries `@RestController`, `@PostMapping`, `@Scheduled` or `@EventListener`. The configuration HTTP API (`/api/v1/configuration` and `/api/v1/catalogs/...`) is owned by `web.ConfigurationController` and `web.CatalogController`, outside this package ([ConfigurationController.java](../../../apps/api/src/main/java/com/aurevia/web/ConfigurationController.java), [openapi.yaml](../../../contracts/openapi.yaml)). The "caller" column therefore names the actor or layer that may invoke each entry point; business roles are never accepted from a request body here.

## Tables it reads and writes

The package contains **no JDBC repository, no SQL and no Flyway migration**, so it reads and writes **no table directly**. Its database relationship is indirect: the authoritative configuration and roster facts are owned elsewhere, and a caller hands this package read-only value objects.

| Schema object | Relationship to this package | Source |
|---|---|---|
| `public.config_entry` and `public.config_approval` | Authoritative ADM-01 configuration and named approvals: immutable versions, `app.actor`-derived author and approver, forced RLS, effective version folded on read. Owned by `ConfigurationRepository` through `web.ConfigurationController`, not by this package | [V5__tenant_configuration.sql](../../../db/migrations/V5__tenant_configuration.sql), [data-dictionary.md](../data-dictionary.md) |
| `public.service_profile.backup_coverage` | Durable backup-coverage field on an approved MSG-06 service profile. | `public.xch04_expected_order.coverage_queue` and `public.xch04_report_revision.coverage_queue` | Columns holding a coverage queue name for result routing, not a table of this package. This package never reads them; the projection here derives the `missing_coverage` name from its own catalog constant | [V22__result_routing.sql](../../../db/migrations/V22__result_routing.sql), [data-dictionary.md](../data-dictionary.md), [MissingCoverageQueue.java](../../../apps/api/src/main/java/com/aurevia/config/rosters/MissingCoverageQueue.java) |

## Events published or consumed

**None.** No class in the package publishes or consumes a domain event, and no `@EventListener`, `ApplicationEventPublisher`, message sender or outbox call appears in its sources. `QueueAction` is an in-memory immutable history entry on a work item, not a durable event; durable event delivery is the separate `events` contract and outbox package ([QueueAction.java](../../../apps/api/src/main/java/com/aurevia/config/queues/QueueAction.java), [events README](../../../contracts/events/README.md)).

## Tests that cover it

All three Java test classes in this package use synthetic data (opaque tenant, unit and actor ids) and assert outcomes such as a startup failure, a status code, a state or a thrown error. There is no dedicated `ClockConfiguration` test class; its bean is loaded by the full Spring context in the repository's `@SpringBootTest` integration tests and consumed by the services that inject `Clock`.

| Test class (count) | What it proves | Source |
|---|---|---|
| `ProductionSafetyCheckTest` (8) | `production` plus `synthetic-auth` fails startup, blank password fails, insecure URL fails, `sslmode=require` and `verify-full` start, bean is absent outside `production`, failure messages never contain the password, and the production YAML declares graceful shutdown and hardened HTTP settings | [ProductionSafetyCheckTest.java](../../../apps/api/src/test/java/com/aurevia/config/ProductionSafetyCheckTest.java) |
| `OperationalQueueItemTest` (16) | Open item fields, immutable assign and resolve with full action history, reassignment, tenant id carried on the result, rejection of blank or null actor/owner/reason, rejection of a null or pre-creation action instant, terminal resolution (409), and a frozen action list | [OperationalQueueItemTest.java](../../../apps/api/src/test/java/com/aurevia/config/queues/OperationalQueueItemTest.java) |
| `MissingCoverageQueueTest` (7) | Missing or blank owner and backup become open items, a fully staffed roster leaves the queue, two tenants cannot see each other's gaps even with the same local unit id, empty input yields an empty queue, and the result is frozen against caller mutation | [MissingCoverageQueueTest.java](../../../apps/api/src/test/java/com/aurevia/config/rosters/MissingCoverageQueueTest.java) |

`UnsignedEncounterQueueTest` also exercises the shared work-item type through its `clinical.queues` consumer ([UnsignedEncounterQueueTest.java](../../../apps/api/src/test/java/com/aurevia/clinical/queues/UnsignedEncounterQueueTest.java)). No test uses real patient data and no test requires a live database for this package.

## Things to know

- **`config` is not the configuration HTTP API.** The name suggests it owns ADM-01 configuration, but the routes, repository and V5 tables live in `web.ConfigurationController`, `web.CatalogController` and `ConfigurationRepository`; this package owns no route, no store and no migration ([ConfigurationController.java](../../../apps/api/src/main/java/com/aurevia/web/ConfigurationController.java), [V5__tenant_configuration.sql](../../../db/migrations/V5__tenant_configuration.sql)).
- **Requirement IDs in the source are layered, not identical to the story ID.** The work-item model is ADM-02, and `MissingCoverageQueue` cites ADM-01 and XCH-05 alongside it because roster facts come from configured rosters; ADM-01 is this story's requirement ID and names coverage rosters among the configured policies, but it does not make `com.aurevia.config` the configuration HTTP API ([PROJECT_V1_SPEC.md](../../../.opencode/config/PROJECT_V1_SPEC.md), [MissingCoverageQueue.java](../../../apps/api/src/main/java/com/aurevia/config/rosters/MissingCoverageQueue.java)).
- **Queues are recalculated, not stored.** A roster that gains an owner and a backup, or a signed encounter, leaves the queue without any deletion; the tenant id is copied onto every item so two tenants can reuse the same local unit id ([MissingCoverageQueue.java](../../../apps/api/src/main/java/com/aurevia/config/rosters/MissingCoverageQueue.java), [UnsignedEncounterQueue.java](../../../apps/api/src/main/java/com/aurevia/clinical/queues/UnsignedEncounterQueue.java)).
- **No authorization or audit lives in this model.** `QueueAction` records a caller-supplied actor, reason and instant and explicitly defers operator authorization and durable audit references to the command boundary outside the domain model; a client-provided role would have no effect here ([QueueAction.java](../../../apps/api/src/main/java/com/aurevia/config/queues/QueueAction.java)).
- **The operator transitions are not wired yet.** `assign` and `resolve` and the `missing_coverage` projection are exercised only by unit tests in this snapshot; the only production caller of the shared work-item type creates open items in the `unsigned_encounters` projection ([OperationalQueueItemTest.java](../../../apps/api/src/test/java/com/aurevia/config/queues/OperationalQueueItemTest.java), [UnsignedEncounterQueue.java](../../../apps/api/src/main/java/com/aurevia/clinical/queues/UnsignedEncounterQueue.java)).
- **The lifecycle is deliberately narrow.** Resolution is terminal (409 `INVALID_TRANSITION`), an assigned item may be reassigned, an action instant may equal but not predate creation, and blank or null actor, owner or reason yield 422 ([OperationalQueueItem.java](../../../apps/api/src/main/java/com/aurevia/config/queues/OperationalQueueItem.java)).
- **The production guard is fail-closed and credential-safe.** It runs only under `production`, rejects a combined `synthetic-auth` profile, a blank password and a URL with neither TLS token, and its messages never include the password; it checks the URL string, not a live TLS handshake ([ProductionSafetyCheck.java](../../../apps/api/src/main/java/com/aurevia/config/ProductionSafetyCheck.java), [ProductionSafetyCheckTest.java](../../../apps/api/src/test/java/com/aurevia/config/ProductionSafetyCheckTest.java)).
- **The shared clock has test-time escape hatches.** `ClockConfiguration` supplies a single UTC bean, but several services and the tenant interceptor also construct `Clock.systemUTC()` in alternate constructors so unit tests can pin time; changes to clock policy must consider both paths ([ClockConfiguration.java](../../../apps/api/src/main/java/com/aurevia/config/ClockConfiguration.java), [TenantContextInterceptor.java](../../../apps/api/src/main/java/com/aurevia/web/TenantContextInterceptor.java)).
- **Work-item action history is not durable.** Because no event, outbox or table backs these values, a process restart discards any assignment or resolution made through this model; durable queue state remains owning-module work ([QueueAction.java](../../../apps/api/src/main/java/com/aurevia/config/queues/QueueAction.java), [events README](../../../contracts/events/README.md)).
