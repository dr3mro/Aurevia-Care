# Module guide: Durable event delivery (`com.aurevia.events`)

The `events` package is the durable delivery boundary for ARC-05: it commits an outbox record, its append-only audit fact and its idempotency key in one tenant-guarded transaction, advances immutable event ids through per-aggregate versions, deduplicates inbound partner events by sender and type, retries transient failures with bounded backoff and routes exhausted events through a restricted, reviewed dead-letter queue ([DurableEventService.java](../../../apps/api/src/main/java/com/aurevia/events/DurableEventService.java), [V55__durable_event_outbox.sql](../../../db/migrations/V55__durable_event_outbox.sql)). It exposes this through a thin `DeliveryController` and a domain service backed by a PostgreSQL adapter, and it carries no clinical payload, attachment bytes or credential in any record ([DeliveryController.java](../../../apps/api/src/main/java/com/aurevia/events/DeliveryController.java), [DurableEventContract.java](../../../apps/api/src/main/java/com/aurevia/events/DurableEventContract.java)).

Primary requirement: ARC-05 ([PROJECT_V1_SPEC.md](../../../.opencode/config/PROJECT_V1_SPEC.md)); the wire contract is the X-02 durable delivery contract in [contracts/events/README.md](../../../contracts/events/README.md), and all twelve routes are published in [contracts/openapi.yaml](../../../contracts/openapi.yaml). The `OPS-05` tag on this story is a downstream consumer relationship, not an implementation claim: OPS-05 asks for monitoring of queue age and partner delivery, operational owners, recovery runbooks and duplicate prevention, and this package only supplies the durable facts such a layer would read (`attempt`, `next_attempt_at`, delivery state, audit outcomes, idempotent deduplication). It emits no metrics, alerts or runbooks itself ([PROJECT_V1_SPEC.md](../../../.opencode/config/PROJECT_V1_SPEC.md), [observability-checklist.md](../observability-checklist.md)).

## Entry points

The package declares one `@RestController` with twelve routes, one `@Service` domain service, one `@Component` action matrix, one `@Repository` adapter, no `@Scheduled` job and no `@EventListener`, message listener or event-bus sender. The caller column names the actor or layer that may invoke each entry point; roles are re-derived from active membership and roles on every protected request, so a revoked credential loses access on the next request and a client-claimed role has no effect ([DeliveryActions.java](../../../apps/api/src/main/java/com/aurevia/events/DeliveryActions.java), [DurableEventService.java](../../../apps/api/src/main/java/com/aurevia/events/DurableEventService.java)).

## Tables it reads and writes

The package owns six tables created by the reserved V55 migration. Each `JdbcDeliveryStore` operation runs in the shared `TransactionTemplate` built by the application and backed by the tenant-guarded manager, which binds `app.current_org`, `app.actor`, `app.purpose` and `app.correlation_id` transaction-locally. Reads add no manual organization predicate because forced row-level security confines every statement to the active tenant, and insert triggers derive authorship from the same transaction ([JdbcDeliveryStore.java](../../../apps/api/src/main/java/com/aurevia/events/JdbcDeliveryStore.java), [AureviaApiApplication.java](../../../apps/api/src/main/java/com/aurevia/AureviaApiApplication.java), [TenantGuardTransactionManager.java](../../../apps/api/src/main/java/com/aurevia/tenant/TenantGuardTransactionManager.java), [V55__durable_event_outbox.sql](../../../db/migrations/V55__durable_event_outbox.sql)).

The publish path is the atomic boundary: `publishAtomically` inserts the outbox row and appends the audit fact in the same guarded transaction, and an empty insert result falls back to the original row rather than creating a second effect ([JdbcDeliveryStore.java](../../../apps/api/src/main/java/com/aurevia/events/JdbcDeliveryStore.java)). All six tables enable and force row-level security and are scoped by a `tenant_isolation` policy; the migration also grants only the minimum privileges to the runtime role ([V55__durable_event_outbox.sql](../../../db/migrations/V55__durable_event_outbox.sql)).

## Events published or consumed

There is no in-process event bus, scheduled dispatcher or broker integration: no `@EventListener`, message listener or sender appears in the package ([DurableEventContract.java](../../../apps/api/src/main/java/com/aurevia/events/DurableEventContract.java), [DurableEventService.java](../../../apps/api/src/main/java/com/aurevia/events/DurableEventService.java)). The "events" are durable facts: an `OutboxEvent` is published by writing `public.delivery_outbox`, and an `ExternalEvent` is consumed through `POST /api/v1/delivery/consumer-events` and recorded as a `ConsumerReceipt` plus an audit fact ([DurableEventContract.java](../../../apps/api/src/main/java/com/aurevia/events/DurableEventContract.java), [DeliveryController.java](../../../apps/api/src/main/java/com/aurevia/events/DeliveryController.java)). Replays, links, dead-letter reviews and audit reads create or read further immutable facts rather than emitting notifications ([DurableEventService.java](../../../apps/api/src/main/java/com/aurevia/events/DurableEventService.java)).

The two production publishers outside the package are the staff notification and reference notifiers, which call `DurableEventService.publish` with a digest over fixed content-free text and no patient identifiers ([NotificationConfiguration.java](../../../apps/api/src/main/java/com/aurevia/staffmsg/notify/NotificationConfiguration.java), [ReferenceConfiguration.java](../../../apps/api/src/main/java/com/aurevia/staffmsg/references/ReferenceConfiguration.java)). The X-02 contract and its synthetic fixture describe duplicate, correction, out-of-order and partial-outage sequences with expected processing outcomes ([contracts/events/README.md](../../../contracts/events/README.md), [partner-events.json](../../../contracts/events/fixtures/partner-events.json)).

## Things to know

- **No component drains the outbox.** There is no `@Scheduled` job, worker or broker listener in this package; `nextAttemptAt` is persisted by `retry` but nothing polls the `delivery_outbox_due_idx` index. Transmission routes must be driven by an external worker, and the OPS-05 queue-age signal is not measured here ([DurableEventService.java](../../../apps/api/src/main/java/com/aurevia/events/DurableEventService.java), [V55__durable_event_outbox.sql](../../../db/migrations/V55__durable_event_outbox.sql)).
- **The staff notifiers may hit the PUBLISH role gate.** `DurableEventService.publish` requires `worker` or `integration_admin`, but `worker` appears nowhere else in production sources and the two staffmsg notifiers publish under the acting staff context; their configuration tests mock the service, so an ordinary staff actor may be denied. Verify the calling role before relying on these in-process publishers ([DeliveryActions.java](../../../apps/api/src/main/java/com/aurevia/events/DeliveryActions.java), [NotificationService.java](../../../apps/api/src/main/java/com/aurevia/staffmsg/notify/NotificationService.java), [NotificationConfigurationTest.java](../../../apps/api/src/test/java/com/aurevia/staffmsg/notify/NotificationConfigurationTest.java)).
- **Migration V55 defers when prerequisites are absent.** A guard block raises a notice and returns if the organization table, the `app_org` or `reject_immutable_mutation` functions, or the runtime role are missing. The compatibility comment in the migration still describes an older offline runner that used a bare shell glob; the current `db/check.sh` and `infra/app/start.sh` apply `db/migrations/V*.sql` through `sort -V`, matching Flyway numeric order, so that comment is stale ([V55__durable_event_outbox.sql](../../../db/migrations/V55__durable_event_outbox.sql), [db/check.sh](../../../db/check.sh), [infra/app/start.sh](../../../infra/app/start.sh)).
- **Some wire parsers are test-only.** `DeliveryInputs.state`, `processingOutcome`, `action` and `outcome` are exercised by `DeliveryDomainTest` but have no production caller; the service uses enum constants directly, except `resolution`, which parses the review request. Keep them covered if they are later wired in ([DeliveryInputs.java](../../../apps/api/src/main/java/com/aurevia/events/DeliveryInputs.java), [DeliveryDomainTest.java](../../../apps/api/src/test/java/com/aurevia/events/DeliveryDomainTest.java)).
- **Concealment and idempotency are deliberate.** A missing or foreign-tenant resource yields a `404` with a `NOT_FOUND` audit outcome, a reused key with a different digest yields `409 IDEMPOTENCY_CONFLICT`, and a stale version yields `412`; denials are audited before they are thrown, and the initial in-memory store exists only in tests ([DurableEventService.java](../../../apps/api/src/main/java/com/aurevia/events/DurableEventService.java), [InMemoryDeliveryStore.java](../../../apps/api/src/test/java/com/aurevia/events/InMemoryDeliveryStore.java)).
- **This is not the order-delivery kernel.** `com.aurevia.orderentry.delivery` is a separate domain that coordinates electronic, manual and print delivery of a placed order and keeps its own `DeliveryEvent` facts; it does not write the V55 outbox tables ([OrderDeliveryCoordinator.java](../../../apps/api/src/main/java/com/aurevia/orderentry/delivery/OrderDeliveryCoordinator.java)).
