# Module guide: Longitudinal chart (`com.aurevia.chart.record`)

The `chart.record` package is the CLN-03 longitudinal chart slice: it records problems, allergies, medications and vitals for a patient, retaining the submitted code and free text verbatim alongside provenance, clinical assertion, effective dates and a separately recorded clinical author and data-entry actor. It also verifies an entry at the version the caller read, so verification is an explicit, version-bound transition rather than an edit ([ChartService.java](../../../apps/api/src/main/java/com/aurevia/chart/record/ChartService.java), [ChartEntry.java](../../../apps/api/src/main/java/com/aurevia/chart/record/ChartEntry.java), [V13__longitudinal_chart.sql](../../../db/migrations/V13__longitudinal_chart.sql)).

Primary requirement: CLN-03, with ARC-01 (tenant-owned keys and clinical effective time), ARC-02 (forced RLS and fail-closed authorization), ARC-03 (version preconditions on irreversible transitions), ARC-04 (412 for stale versions) and OPS-02 (transactional audit) ([PROJECT_V1_SPEC.md](../../../.opencode/config/PROJECT_V1_SPEC.md), [V13__longitudinal_chart.sql](../../../db/migrations/V13__longitudinal_chart.sql)). The task metadata also names CLN-07; see the requirement note under [Things to know](#things-to-know).

## Entry points

This package exposes four HTTP routes through one thin controller, four domain commands on the service, one role matrix and one SQL repository. It declares no scheduled job, no `@EventListener` and no message handler. The "who" column names the business role re-derived from the active tenant on every call; no role or organization is accepted from the request body.

**Feature trace (record).** `POST /api/v1/chart/records/entries` → `ChartController.record` → `ChartService.record` validation → `authorize` (active membership and role from the V4 folds, decided by `ChartActionPolicy`) → tenant-guarded `TransactionTemplate` → `ChartRepository.insert` into forced-RLS `chart_entry` plus `AuditAppender.append` → 201. The read and verify routes follow the same entry → authz → transaction → persistence → audit path, with verify adding the `If-Match` precondition and conditional update ([maintainer.md](../maintainer.md), [ChartService.java](../../../apps/api/src/main/java/com/aurevia/chart/record/ChartService.java)).

The four value types `EntryType` (`PROBLEM`, `ALLERGY`, `MEDICATION`, `VITAL`), `EntrySource` (`PATIENT_REPORTED`, `CLINICIAN_OBSERVED`, `EXTERNAL_RECORD`, `DEVICE`), `PresenceState` (`PRESENT`, `ABSENT`, `UNKNOWN`) and `VerificationState` (`UNVERIFIED`, `VERIFIED`) are wire enums shared by the command, stored row and response; `VITAL` alone requires a value, unit and measurement time ([EntryType.java](../../../apps/api/src/main/java/com/aurevia/chart/record/EntryType.java), [EntrySource.java](../../../apps/api/src/main/java/com/aurevia/chart/record/EntrySource.java), [PresenceState.java](../../../apps/api/src/main/java/com/aurevia/chart/record/PresenceState.java), [VerificationState.java](../../../apps/api/src/main/java/com/aurevia/chart/record/VerificationState.java)).

## Tables it reads and writes

All SQL is confined to the tenant-guarded transaction; no client-supplied organization or actor value crosses the repository boundary, and the ones the repository takes as parameters are derived from server state.

## Events published or consumed

**None.** No class in the package publishes or consumes a domain event: there is no `@EventListener`, message sender or outbox call in its sources. `AuditAppender.append` is a synchronous audit write committed in the same transaction as the command, not a durable event; the separate V55 durable outbox and `events` package are not used by this slice ([AuditAppender.java](../../../apps/api/src/main/java/com/aurevia/audit/AuditAppender.java), [V55__durable_event_outbox.sql](../../../db/migrations/V55__durable_event_outbox.sql)).

## Things to know

- **The task's requirement ID does not match this package.** The story metadata names CLN-07, but the `ChartController` and `ChartService` Javadoc, the V13 migration header and five clause tests identify this slice as CLN-03. CLN-07 covers linking original PDFs and images, retaining bytes and checksums, and PDF rendering; the `PdfRenderer` Javadoc and `SigningDiffersPatientReleasePdfRenderingTest` place that work in the separate `documents` package. This guide records the code as it stands and does not change code or claim this package delivers CLN-07 ([ChartController.java](../../../apps/api/src/main/java/com/aurevia/chart/record/ChartController.java), [ChartService.java](../../../apps/api/src/main/java/com/aurevia/chart/record/ChartService.java), [V13__longitudinal_chart.sql](../../../db/migrations/V13__longitudinal_chart.sql), [PdfRenderer.java](../../../apps/api/src/main/java/com/aurevia/documents/PdfRenderer.java), [SigningDiffersPatientReleasePdfRenderingTest.java](../../../apps/api/src/test/java/com/aurevia/chart/clauses/SigningDiffersPatientReleasePdfRenderingTest.java)).
- **Mapping is a write-time snapshot, never a live lookup.** `mappedCode`, `mappedText` and `catalogVersion` are stored on insert and returned on read; a later catalog version does not rewrite an existing entry, and an unmapped local code simply stays unmapped with its original text retained ([ChartRepository.java](../../../apps/api/src/main/java/com/aurevia/chart/record/ChartRepository.java), [ChartService.java](../../../apps/api/src/main/java/com/aurevia/chart/record/ChartService.java)).
- **A stale precondition beats an already-verified entry on verify.** `ChartService.verify` checks version mismatch (412) before `VerificationState.VERIFIED` (409) so a concurrent verifier that read version N always gets 412; the repository's conditional update is the final arbiter and a zero-row match also becomes 412. `IfMatch.parse` itself only maps an absent header to 428 and a malformed one to 422. `verifiedAt` and `verifiedBy` are set only by this transition ([ChartService.java](../../../apps/api/src/main/java/com/aurevia/chart/record/ChartService.java), [ChartRepository.java](../../../apps/api/src/main/java/com/aurevia/chart/record/ChartRepository.java), [IfMatch.java](../../../apps/api/src/main/java/com/aurevia/api/IfMatch.java)).
- **Verification also assigns clinical authorship.** Both the returned view and the stored row fill a previously null `clinicalAuthor` with the verifying subject, using the same `COALESCE` rule in the service and SQL so they cannot disagree ([ChartService.java](../../../apps/api/src/main/java/com/aurevia/chart/record/ChartService.java), [ChartRepository.java](../../../apps/api/src/main/java/com/aurevia/chart/record/ChartRepository.java)).
- **There is no edit or void route.** The only mutation after insert is verification; retaining history and changing content would need a new versioned command and contract, not a call to this controller ([ChartController.java](../../../apps/api/src/main/java/com/aurevia/chart/record/ChartController.java)).
- **The SOAP narrative clause is an acknowledged gap.** One test is disabled with an explicit reason: chief concern, history, exam, assessment narrative and plan are captured as CLN-04 template fields and note revisions, not as chart entry types, so no `/api/v1/chart/records` family accepts them ([CaptureChiefConcernHistoryExamAssessmentDiagnosesTest.java](../../../apps/api/src/test/java/com/aurevia/chart/clauses/CaptureChiefConcernHistoryExamAssessmentDiagnosesTest.java), [capture clause gap note](../../../docs/spec/clauses/chart/capture-chief-concern-history-exam-assessment-diagnoses.md)).
- **This guide is not a shared index.** `docs/reference/index.md` is owned by START-119, so no index entry was added here; link discovery for this group is handled there ([index.md](../index.md)).
