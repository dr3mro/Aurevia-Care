# Module guide: self-pay finance (`com.aurevia.finance`)

The `finance` package implements FIN-01: it turns itemized, single-currency self-pay lines into draft invoices, issues them, and records payments, refunds and credits as numbered immutable ledger entries with replay-safe references and finance-only daily reconciliation. Every command runs in one tenant-guarded transaction with server-derived roles; changing an existing invoice adds a row lock and a version precondition, and every response carries only finance fields, never clinical narrative ([FinanceService.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceService.java), [FinanceContract.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceContract.java)).

Primary requirement: FIN-01; supporting PRD-04, ARC-01, ARC-02, ARC-03, ARC-04 and OPS-02 ([PROJECT_V1_SPEC.md](../../../.opencode/config/PROJECT_V1_SPEC.md), [V45__finance.sql](../../../db/migrations/V45__finance.sql)). The published HTTP contract is the `finance` tag in [openapi.yaml](../../../contracts/openapi.yaml).

## Entry points

The package has one `@RestController` under `/api/v1/finance` with nine routes; the POST routes are the finance commands. It declares no scheduled job and no event handler. Roles below are decision keys in the bounded action matrix, which is paired with a fresh membership and role lookup on every request; client-supplied role or permission fields have no effect ([FinanceController.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceController.java), [FinanceActions.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceActions.java), [FinanceService.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceService.java)).

The controller is a thin adapter: it parses `If-Match` into an expected version and delegates to `FinanceService`, which owns authorization, replay deduplication, balance arithmetic and approval invariants. The service methods are library entry points reached from those routes, not separate HTTP surfaces; no caller may choose an action or a role in the request body ([FinanceController.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceController.java), [FinanceService.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceService.java)).

## Tables it reads and writes

All four business tables are created by the finance migration. Each carries `organization_id`, enables and forces row-level security with a `tenant_isolation` policy and a `WITH CHECK` clause, and has immutability triggers; the secondary indexes are `finance_invoice_patient_idx`, `finance_ledger_trail_idx` and `finance_ledger_daily_idx` ([V45__finance.sql](../../../db/migrations/V45__finance.sql)).

## Events published or consumed

**None.** No class in the package publishes or consumes a domain event, and no listener, sender or outbox call appears in its sources. The only side effect beyond the four finance tables is the synchronous `audit_event` append described above; that is an audit record, not a durable event ([FinanceService.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceService.java), [AuditAppender.java](../../../apps/api/src/main/java/com/aurevia/audit/AuditAppender.java)).

## Things to know

- **The action matrix permits finance staff to approve their own class of reversal, but never their own request.** `FINANCE_APPROVE` is granted to `finance` and `tenant_admin`, and the service separately rejects an approver equal to the authenticated actor and one without a fresh active membership and approval role ([FinanceActions.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceActions.java), [FinanceService.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceService.java)).
- **A full refund can move `paid` back to `issued`, but `void` is terminal.** State transitions are legalised both in the domain enum and in the V45 update trigger, so a paid invoice reversed by a refund can receive new entries while a voided invoice cannot; a void after any posted entry is refused and must be handled as a refund instead ([FinanceContract.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceContract.java), [V45__finance.sql](../../../db/migrations/V45__finance.sql), [FinanceService.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceService.java)).
- **Replay safety is keyed on a body field, not on an idempotency header.** The published contract lists an optional `Idempotency-Key` on the state-changing routes, but the controller declares no such header; the service deduplicates ledger entries on the body `reference` plus a SHA-256 payload fingerprint, and the database `UNIQUE (organization_id, reference)` constraint is the durable business key ([openapi.yaml](../../../contracts/openapi.yaml), [FinanceController.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceController.java), [FinanceInputs.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceInputs.java), [V45__finance.sql](../../../db/migrations/V45__finance.sql)).
- **The generated command catalog has a stale finance definition.** It registers `issueInvoice` as `POST /api/v1/invoices` with action `FINANCE_INVOICE_CREATE`, which matches neither the controller route `/api/v1/finance/invoices/{id}/issue` nor the issue action; the nine live routes above are the authority ([CommandCatalog.java](../../../apps/api/src/main/java/com/aurevia/api/authorization/CommandCatalog.java), [FinanceController.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceController.java)).
- **The migration is defensive about apply order.** V45 guards its DDL on prerequisite tables, functions and role existing, and raises a notice and returns if they are missing, so the offline shell-glob runner can apply it out of order without error; Flyway applies by numeric version and is the authority ([V45__finance.sql](../../../db/migrations/V45__finance.sql)).
- **The in-memory repositories are test-only.** The JDBC `FinanceRepository` is a `@Repository` injected by constructor into `FinanceService` and is the sole production store; the fakes that drive the fast tests extend it under `src/test`, and no alternative implementation is wired in production ([FinanceRepository.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceRepository.java), [FinanceService.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceService.java), [FinanceLedgerTest.java](../../../apps/api/src/test/java/com/aurevia/finance/FinanceLedgerTest.java)).
- **The approver is a validated self-asserted subject, not a separately authenticated second party.** `FinanceInputs.subject` checks only the subject-key format; the service then checks that it differs from the actor, has an active membership and holds the `FINANCE_APPROVE` role before storing it as `approver_subject` or `voided_by_subject`. The guide's "independent approver" therefore means a distinct authorized member, not an independent session proof ([FinanceInputs.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceInputs.java), [FinanceService.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceService.java), [FinanceRepository.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceRepository.java)).
- **Audit coverage is selective.** Successful commands, authorization or approval denials, and replay or void-after-posting conflicts append an outcome; input validation rejects malformed commands before the transaction opens, while not-found, stale-version, illegal-transition and over-balance failures throw inside the callback and roll back. None of those failures writes a finance audit row. Improving that coverage is a code change outside this documentation task ([FinanceService.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceService.java), [AuditAppender.java](../../../apps/api/src/main/java/com/aurevia/audit/AuditAppender.java)).
- **List pages are deliberately shallow.** A single-record read owns the item and ledger trails, so each page row carries no history, one extra row is fetched to decide the next cursor, and the cursor is the canonical `createdAt` and immutable id used by the database's exclusive paging bound ([FinanceService.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceService.java), [InvoicePage.java](../../../apps/api/src/main/java/com/aurevia/finance/InvoicePage.java), [FinanceRepository.java](../../../apps/api/src/main/java/com/aurevia/finance/FinanceRepository.java)).
