# Module guide: API catalog (`com.aurevia.catalog`)

The `catalog` package owns tenant-administrable versioned catalogs and the versioned clinical dictionaries used across the API: it bounds family and code names, delegates append-only draft creation and named approval to the configuration domain, and folds only approved entries inside their effective window for reads ([CatalogService.java](../../../apps/api/src/main/java/com/aurevia/catalog/CatalogService.java), [CatalogRepository.java](../../../apps/api/src/main/java/com/aurevia/catalog/CatalogRepository.java), [V6__catalog_fold.sql](../../../db/migrations/V6__catalog_fold.sql)). It also holds the localized clinical-text value objects and the mixed-script formatting kernel, plus the version-aware medication catalog fold consumed by prescribing ([MixedScriptSupport.java](../../../apps/api/src/main/java/com/aurevia/catalog/dictionary/MixedScriptSupport.java), [MedicationCatalog.java](../../../apps/api/src/main/java/com/aurevia/catalog/MedicationCatalog.java)).

Primary requirement: ADM-01 — tenant admins configure catalogs with named approval, effective dates, audit and version history ([PROJECT_V1_SPEC.md](../../../.opencode/config/PROJECT_V1_SPEC.md), [V6__catalog_fold.sql](../../../db/migrations/V6__catalog_fold.sql)). Supporting requirement IDs named in the cited source comments and migration headers are CLN-03, CLN-04, RX-01, PRD-05, UX-01, OPS-02, ARC-01, ARC-02, IAM-01 and IAM-03 ([CatalogService.java](../../../apps/api/src/main/java/com/aurevia/catalog/CatalogService.java), [V1__tenant_schema.sql](../../../db/migrations/V1__tenant_schema.sql), [V4__staff_lifecycle.sql](../../../db/migrations/V4__staff_lifecycle.sql), [V6__catalog_fold.sql](../../../db/migrations/V6__catalog_fold.sql), [V76__medication_catalog_version.sql](../../../db/migrations/V76__medication_catalog_version.sql), [LocalizedName.java](../../../apps/api/src/main/java/com/aurevia/catalog/dictionary/LocalizedName.java)). The existing [maintainer guide catalog trace](../maintainer.md) follows the four admin catalog routes end to end.

## Entry points

The package declares thirteen HTTP routes across two controllers (one of which lives in `com.aurevia.web`), plus domain-service operations and a localization kernel. It declares no command in `CommandCatalog`, no scheduled job, no event handler and no `@RequestMapping` outside the two controllers named below. Roles are derived server-side from `TenantContext` and the active membership; the actor is never taken from a request body ([ClinicalCatalogController.java](../../../apps/api/src/main/java/com/aurevia/catalog/dictionary/ClinicalCatalogController.java), [ActionPolicy.java](../../../apps/api/src/main/java/com/aurevia/authz/ActionPolicy.java)).

## Tables it reads and writes

`CatalogRepository` is the only SQL boundary in the top-level package and performs no writes to configuration tables; drafts and approvals are appended by `ConfigurationService`. The dictionary adapters store whole versions as opaque configuration values, so they add no schema of their own ([CatalogRepository.java](../../../apps/api/src/main/java/com/aurevia/catalog/CatalogRepository.java), [DurableVersionStore.java](../../../apps/api/src/main/java/com/aurevia/catalog/dictionary/DurableVersionStore.java)).

| Table or schema object | Relationship | Source |
|---|---|---|
| `public.config_entry`, `public.config_approval` | Catalog entries are versioned configuration keys of the form `catalog.<family>.<code>`, created as pending drafts and made effective by a named approval in these append-only V5 tables | [V5__tenant_configuration.sql](../../../db/migrations/V5__tenant_configuration.sql), [CatalogService.java](../../../apps/api/src/main/java/com/aurevia/catalog/CatalogService.java) |
| `public.effective_config(key)` | Read by `CatalogRepository.effective` to obtain the single effective approved version of a key | [V5__tenant_configuration.sql](../../../db/migrations/V5__tenant_configuration.sql), [CatalogRepository.java](../../../apps/api/src/main/java/com/aurevia/catalog/CatalogRepository.java) |
| `public.effective_catalog_family(prefix)` | V6 fold over `config_entry` joined to `config_approval` with `effective_from <= now()`; read by `CatalogRepository.family` for a whole family | [V6__catalog_fold.sql](../../../db/migrations/V6__catalog_fold.sql), [CatalogRepository.java](../../../apps/api/src/main/java/com/aurevia/catalog/CatalogRepository.java) |
| `public.has_active_membership(subject)`, `public.active_roles(subject)` | V4 folds read by `CatalogRepository` for the server-side read authorization; a stale membership fails closed with 403 | [V4__staff_lifecycle.sql](../../../db/migrations/V4__staff_lifecycle.sql), [CatalogService.java](../../../apps/api/src/main/java/com/aurevia/catalog/CatalogService.java) |

Tenant scoping comes from `TenantContext` and forced row-level security on the underlying tables, never from a request body ([CatalogService.java](../../../apps/api/src/main/java/com/aurevia/catalog/CatalogService.java), [V5__tenant_configuration.sql](../../../db/migrations/V5__tenant_configuration.sql)).

## Events published or consumed

None. No class in the package registers an `@EventListener`, publishes an outbox record or calls a message sender; the audit rows above are synchronous OPS-02 records written inside the caller's transaction, not domain events. Durable event delivery belongs to the separate events package and its contract ([CatalogRepository.java](../../../apps/api/src/main/java/com/aurevia/catalog/CatalogRepository.java), [events/README.md](../../../contracts/events/README.md)).

## Things to know

- **The admin HTTP adapter for catalogs is not in this package.** `web.CatalogController` owns the four `/api/v1/catalogs` routes and injects `CatalogService`; only `ClinicalCatalogController` is declared under `com.aurevia.catalog.dictionary` ([CatalogController.java](../../../apps/api/src/main/java/com/aurevia/web/CatalogController.java), [ClinicalCatalogController.java](../../../apps/api/src/main/java/com/aurevia/catalog/dictionary/ClinicalCatalogController.java)).
- **Reads are admin-only and fail closed.** `CATALOG_READ` appears only in `ActionPolicy.ADMIN_ACTIONS`, so reception and other roles receive 403; a missing active membership also yields 403 and an audit `DENIED` row. A foreign-tenant code is concealed as 404 rather than revealing that another tenant owns it ([ActionPolicy.java](../../../apps/api/src/main/java/com/aurevia/authz/ActionPolicy.java), [CatalogService.java](../../../apps/api/src/main/java/com/aurevia/catalog/CatalogService.java), [CatalogIsolationTest.java](../../../apps/api/src/test/java/com/aurevia/it/CatalogIsolationTest.java)).
- **The clinical controller delegates authorization instead of declaring its own policy.** It derives the author and approver from `TenantContext` and relies on `ConfigurationService`'s `CONFIG_CREATE`, `CONFIG_APPROVE`, `CONFIG_READ` and `CONFIG_HISTORY` checks, all of which are admin actions in this slice ([ClinicalCatalogController.java](../../../apps/api/src/main/java/com/aurevia/catalog/dictionary/ClinicalCatalogController.java), [ConfigurationService.java](../../../apps/api/src/main/java/com/aurevia/configuration/ConfigurationService.java), [ActionPolicy.java](../../../apps/api/src/main/java/com/aurevia/authz/ActionPolicy.java)).
- **A draft is never effective and its author cannot approve it.** Both the in-memory `VersionStore` and the durable `DurableVersionStore` require a named approval from a different subject; the durable store reads the stored author from configuration history and ignores any approver name supplied in the payload, while `ConfigurationService` derives the recorded approver from the authenticated actor ([VersionStore.java](../../../apps/api/src/main/java/com/aurevia/catalog/dictionary/VersionStore.java), [DurableVersionStore.java](../../../apps/api/src/main/java/com/aurevia/catalog/dictionary/DurableVersionStore.java), [DurableVersionStoreTest.java](../../../apps/api/src/test/java/com/aurevia/it/catalog/dictionary/DurableVersionStoreTest.java)).
- **Two persistence implementations coexist by design.** `VersionStore` is a deterministic in-memory kernel used by the no-argument constructors of the dictionary services; `DurableVersionStore` is the injected production adapter that stores versions as opaque configuration values. They share validation helpers in `VersionStore` so a draft cannot be written with null entries or duplicate codes ([ClinicalDictionaryService.java](../../../apps/api/src/main/java/com/aurevia/catalog/dictionary/ClinicalDictionaryService.java), [DurableVersionStore.java](../../../apps/api/src/main/java/com/aurevia/catalog/dictionary/DurableVersionStore.java)).
- **The localization and medication types are pure kernels, but only part of the value model is persisted.** `MixedScriptSupport` returns direction, isolation, unit and time metadata without changing stored text; client-only rendering is explicitly out of scope and this class has no production caller in this snapshot. `LocalizedText` and `Requiredness` are fields of `DictionaryField` and `DiagnosisCode` and are therefore serialized into configuration entries by `DurableVersionStore`; `LocalizedName`, `Direction`, `RunDirection`, `UiLocale` and `LocalizedExport` are presentation and export value objects used with the kernel, not stored by this package. `MedicationCatalog` likewise performs no SQL: its route and version data is loaded by `PrescriptionRepository` ([MixedScriptSupport.java](../../../apps/api/src/main/java/com/aurevia/catalog/dictionary/MixedScriptSupport.java), [DictionaryField.java](../../../apps/api/src/main/java/com/aurevia/catalog/dictionary/DictionaryField.java), [DiagnosisCode.java](../../../apps/api/src/main/java/com/aurevia/catalog/dictionary/DiagnosisCode.java), [MedicationCatalog.java](../../../apps/api/src/main/java/com/aurevia/catalog/MedicationCatalog.java), [PrescriptionRepository.java](../../../apps/api/src/main/java/com/aurevia/prescription/PrescriptionRepository.java)).
- **Corrupt stored versions fail closed.** `DurableVersionStore` maps JSON encode and decode failures to a 422 `INVALID_CATALOG_DATA` rather than returning a partial version, and propagates non-404 authorization failures instead of treating them as an absent version ([DurableVersionStore.java](../../../apps/api/src/main/java/com/aurevia/catalog/dictionary/DurableVersionStore.java), [DurableVersionStoreTest.java](../../../apps/api/src/test/java/com/aurevia/it/catalog/dictionary/DurableVersionStoreTest.java)).
