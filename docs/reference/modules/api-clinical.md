# Module guide: clinical documentation (`com.aurevia.clinical`)

The `clinical` package owns the V1 clinical-documentation backend: versioned note templates that freeze the exact field meanings a note was authored against, and an append-only draft-to-sign revision ledger that preserves every prior revision with its signer, attestation, checksum and provenance. It also projects note revisions into the unsigned-encounter operational worklist without storing queue state ([TemplateService.java](../../../apps/api/src/main/java/com/aurevia/clinical/templates/TemplateService.java), [ClinicalNoteService.java](../../../apps/api/src/main/java/com/aurevia/clinical/notes/ClinicalNoteService.java), [UnsignedEncounterQueue.java](../../../apps/api/src/main/java/com/aurevia/clinical/queues/UnsignedEncounterQueue.java)).

Primary requirements: [CLN-04](../../../.opencode/config/PROJECT_V1_SPEC.md) (versioned SOAP, operative, OB/GYN, perinatal and pediatric development templates with clinical-governance approval) and [CLN-05](../../../.opencode/config/PROJECT_V1_SPEC.md) (draft → signed with amendments, addenda and entered-in-error). The worklist projection serves ADM-02, and the revision store applies ARC-02 and OPS-02 through the forced RLS declared in V15 using the `app_org()` helper from [V2__rls_roles_policies.sql](../../../db/migrations/V2__rls_roles_policies.sql) ([V15__clinical_note_signing.sql](../../../db/migrations/V15__clinical_note_signing.sql), [V80__template_store.sql](../../../db/migrations/V80__template_store.sql)). Template authorization checks the supplied actor's active roles in `TemplateService.authorize()` (IAM-01), and template reads are open to any active role ([TemplateService.java](../../../apps/api/src/main/java/com/aurevia/clinical/templates/TemplateService.java), [TemplateActor.java](../../../apps/api/src/main/java/com/aurevia/clinical/templates/TemplateActor.java)). The task tracker for this guide names CLN-06, but CLN-06 is "Suggest a follow-up date" and is implemented by the separate `scheduling/followup` package and `V74__follow_up_suggestions.sql`, not by this package ([FollowUpService.java](../../../apps/api/src/main/java/com/aurevia/scheduling/followup/FollowUpService.java), [V74__follow_up_suggestions.sql](../../../db/migrations/V74__follow_up_suggestions.sql)).

## Entry points

`notes` declares one `@RestController` with seven routes; `templates` and `queues` declare no controller, and the whole package declares no scheduled job and no event handler, so their operations are library calls made by an integrating caller. Business roles are never taken from a request body: `TenantContextInterceptor` binds the tenant from authenticated claims, and the note service reads that context and re-derives active membership and roles inside the guarded transaction, deciding each action with `CLINICIAN_ACTIONS` or `ASSISTANT_ACTIONS` ([TenantContextInterceptor.java](../../../apps/api/src/main/java/com/aurevia/web/TenantContextInterceptor.java), [ClinicalNoteController.java](../../../apps/api/src/main/java/com/aurevia/clinical/notes/ClinicalNoteController.java), [ClinicalNoteService.java](../../../apps/api/src/main/java/com/aurevia/clinical/notes/ClinicalNoteService.java)).

## Tables it reads and writes

Direct writes are INSERTs into append-only ledgers inside tenant-guarded transactions; the database owns versions, actor columns and checksums, so a caller cannot choose them ([NoteRepository.java](../../../apps/api/src/main/java/com/aurevia/clinical/notes/NoteRepository.java), [JdbcTemplateStore.java](../../../apps/api/src/main/java/com/aurevia/clinical/templates/JdbcTemplateStore.java)). Everything else below is an indirect read of a fold, membership function or audit sink. The unsigned-encounter queue has no store of its own: it is derived from tenant-scoped facts supplied by the caller ([UnsignedEncounterQueue.java](../../../apps/api/src/main/java/com/aurevia/clinical/queues/UnsignedEncounterQueue.java)).

## Events published or consumed

**None.** No class in this package publishes or consumes a domain event, and no `@EventListener`, outbox call or message sender appears in its sources ([ClinicalNoteService.java](../../../apps/api/src/main/java/com/aurevia/clinical/notes/ClinicalNoteService.java), [TemplateService.java](../../../apps/api/src/main/java/com/aurevia/clinical/templates/TemplateService.java), [UnsignedEncounterQueue.java](../../../apps/api/src/main/java/com/aurevia/clinical/queues/UnsignedEncounterQueue.java)). `AuditAppender` rows and `TemplateAuditEvent` facts are synchronous audit writes in the owning transaction, not durable events; the durable event outbox belongs to the separate `events` package and its contract ([contracts/events](../../../contracts/events/README.md)).

## Things to know

- **Templates and the queue have no production entry point.** `TemplateService` and `UnsignedEncounterQueue` are discovered as beans or called directly by tests, but no controller, worker or event handler in the repository calls them; their guarantees are domain and projection guarantees, not request-level ones ([TemplateService.java](../../../apps/api/src/main/java/com/aurevia/clinical/templates/TemplateService.java), [UnsignedEncounterQueue.java](../../../apps/api/src/main/java/com/aurevia/clinical/queues/UnsignedEncounterQueue.java)).
- **Template authorization trusts the caller's actor snapshot.** `TemplateService` authorizes the supplied `TemplateActor`, not a freshly resolved identity; the integrating caller must build it from current active membership on every request, or a stale role set would be honored (IAM-01) ([TemplateActor.java](../../../apps/api/src/main/java/com/aurevia/clinical/templates/TemplateActor.java), [TemplateService.java](../../../apps/api/src/main/java/com/aurevia/clinical/templates/TemplateService.java)).
- **Note serialization and failure audit are deliberate.** Every mutation takes a per-tenant, per-note advisory lock, and a failed command re-appends its audit in a committed second transaction because the inline row would roll back with the command ([NoteRepository.java](../../../apps/api/src/main/java/com/aurevia/clinical/notes/NoteRepository.java), [ClinicalNoteService.java](../../../apps/api/src/main/java/com/aurevia/clinical/notes/ClinicalNoteService.java)).
- **Queue suppression is encounter-wide.** A signature-bearing revision anywhere in an encounter removes the item even when a newer amendment draft is still unsigned; this is narrower than a per-note reading and needs a site ruling before live enablement ([UnsignedEncounterQueue.java](../../../apps/api/src/main/java/com/aurevia/clinical/queues/UnsignedEncounterQueue.java)).
- **The encounter foreign key is deferred.** V15 stores `encounter_id` as a plain uuid because the encounter table is not part of that baseline; a later migration must add the composite tenant, patient and encounter key ([V15__clinical_note_signing.sql](../../../db/migrations/V15__clinical_note_signing.sql)).
- **Signing is not release or rendering.** A signed revision records the signature, effective time and checksum but grants no patient access and renders no PDF; the controller exposes no such route ([ClinicalNoteService.java](../../../apps/api/src/main/java/com/aurevia/clinical/notes/ClinicalNoteService.java), [SigningDiffersPatientReleasePdfRenderingTest.java](../../../apps/api/src/test/java/com/aurevia/chart/clauses/SigningDiffersPatientReleasePdfRenderingTest.java)).
- **The baseline catalog is governance configuration.** V87 deliberately seeds no tenant template version: a migration has no governance actor and cannot satisfy forced RLS, so a tenant adopts version one through the approval workflow, and a future effective date is rejected because V15 requires signed at or after effective at ([V87__baseline_templates.sql](../../../db/migrations/V87__baseline_templates.sql), [NoteInputs.java](../../../apps/api/src/main/java/com/aurevia/clinical/notes/NoteInputs.java)).
- **The tracker requirement differs from the package scope.** CLN-06 follow-up suggestions are implemented by `scheduling/followup` and V74; this package covers CLN-04 and CLN-05 ([FollowUpService.java](../../../apps/api/src/main/java/com/aurevia/scheduling/followup/FollowUpService.java), [V74__follow_up_suggestions.sql](../../../db/migrations/V74__follow_up_suggestions.sql)).
