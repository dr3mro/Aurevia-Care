# Module guide: API documents (`com.aurevia.documents`)

The `documents` package owns the clinical document lifecycle: it attaches retained original PDFs and images to a chart, order or result, verifies their bytes on download, and renders immutable, versioned and direction-aware PDF revisions ([DocumentService.java](../../../apps/api/src/main/java/com/aurevia/documents/DocumentService.java), [DocumentRepository.java](../../../apps/api/src/main/java/com/aurevia/documents/DocumentRepository.java)). A second slice accepts uploads into private quarantine, records independent scan verdicts, binds PDFs to exact immutable revisions and gates release decisions, keeping payload bytes, file names and URLs out of the ordinary operational record ([QuarantineService.java](../../../apps/api/src/main/java/com/aurevia/documents/QuarantineService.java), [PdfBindingService.java](../../../apps/api/src/main/java/com/aurevia/documents/PdfBindingService.java), [DocumentContract.java](../../../apps/api/src/main/java/com/aurevia/documents/DocumentContract.java)).

Primary requirement CLN-07. The artifact and PDF-binding slice also delivers ARC-06, with IAM-01 role checks, ARC-02 tenant isolation and OPS-02 append-only sanitized facts ([PROJECT_V1_SPEC.md](../../../.opencode/config/PROJECT_V1_SPEC.md), [document-artifacts.md](../../../contracts/documents/document-artifacts.md)).

## Entry points

Two `@RestController` classes expose 20 HTTP routes; the rest of the package is reached only through those controllers, through other modules that reuse its validators and renderer, and through tests. There is no scheduled job, message listener or event handler in the package. Roles below are re-derived from current active membership on every command; no tenant, role or patient binding is accepted from a request body ([DocumentController.java](../../../apps/api/src/main/java/com/aurevia/documents/DocumentController.java), [DocumentArtifactController.java](../../../apps/api/src/main/java/com/aurevia/documents/DocumentArtifactController.java)).

## Events published or consumed

**No broker event is published or consumed.** No class in the package declares `@EventListener`, a scheduled job, an outbox call or a message sender. The package's "events" are three append-only database records: association link/void history in `document_association_event`, the tenant fact ledger in `document_event` with the `EventType` vocabulary, and OPS-02 `audit_event` rows appended through `AuditAppender` ([DocumentContract.java](../../../apps/api/src/main/java/com/aurevia/documents/DocumentContract.java), [DocumentGuard.java](../../../apps/api/src/main/java/com/aurevia/documents/DocumentGuard.java), [DocumentService.java](../../../apps/api/src/main/java/com/aurevia/documents/DocumentService.java)). A denial is recorded before the exception leaves the service; a concealment records no fact so an existence probe cannot be distinguished from a missing row in the ledger. Durable integration events are owned by the separate `events` package ([contracts/events/README.md](../../../contracts/events/README.md)).

## Things to know

- **Two independent role matrices coexist in this package.** `DocumentService` uses `DocumentPolicy` for CLN-07 actions (`DOCUMENT_LINK`, `DOCUMENT_READ`, `DOCUMENT_RENDER`, `DOCUMENT_VOID`, clinician or reception), while both artifact services use `DocumentActions.Action` through `DocumentGuard` (12 actions across reception, clinical assistant, document reviewer, clinician, security scanner, PDF renderer, privacy auditor and patient). They are not a single catalog ([DocumentPolicy.java](../../../apps/api/src/main/java/com/aurevia/documents/DocumentPolicy.java), [DocumentActions.java](../../../apps/api/src/main/java/com/aurevia/documents/DocumentActions.java)).
- **The artifact controller refuses a patient-role principal even though the matrix grants it.** The matrix lists `patient` for upload, remove, download and read, but the controller's `actor()` throws 403 for a `patient` role because it cannot independently verify a patient link here. A patient-facing caller carries a verified link through the separate `/api/v1/patient/files` boundary instead ([AttachmentController.java](../../../apps/api/src/main/java/com/aurevia/messaging/attachments/AttachmentController.java), [DocumentActions.java](../../../apps/api/src/main/java/com/aurevia/documents/DocumentActions.java), [DocumentArtifactController.java](../../../apps/api/src/main/java/com/aurevia/documents/DocumentArtifactController.java)).
- **The object-store port is not part of the artifact command path.** `QuarantineService` and `PdfBindingService` never call `ObjectStorePort`; they verify `(objectKey, objectVersion, checksum)` metadata rows in `document_verified_object`. `FileSystemObjectStore`, `S3ObjectStore` and `SignedAccessPort` are consumed by other modules and by tests; the S3 bean exists only under the `production` profile, with endpoint, bucket and region from the environment ([QuarantineService.java](../../../apps/api/src/main/java/com/aurevia/documents/QuarantineService.java), [ObjectStoreConfiguration.java](../../../apps/api/src/main/java/com/aurevia/documents/storage/ObjectStoreConfiguration.java)).
- **A tampered original is reported, not raised as a SQL error.** V75's function returns the bytes with an `intact` flag so the service can audit the tamper and answer 409 while the transaction stays usable; those bytes are never served as a verified original. Voiding never deletes the original or its history ([V75__document_verified_content.sql](../../../db/migrations/V75__document_verified_content.sql), [DocumentService.java](../../../apps/api/src/main/java/com/aurevia/documents/DocumentService.java)).
- **The PDF renderer is a structural reference, not a production typesetter.** It emits a deterministic single-page PDF with a declared TrueType font, A4 print profile, page number, provenance and direction marker, but its Javadoc states that glyph shaping and font licensing for production Arabic layout belong to an approved rendering library with its own review. Arabic-Indic digits are classified as LTR so a value stays attached to its unit ([PdfRenderer.java](../../../apps/api/src/main/java/com/aurevia/documents/PdfRenderer.java)).
- **Synthetic and durable stores are deliberately separate.** `InMemoryDocumentStore` lives only under `src/test`; production wiring binds `JdbcDocumentStore` behind `DocumentStore`, and `DocumentRepository` is the SQL boundary for originals and renders ([JdbcDocumentStoreIntegrationTest.java](../../../apps/api/src/test/java/com/aurevia/documents/it/JdbcDocumentStoreIntegrationTest.java), [JdbcDocumentStore.java](../../../apps/api/src/main/java/com/aurevia/documents/JdbcDocumentStore.java)).
- **V17's duplicate shared functions are legacy compatibility, not current runner behaviour.** `db/check.sh` and `infra/app/start.sh` now apply migrations with `sort -V`, matching Flyway's numeric order. V17 keeps its historical `app_org()` and immutability-helper declarations as a harmless compatibility artefact ([V17__document_associations.sql](../../../db/migrations/V17__document_associations.sql)).
- **The generated command-catalog contract does not list these routes.** The authoritative [openapi.yaml](../../../contracts/openapi.yaml) documents all 20 document routes, but the generated X-04 command catalog [openapi.yaml](../../../contracts/openapi/generated/openapi.yaml) has no `/api/v1/documents` operation. Command-catalog drift checks therefore say nothing about this package ([contracts/openapi/README.md](../../../contracts/openapi/README.md)).
